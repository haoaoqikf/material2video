# 素材工作层实测记录（2026-11-15）

本页记录 `enhance-material-acquisition` 的真实执行结果。媒体、模型权重与评测输出不进入 Git；可复现命令与环境如下。所有结论只覆盖实际执行范围，不把接口成功或零命中当作内容质量通过。

## 环境

- Windows 11 Pro 10.0.26300，CPU-only；Python 3.12.10，`.venv` 由 uv 0.9.11 管理。
- FFmpeg 7.1（imageio-ffmpeg 内置）、ffprobe 9.0.2（`M2V_FFPROBE`/PATH）。
- 模型：`Systran/faster-whisper-small`（int8 CPU）、`SWHL/RapidOCR` PP-OCRv4、`intfloat/multilingual-e5-small`、`google/siglip2-base-patch16-224`；全部经 `models prepare` 恢复并由 `verify` 校验摘要。
- 磁盘：模型与评测媒体位于忽略的 `outputs/materials-eval/`、`outputs/materials/models/`，未提交。

## 端到端本地链路

1. `fetch --local` 获取带中文配音、中文烧录字和 SRT 的本地片段（5.68 s，H.264/AAC），`coverage=full`，映射 verified。
2. `index` 建立 captions（2）、shots（1）、frames（3）、asr（2，词时间码 21 个）、ocr（3，文字“上海城市夜景/人群沿街行走”，置信度 0.997–0.999）、text（7）、visual（3）。
3. `find --query "人群在街道行走"` 四通道返回 13 条命中并融合为 1 个候选；`preview` 生成接触表/短预览/HTML；`select` 以 25 fps 精裁并导入真实 `text-motion` 作品，receipt 状态 committed，`verify_project_media` 通过，作品在补齐字体后 `m2v validate` 通过（不读取工作库）。
4. 相同输入重复 `index`：7 个通道全部 `reused=true`，进程总耗时 0.74 s，无重复推理。

精裁实测（请求 400000–1800000 us）：起点误差 0 us、终点误差 −40000 us、时长误差 −40000 us、帧长 40000 us、音轨偏移 0 us；均在一帧/50 ms 内。选择输出与作品登记 SHA256 一致。

耗时说明：10k 查询为单进程热态；进程冷启动另含约 0.7 s 导入。模型内存为本进程 RSS，不含系统缓存。手工流程对照未取得可靠独立计时，因此不报告“降低 30%”的效率结论，也不以工具耗时冒充人工节省。

追溯完整性：105 条融合候选中 mediaId 与来源身份 105/105；视频候选本地窗口 47/47 有区间，图片按契约没有时间区间。真实交付选择另由 receipt 绑定 sourceId、媒体 SHA、本地/源区间、时间映射与正式登记摘要。

## 已知限制

- 平台搜索/下载受会话、风控与本机网络策略影响；不声称稳定支持。
- 中文短查询对英文标题的 E5 跨语言召回弱，已用最低证据阈值阻止弱匹配污染融合；更长字幕/描述段落需另测。
- SigLIP 2 base 对“歌手演唱”“助推器分离”等动作/阶段画面区分不足，需实际查看并在设计中保留 unknown。
- 评测语料规模小（17 件），只覆盖四类代表性查询；结论不外推到全部题材。
