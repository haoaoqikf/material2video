# 项目规划

Material2Video（材料成片）以统一制作底座承载独立视频类型。发展顺序是：先把金融时间序列等专用视频做扎实，再将多类型共同需要的制作能力沉淀为共享模块，持续完善通用混合媒体讲解。

## 当前落地范围

已落地架构见 [模块化视频制作规格](../openspec/specs/modular-video-production/spec.md)。当前代码状态、可用命令和已验证能力以 README 为准；此处计划内容不代表未完成能力已交付。

当前类型范围（由 `catalog.json` 生成，与 README 和 Skill 的类型清单同源）：

<!-- generated:type-catalog:start -->
- `financial-timeseries`：保留独立金融材料、投资价值计算、专用画面与确定性技术验收。
- `general`：以本地 React 代码场景制作 v8 全画布讲解视频，默认横屏并支持显式竖屏，保留真实配音、输入语义审查与完整候选自动验收。
- `housing-timeseries`：面向住宅年度均价的独立时间序列类型，含材料复算校验、确定性画面与可选画面评审。
<!-- generated:type-catalog:end -->

上列各类型（由 `catalog.json` 生成）均已实现到「校验、准备、按需检查、一次全片生成与验收交付」的完整链路；规划里剩下的不是把它们做出来，而是把制作体验做扎实。

general 的检查点制作工具见[制作证据与状态](../README.md#制作证据与状态)，覆盖合同、状态查询、隔离包和引用保护清理；自动量测不替代独立观感判断。

## 扩展原则

新专用类型按“材料契约—业务准备—专用画面—类型评审—注册接入”实现。共享底座不导入类型私有逻辑；只有多个真实类型出现相同需求时才抽取共享能力。模块边界见 [架构说明](../ARCHITECTURE.md)，已实现的渲染与制作契约见 [OpenSpec 规格](../openspec/specs/) 和 [制作 Skill](../.agents/skills/material2video/SKILL.md)。

## 后续路线

1. 持续完善金融专用类型与 v8 通用作品的实际制作体验；文章自动分镜与新的画面能力需另行评估。
2. 持续完善通用混合媒体的导入留证、按素材 ID 解析及旁白与字幕创作体验。
3. 持续完善镜头表现、后期、素材许可与原生尺寸审计，以及交付后的替代复核方式。
4. 根据新增专用类型的实际重复需求提取能力；保持每类业务门禁独立。
5. 仅在有明确需求且单独评估后考虑横竖屏以外的尺寸帧率；不引入第二套渲染引擎，电影级画面以现有 Remotion/React/R3F 底座上的镜头、后期与共享套件实现。
6. 外部参考项目 `vibe-knowledge-film` 的 C 夜曲与 B 寓言已分别转成正式风格包 `styles/vibe-night` 与 `styles/vibe-fable`（见[风格包目录](../styles/README.md)），各配一个可校验的示例；未并入的外观不提供可安装风格。
7. 已吸收该项目的两项方法：看图诊断的因果表与形象判据（`references/visual-diagnosis.md`），以及 `lookdev` 的任意时刻拼图、区间转场拼图、同帧一致性自检与幕内事件取证。可选二维 Canvas 绘制层（`web/src/code-scene/painter/`）已落地并附同源量测代理，使 Canvas 内容可被检查点量测。
8. 已吸收 `vibe-knowledge-film` 的六项制作方法：Painter 动态能力货架、离屏分组合成、固定种子可回放模拟、数值关键帧、声音全片包络与留静、长片章节递进。已实现能力与使用边界见[README](../README.md)及制作 Skill；这些方法不自动保证成片表达效果，仍按现有画面与声音复核。
9. 后续按实际作品验证风格包边界和性能；外部项目的分镜表格式与镜头语汇仍待评估，暂不改变现行制作材料和流程。

自动行情服务、云端队列、账号、自动发布、自动选曲和第三方插件系统不属于当前路线。配乐来自作品本地素材或确定性程序化音床，不接入第三方音乐服务。
