# 项目规划

Material2Video 当前只提供五类视频，全部使用 project v3、分镜 v9 和统一代码场景制作链路。已实现行为以 [README](../README.md)、[架构说明](../ARCHITECTURE.md) 与 [OpenSpec 主规格](../openspec/specs/) 为准；本页记录后续方向，不把计划当作已交付。

## 当前类型范围

<!-- generated:type-catalog:start -->
- `text-motion`：代码生成文字和图形，侧重排版与动效
- `data-evolution`：结构化数据的可视化变化
- `principle-metaphor`：程序生成物体和场景，说明抽象原理
- `spatial-3d`：三维模型和场景的空间渲染
- `documentary-edit`：真实视频、照片与档案的叙事剪辑
<!-- generated:type-catalog:end -->

金融行情与投资计算作为数据演化的结构化来源；建筑构件、步骤和汽车模型镜头作为三维空间的结构化来源。地图轨迹与情境叙事是表现手法。五部随附作品见 [示例目录](../examples/README.md)。

## 后续路线

1. 用实际作品继续优化五类的画面表达、素材选择、声音、字幕和制作证据，保持统一分镜与验收链路；当前关键帧世界级独立双评、过程直接对照及静态免视频已由本轮实现，后续继续扩展实际题材和品质标杆。
2. 金融来源可继续增加合规且可复核的取数流程；建筑和汽车来源可增加更多真实资产与镜头，但不恢复旧类型或旧材料入口。
3. 跨作品重复且稳定的场景能力先以可复制采用的本地源码或模板能力维护，并按需进入 `templates/standalone/` 或明确第三方依赖；作品专属组件留在作品内，不再建立公共 SDK 或风格包。
4. 完善原生画幅审计、确定性诊断和交付后的复核方式；新能力按 OpenSpec 评估。

2026-10-29 的需求取消记录见 [CHANGE_CANCELLATIONS.md](CHANGE_CANCELLATIONS.md)。自动行情服务、云端队列、账号、自动发布、自动选曲和第三方插件系统不在当前范围。

### 已发现的维护项

- 素材检索阈值与跨语言短文本：2026-11-15 初版 24 查询评测暴露 E5 短文本跨语言相似度与噪声接近的问题。后续已接入来源标题/描述，并以固定正负例校准最低分数及背景对照；现行策略以 `src/m2v/materials/retrieval_policy.py` 为准，旧 0.85 固定门槛不再是当前契约。实测范围见[素材收集整理改进记录](material-library-improvements.md)。后续仍需扩大题材、动作近邻和长字幕评测，不得将小样本结果外推为完整跨语言或动作理解能力。
- 平台来源实测限制：同日真实尝试 B站搜索返回受限、YouTube 在受控网络下被安全策略拒绝、Archive 因混合 DNS（全球 IPv4 与受限过渡 IPv6）按策略拒绝；Commons/NASA 下载通过。逐站状态已记入评测报告，恢复前不把平台下载写成稳定支持。

- 单幕栅格场景的合成性能：2026-11-10太阳系两分钟候选在已有完整代码场景缓存时，四进程合成阶段仍实测635.219秒、总669.11秒（同时存在其他制作负载，不作为隔离基准）。后续先拆分视频定位/解码、截图、字幕和编码开销，再评估保持当前字体、色彩、音画时点、确定性与来源绑定的加速路径。新增后端或缓存复用会影响跨类型渲染/候选契约，须另走OpenSpec及相关类型边界验证；本轮只保留实际性能记录，优先完成当前成片与独立验收，不改共享合成后端。
- 私有合成临时文件的权限诊断：2026-11-11太阳系完整导出对临时`m2v-explainer-*/silent.mp4`提示标准应用访问不足，最终候选与`outputs/video.mp4`的实际授权检查均为true。后续单独核对跨类型临时目录及`private_staging`标记的传递，保留最终发布权限修复与自检；涉及共享安全/发布边界，须另走OpenSpec和Windows专项验证。本轮已核验最终文件，不以屏蔽日志、跳过权限检查或重新编码替代诊断，未把临时提示包装为已修复能力。

- 已封存候选的受控元数据纠正：同次制作已修复母版采样率/声道来源常量，主实现、模板及当前作品均读取真实WAV头。但现有候选复用入口只补candidate绑定、不重建类型音频来源；实现变化又会改变准备指纹。本轮沿既有prepare/render生成新候选，没有手改封存旁车。后续评估在受锁验收/发布入口核对原绑定及媒体SHA、保留旧来源与纠正审计而不重编码的能力；它涉及候选身份、来源绑定和复用契约，须另走OpenSpec，不能作为本轮已实现能力。
- 独立工程音效命令路由：2026-11-09 制作 `start-early-investing` 时，共享 `author sounds import` 写入 `m2v.sound-synthesis` 身份，本地 v3 校验器要求随作品执行的 `film_runtime.sound-synthesis`，prepare按契约明确拒绝。本片已用既有 `assets/sound-recipe.json` 与本地 `setup` 真实重新合成恢复，并保留错误导入记录；操作手册已补充现有入口。共享工具协议尚无 author/sounds 动作，统一路由涉及命令/执行协议、模板及校验边界，超出本片内容制作范围，须另按OpenSpec设计并验证，不以手改身份或放宽验证兼容。
- 混合有声与无旁白场景时，节奏报告的 `storyboardHoldSeconds.readingHold` 可能把无旁白场景计入默认阅读停留；实际时间轴不受影响。待用最小混合场景核对并修正诊断字段。
- 静态代码场景的重复采集：2026-11-07 重制 `start-early-investing` 时，结果页相邻帧 PNG 摘要相同，每帧约1.24 MB，仍逐帧截图和落盘。后续评估可验证的静态区间复用，必须保持字幕、声音、逐帧确定性和现有缓存摘要语义。本轮不新增静态声明或采集捷径，因为它会改变共享采集/缓存契约，需另走 OpenSpec 并覆盖动态场景误判边界；当前仍沿已验证链路制作。
- 代码场景素材缓存按场景精确失效：重剪 OpenAI 与 Anthropic 一片时，采集键包含完整画面素材清单及其摘要，替换仅在开头出现的单张图也会让全片八幕重采。后续评估如何核验每幕实际可访问的素材集合，在保持原件摘要校验、动态素材访问与候选溯源的前提下复用其他幕的缓存。该改动涉及共享采集契约，需另走 OpenSpec，并覆盖动态素材选择与跨幕引用。本片沿现有缓存与渲染契约重新采集。
- 临时文件权限告警上下文：同次制作中，私有临时目录内的 `silent.mp4` 触发标准权限读取告警，最终交付文件的 `has_usable_access` 实测为真。后续区分中间文件与最终交付的告警上下文，保留真实交付权限错误的检查；需覆盖标准权限应用和临时文件生命周期。当前本机应用控制通道不可用，无法完成该项交互回归，作为独立维护项保留，不削弱现有权限判定。
- 同轮对照媒体重复派生已在本轮处理：当前有效盲包的媒体、帧率、窗口、显示尺寸和采样步长完全一致时，独立复制净化媒体并逐文件直读核验原封存摘要，不重复编码、解码和取帧；两包各自封存，不用硬链接共享可写文件。后续仍可评估同包重复显示尺寸的存储优化，不将其写成已实现。
