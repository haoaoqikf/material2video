# 项目规划

本文记录 article2video 的方向与阶段路线。**已实现的能力以 README 的当前状态为准**，
本文中标注「规划中」的部分不代表已有实现。

## 使用场景与表达原则

面向个人 IP 的观点型抖音内容，输入一篇文章，把「抽象观点 + 核心判断」转为信息可视化短视频。
例如：约束与反馈、复利、上场次数、学习先建立结构、复杂问题拆分，以及低频高收益的成功事件。

表达原则是「思想不断变深，表达不断变浅」：保留核心判断和必要推理，通过场景与动画降低理解门槛。
文章可以压缩和改写，但不得虚构论据或扭曲原意；没有来源的数值与图表必须明确标为示意，
不能当作实测结果。

## 落地形态：项目级 Skill

项目最初的设想是「AI 每次自由写网页」或「AI 只挑选固定组件」。实际落地时收敛为第三条路径：

> **AI 写网页，但必须满足一份确定性渲染契约；渲染由脚本完成，不由 AI 完成。**

这样做的好处是：视觉表达不受组件库限制（AI 可以自由设计每支视频的构图与气质），
同时导出过程完全可复现（同一帧永远渲染出同一画面）。

Skill 位于 `.agents/skills/article2video/`，被 Codex 与 DSH 识别为项目级 skill；
内容分工为：

| 部分 | 职责 |
| --- | --- |
| `SKILL.md` | 工作流主文档：从文章到成片的步骤与排查手册 |
| `references/` | 渲染契约、分镜结构、竖屏视觉规范、目录与输出路径 |
| `assets/` | 共享基础样式、设计令牌（`base.css` / `theme.css`）、可选的设计语言层（`keynote.css` / `typography.js` / 随仓库分发的字体）与时间轴运行时 |
| `scripts/` | 校验、配音准备、预览、渲染、视觉评审五个命令行工具 |

因此「可复用的视觉语言」不再体现为固定的 Scene 组件类，而体现为
**共享的运行时 + 契约 + 视觉规范 + 设计令牌**；常规构图由分镜选择受控组件与布局，
特殊构图仍可由每支视频的专属网页决定。
视觉方向的选择（深色科技 / 编辑杂志 / 极简高级）目前仍由人或 AI 工具判断，
自动化属于规划中的能力。

## 目标处理链路

```text
文章
 → 内容理解与压缩          ← 已实现：按文章生成分镜规范执行（由 AI 工具完成，无生成器程序）
 → 分镜规划和视觉语言选择   ← 已实现：同上，规范见 references/article-to-storyboard.md
 → 结构化脚本 JSON          ← 已实现：storyboard.json（校验规则已落地）
 → HTML / CSS / JS 场景渲染 ← 已实现：共享声明式页面或专属网页 + 共享运行时
 → 时间轴动画编排           ← 已实现：帧驱动，禁止 CSS 动画
 → TTS 配音与字幕时间对齐   ← 已实现：edge-tts + 字词时间戳分句
 → 逐帧渲染与音视频合成     ← 已实现：可选 AAC 配音与字幕烧录
 → 竖屏视频                ← 已实现：1080 × 1920 / 30fps / H.264
```

网页预览与最终导出使用相同的场景内容和时间轴，这一点已经落实：
预览与渲染共用同一份分镜 JSON，预览只做整体缩放，不改变内部布局。

示例输入约 500 字，示例输出为 9:16、1080 × 1920、30fps、45 秒。文章字数不是配音时长承诺：
需根据目标时长压缩口播文案，或随配音调整总时长。

## 视觉组件候选

下表是**内容到视觉的映射建议**，供 AI 规划分镜时参考，不是必须遵守的枚举。

现已实现的组件与它们的适用场景，以
[视觉组件目录](../.agents/skills/article2video/references/figure-catalog.md) 为权威来源，
本文不重复维护一份可能漂移的副本。下表只保留尚未实现的方向：

| 组件 | 脚本类型 | 适用内容 | 状态 |
| --- | --- | --- | --- |
| TitleScene | title | 开场命题、主题 | 已实现（`balance`） |
| QuoteScene | quote | 核心判断、金句 | 已实现（`gap`） |
| ComparisonScene | comparison | 两种选择、前后对照 | 已实现（`versus`） |
| TimelineScene | timeline | 事件顺序、尝试过程 | 已实现（`stairs`） |
| DiagramScene | diagram | 因果、约束、反馈模型 | 已实现（`loop`） |
| ConclusionScene | conclusion | 收束、行动建议 | 已实现（`exchange`） |
| ListScene | list | 要点、行动步骤 | 已实现（`iceberg`） |
| NumberScene | number | 数量、频次、收益变化 | 已实现基础数字组件 `number`；复杂数值图表仍待扩展 |

校验器认识这八种类型并对必填字段做检查；出现新类型时给出警告而非错误，
以便扩展，但对应网页必须实现该类型的渲染分支。

## 分镜脚本

分镜 JSON 的字段定义、示例与校验规则以
[分镜脚本结构](../.agents/skills/article2video/references/storyboard-schema.md) 为权威来源，
本文不再重复维护一份可能漂移的副本。

要点：

- 场景时长用帧数表达（`durationInFrames`），起始帧由累加推导，不手写；
- 场景展示文案与口播文案允许不同：画面呈现关键结构，口播补充解释与例子；
- `narration` 用于可选配音准备；有声预览与导出共用媒体清单中的时长和字幕，省略 `--media` 时不渲染口播。

## 分阶段路线与验收目标

### 第一阶段：动画网页与统一时间轴 —— 已完成

用人工编写的示例脚本，完成竖屏网页场景与统一时间轴，支持播放、暂停、重播与拖动。

验收结果：示例 5 幕 1350 帧完整播放；中文排版在安全区内、无溢出；场景切换正确；
同一帧重复渲染逐字节一致（已作为自动化测试固化）。

### 第二阶段：视频导出 —— 已完成（无声）

建立可重复的按时间取帧与视频编码流程，导出无声视频，保持网页预览与导出的一致性。

验收结果：导出视频可播放；尺寸 1080 × 1920、30fps；总时长符合脚本（1350 帧 = 45 秒）；
渲染后自动解码复核帧数与分辨率；字体使用系统栈，换机器可能轻微影响字宽（见视觉规范）。

### 第三阶段：配音字幕同步 —— 已实现

通过 edge-tts 按场景生成配音，用字词时间戳结合标点生成逐句字幕；媒体清单记录派生时长，
场景随配音延长且保留原最短时长。预览使用统一 WAV 音轨驱动画面，导出按帧烧录字幕、
合入 AAC 配音并输出 SRT。配音按文本、音色、语速和生成器版本缓存。

验收：自动化测试覆盖缓存、异常、时间轴、字幕排版、预览控制和音视频合成；
五幕示例真实合成并完成全量导出，原 45 秒延长为 46.27 秒，末尾配音未截断。
首次配音实测 13.3 秒，五幕全缓存准备约 0.1 秒；结果依赖在线服务与本机性能。
背景音乐本次不实现，后续另行规划。

### 第四阶段：视觉与动效基线 —— 已实现

把「高级感」从个人手感变成可复用、可校验的规范，避免每支视频各写一套风格：

- `assets/theme.css` 提供设计令牌（背景 / 表面 / 文字三级色阶 / 强调色 / 阴影 /
  圆角 / 节奏）与三个背景层工具类，只定义变量，不覆盖既有画面；
- `timeline.js` 补齐纯函数动效原语：`spring`（闭式弹簧，第七阶段换成物理参数并引入
  vendored 求解器）、`range`（数值映射）、`breath`（常驻微动）、`drawPath`（SVG 描边）、
  `revealChars`（逐字揭示）；
- `references/visual-spec.md` 增补排版层级表、三层景深做法、动效配方与三套风格方向；
- 视觉规则可执行化：`validate.py` 检查单行字数、场景过短、强调短语不生效；
  `render.py` 开渲前静态扫描 `animation:` / `transition:` / `@keyframes`；
- 示例网页按该规范重做，作为观感基线。

验收：示例 5 幕 1350 帧按新规范渲染，逐帧确定性测试（同帧与跨会话逐字节一致）
继续通过；新增原语与校验规则的测试全部落地。
尚未实现：AI 自动选择视觉风格。webfont 分发与系统字体栈的取舍在第七阶段落地
（启用 `visual.preset` 时改用随仓库分发的可变字体，默认路径仍是系统字体栈）。

### 第五阶段：视觉组件库与设计系统 —— 已实现

目标：把「AI 做导演，不做设计师」变成结构上成立的事——AI 从现成组件里挑、
给标注、指定节奏，而不是每次从零画一遍。

- `assets/figures.js` + `figures.css`：七个视觉组件（`balance` / `gap` / `versus` /
  `iceberg` / `loop` / `stairs` / `exchange`），每个自带 DOM 与样式，
  只从分镜读文案与标注，页面只声明挂载点；
- `A2V.motion` 动效配方层：入场配方（`surface` / `figure`）、具名弹性
  （`enter` / `firm` / `lively` / `snap`）、常驻微动周期、节奏换算，
  手感参数只写在 `timeline.js` 一处；
- 节奏系统：分镜写 `calm` / `normal` / `impact`，运行时把幕内比例点整体缩放；
- `scripts/a2v/catalog.py` + `references/figure-catalog.md`：组件目录与它的服务端镜像，
  校验器据此判断 kind 是否存在、标注键是否认识、条目数是否超容量；
- `references/design-constitution.md`：十四条规则，每条标注**能不能机检**；
- `scripts/review.py`：视觉评审工具——组件契约探针（声明的标注是否真的画出来）、
  帧量测（墨迹覆盖率与安全区）、宪法静态检查，产物为联系表与 `report.json`；
- `references/visual-review-rubric.md`：六项 60 分制量表，机检保证「不是废片」，
  人工（或视觉模型）判断「值不值得看完」。

验收：`uv run pytest` 319 项通过；《永远不要害怕面试》与示例
`examples/why-effort-fails` 都只声明挂载点，同一套组件在浅色与深色两套主题下
都能成立；`review.py` 在两者上均 0 错误。

尚未实现：生成器程序与模型调用（见第六阶段）；组件库的完整换肤
（仍有若干装饰性渐变写死在 `figures.css` 里）。

声明式画面路径已补齐：新作品可由分镜从组件目录中挑选受控组件，并声明深浅主题与预设布局，
由共享页面完成预览和渲染，不必为每篇文章编写 `index.html`。这一步复用现有
帧驱动运行时和七个已有组件，并加入基础数字组件；自动生成分镜仍属下一阶段。

### 第六阶段：文章生成分镜 —— 已实现（规范落地，无生成器程序）

把「文章 → 分镜」这一步从手工编写变为**可复核的生成流程**：步骤、判断顺序、内容与排版约束、
组件目录不足时的处理，以及生成后必须走完的校验闭环，统一写在
[文章生成分镜](../.agents/skills/article2video/references/article-to-storyboard.md)，
由 AI 工具按规范执行；`SKILL.md` 的标准流程第 1 步与 `README` 指向该规范。

验收结果：规范覆盖输入输出契约、拆幕与时长规则、内容忠实与视觉受控、排版与标注约束、
组件缺口处理与校验闭环；生成结果以 `validate.py --declarative --strict` 零错误零警告为准，
并用 `review.py --declarative` 的组件契约探针确认声明的标注真的画了出来。
本阶段的落实方式是**规范而非程序**：没有内置生成器、不调用模型服务、不做批量生成；
生成质量仍按下限交给机检、按「值不值得看完」交给人评。

尚未实现（本阶段之外的遗留项）：生成器程序与模型调用、批量生成、AI 自动选择视觉风格。

### 第七阶段：发布会级设计语言与观感闸门 —— 设计语言层已实现，自动评审仍待做

目标：把「发布会级别的画面」从手感变成可机检的约束，并让它与「是不是废片」分开判定。

- `assets/keynote.css`：设计语言层，由分镜根级 `visual.preset: "keynote"` 显式启用。
  模块化字号阶 8 档（caption 28 / label 34 / body 40 / lead 60 / title 76 /
  headline 96 / display 120 / hero 140，单位 px；正文下限 36px；每档配对行高与字距）、
  8pt 间距阶（4 / 8 / 16 / 24 / 32 / 48 / 64 / 96 / 128 / 192）、五个圆角档 + pill、
  三级阴影、12 列网格（内容宽 888px、槽宽 24px），以及 `keynote-dark`
  （bg `#08090c`、强调 `#32d6ff`）与 `keynote-light`（bg `#eff1f4`、强调 `#0a6ad9`）
  两套主题；对比度预算为正文 7:1、大字与图形 4.5:1，图形再按四类细分
（数据描边 / 图形内文本 / 装饰描边 / 面填充，见
`tests/test_figure_contrast.py` 的分类表）；
- `assets/fonts/`：Inter Variable 与 Noto Sans SC Variable（SIL OFL 1.1）随仓库分发，
  不走 CDN；字体栈只在预设作用域里覆盖 `--a2v-font`，因此未启用预设的页面仍用系统字体栈；
- `assets/typography.js`：可选排版引擎 `A2V.type`，不属于 `window.__A2V__` 渲染契约，
  未启用预设时不会被调用。组件用 `data-a2v-fit="<档位>"` 声明字号上限档位，
  共享页面在预设生效时按实测可用宽度取档、按宽度均衡断行、到 36px 正文下限即停；
  行高、字距、字重仍归组件，字号归字阶；未声明的元素不会被改动；
- `scripts/a2v/keynote.py`：观感闸门 K1–K7 的计算与结果结构（`Gate` / `KeynoteResult`），
  与废片类 C 系列**分开计分**；其中 K7 文字溢出是**硬判定**，失败会并入体检错误数与
  退出码。`inspect.py` 的帧量测扩到 540 × 960 的探针画面，
  并收集字号、文本样张、卡片特征、文本块四边墨迹边界与安全区几何；
- `examples/keynote-baseline/`：8 幕 / 2040 帧 / 68 秒 / 1080 × 1920 @30fps 的参考实现；
- 测试：`tests/test_keynote_assets.py`（令牌自检、对比度、`--fig-*` 覆盖、预设作用域、
  组件墨色字号收进字阶）、`tests/test_figure_contrast.py`（图形颜色分类表、每类的对比度
  预算与判定基座、两套主题分别核对、`fill`/`stroke`/`background` 不许写字面色值、
  边界描边令牌必须真的被引用、纯分隔线必须保持耳语）、
  `tests/test_offline_assets.py`（资产不许引外部 URL、
  `url()` 必须指向仓库内真实文件、断网渲染可跑通）、`tests/test_keynote_layout.py`
  （浏览器里实测安全区、字号阶与四种版面的几何）、`tests/test_typesetting_apply.py`
  （取档不破坏强调标记、退化输入、重复取档零写入）、`tests/test_typesetting_wiring.py`
  （引擎真的接上了、取到的档位与字阶一致、非预设页面零取档）
  与 `tests/test_review.py` 的 K 系列指标与闸门用例。

验收：`examples/keynote-baseline` 上 `validate.py --declarative --strict` 零错误；
`review.py --declarative` 的 C 系列 24 帧抽检 0 错误 0 提醒，K 系列 38 通过 / 7 提醒 /
0 失败 / 11 跳过（跳过项均写明原因，主要是「这一幕没有卡片表面」与「正文级文本块不足两个」）；
K7 的负例（注入 350 字副标题）报「越出安全区：「title-text」上越界 285.2px」、
错误数 1、退出码 2；
未启用预设的页面仍然不加载档位（由 `tests/test_typesetting_wiring.py` 守住），
但**成片的字节一致性哈希在本轮被刻意重新记录**：改的是动效曲线，画面里每个入场元素的
位置都变了，所以这个哈希不再只是「样式有没有被动过」的证明——
它是用「回退到 HEAD 的资产再渲一次」证明差异只来自动效的。新旧哈希：
`--capture-format png` → `A0A94CFC…`（原 `DAFDD423…`）／默认 → `CBEBD8BF…`（原 `DF1DB75D…`）；
命令要连哈希一起记，否则复现不出来。
预设页面的 8 幕共 24 帧在「剥掉档位声明」的加载下逐像素一致。

飞轮节点改为按实测文字宽度定形并在圆内居中；
新增 **K8 容器内溢出（硬判定，容差 2px）** 与 **K9 图形描边一致性（提醒）**，
K8 的反例已取得（关掉内容驱动几何后报「「打开选项」穿出 .loop-node-disc（圆周）16.0px」
等四条、错误数 1、退出码 1）；修好 **K6 的卡片采集**——原先只取图形挂载点的直接
子元素，任何包在包装元素里的卡片都看不见（`compare` 画面上两张卡片、`cost` 两张、
`freedom` 一张，闸门却报「没有可识别的卡片表面」），改为采集整幕里所有被画出来的
HTML 表面，同时确认 **SVG 里的圆角图形是图解对象、不算卡片**（否则会制造 3 处假失败）；
并修掉一处让 K6 长期失效的聚合缺陷——`skipped` 原先排在 `pass` 之上，
把「入场帧量不到、中后段量到了」的幕整幕降级成「无法判定」；
新增 `tests/test_figure_token_closure.py`（43 项）把令牌闭包、基元与状态、
K8 / K9 与聚合规则全部机检住。

第三轮解决了**排版层级**的单一根因：四个分节式幕（`compare` / `attention` /
`loop` / `freedom`）的幕标题原先全按**眉标**排版（40px、字重 500、
字距 +0.14em、颜色取最暗的 `--a2v-text-3`），逐幕实测下来标题是整屏最弱的元素
——`compare` 的卡片标签 44px 比它大、`attention` 的标注 44px 比它重、
`freedom` 的阶梯标签比它亮。八幕里有四幕的最大字号只有 40–44px（画布宽的 4%）。
错位在于文案与排版不一致：分镜的 `title` 是一句完整的话，
页面上方的英文眉标才是角标。修法是把档位换到阶上已有的 `title`（76px），
并用 `--a2v-heading-size|weight|track|color` 四个角色令牌把字重 700、
字距 `-0.03em`、最亮色一起换掉，改完是**标题 76px / 内容 44px / 注 28px** 三级层级。
**踩到的坑**：字号由排版引擎按 `data-a2v-fit` 内联写入，只改 CSS 的 `font-size`
不起作用，必须同时改标记里的档位（兼容性由 `declarative.js` 的
`if (preset && A2V.type)` 保证）。同时修掉 K4 的一处盲区：标题升到 76px 后跨过
K4 的采样门槛（≥ 44px），`compare` 出现假提醒——实际那两条左线是两张卡片各自
对齐**本栏**左边界的镜像对称构图（中心 355 + 725 = 2 × 540），
判据因此补上「镜像对称的两条线并成一条」并附反向测试。

尚未完成：基元与状态推广到其余组件（第 5 轮已迁完阶梯、飞轮、天平三个，
并按「焦点跟着行进走」的原则修掉了前 73% 空焦点的问题；交换幕与连接线的角色色待迁）、
`figures.css` 字号兜底与字号阶的对齐、
**强调色的连续量**（`compare` 的 `--vs-heat` 从 52% 才起步，需要一套
`--a2v-focus-mix` 连续版的焦点量，并补上注释里写了却没实现的"底色一起升温"）、
**「面积」对排版型焦点的代理量**（`one` 一幕的 140px 强调色大数字视觉上无可争议是焦点，
字形笔画却只占整帧 0.18%，K2 因此报警——这是判据问题，不是组件缺陷），
以及**内容尺度**：实测八幕的内容纵向跨度只占画布 23%–51%，留白 72%–86%，
而 K1 只有下限（背景占比 ≥ 40% 通过），死白再多也没有提醒——
这一项要动的是图形本身的尺度，不是排版。
第六轮先把**块间距**收成一个真源（原先实测是 29/32/48/80/88/147px 六个值，
而阶上只有一档被用到），间距收口后跨度反而更小（`compare` 47%→38%、`one` 32%→29%），
把留白的成因变纯了：**剩下的纯粹是尺度不足**——`one` 一幕是 120px 的大数字
+ 91px 的标签 + 59px 的注，合起来占安全区 29%，而 `--a2v-ink-display` 只有 120px。
因为 `data-a2v-fit` 声明的是上限、引擎会自动降档适配，**抬高上限不可能溢出**，
这是下一轮的低风险杠杆。

第七轮已经用上了这个杠杆，并查出一个更严重的根因：`.fig-number` 的兜底一直是
`var(--a2v-ink-display, 240px)`，而 `--a2v-ink-display` 是设计语言层专有令牌——
**预设把主角数字从组件自己的 240px 压到了 120px**。数字幕因此是八幕里最空的
（内容只占安全区 29%）。抬高时撞上模块化字阶的不变量（相邻档位比例 1.1–1.6），
所以补了一档 `mega`（220px）当桥，把主角数值定在 `numeral`（350px）：
数字幕跨度 **29% → 45%**，K2 的该幕也自己通过了。K 系列 **52 通过 / 1 提醒 / 0 失败**。

第九轮补上维度 11（动效自然克制）里闸门量不到的一类问题：
**曲线再自然，只要被驱动的量本身是阶跃的，画面上就是一次瞬跳**。
数字滚动原先无条件执行，`value: 1` 于是先以最高 0.86 的不透明度清楚地显示一秒"0"
再跳成 "1"——既是硬阶跃，也是画面在断言错误的信息。现加 `ROLL_MIN = 10` 步门槛。
同一类问题在图形状态上还没修：状态是离散的（`rest`/`focus`），
而确定性契约禁止 CSS `transition`，所以 `loop` 幕的节点圆盘在相邻帧之间整块跳色。
这与 `compare` 剩下的 K2 提醒是同一个根——**设计系统里没有"连续焦点量"**，
是下一轮的靶子。

第十轮把这条连续通道做出来了：给 `focus` 态加 `--a2v-focus-mix`（0..1，默认 1），
外观由 `color-mix` 得到，`mix = 0` 时等于 rest。**这不新增第五个状态**——
规格早就写明连续量不该并进四态——而是让四态之一在内部连续。
交接因此可以同时满足两条：任何一帧 `focus` 元素只有一个，而视觉上没有缝，
因为换手正好发生在 `mix = 0` 那一帧（实测换手帧填充与 rest 逐位相同，
随后 0.18 → 0.45 → 0.91 连续升上去）。K 系列仍 **52 通过 / 1 提醒 / 0 失败**。

顺带量出一个更严重的缺陷，第十一轮已修：`loopPoint` 被"小球走的环"和
"节点摆在哪"共用，每格固定转 120°（按一圈 3 个停位写死），而分镜给了
**4 个节点**——`打开选项` 与 `推到明天` 的圆盘中心都是 ≈(540,760)，
**中心距实测 0.0px**，屏幕上只看得到三个圆盘，论证少了一步。

修法是让步长取 `360 / 节点数`，格数取 `停位数 × LAPS`（组件自己的注释
就写着"两次完整循环之后条满"，而 `LAPS: 2` 从未被用过）。现在四个圆盘
各占一角、环由四段 90° 弧闭合成整圆。`loopPoint` 是共享几何，
非预设的 `why-effort-fails` 也有 `loop` 幕，所以未启用预设时仍用冻结的
3 个停位 / 6 格——用两个版本的 `figures.js` 分别渲染，成片 SHA256 逐字节一致。

第十二轮把 `compare` 那条 K2 提醒也解决了，首因判断被实测推翻：那一幕缺的
**不是**连续量，而是**基元压根没有 HTML 形态**。`versus` 是 HTML 盒子
（div + border + background），而表面基元当时只声明 `fill`/`stroke`，
所以它用不了状态语汇，只能自己算出一条 1px、alpha 0.24 的暖边框加一层光晕——
整幕强调色占比 0.0016（门槛 0.002）。这和第四轮 `focus` 态查出的问题同源：
细描边缩到判据图上只剩 1px，抗锯齿一糊就量不到。

修法是给每个状态**同时声明两种媒介**：SVG 读 `fill`/`stroke`，HTML 读
`background-color`（不是 `background` 简写——简写会连 `background-image`
一起重置，把组件自己的材质抹掉）。迁移后右侧是表面基元的 `focus` 态，
底色 `rgb(22,70,95)`（色度 73），材质保留：

```
compare K2  0.0016 / 0.0027 / 0.0027  →  0.0289 / 0.0292 / 0.0292
闸门        52 通过 / 1 提醒 / 0 失败  →  53 通过 / 0 提醒 / 0 失败
```

这是闸门首次没有任何提醒。同时补了一条护栏：`figures.js` 的组件模板字符串里
写注释时带了反引号，模板字符串被提前终结、整个脚本语法错误、**首页全部图形消失**，
而纯静态检查全都没拦住——现在 `TestAssetSyntax` 用 `node --check` 逐个检查页面脚本。

第十三轮的靶子是 `compare` 一幕的内容跨度（38%，八幕最低）。量下来发现要害
不是"内容少"而是**层级倒置**：板面按内容收缩只有 596px（安全区 888px 的 67%）、
每栏 226×268、选项文字 44px，而幕标题 76px——**要看的东西比问题还小**。
两个成因：`.vs-side` 是 flex 项，`min-width: auto` 让内容宽度成了下限；
`.vs-text` 固定吃 `--a2v-ink-value` 的兜底值、从不参与自适应。

修法是预设下让两栏均分安全区宽度（`min-width: 0`），文字挂
`data-a2v-fit="lead"` 由排版阶给上限。第一个尝试取 `title`（76px）——
板面同样占满，但 K3 从 `[44, 76]` 变成 `[76]`，**层级反而变平**，
所以最终取 60px，保住"标题 76 > 载荷 60 > 注释 28"这条阶梯：

```
板面 596 → 888px（100%）   每栏 226×268 → 372×300，等宽
选项文字 44 → 60px         K1 留白 0.807 → 0.758   内容跨度 38% → 42%
```

同一轮还把 `test_media.py` 一处**墙钟时序断言**改掉了：它原先"等 250ms 再看
帧号 > 4"，全量跑时进程被饿到 rAF 推不动就会假失败（实测出现过两次）。
现在改成有界轮询，只要求"播起来之后帧号会推进"，不规定多少毫秒推多少帧。

第十四轮逐个量了八幕里每一个文字节点的字号，抓到两处**阶外字号**
（字号阶是 350/220/140/120/96/76/60/40/34/28）：

1. **结论句自己算字号。** exchange 组件的私有 `fitFontSize()` 是
   `clamp(floor(888/最长行字数), 54, 96)`——有意的取舍（不测量，避免逐帧
   布局抖动），但返回任意整数，实测 **88px**。改成从共享字号阶上取档位，
   仍然不测量，实测 88 → **76**。
2. **闸门阈值倒灌进设计系统。** `--a2v-ink-value: 44px` 的注释写着
   "与 K3 的统计下限对齐"——44 是**测量阈值**，阶上没有这一档；
   `figures.css` 里还有两处写死 `font-size: 44px`。八幕里有 **5 幕**
   踩着阶外字号，`closing` 一幕更是同时出现 44px 与 40px 两个
   相差 4px 的字号——看不出区别，只像失手。三处都改成映射到阶上那一档
   （写死的那两处用令牌兜底，未启用预设时回落 44px，逐帧不变）。

```
八幕实测：opening [120,40,28]   compare [76,60,28]   cost [34,28]
         attention [76,40,28]  loop [76,40,34,28]   freedom [76,40,34,28]
         one [350,76,40,28]    closing [76,40,28]
```

**为什么之前没抓到**：`tests/test_keynote_layout.py` 自己抄了一份阶梯，
`{28,34,40,44,60,76,96,120,140}`——**44 就在里面**，而真阶的 220/350 反而没写，
于是"字号必须在阶上"这条不变量恰好放过了 44px。现在改成从设计语言层读真源，
并新增 `TestBaselineTypeScale` 打开**真分镜**逐幕采样（合成样张只有四种版面、
没有 `title`/`exchange` 这类组件，量不到组件写死的字号）。
反向验证：把 44px 放回去，它报出 5 幕 9 个元素阶外。

第十五轮做了三条审计（间距、文案、图标）与一次状态语汇排查，前三条都是**阴性**：

- **间距**：`figures.css` 走令牌 47 处、写死 15 处，写死的全是光学微调
  （`-1px` 幽灵描边、`2px` 下划线、`-104px` 引号装饰），本来就不属于间距节奏；
- **文案**：全片全角标点 3 处、半角 0 处；无句末句号；中文数字 11 处、
  阿拉伯数字 0 处；行长都在组件预算内；
- **图标**：三套箭头确实不同族，但 `arrow` 与 `chevron` 语义本就不同
  （流向 vs 状态转换），现有用法自洽，不凭猜改。

排查中抓到一个**空操作的状态**：`--a2v-label` 基元的焦点态写的是
`fill: var(--a2v-text-1)`，与基元自身的取值一模一样——组件挂上
`data-a2v-state="focus"`，画面毫无变化，而检查项是绿的。线索来自组件那边
（`.berg-callout-label.is-accent` 说明标签本就该在焦点时变强调色），
所以**修基元与迁组件是同一件事**：焦点态改为 `fill: var(--a2v-accent)`
并补上 HTML 媒介的 `color`，`.berg-callout-label` 随之迁到 `a2v-label` +
`data-a2v-state`，棘轮 `PENDING` 从 5 项缩到 4 项。

```
未启用预设  rest rgba(244,247,251,0.96)   focus rgb(53,224,200)   ← 该主题强调色
预设        rest rgba(255,255,255,0.96)   focus rgb(50,214,255)
```

删掉的那条 `.is-accent` 是全局规则，而基元只在预设作用域内定义，所以组件里
补了一条按**状态属性**写的规则接住未启用预设时的表现——否则非预设的 iceberg
作品会静默丢掉焦点标签的强调色，而两个非预设例子都没有 iceberg，
**逐字节回归照样会通过**（那是运气，不是保障）。

**K1 的留白上限：这一条不做，且原因是证据性的。** 把 quote 幕文案从 11 字缩到
2 字，留白值只从 0.748 动到 0.758——`empty` 量的是"与左上角像素颜色接近的占比"，
背景带网格与渐变，该指标被背景纹理卡在 ~0.85（基线 24 帧全落在 0.710–0.850）。
给它加上限等于量一个够不到的数字。「留白合理」的上界若要做，
得换一个能表达"空"的量（例如内容包围盒占安全区的比例）。

第十六轮把状态语汇补成**三族基元**，棘轮归零：

| 族 | 类名 | 供给什么 | 用在哪些元素 |
| --- | --- | --- | --- |
| 面 | `a2v-surface` | `fill` + `stroke` + HTML `background-color` | 圆盘、柱子、令牌、卡片、标注框 |
| 文字层 | `a2v-label` | `fill` / `color` | 组件标签、节点标签 |
| 线条与标记 | `a2v-stroke` | **只给颜色通道** `--a2v-stroke-ink` | 连线、弧、箭头头 |

第 15 轮查出的 4 个临场类名分属两个**语汇没覆盖的角色**：`berg-link` 与
`ex-arc` 是 `fill: none` 的描边，`ex-arrow` 只有 `fill`，
`ex-node-disc` 的焦点表达原本只是描边。三种角色共用一个颜色语义，
但**落点属性不同**——所以线条族不写 `stroke`/`fill` 属性，只供给通道变量，
由组件决定落到哪里。理由很实在：基元选择器是三层（属性 + 类 + 属性），
**只要它写了 `fill`，就会盖掉组件的 `fill: none`**，一条弧线会变成一块实心。

四条 `.is-accent` 规则全部删除，未启用预设时的表现由按**状态属性**书写的
等价规则接住（沿用第 15 轮的教训）。棘轮 `PENDING` 缩到**空元组**并加了
"不得再增长"的终点断言。

**基元仍然没覆盖的**：只有四态，而画面里还有"连续量"（`--a2v-focus-mix`、
`--vs-heat`）与"结构性类名"（`is-left`/`is-right`）。它们按设计**不该**塞进
这四态——四态表达不了连续量，硬塞会让状态失去语义。这条边界是刻意的。

第十七轮修掉的是**上一轮自己造出的重名**：第 16 轮给线条族起了新名字
`a2v-stroke`，而 `a2v-connector` 早就存在（注释写着"连线、箭头、轨道、轴线"），
只是它当时**只有形状、没有状态规则**。所以第 16 轮的工作应改述为
"给既有的连接件族补上状态"，而不是"加了一族"。

重名的成因很具体：**基元清单是手抄的**。`test_figure_token_closure.py` 里一份、
第 16 轮新写的断言里又一份，两份还不一致（后者漏了 `a2v-frame`），谁也没报错。
现在清单从 `keynote.css` 推导。

改名立刻暴露了两个被"没有消费者"掩盖的问题：

- 连接件基础规则写死了 `stroke-width: var(--fig-connector-w, 4)`——没有消费者时
  看不出问题，一旦有消费者就会把组件的 3px / 5px 一起改成 4px。
  现在这一族只供给**墨色与端点形状**，几何归组件；
- 箭头头是**填充标记**而基元给路径写 `fill: none`（三层选择器），
  所以它要用同样三层的选择器盖回来，并显式关掉 `stroke`
  （否则基元会在三角外面描一圈 1px 发丝边）。实测确认：
  `rest fill=rgba(255,255,255,0.52) stroke=none` / `focus fill=rgb(50,214,255) stroke=none`。

另外把"未启用预设时的表现"这类规则改为显式限定作用域
`:root:not([data-a2v-preset="keynote"])`（5 条）——两套规则并列时谁赢取决于
文件顺序，这是最容易在重构里悄悄翻车的一类。

同轮扫了组件层所有裸色值：绝大多数落在令牌定义或 `var(--令牌, 原值)` 兜底里；
真正跑出调色板的只有冰山的水深渐变 `rgba(45,78,120,0.17)`（四套调色板里都没有，
而紧邻的另一个渐变是令牌驱动的）。已改成由调色板的"水"推导，
兜底值即原字面量。另两处裸色值是**冻结端点**（强调词的褪色端点、圆片文字的
渐变端点），换成令牌反而会改动冻结画面，因此保留原样并已在设计文档登记。

**webfont 子集化：按作品切，已实现（静态子集仍然不做）。**
字体 `NotoSansSC-Variable.ttf` 16.9MB（Inter 856KB），**单份共享在 skill 资产里**，
不是每支视频一份。实测三支作品（`why-effort-fails` / `never-fear-interviews` /
`keynote-baseline`）的全部文本合计只有 **249 个去重字符（241 个汉字）**；
按字形均摊估算，只带这些字约 **66KB**，量级上是 1/260。
所以收益是真的，但**对共享资产做静态子集不安全**：共享字体要渲染**将来**的任意
文章，按今天这三支切出来的子集明天就会缺字，而缺字会静默回退到系统字体、
改变字宽与行高——正是「稳定输出」要避免的那类漂移。
要做就得按作品切（`prepare` 时文本已确定），并且**必须配一条缺字机检**
（逐个汉字查字体 cmap，缺了就报错而不是让它悄悄回退）；页面本身也是交付物，
文本改过而子集没重切同样要被这条机检抓住。
**缺字机检在「不启用预设」的页面上曾经是空转的（第 24 轮发现，第 25 轮已修）。**
`@font-face` 声明都在 `keynote.css` 里，而它受档位门控；两支专属作品
（`never-fear-interviews`、`why-effort-fails`）不启用预设，因此**不声明任何 webfont**，
`fonts.page_fonts()` 返回空表，检查直接返回「没问题」。
就语义而言这不算错（没有声明字体，也就无所谓回退），但它违反了本项目一直守的
一条纪律：**一声不吭的检查与通过的检查在报告里长得一样**。
修法就是照 K 系列的写法来：没有声明字体时在体检里**写明「本页未声明 webfont，
字体覆盖检查不适用」**，而不是静静地什么都不说。
第 25 轮已按此修完并实测：`why-effort-fails` → 0 错误 / 1 提醒（就是那句不适用）/
退出码 0；`keynote-baseline`（启用预设）→ 0 错误 / 0 提醒，正确作品上依旧不出噪音。
**那条前置闸门已经具备**：缺字机检（`a2v/fonts.py` ＋ 体检里的字体覆盖检查）
逐个字符查字体自己的 `cmap`，缺了就报错并指到 `sceneId.字段`，进错误数与退出码。
所以现在按作品子集化这件事可以做了：切完之后缺字会被机检抓住，而不是悄悄回退。
「切」本身已实现：`prepare.py --subset-fonts <源字体>` 走可选依赖（`uv sync --extra fonts`），
按 `fonts.charset_for` 取本作品用字切出子集落在 `outputs/<slug>/`，源字体只读，
切完立刻用缺字机检判覆盖；实测 `never-fear-interviews` 86 个字符 → **39KB**（源 16.9MB，
约 1/440），三支作品都切过且都不缺字，默认链路重渲 12 帧哈希仍是 `CBEBD8BF…`。
实现手段当初是这样探清的：**子集化需要字形子集工具**
（从头手写 TTF 子集器要重建 glyf/loca/cmap/hmtx，不现实），
`fontTools` **不是**项目现有依赖，但 `uv run --with fonttools python -c "from fontTools import subset"`
可以按需装起来用（实测「subset 可用」，需要网络）。
因此建议的形状是：把子集化做成**可选依赖组**（例如 `[project.optional-dependencies] fonts`）
加 `prepare` 时的一个开关，而不是塞进默认链路——默认渲染保持完全离线可跑，
装了才切；切出来的子集照旧被缺字机检盯着（这就是它作为前置条件的意义）。

**成片的溯源已经补上**（第 8 轮实测踩到、第 10–15 轮做完）：
渲染成功后落 `<名字>.provenance.json`（页面、分镜、被引用资产的指纹、帧数、
分辨率、帧率、采集格式、渲染时刻），体检命令据此回答
「这个成片是不是旧资产渲的」：`current` 对得上 / `stale` 落后并**指名是哪几个文件变了** /
`unknown` 无法判断（没有溯源、旧格式、网页已不在——不默认放行）。结论只提示、
不参与错误数与退出码。真实作品上三条都验过：旧成片报无法判断，改一行
`vendor/spring.js` 后报落后并指名，重渲后报对得上。
实现里两处细节是实测逼出来的：指纹**只覆盖被引用的资源**（改一个用不到的图形
不得报落后，否则闸门沦为噪音），以及**文本资产按 LF 归一化后哈希**——
git 的换行归一化会静默翻转行尾，否则会出现人怎么重渲都消不掉的假落后
（指纹口径因此升级，溯源带 `version`，旧版本判「无法判断，请重渲」）。

**逐帧看出来的观感缺口**（记录事实，不要当成已解决；三条猜想已被量测证伪，见下）：

- **结构性描边的判定要跟着用途走，不能跟着取值走。** 上一轮把 `.scale-rope`
  （吊着两个秤盘的绳）按「它是细的」归成装饰描边，深色下只有 1.63:1，
  逐帧看时横梁像浮在空中。本轮已改成结构描边（`--fig-line-data`），
  并新增**边界描边 ≥ 3:1**（判据基座是它落座的抬升面）覆盖
  「一个物体唯一可见的边界」——`.drop-track` 的槽填充只有 0.03 白，
  边框是这根竖尺唯一能被看见的边界，现在用 `--a2v-hairline-strong`。
  剩下的同类判断：卡片与面板的边框**刻意**留在装饰档（身份由填充 + 圆角 +
  投影共同界定），这条豁免写进了测试。
- **动效从来没有进过机检，于是「3 帧弹跳」活了很久。** 本轮逐帧量第 1 幕标题的
  58px 入场：旧实现第 1 帧走完 44%、第 3 帧走完 97%，之后只剩 0.76px 的过冲，
  而代码注释写着「约 0.6 秒收敛」——观众看到的是带残影的硬切。
  根因不是参数没调好，而是**两条曲线串起来**：`spring()` 收到的是已经缓动过的进度，
  所以它的 `damping` / `frequency` 两个参数都不再是物理量，整条曲线的时间尺度
  由外面那条 `outQuint` 决定。现在曲线换成 vendored 的阻尼谐振子闭式解
  （`assets/vendor/spring.js`，wobble 1.5.1 · MIT），参数改成 `response`（自然周期）
  与 `dampingFraction`（阻尼比）——只决定快慢、只决定过冲，互不干扰。
  实测新入场：第 6 帧走 2.6%、第 13 帧到 90%、过冲 0.09px（0.16%，理论 0.15%）、
  第 19 帧正好停在 0。并且第一次有了能看见动效的乐器
  （`tests/test_motion_trajectory.py` 逐帧读位移），"第一帧不许走完 25%"这条
  就是专门拦这次这种退化的。
  **已经固化**：轨迹机检不再只盯第 1 幕标题——`tests/test_motion_trajectory.py`
  会逐帧走完参考实现的 8 幕，用元素身份收集每一个入场元素（基准示例共 **90 个**），
  逐个核对「落地距幕尾 ≥ 12 帧」「落地前不透明度不回退」，其中**有位移的 9 个**
  还要满足「首帧不透明度 ≤ 25%」「到 0.9 至少 6 帧」。实测分布说明为什么
  速度判据只跟着位移走：另外 81 个是纯淡入（逐字揭示的单字符 2 帧、
  小标注与箭头 2–5 帧），一刀切只会把刻意做法判成缺陷。
  文件里还带一个反例：把入场整体加速 8 倍后重扫，闸门必须报错——
  实测加速后首帧不透明度跳到 0.855、到 0.9 只剩 1 帧，证明它抓的是对的信号
  （而不是「因为没量到而通过」）。
  **也已经进了验收流程**：量测实现搬进 `scripts/a2v/motion.py`，由
  `tests/test_motion_trajectory.py` 与 `review.py` 共用一份；`report.json` 多一个
  `motion` 段，终端多一栏 M0–M4。三支作品实测（全部 M0–M4 通过）：
  基准示例 90 个入场元素（9 个有位移）、`videos/never-fear-interviews` 99 个（6 个）、
  `examples/why-effort-fails` 62 个（6 个）；最小落地余量分别是 25 / 55 / 48 帧。
  动效结论与「不是废片」类错误分开计，**不改退出码**——「入场快了一点」不是
  「画面坏了」；严格判定留在测试里。
  M0 会把「采样被上限截断」的入场报出来（轨迹不完整就不该算进覆盖），
  但刻意停在部分不透明度的装饰（光晕、火花、引号、注脚）与脉动明暗不在此列：
  这里判的是内容入场的快慢与落地，不是光晕什么时候亮。
  **仍然开放**：动效结论目前只到「量得准」，还没有「该不该这么动」的判断
  （例如某个入场是否显得多余），这仍然归人与视觉模型。
  另外那次扫描踩过两个坑，都写进了代码注释：在 seek 之前取元素集合会拿到空列表
  （第一版只覆盖第 0 幕却报「全部通过」）；SVG 的 `className` 是
  `SVGAnimatedString`，`String()` 之后所有 SVG 元素塌成同一个 key
  （第一版量出的「两幕零入场元素」是假的）。
- **面填充的量级已经查清：三档按性质分家，不给实心物体单独加重。**
  查的方式是看全分辨率实测帧（不看缩略联系表）：`freedom` 的台阶柱读作
  「细描边 + 耳语填充」，形状毫无歧义；`attention` 的冰山图里**水上尖端是
  耳语填充、水下主体是冷色实心**——这个差就是那张图的语义，给实心物体加重
  填充不是「变得更实」，而是把刻意做出来的层级抹平。
  三档的区分本来就是**性质**而不是幅度：实心面取该主题的亮度阶（中性）、
  次级面（水体）是唯一的冷色透明面、空壳是耳语级。
  所以机检只判关系不判幅度（`tests/test_figure_contrast.py`）：
  实心面不等于画布、三档不塌成同一个取值、次级面带冷色色相；
  三条都用变异测试验过（水体改成实心面 / 实心面改成画布色 / 水体改成中性灰，
  分别报出对应的原因）。
  **已知边界**：实心面等于抬升面（浅色主题都是 `#ffffff`，深色主题两者只差
  1.01:1），所以画在面板**上**的实心物体没有面阶，识别由描边承担——
  这是接受的取舍，面板本身已经与画布分开。

**已被量测证伪的三条猜想**（留在这里，避免下一轮重新怀疑一遍）：

- ~~「旧弹簧的形状也还算个弹簧，把参数拟合一下就行」~~：用线性输入的解析弹簧
  去拟合旧曲线，最大偏差约 **0.49**——旧形状（主要是 `outQuint` 加一点过冲包）
  在数学上不是一个弹簧。所以本轮不是拟合旧形状，而是让弹簧真的成为那条曲线。
- ~~「`viewBox` 缩放会把 4px 的描边压成头发丝」~~：实测所有 SVG 描边的
  `getScreenCTM` 缩放比**都是 1**，声明宽度就是渲染宽度。当时的「细得像发丝」
  其实是对比度问题。
- ~~「留白达标但内容重心偏上，下三分之一空着」~~：`opening` 一幕的内容落在
  安全区 240–1600 之间的 510–1350，上下留白 270 / 250——是**居中**的。
  画面下方那 320px 本来就是平台的界面保留带。

- ~~「把组件里三处裸字号包成令牌更规范」~~：它们在字阶上，而且
  `test_keynote_assets.py::test_bare_font_size_must_be_on_the_scale` 早就管着
  同一件事，那条判据的文档还写明「阶上的裸值再包一层只是噪音」。
  包成令牌之后它的防空转断言立刻报警——报警说明改动多余，已整体回退。
  第十九轮的教训是**先找判据，再改代码**：只搜了一个测试文件的属性表，
  就以为没人管。
- ~~「`compare` 一幕的墨迹偏上 14%，说明版式没居中」~~：那个量（墨迹包围盒）
  会被图形容器自己的空白与某一帧里尚未淡入的元素污染。改量块栈后，
  块栈中心与安全区中心只差 **1px**，卡片内文字上下留白 107 / 108px。
  量错了对象，不是版式错了。

- ~~「冻结的 `#4a4a4a` 混色端点在预设的**浅色**主题下会出错」~~：实测反了。
  浅色主题的墨色本来就深，那个深灰端点碰巧对（8.89:1）；出问题的是**深色**主题
  ——它的墨色是浅的，混向深灰把未点亮的文字压到 2.26:1（40px 门槛 3:1）。
  预测写进文档的当天就被自己的实测推翻，所以记在这里。
- ~~「天平图的光晕卡在 28%，整幕都不亮」~~：量错了幕。`glow` 在幕内 66% 起跳，
  而天平图属于 `opening` 幕，我 seek 的是 `compare` 幕——`querySelector` 取到的
  元素停在局部第 0 帧，于是恒为 28%。光晕一直在动（78% → 92% 从 28% 跳到 80%）。

- ~~「上一轮把天平图文字的对比度修好了（7.23:1）」~~：那个数是拿
  `--fig-surface`（画布级的面令牌）当背景量的，而文字真正坐着的是
  `.load-token`（`data-a2v-state="focus"`，填充 `--a2v-accent-soft-solid`）。
  换成量真面之后，浅色主题下是 **1.07:1**——深蓝字压深蓝面，截图里肉眼可见。
  量对了对象，才看出根因是设计层没定义"重点面上用什么墨色"。

## 已完成的实际文章

路线之外，用一篇完整的实际文章验证了整条链路与视觉方向的自由度：

### `videos/never-fear-interviews/`（《永远不要害怕面试》）—— 已完成

目录规范落地后的第一支实际视频，八幕 2160 帧原长，按配音派生为 2189 帧 / 73.0 秒，
1080 × 1920 / 30fps 有声导出。它验证了两件事：

1. **风格方向可独立于运行时**：只覆盖 `theme.css` 的令牌与页面自身的构图，
   在不改 `timeline.js` 的前提下把「深色科技」换成「编辑杂志」（暖灰白底 + 墨黑衬线
   + 单一朱红强调 + 收敛投影），证明视觉方向确实由每支视频的网页决定；
2. **场景分支可以按内容扩展**：示例只实现了 `title` / `quote` / `comparison` /
   `diagram` / `conclusion`，本篇补上 `list` 与 `timeline` 两个分支，
   行与步骤结构由分镜的 `items` 动态生成，网页不重复维护文案。

排版上的两条实测结论（已写进 `index.html` 注释，供后续视频复用）：

- 硬换行之外还要按「每行可用宽度 888px」反推字号：衬线字体下单字宽约 1.02 × 字号，
  14 字一行必须降到 66px 才不会折成第四行；
- `emphasis` 由共享组件渲染成 `<span class="key">`（金句幕另挂 `.key-underline`），
  页面必须为 `.key` 提供颜色样式，否则强调只会「不报错地不生效」。
- 浅色主题要另行覆盖 `.a2v-subtitle`：`base.css` 的默认字幕是面向深色主题的
  白字 + 深描边，压在米色底上几乎读不出来。

## 多篇文章的目录与产物

项目要长期维护多篇文章，因此目录与产物位置是稳定约定而非临时安排：

```text
videos/<slug>/{article.md, storyboard.json, [index.html]} # 专属网页可选，源文件入 Git
outputs/<slug>/{silent.mp4, voiced.mp4, voiced.srt, media/, previews/}
outputs/examples/<slug>/                                   # 示例产物独立一层
```

`prepare.py`、`render.py` 的输出参数改为可选：从输入文件位置向上定位含
`.agents/skills/article2video/SKILL.md` 的项目根，再识别 `videos/<slug>/` 或
`examples/<slug>/`，推导出对应产物路径；渲染以本地网页确定归属，配音以分镜确定归属，
结果与执行命令时的工作目录无关。非规范目录、远程网页或无法识别项目时直接报错并要求
显式指定路径，不猜测归属。显式 `--out`、`--out-dir` 始终优先，原有调用保持兼容；
同类重复导出覆盖固定的 `silent.mp4` / `voiced.mp4`，限帧试渲染只写 `previews/`。

已实现并验证：两篇文章输出相互隔离、示例与实际文章同名时产物分离、不同工作目录下推导一致、
显式路径兼容、限帧输出不覆盖正式成片，以及无法推导时给出明确错误。
规则以 [目录约定与输出路径](../.agents/skills/article2video/references/paths-and-outputs.md)
为权威来源。示例产物已迁入 `outputs/examples/why-effort-fails/`，媒体目录整体移动后清单与
资源引用保持有效。

- **动效时长还没接回设计层**：`figures.js` 的 49 处 `api.progress` 里，
  时长参数有 20 个取值、混用「帧数」与「场景占比」两种单位；设计层的
