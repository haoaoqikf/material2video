# 项目规划

本文记录 article2video 的方向与阶段路线。**已实现的能力以 README 的当前状态为准**，
本文中标注「规划中」的部分不代表已有实现。

## 使用场景与表达原则

面向个人 IP 的观点型抖音内容，输入一篇文章，把「抽象观点 + 核心判断」转为信息可视化短视频。
例如：约束与反馈、复利、上场次数、学习先建立结构、复杂问题拆分，以及低频高收益的成功事件。

表达原则是「思想不断变深，表达不断变浅」：保留核心判断和必要推理，通过场景与动画降低理解门槛。
文章可以压缩和改写，但不得虚构论据或扭曲原意；没有来源的数值与图表必须明确标为示意，
不能当作实测结果。

## 落地形态：项目级 Skill

项目最初的设想是「AI 每次自由写网页」或「AI 只挑选固定组件」。实际落地时收敛为第三条路径：

> **AI 写网页，但必须满足一份确定性渲染契约；渲染由脚本完成，不由 AI 完成。**

这样做的好处是：视觉表达不受组件库限制（AI 可以自由设计每支视频的构图与气质），
同时导出过程完全可复现（同一帧永远渲染出同一画面）。

Skill 位于 `.agents/skills/article2video/`，被 Codex 与 DSH 识别为项目级 skill；
内容分工为：

| 部分 | 职责 |
| --- | --- |
| `SKILL.md` | 工作流主文档：从文章到成片的步骤与排查手册 |
| `references/` | 渲染契约、分镜结构、竖屏视觉规范、目录与输出路径 |
| `assets/` | 共享基础样式、设计令牌（`base.css` / `theme.css`）、可选的设计语言层（`keynote.css` / `typography.js` / 随仓库分发的字体）与时间轴运行时 |
| `scripts/` | 校验、配音准备、预览、渲染、视觉评审五个命令行工具 |

因此「可复用的视觉语言」不再体现为固定的 Scene 组件类，而体现为
**共享的运行时 + 契约 + 视觉规范 + 设计令牌**；常规构图由分镜选择受控组件与布局，
特殊构图仍可由每支视频的专属网页决定。
视觉方向的选择（深色科技 / 编辑杂志 / 极简高级）目前仍由人或 AI 工具判断，
自动化属于规划中的能力。

## 目标处理链路

```text
文章
 → 内容理解与压缩          ← 已实现：按文章生成分镜规范执行（由 AI 工具完成，无生成器程序）
 → 分镜规划和视觉语言选择   ← 已实现：同上，规范见 references/article-to-storyboard.md
 → 结构化脚本 JSON          ← 已实现：storyboard.json（校验规则已落地）
 → HTML / CSS / JS 场景渲染 ← 已实现：共享声明式页面或专属网页 + 共享运行时
 → 时间轴动画编排           ← 已实现：帧驱动，禁止 CSS 动画
 → TTS 配音与字幕时间对齐   ← 已实现：edge-tts + 字词时间戳分句
 → 逐帧渲染与音视频合成     ← 已实现：可选 AAC 配音与字幕烧录
 → 竖屏视频                ← 已实现：1080 × 1920 / 30fps / H.264
```

网页预览与最终导出使用相同的场景内容和时间轴，这一点已经落实：
预览与渲染共用同一份分镜 JSON，预览只做整体缩放，不改变内部布局。

示例输入约 500 字，示例输出为 9:16、1080 × 1920、30fps、45 秒。文章字数不是配音时长承诺：
需根据目标时长压缩口播文案，或随配音调整总时长。

## 视觉组件候选

下表是**内容到视觉的映射建议**，供 AI 规划分镜时参考，不是必须遵守的枚举。

现已实现的组件与它们的适用场景，以
[视觉组件目录](../.agents/skills/article2video/references/figure-catalog.md) 为权威来源，
本文不重复维护一份可能漂移的副本。下表只保留尚未实现的方向：

| 组件 | 脚本类型 | 适用内容 | 状态 |
| --- | --- | --- | --- |
| TitleScene | title | 开场命题、主题 | 已实现（`balance`） |
| QuoteScene | quote | 核心判断、金句 | 已实现（`gap`） |
| ComparisonScene | comparison | 两种选择、前后对照 | 已实现（`versus`） |
| TimelineScene | timeline | 事件顺序、尝试过程 | 已实现（`stairs`） |
| DiagramScene | diagram | 因果、约束、反馈模型 | 已实现（`loop`） |
| ConclusionScene | conclusion | 收束、行动建议 | 已实现（`exchange`） |
| ListScene | list | 要点、行动步骤 | 已实现（`iceberg`） |
| NumberScene | number | 数量、频次、收益变化 | 已实现基础数字组件 `number`；复杂数值图表仍待扩展 |

校验器认识这八种类型并对必填字段做检查；出现新类型时给出警告而非错误，
以便扩展，但对应网页必须实现该类型的渲染分支。

## 分镜脚本

分镜 JSON 的字段定义、示例与校验规则以
[分镜脚本结构](../.agents/skills/article2video/references/storyboard-schema.md) 为权威来源，
本文不再重复维护一份可能漂移的副本。

要点：

- 场景时长用帧数表达（`durationInFrames`），起始帧由累加推导，不手写；
- 场景展示文案与口播文案允许不同：画面呈现关键结构，口播补充解释与例子；
- `narration` 用于可选配音准备；有声预览与导出共用媒体清单中的时长和字幕，省略 `--media` 时不渲染口播。

## 分阶段路线与验收目标

### 第一阶段：动画网页与统一时间轴 —— 已完成

用人工编写的示例脚本，完成竖屏网页场景与统一时间轴，支持播放、暂停、重播与拖动。

验收结果：示例 5 幕 1350 帧完整播放；中文排版在安全区内、无溢出；场景切换正确；
同一帧重复渲染逐字节一致（已作为自动化测试固化）。

### 第二阶段：视频导出 —— 已完成（无声）

建立可重复的按时间取帧与视频编码流程，导出无声视频，保持网页预览与导出的一致性。

验收结果：导出视频可播放；尺寸 1080 × 1920、30fps；总时长符合脚本（1350 帧 = 45 秒）；
渲染后自动解码复核帧数与分辨率；字体使用系统栈，换机器可能轻微影响字宽（见视觉规范）。

### 第三阶段：配音字幕同步 —— 已实现

通过 edge-tts 按场景生成配音，用字词时间戳结合标点生成逐句字幕；媒体清单记录派生时长，
场景随配音延长且保留原最短时长。预览使用统一 WAV 音轨驱动画面，导出按帧烧录字幕、
合入 AAC 配音并输出 SRT。配音按文本、音色、语速和生成器版本缓存。

验收：自动化测试覆盖缓存、异常、时间轴、字幕排版、预览控制和音视频合成；
五幕示例真实合成并完成全量导出，原 45 秒延长为 46.27 秒，末尾配音未截断。
首次配音实测 13.3 秒，五幕全缓存准备约 0.1 秒；结果依赖在线服务与本机性能。
背景音乐本次不实现，后续另行规划。

### 第四阶段：视觉与动效基线 —— 已实现

把「高级感」从个人手感变成可复用、可校验的规范，避免每支视频各写一套风格：

- `assets/theme.css` 提供设计令牌（背景 / 表面 / 文字三级色阶 / 强调色 / 阴影 /
  圆角 / 节奏）与三个背景层工具类，只定义变量，不覆盖既有画面；
- `timeline.js` 补齐纯函数动效原语：`spring`（闭式弹簧，第七阶段换成物理参数并引入
  vendored 求解器）、`range`（数值映射）、`breath`（常驻微动）、`drawPath`（SVG 描边）、
  `revealChars`（逐字揭示）；
- `references/visual-spec.md` 增补排版层级表、三层景深做法、动效配方与三套风格方向；
- 视觉规则可执行化：`validate.py` 检查单行字数、场景过短、强调短语不生效；
  `render.py` 开渲前静态扫描 `animation:` / `transition:` / `@keyframes`；
- 示例网页按该规范重做，作为观感基线。

验收：示例 5 幕 1350 帧按新规范渲染，逐帧确定性测试（同帧与跨会话逐字节一致）
继续通过；新增原语与校验规则的测试全部落地。
尚未实现：AI 自动选择视觉风格。webfont 分发与系统字体栈的取舍在第七阶段落地
（启用 `visual.preset` 时改用随仓库分发的可变字体，默认路径仍是系统字体栈）。

### 第五阶段：视觉组件库与设计系统 —— 已实现

目标：把「AI 做导演，不做设计师」变成结构上成立的事——AI 从现成组件里挑、
给标注、指定节奏，而不是每次从零画一遍。

- `assets/figures.js` + `figures.css`：七个视觉组件（`balance` / `gap` / `versus` /
  `iceberg` / `loop` / `stairs` / `exchange`），每个自带 DOM 与样式，
  只从分镜读文案与标注，页面只声明挂载点；
- `A2V.motion` 动效配方层：入场配方（`surface` / `figure`）、具名弹性
  （`enter` / `firm` / `lively` / `snap`）、常驻微动周期、节奏换算，
  手感参数只写在 `timeline.js` 一处；
- 节奏系统：分镜写 `calm` / `normal` / `impact`，运行时把幕内比例点整体缩放；
- `scripts/a2v/catalog.py` + `references/figure-catalog.md`：组件目录与它的服务端镜像，
  校验器据此判断 kind 是否存在、标注键是否认识、条目数是否超容量；
- `references/design-constitution.md`：十四条规则，每条标注**能不能机检**；
- `scripts/review.py`：视觉评审工具——组件契约探针（声明的标注是否真的画出来）、
  帧量测（墨迹覆盖率与安全区）、宪法静态检查，产物为联系表与 `report.json`；
- `references/visual-review-rubric.md`：六项 60 分制量表，机检保证「不是废片」，
  人工（或视觉模型）判断「值不值得看完」。

验收：`uv run pytest` 319 项通过；《永远不要害怕面试》与示例
`examples/why-effort-fails` 都只声明挂载点，同一套组件在浅色与深色两套主题下
都能成立；`review.py` 在两者上均 0 错误。

尚未实现：生成器程序与模型调用（见第六阶段）；组件库的完整换肤
（仍有若干装饰性渐变写死在 `figures.css` 里）。

声明式画面路径已补齐：新作品可由分镜从组件目录中挑选受控组件，并声明深浅主题与预设布局，
由共享页面完成预览和渲染，不必为每篇文章编写 `index.html`。这一步复用现有
帧驱动运行时和七个已有组件，并加入基础数字组件；自动生成分镜仍属下一阶段。

### 第六阶段：文章生成分镜 —— 已实现（规范落地，无生成器程序）

把「文章 → 分镜」这一步从手工编写变为**可复核的生成流程**：步骤、判断顺序、内容与排版约束、
组件目录不足时的处理，以及生成后必须走完的校验闭环，统一写在
[文章生成分镜](../.agents/skills/article2video/references/article-to-storyboard.md)，
由 AI 工具按规范执行；`SKILL.md` 的标准流程第 1 步与 `README` 指向该规范。

验收结果：规范覆盖输入输出契约、拆幕与时长规则、内容忠实与视觉受控、排版与标注约束、
组件缺口处理与校验闭环；生成结果以 `validate.py --declarative --strict` 零错误零警告为准，
并用 `review.py --declarative` 的组件契约探针确认声明的标注真的画了出来。
本阶段的落实方式是**规范而非程序**：没有内置生成器、不调用模型服务、不做批量生成；
生成质量仍按下限交给机检、按「值不值得看完」交给人评。

尚未实现（本阶段之外的遗留项）：生成器程序与模型调用、批量生成、AI 自动选择视觉风格。

### 第七阶段：发布会级设计语言与观感闸门 —— 设计语言层已实现，自动评审仍待做

目标：把「发布会级别的画面」从手感变成可机检的约束，并让它与「是不是废片」分开判定。

- `assets/keynote.css`：设计语言层，由分镜根级 `visual.preset: "keynote"` 显式启用。
  模块化字号阶 8 档（caption 28 / label 34 / body 40 / lead 60 / title 76 /
  headline 96 / display 120 / hero 140，单位 px；正文下限 36px；每档配对行高与字距）、
  8pt 间距阶（4 / 8 / 16 / 24 / 32 / 48 / 64 / 96 / 128 / 192）、五个圆角档 + pill、
  三级阴影、12 列网格（内容宽 888px、槽宽 24px），以及 `keynote-dark`
  （bg `#08090c`、强调 `#32d6ff`）与 `keynote-light`（bg `#eff1f4`、强调 `#0a6ad9`）
  两套主题；对比度预算为正文 7:1、大字与图形 4.5:1，图形再按四类细分
（数据描边 / 图形内文本 / 装饰描边 / 面填充，见
`tests/test_figure_contrast.py` 的分类表）；
- `assets/fonts/`：Inter Variable 与 Noto Sans SC Variable（SIL OFL 1.1）随仓库分发，
  不走 CDN；字体栈只在预设作用域里覆盖 `--a2v-font`，因此未启用预设的页面仍用系统字体栈；
- `assets/typography.js`：可选排版引擎 `A2V.type`，不属于 `window.__A2V__` 渲染契约，
  未启用预设时不会被调用。组件用 `data-a2v-fit="<档位>"` 声明字号上限档位，
  共享页面在预设生效时按实测可用宽度取档、按宽度均衡断行、到 36px 正文下限即停；
  行高、字距、字重仍归组件，字号归字阶；未声明的元素不会被改动；
- `scripts/a2v/keynote.py`：观感闸门 K1–K7 的计算与结果结构（`Gate` / `KeynoteResult`），
  与废片类 C 系列**分开计分**；其中 K7 文字溢出是**硬判定**，失败会并入体检错误数与
  退出码。`inspect.py` 的帧量测扩到 540 × 960 的探针画面，
  并收集字号、文本样张、卡片特征、文本块四边墨迹边界与安全区几何；
- `examples/keynote-baseline/`：8 幕 / 2040 帧 / 68 秒 / 1080 × 1920 @30fps 的参考实现；
- 测试：`tests/test_keynote_assets.py`（令牌自检、对比度、`--fig-*` 覆盖、预设作用域、
  组件墨色字号收进字阶）、`tests/test_figure_contrast.py`（图形颜色分类表、每类的对比度
  预算与判定基座、两套主题分别核对、`fill`/`stroke`/`background` 不许写字面色值、
  边界描边令牌必须真的被引用、纯分隔线必须保持耳语）、
  `tests/test_offline_assets.py`（资产不许引外部 URL、
  `url()` 必须指向仓库内真实文件、断网渲染可跑通）、`tests/test_keynote_layout.py`
  （浏览器里实测安全区、字号阶与四种版面的几何）、`tests/test_typesetting_apply.py`
  （取档不破坏强调标记、退化输入、重复取档零写入）、`tests/test_typesetting_wiring.py`
  （引擎真的接上了、取到的档位与字阶一致、非预设页面零取档）
  与 `tests/test_review.py` 的 K 系列指标与闸门用例。

验收：`examples/keynote-baseline` 上 `validate.py --declarative --strict` 零错误；
`review.py --declarative` 的 C 系列 24 帧抽检 0 错误 0 提醒，K 系列 38 通过 / 7 提醒 /
0 失败 / 11 跳过（跳过项均写明原因，主要是「这一幕没有卡片表面」与「正文级文本块不足两个」）；
K7 的负例（注入 350 字副标题）报「越出安全区：「title-text」上越界 285.2px」、
错误数 1、退出码 2；
未启用预设的页面仍然不加载档位（由 `tests/test_typesetting_wiring.py` 守住），
但**成片的字节一致性哈希在本轮被刻意重新记录**：改的是动效曲线，画面里每个入场元素的
位置都变了，所以这个哈希不再只是「样式有没有被动过」的证明——
它是用「回退到 HEAD 的资产再渲一次」证明差异只来自动效的。新旧哈希：
`--capture-format png` → `A0A94CFC…`（原 `DAFDD423…`）／默认 → `CBEBD8BF…`（原 `DF1DB75D…`）；
命令要连哈希一起记，否则复现不出来。
预设页面的 8 幕共 24 帧在「剥掉档位声明」的加载下逐像素一致。

图形颜色的预算与实测（见
[发布会级设计语言](../.agents/skills/article2video/references/keynote-design-system.md)
的分类表）：深色／浅色两套主题下，数据描边 5.69 / 5.22（`--fig-line`）与
7.75 / 7.42（`--fig-line-data`），水体描边 4.82 / 5.23，图形内文本 8.06 / 7.22，
装饰描边 1.63 / 1.63，边界描边 3.32 / 3.09（对抬升面），
纯分隔线 1.65 / 1.24 刻意保持耳语并豁免于 WCAG 1.4.11；面填充不设数值下限。
改动前浅色主描边只有 3.31:1、
水体描边 1.89:1、图形内文本 3.73:1，深色水体描边 3.23:1，全部低于 README 承诺的
图形 4.5:1；更隐蔽的是 `figures.css` 里写死的浅色页取值（`.load-hollow` 的填充、
`.drop-track` 与 `.drop-fill` 的槽和柱），在深色预设下与底色同色，
「看着很大其实没有重量」的空壳只剩虚线、一幕「差量」只剩虚线框。
两者现在都由 `tests/test_figure_contrast.py` 守住，并且是**逐帧打开确认过**的：
35% 处左栏出现清晰的实心柱，96% 处抽干后只剩底下一线 + 虚线幽灵框 + 差额括号；
`opening` 一幕的天平吊绳改走结构描边后重新可见，横梁与秤盘之间的关系不再断。

尚未实现：视觉模型自动评审（K 系列只给数值，最终判断仍要人看
[视觉评审量表](../.agents/skills/article2video/references/visual-review-rubric.md)）、
webfont 子集化（Noto Sans SC Variable 约 17MB）、按内容自动选预设（必须显式声明）、
K6 对「整幕没有卡片」只报跳过、不判断「这一幕本该有卡片」，
以及自动拆场景（引擎能算出「缩到正文下限仍放不下」并由 K7 报出来，但拆幕仍由人决定）。

**逐帧看出来的观感缺口**（记录事实，不要当成已解决；三条猜想已被量测证伪，见下）：

- **结构性描边的判定要跟着用途走，不能跟着取值走。** 上一轮把 `.scale-rope`
  （吊着两个秤盘的绳）按「它是细的」归成装饰描边，深色下只有 1.63:1，
  逐帧看时横梁像浮在空中。本轮已改成结构描边（`--fig-line-data`），
  并新增**边界描边 ≥ 3:1**（判据基座是它落座的抬升面）覆盖
  「一个物体唯一可见的边界」——`.drop-track` 的槽填充只有 0.03 白，
  边框是这根竖尺唯一能被看见的边界，现在用 `--a2v-hairline-strong`。
  剩下的同类判断：卡片与面板的边框**刻意**留在装饰档（身份由填充 + 圆角 +
  投影共同界定），这条豁免写进了测试。
- **动效从来没有进过机检，于是「3 帧弹跳」活了很久。** 本轮逐帧量第 1 幕标题的
  58px 入场：旧实现第 1 帧走完 44%、第 3 帧走完 97%，之后只剩 0.76px 的过冲，
  而代码注释写着「约 0.6 秒收敛」——观众看到的是带残影的硬切。
  根因不是参数没调好，而是**两条曲线串起来**：`spring()` 收到的是已经缓动过的进度，
  所以它的 `damping` / `frequency` 两个参数都不再是物理量，整条曲线的时间尺度
  由外面那条 `outQuint` 决定。现在曲线换成 vendored 的阻尼谐振子闭式解
  （`assets/vendor/spring.js`，wobble 1.5.1 · MIT），参数改成 `response`（自然周期）
  与 `dampingFraction`（阻尼比）——只决定快慢、只决定过冲，互不干扰。
  实测新入场：第 6 帧走 2.6%、第 13 帧到 90%、过冲 0.09px（0.16%，理论 0.15%）、
  第 19 帧正好停在 0。并且第一次有了能看见动效的乐器
  （`tests/test_motion_trajectory.py` 逐帧读位移），"第一帧不许走完 25%"这条
  就是专门拦这次这种退化的。
  **仍然开放**：轨迹机检只盯第 1 幕标题这一个入场元素——所有组件共用同一条曲线，
  所以它能拦住「配方层面的退化」，拦不住「某个组件把起始帧或距离算错了」。
- **面填充的量级还没有结论。** 深色 `--fig-surface`（`#171e2b`）对画布 1.19:1、
  浅色 `#ffffff` 对 `#eff1f4` 1.13:1，而 `--fig-surface` 是「实心物体」
  （阶梯柱、节点圆盘、实心块）的填充——这些物体目前主要靠 4px 描边被认出来。
  要不要给「实心物体」的填充单独定一档（区别于冰山水体那样的次级面），
  需要先看清它跟「线框感」的关系，不要凭「1.19 看着太低」就设阈值：
  浅色主题自己的面阶就只有 1.13:1，设错阈值会把正确做法判成缺陷。

**已被量测证伪的三条猜想**（留在这里，避免下一轮重新怀疑一遍）：

- ~~「旧弹簧的形状也还算个弹簧，把参数拟合一下就行」~~：用线性输入的解析弹簧
  去拟合旧曲线，最大偏差约 **0.49**——旧形状（主要是 `outQuint` 加一点过冲包）
  在数学上不是一个弹簧。所以本轮不是拟合旧形状，而是让弹簧真的成为那条曲线。
- ~~「`viewBox` 缩放会把 4px 的描边压成头发丝」~~：实测所有 SVG 描边的
  `getScreenCTM` 缩放比**都是 1**，声明宽度就是渲染宽度。当时的「细得像发丝」
  其实是对比度问题。
- ~~「留白达标但内容重心偏上，下三分之一空着」~~：`opening` 一幕的内容落在
  安全区 240–1600 之间的 510–1350，上下留白 270 / 250——是**居中**的。
  画面下方那 320px 本来就是平台的界面保留带。

完整说明见

## 已完成的实际文章

路线之外，用一篇完整的实际文章验证了整条链路与视觉方向的自由度：

### `videos/never-fear-interviews/`（《永远不要害怕面试》）—— 已完成

目录规范落地后的第一支实际视频，八幕 2160 帧原长，按配音派生为 2189 帧 / 73.0 秒，
1080 × 1920 / 30fps 有声导出。它验证了两件事：

1. **风格方向可独立于运行时**：只覆盖 `theme.css` 的令牌与页面自身的构图，
   在不改 `timeline.js` 的前提下把「深色科技」换成「编辑杂志」（暖灰白底 + 墨黑衬线
   + 单一朱红强调 + 收敛投影），证明视觉方向确实由每支视频的网页决定；
2. **场景分支可以按内容扩展**：示例只实现了 `title` / `quote` / `comparison` /
   `diagram` / `conclusion`，本篇补上 `list` 与 `timeline` 两个分支，
   行与步骤结构由分镜的 `items` 动态生成，网页不重复维护文案。

排版上的两条实测结论（已写进 `index.html` 注释，供后续视频复用）：

- 硬换行之外还要按「每行可用宽度 888px」反推字号：衬线字体下单字宽约 1.02 × 字号，
  14 字一行必须降到 66px 才不会折成第四行；
- `emphasis` 由共享组件渲染成 `<span class="key">`（金句幕另挂 `.key-underline`），
  页面必须为 `.key` 提供颜色样式，否则强调只会「不报错地不生效」。
- 浅色主题要另行覆盖 `.a2v-subtitle`：`base.css` 的默认字幕是面向深色主题的
  白字 + 深描边，压在米色底上几乎读不出来。

## 多篇文章的目录与产物

项目要长期维护多篇文章，因此目录与产物位置是稳定约定而非临时安排：

```text
videos/<slug>/{article.md, storyboard.json, [index.html]} # 专属网页可选，源文件入 Git
outputs/<slug>/{silent.mp4, voiced.mp4, voiced.srt, media/, previews/}
outputs/examples/<slug>/                                   # 示例产物独立一层
```

`prepare.py`、`render.py` 的输出参数改为可选：从输入文件位置向上定位含
`.agents/skills/article2video/SKILL.md` 的项目根，再识别 `videos/<slug>/` 或
`examples/<slug>/`，推导出对应产物路径；渲染以本地网页确定归属，配音以分镜确定归属，
结果与执行命令时的工作目录无关。非规范目录、远程网页或无法识别项目时直接报错并要求
显式指定路径，不猜测归属。显式 `--out`、`--out-dir` 始终优先，原有调用保持兼容；
同类重复导出覆盖固定的 `silent.mp4` / `voiced.mp4`，限帧试渲染只写 `previews/`。

已实现并验证：两篇文章输出相互隔离、示例与实际文章同名时产物分离、不同工作目录下推导一致、
显式路径兼容、限帧输出不覆盖正式成片，以及无法推导时给出明确错误。
规则以 [目录约定与输出路径](../.agents/skills/article2video/references/paths-and-outputs.md)
为权威来源。示例产物已迁入 `outputs/examples/why-effort-fails/`，媒体目录整体移动后清单与
资源引用保持有效。
