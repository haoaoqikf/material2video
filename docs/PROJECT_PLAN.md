# 项目规划

Material2Video（材料成片）以统一制作底座承载独立视频类型。发展顺序是：先把金融时间序列等专用视频做扎实，再将多类型共同需要的制作能力沉淀为共享模块，持续完善通用混合媒体讲解。

## 当前落地范围

已落地架构见 [模块化视频制作规格](../openspec/specs/modular-video-production/spec.md)。当前代码状态、可用命令和已验证能力以 README 为准；此处计划内容不代表未完成能力已交付。

当前类型范围（由 `catalog.json` 生成，与 README 和 Skill 的类型清单同源）：

<!-- generated:type-catalog:start -->
**路线旅程**：以真实道路为骨架的路线与旅程影像：单段自驾行程与多日地图游记。
- `driving-route`：保留独立的请求与路线材料、高速优先取数、授权内普通道路底图、竖屏确定性贴路动画与无声验收；无底部数据面板。
- `road-trip`：保留独立的 trip.json 编排材料、链式取数、每日底图走廊与离线有声渲染；以 318 川藏南线七天为首例。

**未分类**
- `financial-timeseries`：保留独立金融材料、投资价值计算、专用画面与确定性技术验收。
- `general`：以本地 React 代码场景制作 v8 全画布讲解视频，默认横屏并支持显式竖屏，保留真实配音、输入语义审查与完整候选自动验收。
- `building-construction`：以稳定构件 ID 和阶段时间轴表达建造过程；不提供 BIM/CAD 导入或工程计算。
- `vehicle-showcase`：以本地模型和节点/镜头轨道驱动展示，按参考影棚校正车漆、反射与车轮旋转；SU7 作为首例资产。
<!-- generated:type-catalog:end -->

上列各类型的校验、准备、预演、渲染与验收链路均已实现；真实数据是否可用取决于来源授权（金融行情与自驾路线取数各有前置条件），不以合成材料替代真实验收。

自驾路线把在线取数与离线成片分开：只有 `m2v driving-route fetch` 与可选的 `m2v driving-route basemap` 访问高德服务，取数或取道路瓦片前必须落实当前账号与用途的授权依据；其余流程只读本地材料。竖屏普通道路/卫星地图、市/县行政区标注（市辖区不单独标注）、车辆旁里程、30 fps、16× 平滑跟随与 z12 瓦片走廊作为当前能力实现，首例在完成当前候选独立视觉评审前不声称通过。

general 的检查点制作工具见[制作证据与状态](../README.md#制作证据与状态)，覆盖合同、状态查询、隔离包和引用保护清理；自动量测不替代独立观感判断。

通用代码场景已支持 opt-in 的全局时间与事件化声音语义；pure-time 场景可直接 seek、按块并行采集，`render --jobs` 可按帧区间分进程渲染。默认仍是顺序采集与单进程，跨类型扩展待实际需求。

## 扩展原则

新专用类型按“材料契约—业务准备—专用画面—类型评审—注册接入”实现。类型目录支持可选的「类别 → 类型」归组：类别只组织类型、派生规范作品位置与文档分组，不提供行为；当前 `route-journey`（路线旅程）包含 `driving-route` 与 `road-trip`，其余类型未分类。共享底座不导入类型私有逻辑；只有多个真实类型出现相同需求时才抽取共享能力。模块边界见 [架构说明](../ARCHITECTURE.md)，已实现的渲染与制作契约见 [OpenSpec 规格](../openspec/specs/) 和 [制作 Skill](../.agents/skills/material2video/SKILL.md)。

## 后续路线

2026-10-29 已按用户要求取消两个未闭环活动需求，已实现能力保留；原计划的剩余工作不再作为待办，依据见[需求取消记录](CHANGE_CANCELLATIONS.md)。

1. 持续完善金融专用类型与 v8 通用作品的实际制作体验；文章自动分镜与新的画面能力需另行评估。
2. 持续完善通用混合媒体的导入留证、按素材 ID 解析及旁白与字幕创作体验。
3. 持续完善镜头表现、后期、素材许可与原生尺寸审计，以及交付后的替代复核方式。
4. 根据新增专用类型的实际重复需求提取能力；保持每类业务门禁独立。
5. 仅在有明确需求且单独评估后考虑横竖屏以外的尺寸帧率；不引入第二套渲染引擎，电影级画面以现有 Remotion/React/R3F 底座上的镜头、后期与共享套件实现。
6. 外部参考项目 `vibe-knowledge-film` 的 C 夜曲与 B 寓言已分别转成正式风格包 `styles/vibe-night` 与 `styles/vibe-fable`；仓库原有三个固定示例已整理为 `doc-archive`、`count-ledger`、`deep-journey` 三个正式风格包，并迁入 `styles/<style-id>/examples/<slug>/` 作为规范示例（见[风格包目录](../styles/README.md)）。当前共 5 个风格；未并入的外观不提供可安装风格。
7. 已吸收该项目的两项方法：看图诊断的因果表与形象判据（`references/explainer-design.md#看图诊断与形象判据`），以及 `lookdev` 的任意时刻拼图、区间转场拼图、同帧一致性自检与幕内事件取证。可选二维 Canvas 绘制层（`web/src/code-scene/painter/`）已落地并附同源量测代理，使 Canvas 内容可被检查点量测。
8. 已吸收 `vibe-knowledge-film` 的六项制作方法：Painter 动态能力货架、离屏分组合成、固定种子可回放模拟、数值关键帧、声音全片包络与留静、长片章节递进。已实现能力与使用边界见[README](../README.md)及制作 Skill；这些方法不自动保证成片表达效果，仍按现有画面与声音复核。两个风格示例已按镜头连接、时间预算和共同尺度补充 `DESIGN.md`，并提供 `HOWTO.md` 的可复现修改练习；练习在临时副本执行，未把变体或媒体纳入仓库。
9. 后续按实际作品验证风格包边界和性能；已吸收的镜头连接、连续对象与时间预算按现行指导使用；外部分镜表格式及其余镜头语汇尚未整体引入，后续仅按实际需求评估，不建立平行材料或流程。
10. 通用视觉与运动方法已收归两个项目级 skill：`frontend-design` 负责视觉方向、字体、构图与反模板判断，`motion-design` 负责运动人格、时长、缓动与编排；项目文档只保留五块式设计记录、逐场表、证据与验收。主规格已移除七段式模板，规范示例 `solar-system-journey` 补写了五块式记录与逐镜运动计划范本。下一步是在一部真实 general 作品上实填五块式与逐镜运动表，按填写卡点再改模板；本次未实跑，不声称模板已被验证。

自动行情服务、云端队列、账号、自动发布、自动选曲和第三方插件系统不属于当前路线。配乐来自作品本地素材或确定性程序化音床，不接入第三方音乐服务。
