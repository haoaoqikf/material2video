# 项目规划

Material2Video（材料成片）以统一制作底座承载独立视频类型。发展顺序是：先把金融时间序列等专用视频做扎实，再将多类型共同需要的制作能力沉淀为共享模块，持续完善通用混合媒体讲解。

## 当前落地范围

已落地架构见 [模块化视频制作规格](../openspec/specs/modular-video-production/spec.md)。当前代码状态、可用命令和已验证能力以 README 为准；此处计划内容不代表未完成能力已交付。

当前类型范围（由 `catalog.json` 生成，与 README 和 Skill 的类型清单同源）：

- `financial-timeseries`：保留独立金融材料、投资价值计算、专用画面与确定性技术验收。
- `general`：以本地 React 代码场景制作 v8 全画布讲解视频，默认横屏并支持显式竖屏，保留真实配音、输入语义审查与完整候选自动验收。
- `housing-timeseries`：面向住宅年度均价的独立时间序列类型，含材料复算校验、确定性画面与可选画面评审。

## 扩展原则

新专用类型按“材料契约—业务准备—专用画面—类型评审—注册接入”实现。共享底座不导入类型私有逻辑；只有多个真实类型出现相同需求时才抽取共享能力。

通用类型采用 v8 全画布代码场景多幕讲解，默认横屏 1920×1080 并支持显式竖屏 1080×1920、默认 30 fps（可显式 60 fps），由真实配音与镜头时长编译全片时间轴；每一幕都是作品 `scenes/` 下的本地 TSX 实时录制，不支持旧 general-plan 编排、六种受控模板、视觉主题或完整片段嵌入。

通用作品采用**唯一制作契约**，不再区分 standard / cinematic 档位：所有作品执行方案循环、核心试制、整片粗预演、精制与复核回退，产出按风险选择尺寸的代表静帧与按风险确定长度的有声样片，镜头清单、look、后期与声音设计按内容选择，并以普通 H.264 MP4 交付。look-dev 只产出检查产物，不设人工门禁；准备记录、预演与溯源统一记录同一契约。

当前设计与评审指导见[制作流程](../.agents/skills/material2video/references/production-workflow.md)：立意六项覆盖核心体验与表达载体，选定方案后按[视觉创意导演方法](../.agents/skills/material2video/references/visual-creative-direction.md)完成七段式视觉创意方案（核心表达、核心视觉母题、整体视觉风格、分镜设计、视觉高潮、结尾视觉揭示、禁止项）与十项自检，载体来源先定整体政策再逐场落实实例，三案比较揭示与题材关联，全片安排强弱并主动强化有效表达；预算、减法与返工兼顾信息和体验。诊断按适用性执行，缺陷、风险、偏好和证据不足分别处理，母题以完整段落作用判断。此处仅记录指导已更新，不代表新成片或真实观众效果已验证。共享动效原语以 `progress` 为唯一时间输入，供作品场景按需导入。上述均为记录与制作指导，不新增阶段、评分、用户确认或 CLI 门禁。

准备产物和评审绑定材料、资产与依赖指纹；影响画面、声音或评审依据的变更会让它们过期。正式渲染使用临时输出，经媒体验收后再替换成片。

## 后续路线

1. 持续完善金融专用类型与 v8 通用作品的实际制作体验；文章自动分镜与新的画面能力需另行评估。
2. 持续完善通用混合媒体的导入留证、按素材 ID 解析及旁白与字幕创作体验。
3. 持续完善电影级表现套件：镜头与后期、素材许可与原生尺寸审计、普通 MP4 交付与替代复核，让「电影级」成为可执行、可留证、可验收的制作方式。
4. 根据新增专用类型的实际重复需求提取能力；保持每类业务门禁独立。
5. 仅在有明确需求且单独评估后考虑横竖屏以外的尺寸帧率；不引入第二套渲染引擎，电影级画面以现有 Remotion/React/R3F 底座上的镜头、后期与共享套件实现。

自动行情服务、云端队列、账号、自动发布、自动选曲和第三方插件系统不属于当前路线。配乐来自作品本地素材或确定性程序化音床，不接入第三方音乐服务。
