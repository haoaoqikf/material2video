# 项目规划

本文记录 article2video 的未来方向，所有功能均处于规划阶段，不代表已有实现。

## 使用场景与表达原则

面向个人 IP 的观点型抖音内容，输入一篇文章，把“抽象观点 + 核心判断”转为信息可视化短视频。例如：约束与反馈、复利、上场次数、学习先建立结构、复杂问题拆分，以及低频高收益的成功事件。

表达原则是“思想不断变深，表达不断变浅”：保留核心判断和必要推理，通过场景与动画降低理解门槛。文章可以压缩和改写，但不得虚构论据或扭曲原意。

AI 优先选择已有视觉组件并填充内容，不在每次生成时自由编写整套网页。前端负责稳定渲染，分镜描述内容及编排意图。

## 目标处理链路

```text
文章
 → 内容理解与压缩
 → 分镜规划和视觉语言选择
 → 结构化脚本 JSON
 → HTML / CSS / JS 场景渲染
 → 时间轴动画编排
 → TTS 配音与字幕时间对齐
 → 逐帧渲染与音视频合成
 → 竖屏视频
```

网页预览与最终导出应使用相同的场景内容和时间轴。完整链路是长期目标；早期先用人工编写的固定脚本验证视觉与渲染能力。背景音乐作为后续可选音轨，使用具有使用权限的素材。

示例输入约 500 字，示例输出为 9:16、1080 × 1920、30fps、约 45 秒。文章字数不是配音时长承诺：需根据目标时长压缩口播文案，或随配音调整总时长。

## 视觉组件候选

| 组件 | 脚本类型 | 适用内容 | 视觉表达示例 |
| --- | --- | --- | --- |
| TitleScene | title | 开场命题、主题 | 中央大字出现，关键词强调 |
| QuoteScene | quote | 核心判断、金句 | 分段呈现，关键短语高亮 |
| ComparisonScene | comparison | 两种选择、前后对照 | 双栏对照或两条路径展开 |
| TimelineScene | timeline | 事件顺序、尝试过程 | 节点依次出现，当前步骤突出 |
| DiagramScene | diagram | 因果、约束、反馈模型 | 节点连线逐步展开 |
| NumberScene | number | 数量、频次、收益变化 | 数字增长或曲线变化 |
| ListScene | list | 要点、行动步骤 | 逐项出现，当前项高亮 |
| ConclusionScene | conclusion | 收束、行动建议 | 全屏结论与简短行动提示 |

这是组件候选清单，首阶段只实现演示所需组件，后续逐步扩展。没有来源的数值与图表必须明确标为示意，不能当作实测结果。

## 示例分镜 JSON

以下示例用于表达方向，不是已确定的 API 或最终 Schema。第一阶段采用人工脚本，开发时再确定时间字段、样式配置和校验规则。

```json
{
  "title": "为什么努力没结果",
  "scenes": [
    {
      "type": "title",
      "text": "为什么努力没结果？"
    },
    {
      "type": "quote",
      "text": "努力没有结果，有时是因为方向错了。"
    },
    {
      "type": "comparison",
      "left": "不断增加努力",
      "right": "寻找当前约束"
    },
    {
      "type": "diagram",
      "nodes": ["问题", "约束", "行动", "反馈"]
    },
    {
      "type": "conclusion",
      "text": "先找到限制结果的环节，再决定把努力放在哪里。"
    }
  ]
}
```

场景展示文案和口播文案允许不同：画面呈现关键结构，口播补充解释与例子。后续脚本应承载两者及其同步关系。

## 分阶段路线与验收目标

### 第一阶段：固定脚本动画预览

使用人工编写的示例脚本，完成竖屏网页场景和统一时间轴，支持播放、暂停及重播。先实现上方示例使用的五类组件。

验收：完整播放一个示例；中文排版清晰、无溢出；场景切换正确；重播结果一致。

### 第二阶段：视频导出

建立可重复的按时间取帧与视频编码流程，导出无声视频，保持网页预览与导出的一致性。工具选型在开发阶段确定。

验收：导出视频可以播放；尺寸为 1080 × 1920、帧率为 30fps；总时长符合脚本；没有漏帧导致的场景缺失、字体缺失或明显闪烁。

### 第三阶段：配音字幕同步

加入口播文案、TTS 音频、字幕时间对齐和音视频合成，根据音频时长调整场景节奏；后续可选加入背景音乐。

验收：配音与字幕匹配；字幕处于竖屏安全区域；场景切换与讲述一致；末尾音频不被截断。TTS 服务与对齐方案届时确定。

### 第四阶段：AI 分镜生成

接入内容理解和分镜生成，把文章映射到已有组件。输出先校验，再供人工预览和修订，最后导出。

验收：示例文章能生成有效脚本；使用受支持的组件；保留原文核心判断；字段缺失或类型不支持时给出明确错误，并允许修正后重试。

## 当前边界与后续决策

本次只初始化仓库和文档，不实现上述阶段，不创建远端，不安装依赖，不自动发布到抖音。

技术栈、渲染工具、LLM 与 TTS 服务、最终脚本 Schema、音乐来源以及正式视频视觉风格，均在对应开发阶段依据原型效果和成本选择。当前不引入账号系统、云端任务队列或多用户管理。
