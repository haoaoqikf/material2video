# 代码场景动作脚本示例

以下演示如何先为场景说明状态变化，再在同源 `review.md` 记录动态评审；口播和场景数据仍只取自 `storyboard.json`。

| 场景 | 动作说明 |
| --- | --- |
| opening | 初始文字立定；按 b1 建立命题，按 b2 将焦点收束到判断结果，末尾稳定停留。 |
| icon-card | 图标不单独弹入；按对应 beat 将图标与标签组成一个信息单元，再停留供阅读。 |
| quarter-chart | 坐标系先建立；按口播 beat 逐步画出数据关系，结果稳定后保留阅读窗口。 |
| graph-flow | 起点先出现；边按因果顺序连接节点，节点状态随 beat 交接，最后展示完整路径。 |
| arc-goal | 目标为终点；进度弧按 beat 推进，达成后停留。 |

示例评审按实际渲染播放填写，以下模板分数留空：

```markdown
## 定制动画动态评审

状态：待评审

| 场景 | 焦点清晰度 | 动作解释力 | 节奏变化 | 转场连贯性 | 结果可读性 | 依据 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| opening |  |  |  |  |  |  |
| icon-card |  |  |  |  |  |  |
| quarter-chart |  |  |  |  |  |  |
| graph-flow |  |  |  |  |  |  |
| arc-goal |  |  |  |  |  |  |
```

只有观看实际输出并写出帧或时间依据后，才把状态改为「启用」并提交评分。
