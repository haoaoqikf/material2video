## Context

动机见 [proposal.md](proposal.md)。当前 issues.from_review 将每个 fail 登记 required=True，这是失败闭环保障，不是应删除的根因。报告以包、来源及媒体摘要绑定，样品交付要求当前同轮双通过。用户选择的第四张是采集 1384889b306d4c148eee18d7b43e6fd7，金额本身成为纸质立体主体；其盲看通过、对照失败，不能直接把该失败抹掉。

## Goals / Non-Goals

**Goals:** 把目标采用、独立观察、作者选案和当前技术验证分清；保留可用方向，同时保障真实失败必修；让相同完整观察结果可审计复用。

**Non-Goals:** 不新增投票/总分门禁，不设试验次数上限，不用用户喜欢替代数值或可读性验证，不以静帧授权动画或全片。此次规划不是第四张已通过或成片已完成的声明。

## Decisions

1. 继续使用 pass/fail/insufficient 与 limitations，不增加轻重评分体系。指南要求 fail 说明已采用目标和阻断影响；校验只能检查记录完整，不能自动判审美。原导入 fail 仍自动必改，避免作者事后降级。
2. 作者在 DESIGN.md 记录采用范围、选案证据、保留项和局部修复。用户认可方向后，两轮无改善比较不同修复机制；只有实际整体方向不成立或用户改选才重新选风格。不能用保留方向阻止真实缺陷被指出。
3. 扩展现有 production 媒体证据机制而不引入外部评审框架。已有文件摘要工具足够，无需新依赖。提供显式 `review reuse --file` 入口，收据绑定原同轮 trial 双报告、当前盲包、媒体字节摘要与当前周期。完整媒体文件、窗口、帧率、显示条件、职责及目标必须相同；首版不做不同容器或编码的解码等价，避免漏掉色彩、旋转、像素宽高比及音轨解释。流式文件哈希，内存不随全片帧数增长。final 不使用该入口，仍实际执行合格新代理终审。
4. 复用不复制或篡改报告。统一证据解析器供 status、issues 和 sample deliver 使用，检查原报告及调用有效、当前采集和包有效、目标/职责/尺寸相同、同周期、无未解决相反结论。唯一可不要求与当前文件相符的是旧来源内容；封存请求、来源摘要记录、包、全部包内文件、报告、调用与账本必须保持完整。旧来源过期只影响原技术有效性；不能跳过整个旧绑定验证。当前技术验证独立执行。关闭问题仍使用原报告导入和调用时间，不能使用收据时间刷新观察资格。
5. 冲突不自动取旧 pass。已有相同开场收到相反对照结论，必须保留冲突；关联 fail 经晚于失败的新代理实质争议复查并合法关闭后才解除，关闭失效恢复阻断。第四张沿用户明确选择更新目标时用已有 retarget，保留过去全部失败；新独立复查开始时间晚于登记，不能拿旧 pass 关闭新目标。

## Risks / Trade-offs

- [建议被误称为小问题] → 原目标明确失败仍 fail；具体位置和影响必须记录，独立终审不取消。
- [等价复用掩盖新缺陷] → 完整媒体、时间、声音覆盖、条件及显示一致；数据、来源和许可重新核验。用户改变目标必重审，不接受感知相似阈值。
- [文件摘要成本] → 复用已有操作内快照，流式哈希；不为复用再次解码影片，输入变化拒绝。
- [实现破坏旧证据] → 新增收据格式，不改写历史报告；没有收据仍按现有严格规则。不是版本升级，不保留新旧两套评审契约。

## Migration Plan

先落地指南、复用证据路径与针对性测试，独立代码评审后提交并归档。再登记本片用户选择及实际采用边界，恢复第四张原生入口，针对蓝色字组与手机读取局部打磨；重新验证对应静态及完整运动。之后展开全片、技术 QA、独立终审和实际声音覆盖。不得用本次流程提交代替视频交付。
