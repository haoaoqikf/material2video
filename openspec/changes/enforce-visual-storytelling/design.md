## Context

现有生成流程已经把内容、视频级视觉策略、逐幕意图、场景树和动效分开，并能用布局指纹阻止完全同构；但 `visualIntent` 只描述关系、焦点、构图、密度和情绪，无法证明图形承担了论证。`validate.py` 主要验证字段与结构，`review.py` 主要验证实际渲染、排版和动效，两者都可能放行由不同布局包装的文字卡片。设计还必须保持离线确定性：脚本不能调用模型去理解画面语义。

## Goals / Non-Goals

**Goals:**

- 让 AI 在场景树之前显式完成视觉转译，并留下可复核的语义声明。
- 用确定性规则拦截可客观识别的文字主导模式、占比超限和模式单一。
- 把脚本能测的结构证据与只能人工或视觉模型判断的“图形是否真的论证”分开呈现。
- 保持既有 schema v2 分镜可预览、可渲染，同时阻止其未经升级便作为严格验收通过的新交付物。

**Non-Goals:**

- 不在校验器或评审器中接入模型服务。
- 不要求每幕使用照片、插画或代码场景，也不把节点数量等同于视觉质量。
- 不在本变更中新增视觉原语；实现期间发现通用能力缺口时应另行按注册表契约扩展。
- 不自动把既有分镜的文字卡片改写成图形叙事。

## Decisions

### 1. 扩展逐幕 `visualIntent`，而不是增加第二套平行场景描述

在现有 `visualIntent` 内新增：

- `mode`：受控视觉模式；
- `claim`：该幕唯一核心论点；
- `showWithoutText`：移除标题和正文后仍应看见的关系或变化；
- `primaryObject`：承担论证的主要对象；
- `motionMeaning`：主要动效推进了什么理解。

这些字段属于导演意图，不参与 React 渲染；场景树仍是唯一画面声明。这样可以复用现有分阶段修订路径，也避免引入运行时双真源。

备选方案是新增根级 `visualArguments` 并按场景 id 关联，但会产生跨数组引用、增加局部编辑和错误定位成本，因此不采用。

### 2. 采用“声明 + 结构反证”，不做伪语义评分

校验器检查字段存在、枚举、非空、与场景树的可客观矛盾，并生成视觉叙事分类。下列节点本身不构成论证型图形：背景或装饰 `shape`、单独 `icon`、分隔线、以及子树只包含文本/符号的 `surface`。`chart`、`image`、具有多个语义节点的关系布局和带连接关系的组合可以提供结构证据，但脚本只报告证据，不据此断言语义质量。

“移除文字后是否仍然成立”与“图形是否承担论证”继续由人工或视觉模型在联系表上判断。备选方案是按图形节点数量打分；它容易被堆装饰节点规避，故不采用。

### 3. 将客观预算作为严格校验错误

严格模式执行以下版本化规则：

- 文字幕数量不超过 `ceil(sceneCount * 0.30)`；
- 相邻两幕不能均为文字幕；
- 八幕及以上至少三种非文字视觉模式，少于八幕至少两种；
- 非文字幕若只有装饰节点和文字承载节点，则报告声明与结构不一致；
- `showWithoutText` 为空、与 `claim` 完全相同或使用“显示/呈现 + claim”式机械复述时失败。

最后一项只检测明确的机械复述模式，不尝试做通用自然语言相似度判断。阈值集中定义并由单元测试固定，报告始终列出分子、分母、上限与场景 id。

### 4. 普通校验兼容，严格校验升级

为了不让已经可渲染的作品突然失效，缺少新字段的 schema v2 分镜在普通校验中产生兼容警告，预览和渲染仍可继续；`--strict` 把缺失字段和视觉预算问题视为错误。所有新生成、更新和最终交付流程本来就要求严格校验，因此新规则能阻断后续低质量作品。

备选方案是提升 schema 版本并拒绝旧文件；本次字段不改变渲染器解释场景树的方式，强制迁移成本高于收益，故不提升版本。

### 5. 在体检报告中新增独立 V 系列，不混入 C/K/M

`review.py` 增加视觉叙事章节：

- V1 文字幕预算；
- V2 连续文字幕；
- V3 非文字模式覆盖；
- V4 声明与结构一致性；
- V5 文字主导候选清单；
- V6 人工“图形承担论证”结论。

V1–V4 可由确定性脚本判定并与严格校验保持一致；V5 是证据清单；V6 在未填写 `review.md` 结论时显示“待评审”，不能显示通过。视觉语义结论不并入自动退出码，但发布清单明确要求 V6 ≥ 4/5 且无未裁决候选。

### 6. 原语不足显式中止，不自动回退

生成指南要求 AI 在 `showWithoutText` 无法映射到目录原语时，输出能力缺口并停在视觉意图阶段。它可以重新构思、提出通用原语扩展，或在确属作品特例时使用代码场景；不得改写为 `surface + text` 后继续宣称原视觉模式。这个行为主要由 Skill 指令、严格校验的结构反证和示例共同约束。

## Risks / Trade-offs

- [固定 30% 阈值可能不适合极短或刻意排版型作品] → 使用向上取整，并允许开场、转折、收束进入预算；超出预算必须修改分镜，而不是设置静默豁免。
- [结构规则可能把复杂的文字型图解判为文字幕] → 报告列出判定证据，人工可以调整真实视觉模式和场景树；不提供绕过严格验收的自由文本开关。
- [AI 可能填写漂亮但空洞的 `showWithoutText`] → 机械复述由校验器拦截，语义空洞由 V6 人工评审兜底，并在文档和示例中提供正反例。
- [既有示例在严格校验下失败] → 实施时一次性补齐仓库内示例；作品内容目录不入库，由兼容警告指导逐支升级。
- [V 系列与现有多样性检查重复] → 复用同一场景树遍历和归一化特征，布局指纹回答“是否同构”，V 系列回答“是否文字主导”，报告分栏呈现。

## Migration Plan

1. 先实现字段解析、普通模式兼容警告和严格模式错误，不改变渲染器。
2. 更新仓库内示例与文档，使所有受版本控制的分镜通过严格校验。
3. 增加 V 系列报告和人工评审模板，使用现有作品作为失败回归夹具、合格示例作为通过夹具。
4. 更新 README 当前能力与项目计划状态，完成全量验证后按项目约定提交并归档。
5. 如需回滚，可撤销新校验和文档字段；由于渲染器忽略导演意图字段，已升级分镜仍可由旧运行时读取。
