# 设计与取舍

## 为什么作为同级 skill，而不是塞进 material2video references

两个上游 skill 本身就是完整知识包。作为 `.agents/skills/` 下的同级 skill：

- Codex / DSH 可直接发现，主 Skill 也可用相对路径读取；
- 上游文件与项目调度分离，更新时只需对照 `UPSTREAM.md`；
- 不会把两份知识塞进主 Skill 的阅读预算。

## 为什么选官方 frontend-design

官方 `frontend-design` 是通用的视觉设计指导，不是网页框架清单：

- 视觉方向来自题材材料，而不是套用默认；
- 字体、结构、颜色、克制用色和自我批评都可以直接迁移到单帧与镜头；
- 只有一份 `SKILL.md`，没有脚本、组件库和浏览器检查，接入成本低；
- Apache 2.0，保留许可证与来源即可。

它仍然包含 Web/UI 语境（响应式、CTA、表单、CSS 选择器等），这些由 `ADAPTATION.md` 标为不适用；视频的运动判断仍由 `motion-design` 负责。

## 为什么保留上游原文，只加 ADAPTATION

上游内容是用户指定的权威来源。直接改写会失去与上游的对照能力，也会把“以官方 skill 为准”变成“以项目改写版为准”。因此：

- 上游正文不改、不翻译；只调整 `SKILL.md` frontmatter 的 `description` 与 `license`，并在顶部加一行指向 `ADAPTATION.md`，差异记录在 `UPSTREAM.md`；
- 所有 UI→视频的翻译、不可用章节和项目边界集中写在中文 `ADAPTATION.md`。

## 运动运行时：显式缓动，而不是内置风格

`scene-motion-primitives` 现有规格要求原语不内置视觉主题、缓动由作品传入。把缺省恒等改成某个内置曲线会违反这条原则。因此采用：

- 新增 `motion.ts` 命名曲线库，曲线作为共享词汇提供给调用方；
- 原语 `easing` 改为必填，删除缺省恒等；
- `linear` 保留为显式选项，只允许匀速跟踪、进度或旋转等有说明的用途；
- 相机保留默认曲线，但统一到命名曲线并把旧名改为新名。

这样既满足“空间运动不得线性”的默认，又不把某一种风格写进原语。

## 深度重写的边界

“深度重写”指把通用视觉/动效判断迁到两个 skill，而不是删除项目契约：

- 保留：阶段、检查点、审核人数、证据失效、问题闭环、手机尺寸、字幕安全区、类型契约、八项量化指标。
- 迁出：构图/色彩/字体/留白/层级的一般性判断，ms 时长与 UI 交互动效规则。
- 保留在项目文档：项目特有的辉光、字幕区、主体尺度、讲解机制、反平庸默认清单与风格包规则。

## 与受控时钟的关系

`sequential` 采集允许在受控时钟下使用 Motion / GSAP / CSS 动画；`pure-time` 与并行渲染只接受帧推导纯函数。运动 skill 的“任意动画库”因此不能原样照搬，`ADAPTATION.md` 明确这一边界。
