# 任务：成片溯源与陈旧判定

## 1. 溯源伴随文件

- [ ] 1.1 渲染成功后落一份伴随文件（默认与成片同目录、同主名），字段：页面、分镜、资产指纹表、帧数、时长、分辨率、帧率、采集格式、渲染时刻。
- [ ] 1.2 指纹口径与 `media.json` 的 `sourceFingerprint` 一致（哈希算法与字段命名不另造）。
- [ ] 1.3 只指纹**网页真正引用的本地资源**（样式表与脚本，含 skill 共享资产），不把整个 `assets/` 目录算进去——否则改一个用不到的图形也会报落后。
- [ ] 1.4 有声导出把媒体清单的指纹一并记进溯源（同一个成片要能回答「素材是哪一版」）。

## 2. 陈旧判定

- [ ] 2.1 验收命令能回答「这个成片是不是旧资产渲的」；不一致时报出**是哪几个文件**变了。
- [ ] 2.2 溯源缺失时如实报「无法判断」，SHALL NOT 默认放行，也 SHALL NOT 当成失败。
- [ ] 2.3 判定不改变画面类检查的错误数与退出码（它是提示，不是废片判定）。

## 3. 测试

- [ ] 3.1 指纹口径的单元测试：同一组文件稳定、文件内容变一位就不同、路径顺序不影响结果。
- [ ] 3.2 反例：改掉一个被引用的资产之后，已有成片必须被判为落后，并指出是哪个文件。
- [ ] 3.3 未引用资产的变化**不得**触发落后（否则闸门会变成噪音，人会开始忽略它）。
- [ ] 3.4 缺失溯源时的行为有测试（报「无法判断」而不是通过或失败）。

## 4. 文档与验收

- [ ] 4.1 `references/render-contract.md` 补上溯源伴随文件的位置与字段。
- [ ] 4.2 `SKILL.md` 的渲染验收把「靠人比对时间戳」改成查溯源。
- [ ] 4.3 `docs/PROJECT_PLAN.md` 把这条从缺口移入已实现。
- [ ] 4.4 全量 `uv run pytest` 通过；重渲一次基准示例确认成片字节不变、只多出伴随文件。
