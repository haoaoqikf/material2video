## Context

动机见 [proposal.md](proposal.md)。现有 v8 场景、逐帧录制、局部检查、一次完整候选及 technical-only QA 可以继续使用；缺口主要在助手的创作与验收契约。作品可编辑示例在 examples，交付在忽略的 videos/examples 输出目录。

## Goals / Non-Goals

目标：把创作目标落实到每场美术与技术细节；让验收可以推翻创作意图；用拥堵波真实重制验证流程；全过程形成有证据的百万播放潜力判断。

不做：自动预测播放量、自动审美评分、平台发布或数据接入、用户审批、新 CLI 门禁、新分镜版本；不重制另外两片，也不要求用户提供视觉参考或试听。

## Decisions

### 设计与验收保持 Markdown，按场景 ID 对齐

沿用 DESIGN.md 和 outputs/visual-notes.md，新增输出 reach-potential-report.md。共享模板放 Skill 参考文档中，由主入口及现有制作、视觉复核文档链接。设计表覆盖叙事、美术、技术、时间、声音及验收；验收逐场对应并绑定版本。采用文档契约而非新增运行时 JSON，避免把主观判断伪装成程序已验证；分镜 v8 保持不变。

单场含多个镜头时列出内部镜头及交界；静态场景检查呈现顺序和阅读窗口，动态场景检查全过程。四张全片基准保留作为统一性参照，不再承担其余场景的代验职责。所有类型落实适用的场景/阶段单元，金融与住宅不强加讲解片结构和声音。

### 分开执行观察与对照

助手验收时先不读取设计结论，仅根据本轮实际帧序列及文案时间窗复述问题、事件、答案和继续观看理由；保存观察后再对照目标，明确是自审而非真实观众测试。随后逐维度检查，按问题来源回退。无新增独立代理或用户接手要求。

### 潜力判断不预设成功

设计阶段记假设，制作阶段记实现差距，逐场与全片验收记实际证据，报告汇总并引用，不复制未验证的设计优点。输出定性结论及支持/反对依据，不填概率或代理分数；账号未知记未知。可修改的表现失败须返工，未知分发因素不作为无限循环条件。

报告由 visual-notes.md 直接引用；实施时核对既有清理逻辑，确保报告及其合法输出目录内证据在成功清理后保留。若现有引用保留机制已满足，不扩展清理实现；否则只增加必要保留规则和回归测试。

### 拥堵波先重做观看路径，再确定实际分镜

先保存现有候选摘要、旧帧及设计依据；以生活困惑开场，追踪减速接力，再用环路证明无瓶颈也能出现低速区域，以密度对照作补充，最后回到驶出拥堵却没有障碍。实际幕数和秒数在逐场试制与实测 TTS 后确定，禁止继续把原有五幕顺序视为既定答案。

比较两个不同表现方式，用同一核心事件、正式文字及实际字幕试制；助手自主搜索并留存外部机制与视觉参考，不将参考当授权素材。沿用确定性轨迹，必要时重构展示方式，车灯、编号、图表与波方向使用同源数据；美术方案通过后再精制全部场景。保持无配乐，可用少量提示音；同步修正旧记录“完全无音效”与分镜实际提示音不一致的问题。

### 既有时长约束显式替换

现有 article-explainer 主规格已按核心试制与粗预演确定交通时长，但 README 仍写目标75秒、实际60～90秒。本次新增重制要求明确沿用主规格，实施时清理 README、示例材料及校验中残留的固定预算，保留其他两片约束。无需改写已一致的主规格要求；若发现其他实际冲突，在本变更中完整修订对应要求并重新严格校验。

## Risks / Trade-offs

- 自审仍有已知答案偏差 → 先观察后对照、记录反证与未覆盖范围，不声称真实观众验证。
- 逐场表格变成填表 → 必须引用当前作品状态和时间码；泛化形容词与缺证据不通过。
- 百万目标诱发夸大或无限返工 → 允许否定结论，区分内容不足与分发未知，沿用两轮无改善换方法规则。
- 帧序列不能覆盖全部听感与瞬时运动 → 保留现有高密度采样、量测和自动声音检查，披露边界，不虚构播放试听。
- 新实现增加录制成本 → 先局部试制，复用缓存，最终按现有候选机制生成，不为记录形式重复完整编码。

## Migration Plan

先提交提案；后续 apply 同步共享规范与模板、重制示例、更新相关校验及测试，再准备、逐场检查、正式生成与全片复核。旧媒体仅在成功交付后按既有规则清理，保留本轮新旧对照与引用证据。实现与验证提交成功、任务全勾选后再同步主规格并归档提交；失败保留未完成状态及旧有效交付。
