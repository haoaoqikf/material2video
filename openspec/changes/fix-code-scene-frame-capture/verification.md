# 验证与审查记录

## 核心结论

共享录制已切换到顺序帧推进，删除实时 screencast、concat 时间戳重采样和尾帧补齐。React 上下文由帧号推导，动画库和 R3F 使用受控时钟；CSS 与本地视频在截图前同步。旧录制缓存因采集标识和实现指纹变化失效。

## 已核实的行为

- 真实浏览器逐帧检查匀速 DOM 位移、R3F 网格位置、Motion 透明度、GSAP 位移及 CSS 动画；人为等待 180 ms 后截图保持一致。
- ECharts 三个时间点画面不同，定时器执行次数正确；视频入点、倍速、循环、暂停和恢复均按受控时间定位。
- 重复或跳跃帧号被拒绝，缺失 PNG 不编码；真实绘制超时不依赖冻结的作品时钟。原有外网、异常、就绪失败和缓存复用测试通过。
- 三个固定示例完成代表片段采集，缓冲和试错各 180 帧，太阳系 1080 帧；抽帧检查布局，太阳系连续序列覆盖近景拉回总览。
- 同取太阳系 13.8～14.6 秒的运动区域，缩小为 192×104 灰度画面；47 对相邻帧中，旧片有 38 对平均像素差小于 0.04，新片为 0 对。该阈值只用于此运动段前后对比，不用于判定静止镜头失败。

## 逻辑、性能与影响

公开 CLI、v8 分镜与作品上下文接口保持不变；改变录制实现与内部顺序推进接口。动态时间由受控时钟推进，机器负载只增加采集耗时；预演和正式导出继续复用同一录制片段。视频服务器启用原有 Range 支持，确保 seek 不被浏览器钳到零。

PNG 每帧落盘并在工作目录生命周期结束后清理，内存不累计全片图像。新增成本是每帧绘制屏障、PNG 采集与编码后解码计数；空间与耗时随帧数线性增长，优先保证运动完整性。采用快速 PNG 压缩和单次异步推进，减少压缩与轮询开销。

## 剩余边界

不支持倒序或任意跳帧，不承诺任意异步、随机作品的逐像素重现。抽帧与连续画面序列检查不能替代全片人工播放或音色试听；本次不把技术验收写成完整试听通过。

审查未发现当前验证范围内的阻断问题；最终出片数据及验证命令结果在完整制作结束后补记。
