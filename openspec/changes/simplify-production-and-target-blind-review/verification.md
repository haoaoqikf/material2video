# 验证与审查

## 规则演练（文档验证，非成片实测）

| 情形 | 核对结果 |
|---|---|
| 核心隐喻被当成第三组 | 扩展全片前盲测，先修复并复查，不靠补设计理由放行 |
| 删短不损理解与收束 | 首次重要返工匿名比较，不因旧版投入保留等待 |
| 同问题两轮无改善 | 停止同类微调，强制删短或重排对照 |
| 两份报告对核心问题冲突 | 新代理先盲看落盘再核对中性条件，不投票或挑宽松意见 |
| 局部修改复用其他观察 | 复查本场和衔接，引用来源与依赖证明，最终当前文件仍全片检查 |
| 技术通过但报告空白 | 技术完成可报告，制作复核仍未完成 |

## 检查与影响

- OpenSpec 增量严格校验通过，修改的现有要求保留全部原场景。
- 44 个新增相对链接/锚点、1 个 JSON 示例校验通过，删除标题未导致入链失效；类型目录文档同步检查通过。
- 当前共享规范已无旧五阶段主线、单独潜力报告路径、一次评审只问一件事或强凑三条缺陷的要求。
- 职责映射逐项检查：保留逐场/内部镜头覆盖、独立性、两次导演审查、手机检查、事实许可、自动声音与技术 QA。
- 审查修复先盲看与原条件核对的输入冲突；原始报告不重写，问题唯一登记，当前交付摘要不由旧结论授权。
- 无代码、API、运行时字段、校验器、示例、画幅、声音或 CLI 门禁变化，无运行时性能影响。
- 初始 Git 工作区无已有改动；实施未发现目标文件并发变化。未触碰任何作品、渲染进程或缓存，未运行视频命令、清理或工作区切换。
- 限制：仅验证流程契约与文档一致性，未重制视频，未测量实际调用成本与成片收益；新规则仅用于后续任务。
