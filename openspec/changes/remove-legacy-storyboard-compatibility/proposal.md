# 变更提案：移除旧分镜兼容并升级到 v3

## 问题
当前分镜经历了场景树、视觉导演和语义节拍等多次迭代，但 Python、TypeScript、浏览器运行时和评审器仍含可选字段、默认值及旧格式分支。结果是输入通过的契约并不唯一，旧作品可能被静默按缺省导演行为渲染；迁移命令和迁移文档又延长了旧契约寿命。

## 目标
- 将唯一可执行分镜契约升为 schema v3，并在校验、评审、预览和渲染入口统一拒绝 v1/v2。
- 让导演策略、每幕 renderer、视觉论证、镜头段、beat 驱动动作和配音均显式且可验证。
- 删除分镜迁移程序、模块、测试和过期迁移规格；历史媒体溯源仍可只读识别并报告需重渲染。
- 重新编排目标作品及 7 个示例，保留各自教学目的，并按 v3 重新评审和渲染 outputs。
- 同步更新项目权威文档并归档本变更。

## 非目标
不改造共享原语为单作品专用组件，不提供自动迁移、legacy 开关或双版本并行；不把生成媒体纳入 Git；不删除仓库外内容根中的用户数据。

## 破坏性影响
旧分镜将在所有可执行入口收到明确的“分镜版本早于 v3，不受支持”错误。用户需重新编排为 v3。仓库中被忽略的旧 outputs 将按本变更明确要求删除后重建。

## 验收
8 份作品严格校验零错零警告；C/K/V/A 硬闸门通过并完成 V6/A6 人工裁决；测试、类型检查、构建通过；新媒体完整解码且满足编码参数，逐幕抽查确认 beat、镜头及连续性可见。最后同步主规格、归档 OpenSpec 并提交所有受版本控制改动。
