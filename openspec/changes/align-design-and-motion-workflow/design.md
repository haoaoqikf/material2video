## Context

两个项目级 skill 已于 `fe5e8be5` 接入阅读路由、三阶段与评审词汇，`7803b0d5` 又合并了重复流程。遗留问题是制品层：主规格仍有"七段式"要求，视觉复核仍在核对已删除的模板，规范示例与全部作品没有五块式记录，运动计划只有四行文字且没有任何落到镜头的通道，运动节拍只能借用"事件"才进入证据密度守卫，五份类型指南零引用。

## Goals / Non-Goals

**Goals**

- 主规格、指导文档、示例对"设计记录长什么样"只有一个答案：五块式。
- 运动计划可被逐镜核对，且不新增分镜字段。
- 运动节拍能被既有采样密度守卫覆盖，`structure-timing` 的证据要求包含运动。
- 类型专用指南指向两个 skill，不再让类型成为通用理论的第二份副本。

**Non-Goals**

- 不改分镜 JSON 字段、检查点合同结构、CLI 命令、审核人数与轮次。
- 不给运动或审美增加评分、阈值或新风险 `kind`。
- 不重制示例成片，不追认旧交付；示例只补非重制设计记录。
- 不把上游 skill 的毫秒表、1/3 规则或反默认清单变成门禁。

## Decisions

### 1. 移除七段式要求，而不是保留双轨

七段式模板已被 `visual-creative-direction.md` 删除，保留要求只会产生"规格要求填写一个不存在的模板"。移除后用 MODIFIED 把仍然有效的约束（核心表达、母题、禁止项、方法库按未决问题使用、形式不否决、不因表单未填判未完成）并入五块式要求，避免在同一份规格里出现两套命名。

替代方案「把七段式 RENAMED 为五块式」不可行：两者条目不同（七段含"整体视觉风格""视觉高潮""结尾视觉揭示"，五块含"题材""风险与证据"），重命名会丢失条目差异。

### 2. 运动计划用 `DESIGN.md` 内的表，不用分镜字段

运动由作品 TSX 代码兑现，`shots[].camera` 只承载相机参数。因此运动计划按 `scene.id` / `shots[].id` 列表记录"运动类型、起止帧、命名曲线、`linear` 用途"，与导演卡现有的映射方式一致（`storyboard-schema.md` 的"导演设计映射"）。不新增 JSON 字段的原因：任何新字段都会进入准备指纹并需要校验器、缓存键与示例同步，而运动决策本来就要读设计文档才能判断。

### 3. 运动节拍复用幕内事件，不新增时间源

`events` 已是声画共用的唯一幕内时间源，且 `minEventFrames` 守卫已按"最短事件"比对步长（`checks.py`）。把入场、离场、落点登记为事件，即可让既有守卫覆盖运动，无需新字段或新校验。指导文档必须同时说明：运动事件不自动生成音效，也不改变事件语义。

### 4. `structure-timing` 只改证据文本，不改门

`policy.RISK_CATALOG` 的 `evidence` 是文档展示文本，不参与判定。把"animatic 观察，可与核心样片同轮"扩为"animatic 观察；关键运动窗口须有加密帧或过程片段，可与核心样片同轮"，经 `sync_docs.py` 重新生成 `checkpoint-gates.md` 生成区。风险 `kind`、门位与人数表不动。

### 5. 示例选 `deep-journey/solar-system-journey`

它是唯一同时具备真实运动复杂度与既有 `linear` 例外记录的作品：一镜到底要求全部镜头 `easing: "linear"`（`storyboard-schema.md` 的一镜到底约定），正好用来示范"`linear` 例外必须写用途与范围"。补写为"非重制设计记录"，保留原七段内容作为历史；不触碰 `style.json`、组件与素材，风格包指纹不变。

### 6. 类型指南只加链接，不搬理论

五份类型指南各自的画面段落加一句指向两个 skill 与 `ADAPTATION.md`，并按类型点明该用哪一部分（例如自驾与车辆看镜头与匀速跟踪，金融看数据揭示节奏）。用一条测试断言五份指南都含两个链接，防止再次脱钩。

## Risks / Trade-offs

- **五块式仍无实跑验证**：模板至今没有作品用过。本变更只补示例，不声称模板已被验证；下一部 general 作品实填后如需调整，按简单变更改模板。
- **事件数量增加**：把运动节点登记为事件会让 `events` 变多。取舍是宁可多登记也可判定，事件本身不影响渲染；若某幕事件接近 1024 上限，改回按 `minEventFrames` 收窄采样。
- **示例变长**：`solar-system-journey/DESIGN.md` 会增加一段五块记录。它是作品内容、不入库媒体，不影响风格指纹与测试名单。
- **规格移除的追溯**：七段式的历史记录保留在 `openspec/changes/archive/`，主规格只保留当前契约，符合"版本升级默认不兼容"。

## Migration

主规格归档后不再要求七段式；已有作品与示例的历史七段记录保留原样，不追改正片，不做批量重写。新启动的 general 作品按五块式记录。
