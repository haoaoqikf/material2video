# 图形的对比度预算

## 为什么要做

把 `examples/keynote-baseline` 的成片逐帧打开看（不是看哈希、也不是看闸门数字），
会发现图形读起来像**占位图**：天平是几条淡到几乎看不见的线，差量条是描边而不是体块，
阶梯是轮廓，冰山只有一圈边。

量一下就知道不是错觉。README 写着「对比度预算正文 7:1、大字与图形 4.5:1」，
而 `keynote.css` 里预设层实际给图形的令牌是：

| 令牌 | 深色主题 | 浅色主题 |
| --- | --- | --- |
| `--fig-line` | 5.69:1 | **3.31:1** |
| `--fig-line-soft` | **1.63:1** | **1.35:1** |
| `--fig-water-line` | **3.23:1** | **1.89:1** |
| `--fig-water-text` | 8.06:1 | **3.73:1** |
| `--fig-surface` | 1.19:1 | 1.13:1 |
| `--fig-water` | 1.34:1 | 1.20:1 |

（对各自主题的 `--a2v-bg-0` 计算，半透明令牌先合成。）

也就是说：深色主题下承载「以为需要 / 真正需要」那两根差量条的虚线轮廓只有
**1.63:1**，浅色主题下连图形的主描边都只有 **3.31:1**、图形内文本 **3.73:1**。
预算写了 4.5:1，实现没做到，而且**没有任何检查会发现**。

## 为什么现在才发现

- `TestFigureTokenCoverage` 只查 `figures.css` 引用的每个 `--fig-*` 令牌在两套主题里
  **有定义**，不查取值**看不看得见**；
- K5 正文对比度只量 DOM 里的**文本样张**，SVG 的 `fill` / `stroke` 不在量程内；
- K1 留白预算量的是背景像素占比——图形越淡，背景占比越高，**越容易通过**。

三者叠起来正好是一个静默失效：不报错、校验通过、闸门全绿、图形淡到看不清。

## 要做成什么样

给图形令牌定一个**分类 + 预算**，并让测试守住：

- **数据描边**（画出数据形状的轮廓、柱体边、轴线、括号、箭头）对 `--a2v-bg-0` ≥ 4.5:1；
- **图形内文本**对 `--a2v-bg-0` ≥ 4.5:1，`--fig-ink` 上的文字对 `--fig-ink` ≥ 4.5:1；
- **装饰描边**（不承载数据的辅助线）对 `--a2v-bg-0` ≥ 1.5:1；
- **面填充**只要求归类，**不设数值下限**：形状的可读性由数据描边负责。
  给面填充设下限会把浅色主题里正确的白色面阶（对底色 1.13:1）判成缺陷；
- 两套主题都要满足。分类表写进参考文档，测试按表断言，
  **新增图形令牌必须先在表里归类**，否则测试直接报错。

落地前逐项核对过：`--fig-line-soft` 被用在四处（`.ln-soft`、`.scale-rope`、
`.loop-track`、`.stair-axis`），前两处是装饰、后两处承载结构，因此按用途拆成
两类，而不是整体提高。

## 怎么做到不破坏兼容

`figures.css` 是非预设路径与预设路径共用的，直接改它的颜色会破坏
`examples/declarative-number` 的逐字节保证。因此沿用仓库已有的
`var(--a2v-ink-*, <原值>)` 手法：

- 把承载结构的描边（`.loop-track` / `.stair-axis`）从 `var(--fig-line-soft)`
  改成 `var(--fig-line-data, var(--fig-line-soft))`；
- 非预设路径没有 `--fig-line-data`，回落到原值，**画面逐字节不变**；
- 预设层定义 `--fig-line-data`，取值满足 4.5:1。

`--fig-line-soft` 保持「软线」语义（装饰用，预算是 ≥1.5:1），不再让它承担结构。

## 影响

- 预设生效的页面：浅色主题的图形轮廓从 3.31:1 提到 5.22:1、水体轮廓从 1.89:1
  提到 5.23:1，深色主题的水体轮廓从 3.23:1 提到 4.82:1，结构线由新的
  `--fig-line-data` 承担（深色 7.75:1 / 浅色 7.42:1）；
- 未启用预设的页面：**逐字节不变**（有 SHA256 回归守住）；
- 新增机检 `tests/test_figure_contrast.py` 与设计宪法的一条规则；
- 不引入任何外部依赖，仍然不走 CDN。
