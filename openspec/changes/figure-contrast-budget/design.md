# 设计决策

## 决策 1：把「图形」纳入对比度预算，而不是只调几个数值

**背景**：预算早写在 README 里（图形 4.5:1），但没有任何机制保证它成立。

**选择**：先给图形令牌建**分类表**（数据描边 / 图形文本 / 面填充），再按类给预算，
最后由测试按表断言。新增令牌必须先在表里归类。

**理由**：只把几个数值调到达标，下一次有人加一个图形令牌，同样的洞会再出现一次。
分类表的成本很低（十几个令牌），但它把「图形看不看得见」从审美判断变成了可验证契约。
反过来说，如果不分类，一条「所有 `--fig-*` 都 ≥ 4.5:1」的规则会逼着面填充
（水体、次级面）也变重，那会把「被藏起来的一半」这种刻意的淡填充也一起毁掉——
**规则必须能区分「淡得有意」和「淡到看不见」**。

## 决策 2：面填充不设对比度数值下限

**背景**：第一版方案给面填充定了「与落座面的明度比 ≥ 1.25:1」。落地前逐项核对发现
这条会把**正确做法**判成缺陷：浅色主题自己的面阶是 `--a2v-bg-0` `#eff1f4` →
`--a2v-surface-1` `#ffffff`，明度比只有 **1.13:1**；`--fig-surface` 取白色正是
跟着这套面阶走。按 1.25 判，等于要求把浅色主题的白色卡片面改成灰色。

**选择**：面填充只要求**归类**，不设数值下限；形状的可读性由数据描边负责。

**理由**：面填充的职责是「分出一块面」，而形状是否读得出来由描边界定——
`.berg-tip` 有 4px 的 `--fig-line` 描边，`.load-hollow` 有 `--fig-line` 描边。
对「形状必须由描边界定」这条，静态检查表达不了（要知道哪条描边属于哪个填充），
因此写进参考文档作为人工判据，机检只守「分类表覆盖了每个图形颜色令牌」。
这和 K2 早期把「强调色占比低」判失败是同一类错误的规避：
**规则必须能区分「淡得有意」和「淡到看不见」**，而区分的依据是它承不承载数据。

## 决策 3：把「装饰描边」单列一类，而不是并入数据描边

**背景**：`--fig-line-soft`（深色 1.63:1、浅色 1.35:1）被用在四处：
`.ln-soft`、`.scale-rope`、`.loop-track`、`.stair-axis`。

**选择**：给它单列「装饰描边」类，预算 ≥ 1.5:1；另外新增 `--fig-line-data` 给
`.loop-track` 与 `.stair-axis` 这类承载结构的线用，预算 ≥ 4.5:1。

**理由**：把 `--fig-line-soft` 整体提到 4.5:1 会让它和 `--fig-line`（0.52）几乎同值，
「软线」这个语义就没了，而天平绳确实该是软的。反过来，阶梯图的轴线与循环图的轨道
是结构的载体，靠一条 1.63:1 的线说不清楚。**分类要跟着用途走，不是跟着取值走。**

## 决策 4：用 `var(--fig-line-data, var(--fig-line-soft))` 而不是改 `figures.css` 的取值

**背景**：`figures.css` 同时服务预设与非预设路径。直接提高它的描边颜色会改变
`examples/declarative-number` 的成片，破坏「未启用预设时画面逐字节不变」的保证——
而这个保证是「设计语言层可选」这句话的唯一证据。

**选择**：新增 `--fig-line-data` 令牌，`figures.css` 里承载结构的描边写成
`var(--fig-line-data, var(--fig-line-soft))`。非预设路径没有该令牌，回落到原值。

**理由**：这是仓库已有的手法（`var(--a2v-ink-display, 240px)` 就是这么做的）。
它让「同一个组件在两条路径下取值不同」变成显式声明，而不是靠选择器覆盖去猜。
代价是 `figures.css` 里多出一层 `var()`，收益是兼容性有证据而不是有承诺。

## 决策 5：只改预设层，且不新增运行时逻辑

**选择**：本次只动 `keynote.css` 两套主题的 `--fig-*` 取值、`figures.css` 的
两处 `var()` 回落写法，以及测试与文档。不加 JS、不加探针、不加运行时测量。

**理由**：对比度是**静态可算**的量——给它写运行时代码是浪费。
把它放进静态测试比放进帧量测更快、更稳，而且失败信息能直接指出是哪个令牌差多少。
K7（溢出）必须是帧量测，因为它依赖实际排版结果；对比度不是。

## 决策 6：预算按主题分别满足，不取两套主题的公共下限

**背景**：浅色主题目前全面差于深色（数据描边 3.31:1 vs 5.69:1）。

**选择**：两套主题各自满足预算，允许取值不同。

**理由**：浅色背景下同样的视觉重量需要更深的颜色，这是对比度计算本身的性质，
不是实现偏差。取公共下限会让深色主题的图形过重。
