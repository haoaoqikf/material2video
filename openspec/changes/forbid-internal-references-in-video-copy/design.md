## Context

见 [proposal.md](proposal.md) 与 [video-production-workflow delta spec](specs/video-production-workflow/spec.md)。当前 v8 通用作品的正文由作品 TSX 自行绘制，技术 QA 不解析所有作品正文；资产来源与许可已在作品材料中留证。此次不增加 CLI、分镜字段或渲染器能力。

## Goals / Non-Goals

**Goals:**

- 将手机观看、避免幻灯片式重复呈现、清理内部文案及集中片尾署名变成可检查的制作要求。
- 以当前已有全片帧序列、接触表和人工视觉复核执行这些检查，并在 visual-notes 中记录文案清单与版式问题处置。
- 重制固定示例并用新候选验证流程能发现和关闭已知风格问题。

**Non-Goals:**

- 不做通用 OCR/幻灯片风格自动分类器，不声称技术 QA 能自动判断所有观众可见正文。
- 不强制竖屏、不改各类型画幅契约、不变更渲染接口。
- 不把完整来源表或文件名烧进成片；不豁免入片素材已有署名与许可义务。

## Decisions

1. **使用复核清单与可见文案盘点，而非新增 OCR 门禁。**
   TSX 全画布允许任意作品代码绘制文字，OCR 对中文、动效和图形内文字覆盖不足；制作助手在粗预演与最终全片帧序列中逐项盘点固定文案和动态字幕，并按时间标注图像复核，记录在现有 `outputs/visual-notes.md`。未来自动能力另行评估。

2. **将“幻灯片式”判据落在全片重复模式与信息发展上。**
   检查全片时间标注帧序列与镜头清单，识别连续段落是否只替换年份/标题/说明；同时观察画面主体、动作、空间关系、摄影机或图形是否随内容推进。重复卡片主导且无有效发展时作为必改项，不因少数相同构图或片尾署名卡自动判失败。

3. **署名以一份片尾画面集中承载。**
   源素材清单、来源页、作者、许可、SHA-256 和改编细节留在 `SOURCES.md` / `assets/media-sources.json` 等作品材料；片中仅显示必要且简洁的许可署名，不引用这些材料文件。共同许可内容按对应许可证提供作品级版权说明。

4. **重制片采用约 60 秒、12 个场景的紧凑时间线。**
   以 3 秒开场、十项共约 52 秒（按叙事节奏分配）、约 5 秒收束/署名构成，目标 60 秒并以 prepare 后实际帧数为准。每项保留年份、短名称和压缩后的贡献说明；不同素材特征决定全幅档案、细节裁切、动效示意或镜头承接，避免固定文字板模板。片尾署名和主旨收束共用同一画面，仅有一份版权文字。

5. **手机观看默认目标不决定画幅方向。**
   示例遵照用户选择保持 1920×1080 横屏；场景以横屏手机缩放后的实测文字大小和主体可辨为准。平台 UI 安全区依据仅采用可核验信息；不能取得时如实记录具体测试显示尺寸和未知边界。

## Risks / Trade-offs

- [短时长压缩十项说明可能降低理解度] → 保留每项一个贡献边界句，粗预演逐项核验信息足够；无法在 60 秒中清楚表达时先压缩重复措辞，不删十项内容。
- [极简署名可能不足以满足许可] → 逐项对照素材登记与许可证确定最小必需署名；若单一片尾不能清晰承载，调整版式与可读时长，不以省略义务换取简洁。
- [“PPT 风格”存在主观性] → 采用可复查的重复模式判据和时间码证据，不设统一镜头数量或构图变化配额；由内容推进证据支撑结论。
- [横屏平台遮挡信息缺失] → 不宣称官方像素安全区通过，按指定手机播放尺寸测量并记录限制。

## Migration Plan

先更新制作流程规范与 Skill，再按新规则重编、准备、预演和生成示例；同时把 `article-explainer` 中固定示例的时长契约及示例严格测试改为60秒，避免主规格与实际交付互相矛盾。随后保存新候选的摘要、完整帧序列与视觉复核证据；验证通过后更新主规格并归档本变更。旧输出为忽略的派生产物，由新交付替换；源码仍只有固定的三个示例目录。
