# `@remotion/paths` 作品需求评估

## 需求来源与当前实现

| 固定示例 | 已有路径动作 | 是否需要曲线/描边/形变能力 |
| --- | --- | --- |
| `buffer-smoothing` | inlet、outlet、bypass 是 `compilePath` 生成的直角折线；水位/阀门按帧更新 | 否；现有折线路径清楚表达数据流向 |
| `darts-trial-and-error` | 飞镖轨迹是按帧线性插值，轨迹提示为静态二次曲线 SVG | 当前无连续曲线运动或描边展开要求 |
| `keynote-baseline` | 路线图使用静态二次曲线作为分叉关系 | 当前不沿曲线运动，也不动画展开描边 |

三个示例都没有轮廓形变需求。现有路径要么是正交流线，要么是静态构图；没有因 `compilePath` 导致的可观察误差或手写维护问题。因此不安装 `@remotion/paths`，不改示例叙事。

## 结论

**暂缓**。当前没有足以抵消新增依赖、路径预编译/缓存与非法输入处理成本的真实收益。包体变化和运行性能不做无需求基准，因为本项不适用。npm 注册元数据中 `@remotion/paths@4.0.526` 的 unpacked size 为 289,621 bytes（约 283 KiB），这是含类型与非运行时代码的包体上界参考；压缩后实际进 bundle 的增量未测，不把它误报成用户可下载体积。如未来作品需要连续曲线运动、路径描边展开或轮廓形变，应另立变更，以受控 API 白名单、端点/切线/进度边界、非顺序求帧及性能实测为准。
