# 提案：文章与仓库解耦（`videos/` 退出 Git，内容根可外置）

## Why

仓库现在同时扮演两个角色：**工具链的仓库**与**文章内容的仓库**。两者混在一起，
每一种都替对方付代价：

- 文章是个人内容，却被 Git 跟踪：`videos/never-fear-interviews/` 的 4 个文件
  （文章、分镜、网页、生成分镜）随代码一起提交，仓库无法独立分享或备份；
- 反过来说，仓库里的测试与文档也**依赖这些内容存在**：
  `tests/test_figures_assets.py` 直接读 `videos/never-fear-interviews/index.html`，
  两个字体测试把它列进参数表。于是「删掉一篇文章」会同时弄坏测试——
  内容与工具链的耦合是双向的；
- 路径推导、成片溯源、静态资产扫描三处都**假设文章在仓库根下的
  `videos|examples/<slug>`**，页面也用 `../../.agents/skills/...` 相对路径引用共享资产。
  文章一旦落在仓库外，相对路径必然断裂、溯源退化成「无法判断」、共享资产漏出指纹。

已经踩到的现实：换一台机器克隆下来，仓库里既没有你的文章，测试也跑不绿；
把文章放进仓库，又让「分享工具链」变成「分享你的内容」。

## What Changes

- **`videos/` 退出 Git 管理**：取消跟踪（磁盘文件原地保留），`.gitignore` 明确忽略；
  `examples/` 作为仓库自带示例继续入库。
- **内容根可外置**：新增 `A2V_CONTENT_ROOT` 环境变量与 `--content-root` 参数
  （优先级 `--content-root` > `A2V_CONTENT_ROOT` > 仓库根）。内容根可以是仓库外的任意目录，
  内部布局与仓库同构（`videos|examples/<slug>/`、`outputs/<slug>/`），
  未设置时行为与今天完全一致。
- **共享资产别名 `/__a2v__/`**：内容根里的页面据此引用 skill 的样式与脚本，
  与内容根位置无关；渲染/预览/体检用的本地服务器按声明的前缀映射，
  仓库内的页面继续用相对路径（逐帧行为不变）。
- **成片溯源升到 version 3**：改记「工作区根相对路径 + 挂载资产键」，不再依赖
  `.git`/`pyproject.toml` 标记定位；仓库外文章的成片仍能给出
  `对得上 / 落后 / 无法判断`，而不是永远无法判断。
- **测试与文档同步**：去掉测试对未跟踪内容的硬依赖；README、Skill 主文档、
  目录约定参考、项目规划与协作约定一起更新。

## Impact

- 不改画面：默认（内容根=仓库根）时渲染结果与今天逐帧一致，示例页面与既有文章的
  引用方式不动。
- 不改分镜 schema、`window.__A2V__` 渲染契约与视觉规范。
- 已渲染成片的溯源 sidecar 是 v2，升级后会显示「旧格式，请重渲一次」——
  如实报告，不自动改写产物。
- 新增能力：内容根外置时的归属推导、别名引用、跨根溯源，都需要有测试守着。
