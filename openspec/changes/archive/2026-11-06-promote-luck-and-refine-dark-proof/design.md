## Context

参见 proposal.md。`luck-on-stage` 目前是 `videos/` 下被 Git 忽略的完整作品；示例必须位于风格包的 `examples/` 子树，源材料入库，生成媒体不入库。现有示例测试以每风格一个 slug 为前提。

## Goals / Non-Goals

**Goals:** 两部暗场论证示例可分别重建，文档读者能快速找到原则和操作入口；复利示例的图文层级、角色接棒与光效更准确。

**Non-Goals:** 改变共享风格 API、视频类型、v8 分镜格式或评审门禁。

## Decisions

1. 复制当前作品的分镜、场景、声音配方和必要来源说明到新示例，清理只服务旧制作周期的辅助脚本和历史记录。保留原 `videos/` 目录作为既有作品；新目录的产物必须重新准备，旧审核只作历史参考。
2. 将测试清单改为“风格 ID → slug 列表”，保留固定全集检查和指纹不变检查。比仅新增一个散列测试更能防止遗漏，也不改变运行时发现规则。
3. 复利示例沿当前数字、球、表格、折线、柱图、公式主线做精修。优先增加有效画面占比与字阶、收紧无信息留白、让金色球连续指向正在变化的数据；仍使用已有确定性组件，不引入同类依赖。
4. 文档精简先处理重复推演与案例堆叠；结构性契约保留在权威页，阶段入口和外链仍可用。任何删改的锚点须检查引用。

## Risks / Trade-offs

- [新示例复制后资源路径变化] → 用独立素材恢复与 `validate/prepare` 验证，不继承旧 prepared/QA 结论。
- [字阶放大后遮挡] → 检查原生帧和手机尺寸帧，做字幕及图表量测。
- [文档删减导致链接断裂] → 扫描相对链接、锚点与 JSON 路由。
- [渲染时间较长] → 按受影响场景预演，再生成完整当前候选和 QA。
