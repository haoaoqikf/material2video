## Context

动机见 `proposal.md`。这里只记影响方案取舍的现状与约束。

**引擎侧的既有事实**（`assets/typography.js`，已由 `tests/test_typography.py` 覆盖）：

- `fit(options)` 接收单个对象：`el` 必填、`text`、`availableWidth`、`maxLevel`（档位下标）、
  `minPx`；返回 `{level, fontSize, lineHeight, letterSpacing, lines, lineCount, fits, measured, reason}`。
- `resolveAvailableWidth(el, width)`：`width` 为假值时回落到元素自身的客户区宽度。
  因此 `declarative.js` 传的 `availableWidth: 0` 不会缩小到最小值，而是用元素实际宽度。
- `applyFit(el, options)` 写内联 `font-size` / `line-height` / `letter-spacing`，
  并在 `balance !== false` 时写 `el.textContent = lines.join('\n')` 与 `white-space: pre-line`。
- `autofit(root)` 只处理 `root` 内带 `data-a2v-fit` 的元素，并用
  `data-a2v-fit-for` 记录「文本 + 档位」签名，签名不变就跳过。
- 档位下标：hero0 / display1 / headline2 / title3 / lead4 / body5 / label6 / caption7；
  正文下限 `MIN_BODY_PX = 36`。

**组件侧的既有事实**（`assets/figures.css` + `assets/keynote.css`）：

- 预设给组件文字的两套字号：`figures.css` 用 `var(--a2v-ink-*, 原值)`，
  `keynote.css` 给其中一部分元素写了更高优先级的预设规则（例如 `.fig-number` → hero）。
- 因此「这个元素在预设下该是几号字」有两个可能来源，接线时必须以后者为准。

**渲染契约**：`A2V.type` 不属于 `window.__A2V__`，它挂在 `window.A2V` 上；渲染契约不变。

## Goals / Non-Goals

**Goals:**

- 让「字号由测量决定」从注释变成在成片里成立的事实：组件声明档位，引擎按实测宽度取档。
- 让引擎在接线后**不改变已放得下的文案的版式**（取档结果等于组件字号），
  也不改变未启用预设的页面（逐字节不变）。
- 让溢出无法静默发生：无论引擎是否接管，超安全区的文字都要被实测出来并报错。

**Non-Goals:**

- 不改渲染契约（`window.__A2V__` 的成员与语义不变），不改分镜结构。
- 不做 webfont 子集化；不做视觉模型自动评审；不做自动选择预设。
- 不把 `data-a2v-fit` 声明成「所有文字元素」：图注、轴名这类固定短标签的字号由
  组件与预设决定即可，接上引擎只会增加逐帧成本与漂移面。
- 不让引擎接管**含强调标记的文案重排**之后再去补一次强调——那需要改动组件的
  标记生成方式，属于另一层重构；本次只要求「不破坏」。
- 不追求「自动拆场景」。引擎报告 `fits: false` 与所需行数，拆场景仍由人（或上游 AI）决定。

## Decisions

### D1：均衡断行保留子元素标记，而不是「先抹掉再补回」

`applyFit` 现在直接写 `el.textContent`。两种改法：

- **甲：只在元素没有元素子节点时才均衡断行**，有子节点时跳过断行、只取字号；
- **乙：按文本节点逐段重排**，把 `lines` 结果重新分配到原有文本节点上，保留元素子节点。

选**乙**为主、**甲**为兜底。理由：`.quote-text` 这类元素的强调词正是「一句话里最该被
看见的几个字」，跳过断行等于在最重要的元素上放弃均衡；而逐文本节点重排可以做到
「元素结构完全不动、只改各文本节点的字符串」。若某个元素的结构无法安全映射
（元素子节点数量与文本片段对不上），退回**甲**：保留原标记与原文，只改字号，
并把这情况记为 `balanced: false`，由溢出闸门继续兜底。

**反面方案**：把强调词改成 CSS `background-clip` 或伪元素——伪元素无法按帧改样式，
逐帧渲染下必须靠真实节点，这条路已经在本项目里被否过。

### D2：档位声明取「预设下该元素的实际档」，并由测试锁死一致性

每个接线的元素声明 `data-a2v-fit="<档位>"`。档位不能凭感觉写，必须等于
`keynote.css` 在预设下给它的字号档（考虑到 `keynote.css` 可能覆盖 `figures.css`）。
一致性由测试守住：在真实页面里量出该元素的预设字号，要求它等于引擎取到的档。
这样「引擎取 40px / CSS 给 60px」这类双真源问题会在测试里暴露，而不是在成片里。

**反面方案**：让引擎自己读 CSS 字号作为上限——需要在每帧读一次 `getComputedStyle`，
且无法区分「预设覆盖」与「组件默认」，反而更脆。

### D3：溢出按「废片类」判错，而不是观感提醒

新增的溢出判定放在运行时探针的结果里，但按**错误**报告：正文级文本块的墨迹左/右/上/下
越出安全区，或 `fits: false`。理由：K 系列是「像不像发布会」，可以提醒可以跳过；
文字被裁掉或压出安全区是画面直接坏了，与 C 系列同类。仍然放在 K 编号序列里，
但在结果结构里标注它是硬判定，避免与「可以放行的提醒」混在一起。

### D4：可用宽度仍走元素自身宽度，不改成显式传参

`declarative.js` 目前传 `availableWidth: 0`，`resolveAvailableWidth` 回落到元素客户区宽度。
实测这比显式传安全区宽度更准：`.quote-text` 是 flex 项，它的真实可用宽度不等于安全区宽度。
因此**保留现状**，只补一条测试固定这一行为，防止以后有人「顺手修一下」把它改成安全区宽度。

## Risks / Trade-offs

- [接线后预设页面版式变化] → 用「取档结果必须等于组件字号」的一致性测试 + 逐字节回归
  （`examples/keynote-baseline` 限帧导出的 SHA256 必须与接线前相同）双保险。
- [逐文本节点重排写错，把文案搞乱] → 断言「重排前后去掉换行后的字符完全相同」，
  字符不丢不增；退化输入（空串、纯空白、只有一个字、含 `<br>`）各有用例。
- [元素没声明档位，溢出就查不出来] → 溢出闸门与声明与否**无关**：它直接量墨迹边界，
  没接引擎的元素一样会被查出来。
- [逐帧调用 autofit 带来性能与抖动] → 延续「签名不变就跳过」的机制；
  另加一条测试：同一帧连续取两次，第二次不产生任何 DOM 写入。
- [未声明预设的页面被波及] → `autofit` 只在 `preset` 存在时调用；用
  `examples/declarative-number` 的逐字节回归守住。

## Migration Plan

1. 先修 `applyFit` 的标记保留与退化路径，补单测；此时还没有元素声明档位，行为不变。
2. 再逐个元素声明 `data-a2v-fit`，每声明一个就跑一次限帧导出 + 逐字节对比，
   确认「放得下时结果不变」。差异出现就说明档位选错，退回重选。
3. 最后加溢出闸门与文档同步。
4. 回滚策略：档位声明是纯新增属性，删掉即回到「引擎空转」的现状；
   `applyFit` 的改动在无声明时不可达，可独立回滚。
