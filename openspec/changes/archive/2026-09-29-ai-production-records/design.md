## Context

参见 proposal.md。当前 CLI 创建空记录，制作状态由结构化 `production.json` 驱动；AI 能力由会话中的 Skill 助手提供，因此 CLI 不应另行接入模型服务。

## Goals / Non-Goals

**Goals:**
- 把制作规划与视觉复核纳入 article2video Skill 的强制操作流程。
- 让记录及渲染门禁能核对 AI 评审来源、证据材料摘要和现有输入指纹。
- 兼容读取旧记录，但旧的无来源通过结论不能解锁正式渲染。

**Non-Goals:**
- 不引入远程模型 API、模型密钥、CLI 模型选择或自动视觉评分服务。
- 不改变现有渲染器、分镜结构、机检判定或返工关闭规则。

## Decisions

- 在每个静态/动态评审对象上增加可选 `assessment` 来源：`reviewer: "ai"`、`model`、`session` 与材料引用；只有通过/失败的已完成评审强制要求该来源，待评审项仍可为空。
- `materials` 对联系表和评审视频清单保留输入指纹，并写入本体 SHA-256。若材料是包含视频的 JSON 清单，同时摘要其引用视频文件，避免原位替换视频后来源未变。
- 门禁逐项校验评审引用的材料类别、摘要和输入指纹；静态评审至少引用 keyframes，关键幕动态评审引用 samples，全片动态评审引用 rehearsal。静态忽略 media 指纹，动态绑定 media 指纹。
- Skill 要求当前助手亲自查看实际材料并写入可定位到场景/帧或时间的证据；CLI 负责结构、摘要和指纹校验，不自行生成语义结论。
- 旧记录仍按原结构加载和展示，但任何无 assessment 来源的已完成评审在新门禁下视为待评审/缺来源。

## Risks / Trade-offs

- AI 评审的语义判断仍可能错误 → 保存材料摘要、逐项依据与来源，确保可追溯和复评。
- 本地记录的来源声明不是密码学身份认证 → 仅用于审计工作流，不声称防篡改；材料 SHA-256 用于发现内容变化。
- 大视频摘要需流式读取 → 采用分块 SHA-256，避免把视频整体载入内存。

## Migration Plan

模板写出新来源结构；现有记录保持可读，但需重新检查当前画面并添加来源摘要后，才可通过门禁。回滚时旧代码忽略新增字段，记录结构兼容。
