## Context

当前共享 composition 通过 `scene.type -> default kind` 或显式 `data.figure.kind` 选择一个整页 React 组件。注册表统一了组件元数据，但整页组件同时承担布局、图形、内容槽位和动效，导致新增表达只能新增组件，且不同文章采用相似场景类型时必然复用相同页面骨架。详见 [proposal.md](proposal.md)。

现有系统已经具备必须保留的约束：分镜是内容与时长的单一真源、画面逐帧确定、预览和导出同源、严格 schema 校验、DOM 契约探针、K/M 验收闸门、内容根与输出归属规则。新版结构需要在不引入运行时模型服务和任意页面代码的前提下扩大组合空间。

## Goals / Non-Goals

**Goals:**

- 用一个版本化、可校验的场景树取代整页语义组件选择。
- 让 AI 分开决定内容、全片视觉策略、逐幕视觉意图、布局和动效，并能局部返工。
- 通过少量可组合原语获得远大于整页模板的构图空间，同时保持品牌令牌、确定性和自动验收。
- 为旧分镜提供显式、保守、可审计的一次性迁移路径，迁移后只运行新版架构。

**Non-Goals:**

- 不在仓库内增加自动调用模型的分镜生成服务。
- 不允许 AI 输出可执行页面代码、自由 CSS、任意坐标脚本或第三方组件引用。
- 不保证旧组件迁移后逐像素一致，也不长期维护旧组件渲染器。
- 不用算法替代最终人工审美评分；多样性检查只拦明显结构复用。
- 不在本变更中增加背景音乐、发布平台或历史版本管理。

## Decisions

### 1. 最终分镜内嵌视觉策略、视觉意图与场景树

最终 `storyboard.json` 增加根级 `schemaVersion` 与 `visualDirection`，每幕增加 `visualIntent`、`sceneTree` 和 `motions`。内容字段继续保留在场景数据中，树节点优先通过受控引用读取内容，避免在视觉结构里复制文案。

中间生成过程可以使用临时推理，但渲染只依赖最终分镜。这样可复核各阶段，又不增加多文件同步问题。备选方案是为每阶段保存独立 JSON；它会制造新的真源冲突，因此不采用。

概念结构如下：

```json
{
  "schemaVersion": 2,
  "visualDirection": {
    "motif": "boundary",
    "compositionBias": "asymmetric",
    "density": "sparse",
    "rhythm": "restrained",
    "avoid": ["repeated-center"]
  },
  "scenes": [{
    "id": "claim",
    "type": "quote",
    "data": { "text": "真正害怕的是被否定" },
    "visualIntent": {
      "relation": "focus",
      "focus": "text",
      "composition": "offset",
      "density": "sparse",
      "tone": "tense"
    },
    "sceneTree": {
      "id": "root",
      "type": "stack",
      "children": [
        { "id": "halo", "type": "shape", "shape": "spotlight" },
        { "id": "claimText", "type": "text", "contentRef": "data.text", "role": "headline" }
      ]
    },
    "motions": [
      { "target": "claimText", "recipe": "reveal", "startFrame": 18 }
    ]
  }]
}
```

### 2. 原语分为布局、内容和图形三类

第一版原语保持小而闭合：

- 布局：`stack`、`row`、`column`、`split`、`grid`、`radial`、`overlay`；
- 内容：`text`、`number`、`image`、`icon`、`chart`；
- 图形：`shape`、`surface`、`connector`、`group`。

原语使用枚举化属性和设计令牌，例如 `align: start|center|end`、`role: headline|body|label`，而不是任意 CSS。允许比例、间距档位和有限形状参数，但不允许通用 `x/y/transform/style` 逃生口。自由坐标会让安全区、响应式布局和契约检查失效，因此即使牺牲部分表达自由也不提供。

备选方案是保留现有整页组件并增加 `variant`。它改动较小，但仍把组合空间锁在人工枚举模板上，不能满足“取消自定义组件”的目标。

### 3. 原语注册表取代组件注册表，但沿用单一真源机制

继续以 JSON 注册表作为跨 TypeScript、Python 和文档的唯一真源，但元数据改为节点 schema：类别、属性类型与枚举、内容插槽、允许父子关系、容量、可用动效、渲染来源和测试锚点。同步命令生成 TypeScript 类型、Python 镜像和原语目录；测试验证重新生成无差异及声明属性确实被渲染层消费。

图表和关系布局作为可嵌套原语保留，避免退回手写 SVG。现有整页组件源码在迁移和视觉基线完成后删除，不作为隐藏兼容层继续存在。

### 4. 渲染器采用递归解释器和两阶段布局

共享 composition 对每幕执行：

1. 校验并解析内容引用；
2. 自上而下传递可用区域和令牌；
3. 自下而上量测需要字体尺寸的内容；
4. 确定布局框并冻结几何；
5. 根据帧号计算节点可视状态；
6. 输出带 `data-a2v-node-id`、原语类型和动效锚点的 DOM/SVG。

字体量测只参与确定性取档，不允许依据当前动画状态改变布局。对于图表、径向和关系布局，使用纯函数几何核；相同输入返回相同结果。

### 5. 多样性使用归一化布局指纹，不读取正文

每幕指纹由下列信息生成：归一化树形、原语类别序列、主要分区比例档、焦点象限、密度档、视觉意图关系和动效配方序列。文字内容、口播、具体数值、场景 id 不进入指纹。

检查分三层：

- 相邻同构：连续场景结构完全相同或仅替换内容节点；
- 片内复用：同一指纹或近似指纹超过阈值；
- 跨作品相似：只对命令显式提供的参考分镜集合运行，避免扫描用户内容目录。

报告展示匹配特征，不只给一个不透明分数。阈值放在版本化规则中，并用正反样例测试。第一版将明显同构作为严格失败，近似相似作为人工提醒，以降低误报。

### 6. 旧格式通过离线迁移命令升级，不做运行时兼容

迁移命令单文件输入、显式输出，默认不覆盖。它保留场景 id、内容、口播、时长和主题，再通过固定映射把旧组件转换为基础原语树。例如 `number` 转为数字文字与标签组合，`versus` 转为分栏与两个表面，`flow` 转为关系布局和连接原语。

隐喻无法等价转换时，迁移器选择内容安全的基础布局并在报告中标记人工重编排；不为了“成功”而虚构视觉含义。新版入口遇到旧格式立即给出迁移提示。

回滚方式是保留原始旧分镜与变更前代码版本；由于运行时不双轨，已部署新版代码不能直接渲染旧格式。迁移替换前必须保留原文件或使用版本控制/外部备份。

### 7. 验收锚点提升到场景树节点

每个可渲染节点输出稳定的节点 id、原语类型、内容来源和动效锚点。契约探针核对：声明节点是否存在、内容引用是否真正画出、节点是否在父容器内、动效目标是否可量测。现有 K/M 分类和退出码语义保留，新增树结构、多样性与迁移报告单独列项。

## Risks / Trade-offs

- [组合空间扩大后 AI 可能生成合法但平庸的树] → 用视觉策略、逐幕意图、多样性检查和人工量表形成四层约束，并提供高质量示例。
- [递归布局和字体量测增加渲染成本] → 限制树深、节点数和原语容量；布局按幕与输入缓存，逐帧只计算视觉状态。
- [禁止自由坐标会限制特殊构图] → 先扩充可复用布局原语；只有多个作品都无法表达的基础能力才新增原语。
- [旧组件无法完全映射] → 迁移报告明确标记损失与人工复核，不承诺像素等价，不静默替换原文件。
- [多样性阈值误伤合理重复] → 严格失败只覆盖连续完全同构，近似复用先作为提醒；报告公开匹配特征和规则版本。
- [一次性删除旧运行时使升级不可逆] → 迁移默认输出新文件，示例先迁移并建立基线，正式替换前完成校验和视觉验收。

## Migration Plan

1. 定义 v2 schema、原语注册表和生成物，不接入正式渲染入口。
2. 实现原语运行时、递归解释器及节点契约探针，以专用 v2 示例完成结构、视觉和性能基线。
3. 实现分阶段生成规范、多样性指纹和检查器，补齐正反测试。
4. 实现旧组件到场景树的迁移器，为仓库内示例生成候选 v2 分镜并逐个验收。
5. 将预览、评审和渲染入口切换为只接受 v2；更新媒体准备中对分镜内容和时长的读取。
6. 删除旧默认映射、整页组件渲染路径和作品专属 composition 支持；同步 Skill、README、规划与示例。
7. 运行全量测试、严格校验、构建、代表性预览/限帧渲染和视觉评审后提交；失败时回退切换提交并保留迁移产物供排查。
