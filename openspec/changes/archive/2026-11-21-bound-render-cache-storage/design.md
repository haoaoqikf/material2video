## Context

作品运行时在同一个构建根内串行打包。渲染和静帧采集在构建锁释放后继续读取构建目录。代码场景将逐帧临时文件和已发布的片段放在同一个缓存根。

## Goals / Non-Goals

**Goals** 控制构建数量，保持构建的完整性检查，回收中断留下的录制工作目录。

**Non-Goals** 历史评审去重和已发布片段的保留策略属于独立问题。

## Decisions

- 每个构建根保留最近使用的八份。沿用现有构建锁协调保留判断和使用登记，渲染及取帧只在读取构建期间持有进程登记。并发占满时使用调用方的临时构建，不要求等待其他渲染结束。
- 录制工作目录使用包含创建进程号的独立名称。并行采集子进程在写入前登记。下次录制回收超过 24 小时且所属进程均已退出的工作目录。沿用跨平台进程探测和 Python 标准库，保留并行能力及现有媒体引用。
- 无归属的旧录制目录由本次人工核查处理。模板和随附示例采用相同的保留逻辑。已交付本地作品保持其固定的运行时，避免改变现有准备指纹和评审绑定。

## Risks / Trade-offs

- 锁和目录状态无法确认时保留现场并记日志。空间回收会在后续录制或构建重试。
- 容量按构建数量计算，单份产物大小取决于作品。
