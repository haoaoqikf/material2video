## Context

当前金融材料使用请求 v1、价格 v3、计划 v5；React 从完整日期范围计算横坐标，Python 校验固定横轴声明，预演评审要求横轴固定。动机见 [proposal.md](proposal.md)，行为要求见 [增量规格](specs/financial-timeseries-video/spec.md)。

## Goals / Non-Goals

**Goals:** 自动年度分阶段扩展，随机寻帧一致，平滑刻度和完整历史；显式迁移并重新评审。

**Non-Goals:** 不改变日期推进速度、纵轴策略、价格口径、事件层或音轨，不增加手工阶段配置。

## Decisions

### 阶段与帧区间

覆盖年份数为终年减起年加一，步长为 ceil(N / 6)。首边界为起年加步长减一的年末，逐步增加步长，所有边界截断到终日并去重。采用约六阶段而非逐年缩放，降低长历史中的运动频率。

对每个非最终边界，求 advance 内日期位置首次严格超过边界的帧 c；过渡区间为 [max(advanceStart, c-15), c]。重叠或相接区间合并，起点取最早起点、终点取最晚终点、目标取最远边界。以 UTC epoch day 和现有连续帧日期映射计算，避免闰年与时区误差。

对区间 [s,e]，令 t=clamp((frame-s)/(e-s),0,1)，以 t*t*(3-2*t) 插值旧边界与目标边界；实际右边界取插值与当前日期位置的最大值，并截断到终日。这一包络保证高速播放时不裁切最新点。单日仅计算跨度使用至少一天，显示边界仍为真实日期。ending 使用最后推进帧状态。

### 刻度与性能

将现有日期刻度生成器拆为间隔选择与指定间隔生成。过渡使用旧间隔，进入视野的新刻度在图右侧最后 24 像素内按距离淡入；完成后 6 帧内交叉淡化旧、新间隔，相同日期合并为单一标签。下一次扩展开始时结束上一刻度淡化，终幕直接冻结最终刻度；淡化不延伸进终幕。

阶段和过渡可按不可变计划缓存，帧求值不得依赖上一帧 React 状态。最多六阶段，不为每帧重复扫描全部价格，保留现有前缀纵轴缓存。

### 版本与评审

v6 是唯一活动计划版本，axis.dateScale 使用 staged-expanding，无新增参数。沿用 migrate-line 和现有备份、失败回滚机制，纳入 v5；不静默修改旧作品。计划变化使旧评审失效，评审替换“横轴固定”为“分阶段扩展稳定”，检查左边界、扩展、历史保留和终幕。

## Risks / Trade-offs

- 历史斜率随缩放改变 → 明示横轴扩展，短时过渡后保持稳定范围。
- 极短视频过渡重叠 → 合并区间并用当前日期包络保证所有已揭示点可见。
- Python 与 TypeScript 契约漂移 → 共用合成日期案例，检查 v6 声明、迁移及逐帧边界。
- 刻度拥挤 → 沿用约七个刻度的稀疏策略，并抽检扩展前、中、后。

## Migration Plan

先落地 v6 生成、校验和渲染，再扩展显式迁移及评审。迁移核验数据并备份全部旧活动材料和评审，保留来源、价格与已有成片，生成 v6 并要求完整预演；写入失败恢复活动材料。回滚使用备份与旧版本工具，不让新工具直接渲染旧计划。

提案阶段仅提交规划文档；实施阶段同步 README、Skill 参考文档并核对既有三个示例，完成验证和提交后自动归档。
