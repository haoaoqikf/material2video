## Context

通用讲解片的诊断能力目前集中在 `explainer-design.md` 的看图改图检查表（十二项勾选）与 `visual-creative-direction.md` 的可见变化七类表。前者只回答查什么，后者回答什么是变化，但都不回答"看到某个具体现象是为什么、该改哪一层"。同时形象判据停在"它本身是个东西吗"，没有回答要画到什么程度才算画了。

本变更采用症状→成因→改法的因果表形态与“画得像它本身”的判据，将看图观察转成具体修正办法。

## Goals / Non-Goals

目标是让制作助手看图时能把问题定位到美术方向、取景或实现参数，并为"形象是否成立"提供可判定条件。同时把可见变化的定义收敛为唯一权威，避免多处摘要各自漂移。

非目标：不新增验收门禁、不改变审核轮次与人数、不改变分镜 schema 与渲染契约、不新增 CLI 命令、不复制外部资产、不追溯改写既有作品的记录。

## Decisions

- **诊断表独立成文件**，不塞进 `explainer-design.md`：后者已是 5361 字符的讲解设计正文，诊断表属于"返工定位"这一不同用途，独立文件可按需展开，符合现有条件路由的阅读模型。
- **判据写成可判定条件而非形容词**：每条都能回答"这样算不算"，例如旁边加名称标签不算画出该物体；否则判据会退化成"要画得像"式空话。
- **主体尺度给起点不给阈值**：占宽比例与最小可辨单元作为设计期反推的起点，与 `reference-style.md` 的事后量测衔接但不互相替代。给固定像素会成为所有画幅通用的假标准，与项目既有的"不设所有画幅通用固定像素字号"原则冲突。
- **可见变化收敛到 `visual-creative-direction.md`**：该处已有完整表格、弱强示例与映射表，其余位置本就是摘要。转介时保留一句可自查结论，避免单文件阅读时规则丢失。
- **开场闸写成阶段内证据**：不新增用户确认或独立评审轮，因为 `video-production-workflow` 已明确禁止新增用户确认门禁。
- **终检门槛表声明冲突让位**：门槛表是自查定位工具，与 `checkpoint-gates.md` 的审核策略重复时以后者为准，避免出现第二套完成条件。

## Risks / Trade-offs

- **转介后单文件阅读丢失上下文** → 每处转介保留一句可自查结论，并逐条核对权威定义里有对应原文。
- **诊断表与既有勾选项重复** → 检查表保留为使用点（勾选），诊断表负责成因与改法，两者分工写清，不互相替代。
- **字符预算超限** → 阶段指南加内容后可能逼近 3000；超限时压缩措辞或改为条件路由，不抬预算。
- **判据被当作自动通过条件** → 明确写入规格：判据用于设计与返工定位，不替代独立评审的实际观察。

## Migration Plan

新规则适用于后续启动的制作与修订任务，不追溯改写既有作品的合同、报告或完成状态。文档改动随提交生效；回退本次提交即可恢复到原检查表与分散摘要。完成后同步 `explainer-visual-diagnosis` 与 `video-production-workflow` 主规格并归档。
