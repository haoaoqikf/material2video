## Why

「高级感」目前是**散落在规范里的数值 + 组件里的裸数字 + 每次都靠人眼收尾**，
没有一处是「可以被判定的目标」。结果是：同一套组件在不同视频里观感差异明显，
换个人（或换个模型）重做一遍就会漂移；`videos/never-fear-interviews/` 里两条排版结论
（每行 888px 反推字号、浅色主题必须另覆盖字幕）是在**成片之后**才被发现的，
说明前端缺一层「排版先算好再画」的机制。

同时，项目里有两个已经反复被证明有效、但只做了一半的做法：

1. **共享资产层**（`base.css` / `theme.css` / `timeline.js` / `figures.js`）——
   证明「AI 做导演、共享资产做设计」是可行路径，但它只固化了颜色与手感，
   **没有固化排版尺度、间距网格、层级与版式约束**；
2. **`review.py` + 设计宪法**——证明「能不能机检」是这套体系的地基，
   但机检项只覆盖「不是废片」（安全区、墨迹、契约、曲线），
   **完全覆盖不到「好不好看」那一半**，而后者才是观感差异的来源。

本变更把这两件事补完：**引入一层成熟的设计语言（含外部开源字体与令牌体系）**，
并把「发布会级别的排版与画面纪律」变成**可机检的量化闸门**，
让「稳定输出发布会级别观感」从愿望变成每次渲染都能复核的判定。

## What Changes

- **引入外部成熟资产并落盘**：随仓库分发 Inter Variable（拉丁）与 Noto Sans SC Variable
  （中文）两套可变字体及其 OFL 许可证，替代「依赖本机系统字体」的字体栈。
  字体是观感的第一个变量，也是「配色一样但看起来不一样」的主要原因；
  落盘而不是走 CDN，是为了渲染可离线、可复现。
- **新增设计语言层**（`assets/keynote.css`）：把现有令牌从「颜色 + 手感」扩展为
  一套完整的版式系统——模块化字号阶（固定比例、每幕字号种类受限）、8pt 间距阶、
  五个圆角与三级投影、字号相关的行高与字距配对、焦点光晕强度阶、
  以及两级对比度下限（正文 7:1 / 大字 4.5:1）。
  以 `data-a2v-preset="keynote"` 显式启用，未启用的既有视频画面不变。
- **新增排版引擎**（`assets/typography.js`）：用测量得到的字宽把「一行放得下几个字」
  变成计算而不是试错——`fit()` 在字号阶上向下取档（不缩到下限以下）、
  `balance()` 按语义均衡断行（禁止末行只剩一个字）、`optical()` 做标点悬挂。
  现有做法是「先写字、再看效果、再回来改字号」，本层把这一步前移到渲染时确定。
- **新增主题预设**：`keynote-dark` / `keynote-light`，按**亮度序**组织表面层级
  （同一主题内的组件不重新发明自己的颜色），强调色只允许一个，
  对比度在令牌层就给足，避免「浅色主题上字幕读不出来」这类成片后才发现的缺陷。
- **新增可机检的观感闸门**（设计宪法 K1–K6）：留白预算、强调色占比、
  同帧字号种类上限、对齐基线、正文对比度、卡片纪律。
  这些规则由 `review.py` 在帧量测阶段给出数值结论，
  与现有 C 系列（不是废片）分开计分，不混为一谈。
- **同步文档与示例**：把「什么算发布会级别」写成可判定的规范
  （新增 `references/keynote-design-system.md`），
  更新视觉规范、设计宪法、组件目录、Skill 主文档、README 与项目规划。

## Capabilities

### New Capabilities

- `keynote-design-system`：发布会级别的设计语言与它的可机检判定——
  外部字体资产的落盘与许可、令牌体系（字号阶 / 间距阶 / 层级 / 对比度）、
  排版引擎的拟合与断行契约、主题预设的启用方式、观感闸门的量化条件，
  以及启用该预设时的兼容与降级行为。

### Modified Capabilities

- `declarative-video-scenes`：共享声明式路径 SHALL 支持在分镜里声明设计语言预设
  （`visual.preset`），并在启用时加载对应的排版引擎与主题令牌；
  未声明预设时行为不变。该改动只增字段、不改既有字段语义。

## Impact

- 制作 Skill 的资产层（新增 `keynote.css` / `typography.js` / `fonts/`）、
  共享声明式页面与它的脚本、参考文档、设计宪法与机检脚本；
- 新增能力规格与文档，`declarative-video-scenes` 主规格增一条需求；
- 不新增 Python 运行时依赖，不接入网络服务或密钥；字体为随仓库分发的外部开源资产
  （SIL OFL 1.1，附许可证文件）；
- 渲染契约（`window.__A2V__`）、分镜结构版本、输出归属与音频链路不变；
  既有视频与专属网页路径继续按原方式工作，未启用预设的画面逐帧不变。
