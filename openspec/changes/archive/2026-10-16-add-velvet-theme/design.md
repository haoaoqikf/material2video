## Context

主题此前是 `web/src/palette.ts` 里的一份 TS 记录，只承载六个颜色字段；`ArticleExplainer`
通篇用内联样式消费它，而 `tokens.css` 是另一套只提供深色的令牌层（`keynote-design-system`
第 34、48 行：只提供一套深色，且禁止按属性切换的作用域层）。因此**多主题只能靠数据**，
不能靠 CSS 作用域层——后者在没有代码挂属性时整层令牌是空值，画面会静默落到初始值。

本轮要把主题扩到颜色之外，并引入第三条主题。难点是准备阶段也要用主题的动效帧数：
`explainer_prepare.py` 依赖转场时长与阅读停留编译时间轴和 `minimum` 判据，
Python 若拿不到主题动效，「改主题也只改到画面那一半」。

## Goals / Non-Goals

**Goals**：主题成为颜色 / 排版 / 动效的唯一真源；引入 `velvet`；主题可接管转场与阅读停留；
dark/light 既有作品画面逐像素不变。

**Non-Goals**：不改分镜字段；不让 `tokens.css` 变成多主题；不引入 CSS 作用域层；
不照搬原风格的 web 尺度字号；不落地缓动曲线（画面仅由帧号驱动，源码闸门拒绝 CSS 动画）。

## Decisions

**动效以帧数表达。** 原风格给的是秒与 GSAP 缓动名（`sine.inOut` / `power1.in`）。
画面仅由帧号驱动，`animation` / `transition` 会被 `source_policy` 拒绝，因此主题里的动效
只能是帧数：入场 36、停留 90、转场 45（30 fps 下对应 1.2s / 3.0s / 1.5s）。
缓动曲线在文档中标注为「当前不渲染」。

**数据放 JSON 而不是 TS。** Python 需要读同一份主题规格。可选方案是与 `fonts.json`
同构的共享 JSON、由 Python 解析 `palette.ts`、或在 Python 另存一份。选 JSON：
真源唯一、不需要解析 TS、且 `web/src/assets/fonts.json` 已有先例。
Python 侧的 `m2v.engine.themes` 只暴露编排需要的部分（主题名单、默认主题、动效帧数），
颜色与排版不经过 Python——把它们搬进准备产物会让「调一个色值」也要重新准备。

**主题覆盖分镜的边界。** 语义定为「主题声明了就覆盖，没声明就让位」：
`velvet` 声明 45 帧转场，因此覆盖每幕的 `transitionFrames`；dark/light 不声明，
沿用分镜与契约默认值，行为与从前一致（既有作品里声明过 `transitionFrames` 的仍然生效）。
转场**类型**始终由分镜决定，所以「首幕必须 cut」不受影响。

**颜色按对比度预算改编，不做原值照搬。** 原风格只给 primary / on-primary / accent 三色，
且 accent 在近黑底上只有 1.49:1。取 `bg`/`ink` 原值，`muted`/`panel`/`border` 按
`design-tokens.md` 既有的对比度预算派生，accent 保留靛蓝色相提亮为 `#c5cae9`（12.25:1）。
改编理由写进 `themes.json` 的注释与参考文档，不留在提交信息里。

**验收方式。** `dark`/`light` 保持原有的逐帧字节相等守卫（非单调 seek 下同一帧必须一致）；
`velvet` 不加入该守卫，因为它的 36 帧入场会让 Chrome 对亚像素偏移的合成层复用不同光栅缓存，
面板圆角出现约 1 个色阶的单像素差异——是光栅缓存而不是画面状态。`velvet` 改由
计算样式与入场进度判定（背景色、字重、字距、第 18 帧正好过半）。

## Risks / Trade-offs

- **入场 36 帧可能长于一个短旁白段**，元素在切换前尚未完全显影。这是照搬原值时长的直接
  后果，本轮不设门禁，调整入口是改写旁白分段或改主题帧数。
- **主题数据外置后多一处构建期依赖**：`themes.json` 结构错误会在校验与准备阶段报错，
  已由 `m2v.engine.themes` 的显式校验覆盖（缺字段、未知字段、非正整数、默认主题不存在）。
- **作品代码场景拿到的是主题名字**，需要覆盖清单里的每一个主题；只写「浅色走 A、其余走 B」
  会在新增主题时静默把新主题当深色画。本轮只在参考文档写明，不做静态检查。
- **`velvet` 的 45 帧转场会显著拉长成片**（逐幕多出 37 帧），是否越 600 秒上限由既有检查兜底。

## Migration

无。dark/light 取值与从前逐字相等，既有作品重新准备后画面不变（已用改动前后的
dark 截图哈希比对确认）。旧材料的 `visual.theme` 仍只接受清单内的名字。
