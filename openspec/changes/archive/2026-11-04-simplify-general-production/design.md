## Context

动机见 proposal.md。general 的渲染、制作证据与独立审核已经分离；本次复用 v2 合同和现有来源摘要，不建立第二套状态或导出门禁。

## Goals / Non-Goals

目标是减少人工重复记录和媒体处理次数，同时保持风险窗口、当前版本绑定、完整全片检查与独立终审。专用类型、画面运行时、分镜版本和独立身份认证保持当前范围。

## Decisions

1. DESIGN 只保留全片原则、逐场表、必要附件。原五块与立意六项作为设计提示合入全片原则，不再各自填表；逐场运动引用分镜/代码事件，只有未决风险需要详细导演卡。全片声明的缺省项不逐镜解释。
2. 操作顺序归三份阶段指南；production-workflow 只维护跨阶段的修订、基线、局部检查、回退和记录规则。保留旧锚点的简短链接导航以免现有活动引用失效，不保留旧规则副本。不使用七步作为另一套流程编号。
3. open/closed 仍是唯一机器问题状态。未解决、待复查映射 open；已关闭映射 closed；接受保留仅用于非必改项，保持 open 且 required=false，正文记录影响，不冒充解决。外部评审明确为补充意见，不新增身份认证或降低独立要求。
4. G4 无显式步长时，普通窗按半秒取帧；动态/时序风险未声明最短节拍时保持逐帧，声明后步长不超过该节拍；显式步长仍受密度检查。指定帧、起止、文字/状态/时序边界与幕内事件前后帧必取。完整过程视频始终保留。默认输出原生与393宽，目标对照确需852宽时才派生该宽度。
5. 复用 Pillow 13（已有依赖，HPND 许可）一次解码、多尺寸 LANCZOS 缩放，替代每图每尺寸 ffmpeg 子进程。调研依据：https://pillow.readthedocs.io/en/stable/reference/Image.html 、https://pillow.readthedocs.io/en/stable/reference/open_files.html 。ffmpeg 继续负责视频与时间精确拼接，复用现有实现，依据：https://ffmpeg.org/ffmpeg-filters.html 。无需新依赖或自研图像/媒体引擎。
6. G3 的 --timing-reports 接收输出根内当前 G4 报告路径，只复用实际采集且摘要、上游、窗口有效的过程片段；全部时序风险须覆盖，缺证明确失败，不静默回退。报告同时绑定复用来源与 G4 上游；status/register 校验该依赖，源码改变立即使 G3 过期。仅复用过程证据，不继承 G4 通过或独立观察。
7. 无复用报告时，animatic 只生成风险镜头及紧邻镜头上下文，并登记原场景、原帧窗与输出帧窗映射。无 structure-timing 风险时仅做 G3 分镜映射检查。
8. manifest 构建提取为打包器共用函数，文档同步脚本通过该函数投影确定性示例；正常推进只链接报告。详细回退模板只用于局部修复、补证、重设计，重渲染理由并入原问题记录。

## Risks / Trade-offs

- 普通窗降采样可能漏瞬时缺陷 → 已知动态风险维持逐帧或按声明节拍，所有事件及状态边界强制取帧，保留过程视频，证据不足继续补证。
- 复用时序片段可能过期 → 校验报告摘要、完整证据、原采集窗口和当前 G4 上游；状态查询重新核验，不能只信生成时检查。
- Pillow 与 ffmpeg 缩放像素可能略异 → 不用像素一致替代审美；验证尺寸、原图保真、颜色/透明度与可读性，视频编码不变。
- 历史示例缺少正式新流程证据 → 仅整理设计结构与引用，不补造历史评审或宣称成片重新通过。

## Migration Plan

保持 v2/v8 格式，不自动迁移作品历史。六个规范示例整理为新记录结构，既有事实、体验与来源仍保留。先执行契约/媒体/真实浏览器验证，再独立代码审查、提交；完成后自动归档同步主规格。

性能验收使用固定10秒30fps普通窗口：无边界时采样从300降至不超过23帧；图片派生不启动 ffmpeg。记录真实批处理与原逐图子进程的耗时比较，不把该结果外推为全片渲染加速。

回归发现 Windows 缓存收据替换可被短暂文件占用中断；复用 core.delivery 已有的有界 PermissionError 重试，不另写一套重试策略。共用代码场景夹具移入 tests/helpers/general.py，消除单独运行风格测试时依赖其他测试模块先被收集的问题。
