## Context

当前运行时已具备帧驱动 beat、场景级镜头、显式跨幕映射、风格包与连续焦点混合，但镜头是一条覆盖整幕的简单曲线，节点动效只读取单个绝对窗口，跨幕连续性也主要通过透明度和局部缩放近似。实现必须继续满足离线渲染、随机寻帧、预览与导出同源、无 DOM 布局测量和旧 schema v2 可解析等约束。动机与破坏性兼容选择见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 建立一套由 beat 驱动、可独立求任意帧的统一动画计划。
- 让节点、共享元素与镜头的变换可以组合，而不是互相覆盖。
- 让场景树获得自动编组能力，同时给代码场景稳定且有限的接入边界。
- 用运行时探针与评审量测守住连续性、节奏和稳定收尾。

**Non-Goals:**

- 不引入基于 DOM 实测的 FLIP、截图纹理、粒子系统或第三方时间轴引擎。
- 不提供旧动画语言开关，也不保持旧成片视觉哈希。
- 不自动理解代码场景内部结构，不替代人工审美裁决。

## Decisions

1. **先解析动画计划，再逐帧求值。** 运行时把 scene、beat timeline、motions、camera 和 transition 解析为不可变 `SceneMotionPlan`；计划只含帧区间、目标 id、阶段、轨迹和插值参数。逐帧函数只读取该计划，避免组件分别猜测时间。相比让每个原语自行解释字段，这能保证字幕、节点与镜头共享边界，也便于 Python 与 TypeScript 用同一测试向量核对。

2. **保留旧字段，增加语义编排字段。** `motions` 继续接受单个 `target`、旧 recipe、`startFrame` 和 `durationFrames`，同时增加 `targets`、`phase`、`beatId` 与 `stagger`。单目标与多目标互斥；有 `beatId` 时禁止再声明绝对起点。旧字段进入默认计划解析器，而不是保留一条旧渲染分支。

3. **镜头使用段列表，旧 movement 作为简写。** `camera` 增加 `segments`；每段包含受控 kind、`beatId` 或 `phase`、focus 与有限强度。现有 `movement` 被解析为默认的 `hold → movement → settle` 三段计划。这样旧文件无需迁移，同时不再产生整幕持续漂移。

4. **几何由布局原语解析，不读取 DOM。** 各布局原语根据画布、安全区、子节点次序、受控 gap / ratio / direction 产生归一化 `GeometryBox`；内容尺寸采用原语注册表中的受控档位与容器框，不以浏览器实测文字宽高作为转场输入。共享转场对源、目标框及 `VisualState` 做插值。文本内部仍由正常排版渲染，但不参与几何求解。

5. **变换分层输出 CSS 变量。** 基础布局、beat、节点 motion、continuity 与 camera 分别输出 translate / scale / rotate / opacity / visual-mix 通道，最终由单一组合器按规格顺序生成样式。选择 CSS 变量而不是串接任意 transform 字符串，是为了让探针能读取各层实测值并防止后写覆盖。

6. **状态语义离散，外观连续。** `data-a2v-state` 仍只表达唯一语义终态；运行时另输出 0..1 的 focus、muted、done 混合量。焦点交接分成旧焦点淡出和新焦点淡入两半，确保单一语义焦点规则与视觉连续性同时成立。

7. **代码场景只共享上下文和显式探针。** `A2VCodeSceneProps` 增加只读 motion plan 摘要、当前阶段、camera state 和 continuity state。代码场景若要参与节点连续性，必须通过探针暴露预先计算的归一化几何和外观；运行时不调用 `getBoundingClientRect`。探针缺失时回退到场景根级转场并记录诊断。

8. **评审以实际 DOM 通道为准。** 契约页逐帧读取 camera、motion、state mix 和 continuity 数据属性，量测速度是否归零、错峰间隔、混合量跳变和转场首尾误差。语义是否高级仍由 `review.md` 人工结论负责，脚本只判断可验证的运动事实。

## Risks / Trade-offs

- [风险] 受控几何与最终文字排版存在偏差 → 共享转场只承诺原语容器几何连续，文本字形不做逐字形变；测试覆盖安全区和首尾误差。
- [风险] 全局默认改变旧作品观感 → 更新仓库示例和视觉基线，并在发布说明明确重新渲染会变化；不维护双运行时。
- [风险] 多层变换增加调试难度 → 在 DOM 暴露每层独立通道和解析后的计划摘要，评审报告定位到场景、节点、阶段与帧。
- [风险] 短幕无法容纳标准节奏 → 先保留 12 帧稳定窗口，再等比压缩动作；仍无法容纳时在校验阶段失败。
- [风险] code 场景能力与 tree 场景不对称 → 文档明确其责任边界，未提供合格探针时只保证场景级镜头和转场。

## Migration Plan

1. 先增加 schema、计划解析器和共享测试向量，使旧分镜可进入新版计划。
2. 依次接入节点动效、连续状态、镜头段和共享几何；每一步保持随机寻帧确定性测试通过。
3. 扩展契约探针和 Python 评审，再更新仓库示例、视觉基线、README、项目规划与 Skill 参考文档。
4. 对标杆示例执行严格校验、联系表审美评审、完整渲染和码流验收。
5. 实施完成后同步主规格并自动归档；若验证失败，在归档前回退本变更实现提交，不引入 legacy 运行时开关。
