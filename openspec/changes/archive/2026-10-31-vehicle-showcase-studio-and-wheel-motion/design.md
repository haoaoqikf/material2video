## Context

动机见 [proposal.md](proposal.md)。当前实现把参考网页简化成了「RoomEnvironment + 方向光 + 灰色地面 + 网格」，这既不是参考网页的影棚，也无法给车漆提供正确反射。车轮旋转失效是 three.js 节点名清洗导致的查找缺陷，与参数无关。

参考仓库 `alphardex/su7-replica@6d56d36` 的观感由四层构成：HDR 影棚环境图（柔光箱）、顶部发光灯板、带平面反射的暗色地面、后期辉光。本次只取渲染需要的四张贴图（环境图、车漆 AO、地面法线、地面粗糙度），不引入其自定义着色器依赖、BGM 与角色。

## Goals / Non-Goals

**Goals:**
- 车漆、玻璃、金属和轮胎在 1920×1080 下呈现参考网页级别的反射与明暗层次。
- 背景为连贯暗色影棚：顶部柔光板、地面光池与反射、无网格、无地面边缘、无可疑光斑。
- 车轮在启动与疾驰段清晰可见地旋转，逐帧确定性，不频闪。
- 材料 v2 校验、准备内嵌、文档与测试一致；离线渲染。

**Non-Goals:**
- 不整体移植参考网页的 StartRoom 模型、芙宁娜角色、BGM、Speedup 模型与自定义反射后期。
- 不引入真实驾驶物理、道路、转向或车辆位移。
- 不改动共享无声渲染管线与其他类型。
- 不为 v1 材料提供兼容分支或迁移工具。

## Decisions

### 1. 材料 v2：影棚资产显式登记

`showcase.json` 升到 `schemaVersion: 2`，新增必填 `studio`：

```json
"studio": {
  "environment": "assets/studio/env_light.hdr",
  "bodyAo": "assets/studio/car_body_ao.jpg",
  "floorNormal": "assets/studio/floor_normal.webp",
  "floorRoughness": "assets/studio/floor_roughness.webp"
}
```

四个路径都必须是作品内相对路径、在 `manifest.json` 登记且摘要一致。准备时统一内嵌为 data URI，随 props 传给 composition，运行时零网络请求。

选择把影棚贴图放进作品材料而不是仓库共享资产：它们是第三方媒体，必须逐作品记录来源与许可，且不能入库。版本升级按项目约定不保留兼容分支，v1 材料直接拒绝。

### 2. 影棚由几何 + HDR + 反射构成

- **环境**：`RGBELoader` 读取 HDR，`PMREMGenerator` 预滤波后作为 `scene.environment`；帧内只调 `scene.environmentIntensity` 做亮灯显现与疾驰增强。
- **灯板**：车顶上方一块白色自发光圆形柔光板，中心亮、边缘渐隐，`toneMapped=false`，由辉光产生光晕；半径与车长成比例，环绕时不会读成硬多边形。
- **地面**：大半径圆盘 + 自定义着色器。每帧把主相机按 `y=0` 镜像后渲染到低分辨率反射目标（斜裁剪近平面，避免地面下方几何穿帮），地面着色器用法线贴图扰动反射 UV、用粗糙度贴图控制五点模糊半径、按菲涅耳混合反射与基色，并按距离衰减到黑色，消除地面边缘。
- **接触阴影**：车底一张程序化椭圆径向渐变贴图，压暗车底，弥补资产轮拱阴影偏弱。
- **后期**：`postprocessing` 的 `EffectComposer + BloomEffect`，亮度阈值让灯板和灯带发光，随疾驰增强。
- **背景**：纯黑；地面在约 25–30 单位内淡出到黑，不再出现地面边缘或网格。

### 3. 车轮：按清洗后名称查找，按本地 Z 轴旋转

three.js 的 `GLTFLoader` 使用 `PropertyBinding.sanitizeNodeName`，会去掉 `[ ] . : /` 并把空白换成下划线。`Wheel.001` 运行时的实际名称是 `Wheel001`。解析顺序：

1. 原名精确查找；
2. 清洗后名称查找；
3. 都失败则准备阶段仍按 glTF 原始节点名校验，渲染阶段报错（不静默跳过）。

旋转直接作用在节点自身（节点原点即轮心，几何在 X/Y 对称、Z 为轮宽方向），不再创建轴心组。角度由速度轨道解析积分得到：

| 时间 | 角速度 |
| --- | --- |
| 0–16 秒 | 0 |
| 16–19 秒 | 0 → 4.5 rad/s（启动加速） |
| 19–26 秒 | 4.5 → 13.5 rad/s（疾驰） |
| 26–28 秒 | 保持 13.5 rad/s |
| 28–30 秒 | 13.5 → 2.5 rad/s（收束减速） |

30 fps 下最大约 0.45 rad/帧（26°），小于五辐轮毂 72° 的对称周期，避免车轮频闪或倒转错觉。

### 4. 时间轴与确定性

所有状态都是 `frame / fps` 的纯函数：镜头、车轮角度、环境强度、灯板亮度、地面反射强度、辉光强度与抖动。反射目标每帧重渲染，不跨帧累积。乱序取帧结果必须一致。

### 5. 构图

环绕距离 8.2 → 7.05（侧视基准），高度 2.4 → 0.9，FOV 38 → 34，注视点 0.65 → 0.76；开场推近保留。侧视角看到车长、前后视角只看到车宽，距离按 `0.8 + 0.2·|sin(angle)|` 收放，使整圈主体占比稳定。目标：车漆、地面反射与顶部灯板在低机位下接近参考网页侧视图，同时整圈不裁切。

## Risks / Trade-offs

- **HDR 与反射在无 GPU 的 Chrome 中成本高**：先渲染 0–4、8–12、19–23 秒短段，实测耗时与显存；若 `HalfFloat` 后期缓冲不可用，退到 `UnsignedByte` 反射目标。
- **反射目标与主画面双重色调映射**：参考实现同样如此；以观感调反射强度，不追求物理正确。
- **顶部灯板在部分机位可能出画**：通过尺寸与高度比例保证其作为环境光晕存在；不要求每个机位都完整可见。
- **车轮网格可能包含同轴左右两轮**：绕节点 Z 轴旋转对同一轴线上的两轮同时成立；用近景预览确认无偏心。
- **资产授权**：新增四张贴图取自用户已确认授权的同一固定提交，仍需在清单中如实记录来源与用途。
