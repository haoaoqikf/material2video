## Context

各视频类型由 `VideoType.render` 执行正式渲染，统一 CLI 负责评审门禁并调用该适配器。金融、文章和通用适配器分别写入成片旁车，因此在各渲染器内分别清理会重复逻辑，也可能在旁车写入前误删旧产物。

## Goals / Non-Goals

**Goals:** 在统一入口确认新视频存在后，集中清理当前作品可再生成的旧媒体；限制文件系统作用域并逐项报告删除失败。

**Non-Goals:** 清理预演命令、源材料、准备媒体、评审 JSON 或仓库共享 Remotion 缓存；提供通用清理 CLI。

## Decisions

- 在 `m2v render` 调用类型渲染器并确认输出文件存在后执行清理。该时点保证类型渲染器已完成成片验收及溯源/性能信息写入；异常路径不会进入清理。
- 清理器只接受位于该作品 `outputs/` 内的当前成片路径。保留该文件及同名 `.srt`、`.provenance.json`、`.performance.json`；保留 `prepared.json`、评审 JSON 和 `media/`。删除 `previews/`、已知 QA/bench/接触表/临时渲染目录，以及其余旧视频和对应旁车。
- 删除按文件逐项处理，收集 `OSError` 后向 CLI 输出告警并保留成功渲染的退出状态；这样清理问题不会把已交付的新片误报成渲染失败。
- 清理器对符号链接和解析到 `outputs/` 外部的目标不递归跟随或删除；无法确认安全范围时跳过并报告。

## Risks / Trade-offs

- [输出目录可能包含未识别的派生物] → 清理旧视频及已知目录，不对未知普通文件做全目录清空。
- [成功渲染后部分文件被占用] → 按文件报告失败路径，保留新片并允许用户稍后手动清理。

## Migration Plan

无需材料迁移。现存作品在下一次统一正式渲染成功后自动清理其旧媒体；NVIDIA 作品按本次任务立即清理。
