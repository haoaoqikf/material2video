# 苹果级组件设计系统：把组件从写死的数字收口到令牌与状态

## Why

目标是把生成的网页在十三个维度上看齐苹果官网。发布会级设计语言层已经把**页面级**的
令牌建起来了（八档字号阶、8pt 间距阶、五个圆角档、三级阴影、两套主题、K1–K7 闸门），
但**组件级**没有跟上：约束在组件里没有落地，而现有的机检**结构性地看不到**它们。

### 证据一：间距、描边、字重三族在组件里根本没走令牌

实测 `figures.css`（2026-09-18）：

| 属性 | 声明总数 | 走令牌 | 字面值 | 字面值样例 |
| --- | --- | --- | --- | --- |
| `gap` | 13 | **0** | 13 | 30 / 46 / 18 / 22 / 44px |
| `padding` | 4 | **0** | 4 | `26px 20px 24px` |
| `letter-spacing` | 16 | **0** | 16 | 0.14em / 0.08em / 0.02em |
| `font-weight` | 10 | **0** | 10 | 500 / 600 / 700 / 800 |
| `stroke-width` | 18 | **0** | 18 | 2 / 3 / 4 / 5 / 6 |
| `border-radius` | 11 | 3 | 8 | 19px / `0 0 19px 19px` |
| `font-size` | 26 | 21 | 5 | 44 / 40 / 96px |

规范写着「组件设置外边距、内边距或元素间距时取值来自 8pt 间距阶」，
实际 13 处 `gap`、4 处 `padding` **一个都没走阶**，30 / 46 / 18 / 22 / 26 / 34 都不在阶上。
描边更散：2 / 3 / 4 / 5 / 6 五种线宽，没有令牌、没有语义——
苹果的图形语言是**少数几档线宽 + 固定的线帽线接**，现在是每张图各自决定线多粗。

### 证据二：字号阶在未启用预设的路径上自成一套，而且没人管

`keynote.css` 把 `--a2v-ink-*` 映射到字号阶（40 / 44 / 60 / 76 / 120px），
而 `figures.css` 里同一个令牌的 `var()` 兜底是另一组数：36 / 38 / 46 / 48 / 56 / 62px。
未启用预设时组件因此跑在阶外，K3（同帧字号种类）也数不到——层级统计变成一张漏网的表。
`tests/test_figures_assets.py` 只查「令牌有定义、不是硬编码白色」，不校兜底是否对齐。

### 证据三：SVG 里的文字**完全不在任何检查的量程内**

`inspect.py` 的文本采集显式排除 SVG 宿主文本（`ownerSVGElement` 或 `tagName === 'svg'`），
而 K7 唯一的参照矩形是 `.a2v-safe`。也就是说飞轮节点文字、双向选择节点文字、
冰山标注、天平载物文字、阶梯柱顶注**既不受安全区判定，也不受容器判定**。

后果是可见的：`figures.js` 的飞轮节点 `LOOP.NODE_R = 76`（直径 152px），
`.loop-node-text` 在预设下取 `--a2v-ink-value` = **44px**，四个汉字带 0.04em 字距约 **183px**
——比直径宽 31px，文字必然穿出圆。逐帧看图直接可见
（`outputs/examples/keynote-baseline/inspect/frames/loop-68-f1124.png`），
而 `report.json` 的 K7 写着「量了 2 个文本块，都在安全区内」。

### 证据四：卡片纪律在真正有卡片的画面上量不到

K6 的「卡片」由浏览器探针从 `[data-a2v-figure] > *`（**只取挂载点的直接子元素**）
且圆角 > 8px 的节点里采集。于是 SVG 内的圆角矩形（冰山标注、天平载物、阶梯柱）
与包在包装元素里的卡片**都不算卡片**：`examples/keynote-baseline` 八幕里 K6 跳过 11 次，
其中 `compare` 一幕画面上明明白白两张卡片。**跳过不是通过**，但一条量不到卡片的
闸门等于没有这条闸门。

### 证据五：状态表达有三套机制，没有一处统一

- `is-*` 修饰类：`is-fact` / `is-flat` / `is-accent` / `is-focus` / `is-left` / `is-right`；
- 自定义属性：`--vs-heat`（双栏对照的冷热）、`--a2v-emphasis-mix`（强调词褪色）；
- 内联几何：落差尺用 `height/top` 写状态，阶梯用 SVG 属性写状态。

同一个语义「强调/焦点」在三个组件里是三种写法。苹果观感的很大一部分来自
**同一套状态在每处都长得一样**；没有这套语汇，「主次分明」只能靠每个画面临场发挥。

### 为什么现在才发现

`TestFigureTokenCoverage` 只查令牌**有定义**、不查组件**有没有用**；
`test_typesetting_wiring.py` 只覆盖声明了 `data-a2v-fit` 的少数元素；
K1–K5 只看页面级文本与像素；`test_keynote_layout.py` 复核的是三种**版面**的几何，
不是组件内部的几何。**规范写了约束、组件没执行、机检没覆盖**——三者之间是静默失效。

## What Changes

把组件收口到一条闭合链：**令牌 → 基元 → 状态 → 机检**。

### 1. 补上缺的四族令牌

- `--a2v-stroke-1..5`（1 / 2 / 3 / 4 / 6px）：描边阶。语义分工——
  发丝边界 / 次级结构 / 数据描边 / 图形主体 / 焦点与运动轨迹。
- `--a2v-weight-{regular,medium,semibold,bold}`（400 / 500 / 600 / 700）：字重阶。
- `--a2v-track-{tight,snug,normal,wide}`（-0.03 / -0.015 / 0 / 0.06em），
  以及标签档 `--a2v-track-label`（0.14em）。
- 统一的**图形几何档**：节点半径、表面内边距、连线上限、箭镞尺寸各一档。

### 2. 引入图形基元与状态语汇

组件不再各自发明表面、标签与连线的长相。令牌层定义四个**基元类**，
组件在自己已有的元素上**追加**一个基元类，再挂一个状态属性：

| 基元 | 用途 | 例 |
| --- | --- | --- |
| `.a2v-surface` | 任何表面（卡片、节点圆盘、托盘） | `.vs-card`、`.loop-node-disc` |
| `.a2v-label` | 图形内的文字 | `.loop-node-text`、`.vs-text` |
| `.a2v-connector` | 连线、箭头、轨道、轴线 | `.loop-arc`、`.vs-arrow` |
| `.a2v-frame` | 边界描边（一个物体唯一可见的边界） | `.drop-track` |

状态只有四个，语义固定；**状态只表达语义，不表达动效**——
不透明度与位移仍由组件按帧推导：

| `data-a2v-state` | 语义 | 表面 | 描边 | 文字 | 光晕 |
| --- | --- | --- | --- | --- | --- |
| `rest` | 基准 | `--fig-surface` | `--fig-line` | `--a2v-text-1` | 无 |
| `focus` | 当前焦点（一屏一个） | `--fig-surface` | `--a2v-accent` | `--a2v-text-1` | 内外发光 |
| `muted` | 已被否定的那一侧 | 画布色 | `--a2v-hairline` | `--a2v-text-3` | 无 |
| `done` | 已完成 / 已翻转 | `--a2v-accent-deep` | `--a2v-accent` | `--fig-on-ink` | 无 |

### 3. 容器内文字不再溢出

两条一起用：

- **几何由内容驱动**：装文字的容器（节点圆、托盘、卡片、标注）先测文字实际宽度
  再定自己的尺寸，而不是先写死半径再把字塞进去。SVG 用同帧同步的 `getBBox()`
  （逐帧可复现，不引入时钟或随机数）；文字确实放不下时按字号档降档，
  降到正文下限仍放不下则由构建期检查报错，而不是让它溢出。
- **新增 K8 容器内溢出（硬判定）**：把 SVG 内的文字纳入量程，
  文本墨迹越出所属容器（闭合形状的边界、表面的内边距盒）即报错，
  给出文本内容、容器、方向与像素值，并入错误数与退出码。

### 4. 把 K6 的卡片采集修好，并新增一条闸门

- **K6 修采集**：卡片识别不再只看挂载点的直接子元素，改为遍历整幕；
  圆角判定对 SVG 元素改用图形自身的圆角/描边/填充特征，
  让 `compare`、冰山这类画面里的卡片真的被量到；确实没有卡片时照旧跳过并写明原因。
- **K9 图形描边一致性（提醒）**：同一帧里出现的线宽去重计数，
  不在描边阶上或同帧超过三档时提示；同时断言线帽与线接取值为约定集合。

### 5. 工作流同步

- `figure-catalog.md` 增加「新增组件必须挂基元与状态」的硬要求与新增组件检查单；
- `visual-spec.md` 的「排版自查」增加容器内溢出与状态一致性两条；
- `keynote-design-system.md` 增加新令牌表、状态表与分档理由；
- `design-constitution.md` 新增 C17（组件走令牌，不走裸数字）与 C18（状态语汇唯一）
  并写进「机检与人工的分工」表；
- `SKILL.md` 的制作流程增加一步：组件改动后跑基元与状态的契约检查。

## Impact

- **预设页面**：间距、圆角、线宽、字重、字距全部落回令牌；节点文字不再溢出；
  同一套状态在八个组件里长得一样。这一层的主要目的就是改变画面观感。
- **未启用预设的页面**：**逐字节不变**。手法沿用仓库既有约定——
  基元类只在预设作用域里有规则（不进作用域就没有任何规则），
  几何与字号改成 `var(--令牌, 原值)`，非预设路径取不到令牌就落回原值。
  用 `examples/declarative-number` 限帧 12 帧的 SHA256 回归守住，
  **命令与哈希一起记录**（上一次只记了哈希没记命令，照它复现不出来）。
- 新增 `tests/test_figure_token_closure.py`（组件不走裸数字、字号兜底与字号阶对齐、
  基元与状态覆盖八个组件）以及 K8 / K9 闸门；`openspec validate --strict` 通过。
- **不引入外部运行时依赖。** 评估过引入外部组件库，结论是不适合：画面必须逐帧确定、
  离线可用、不走 CDN，而这里的组件是**图解**（天平、冰山、差量尺）而不是通用控件，
  外部控件库解决不了「图解怎么长」的问题。真正可复用的部分（物理弹簧曲线、字体资产）
  此前已按同一标准 vendored。
- **明确不在本次范围内**：`figures.js` 里约 696 处数值字面量中的**布局坐标**
  （立柱位置、圆上节点角度、柱高数组）保持为组件自身的图稿常量，不做令牌化——
  一张图的坐标是内容，不是设计令牌；本次收口的是**样式属性**（线宽、圆角、颜色、
  字号、字重、字距、间距）与**状态表达**。这条边界写进 `design.md`，
  避免下一轮把「令牌化」误扩成「把所有数字换成 var()」。
