## Context

三阶段入口共用四问、场景索引、按需的对象与节拍模板、正式评审和问题记录。动机见 [提案](proposal.md)。

## Goals / Non-Goals

让编排、实现、观察在同一片段范围内逐步细化。把各阶段不同的职责留在各自入口，把片段操作和通用返工分别集中在原有指南。沿用现有材料字段、命令、流程门禁及评审职责。

## Decisions

1. `scene-design.md` 的「渐进设计与开发循环」统一维护依据检查、粗排、关键过程、精修与衔接复查。将独立的逐场补查正文纳入该节，保留原锚点以承接组件指南等既有入口。对象、节拍、单对象与光影表继续按机制选用，字幕专项核查接到实际检查时机。简单片段合并，承担表达的材质、运镜或声音可提前试。
2. 研究页保留选案和代表性证据，正式设计页保留全片预演，制作页保留整片验收。修订页用一张重入表处理范围，保留基线、命令及证据有效性。通用回退和同范围复查由 `production-workflow.md` 维护。入口和 README 简短链接，避免重新介绍循环。
3. 用复利年度柱接双塔、贝尔电话验证复杂与简明两种写法。引用已有候选、正式记录和检查窗口，并从可用候选复核关键状态。示例文档记录观察与取舍，历史口径按原版本引用。相同观察问题用于改前改后比较，当前正式验收仍走其专用入口。

## Risks / Trade-offs

- 逐层深化容易演变成固定版次。用当前问题决定最小充分的证据，简单片段允许合并。
- 粗排可能掩盖决定方向的细节。对核心材质、光影、音画或其他关键机制提早取得足量证据。
- 局部通过可能掩盖整片衔接问题。对受影响的两侧取证并在整片候选复核，按绑定保留或重取现有证据。

## Migration Plan

先改唯一操作指南与规格，再收束导航和各阶段，最后在两部现有示例验证文档与媒体证据。按影响运行路由、投影和局部场景检查，验证后提交实施，随后同步主规格并归档。
