## Context

当前 general 校验器固定 1080×1920，准备阶段读取主题来覆盖阅读停留与转场时长；录制 host 与 SDK 依赖 theme，代码内容固定为 864×920，composition 绘制标题及外壳。素材入口已有导入记录、摘要与本地服务边界，代码录制已有资源指纹和无声片段缓存，均可复用。

## Goals / Non-Goals

**Goals:** 以 v8 彻底替换旧通用契约；支持默认横屏及显式竖屏；作品自由设计整张画布；保持音轨、字幕、素材溯源和当前预演自动验收。

**Non-Goals:** 不更换渲染引擎、不支持任意尺寸、不自动迁移旧分镜、不保证自动横竖屏排版、不新增模板/主题库、不改金融住宅画面，不新增人工批准或审美导出门禁。

## Decisions

### 1. 版本与规范化边界

只接受 version/schemaVersion 均为 8。保留现有 article/topic 输入、逐段旁白、关键词、speech、soundtrack 和转场结构。场景仍写 template: code，content 仅接受 title、entry、props；title 可选且仅作元数据，entry 必填，props 默认为空对象。全片 title 保留必填。删除旧展示元素、aspectRatio 和 visual 字段，并按未知字段拒绝。场景及旁白 ID 维持全片唯一。

尺寸在校验后统一规范化：width/height 均省略时填入 1920/1080；同时提供时仅接受整数对 (1920,1080) 或 (1080,1920)，拒绝布尔值、字符串、半指定及其他组合。fps 仍必填且为 30。源文件不被 prepare 自动改写，准备快照包含解析后的实际尺寸。保留单一 width/height，避免方向字段与尺寸冲突。

### 2. 全画布录制与字幕

录制 viewport、root、ffmpeg 片段标准化尺寸和 composition 均使用规范化尺寸。移除通用固定标题/外壳；host 不再根据主题设置前景背景，作品在 ready 前明确绘制不透明背景。底层编码的黑色兜底不是作品主题。共享字体加载保留。

新增通用画幅配置作为字幕几何的唯一真源，Python 和前端消费同一数据。竖屏继承当前字幕几何；横屏按竖屏现有数值乘 1080/1920 缩放字号、行高、底部距离及安全区高度，水平内边距采用画布宽度的同一比例，像素值四舍五入取整。安全区为实际字幕容器矩形，文字测量与换行使用该容器宽度；共享字幕采用白字及不透明深色底板，独立于作品配色。这套规则只约束字幕，不规定正文排版。

SDK 的 CodeSceneProps 删除 theme，增加 width、height、subtitleSafeArea（x、y、width、height）；其值来自同一画幅配置。Chart 不再默认旧内容框尺寸，默认使用当前画布尺寸，允许作品显式传入宽高。共享字幕在录制片段上方绘制，继续检查实际可见性；不尝试从栅格片段推断全部正文包围盒或宣称能够自动发现主体遮挡。

### 3. 代码素材接口

在 m2v/code-scene 导出 useMediaAsset(id)，读取准备阶段校验并注入的只读媒体映射，返回 src、kind、width、height 和视频 durationSeconds（图片为空）。src 是当前本地服务地址，不将绝对文件路径暴露为可任意读取的地址。未知 ID 明确抛错。

准备阶段校验 media-sources 中全部登记素材，包含摘要、真实类型、尺寸与视频时长；依赖映射及原文件摘要进入缓存键。媒体服务只暴露登记的内容寻址文件、源码构建资产及批准字体，不继续允许绕过留证直接获取 assets 下任意媒体。图片视频不受画布比例限制，由代码设置 fit/crop/播放入点，作者负责解释其视觉用途。视频必须等到可播放后 ready，素材原声不进入录制片段或母版；有声音需求使用统一 soundtrack。错误、超时、外网/WebSocket 和未批准依赖沿用失败即不保存有效准备的策略。

### 4. 时间轴与指纹

保留真实 TTS、segmentWindows、12 帧阅读尾段、cut/fade/crossfade、无旁白固定帧数或剩余目标时长分配，以及 18000 帧上限。删除主题覆盖，不改变原有转场语义。缓存输入显式包含规范化尺寸、字幕安全区配置、SDK/host/共享实现、媒体映射及导入记录摘要；画幅改变即使源码未变也重新录制。预演/抽帧/验收从当前准备读取尺寸，正式导出只回放相同片段。

### 5. 创作指导与示例

作品内新增 DESIGN.md 创作约定，记录横竖屏、参考依据、视觉隐喻、字体配色、代表构图、镜头衔接和声音意图。它是助手创作依据，不参与运行时、不作为 CLI 必填字段；直接修改它不会假装画面已经改变，需落实为代码后重新准备。

助手制作前先确定画幅，未指定采用横屏；完成开场/核心/结尾关键画面，再编排运动。实际观看代表动态片段和声音，把时间位置、问题、修改与复查结果记入作品 outputs/visual-notes.md；无法观看时如实报告，不能虚构通过。记录不作导出门禁。镜头复用只限工具级，不新增固定整幕布局。

buffer-smoothing 与 keynote-baseline 为横屏，darts-trial-and-error 为竖屏；原地重编所有场景，保留文章论点、120～180 秒目标、批准组件覆盖与核心演示旁白同步。示例 DESIGN.md 与源代码可入库，视频和作品调试记录不入库。

## Risks / Trade-offs

- 自由代码增加制作、录制和调试成本：先制作 15～20 秒代表片段验证风格，再扩展全片；保留分段缓存和性能报告，不设无实测依据的速度承诺。
- 全画布录制可能增加资源消耗：验证两种画幅各一次缓存未命中/命中，记录尺寸、帧数、耗时与实际缓存状态；命中不得重新录制。
- 自动检查不能判断全部审美和栅格正文溢出：用助手真实观看补充，不恢复模板 DOM 量测的虚假保证。
- 共享令牌仍用于金融住宅：仅删除无引用的通用主题代码，基础字体、安全和专用类型令牌保留并执行回归。
- 破坏性升级会拒绝旧作品：错误明确要求 v8 重新设计，不隐式迁移。提案阶段不更新 README 为已实现；apply 时再同步当前能力及主规格 Purpose。
