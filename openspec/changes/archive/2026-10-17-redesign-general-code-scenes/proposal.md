## Why

当前通用视频以受控模板、预设主题和固定竖屏内容框组织画面，容易形成重复的卡片式构图；即使使用代码场景也无法自由使用画布。本变更拟将视觉决策前移到作品设计阶段，使横屏和竖屏作品都能围绕内容设计镜头，同时保留可靠的音视频制作底座。

## What Changes

- **BREAKING**：通用分镜升级为 v8，只接受本地 React `code` 场景，删除六种受控模板、预设主题与主题节奏覆盖；拒绝旧材料，不提供迁移工具。
- **BREAKING**：删除固定标题和内容框，代码场景控制完整画布；SDK 删除 theme，提供画布尺寸、字幕安全区和已导入媒体解析接口。
- 支持 1920×1080 横屏及 1080×1920 竖屏，默认横屏；两种尺寸贯穿准备、录制、字幕、缓存、预演和导出。
- 制作 Skill 要求先确定画幅及作品视觉设计，再制作关键画面、编排运动并实际观看修改；不新增 CLI 审美门禁或用户确认环节。
- 原地重做三个固定示例，更新契约、校验器、初始化材料及权威文档；金融、住宅类型不改变。

## Capabilities

### New Capabilities

无，复用现有能力目录。

### Modified Capabilities

- `general-video-composition`：v8 纯代码场景与默认横屏。
- `article-explainer`：横竖屏分镜、字幕约束、移除模板及主题、固定示例要求。
- `react-code-scenes`：全画布录制、SDK 尺寸与媒体接口、缓存绑定。
- `article-media-assets`：代码场景素材引用与不限制素材比例。
- `video-production-workflow`：助手视觉设计及观看迭代，不新增导出门禁。
- `keynote-design-system`：区分专用类型共享令牌与通用作品自由设计，移除主题真源要求。
- `remotion-renderer`：共享 composition 仅回放 v8 全画布录制片段。

## Impact

影响 general 的 Python 校验/准备/录制、前端 composition 与 SDK、类型目录初始化材料、测试和三个固定示例。清理已无调用的主题实现；共享字幕、字体、音轨及金融住宅依赖须先检查再处理，不因删除通用主题破坏其他类型。

作品从 v7 升级必须重新设计；画幅或实现变化使旧准备与预演失效。实时录制与现有批准依赖继续使用，不引入新渲染引擎、自动配乐服务或任意尺寸支持。提案阶段只提交本变更材料，实施与归档在后续 apply 完成。
