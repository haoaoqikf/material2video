## Context

动机见 [proposal.md](proposal.md)。现有 v3 分镜、静态联系表、布局多样性检查和定制动画评审已经提供基础能力；缺口是制作顺序、评审材料统一输出、版本有效性及返工管理。规格分别见 [制作流程](specs/video-production-workflow/spec.md)、[导演流程](specs/visual-direction-pipeline/spec.md)和[审美评审](specs/storyboard-aesthetic-review/spec.md)。

## Goals / Non-Goals

**Goals:** 以同源样片提前验证表达；让阶段状态由有效证据派生；让正式渲染只能使用已评审版本。

**Non-Goals:** 不增加音乐、音效、模型调用、自动审美评分、分镜迁移或新的视觉原语；不把制作记录交给 composition 读取。

## Decisions

### 1. 制作记录与渲染分镜分离

新增 `production.py` CLI，提供 `status`、`template`、`keyframes`、`samples`、`rehearsal` 子命令，共用 `--storyboard`、`--content-root`，有声输出使用 `--media`。记录写入作品根的 `production.json`，版本为 1；示例作品的运行记录放在对应的忽略目录 `videos/examples/<slug>/`，不污染已入库示例源目录。审美解释和既有评分继续保留在 `outputs/inspect/review.md`。JSON 保存阶段声明、关键幕角色映射、逐幕起始/变化/结果、快慢安排、材料路径及指纹、评审结论与返工项，作为正式闸门的结构化证据。生成材料只更新 `materials` 的出处，不替评审者写入通过结论。两者的重复状态不各自维护：新流程状态以 JSON 为准，既有评分从现有评审解析器取得。

关键幕草稿保持有效 v3：先完成内容幕序与口播，未试制场景可以采用有效临时画面并明确处于草稿阶段；只评审选定关键幕，不宣称其余幕已完成。没有记录时查询返回初始化模板和下一步说明，不修改分镜。模板由文档提供，评审者填写；未知字段、无效场景或材料缺失报告字段路径。采用独立记录而非升级分镜 schema，保持离线渲染契约稳定。

### 2. 样片沿用完整 composition

`samples` 默认读取三个关键幕角色并去重，也支持显式场景 ID；`rehearsal` 输出全片。扩展现有 Remotion 编排支持原始全局帧范围与输出 scale，禁止裁剪分镜再从零计时。关键幕范围包含前一幕尾部与后一幕头部各 0.5 秒，边界在全片内截断；连续范围合并，清单保留场景与全局帧区间映射。

评审输出默认 540×960、原 fps、CRF 28，保留音频和字幕；正式参数保持既有默认值。画布仍按 1080×1920 排版，以渲染 scale 缩小，禁止更改逻辑画布。输出写入 `outputs/previews/production/`，清单明确用途和指纹；不覆盖成片。相比临时拼接独立幕，这样能保留转场、跨幕对象与实际配音同步。

### 3. 两类评审与定向返工

`keyframes` 复用现有 review 生成静态材料；关键幕范围与全片范围分别记录结论。新维度使用 `pass/fail/pending` 加依据，不新增形式化总分；既有 V6、A6 和定制动态评分门槛继续检查。脚本只验证完整性和版本，不判断画面高级程度。

返工项包含 id、sceneIds（全片问题允许空列表并注明范围）、dimension、problem、direction、returnStage、severity、status 与复查依据及指纹。必改状态为 open 或 resolved，resolved 必须在当前有效材料上有通过复查；可选项不阻断。阶段状态为 pending、blocked、passed、stale，返工无问题时为 not-required；正式完成依据成功渲染的溯源，不凭手工声明。

### 4. 指纹依赖与正式闸门

复用现有分镜与资产溯源逻辑，媒体指纹覆盖清单及引用音频、字幕内容，不只比较路径或时间戳。首版采用保守失效：分镜或共享资产变化使全部静态/动态结论及复查失效；媒体变化使动态结论失效，静态材料若基于媒体时间轴取帧也失效。材料重新生成不自动恢复结论。

正式 render 入口统一检查新记录与现有闸门；通过共享内部输出用途区分正式、关键幕样片与评审版，不提供通用跳过正式评审的开关。样片仍过结构、安全、媒体和契约验证。状态查询只读，并输出具体下一步命令与非零错误退出码，供 AI 流程定位失败。相比只在新入口拦截，该设计避免旧 render 命令绕过制作要求。

## Risks / Trade-offs

- 保守失效可能重复评审 → 首版优先保证可信度，状态明确指出变化来源，不做复杂逐节点依赖。
- 低分辨率可能掩盖小字问题 → 静态可读性评审仍使用原尺寸材料；低成本视频只用于动态预演。
- 人工可以填写缺乏质量的依据 → 文档要求场景与可观察问题，抽象示例展示失败及复查；不声称结构检查能证明审美。
- 关键幕有上下文依赖 → 草稿先固定内容幕序，并保留邻幕过渡范围；全片预演再次验证。

## Migration Plan

实施时同步 CLI、正式闸门、Skill、评审参考和 README。已有作品缺少记录时标为待初始化，沿用原分镜与媒体，重新建立材料及评审；不导入历史通过评分来自动完成新维度。示例模板可入库，实际文章、制作记录和生成媒体维持忽略。回退通过回退功能提交恢复旧入口，不删除作品内容；本 propose 不更改当前制作行为。
