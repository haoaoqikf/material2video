## Context

动机见 proposal.md。现有阶段由指导路由和 production/workflow.py 的门映射共同展示，审核仍由 G0–G6 与审核计划驱动。用户已确认本方案并授权实施。

## Goals / Non-Goals

消除粗片到精制的阶段交接；保留核心、全片粗片与最终评审的各自职责，不把截图替代动态证据。不改合同和账本版本。

## Decisions

- 单一 stage-iterate.md 承接两阶段，旧文档仅保留转介，所有活动入口更新；不保留两套执行规则。
- 阶段 ID 为 plan/iterate/final；G4/G5 共用制作与迭代阶段，reviewRound 的 core/rough/final 是审核轮，不与阶段 ID 混同。
- 移除粗片通过后转精制的分支及不再使用的参数；只改变展示和导航，不放宽账本完成计算。
- 在 production-workflow.md 集中维护按问题选择复查工具的表格，各入口引用；一份问题清单、有效证据复用，依赖变化按既有绑定失效。
- 保留最难关系、开场先行、全片检查、目标对照、修订损益与连续失败回退，禁止通过合并丢失规则。

## Risks / Trade-offs

阶段合并可能被误读为审核合并 → 明确保留 G4/G5/G6 职责并验证状态与门映射。
旧链接可能失效 → 保留短转介，更新活动链接和标题锚点；历史迁移摘要不改写。

## Migration Plan

更新当前指导、路由与展示，无需迁移作品；测试验证后提交，再同步主规格并归档。历史记录继续保留原文。
