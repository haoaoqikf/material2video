## Context

当前新作品由 `project.json` 声明类型，但 `m2v init` 接受任意目录；文章辅助流程则单独按 `videos/<slug>/` 推导归属。生产记录、准备记录和嵌入依赖都保存相对路径，因此改变作品根时需要审慎处理路径引用。详见提案及规格。

## Goals / Non-Goals

**Goals:** 新旧统一契约作品可通过显式命令迁移到类型分层布局，制作入口按 manifest 类型验证路径，外部内容根和示例行为一致。

**Non-Goals:** 不自动批量迁移内容根；不改变旧材料格式迁移；不重写相对引用文件内容或重置准备/评审指纹。

## Decisions

- 规范作品路径为 `videos/<manifest.type>/<slug>/`。统一 CLI 装载作品后，以 manifest 类型和相对路径验证类型目录；文章工具由分镜所在作品根的类型层推导工作区。仓库示例源仍在 `examples/<slug>/`，但其制作输出仍使用 `videos/examples/<slug>/outputs/`。
- 新增 `m2v relocate --project <旧作品目录> [--content-root <根>]` 专用于路径迁移，和 `m2v migrate --from` 的材料契约迁移分开。来源必须是规范工作区下直接位于 `videos/` 的旧 `<slug>` 目录，且含有效、已登记类型的 `project.json`。
- 迁移先完整复制备份到同级唯一时间戳目录，再逐文件移动到类型目录。已有目标文件永不覆盖；同路径文件留在来源并作为可重试冲突报告。移动使用同一文件系统内的 `replace`，目标父目录逐层创建；符号链接按链接本身移动，不跟随目录链接。源目录仅在空时删除。
- 目标可能部分存在，逐文件原子移动实现幂等重试；备份名冲突则拒绝启动。迁移不会修改 JSON 中已存在的相对路径，因其解释基准是作品根且目录内部结构保持不变。
- 初始化将相对 `--project <slug>` 解析为 `<content-root>/videos/<type>/<slug>`；显式类型路径只接受正确的 `<type>/<slug>` 形式。绝对路径和外部工作目录不自动改写。

## Risks / Trade-offs

- 类型层违反 manifest 类型时作品会无法通过统一入口 → 在路径入口给出含预期目录的明确错误。
- 迁移中断会留下部分文件在旧、新目录 → 逐文件移动、完整备份及可重跑冲突处理支持恢复。
- 通用作品中跨目录嵌入路径指向关系可能因移动改变 → 本次路径迁移限定单作品文件树，不搬迁其上层容器；嵌入子项目若在作品根内部，会随目录一起移动。

## Migration Plan

1. 部署新入口和文档；不自动触碰现有内容。
2. 对每个 `videos/<slug>/` 运行 `m2v relocate --project videos/<slug>`。命令建立同级备份后迁移到 `videos/<type>/<slug>/`。
3. 检查冲突报告；处理目标与源版本后重跑命令，直到来源清空。
4. 回滚时从备份恢复旧目录；迁移不会删除备份。
