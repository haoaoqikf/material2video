## Context

动机与范围见 [proposal.md](proposal.md)，目标行为见 [设计语言增量规格](specs/keynote-design-system/spec.md)。本变更已实施并完成验证；评估数据见 [layout-evaluation.md](layout-evaluation.md) 与 [paths-evaluation.md](paths-evaluation.md)。

现有 `SceneTree.tsx` 按元素真实宽度进行字号取档，`fonts.ts` 等待本地字体就绪；契约页已有字号量测测试。`geometry.ts` 按场景树推导归一化几何，不能直接等同于文字适配后的实际 DOM 边界。代码场景通过 `@a2v/scene` 接入，已有 Dagre 布局适配器及 `compilePath` 折线路径工具。

`docs/PROJECT_PLAN.md` 的双向选择节点、冰山标注、天平载物、阶梯柱顶注是历史缺口线索。实施前须核实其当前 v4 对应对象是否仍存在，不能以历史文档直接判定当前代码存在四个缺陷。

## Goals / Non-Goals

**Goals：**

- 统一文字度量、容器适配、包含关系检查与镜头几何的衔接，明确无法容纳时的错误路径。
- 通过可复现对比决定 `layout-utils` 是否值得接入，保留依赖未获采用时的实现路线。
- 按布局完成、作品需求筛选、路径评估的顺序推进，给出可采用或暂缓的结论。

**Non-Goals：**

- 不安装评估未通过的候选依赖，不扩大制作契约；主规格只在按工作流归档时同步本变更已实现的行为。
- 不重写设计系统、不全量替换现有测量逻辑，不增加 tree 原语、分镜字段或第二套动画时间轴。
- 不将三维、物理模拟、外部动画播放器、云渲染或并发调优合并到本变更。
- 不在本变更内上线新路径能力，不承诺跨机器逐像素一致或预设性能收益。

## Decisions

### 1. 先建立对象清单，再决定迁移范围

盘点 tree 文本、surface 容器及三个固定示例中的代码场景，记录对象 ID、文字角色、字号上下限、行数、内边距、包含标记、当前测量入口和镜头引用。对历史四处缺口逐项标为当前存在、已修复或历史对象已移除；只修复当前可复现的问题。

不直接按历史名称扩展组件库：这会把已删除实现的遗留记录误当成当前需求。财务专题采用单独版式，本轮只做回归检查，不自动接入通用文字适配。

### 2. 用项目适配层封装文字度量，保持设计令牌为真源

评估后保留 DOM 度量，不引入候选库。预设启用且显式声明 `role` 的 tree 文本在本地字体就绪后，沿字号阶向下尝试；每档检查真实宽度与最多四行。自动换行保留完整内容，最低档仍超限或容器边界/safe 越界时标记 `data-a2v-fit-fits=false`，由 K7 报告节点 ID 并阻断正式渲染。未声明适配的文字保持原行为。surface 使用现有固定布局和内边距，不擅自改变排版尺寸；不能容纳时要求调整文案或构图。

现有 `fitRoleDown` 在全部档位均不满足时仍返回最低档，这一分支须在盘点中核实完整错误路径，不把“已实测”视为“已容纳”。不新增默默裁切或省略号回退，也不通过增加叙事场景违反单场景原则。

预检在全片首尾帧、每个阶段边界与每条状态轨道的开始/结束边界挂载同尺寸树，按节点 ID 合并可达布局盒，避免文案切换改变相机几何。该结果在一次布局预检后缓存于 composition 生命周期，不依赖求帧顺序；新分镜、字体或画布重新挂载会重新测量，因此不设跨挂载度量缓存。

### 3. `layout-utils` 采用与否由同输入对比决定

官方工具提供 `measureText`、`fillTextBox`、`fitText` 与 `fitTextOnNLines`，分别用于文字尺寸、换行/溢出及字号适配；它们作为候选底层工具，不能替代项目中文排版和字号阶策略。参考 [官方 API](https://www.remotion.dev/docs/layout-utils) 与 [使用建议](https://www.remotion.dev/docs/layout-utils/best-practices)。

未来评估在隔离试验环境进行，不先修改正式依赖或锁文件。比较现有 DOM 度量和候选方案，使用同一组中文长句、标点/引号、中英混排、数字单位、强调片段、多行和动态文案。记录冷启动、字体就绪、首次布局及重复求帧的耗时与内存；同机同工具链重复三轮，采用中位数，并记录环境。

采用门槛：

- 上述输入的字号、字符与强调片段、中文规则、容器包含及安全区检查全部通过。
- 预览和 Remotion 导出的关键帧布局一致，随机寻帧和重复求帧结果稳定。
- 同样本的端到端耗时与峰值内存相对基线增幅均不超过 10%；该数值为计划验收阈值，尚无实测结论。
- 至少能消除一处真实重复度量逻辑或解决一个现有适配缺口，并记录收益及新增维护成本。

通过后才将依赖接入项目适配层、更新锁文件及依赖策略，版本与当时仓库锁定的 Remotion 版本核对；不通过则完善现有 DOM 方案并记录不采用原因，两种路线都须满足增量规格。未完成测量不能被写为“通过”。

### 4. 容器、探针与镜头使用一致的几何来源

优先在既有构建/字体就绪阶段形成稳定布局，再由画面与量测共同消费。盘点 `geometry.ts` 与实际容器边界的差异，对受影响对象提供一致坐标，明确局部坐标到画布坐标的转换；禁止摄像机用旧尺寸而文字用新尺寸。代码场景通过受控 API 接入，不导入仓库私有模块。

**实现时序（已由用户选择）：** Remotion 入口已有 `delayRender` 等待字体，但 `compileCameraV4` 在 DOM 挂载前运行，不能读取浏览器几何。v4 tree composition 增加一次确定性的浏览器布局预检：在真实画布尺寸、正式字体、主题及样式下挂载测量树，覆盖全片文案状态变化边界；测量完成后把每个节点的画布坐标盒传入 `compileCameraV4`，完成镜头轨迹编译，再释放布局预检的 Remotion delay handle。正式画面与预检消费相同布局结果。预检不依赖当前求帧顺序或上一帧状态，失败时 cancelRender 并指出对象 id。code renderer 继续使用其公开 `probe` 几何，不访问私有 DOM 或内部模块。

测量树需等字体 Promise 与 React 字号适配提交完成后读取。容器矩形统一转换为相对 1080×1920 画布的归一化几何；镜头只消费该 map，不在编译器内再计算 tree 几何。服务端静态输出与单元测试保留结构性几何回退；Remotion Chromium 客户端正式渲染必须完成预检，不能静默回退。

先确定真实包含关系，再补 `data-a2v-inside` 或现有探针所需标记；不把所有装饰节点都声明为容器内部元素。验证深浅主题、1080×1920 输出与 360×640 缩放，选择文字最长、文案切换及镜头移动的关键帧。验收保留安全区、对比度和既有字体/字号规则。

### 5. `paths` 按作品需求评估，不预先上线

此处 `paths` 指 `@remotion/paths`。其官方 API 涵盖路径长度、沿路径取点/切线、描边展开和插值，参考 [官方文档](https://www.remotion.dev/docs/paths)。

布局验收后，检查 `buffer-smoothing`、`darts-trial-and-error`、`keynote-baseline` 的动作设计或实际作品需求。只有需要连续曲线且现有折线工具造成可见偏差、或复杂 SVG 描边/变形显著增加手写成本时，才进入隔离对比试验。无真实需求时直接记录暂缓，不为展示工具改写示例叙事。

| 需求 | 现有路线 | 候选评估重点 |
| --- | --- | --- |
| 直线或折线对象传输 | 保留 `compilePath` | 不构成引入依据 |
| 沿曲线连续运动 | 比较预采样折线 | 位置误差、切线方向、运动速度与路径长度 |
| SVG 描边逐步展开 | 比较现有 SVG 属性计算 | 端点正确、进度与全局 beat 一致 |
| 两轮廓之间的形变 | 仅明确叙事需求时比较 | 路径兼容性、自交和非法输入处理 |

试验要求：路径预编译/缓存不依赖上一帧；进度仅来自全局帧或 beat；验证 0、1、边界及非顺序求帧；覆盖空路径、零长度与非法输入。对同样本记录几何误差、耗时、内存和正式依赖包体变化预估，使用布局评估相同的三轮中位数与 10% 性能退化阈值。可接受几何误差在选定具体作品后以画布像素和手机缩放可读性记录，不以未经量测的“更平滑”作为采用证据。

评估结论限定为采用建议、暂缓或不采用，包含需求来源、对比材料和理由。采用建议仍须另建 OpenSpec 实施变更，确定受控 API、依赖白名单、参考文档、测试及现有示例更新，再安装正式依赖；本变更任务不包含路径库上线。

## Risks / Trade-offs

- 历史缺口与现有代码不一致 → 先复现并标明对象，清理过期描述，不按旧清单机械实施。
- 测量函数与实际中文 DOM 布局不同 → 对比真实字体与浏览器结果，中文规则由项目适配层负责。
- 内容切换引起镜头漂移或文案抖动 → 预检合并所有可达状态的实际边界，预览契约等待预检完成，并验证非顺序寻帧。
- 全片最大容器造成过大留白 → 逐对象按安全区评估，必要时重新构图，不自动突破字号和容量上限。
- 字体或状态边界漏采导致测量失效 → 字体就绪后统一预检阶段与状态轨道边界；同机三轮性能对比未见超过 10% 的退化。
- 路径工具收益不足或鼓励装饰动画 → 由实际推理动作触发评估，允许暂缓结论作为完整交付。

## Migration Plan

1. 盘点并保存当前布局事实、关键帧和同机工具链基线；生成媒体保持在忽略的输出目录。
2. 隔离评估 `layout-utils`，记录不采用结论，保留 DOM 测量与项目字号策略。
3. 同步 tree 文字量测、包含探针与镜头几何；code scene 保留公开 probe 作者几何，相关契约与 K7 校验器同步更新。
4. 布局通过后评估路径工具，将结论保存在本变更的评估记录；有需求再立独立接入变更。
5. 实施交付前执行相关测试、严格示例校验、浏览器量测及必要的对应帧导出核对；更新 README 当前事实和项目规划。
6. 若接入后回归失败，回退适配层、依赖及锁文件到对应基线；不接受在运行中偷偷切换测量方案。按既有资产指纹机制重新准备评审材料，正式渲染门禁不跳过。
