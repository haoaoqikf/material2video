## Why

用户明确要求某个作品借鉴一条抖音参考视频的**风格**时，现有流程没有承接这一步：参考素材的规则只覆盖获取、校验与音轨复用；创作文档只要求「先自主搜索参考」，没有规定如何把参考的视觉语言转成可执行、可验收的设计约束。

实际后果已经出现：`videos/general/career-security` 的第一次成片沿用了参考的深蓝配色与细线人物，但主体尺度、空场率、光源结构、运动方式和文字层级都与参考相反，被用户判定「借鉴效果很差」。当时的参考分析只产出音频电平与段落时间，视觉层没有留下任何可核对的数值；验收条目也全是理解度与可读性，没有一条与参考对照。

这不是要新增审美评分或用户确认，而是补一条**可查证的创作门禁**：借了哪一层、参考值是多少、本片实际值是多少、差值如何解释，必须在进入精制前留下记录。

## What Changes

- 新增 `.agents/skills/material2video/references/reference-style.md`：定义借鉴分层（L1 视觉语言 / L2 节奏结构 / L3 情绪调性）、八项可量测指标、横屏与竖屏之间的转译规则、风格契约模板、三张风格基准与 2 秒动效样片门禁、同族冷审方法。
- 修改 `creative-production.md`：创作目标阶段要求先写 `outputs/style-reference.md`；美术定稿阶段在四张叙事基准之外增加三张风格基准与 2 秒样片；阶段表补充放行条件。
- 修改 `SKILL.md`：通用作品编排原则增加参考风格借鉴的强制入口与「只写气质一致不算完成」。
- 修改 `article-media-and-sound.md`：明确音轨复用授权只覆盖音频，不等于画面风格可以借鉴。
- 更新 README 文档导航。
- 不新增 CLI 命令、运行时字段或自动审美阈值；风格契约是作品证据，不参与渲染，不改变任何分镜结构或校验器。

## Capabilities

### Added Capabilities

- `reference-style-transfer`：用户明确要求借鉴参考作品风格时，把借鉴范围、八项量化指标、画幅转译、风格基准与同族复核固化为可查证的流程。

## Impact

- 只改 `.agents/skills/material2video/` 下的创作参考文档与 README；不改 `src/`、`web/`、`examples/` 与任何渲染契约。
- 不触碰 `videos/`、`work/`、`refs/` 等内容目录；不影响正在进行的作品制作。
- 参考素材的默认禁令不变：参考画面仍不得进入成片，`refs/` 仍不被渲染链路读取。
- 不引入依赖，不需要新增测试用例；验证方式为文档链接、术语一致性与现有检查脚本。
