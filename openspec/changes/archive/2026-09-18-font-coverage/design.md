# 设计：怎么判断「缺字」

## 决策 1：读字体自己的 cmap，不相面字体

判据只能是字体文件自己的字符映射表。备选做法（按字体名猜覆盖面、按 Unicode
区段猜「汉字都在」）都会给出**看起来合理但可能错**的结论，而这条闸门存在的
唯一理由就是不能猜。

零依赖：`cmap` 是 TTF/OTF 里结构最简单的一张表，自己读即可，不为此引入
fonttools（多一个依赖也是多一个会坏的地方）。支持子表格式 4（BMP，
platform 3/encoding 1）与格式 12（含 BMP 之外）。同一字符在多个子表里出现时
取「有字形」的那个——字体把同一个字分别登记在不同子表是正常做法。

## 决策 2：扫描范围按「会被渲染的文本」定

分镜里带 `narration` 的字段**当前不渲染**（见制作流程文档），因此不进扫描：
把不渲染的文本算进来会让闸门报出人看不见的缺字，那是噪音。
反过来，预设层（keynote.css 的 `content:` 固定字串）会被渲染，所以也要算——
`content: "·"` 这类字符缺了就真的会回退。

## 决策 3：缺字是错误，不是提醒

它和 K7 溢出同性质：画面坏了，只是坏得没有报错而已。所以进错误数与退出码。

## 已知边界

- 只判「字体里有没有字形」，不判该字形的**字宽/字重**是否合适；
- 不判断浏览器实际选了哪个字体（那要跑浏览器），只判断「不该回退的地方不会回退」。
