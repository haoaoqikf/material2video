## Context

动机见 proposal.md。现有三阶段入口、单份 DESIGN.md 与风险派生审核已能容纳细节设计；内部已具备纯时间关键帧、路径形变、滚动和重力粒子。问题在于逐场编排与实际观察缺少明确落点，无需新增渲染能力。

## Goals / Non-Goals

**Goals:** 在每场目标与动态实现之间加入可执行的细节记录，并用既有动态证据观察实际效果；维护单一参数源与方法归属。

**Non-Goals:** 不改分镜版本、校验 schema、运行时、审核轮次或风格默认；不把每场都变成复杂导演卡；本变更交付共享流程，当前作品按新流程单独继续制作。

## Decisions

1. 运动方法放入 motion-design/ADAPTATION.md，保留上游原文。制作参考新页只负责记录、顺序与证据，并链接方法，避免另一套运动理论。
2. 逐场表新增细节引用，较长记录放在同一 DESIGN.md。选择此方式而非新建 DETAILS.md 或平行帧表，防止设计与实现漂移。
3. 沿用 G4/G5/G6 与独立评审职责。复核完整动态窗口，不新增按关键词或效果数自动判断的校验器；已有路由、链接、预算检查验证文档接线。
4. 数据准确性约束稳定比较窗口；过渡可用受控回弹。球绑定实际柱顶，惯性离地作为显式状态。相比禁止柱高过冲，此方式同时满足用户弹性要求与准确比较。
5. 示例只补充 compound-connect 已有行为及源码引用，不修改组件或生成媒体，不把补写文档当成重新通过评审。

## Risks / Trade-offs

- [表格变成填空负担] → 普通场景简写，允许不适用项合并说明，只有复杂依赖才展开。
- [细节争夺焦点] → 每项写用途与稳定阅读窗口，复核原生及手机尺寸的实际过程。
- [方法重复维护] → 流程页只管操作与证据，方法只在运动适配层。
- [数字与图形过冲造成误读] → 明确过渡和稳定窗口，共同数据源，终态准确。

## Migration Plan

同步入口、三阶段指南、模板、阅读路由、README 与规范示例；运行相关导航/预算/文档同步检查及严格规格校验后提交，随后同步主规格并自动归档。已有成片不追溯重渲，后续制作与明确启动的修订使用新要求。
