## Context

动机见 [proposal.md](proposal.md)。既有规格要求自行搜索参考，但方案指南没有前置操作入口，灵感文档又强调“采用自选”，两者容易被误读为研究也可选。该变更跨越制作入口、修订路径和规格，适合明确权威归属后统一修改。

## Goals / Non-Goals

**Goals:** 让未来制作助手能在设计之前定位并执行研究要求，识别 HTML 草稿、参考未采用、新问题补查和不可访问等边界。

**Non-Goals:** 不新增命令、报告格式、研究评分、搜索配额、审核人数或素材库，不以网络搜索替代样片和独立评审，不追溯补造旧作品研究。

## Decisions

1. **研究操作规则归方案指南。** 在 `stage-plan.md` 添加“设计前搜索研究”，灵感文档只声明义务并链接；SKILL、阅读路由、修订入口和参考分析导向同一位置。相比在各页复制完整检查表，单一来源能避免规则漂移。
2. **区分内容题面与视听方案。** 可以先明确主题、受众、硬约束和待解决问题；在搜索研究完成后才形成视听方案与展示型 HTML 草稿，避免“检索素材需先有场景任务”造成先后循环。
3. **研究不等于采用。** 按当前表达问题搜索并实际查看，留下来源、访问日期、观察维度和设计启发；不要求解释每一种未采用风格，不将搜索结果或摘要当查看证据。
4. **复用以覆盖为依据。** 同一任务中已有真实记录且覆盖当前问题的研究可复用；方向变化、新对象或用户反馈暴露新问题须针对缺口补查。纯实现修复不重复风格调研，临时原型不能绕开首次研究。
5. **无法研究时保留未满足状态。** 换词或换来源后仍无法实际查看时，如实记录，继续无关整理，不自行省略前置要求。研究依据足够即可停止，不设置次数或案例数量。
6. **人工执行要求与技术门分开。** 复用现有 DESIGN.md 和参考分析的证据边界，CLI 不新增研究判定，不声称导航检查能证明实际搜索或审美质量。

## Risks / Trade-offs

- [凑链接代替研究] → 要求实际查看、具体观察和当前问题的关联，不设搜索次数与案例配额。
- [小修被无限重开选案] → 保留有覆盖依据的复用与纯实现修复边界，出现新设计问题时才补查对应范围。
- [入口文字重复或超预算] → 详细规则只在方案指南，其他入口链接，沿用已有导航和字符预算校验。
- [只看静图却推断动态或声音] → 沿用参考分析的证据类型边界，明确未观察的维度。

## Migration Plan

修改现有指导并同步路由与入口；执行针对性文档检查、技能格式校验和独立场景演练，验证通过后提交。再同步三项主规格、自动归档并提交归档结果。无作品迁移或缓存失效；回退时可整体撤销本次规则修改，不修改历史研究记录。
