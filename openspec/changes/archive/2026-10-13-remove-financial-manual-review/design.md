## Context

见 `proposal.md` 的 Why。统一 CLI 当前先执行通用 `review.json` 门禁，金融类型再执行 `legibility-review.json` 门禁；金融完整预演本身已绑定价格、计划、构建资产和金融渲染代码，并在全帧渲染时运行画面探针和媒体验收。

## Goals / Non-Goals

**Goals:**

- 让金融作品以绑定当前输入的完整预演和确定性自动验收作为正式导出前置条件。
- 保持文章、通用类型的人工评审，并保持金融渲染器对过期或无效预演的拒绝能力。
- 将金融 CLI 状态清楚标为人工评审不适用，不制造主观评审证据。

**Non-Goals:**

- 不移除金融行情、布局、逐帧裁剪、MP4 解码和无音轨检查。
- 不改变 request、prices、animation-plan schema 或画面表现。
- 不对文章或通用视频评审做调整。

## Decisions

- 在 `VideoType` 添加 `manual_review_required: bool = True`，追加在现有可选字段之后，保持现有构造调用兼容；金融类型设为 `False`，其他类型使用默认值。
- 统一 CLI 仅对要求人工评审的类型调用通用 `_require_review`。金融的 `review-template` 不落盘空白模板；`review` 调用类型门禁检查当前完整预演后报告自动验收结果，`status` 报告 `review.status = not-required`。
- 保留金融 `review_gate` 作为自动类型门禁，并让金融渲染函数自身也检查 `load_preview_record`，保证统一入口和直接渲染都要求完整、当前且摘要一致的预演。此检查不仅读预演路径，还核对材料/构建代码摘要、帧数和文件摘要。
- 将金融输入摘要从“可读性评审摘要”语义重命名为渲染输入摘要，继续绑定预演材料与资产；删除金融专属人工评审模板和证据校验实现，不把自动探针描述为审美或可读性人工结论。
- 继续使用现有全帧画面探针及 `output_validation` / 无音轨验收；失败仍在临时输出发布之前中止。
- 正式金融成片清理时保留当前已绑定的完整预演和记录，以便渲染后状态仍可报告预演当前；其他类型保持原有预演清理方式。

## Risks / Trade-offs

- 自动检查无法判断主观节奏或审美 → 金融类型不再把此类判断伪装成机器结论；保留可选的人工外部查看，但不作为 CLI 门禁。
- 旧金融作品可能留有历史 `review.json` 或 `legibility-review.json` → 新流程忽略这些文件；其存在不会改变自动验收，也不会被改写成通过记录。
- 完整预演与正式渲染各需一次全帧渲染 → 这是绑定与验收自动化的成本，沿用 Remotion 构建缓存并保持串行会话。

## Migration Plan

不迁移作品材料 schema。升级后金融作品重新 prepare 并生成完整预演；仅当前材料/资产摘要、准备记录和预演帧数一致时可导出。苹果作品在实现后重查行情，若数据更新则重建计划、准备和预演，再渲染正式成片。共享代码和文档验证、提交后同步主规格并归档本变更；若自动验收或渲染失败，修复后重跑验证，旧成片由临时文件发布机制保留。
