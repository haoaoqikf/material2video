## Context

现有流程已有 schema v2、场景树、语义 beats、设计令牌和渲染后体检，但导演策略主要停留在逐幕声明，跨幕连续性、镜头语言和渲染前审美判断没有统一数据契约。设计必须保持帧驱动、离线可渲染、旧分镜兼容和“文章内容不入库”的项目约束。

## Goals / Non-Goals

**Goals:**

- 用可验证的导演简报和风格包统一一支视频的气质。
- 让 beat 能表达状态 / 关系变化，并支持跨幕连续对象。
- 在正式渲染前提供复用同一 composition 的关键帧联系表和审美评审。
- 让所有新增能力在缺省时不改变旧分镜行为。

**Non-Goals:**

- 本期不接入视觉模型自动裁决，不把审美评分伪装成确定性机检。
- 本期不实现平台发布、自动选题、自动生成音乐素材或完整音频混音系统。
- 不为单篇作品增加专属渲染模块；缺口优先沉淀为通用契约和原语能力。

## Decisions

1. **导演字段放在 storyboard 根级与 scene 级。** 根级保存创作简报、情绪曲线、母题和风格包；scene 级保存镜头与转场声明。这样仍以单一 storyboard 为真源，也不增加第二套运行时配置。
2. **跨幕连续性采用稳定节点身份 + 显式 transition，而不是自动图像匹配。** 自动匹配容易把相似图形错误连接；未声明的节点保持现有按幕渲染，声明但无法实现时前置失败。
3. **风格包复用现有设计令牌体系。** 先扩展 registry / style token / motion recipe 的受控枚举，不允许 storyboard 携带 CSS、坐标脚本或任意 easing。
4. **审美预检复用契约页。** 通过同一 composition 在关键帧采样，生成 PNG 联系表和 Markdown / JSON 报告，避免预览与成片使用两套画面；人工结论写入 inspect 目录，不写回文章内容。
5. **分阶段兼容迁移。** 新字段全部可选；只有声明 `directingVersion` 或作品级风格包时启用新增硬校验。迁移工具不猜测旧作品的母题、镜头或跨幕关系。

## Risks / Trade-offs

- [风险] 跨幕变形扩大运行时复杂度 → 第一版只支持注册表声明的有限变换和稳定 id，其他情况明确失败。
- [风险] 审美预检增加制作时间 → 只采样关键帧和低分辨率联系表，不重复完整渲染。
- [风险] 新风格包造成作品同质化 → 风格包只规定语言和节奏，不规定每幕布局；严格保留视觉多样性检查。
- [风险] 人工评审标准不一致 → 固定评审维度、评分格式和发布门槛，并把依据保存为可追溯文件。

## Migration Plan

1. 先实现 schema、校验和报告字段，默认关闭新增硬门槛。
2. 为一个现有示例补齐导演简报、镜头、转场和审美预检产物，验证兼容路径。
3. 增加有限跨幕变形和风格包，再将新示例纳入严格验收。
4. 更新 skill、README、主规格和测试；旧分镜继续使用兼容模式，新增作品默认采用新版闭环。
5. 回滚时删除新版字段或关闭 `directingVersion` 即可回到旧渲染路径；不修改旧媒体产物。
