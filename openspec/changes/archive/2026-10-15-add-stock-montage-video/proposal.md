## Why

现有四类视频的材料都由人手工准备：金融要抄行情、文章要写分镜、房价要录数据、通用要逐个场景编排。缺少「只给主题，其余交给工具」的成片路径——也就是按关键词到在线图库自动找素材、再自动剪成一条竖屏短片。这类需求与现有类型在**材料来源**上根本不同（材料不是人手填写的数据，而是检索到的第三方媒体），因此按项目约定新增一个独立视频类型，而不是把它塞进 `general`。

## What Changes

- 新增视频类型 `stock-montage`（在线素材剪辑）：作品只声明一份 `brief.json`（主题、逐幕关键词、可选口播、时长与画面要求），其余材料由工具检索得到。
- 新增**检索与下载**步骤 `m2v stock search --project <目录>`：按逐幕关键词调用在线图库（首版 Pexels）检索候选，确定性排序并去重，把入选素材下载进作品 `assets/stock/`，同时把来源页、作者、许可、分辨率、时长与内容摘要写入 `outputs/footage-search.json`。
- 素材来源与许可成为**可校验的材料事实**：`validate` 要求检索记录与当前 `brief.json` 指纹一致、每个入选文件存在且摘要匹配、来源与许可字段非空、逐幕都有可用素材；缺一即在渲染前失败。
- `prepare` 把检索结果**自动剪**成帧精确时间轴：按幕分配时长、视频裁剪入出点、静图做推拉平移、硬切或交叉淡化；可选逐幕口播与字幕（复用现有 TTS 与字幕能力），可选作品内本地音床与响度归一（复用共享声音契约）。
- 新增 Remotion composition `StockMontage` 与本地媒体服务接线：渲染期素材经回环 HTTP 提供给 Chromium（支持 Range 请求），素材 URL 在渲染前本地可用，画面本身仍然离线。
- 交付门禁沿用统一入口：人工评审绑定当前准备指纹；正式渲染前要求评审通过。
- 文档同步：新增 Skill 参考文档（材料字段、检索与许可要求、剪辑规则），并更新 README 当前能力与项目规划清单。

## Impact

- `src/m2v/types/catalog.json`：登记 `stock-montage` 的类型身份与 `brief` 材料模板。
- `src/m2v/types/stock/`（新增）：检索与下载、类型适配器（校验、准备、预演、渲染、评审）。
- `src/m2v/cli.py`：挂载 `m2v stock search` 子命令。
- `web/src/compositions/StockMontage.tsx`（新增）与 `web/src/Root.tsx`：注册新 composition。
- `src/m2v/engine/`：媒体服务在渲染期对作品目录的回环暴露（复用现有 `LocalServer`，不新增依赖）。
- `tests/`：新增离线测试（本地假图库服务、检索与下载、校验失败路径、时间轴编译、混音调用、composition 单测）。
- 依赖：只使用标准库 `urllib`，不新增 Python 或 npm 依赖；检索需要联网与图库 API 凭据，凭据只从环境变量读取，不入库。
- 内容与许可：下载的素材属于作品内容，按既有忽略规则不进 Git；作品必须保留来源、作者与许可记录。
