## 背景

Windows 的 `tempfile` 会在创建的临时目录上设置一份收紧的 DACL：只有 `SYSTEM`、`Administrators` 与 `OWNER RIGHTS`，且关闭继承。`Path.replace` 把文件搬到最终位置时会把这份 ACL 一起带走，因此交付文件对当前账号可用，却对以标准权限运行的打包应用不可用——用户双击成片时才暴露为 `0x80070005`。`mkdtemp`、`TemporaryDirectory` 与 pytest 的 `tmp_path` 都会产生同样的目录。

## 决策

### 一个交付原语，而不是「记得调用一次」

2026-10-09 的金融类型修复把 `grant_inherited_access` 放在金融与住宅渲染模块的交付点，属于「每新增一条交付路径就要记得补一次」。事实是通用类型的六条交付路径都漏了。因此这次把搬运与修复收成 `security.deliver(temporary, destination)`：调用方只表达「把这个产物交付到那里」，不可能只做一半。目录交付（打包缓存整体发布）用 `security.deliver_directory`，`icacls /reset /t` 递归复位。

### 交付后复核目标本身

`icacls /reset` 返回 0 只说明命令执行成功：如果父目录本身是收紧的（例如把临时目录整体搬成了产物目录），复位只会再套一遍那份 ACL。因此交付后复核一次 `has_usable_access`，失败时报告目标与所在目录。复核只查目标本身、不递归，代价是一次 `icacls`。

### 复核判据沿用既有 `has_usable_access`

不新写一套判断：它按授权行解析，要求存在 `Users` / `Authenticated Users` / `Everyone` 或当前用户的写权限。仓库与作品目录的继承权限里都有 `Authenticated Users:(M)`，因此正常交付必然通过；只在目标真的没有普通用户授权条目时报告。

### 修复范围

- 文件交付：通用成片与溯源记录、混音主音轨、代码场景录制片段、导入素材、配音缓存与词边界、金融与住宅成片。
- 目录交付：Remotion 打包缓存条目。
- 保持原样：`_write_json` 这类「同目录临时文件 + replace」不经过临时目录，ACL 正常；内容搬迁（`migrate` / `relocate`）搬的是已有目录，权限随源走。

### 既有不可读产物的处置

代码修复不能让已经落盘的文件变得可读，因此对工作区现有产物做一次 `icacls /reset` 修复。测试与 `.cache` 下的临时残留属于测试脚手架，不在修复范围。

## 备选方案

- **在 `m2v render` 之后补一次修复**：只覆盖成片，漏掉溯源记录、音轨、片段与素材，且预演路径仍会漏。
- **把产物复制到别处或手工改 ACL**：与既有约定冲突（`security.py` 明确写了修法是重新继承父目录权限），也会让产物脱离作品目录。
- **给 `icacls` 加白名单授权（例如显式给 `Users` 读权限）**：绕过了目录继承这一事实来源，父目录权限变化后产物不再跟随。

## 风险

- 每条交付路径多一次 `icacls` 复核（约 30–50 ms）；素材批量导入时按条数线性增加，实测可接受。
- 非 Windows 平台 `deliver` 与 `deliver_directory` 无行为差异，回归用例在非 Windows 上只验证搬运语义。
- 复核判据要求写权限，若某个内容根的继承权限只给普通用户读权限，会多出一条警告日志；不影响交付与播放。
