## Context

见 proposal.md 的 Why。与设计相关的现状约束：

- 项目已经确立「新增视频类型只在两处落地」：`src/m2v/types/catalog.json` 登记身份与材料模板，类型适配器实现校验、准备、预演、渲染与评审钩子；统一入口不按类型名硬编码分发。本变更完全按这条路径走。
- 现有类型的材料都是人手准备的确定性数据，指纹由 `core/project.py` 的 `file_inputs` 与 `file:` 前缀输入承担，`load_current_prepared` 会在每次读取时复核。
- 渲染期禁止非本地网络：`web/src/runtime/offline-guard.ts` 在浏览器侧阻断非本机请求；`engine/http_server.py` 已提供带回环绑定、CORS 与 Range 支持的本地静态服务器。
- 声音、口播、字幕、评审门禁、输出清理都是共享能力：`engine/sound.py`、`engine/audio.py`、`engine/tts.py`、`cli.py` 的 `_require_review` 与 `core/output_cleanup.py`。
- Python 依赖只有 playwright、imageio-ffmpeg、edge-tts；检索与下载不应引入新的 HTTP 客户端依赖。

## Goals / Non-Goals

**Goals:**

- 让「主题 → 素材 → 成片」这条链路只由一份 `brief.json` 驱动，检索与剪辑都可重放、可核验。
- 把第三方素材的来源、作者与许可变成准备指纹的一部分，使合规信息与画面同生共死。
- 复用既有底座（TTS、字幕、混音、声音契约、评审、清理），只新增本类型特有的检索与剪辑逻辑。

**Non-Goals:**

- 不做素材的语义理解或自动审美裁决：候选排序只按声明关键词与媒体元数据的确定性规则，画面好坏由人工评审负责。
- 不做多个图库的并发聚合、缓存共享或商用许可判定；首版只实现一个图库适配器。
- 不新增音乐检索：音床仍由作者放入作品目录并显式声明（与 `general` 一致）。
- 不改动既有类型与共享底座的对外行为。

## Decisions

### 1. 新增独立类型，而不是给 `general` 加媒体场景

`general` 的场景类型是受控图文、完整类型片段与代码场景，它的材料是帧级编排；本类型的材料是**检索结果**，且带来源与许可这类合规事实。把两者混在一起会让 `general` 的计划契约既要表达人手编排又要表达检索留证，并让「通用计划不需要联网」这条既有性质失效。因此新增 `stock-montage`，复用底座但不改 `general`。

### 2. 检索是 prepare 之前的独立步骤（`m2v stock search`）

检索需要联网与凭据，而 prepare/preview/render 必须可离线重复执行。把检索放进 `prepare` 会让每次准备都联网、失败点漂移、重放不稳定；独立步骤还能让人在下载后先看素材再决定是否继续。检索结果落盘为 `outputs/footage-search.json`，prepare 只读它，因此准备与渲染完全离线。

### 3. 首版图库实现 Pexels，接口地址可覆盖

Pexels 提供免费 API 凭据、图片与视频同一套检索接口、许可条款清晰，适合作为首版来源。适配器通过 `provider.name` 选择，未知名称直接失败并列出可用名称，不做静默降级。`provider.apiBase` 可覆盖官方地址，用于镜像与离线测试；默认值写在类型文档与模板里，不在实现里散落。

### 4. 候选排序与选取完全确定性

评分只使用声明关键词与图库返回的元数据（描述文本命中、方向与分辨率适配、时长落在声明区间、来源 id 稳定排序），不使用随机数、不使用当前时间，不因重跑而改变结果。逐幕按幕内顺序取第一个未被使用的候选；已使用的来源 id 不重复使用，除非作品显式允许。任一幕没有候选即整体失败并报出该幕与关键词——部分成功的结果不落盘。

### 5. 素材本地化并按内容摘要留证

入选素材下载到作品目录 `assets/stock/`，文件名由来源名与来源 id 派生（可读、稳定、不覆盖同名不同内容的文件）。检索记录保存每个素材的来源页、作者、许可、媒体类型、像素尺寸、视频时长与内容摘要，并记录当前 `brief.json` 的摘要与检索参数；prepare 把素材文件登记为 `file:` 输入，于是素材、许可记录或材料任一变化都会让准备与评审过期。

### 6. 渲染期素材经回环 HTTP 提供，URL 在渲染前注入

视频素材无法像图片那样内嵌为 `data:` URL（体积与解码成本都不可接受），把素材复制进共享前端工程的 `public/` 又会污染共享工程并让打包缓存键随作品变化。因此渲染与预演时用现有 `LocalServer(root, cors=True)` 暴露作品目录，在写临时 props 时注入 `mediaBase`（回环地址），画面只用相对路径拼 URL；服务器只绑 127.0.0.1，浏览器侧的离线守卫仍然放行本机地址，Range 支持由现有 `_MediaHandler` 提供。渲染结束后服务器随进程销毁。

### 7. 视频画面用 OffthreadVideo，静图用 Img 加推拉平移

`OffthreadVideo` 由 Remotion 在渲染端逐帧取帧，比 `<Video>` 的浏览器 seek 更确定，适合帧精确的裁剪与合成；`startFrom`/`endAt` 表达裁剪入出点。静图用 `Img` 加 `interpolate` 驱动的缩放与平移（肯·伯恩斯），参数由 prepare 编译进 props，画面不做时序推导。

### 8. 时长分配与裁剪规则写在类型契约里

每幕目标时长 = 目标总时长 / 幕数，夹在 `minClipSeconds` 与 `maxClipSeconds` 之间，再夹到素材自身可用时长；剩余差额按幕均摊一次，最后校验全片时长与目标时长的偏差不超过声明容差，超出即失败。声明固定帧数或口播的幕优先使用其自身时长，口播超出固定容量按既有规则失败。这样「自动剪辑」的每一步都能被复算，不需要人逐幕调帧。

### 9. 复用而非重写

口播与字幕复用 `article-narrative` 已公开的 `prepare_narration`（与 `general` 的做法一致）；音床校验复用 `engine/sound.py` 的 `validate_sound(..., effects=False)`；混音复用 `engine/audio.py` 的拼接、归一与闪避混音；评审门禁与输出清理完全沿用统一入口。类型私有代码只包含：检索与下载、素材校验、时间轴编译、媒体服务接线与画面。

## Risks / Trade-offs

- [在线图库内容不可控，画面质量与许可可能变化] → 只采用返回了作者与许可的候选；把来源、作者与许可写入检索记录并纳入准备指纹；正式渲染前强制人工评审，评审项包含来源合规。
- [检索依赖网络，可能失败或限流] → 检索失败即整体失败并报出该幕与关键词，不写部分结果；已下载素材与检索记录可重放，重试不需要重新挑素材。
- [凭据泄漏] → 凭据只从环境变量读取，不写入 brief、检索记录、准备记录或 Git；文档给出环境变量名与获取方式。
- [视频素材在渲染期加载失败] → 渲染前校验素材存在且摘要匹配；渲染期素材只经回环 HTTP 提供，成片仍走既有媒体验收（帧数、尺寸、帧率、音轨）。
- [自动时长分配与素材时长冲突] → 分配算法把每幕夹到素材可用时长，冲突时明确失败并报出该幕与两个时长，不静默截断口播或拉伸画面。
- [打包缓存键随作品素材变化] → 素材不进共享前端工程，打包缓存键与素材无关；素材变化只影响本作品的准备指纹。

## Migration Plan

新类型没有历史作品，不需要迁移。既有四类作品的材料、准备记录与评审均不受影响；`catalog.json` 只新增一个登记项，统一入口与作品契约不变。回滚方式为移除该登记项与适配器注册，已下载素材与检索记录留在被忽略的作品内容目录中。
