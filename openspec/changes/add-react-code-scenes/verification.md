# 实施验证与审查

## 结论

通用类型升级到 v7，新增 `code` 模板与本地 React 代码场景链路：准备阶段用 esbuild 受限打包作品 `scenes/` 入口，在无头 Chromium 中按 `ready()`/`running` 协议实时录制，再用 FFmpeg 标准化为与镜头帧数完全一致的 30 fps 无声片段，按内容寻址缓存；完整预演与正式导出只回放已验收片段，不执行作品代码。三个固定示例都完成了真实录制、完整预演与正式导出。

代码审查发现并修复两处录制缺陷：录制页原先把背景留成透明，而不带透明通道的视频会把透明合成成白色，导致片段以白底混进深色成片、浅色作品文字消失；随后片段底色又与外壳背景相差两三个色阶，在深色画面上显出可见的方块边缘。现在录制页按分镜主题画出背景与前景色，片段改用 PNG 截屏与 4:4:4 中间编码，实测片段区与外壳区在成片里取到同一像素值。

## 验证结果

- Python：418 passed、4 skipped（缺少可选 fonttools，字体子集化用例跳过），含真实浏览器录制、构建边界拒绝、缓存复用与失效、失败不落准备记录等回归。
- 前端：57 项测试通过，`tsc --noEmit` 通过。
- 真实制作：`buffer-smoothing`、`darts-trial-and-error`、`keynote-baseline` 三个固定示例各自完成 `prepare`（含真实录制与真实配音缓存）、完整 `preview` 与正式 `render`，均退出码 0；对三幕代码场景抽帧核对标题、正文与字幕分区，并逐点采样片段边界确认无可见接缝。
- 文档：类型目录生成检查通过；修改文档的相对链接、JSON 示例与三个示例的严格校验通过。
- OpenSpec：`openspec validate --all --strict` 17 项全部通过。

## 逻辑与性能影响

- 分镜只接受 v7；v6 及更早分镜与旧准备记录明确拒绝，不自动迁移。
- 缓存键包含构建可达源码摘要、整个 `assets/` 集合、场景参数与本地时间窗、共享实现与锁文件、浏览器可执行文件摘要及录制编码配置；源码或资源变化使旧片段失效，资源集合变化在渲染前再校验一次。
- 导出不运行作品代码：`render` 只校验准备记录、片段摘要与实现指纹。
- 确定性闸门仍只覆盖共享 composition；作品代码的自由动画不承诺逐像素复现，实时录制可能掉帧，标准化时按时间戳保留已绘制帧并复制补帧。
- 录制耗时随镜头时长线性增长（示例 90 帧约 3 秒内容、含浏览器启动约 11 秒），命中缓存时不启动浏览器；未新增业务网络请求。

## 剩余风险

- 录制片段使用 H.264 High 4:4:4 中间编码，只能由软件解码；当前解码方是 Remotion 内置 FFmpeg，浏览器不直接解码该片段。
- 长镜头会同时占用较多临时磁盘（PNG 逐帧落盘），临时目录在编码后删除。
- 作品代码仍属可信代码：限制的是打包导入与运行时网络，不是恶意代码沙箱。
- 示例的真实配音命中本地缓存，未重新调用在线 TTS 服务。

## 质量评分

96/100。契约、录制、缓存与三个示例的端到端链路均已验证，审查中发现的可见缺陷已修复并复测；扣分来自实时录制的帧重复边界与 4:4:4 中间编码带来的解码兼容性假设。
