## Context

动机和范围见 [proposal.md](proposal.md)。当前构建器将 `m2v/code-scene` 映射至仓库源码，裸依赖从 `web/node_modules` 解析；Python 准备、采集、字体检查和 Remotion composition 均以仓库 `web/` 为运行根。`implementation_inputs()` 绑定整个 SDK 和全局锁文件，`delivery.binding()` 还绑定主项目 Python 实现。内容根分离没有解决这些执行依赖。

七例实际采用范围已核对：fold 使用 Painter 和衬线字体；compound-interest 使用本地数学模型及音床／事件声；compound-connect 使用公式与事件声；pigeon 使用 Painter 与事件声；luck-on-stage 使用路径／Painter 与事件声；solar-system-journey 使用 R3F 镜头后期、15段旁白、音乐和事件声；american-science-milestones 使用真实登记媒体及图表。七例均未绑定金融／建筑／汽车结构化来源，不能据此删除仍有公开用途的数据准备能力。

## Goals / Non-Goals

**Goals:**
- 工程可以复制到任意目录，在主项目不可访问时恢复、预览与完整导出。
- 生成后只有作品拥有运行代码、依赖、资源和配置；模板更新不传播。
- 主项目统一入口和制作评审委托／检查作品，无第二条生产渲染路径。
- 七例原地独立化；通用实现有可审计的删除、转参考或转模板结果。

**Non-Goals:**
- 不更换渲染引擎，不重设计七例叙事和画面，不新增示例或保留旧执行兼容层。
- 不批量改写忽略的历史作品，不转移旧报告通过，不删除历史研究及失败证据。
- 不承诺首次恢复无网络，也不承诺跨GPU／驱动逐字节相等；恢复后正式渲染使用本地输入。

## Decisions

### 1. 当前契约为独立工程，不发布强制SDK

`project.json` 升至 v3，准备记录同步升级以明确拒绝旧工程。作品保留既有五类身份和分镜 v9 的场景、事件、声音等表达；不因执行所有权变化而复制另一套分镜字段。字段若在实施中必须调整，先同步本变更规格，不隐式解释旧字段。

作品根拥有 `package.json`、独立 pnpm 锁、TypeScript／构建配置、`pyproject.toml`／uv锁（采用Python准备／采集时）、本地运行代码和 `scripts/`。Node/Python/包管理器前提写入作品说明。禁止 `workspace:`、指向主项目的 `file:`／`link:`、上级tsconfig和父目录node_modules兜底。

对比方案：版本化共享SDK仍使主项目组件成为强制依赖，不符合用户目标；全量复制仓库会带入制作管理和无关类型能力，维护成本过大。因此采用小型基础模板与显式采用的本地组件。

### 2. 成熟运行能力从现有实现提取到可执行模板

模板位于 `templates/standalone/`，构成生成器的输入，模板本身在仓库内可以独立构建和测试。生成器只在创建时读取；运行时不定位模板。基础运行包括本地manifest、时间轴、字体、资源、逐帧宿主、异步任务、采集、字幕、转场、混音、编码和输出核验；图表、R3F、公式、路径追踪、业务来源计算等按实际采用增加。

优先整理和移动现有经过测试的 Python／TS／JS 实现，改掉仓库根和全局登记假设，不重写另一套计时或异步绘制算法。移入作品的Python模块用本地命名空间，不能 `import m2v` 或通过PYTHONPATH导入主项目。多进程worker也从作品环境启动。

模板提供本地 `setup/validate/prepare/preview/build/render/qa/sample` 入口。`render` 能完成必要准备，最终字幕、转场、音轨也由本地composition与执行器完成。网页预览与采集共用场景、配置、资源及时间逻辑。

模板采用的基础配置只有一处权威来源；生成文件归作品，主项目测试生成物，不保留运行时读取主项目的别名作为过渡。

### 3. 本地执行协议只连接可选制作工具

v3 manifest声明协议版本、本地入口及参数数组；默认入口为作品 `scripts/` 内的可执行脚本。主项目以参数数组、`shell=False`、作品cwd和作品锁文件启动，按类型化参数转发命令，启动时建立可取消的进程组；超时、用户取消或异常时终止整个Python／Node／worker／浏览器／ffmpeg子进程树并等待退出，失败不发布有效收据也不替换原成片；超时／失败清楚报告，不修改作品依赖、不偷偷安装主项目运行时。

协议结果记录实际输入摘要、准备／候选身份、产物相对路径及环境。主项目验证路径、文件存在、媒体摘要和绑定；不把成功退出或一份自报JSON当成完整证明。直接调用作品入口与通过m2v调用必须同源。

协议并非所有独立作品必须实现的框架；只有希望接入m2v制作管理的工程需要实现接口。默认生成工程自带该接口。

### 4. 依赖、组件与资源按作品拥有

基础模板仅安装实际需要的依赖；组件采用时递归带入其本地依赖与来源／许可，第三方依赖在本作品声明精确版本并锁定传递依赖。补丁、资源加载配置及二进制模型恢复配方均随作品。不得用符号链接让“独立工程”继续读仓库文件。

当前 `sdk.tsx` 的三维、ECharts、motion、GSAP等总入口拆开。示例直接导入本地组件或明确第三方入口；未采用的库不成为默认工程依赖。公式字体只放入采用公式的工程；衬线、中文、拉丁字体同样按实际用量登记。

字体及媒体沿用原始来源、版本、字节数、SHA-256和许可。迁移配方可以调整恢复目标的相对位置，不能修改预期内容或接受摘要漂移。已有正确素材不覆盖，缺失明确恢复，错误摘要明确拒绝。二进制不新增入Git。

数据渲染需要的快照必须在作品；需要更新／重算的作品携带自己的计算代码及依赖。主项目金融等工具可继续作为辅助，但默认工程不预装所有业务来源。已有旁白音频可重用，生成服务和凭据不是正式本地重渲的隐藏前提。

### 5. 保留默认采集后合成链路

作品本地场景经受控时钟、资源ready和waitForFrame等待后采集为片段，本地composition再处理字幕与转场，最后按当前音轨政策混音与编码。保持纯时间资格、顺序模式、乱序核验、子帧、SSAA、元数据确认、并行和可靠候选发布的已有边界。

已经存在的成熟外部能力继续复用，不新增自研渲染引擎。2026-11-08核查官方资料：
- [Remotion renderer](https://www.remotion.dev/docs/renderer)：渲染API可作为工程依赖使用；API调用不读取CLI配置，继续使用现有明确配置的构建／渲染分工，不假定自动继承配置。
- [Playwright browsers](https://playwright.dev/python/docs/browsers)：浏览器版本随Playwright匹配；本地setup及环境记录必须覆盖浏览器恢复。
- [pnpm install](https://pnpm.io/cli/install)：独立冻结安装可验证本地锁文件；项目不得依赖父工作区。包存储可共享缓存，依赖解析与锁定仍属于各作品。

既有依赖版本与许可作为选型起点，不为架构重整顺便升级版本。新增组件时另按项目规定检索和验证。

### 6. 主项目精简为指导、生成和可选制作管理

`m2v init`生成完整工程；validate/prepare/preview/render调用本地执行；sample采集／播放使用作品同一实现；qa/review/issues/status/baseline继续管理当前媒体与独立证据。

原通用实现的处置要在 `inventory.md`逐项完成：
- 总SDK别名、全局作品依赖登记／安装校验、强制后期依赖、仓库动态入口和主项目渲染根：删除。
- 字体／帧参数、host／clock／frame-tasks、采集／合成／混音：收敛到可生成本地模板。
- Painter、图表、路径、公式、镜头等实际采用能力：保留必要参考或选用源码；示例使用本地副本。
- 无实际消费者的diagram入口、业务绘制包装、重复主题／令牌、全量转导出包装及其直接依赖：依据引用和现有公开契约逐项删除或转为选型说明，不盲目删除数据能力。
- 制作证据、素材研究和独立审核工具：保留其工具职责，解除对主项目web的运行依赖。

删除对应代码时同步调整测试和文档，记录仍保护的独特行为；不以删测试掩盖回归。

### 7. 输入、媒体和审核分别绑定

构建记录覆盖作品实际构建输入、依赖、补丁、显式资源和运行环境。以构建器实际输入为优先，动态引用无法解析时显式登记或保守扩大。元数据、配置等非import输入仍显式绑定。相对路径以作品为根，搬移不改变身份。

渲染记录不绑定主项目整包或参考组件；外部检查器版本与规则放在检查／评审记录。改变检查器可以要求重查，不自动触发画面重采集。主项目不能只信任作品自报的依赖，复核实际文件、摘要和输出；采集失败或输入变化不发布有效收据。

旧报告、问题和历史保持其原输入和结论，不转换为新版通过。技术候选可独立生成，正式制作完成仍按既有独立审核门禁。

## Risks / Trade-offs

- 本地代码重复 → 接受作品所有权带来的必要重复；基础模板精简、采用范围明确，更新以作品显式改动为准。
- 提取遗漏字体、worker或动态资源 → 脱库测试必须在无主项目PYTHONPATH、无共享node_modules、无构建缓存环境进行，检查实际构建输入和进程环境。
- 只测七例漏掉来源数据 → 额外选择金融、建筑、车辆来源直接相关节点验证；七例不增加来源数据来充覆盖。
- 三维和旁白恢复耗时／服务失败 → 记录具体过程与实际句柄，不借用别例、历史缓存或静态图声称全片独立通过；失败先定位并修复，不能缩减验收目标。
- 主项目文档与代码职责漂移 → 同步Skill、架构、初始化说明、测试和规格；README只记已实现状态。
- 视觉意外变化 → 改造保留原场景和参数，按受影响窗口实际核对；独立审核按现有策略执行，不把技术通过当美术通过。

## Migration Plan

1. 建立并验证本变更，形成通用功能处置清单与逐例验收矩阵。
2. 打通基础模板真实脱库准备、网页预览、字幕／声音成片、原生样品和技术检查。
3. 接通m2v委托和证据绑定，再逐例本地化实际采用组件与资源。
4. 七例逐一独立恢复、构建、真实短预演和完整技术导出；针对异步三维、公式、媒体、声音及受影响画面补核对。
5. 删除旧主项目运行分支及无用通用功能，完成定向测试、文档与独立代码审核，修复后提交。
6. 任务全部完成且验证／提交通过后自动同步主规格、归档并提交。未完成项保持勾选未完成，不把阶段完成报作整体完成。

回退以Git提交为单位，恢复旧代码与已跟踪示例源码；不自动修改被忽略的历史作品或伪造恢复旧媒体。旧运行环境的可追溯依据是改造前提交，非新版兼容分支。
