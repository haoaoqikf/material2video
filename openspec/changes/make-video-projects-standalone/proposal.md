## Why

目前作品可以离开仓库存放，但其 SDK、依赖解析、数据准备、字体、采集和最终合成仍读取主项目当前实现。作品不能独立重建，一部作品的依赖升级也会扩大其他作品的失效范围。用户已明确要求完整实施独立工程、清理不必要的通用功能，并将现有七部示例一起独立化。

## What Changes

- **BREAKING**：将当前作品契约升级为独立工程契约。作品拥有本地依赖与锁文件、配置、运行时、数据与资源恢复、预览、准备、采集、成片合成、导出和技术检查入口；主项目不可访问时仍可运行。
- 主项目提供制作方法、初始化模板、可选择的组件参考及可选的检查和评审工具。模板在创建时生成实际文件；作品执行时不加载模板或主项目源码，不自动同步后续更新。
- **BREAKING**：移除 `m2v/code-scene` 的主项目源码映射和全局作品依赖安装／登记路径。组件按作品实际需要成为本地源码或其显式第三方依赖，不建立新的强制 SDK 包。
- 保留既有受控采集与片段合成的成熟实现，重整为可生成的本地执行材料；拆开可选组件与基础运行能力，不把整个主项目复制到作品。
- 统一 `m2v` 入口调用作品本地命令，保留独立评审、问题闭环与制作完成规则。渲染输入和外部检查器版本分别绑定。
- 七部既有示例原地改造，保留主题、场景身份和视听要求；不新增简化示例替代，不保留旧工程双轨。
- 清查主项目通用实现，删除已失去运行职责、重复、不可达或无实际消费者的组件、包装层、登记及依赖。仍有参考价值的实现按实际用途收敛为明确的参考或模板，输出逐项处置记录。
- 不批量改写被忽略的 `videos/` 历史作品，不删除原始研究、失败报告、问题台账或历史证据；旧工程不自动转换，按旧 Git 修订可追溯。

## Capabilities

### New Capabilities
- `standalone-video-projects`：完整独立工程、本地执行协议、按需组件采用、七例改造与通用实现清理。

### Modified Capabilities
- `article-workspace`：作品可任意搬移；运行时不再定位主项目或生成仓库动态入口。
- `five-video-types`：保持五类与七例身份，统一新独立工程契约。
- `react-code-scenes`：作品本地构建、依赖、宿主和指纹；共享 SDK 责任改为可选本地参考。
- `modular-video-production`：初始化完整工程、统一入口委托本地执行、渲染与审核记录解耦。
- `remotion-renderer`：默认渲染实现归作品；保留确定性、元数据、缓存、并发和可靠交付边界。
- `font-pipeline`：每个作品拥有实际使用字体的登记、许可、恢复和校验。
- `native-design-samples`：原生样品使用作品自身执行链路，保留现有独立评审与交付门禁。
- `render-provenance`：产物绑定作品实际输入和环境，不以主项目更新使无关画面失效。
- `example-media-recovery`：示例独立恢复媒体与声音，保持原始来源和摘要。
- `shared-motion`：通用动效作为可采用的本地实现／第三方选型参考，不强制运行时 SDK。
- `diagram-layout`：布局能力降为可选组件参考，删除无实际消费者的强制宿主入口。
- `math-and-icons`：公式和图标按作品需要本地采用，不从主项目加载字体或组件。
- `typed-scene-sources`：渲染使用作品自身的数据快照及本地准备逻辑；主项目准备工具为可选辅助。
- `keynote-design-system`：共用设计与字幕建议落实为作品本地单一来源，无运行时全局主题／组件依赖。
- `compound-interest-explainer-video`：保留作品全部视听要求，将共享 SDK 导入要求改为本地动效实现。

## Impact

涉及 `src/m2v/core/`、`type_system/`、`types/scene_film/`、`engine/`、`production/`、`web/`、字体恢复、七部 `examples/`、相关测试、README、ARCHITECTURE、AGENTS、项目规划、制作 Skill 与 OpenSpec 主规格。以复用既有成熟实现为首选，不新增渲染引擎、不增加示例、不以测试桩代替真实脱库验证。Python、Node、浏览器、ffmpeg 和 GPU 前提需随作品声明；不承诺跨硬件逐字节复现。
