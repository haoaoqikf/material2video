## Context

参见 `proposal.md` 的 Why。当前链路中「网页 → MP4」全部由脚本完成，而「文章 → 分镜」没有任何规范：
`docs/PROJECT_PLAN.md` 第六阶段只有一句目标与四条验收，`SKILL.md` 的标准流程第 1 步写的是
「读文章，按…拆成若干场景，写入 `storyboard.json`」，没有判断顺序、约束清单和交付标准。
现成可复用的能力已经齐备：`validate.py --strict/--json` 能在开渲前给出带字段路径的错误与排版警告；
`review.py` 的组件契约探针能读出挂载点里的实际文本；组件的新增流程（`figures.js` 注册 →
`figures.css` 样式 → `catalog.py` 登记 → `figure-catalog.md` 记一行 → 逐项对照测试）已由
`tests/test_figures_assets.py` 守住。约束是：本变更不引入 Python/JS 依赖，不接入模型服务或密钥，
不改变渲染契约与输出归属。

## Goals / Non-Goals

**Goals:**

- 让「文章 → 分镜」有单一权威来源：可照做的步骤、可核对的约束、可判定的完成条件。
- 让生成结果自动具备「可渲染」属性：产物直接通过声明式严格校验，组件选择受目录约束。
- 让组件缺口有明确出口：按契约新增组件并完成登记，而不是在生成过程中退化或绕过契约。
- 控制评审成本：规范本身要能被人工逐条核对，不依赖某次生成的运气。

**Non-Goals:**

- 不写生成器程序、不建模型调用通道、不管理密钥。
- 不承诺同一篇文章每次生成完全相同的分镜；也不做自动选择视觉风格。
- 不做批量生成与批量渲染。
- 不为效果验收新建一支视频；复用现有已完成作品。

## Decisions

1. **生成能力落在 Skill 流程规范，不落到代码。** 新增一份参考文档承载完整生成规范，并在
   `SKILL.md` 的标准流程第 1 步与 `README`、`PROJECT_PLAN` 中指向它，使该步骤有权威来源。
   理由：`PROJECT_PLAN` 第六阶段的验收全部是内容质量约定（保留核心判断、只用受支持组件、
   报错可修正），没有一条需要新程序；而项目对依赖引入一贯保守。替代方案一是内置规则式生成
   （可按段落映射到场景与组件，但选比喻、拟标题这类判断质量明显偏低）；替代方案二是可插拔模型
   后端 + CLI（更接近「可调用」，但会把密钥与厂商耦合带进仓库）。两者都记录在本变更之外，
   若将来需要，可作为独立变更提出。

2. **把校验器当作生成流程的验收接口，而不是新增检查逻辑。** 生成方按
   `validate.py <分镜> --declarative --strict --json` 的 `errors[]` / `warnings[]` 与字段路径逐条修正，
   直到严格校验通过。理由：`--json` 已为自动修正循环设计，错误路径可定位到
   `scenes[2].data.figure.kind` 这一级；另写一套生成侧检查会与校验器形成第二个真源。

3. **新组件的门槛写进规范，而不是靠自觉。** 规范要求：先检索组件目录；确实没有合适表达时按
   组件契约新增；新增必须完成四处登记（`figures.js`、`figures.css`、`catalog.py`、`figure-catalog.md`）
   并通过 `tests/test_figures_assets.py` 的逐项对照；新组件必须调用具名动效配方、文案全部来自分镜、
   样式只用设计令牌。判定「确实没有」时要求给出与最接近组件的差异说明，避免同一比喻被反复重写。
   替代方案是禁止新增并强制就近降级：会产生「分镜写得通、画面表错意」的静默偏差，与本项目
   「宁可报错也不静默错位」的既有取向（同 `figure-catalog.md` 对标注键的处理）相冲突。

4. **验收复用现有作品，不新造示例。** 用 `videos/never-fear-interviews/` 按规范产出更新版分镜，
   以「严格校验通过 + 与原分镜的场景结构一致或更优 + 组件登记未被污染」为验收证据，
   不新增视频目录、不重新渲染成片作为门槛。理由：该作品 8 幕已覆盖 `balance` / `gap` / `iceberg` /
   `loop` / `stairs` / `versus` / `exchange` 六类以上组件与两处组件缺口处理，是最真实的样本。

5. **文档分层，避免三处维护同一份事实。** 生成规范的权威来源放在 Skill 参考文档；
   `SKILL.md` 只保留流程入口与要点；`README` 记录「已实现」的状态；`PROJECT_PLAN` 第六阶段
   改为已实现并指向参考文档，不复制规范内容。理由：`PROJECT_PLAN.md` 与 `storyboard-schema.md`
   已明确采用「权威来源单一、他处只链接」的写法，本变更沿用。

6. **为声明式路径补齐组件契约探针（实施中发现的工具缺口）。** 规范要求交付前确认声明的标注
   真的画了出来，而探针此前只支持专属网页：`review.py` 把本地页面交给通用的
   「页面 → URL」转换，而共享页面必须带 `a2v-storyboard` 查询参数才初始化，于是必然超时报错；
   默认输出目录又从 `--page` 推导，共享页面不在 `videos/`、`examples/` 下，同样推导失败。
   做法是加 `--declarative` 省略 `--page`、复用渲染入口的共享页面与查询参数拼装、输出目录回退到
   分镜归属，并让静态宪法显式跳过依赖源码的三项检查（C1 场景层 / C4 挂载点 / C5 文案单一真源）——
   共享页面的场景、挂载点与文案都由运行时按分镜生成，查源码必然误报，结论本就该由运行时探针给出。
   替代方案是把静态检查改成读运行时 DOM：那会让宪法从「静态」变成「运行两遍」，成本更高且结论重复。
   代价是 `review.py` 出现两套入口语义（`--page` 对专属网页，`--declarative` 对共享页面），
   已写进 `SKILL.md` 与生成规范以免误用。

## Risks / Trade-offs

- [纯流程规范容易被误当作已实现的程序能力] → 在参考文档与 `SKILL.md` 中明确「本步骤由 AI 工具按规范执行，项目不含生成器程序」，与既有「尚未实现：AI 自动分镜」的表述同步更新，避免两处说法互相矛盾。
- [允许新增组件可能导致组件库膨胀或同一比喻重复实现] → 规范要求新增前检索目录并写明与最接近组件的差异；目录文档新增一行时须给出适用内容，人工可据此否决重复组件。
- [生成质量依赖不可复现的判断，无法像渲染那样逐帧比对] → 不承诺确定性；把下限交给 `validate.py --strict` 与组件契约探针，把「值不值得看」留给按量表的人工/视觉评审，与既有「先机检再人评」一致。
- [规范文档存在漂移风险：排版上限、标注长度、动效名散落在多份参考文档] → 规范只引用这些文档，不复制其数值；改动排版或动效时同步检查规范中的引用是否仍然成立。
- [组件缺口判断依赖主观，可能被滥用为「先新增再说」] → 把「检索 → 差异说明 → 按契约新增 → 四处登记 → 对照测试通过」写成有先后顺序的清单，确保任一步缺失都会在测试或评审中暴露。
