## Why

从文章到分镜目前完全依赖手感：没有一处文字说明「怎么把一篇文章拆成幕、选组件、定时长、写文案」，
每支新视频都要重新推导一遍，`videos/never-fear-interviews/storyboard.json` 这样的 226 行脚本
靠反复试错才收敛。组件库、共享声明式页面、校验与渲染链路都已就位，缺的正是这条链路最前端的
一步——它也是 `docs/PROJECT_PLAN.md` 路线中唯一仍标注「规划中」的阶段（第六阶段）。

## What Changes

- 把「文章 → 分镜」从个人经验变成**可复核的生成流程规范**：明确输入（规范目录下的 `article.md`）、
  唯一产物（`videos/<slug>/storyboard.json`）、拆幕与视觉选择的判断顺序、以及生成后必须走完的
  校验—修正闭环，写入制作 Skill 并成为该步骤的权威来源。
- 固化生成的硬约束：不虚构论据、无来源数值标注示意、画面文案与口播文案分离、时长由口播需求反推、
  硬换行与单行字数按现有排版上限、`emphasis` 短语必须原样命中、标注用组件认识的键且不过长。
- 定义组件缺口行为：现有目录表达不了该段落时，允许在生成过程中按组件契约**新增组件**，
  新组件必须完成既有登记流程——`figures.js` 注册、`figures.css` 补样式、`catalog.py` 登记、
  `figure-catalog.md` 记一行，并通过镜像与注册表的逐项对照测试；不得绕过契约直接写专属网页里的图形。
- 为生成流程提供可执行的验收：用示例文章走完「生成分镜 → `validate.py --declarative --strict` 通过
  → 预览 → 短片导出」，并覆盖修正重试与组件缺口的场景。
- 同步更新 Skill 主文档、分镜结构、组件目录、README 与项目规划，把第六阶段从「规划中」改为已实现，
  并明确未随本变更实现的部分。

## Capabilities

### New Capabilities

- `article-to-storyboard`：从文章生成分镜的流程规范——输入输出契约、拆幕与视觉选择规则、
  内容与排版约束、组件缺口时的处理、生成后的校验闭环与修正要求。

### Modified Capabilities

无。`declarative-video-scenes` 已规定分镜如何声明组件、布局与主题，本变更生成的产物沿用同一套声明；
组件库的登记与目录对照也沿用既有流程，因此没有既有规格的需求被改动。

## Impact

涉及制作 Skill 的流程文档与参考文档、组件库与目录镜像的登记约定、组件登记相关测试、
示例文章与其分镜、README 与项目规划。不新增 Python 依赖，不接入任何模型服务或密钥，
不改动渲染契约、预览/渲染脚本、音频链路与输出归属规则。
生成产物仍走现有声明式路径，旧视频与既有专属网页路径保持兼容。
