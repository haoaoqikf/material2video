## Context

动机见 proposal.md。当前四阶段、G0–G6 和隔离评审包均已存在；仓库有其他代理正在修改复利作品、README 与视觉创意文档。本变更只能触及未被占用的流程参考及独立的演练文件。

## Goals / Non-Goals

目标是让制作助手知道何时检查、凭什么通过及失败回到哪层，并保护文字、静态、功能镜头等有效表达。不新增阶段、字段、评分、用户审批或自动审美判定，不重制任何作品，不改已有制作记录。

## Decisions

- production-workflow.md 是两项检查的唯一权威定义，其他参考通过链接引用，避免重复维护判据。
- 视觉事件检查先盲看完整窗口，只记录实际变化，再提供中性原条件；不以文字、移动或运镜形式直接否决。
- 设计兑现先保留独立盲审观察，再使用独立 consistency 包对照中性可观察目标与目标关键帧。完整导演方案只由制作助手关联，不进入盲包；对照不能代替独立审美通过。
- 覆盖 A 级与核心表达，B/C 按用途与合同核对；没有独立目标图时明确不适用图像对照，不伪造通过。
- 固定太阳系示例新增单独的规则演练文件，使用假设情景，不写实际成片新结论，不改场景与素材。此方式避免干扰复利在制任务。
- 无可自动判定的审美新增字段，故不修改校验器；验证采用规格严格校验、文档链接/JSON 检查、情景演练和既有文档同步检查。

## Risks / Trade-offs

- 共享手册更新被在制代理读取 → 在 Skill 入口和新增规则中明确前瞻适用范围，不要求在制任务重新 prepare 或补评审。
- 三方对照污染盲审 → 分离 blind 与 consistency 两次证据视图，设计理由和旧结论始终不投喂。
- 仅端点相似掩盖动态失败 → 必须检查完整窗口，区分静态与时序证据；证据不足保持未验证。
- 并发 Git 暂存混入 → 提交前按显式路径检查暂存清单；不执行 stash、reset、checkout 或清理其他任务。
