## Context

现有流程已规定先粗预演、风险优先、独立复核六个维度且技术通过不等于审美通过。本次补齐执行判据，并用太阳系之旅的重新制作验证效果。完整任务包含工作流规范修改与视频重制；当前阶段仅更新计划文档，后续按任务清单实施两部分。

## Goals / Non-Goals

目标：让核心体验决定预算、检查方式与完成判断；让同类问题在精制前暴露；防止已知体验缺陷以限制披露代替修复；交付解决快速掠过、切换突兀问题的新太阳系成片。

范围内：工作流规范、太阳系示例的必要代码和材料修改、相关测试与契约同步、粗预演、风险样片、全片准备与导出、最终复核和交付记录。优先复用现有资产与未改变的旁白；修改旁白时按既有选音与摘要契约重新判断，不能沿用失效的音色选择记录。

范围外：通用运动分析平台、无关类型或示例重制、与本片无关的相机框架改造、新用户审批和 CLI 人工门禁。本计划不声称规范或视频已经完成。

## Decisions

### 1. 核心体验先写成观察标准

在现有 DESIGN.md 与 visual-notes.md 模板中补充核心要求、失败现象、验证范围、证据方法和当前结果，不新增审批文件。例如一镜到底需观察出发—穿行—到达的关系、视线承接、速度变化与观察时间，不能只检查单幕与路径端点。

### 2. 预算允许双向修订

先做内容与视觉的联合预算，再由完整动态粗预演和实测配音回填。无硬时长约束时优先保留定位、运动和观察所需时间；有明确时长上限时删减信息、减少站点或重构镜头，而非靠突发加速塞进时间线。不得从本片问题推出所有视频固定延长若干秒的规则。

### 3. 检查整段运动，证据分工明确

风险清单覆盖最远距离、最大尺度变化、最大转向、最短停留、开场和收尾，允许片段重叠。每段检查离场、飞行、转向、抵达及观察，不只看镜头边界。关注速度峰值、加减速、方向、主体屏幕尺度变化及重复运动；有实际测量才填写数值，不引入缺乏依据的统一速度阈值。

静态关键帧用于构图与材质；动态片段或有时间标签的加密帧序列用于运动；自动 QA 用于其已声明的技术范围。沿用无连续播放接口时的替代验收，要求加密范围覆盖风险全过程，并披露对节奏体验和帧间运动的覆盖限制。若证据不足以判断已知运动问题是否解决，应保持待复查，不能仅凭路径数据关闭。

### 4. 放行规则围绕问题是否解决

用户指出的核心体验缺陷和复核发现的明显急冲、急转、主体一闪而过列为必改。渲染成功、技术通过、完成抽帧不自动关闭问题；不得将同一缺陷改名为可选或限制以取得通过。能力覆盖限制和已观察到的缺陷分别记录。粗预演失败先调整方案；已有连续两轮无改善则更换方法的规则继续适用。

### 5. 单一权威与同步范围

- `creative-production.md`：体验条目、时间预算与阶段条件的操作规则。
- `visual-review-rubric.md`：证据分工、整段运动复核与问题等级模板。
- `production-workflow.md`、`cinematic-video.md`、Skill 入口：简明摘要与链接，不复制多套标准。
- OpenSpec：可验证的助手制作行为，不把倡议写成运行时自动门禁。
- README：仅检查导航及当前行为表述是否需要同步。

太阳系既作为判断演练，也作为实际重制的验证作品：路径相接但中段猛加速应返工；已记录偏快但只有稀疏静帧不得关闭。旧版状态保留历史标识，新版结论绑定当前准备指纹与交付摘要。

### 6. 太阳系重制分阶段推进

1. 记录 S01「天体之间快速掠过、缺乏持续穿行感」和 S02「局部切换或转向太快」两条必改反馈；登记旧版摘要、典型时间码和对应证据。
2. 重新核算离场、空间移动、视线承接、到站与观察预算。统一考虑位置、方向、速度、FOV 与主体屏幕尺度，检查重复推近拉远；不预设把所有过场统一延长就能解决。
3. 保留 15 个站点、单幕连续旅程、地球/土星/奥尔特云 hero、1920×1080、60 fps、cinematic 及科学示意边界。当前规格的固定时长和镜头数先作为待验证约束；若与自然运动冲突，先补齐对应增量规格，更新校验、测试及文档，再落地新的预算，完整片长仍不得超过 600 秒。不得为保留 135 秒而机械赶路，也不先写死未经预演验证的新时长。
4. 先制作覆盖全片的低成本动态粗预演，调整整体旅程节奏；再制作覆盖急冲、急转、远距离、跨尺度、短停留和三个 hero 风险的最终参数样片。提供既有 cinematic 要求的 3～5 张原生 4K 静帧与 20～30 秒有声样片，未覆盖风险另补短片；实际复查后再精制全片。
5. 回填实际旁白窗口与音乐段落；时长变化后同步音乐覆盖、闪避与恢复、音效、字幕和主体身份显示。按改动影响执行代码测试、构建及示例校验，不只重新导出旧路径。
6. 重新 prepare、完整 preview、QA 与 render；对最终文件执行全片帧序列、风险过程加密与自动音频检查。可播放时补连续运动检查；无法播放时明确证据范围，不能用静帧证明节奏自然。
7. 新版本上关闭 S01、S02 及新增必改项，记录前后差异、时间码、准备指纹、交付摘要与限制，更新示例 README、DESIGN 和 VERIFICATION。成片保存在 `videos/examples/solar-system-journey/outputs/video.mp4`，生成媒体不入库，不增加第四个示例。

### 7. 完整任务的完成边界

工作流规范通过一致性验证、必要代码与材料通过相关验证、新版太阳系完成当前完整预演与成片复核，且两条用户反馈及新增必改项有有效关闭证据后，才完成整个任务。规范完成、技术 QA 通过或导出成功均不能单独代替这一结论。所有任务完成并提交后再同步主规格和归档，不在仅完成规范时提前归档。

## Risks / Trade-offs

- 规范仍依赖助手执行，不能保证运行时拦截；明确保持现有 CLI 自动验收边界。
- 加密帧序列对连续节奏的证明有限；记录范围与限制，证据不足时不虚构完成。
- 规范重复会漂移；详细规则集中在两份参考文档，其余入口只链接。
- 重制可能需要调整固定时长、镜头数或局部实现；先用粗预演和风险证据确定，再同步契约，不以预设秒数代替设计。
- 渲染成本增加；先用低成本整片粗预演与风险样片淘汰问题方案，再开展正式全片录制。

## Verification

规范：严格验证 OpenSpec，核对文档相对链接与 JSON 示例（如有），演练两项太阳系反馈、固定时长约束、缺播放接口和证据过期情形。

重制：按实际改动运行相关单元测试、相机与浏览器场景验证、前端类型检查和构建、固定示例校验；完成当前版本 validate、prepare、完整 preview、assets audit、QA 和 render。单独记录技术检查与运动体验的依据，验证字幕、主体与实际配音时间窗、音乐覆盖和声音指标，检查最终摘要及未关闭问题。

入库：当前计划阶段 diff 只含规划文档；后续实施只暂存本任务规范、必要实现、相关测试与示例可编辑材料，排除视频、配音、缓存与凭据。
