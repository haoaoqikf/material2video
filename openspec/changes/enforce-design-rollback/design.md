## Context

动机见 proposal.md。现有 v2 合同、独立失败 REVIEW- 必改项、依赖摘要失效、G4 expansion 与 G5 精制前审查已承担机器状态闭环。缺口是制作助手在证据形成后如何区分局部修复与根本重设计，以及具体暂停哪些工作。

## Goals / Non-Goals

**Goals:** 把两个现有评审节点变为明确推进决策，根本失败即时回退；让操作文档与现有机器状态保持一致。

**Non-Goals:** 不新增强制核心轮，不改变审核人数，不增加用户例行审批，不自动判断设计优劣，不升级合同／分镜版本，不迁移在制作品或补造历史证据。

## Decisions

1. 在 production-workflow.md 维护唯一回退规则、触发表及记录模板，其余入口链接引用；审核适用性与人数继续由 checkpoint-gates.md 及既有策略派生。
2. 四种决策是评审后的制作记录正文，不新增 JSON 枚举。失败沿用 fail，证据不足沿用 unverified／insufficient，局部修复与重设计沿用未关闭必改项。机器不能仅从文字决策推断设计通过；不新增校验器字段，验证现有失败和问题阻断行为即可。
3. 独立评审先观察现象，制作助手随后结合技术限制和依赖确定回退范围，避免把作者解释塞进盲包。技术不可行必须以试制和制作条件为依据；粗片精度不自动触发设计否决。
4. 关联既有 DESIGN.md 和 outputs/visual-notes.md 原问题 ID；保留基线、旧失败与未变证据，重做受影响范围的独立验证。全片结构变化必须重做 G5，不用局部通过替代。
5. 三个既有示例只添加针对其内容的未来复用决策示例，不篡改旧合同或声称实际评审通过。共享流程生效于后续启动／重制，当前在制周期不追溯补造。

## Risks / Trade-offs

- 人工决策不能自动保证质量 → 明确证据、独立性、暂停范围及重新放行条件，不宣称新增自动门禁。
- 回退滥用造成推翻重做 → 区分偏好、局部缺陷、粗片精度与根本失败，选择最小充分回退范围。
- 改目标绕过问题 → 原问题不删除，重新绑定当前证据，独立失败仍按原范围与观察类型复查。

## Migration Plan

同步制作入口、审核契约、独立评审和导演模板、README 与示例；执行文档一致性、相对链接／JSON 检查和现有 production 测试，经独立审查修正后提交。全部任务通过后同步主规格并归档再提交。无需运行时迁移；撤销本变更的文本提交可恢复原指导，作品历史证据不删除。
