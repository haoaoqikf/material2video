## ADDED Requirements

### Requirement: 自主视觉复核证据绑定
助手 MUST 在现有观看记录中登记准备指纹、检查对象摘要、时间范围、检查方式和结论。最终全片复核 MUST 同时绑定交付文件 SHA-256。准备指纹变化或交付文件被替换后，相关通过结论 MUST 失效；问题描述可以保留，但 MUST 在有效版本上复查。全局材质、运镜、字幕或混音变化后 MUST 重新完整看听。历史用户确认 MUST NOT 授权当前版本完成。

#### Scenario: 替换成片
- **WHEN** 最终 MP4 的摘要与观看记录不一致
- **THEN** 原全片通过结论无效，助手必须复核新文件后才能标记完成

#### Scenario: 旧记录无版本
- **WHEN** 旧观看记录缺少准备指纹或文件摘要
- **THEN** 记录只作为历史参考，不能支持当前版本完成

## MODIFIED Requirements

### Requirement: 失败评审必须形成返工闭环
制作助手 MUST 记录稳定问题 ID、当前版本、时间码或范围、维度、现象、修改措施、必改或可选等级、状态及复查依据。影响理解、主体识别、文字阅读、旁白主张可见性或存在明显视听异常的问题 MUST 为必改项。必改项只有在修改后的有效版本上复查通过才能关闭，MUST NOT 因重新渲染自动关闭。

同一问题连续两轮修改复查无明显改善时，助手 MUST 调整素材或实现方法；仍无法解决时 MUST 报告未完成及原因，MUST NOT 无限盲调或要求用户批准继续。general 视觉问题 MUST 限制助手的阶段通过和制作完成结论，MUST NOT 新增 CLI 导出门禁。

#### Scenario: 修改尚未复查
- **WHEN** 必改项对应场景已修改但没有有效复查结论
- **THEN** 问题保持待复查，助手不得标记阶段通过或制作完成；CLI 不因此拒绝生成检查文件或正式导出

#### Scenario: 连续无改善
- **WHEN** 同一问题连续两轮修改仍无明显改善
- **THEN** 助手记录前后差距并调整素材或实现方法，替代方案仍失败时报告未完成

### Requirement: 通用作品视觉设计与实际观看
制作助手 MUST 在编写场景前记录受众、观看设备、表达重点、视觉风险及作品设计。general 未指定发布平台时 MUST 面向抖音，未指定画幅时 MUST 使用 1920×1080 横屏、60 fps；用户显式平台或画幅 MUST 优先。金融和住宅专用画幅 MUST NOT 因此改变。设计 MUST 包含视觉隐喻、字体配色、开场/核心/结尾构图、镜头承接与声音意图，时长 MUST 按内容目标确定，不统一强制 60 秒。

助手 MUST 自行搜索事实资料和视觉参考，记录来源、访问日期、用途及具体参考维度，不要求用户提供。直接进入成片的素材 MUST 另行按素材导入契约核验许可并留证；参考用途 MUST NOT 等同于入片授权。资料不可访问时 MUST 如实记录，MUST NOT 虚构搜索、观看或许可结论。

所有 general 作品 MUST 先以最终交付参数验证覆盖开场、核心难点、结尾及主要风险的片段，必改项关闭后再扩展全片。cinematic MUST 额外提供参考板（3–5 张静帧、1–2 段运动参考、1 段声音参考）、look bible 与镜头清单，并保留 3–5 张原生 4K 静帧和 20–30 秒有声样片；未被样片覆盖的高风险章节 MUST 补查。参考与实际画面 MUST 按具体维度对照，MUST NOT 只写形容词。

静帧 MUST 用于检查构图、材质和明暗，连续播放 MUST 用于运动和节奏，实际试听 MUST 用于声音，MUST NOT 相互替代。最终交付文件 MUST 完整看听，并按手机观看尺寸检查文字、主体和平台界面遮挡风险；平台依据 MUST 注明来源和日期，不可核实时 MUST 披露限制。无法实际观看或试听 MUST 报告未完成，不得虚构通过。

standard 与 cinematic MUST 均由助手自主执行，不要求任何制作阶段的用户确认。设计、参考与观看记录 MUST NOT 成为 CLI 导出门禁。

#### Scenario: 未指定画幅
- **WHEN** 用户只提供 general 内容
- **THEN** 助手自行搜索参考，以抖音、1920×1080 横屏、60 fps 设计，记录手机观看目标

#### Scenario: 显式竖屏
- **WHEN** 用户明确要求竖屏或其他受支持平台
- **THEN** 采用显式要求，且不改变其他类型的专用画幅

#### Scenario: 抽帧不能替代播放
- **WHEN** 助手仅检查关键帧，尚未连续播放或试听最终文件
- **THEN** 只报告静帧检查结果，不标记动态、声音或全片复核通过

#### Scenario: 纯 CLI
- **WHEN** 有效材料通过当前完整预演和既有技术门禁但没有观看记录
- **THEN** CLI 可正常导出，助手不能据此宣称视觉复核或制作完成

#### Scenario: 高风险遗漏
- **WHEN** 样片仅覆盖地球与土星，未覆盖有明显暗景风险的外行星和结尾
- **THEN** 助手补查遗漏风险片段，解决必改项后再扩展全片

#### Scenario: 观看发现问题
- **WHEN** 代表片段存在节奏、构图或声音问题
- **THEN** 记录具体时间位置，修改相关材料后重新准备并复查，必改项关闭前不标记阶段通过

#### Scenario: 电影级缺 look-dev 产物
- **WHEN** cinematic 尚未产出要求的 4K 静帧或有声样片
- **THEN** CLI 不因缺失产物阻断导出，但助手不能标记样片通过或铺全片阶段完成，应补齐产物并实际复核

### Requirement: 电影级制作档位与质量门禁
系统 MUST 提供 standard 与 cinematic 两个制作档位。standard MUST 保持现有自动技术验收和默认编码，并执行基础视觉复核；cinematic MUST 增加 look-dev、镜头清单、后期、声音设计、资产质量和参考对照。用户明确要求电影级、极致、惊艳、发布级或品牌片时，助手 MUST 使用 cinematic，并说明约 2–4 倍制作与渲染成本，MUST NOT 静默使用 standard。

cinematic MUST 按 Brief → Look-dev → Hero → Full film → QA/自主复核推进：Brief 记录受众、平台、时长、情绪、必须可见特征及参考；Look-dev 产出 3–5 张原生 4K 静帧、20–30 秒有声样片、至少两种旁白音色 A/B（无旁白时不适用）及声音意图，实看后关闭必改项；Hero 至少三个，每个 8–12 秒连续；Full film 完成全片、声音与界面；QA/自主复核运行技术检查，实际检查 claims 可见性，完整看听最终文件。

技术检查 MUST 区分自动判定与测量提示。冻结/重复帧、字幕配色对比度、响度/真峰值、音轨时长差和 claims 时间窗覆盖的技术结论 MUST NOT 替代构图、可读性、语义同步或视觉质量结论。banding/aliasing 等测量 MUST NOT 自动写成视觉通过。

两个档位均 MUST 取消 look-dev、中间阶段及最终成片的用户确认。技术验收通过、当前有效观看记录齐全、必改项全部关闭且最终文件完整看听后，助手 MUST 可自主标记完成；可选问题 MUST 随交付披露。无观看能力或必改项未关闭时 MUST 报告未完成，MUST NOT 以技术通过代替质量结论。该完成条件 MUST NOT 新增 CLI 导出门禁。

#### Scenario: 自主完成
- **WHEN** cinematic 技术检查通过、当前最终文件已完整看听且必改项关闭
- **THEN** 助手自主交付并标记完成，不询问用户是否通过

#### Scenario: 严重问题未解决
- **WHEN** 技术 QA 通过但存在主体不可识别或字幕无法阅读的必改项
- **THEN** 助手继续返工或如实报告未完成，不以技术通过标记完成

#### Scenario: 无法观看
- **WHEN** 助手无法播放 hero、样片或最终文件，或无法实际试听
- **THEN** 报告检查范围与未完成原因，不虚构通过，不以用户确认补足缺失复核

#### Scenario: 标准档不受影响
- **WHEN** 作品未选择 cinematic
- **THEN** 保持 standard 编码与 CLI 门禁，执行基础视觉复核，不强加 cinematic 资产和 hero 成本

#### Scenario: 用户要求电影级
- **WHEN** 用户明确要求电影级、极致或发布级成片
- **THEN** 助手选择 cinematic，说明成本，自主完成风险样片和复核，不要求用户批准

#### Scenario: 用户未通过
- **WHEN** 用户主动指出已交付成片存在问题
- **THEN** 助手记录具体位置并按严重度返工复查，不将用户反馈设为必须等待的审批阶段

### Requirement: 旁白主张与画面可见性
系统 MUST 接受旁白段可选 claims，记录旁白声称的画面特征。现有 claims 自动检查 MUST 仅承诺旁白时间窗是否被镜头覆盖，并明确报告检查范围；MUST NOT 将覆盖通过描述为特征实际可见。

助手 MUST 在当前时间窗实际观看声明特征，记录时间码、观察结果及版本；不可见时 MUST 形成必改项，调整镜头、材质、朝向或旁白后复查。无法判定时 MUST 记录待复核，MUST NOT 静默通过或依赖图像识别模型作唯一依据。standard 未声明 claims 时 MUST 保持时间轴、准备记录和既有技术验收行为。

#### Scenario: 旁白声称大红斑
- **WHEN** claims 大红斑有对应覆盖镜头，但实际画面不能辨认大红斑
- **THEN** 技术报告只记录覆盖通过，助手记录可见性必改项，解决前不标记制作完成

#### Scenario: 自动无法判定
- **WHEN** 尚未实际查看特征所在时间窗
- **THEN** 可见性保持待复核，不以元数据覆盖结论代替

#### Scenario: 标准作品未声明 claims
- **WHEN** standard 作品没有 claims
- **THEN** 时间轴、准备记录和既有技术验收保持不变
