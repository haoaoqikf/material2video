### 稳定闪白的输入域局部续审（修入前历史）

范围只包含当前 `scenes/world.tsx`、直接相关公共 Shader、Three.js 的实际程序缓存实现，以及作者允许读取的 `outputs/trials/probe-flash.py` 与 `flash-probe/results.json`。未读取视觉评审包、报告、设计或图片；未修改冻结源码；未重复既有 31 项测试。

**P1：非整数 pow 底数未防御浮点上界越界，当前出现稳定异常帧。** `world.tsx` 的 `ATMOSPHERE_FRAGMENT`（约 131 行）为 `pow(1.0 - max(dot(normalize(vNormal), normalize(vView)), 0.0), 4.6)`；`saturnShadow` 母星 litLimb（约 180 行）为 `pow(1.0 - max(dot(radialNormal, toViewer), 0.0), 4.5)`。数学上单位向量点积不大于 1，但 GPU 有限精度的 normalize/dot 不保证严格保持这个上界；点积略大于 1 时，max 仅限制下界，剩余底数变为负数。Khronos 明确将负底数 pow 定义为未定义结果，因此这是实际域缺陷，不是只能靠调曝光或画面参数解决的审美问题。[Khronos pow 原始参考](https://raw.githubusercontent.com/KhronosGroup/OpenGL-Refpages/main/gl4/pow.xml)

拟修为 `pow(1.0 - clamp(dot(...), 0.0, 1.0), exponent)` 正确：在有限正常向量下使底数落在 [0,1]，指数 4.6/4.5 为正，包含零的端点合法；在原理论输入域内保持效果，不改变时间、几何、媒体或外部契约。两处 normalize 的向量由当前正半径球面、有效法线和球外相机产生，未发现当前几何中的零向量来源，不建议在没有实际触发证据时扩大为全模块另一套归一化实现。前轮没有识别 normalize/dot 舍入越过 1 的边界，本轮据新技术证据更正结论。

探针代码确实以同一 bundle 为基线，只在 clamped 模式替换上述大气 pow 表达式；两种模式分别建立新 context，固定同一配置并 seek [384,385,386,385]。JSON 记录基线均亮 6.68757 / 214.48674 / 6.49525 / 214.48674，修改后 6.68757 / 6.59211 / 6.49525 / 6.59211，pageerror 均为空。该局部单变量变化及重复同帧数值支持底数域与异常帧的关联，384/386 的数值完全保持。它没有直接采集 Shader 的中间点积/NaN，也未证明所有 GPU 的传播方式；本审查读取并核对探针与数值，没有独立重跑浏览器，不把均亮正常等同视觉目标通过。
