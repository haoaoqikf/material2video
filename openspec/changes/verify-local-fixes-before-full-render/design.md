## Context

动机见 proposal.md。现有 lookdev、preview 与检查点工具已能提供局部证据；唯一问题表使用 open/closed，适用独立必改项有既定关闭规则。本次只调整制作助手的执行顺序和正文记录。

## Goals / Non-Goals

**Goals:** 将修改后的效果确认与再次全片生成连接起来，让前期设计从实际试制中获得反馈，后期把已确认修改集中进一个新候选。

**Non-Goals:** 不承诺全片仅生成一次，不增加预览必跑组合、硬门禁、审核轮次、问题状态字段或自动影响分析；不重做 perfect-step 或规范示例。

## Decisions

1. 规则集中在 production-workflow.md 的检查与返工循环，阶段入口及修订入口引用。相比复制多套清单，单一权威来源更易保持一致。
2. 在现有问题正文记录「已修改，待复查」与「效果已确认」及当前证据，未满足独立关闭规则前仍为 open。相比新增状态枚举，正文足以表达制作进度，不改变契约。
3. 再次生成前按一批问题汇总修改、实际观察和仍需完整合成判断的项目。只有已知问题无法由局部证据充分验证时才记录全片验证原因；不为了减少次数搁置修复，不用多段 preview 变相生成完整草稿。
4. 静态、动态与全局问题分别选用现有检查方式；无视频播放能力时按原动态证据规则补有序时间码帧，仍不足则保留未验证。局部效果确认不自动关闭独立必改项，也不替代新候选 QA/G6。

## Risks / Trade-offs

- [记录变成额外表单] → 原问题正文只补进度、观察与证据；每批再次生成仅留一条简记，引用问题 ID，不重复评审报告。
- [为减少渲染而少看全片] → 全局结构、总时长、全局风格、混音和编码效果按实际影响扩大全片验证，最终候选仍完整复核。
- [文档更新被误称为已验证提效] → 只报告规范与场景演练验证，不宣称已减少实际渲染耗时或次数。

## Migration Plan

更新共享制作指引与入口，执行文档和相关契约验证后提交，再同步主规格并归档。适用于后续制作与修订，不追补旧作品的历史记录；若需回退，撤销本次文档与规格提交，不涉及材料迁移。
