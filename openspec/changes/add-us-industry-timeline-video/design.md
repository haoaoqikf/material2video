## Context

动机与交付行为见 [proposal.md](proposal.md) 与[作品规格](specs/us-industry-timeline-video/spec.md)。用户已给出详细分镜、7 个产业节点、30 秒节奏与视觉方向，并选定路线 A：30 秒、横屏、无旁白、3 幕、混合载体。现有 general v8 足以承载本片；作品级逐镜表、字体、颜色、像素、素材 ID 与评审记录在 apply 阶段进入被忽略的作品 `DESIGN.md`，本文只保留跨实现的关键决策与验收边界。

## Goals / Non-Goals

**Goals:**

- 让观众在 30 秒内形成“美国过去三十年一波接一波把技术做成产业”的认知，而不是记住 7 个 Logo。
- 用一条连续的时间轴 HUD 串起 7 个产业节点，用每站一个肉眼可见的事件承担信息。
- 在现有 general 能力内完成，不扩展 3D 模型、HDR 或视频类型。
- 把事实、素材许可、评审风险与验收证据固定为可核验合同。

**Non-Goals:**

- 不做 35–40 秒旁白版，不引入 TTS、讲话字幕或第二套文字层。
- 不做“产业时间轴”系列能力、风格包或新视频类型。
- 不承诺真实 SpaceX/Tesla 车型或火箭外观；不使用品牌 Logo。
- 不修改 general 共享行为、固定示例、渲染契约或审核策略。
- 本轮不执行 apply：不初始化作品、不下载素材、不写场景、不渲染、不启动评审。

## Decisions

### 1. 用户方案直接采用

用户已给出详细分镜、节点顺序、30 秒节奏与视觉方向，并选定路线 A。按项目“用户详细方案直接采用”路径执行，不另做三机制匿名比较；替代验证是四个风险样片、G2 目标关键帧、G3 animatic 与 G4 核心动态窗。逐镜表、导演卡、字体与像素留给作品 `DESIGN.md`，本文不复制完整分镜。

### 2. 900 帧节奏骨架

| 幕 | 段落 | 时间 | 帧（左闭右开） |
|---|---|---|---|
| 1 | 开场问题 + 时间轴 | 0–3.0s | 0–90 |
| 1 | 互联网 | 3.0–6.0s | 90–180 |
| 1 | 移动互联网 | 6.0–9.0s | 180–270 |
| 1 | 云计算 | 9.0–12.0s | 270–360 |
| 2 | 页岩油 | 12.0–16.0s | 360–480 |
| 2 | 商业航天 | 16.0–20.5s | 480–615 |
| 3 | 电动车/储能 | 20.5–23.5s | 615–705 |
| 3 | 生成式 AI | 23.5–27.0s | 705–810 |
| 3 | 收尾 | 27.0–30.0s | 810–900 |

三幕 `durationFrames` 分别为 360 / 255 / 285，全部 `cut`，合计 900 帧。幕内保持连续；幕间用设计好的匹配剪辑/硬切（云→地下、火箭烟尘→车辆、电池→GPU）。每站至少 2 秒稳定阅读窗口；开场问题至少 3 秒；收尾最多两行。相比 9 个独立 storyboard 幕，3 幕减少跨幕跳变与 0.4 秒阅读停留开销；相比单幕 900 帧，3 幕保留逐幕缓存与检查点粒度。

### 3. 无旁白、输入与文字预算

- 使用 `input.kind: "topic"`，每幕写 `keywords`；不伪造 `article.md`，也不走源文语义审查；事实与许可仍由 G0 与 `SOURCES.md` 承担。
- `storyboard.json` 显式写 `targetSeconds: 30`、`fps: 30`、1920×1080，三幕 `durationFrames` 为 360/255/285，`narrationSegments: []`，全部 `cut`。
- 每幕 `content.props.capture: {"timebase": "global"}`，共享 HUD 用 `globalSeconds` 维持读数连续。
- 无旁白、无 TTS、无共享字幕层；每站文字为对象名 + 一条不超过约 12 个汉字的结论，不叠加英文释义、小字说明或第二结论。
- 时间轴 HUD 放在字幕安全区上方（横屏 `y < 888`）；即使未来加旁白，也不被字幕覆盖。
- 手机横屏按 852×393 复核；主体与必要文字可读，示意标注按次要标记处理。

### 4. 时间轴与事实口径

- HUD 为四个年代带 + 七个等距产业站点：1990s（互联网）、2000s（移动 + 云）、2010s（页岩油 + 商业航天）、2020s（电动车/储能 + AI）。年代带是视觉分组，不是等比时间轴。
- 画面不显示与站点顺序矛盾的精确年份；2006/2007 这类相邻或交叉年份只进入作品材料与必要的来源说明。若确需在画面显示年份，必须使用年代带或明确标注“非等比产业节点”。
- 节点事实以来源核验为准：互联网 1995、移动 2007、云 2006+、页岩油 2010s、商业航天 2015 首次回收、电动车/储能 2020s、AI 2022+。
- 表述用“美国主导或深度参与”“率先形成产业规模”，不用“押中”暗示国家计划或单一因果。
- 每个节点至少一条来源；`SOURCES.md` 记录访问日期、主张、口径与边界。

### 5. 混合载体边界

- **代码**：互联网节点网络、移动入口迁移、云机柜与应用方块、页岩油二维剖面、AI 的 GPU→模型→Agent。
- **授权实拍/预渲染 MP4**：商业航天与电动车的物理动作优先；预渲染只作为“视频素材”导入，不新增 glTF/HDR 素材类型。
- **程序化兜底**：实拍/预渲染不可得时，用现有三维能力与导入贴图（`color/normal/roughness/emissive`）构建通用物体；仍不导入模型。
- **调色**：只用内置 LUT（`neutral` / `deep-space` / `teal-amber` / `warm-film`）与现有后期参数；不依赖外部 `.cube`。
- **禁止**：SpaceX/Tesla 等品牌 Logo、可识别专有型号、用代码伪造真实事件、用静帧推拉伪装动作。
- 任何图库/代码示意按既有规则保留持续可见的“示意”小字边界标注；完整来源、作者、许可留在作品材料。

### 6. 声音

- 30 秒音床，长度精确为 30.000 秒（24 kHz 下 720,000 采样），使按采样数派生的总帧与 900 一致；淡入淡出包含在 900 帧内。
- 每个产业节点至少一个与画面事件同源的 `eventId` 音效；开场、转场、收尾各有明确声音角色。
- 结尾约 0.5 秒 `silence`，音乐与音效静音，保留画面问题。
- 自制 CC0 合成优先；第三方实录必须有作者、许可与直链留证；最终混音通过 −14 LUFS / ≤−1 dBTP 验收。
- 按契约显式声明 `music` 的增益、循环与淡化字段；若 prepare 把“只有音床、没有旁白”按采样数派生总帧，必须仍得到 900 帧。

### 7. 评审风险与门

- `core-event`：页岩油钻头转向与压裂、商业航天升空→返回→落地、AI 的 GPU→模型→Agent、时间轴跨幕连续性。完整动态窗口，静帧不能替代。
- `static-expression`：7 个世界各自的目标关键帧与盲看；实际 G4 核心窗同轮对照。
- `structure-timing`：30 秒密度、每站 2 秒阅读窗口、开场 3 秒问题、收尾两行；用 animatic/加密帧验证。
- 默认核心轮 1 次 + 终审 1 次；若声明 `split-final` 则终审 2 人。G5 为制作助手内部检查。
- 独立评审不可用时披露角色分离自审与限制，不能据此关闭评审项或宣称完成。

### 8. 范围边界

- 不修改 general 共享行为，不新增 glTF/HDR 导入、不新增视频类型、不新增风格包、不改 `article-explainer` 固定示例。
- 若试制证明必须扩展共享能力，先停止并补新 OpenSpec 变更，不在本变更内顺手扩引擎。
- 作品内容、素材、场景源码与证据留在忽略目录；共享代码/文档变化才入库。

## Risks / Trade-offs

- [3 秒一站信息过密] → 每站一个事件、一句结论；火箭段给 4.5 秒；必要时删动作而不是加速。
- [真实材质依赖不可得素材] → 实拍/预渲染优先，程序化兜底；改变关键目标后重新盲审。
- [3D 模型无法导入] → 不承诺真实车型/火箭；用通用物体或预渲染视频，避免引擎扩展。
- [时间轴年份误读] → 等距站点 + 年代带 + 明确“产业节点”表述 + `SOURCES.md`。
- [品牌/许可风险] → 通用物体、无 Logo、图库/代码示意标注、来源留证。
- [评审成本高于 30 秒制作] → 先做四个风险样片，未通过不扩展全片。
- [30 秒总长被音床采样数改写] → 音床精确 30.000 秒，prepare 后核对派生帧数仍为 900，不为凑长度截断声音。

## Migration Plan

无共享契约迁移。apply 按“事实与作品准备 → 关键帧/样片与核心风险 → 三幕实现与声音 → 全片粗片与 G5 → G6 终审与交付 → 归档”推进。全部任务完成、验证与提交通过后才归档；本轮不归档。
