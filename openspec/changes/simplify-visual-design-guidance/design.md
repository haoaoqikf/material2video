## Context

动机见 proposal.md。现有路由校验将“视觉审美”列为必需规则归属，多份阶段、评审、来源指南和示例链接到待删除文件；现行规格也保留固定拆解配额与重复创作表单。需要同时处理文档、导航与规格，避免删文件后仍隐式执行旧义务。

## Goals / Non-Goals

- 灵感、可选方法、技术契约与验收职责分离；减少实际阅读与填写负担，不整篇搬迁被删除内容。
- 不改变作品字段、CLI、视频类型、运行时、风险枚举、独立评审人数及证据有效性；不修改媒体，不倒填历史评审。

## Decisions

1. 灵感采用用户原文，作为 material2video 的普通参考页而非 skill。入口可选，路由不将其列为规则权威；不使用更名后的视觉设计 skill 继续执行旧流程。
2. DESIGN.md 的最简结构只维护在 stage-plan；执行帧和参数引用现有分镜/代码，复杂风险才补附件。删除四份独立指南及旧视觉 skill，活动引用直接指向当前权威位置，不留空壳重定向页。
3. 参考分析只按用户任务记录来源、要求/采用特征、落点和必要对照。允许只借外观，取消固定规则数、指标、时间窗、风格报告及同族结论。关键采用项继续引用风险计划，不改变盲审隔离或资产许可边界。
4. 讲解与运动适配中的创意方法均可选；保留辉光、相机、字幕区、对象依赖、数据与最终显示尺寸的项目排错知识。评审只核对实际目标、可观察缺陷与适用证据，不检查是否采用某种方法。
5. 阅读路由保持 schemaVersion 1，取消旧条件入口和“视觉审美”归属，同时同步校验器的必需集合。其余结构、预算、路径、锚点、代码围栏和 JSON 检查不变。仅修改文档工具的内部校验，不改变作品契约。
6. 旧 frontend-design 能力通过移除全部要求退役，明确声明 retire_capabilities。其他规格通过差异记录取消创作义务，保留未涉及的技术与验收要求。历史归档不重写；示例只修活动链接和当前导航。

## Risks / Trade-offs

- 创意质量不会因删除规则自动提高 → 用现有实际表达与用户关键目标验证，灵感不承担质量保证。
- 删除文档留下引用或隐性义务 → 检查全部受版本控制的活动文档，扫描旧文件名、锚点及固定步骤；核对新制作、参考、终审三条路径。
- 规格同步重新引入旧规则 → 归档前逐能力核对差异，退役文件不留空 Requirements，修改 Purpose 中的过时描述。
- 示例历史记录使用旧方法名称 → 保留历史事实，只修活动链接，不将历史成片标为重新验证。

## Migration Plan

在本变更中完成文档和工具调整、针对性测试及审查后提交实施。随后同步主规格、核对差异、归档并提交归档结果。无需作品迁移或媒体重制；回退使用本次 Git 提交，不提供旧规则兼容入口。
