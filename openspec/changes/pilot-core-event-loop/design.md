## 设计

### 流程位置

短循环属于现有“粗片验证”阶段，不增加阶段或状态。只有核心表达依赖动态事件，或该事件有未验证的核心风险时才触发。纯静态表达及无实质风险的作品记录不适用原因。

### 执行顺序

1. 选出最能代表核心表达且失败代价最高的一个事件窗口，并记录选择理由及其他未验证核心风险。
2. 制作前声明事件初态、原因、变化、结果、观察窗口、手机显示尺寸、观众应理解的关系、表现目标及失败现象。
3. 制作覆盖初态、关键变化、揭示（适用时）与结果的低成本动态粗样。保留判断所需的主体、比例、运动和观察时间，不扩展其他段落。
4. 评审材料绑定同一候选和完整窗口。评审者先盲看并记录观察，再核对中性条件；材料不含设计理由、预期答案和旧结论。按风险加密时间码帧，不能假设评审端能播放视频。
5. 分别判断理解、表现和证据充分性。都成立才扩展；理解成立而表现不足则按原条件局部修复；理解不成立则回到事件或导演顺序；证据不足或有实质分歧则补证或复核。
6. 同一核心问题两轮无改善后，停止同类微调，匿名比较不同表达机制，必要时换机制。

### 继续条件

只有理解与表现分别达到制作前声明的条件且证据足够，才把该事件作为扩展基准。它不替全片其他段落验收；后续仍执行完整粗片和最终候选审查。

### 记录位置

设计条件与事件选择记录在作品 `DESIGN.md`；阶段观察、问题状态和证据链接沿用 `outputs/visual-notes.md` 与独立评审原始报告。不另建通用表单，不新增 CLI、运行时字段或审美分数。
