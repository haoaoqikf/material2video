## Context

动机见 [proposal.md](proposal.md)。当前 `a2v/remotion.py` 每次在交付临时目录打包，`metadata()` 与 `render_frames()` 各起一个 Node 进程，Node 两次调用 `selectComposition`；`remotion-render.mjs` 固定 `concurrency: 1`。音轨合成已采用视频流复制，因此不将二次视频编码作为优化目标。上述是源码观察，尚无阶段实测，不能据此宣称加速比例。

## Goals / Non-Goals

**Goals:** 测量完整链路；减少重复构建与启动开销；提供主动可调的吞吐能力；默认安全兼容。

**Non-Goals:** 不修改 TTS、字幕、视觉设计或分镜数据结构，不降低交付标准，不自动提高并发，不移除完整解码验收。

## Decisions

1. **先记录基线。** 使用单调时钟分别记录打包、元数据、画面渲染编码、mux、probe 和端到端耗时；结构化报告置于作品输出目录并被 Git 忽略。逐帧渲染与编码在 Remotion 中重叠执行，记录合并耗时，避免相加造成重复计数。
2. **指纹缓存。** 新增独立缓存键，不直接把成片溯源指纹当作完整构建键：现有指纹有意排除全局生成索引，而缓存必须包含生成的场景清单、Tailwind 内容、public 资源及构建工具输入。先按本作品生成清单并执行安全扫描，再计算缓存键。缓存位于被忽略的 `web/.cache/a2v-bundles/`，保存产物清单与摘要，临时构建成功后原子发布；完整性不符即重建。提供 `--no-bundle-cache` 诊断与基准入口。按同键加锁，并串行保护全局 `.gen` 的生成到构建过程，避免切换作品污染缓存；不同作品同时启动时等待，不能混用清单。
3. **显式并发。** Python render CLI/API 向 Node 透传正整数，默认 1。不按 CPU 数自动提高并发，因为历史注释已记录 Windows `Target closed` 风险。报告实际值，用并发 1/2/4 对照给出本机建议；不把本机结果视为所有机器保证。
4. **会话握手。** Node 打开一个浏览器，选择 composition 后输出元数据并等待 stdin 确认；Python 使用既有判定函数校验后发送渲染参数。浏览器传给选择与渲染步骤复用。父进程 EOF、超时或拒绝确认时退出，finally 关闭浏览器；Python 退出时清理子进程树。保留 metadata-only 诊断路径。相较取消元数据检查，该方案保留可信边界。
5. **质量与性能验收。** 三个固定示例均跑 1080×1920、同帧区间至少 90 帧，冷/热缓存各重复 3 次，报告中位数；其中至少一份完整全片并使用可用的本地媒体清单验收音轨，不联网生成配音。热缓存打包阶段目标比冷缓存下降至少 80%，代表作品热缓存端到端目标下降至少 10%，同配置冷路径回退不超过 5%。目标是验收条件，不是已实现承诺；未达到则检查耗时报告并修复或报告未完成，不通过降低画质达标。跨并发先比较未编码截图 PSNR ≥60 dB，再检查编码成片帧数、色彩、音频与关键帧；不同码流不要求逐字节一致。

   实施时的两处测量口径（都由实测数据逼出来，避免把噪声当结论）：

   - **每个示例先跑一次丢弃式预热。** 一组里的第一次测量还含一次性开销（打包器首次缓存、文件缓存、CPU 升频），实测同一配置的端到端中位数因此浮动 ±2 秒，比要判定的差异还大。预热那一跑照实写进报告的 `discarded`，不参与判定。
   - **冷路径回退读「可归因开销」，不读两次端到端中位数之差。** 缓存唯一新增的工作是它自己的准备阶段（键计算、完整性复核、发布），因此回退量取冷缓存运行的 `cache` 阶段中位数 ÷ 基线总耗时中位数；同时把端到端差值与观测带宽一并写进报告，谁想按总耗时复核都能看到。两个数一起看，才能区分「缓存确实多花了时间」与「这次渲染本来就慢」。

## Risks / Trade-offs

- 缓存遗漏资源 → 单独验证代码导入、外置内容根、字体、public 与生成 CSS 的失效路径。
- 产物完整性检查自身耗时 → 计入缓存准备阶段，与重打包对比；缓存数量有限，最初不做复杂淘汰策略，可手动清理缓存根。
- 高并发内存峰值 → 默认 1，显式配置，记录基准期间进程树峰值内存与失败情况。
- 会话等待或浏览器泄漏 → 等待超时独立于日志读取，覆盖静默进程、EOF、校验失败和取消测试。
- 正式制作门禁干扰基准 → 使用内部渲染 API 做固定基准，并另行验证正式 CLI 门禁不被绕过；实测数据注明入口。

## Migration Plan

先基线，再性能报告、缓存、并发和会话复用，逐步测试。旧命令默认行为兼容；回退可禁用缓存并使用并发 1，必要时回退本次实现提交。完成验证与实现提交后按项目规则归档并提交主规格同步。
