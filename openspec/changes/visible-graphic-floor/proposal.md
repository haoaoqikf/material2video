# 提案：承重的描边要有 3:1

## Why

上一轮把图形颜色分了四类并给了对比度预算，但预算里最低那一档（装饰描边 ≥ 1.5:1）
留了一个洞：**一条承载意义的线可以躲在「装饰」这个类里**。逐帧看 `opening` 一幕的
天平时才看见后果——`.scale-rope`（吊着两个秤盘的绳）被归成装饰描边，
深色下只有 1.63:1，画面上横梁像是浮在空中。

同时量测发现设计语言里已经有一个 `--a2v-hairline-strong`，**定义了却一处都没用**：
需要「界定一个物体的边界」的地方（`.drop-track` 的竖尺槽）用的是
`--a2v-hairline`（深色 1.64:1），那是给「纯装饰分隔」准备的。

WCAG 1.4.11 对非文本图形的下限是 **3:1**，管的是「理解内容所必需的图形对象」。
纯装饰的分隔线本来就在豁免范围内，所以问题不在于「所有线都要 3:1」，
而在于**我们把承载意义的线也当成了装饰**。

### 为什么现在才发现

- 上一轮的分类表按**取值**分档（细的归装饰），而不是按**它在图里承担什么**分；
- `--a2v-hairline-strong` 存在于令牌表里，但没有任何检查问「它被用上了吗」——
  测试查的是「令牌有定义」，不是「定义的令牌有人用」；
- 描边的视觉重量看起来可疑，所以先量了再说：实测所有 SVG 描边的
  `getScreenCTM` 缩放比**都是 1**，声明的 4px 就是 4px。
  于是「viewBox 缩放把 4px 变成头发丝」这个猜想被证伪，问题定位到**对比度**上。

## What Changes

- 新增一类 **边界描边 ≥ 3:1**（判据基座是它落座的面 `--a2v-bg-2`），
  首个成员 `--a2v-hairline-strong`；把它的取值调到真的够 3:1
  （深色 `rgba(255,255,255,0.36)`、浅色 `rgba(12,14,19,0.45)`；
  原来的深色 0.30 实测只有 2.49:1，注释里写的 2.99:1 与实测不符）；
- `.drop-track` 的边框改用 `var(--a2v-hairline-strong, var(--a2v-hairline))`：
  它的填充是耳语级的一层白，边框是它唯一能被看见的边界；
- `.scale-rope` 按用途重新归类为**结构描边**（`--fig-line-data`）：
  它是吊着秤盘的东西，不是装饰；
- 明确写下**豁免**：`--a2v-hairline`（1.64:1）继续用于纯分隔，
  卡片/面板的边框也留在这一档——卡片的身份由填充、圆角与投影共同界定，
  把每一条分隔线都提到 3:1 只会让画面变重，正是 K2 早期那类误判的反面；
- 测试补一条：**已定义的承重描边令牌必须真的被用上**（防止再出现
  「定义了却没人用」的令牌），以及一条显式断言「分隔线保持耳语」。
