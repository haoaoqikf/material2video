# 设计决策

## 决策 1：按「这条线在图里承担什么」分类，不按取值分类

**背景**：上一轮的分类把细线归成装饰描边，`.scale-rope` 因此拿到了 1.5:1 的预算。
逐帧看下来，横梁像浮在空中——绳子是吊着秤盘的东西。

**选择**：判据跟着职责走。承载结构或数据的线拿 4.5:1（数据描边），
**界定物体边界**的线拿 3:1（边界描边），纯分隔线留在耳语档（豁免）。

**理由**：按取值分类会让规则自证——「因为它是细的，所以它是装饰」。
按职责分类才能问出正确的问题：「这条线消失了，观众还看得懂这张图吗？」
`.scale-rope` 消失后秤盘与横梁断了关系，所以它是结构。

## 决策 2：3:1 的判据基座是「它落座的面」，不是画布

**背景**：`.drop-track` 在面板内部，它的边框压在 `--a2v-bg-2` 这一层上。

**选择**：边界描边的对比度对 `--a2v-bg-2` 判定；数据描边与图形内文本仍对
`--a2v-bg-0` 判定。

**理由**：同一个颜色在不同基座上的比值不同（深色 `--a2v-hairline` 对画布 1.52:1、
对抬升面 1.64:1）。基座写进分类表，规则才没有解释空间；
拿画布去量一个压在面板上的边框，会得到一个乐观的数字。

## 决策 3：不一刀切提高所有分隔线

**背景**：最省事的做法是把 `--a2v-hairline` 直接提到 3:1，全局生效。

**选择**：不这么做。`--a2v-hairline` 保持 1.64:1 并写明它是**有意的**分隔线，
豁免于 WCAG 1.4.11（那条管的是「理解内容所必需的图形对象」）；
卡片的边框也留在这一档。

**理由**：卡片的身份由**填充 + 圆角 + 投影**共同界定，边框只是辅助；
把所有分隔线提到 3:1，画面会整体变重、层次变平——这正是 K2 早期
「强调色占比低就判失败」的同类错误：**规则惩罚了正确的做法**。
真正要抬的是「边界是它唯一身份来源」的那些线，`.drop-track` 是典型：
它的填充只有 0.03 白，边框一淡，这根竖尺就没了。

## 决策 4：补一条「已定义的承重令牌必须被用上」的检查

**背景**：`--a2v-hairline-strong` 定义了却一处都没用，注释里的实测值
（2.99:1）与真实测量（2.49:1）也不符——两件事都没人发现。

**选择**：测试断言「边界描边令牌至少被一个边界声明引用」，并断言它真的过 3:1。

**理由**：令牌表最容易的腐烂方式不是取值错，而是**没人用**：
它看起来像一套体系的一部分，实际上没有承担任何东西。
这和「排版引擎全绿但空转」是同一类静默失效，只是发生在 CSS 层。
