## ADDED Requirements

### Requirement: 核心表达检查必须具有结构化完成凭据

新启动 general 合同 MUST 声明 acceptanceChecks=true；已有在制合同缺省时 MUST NOT 追溯补项。启用后 G4 核心/A 检查点 MUST 有独立盲审的 visual-event 凭据，记录当前完整检查窗、实际观察与有效证据；G6 MUST 有全部核心检查点的 design-fulfillment 对照凭据，覆盖构图尺度、空间层级、冲击力、注意力和时间兑现及导演条件、关键帧、动画三方证据。对照 MUST 在同一检查的独立盲审落盘后单独导入，不计审美通过。缺项或证据不足 MUST 保持待评审，失败 MUST 阻断制作完成。机器 MUST 仅检查记录完整性、覆盖和绑定，不代替独立判断，不改变技术导出门禁。

#### Scenario: 通用通过报告未含视觉事件凭据
- **WHEN** 已启用合同的核心检查点只有普通通过报告和独立通过结论
- **THEN** G4 仍待评审并列出缺失项目，不能报告制作完成

#### Scenario: 终审未完成设计兑现对照
- **WHEN** 当前 G6 两类盲审已通过但缺少任一核心检查点的五维对照或三方证据
- **THEN** 该门保持待评审，旧版在制合同不新增此要求

### Requirement: 检查点采样必须包含关键状态边界

G4 MUST 在既有步长与指定帧之外，自动采样检查窗内文字计划、状态计划和时间结构每个边界的前一帧、边界帧和后一帧，去重并裁剪至合法半开窗。可选 statePlan MUST 按场景局部、位于所属镜头内的窗口声明对象状态断言并在匹配采样帧核对；同一状态计划角色的窗口 MUST NOT 重叠。关键过程缺证 MUST 保持未验证；边界覆盖 MUST NOT 被声称为全部连续运动已验证。

#### Scenario: 短暂文字状态落在步长之间
- **WHEN** 步长采样跳过仅一帧显示的文字计划
- **THEN** 自动加入出现和离开边界帧，能检查该文字是否按计划出现并消失

#### Scenario: 状态计划中间错数
- **WHEN** 结果指定帧正确，但中间状态计划的采样帧对象数错误
- **THEN** 检查点失败，不以端点正确放行

### Requirement: 证据有效性必须独立于前置门就绪状态

制作状态 MUST 分列本门证据/评审结果、未满足前置门与就绪状态。仅依赖摘要变化、文件缺失或证据失配才可使自身证据过期；上游门未完成但本门结果有效时 MUST 显示等待前置并保留自身结果。全部门满足前不得报告制作完成；查询 MUST 保持只读，B/C 批量回绑路径不得循环等待。

#### Scenario: G1 有效但 G0 未完成
- **WHEN** 合同检查和证据有效，输入审查尚未完成
- **THEN** G1 显示等待前置，自身结果仍通过，列出 G0，不要求重做合同检查

#### Scenario: 合同真实变化
- **WHEN** 检查范围的合同摘要改变
- **THEN** 对应旧证据显示过期，不能仅靠补齐前置门恢复通过
