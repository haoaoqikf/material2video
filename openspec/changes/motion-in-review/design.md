# 设计：验收里的动效量测

## 决策 1：一份实现，两处调用

扫描既要在测试里跑（严格判定 + 反例），又要在验收里跑（任意作品）。
两份实现必然漂移，所以实现放 `a2v/motion.py`，测试改成调用它——
测试里只留「参考实现上的严格判定」这一层：覆盖度必须真的覆盖到每一幕、
以及一个把入场加速 8 倍的反例。

`page.evaluate` 原本不接受参数（验收里的探针脚本都自己从 DOM 取数）。
扫描要逐幕传参数（第几幕、起始全局帧、帧数），所以给
`AnimatedPage.evaluate` 加了一个可选参数位，`None` 时行为不变。

## 决策 2：闸门只提示，不改退出码

C 系列回答「是不是废片」，K 系列回答「够不够发布会级」，M 系列回答「动作对不对」。
三栏分开报，不揉成一个分。

M 系列默认不拦人，与 K 系列同性质：入场快一点、慢一点是判断问题，
不是「画面坏了」。项目里唯一被提为硬判定的是文字溢出（K7），理由是
「有人会看到被裁掉的半行字」——那一条是确定的损坏，动效不是。

严格判定留在测试里：参考实现上的阈值一破就红。

## 决策 3：只扫「内容入场」，不扫装饰的明暗

第一版把「从透明开始但在采样窗口内没走到不透明」一律当成漏测，结果在参考实现上
一次点名 11 个元素：光晕、火花、引号、注脚——它们是**刻意停在部分不透明度**的
装饰。这里要判的是内容入场的快慢与落地，不是「光晕什么时候亮」。

所以「截断」只报一个很窄的情形：**单调上升到采样上限、却还没接近不透明**。
三个条件缺一不可：

- 单调上升——脉动的装饰会自己回退，本来就不落地；
- 到上限时仍 < 0.95——已经落地的不进来；
- 最后一帧还在上升——停在部分不透明度的装饰会自己停下来。

这样既不会把刻意做法判成缺陷，又不会把「轨迹不完整」静默丢掉。
丢掉是最坏的：闸门全过，而人以为自己量过了。

## 决策 4：跳过要给理由

分镜没有场景、或场景没有声明帧数时，`motion` 段落如实写 `enabled: false` 与原因
（终端也照实打印「不适用——…」），而不是静默返回空结果。
一个安静跳过的检查和一个通过的检查在报告里长得一模一样，这是要避免的。

## 已知边界

- 扫描逐帧走遍全片，量的是「元素状态序列」；它不判断动效好不好看，
  也无法判断「这个入场该不该有」。
- 位移的精确判据（过冲、末尾必须正好为 0）仍只在测试的单元素用例里。
- 采样上限 60 次变化：超长入场会被截断，此时报 M0 提醒，但那条入场不进判据。
