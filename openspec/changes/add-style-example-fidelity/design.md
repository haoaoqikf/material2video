## Context

动机与量化差距见 proposal.md。`styles/examples/` 的两个示例已合入并被登记为「风格示例」，但仓库内约束它们的只有「可校验、可渲染、与包分离」三条技术条件（`vibe-fable-style` 的三个 Requirement），没有任何一条要求它们看起来像参考片。`vibe-night-style` 有八项指标条款，但作用域是 `videos/` 下的原创试制，不是 `styles/examples/`。

同时，参考样片的核心表达手段在本仓库没有对应原语：`fold_C/film.js:38-45` 的 `camAt(t)` 是一台在**对数空间**连续缩放、焦点随镜头高度平移的摄影机，33 秒里 0 硬切。本仓库的 `Painter` 只提供 `group({at, rotate, scale})`，各场景自行把几何换算到屏幕坐标，于是「连续推拉」在实践中退化成了「每幕一套固定几何」。

## Goals / Non-Goals

目标：

- 让「风格示例的还原度」成为可判定、可复核的验收项，而不是披露风险。
- 给二维绘制层一个确定性的相机原语，使示例能用固定世界坐标 + 一台摄影机表达连续推拉。
- 按证据修复两个示例：主体有质量、氛围不被自身管线吃掉、声画同步、每幕有景别变化。

非目标：

- 不新增视频类型、CLI 命令、分镜字段或风格包清单字段。
- 不复制参考的 `engine/`、`film.js`、GIF/JPG、角色与文案。
- 不设机器审美门禁（不规定「饱和度必须 ≥ x%」），只要求过程完备。
- 不为两个示例补造核心样片、粗片与终审记录——它们仍是风格示例，不是交付作品。

## Decisions

### 1. 验收硬度取「过程完备」，不取数值门禁

八项指标在本仓库的定位是**证据格式**，不是通过阈值（`reference-style.md` 只说「不写数值与差值视为契约未完成」）。给风格示例设定数值下限会把「题材不同导致的高度差异」误判为失败——`olbers-night` 的 `style-reference.md` 里已经出现过这类例外说明。因此 Requirement 只要求：八项指标的参考值/实际值/差值齐全、并排基准存在、独立冷审存在且回应「是否同一部片的视觉系统」；不强求冷审判「同族」。

### 2. 相机做成 `painter` 的纯函数导出，不做组件

`cameraAt(keys, progress)` 只做一件事：把关键帧表与进度求成 `{scale, focusX, focusY}`。它不持有状态、不读挂钟、不认识 React，因此可以像 `primitives.ts` 那样被逐帧录制、跳帧采样与重录共用同一份求值。做成组件会把它绑进 React 生命周期，与「不读挂钟」的约束产生不必要耦合。

`scale` 在**对数空间**插值：视觉上等速的推拉对应几何级数，线性插值会在近景端显得突进。焦点按 `1/scale` 加权插值，使推近时焦点更快贴到目标对象上——这两点直接对齐参考 `film.js:40-45`。

### 3. fold 用一条贯穿九幕的相机表，而非每幕一张

参考片的价值在「同一个东西在不同尺度上」，不是九个机位。实现上定义一份覆盖全片的 `CAM` 关键帧表（时间 → scale/focus），每一幕只是这张表的一段。世界坐标固定（珠间距 31.5、细胞半径、团半径），屏幕位置 = 世界坐标 × 当前 scale + 焦点平移。这样「第 3 镜与第 8 镜是同一个画面」这句话在代码里成立，而不是靠人肉对齐两套几何。

### 4. 六个景别用同一份相机表表达，幕内插值、幕间不硬切

pigeon 的参考是六个不同景别（全景 / 计时器特写 / 中景 / 近景 / 慢推 / 计时器前置）。当前示例除 `inside` 布尔值外每幕画面完全相同。做法是在场景内维护一张按幕的镜头表（scale + 平移），每幕在自己的帧区间内做缓动；跨幕处保持镜头不跳，靠字幕与动作转折。

### 5. 声音走既有 `soundtrack.effects`，不新增场景内 sfx API

参考是声画一体的（数珠子 tick、翻转 tock、食物落下 thud）。核实后确认仓库**已有**无旁白音效通路：`soundtrack.py:19-58` 校验 `effects`，`sound_library.py` + `sound_synthesis.py` 提供 12 种确定性拟音，`videos/general/olbers-night`（7 个 effects）与 `embarrassment-night`（21 个）都是无旁白作品。缺的是示例没写 `soundtrack`，不是能力。

在场景源码里按帧触发音效是另一件事：它会把音频事件绑到画面代码，破坏「音频由 prepare 编排」的现有分层。本轮不做，若将来确有必要应单独评估。

### 6. 亮度问题在场景侧修，不改合成管线

pigeon 实测米墙 253.7、fold 底色中位 1.2，两者都是**场景自己的绘制**造成的（`P.clear('#010104')` 覆盖了 `NightBackdrop` 的光池；`#EFE2C4` + bloom + `overlay` 颗粒把米色推爆），不是 `compose()` 的缺陷。修改共享合成器会影响所有既有作品，收益不足以承担回归风险。因此只调场景内的底色与层序，`compose()` 不动。

## Risks / Trade-offs

- **相机原语引入新的共享面**：`painter` 是已被其它作品使用的模块。风险是中性的——新增导出不改变既有 API，`camera.test.ts` 覆盖确定性与端点精度；但仍须跑既有 `painter.test.ts` 与作品回归。
- **修完仍可能不像参考片**：「过程完备」的验收意味着不达数值也可能通过。这是有意的取舍：要求数值达标会逼出「为指标而画」的作弊，而这套指标本来就是描述性的。风险由冷审回应「是否同一部片的视觉系统」兜底。
- **示例体积与渲染成本上升**：fold 的珠子从 5.4px 点改为渐变球体、pigeon 的鸽子从 11 点轮廓改为 10 余层色块，逐帧绘制变慢。若 lookdev 与 render 明显变慢，需在场景内做缓存（例如把静态色块预渲染到离屏画布）。这不是阻塞项，但要观察。
- **不复制参考画面的边界仍然有效**：相机表、形体画法与音效点是从参考的**机制**推导的，不是移植代码。示例 README 与 `style-reference.md` 须继续写明「不复制上游 `film.js`、GIF/JPG 或画面」。

## Migration Plan

1. 先建本变更的规格 delta 与任务。
2. 实现共享相机原语与测试。
3. 按证据修复 fold 与 pigeon，边改边用同一套量测复核。
4. 补 `soundtrack.effects`。
5. 产出 `style-reference.md`、并排图与独立冷审。
6. 验证、归档、提交。

无兼容性影响：不改变任何既有契约字段；未选择风格的既有作品、`examples/` 三个固定示例与金融/住宅类型行为不变。

## Open Questions

- 参考片底部的中英双语字幕行（中文 + Lora 斜体英文）是否要还原？项目「画面注释从紧」与「装饰英文从紧」倾向于不加；但英文行在参考里承担节奏功能。本轮**不加**，保留中文单行；若冷审认为这构成「不是同一部片」，再单独评估。
- 两个示例的 `outputs/` 不入库，`style-reference.md` 也不入库。这意味着还原度证据只存在于本机。这是与 `videos/` 一致的既有规则，不在本变更调整。
