## Context

现状及动机见 proposal.md。代码已有摘要、调用隔离、窗口和核心三维判断校验；文档由 sync_docs.py 生成类型与审核表。共享入口过长，专项文档混有执行规则、模板、案例及排错。

## Goals / Non-Goals

目标是默认只读短入口与当前阶段指南，适用专项必须展开；动态证据有效性同时约束新导入与历史证据的当前状态。
不改变画面、审核人数、材料和报告字段，也不判断 AI 是否真实阅读或画面是否有美感。

## Decisions

- 阅读路由使用 JSON，沿用标准库，不新增 YAML 依赖。登记类型分流、任务、四阶段唯一主指南、条件参考及规则归属。
- 字符预算去 frontmatter 与 generated 标记区域后按 Python len 计，统一 LF；入口2000、阶段3000、两者5000。检查器集成 sync_docs.py --check；规则迁移用可核验文本摘要和位置记录，独立审查语义保全。
- 旧文档保留规则，模板/演练/排错按区间原文迁移到相邻参考文件；全仓库维护活动文档引用，已归档历史保持原样并在原入口留转介。
- 媒体校验放 production 专用小模块；用依赖内自带的 ffmpeg 以显式参数数组解码视频流读出长度，带超时与具体诊断；同次操作缓存成功和失败，不跨查询缓存。只映射 `0:v:0` 并读取视频流进度，不使用音轨较长的容器时长冒充视频长度，也不新增系统 ffprobe 安装前提。
- acceptance 导入与 ledger 当前状态共用校验函数，坏证据保持缺少有效评审且完成为 false；视频生成不依赖新增约束。静态项不探测视频。

## Risks / Trade-offs

- 摘要变短丢规则 → 逐段迁移记录、链接与独立审查，条件触发不降低规则效力。
- 时长被误认为窗口内容正确 → 明确最低容量只证明可探测与长度，实际内容仍独立判断。
- 状态查询多次探测 → 单次操作只探测每个真实路径一次，失败同样缓存，测试探测次数。
- 视频不可解码或流时长不明 → 输出文件与检查点诊断，证据不能支持完成，不修改历史或阻止候选生成。

## Migration Plan

新制作从路由开始；存量材料不迁移，历史报告只在当前有效性判断中重验。实施验证提交后同步主规格并自动归档；回退本次提交即可恢复指导和证据策略。
