## Context

动机见 proposal.md。五个示例目前与所属风格分离，风格加载器递归哈希所有包文件，构建器用目录包含关系判断作品与风格身份。用户已授权实施此前研究方案；本变更独立于蛋白质视频制作。

## Goals / Non-Goals

目标：统一 styles/<style>/examples/<slug>/ 布局，保持规范示例数量、作品功能、媒体恢复与安全隔离，示例内容不影响风格依赖。

不做：新风格、清单字段、成片重制、旧路径兼容、历史审核补造或其他类型契约调整。

## Decisions

1. 保留 examples/<slug> 层。与直接平铺单个 example 相比，作品名称清楚且共享实现和作品边界明确。以 styles/README.md 为唯一总索引，合并原 examples/README.md 的用途。
2. 风格哈希遍历在直属 examples 入口剪枝，避免读取大媒体及生成缓存；其余文件继续全覆盖。清单路径拒绝 examples 子树，真实路径检查继续阻止符号链接越界。排除子树不能成为共享实现隐藏依赖的入口。
3. 构建器将真实路径位于直属 examples 下的源码排除出风格身份。作品相对导入仅限自身，共享实现相对导入限共享包且禁止 examples 子树；风格组件仅能通过现有登记别名接入。保留资产登记和现有依赖白名单规则。
4. 五个示例连同本地忽略产物整体移动，不覆盖已有目标；移动前核验绝对路径均位于工作区。当前源码和文档按新路径调整，归档及不可变历史证据不批量改写。目录层数不变，指向仓库根的相对路径原则上不变，指向风格的链接需重新计算。
5. 改名不保留别名。更新固定测试清单、glob、媒体/声音/候选稿忽略与所有当前调用，历史生成记录不重绑为新路径有效证据；重新校验和 prepare，验证五份实际场景能构建。

## Risks / Trade-offs

- 哈希排除造成漏依赖：清单和构建器同时拒绝共享代码依赖示例，增加双向边界与哈希稳定性测试。
- 恢复媒体误入库：新路径 ignore 规则与 git check-ignore 验证，提交前检查二进制与生成物。
- 路径改动遗漏：检查当前引用、文档相对链接、固定示例集合，跑相关及全量非慢测试、前端类型检查与测试、五示例准备和构建。
- 历史绝对路径及摘要不可迁移：保留历史证据原貌，不宣称旧审核仍有效；内容和输出不重渲染、不改写历史摘要。

## Migration Plan

先建规划，再修改隔离与哈希、整体移动示例、同步引用、验证并提交。完成后同步主规格并自动归档和提交。回退通过 Git 还原源码布局，本地忽略产物按实际目录整体移回，禁止覆盖目标或删除素材。
