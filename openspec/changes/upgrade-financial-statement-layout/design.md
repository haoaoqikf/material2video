## Context

金融时间序列的当前构图是「标题 + 浮空市值 + 折线」：市值固定在右上 y=400/438，曲线在 y=500～1280，二者没有几何关系；标题、条件句、市值和日期共用一套无衬线字阶；`profile` 只改背景光晕色。Frontend Design 的判断是这属于近黑底 + 单一高饱和强调色的通用默认，题材没有进入设计；Motion Design 的判断是开场以透明度为主、缺少位置与尺度变化，数据自身的节奏没有被编排。

本次按用户选定的「深色对账单」方向重构画面层，不改投资计算、日期映射、材料 schema 或 v8 计划。只重新生成苹果作品；其他金融作品的既有成片和材料保持不动。

## Goals / Non-Goals

**Goals:**

- 把画面组织成一张持仓对账单：标题区、分隔线、余额曲线、收束区账目、底部口径。
- 让当前市值与曲线末端产生结构关系：金额不再浮在右上，而是成为图表下方的期末余额。
- 用暖近黑、细规则线、等宽数字建立金融题材的视觉身份；`profile` 真正决定分隔线色。
- 开场形成一次可观察的编排，重要入场同时改变透明度与位置；推进段继续由数据驱动。
- 保持手机 360×640 可读、红涨绿跌语义、无面积填充、结尾冻结和现有自动验收门禁。

**Non-Goals:**

- 不新增材料字段、计划版本、CLI 命令或视频类型。
- 不改变价格口径、投资计算、交易日验证、节奏锚点或横纵轴映射。
- 不加入事件、K 线、收益金额、收益率、面积填充、卡片底板、注释文字或电影化运镜。
- 不重新生成其他金融作品；不改动它们的材料与既有产物。
- 不把分隔线或 accent 引入数据层。

## Decisions

### 1. 收束区取代右上浮空市值

图表下方新增收束区：一条 1px 分隔线起头，左列是本金（28px）与投资起点（20px），右列是「当前市值」标签（20px）、hero 金额（72/64/56px）和最近实际收盘日期（24px）。这样金额与曲线共用同一阅读顺序：先看走势，再看期末余额；同时释放标题右侧的空白，避免数字与曲线各自为政。

不在绘图区内放金额标签或底板，历史曲线仍完整可见；收束区在绘图区之外，不触发裁剪探针。

### 2. 两条分隔线作为对账单结构

标题上方与收束区上方各一条 1px 分隔线，横跨 x=140～940。它们编码「表头 / 账目 / 期末余额」的结构，不是装饰；因此只保留两条，不再增加第三条或卡片边框。分隔线颜色由 `profile` 决定：`ledger` 暖金、`signal` 冷灰、`archive` 冷青，透明度 16%–22%。用户 `accent` 仍只进入背景，避免把主题色误读为收益色。

### 3. 暖近黑与等宽数字

背景从 `#0A0A0B` 改为暖近黑 `#0B0A09`，径向光晕保留但偏暖；正文改为暖白 `#F1EBDF`。数字统一 `tabular-nums lining-nums`，避免市值、日期和刻度在位数变化时抖动。红 `#FF5A4E`／绿 `#4BD39A`／中性 `#D8D4CC` 不变。

### 4. 开场编排与数据驱动推进

开场仍占 30 帧（1 秒）：0–14 帧画标题分隔线；0–10 帧主体名、5–16 帧条件句以透明度 + 10px 上移入场；9–25 帧图表框/网格淡入；14–28 帧画收束区分隔线；16–30 帧本金账目与市值入场，金额另带 0.985→1 缩放。所有入场在 30 帧内完成，不延长开场或修改计划。

推进段曲线仍是 primary，收束区金额是 secondary，年份标签是 tertiary；金额只随真实收盘值更新，不插值、不滚动。结尾 2 秒全部冻结，端点呼吸在结尾前 15 帧收回。

### 5. 布局键包含动态账目

`contentLayoutKey` 增加 `showValue`、`valueFontSize`、`liveValue`、`liveDate`、本金与起点文本。金额出现或换档时重新计算整体包围盒与 y=960 居中位移，避免收束区高度变化后仍沿用旧偏移。

### 6. 金额与本金账目并排的容量检查

收束区右列可用宽度 = 布局右边界 −（左列最宽行 + 32px 间距）。金额按 72/64/56 档位适配；56px 仍放不下时在 `overlayCopy` 阶段阻断，并指出字段。这样避免金额覆盖本金账目，也避免运行时才发现越界。

## Risks / Trade-offs

- **手机可读性**：金额移到图表下方后，360×640 缩放下仍需保持 56px 档位可辨；用代表帧和 360×640 缩放帧验证，不用源码代替画面。
- **内容高度**：收束区、底部口径和风险提示叠加后可能接近 y=1740；`canvasCenterOffset` 会在超高时阻断。苹果案例预计仍有约 60–80px 余量，但加密作品的长说明需要逐例验证。
- **其他作品**：画面层对所有金融渲染生效；其他作品的既有成片不会变化，但若重新渲染会得到新布局。本次不重新 prepare/render 它们，交付说明中明确这一点。
- **无人工评审**：金融类型使用专用自动验收，不生成人工评审结论；本变更仍用实际帧做内部视觉批评，并按自动门禁验收。
- **profile 语义**：分隔线色由 profile 决定，可能与用户 accent 不同。文档明确 accent 只进背景，避免用户误以为 accent 会改变结构线。
