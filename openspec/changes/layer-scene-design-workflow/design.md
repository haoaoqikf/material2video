## Context

动机见 proposal.md。现有三阶段、原生样品、trial/final 隔离评审和唯一问题记录已可复用；指导文档不进入准备指纹，不能把设计编辑误当成画面变化。

## Goals / Non-Goals

目标是让详细编排指导制作，并保留试制反向修订设计的空间。场景设计属于人读制作依据，当前不渲染；不引入第二套 storyboard、状态机、审美评分或逐场审批。

## Decisions

1. `scene-design.md` 作为分层职责、十二方面、节拍表、简明总设计/场景模板和迭代的唯一操作权威；短阶段指南只写阶段行动并链接。拒绝把完整模板复制到各阶段。
2. 每场复用 storyboard 的 scene.id，文档固定 `design/scenes/<id>.md`。DESIGN.md 的索引文字为 scene.id、链接目标为对应场景文件；同一实现可供多场引用。场景内部用现有镜头/事件标识，不新增执行字段。出口场景维护衔接设计，入口引用接入条件。
3. 分阶段深化：试制只写当前场景，正式展开补齐全片骨架和场景文件，开发前补足本场关键关系；允许未知和假设，但不能将缺证据写成有效基线。精确参数保持分镜/代码单源；只记录适用指标，取消普遍 cut/运动/声音配额。
4. 复用现有 `guidance_docs` 的 Markdown/锚点原语，新增独立技能脚本 `check_scene_design.py --project ... [--scene ...]`。完整检查对照现有分镜 ID、总索引、文件和局部链接；局部模式只检查指定场景和相关索引，试制前未成形的全片不强制补齐。指导检查与 render/prepare/生产完成投影隔离。
5. 外部方案评估：这是本仓库固定 scene.id 与 Markdown 关联，不是通用文档平台。现有 guidance_docs 已有围栏、锚点和安全路径检查；继续复用 Python 标准库，无新直接依赖。引入文档站点/Markdown 框架会增加依赖和第二套标题规则，不能增加目标语义保证。
6. 七部示例把原逐场概述移入各场文档，总设计保留共同语言和索引；原报告保持历史，未验证项明确保留。当前作品以既有纸层正文及其相邻场景建立实际详细文档，按当前代码/媒体取证；本轮只验证流程试点，不宣称成片完成。必要的技术采集和独立观察复用原生/preview/review 入口，不新增通用画面组件。
7. 评审职责和轮次不变。文档只在制作侧；相关原要求、中性可观察特征与实际参考沿现有条件进入对照，理由不进盲包。设计修订引发目标变化时重建相关条件/证据，纯文字清理不触发媒体重编码。

## Risks / Trade-offs

- 文档膨胀 → 总设计只存共同规则；场景继承并写差异；研究/问题/报告只引用；不要求十二个空栏目。
- 形式检查被当成设计通过 → 输出明确只检查对应和路径；场内关系、证据与品质仍须真实观察。
- 既有作品缺文档 → 只补本轮受影响部分，不补造历史；七例作当前结构示范，旧证据不自动升级。
- 试点渲染昂贵 → 优先复用当前有效媒体/来源，必要时只采集相关完整窗口，记录实际收益和未覆盖范围。

## Migration Plan

先更新指南、模板、检查和七例，再在当前作品试点并根据真实反馈精简。运行相关节点、独立审核、检查暂存后提交；主规格合并并归档后另提交归档。保留现有历史材料和失败；无运行时版本迁移。
