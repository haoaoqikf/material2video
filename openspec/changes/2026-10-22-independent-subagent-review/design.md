## 背景

现有流程把「独立」理解为角色与判断顺序分离，允许同一助手先观察后对照。这在有严格证据纪律时仍有价值，但它无法阻止作者把已知设计意图带进观察。用户明确要求 A/B 级评审都由子代理执行，因此需要把执行方式、输入隔离和失败披露写成可核对的条件。

## 决策

### 1. A/B 两级都强制，不分先后

A 级是判断与否决（冷观众、复述、候选淘汰、美术方向、同族、逐场观察、两次导演审查），B 级是事实与量取（传播反面依据、可见文案、手机可读性、节奏、八项指标）。两者都容易受作者预期影响，所以执行方式一致；区别只在未通过时的后果。

### 2. 用「独立子代理」而不是「独立上下文」

「独立上下文」可以指新建子代理，也可以指同一助手切换角色，无法核对。统一改为三种可记录的执行方式：独立子代理、外部评审、角色分离自审（仅降级）。

### 3. 评审包采用允许清单

被评审对象可以进包，设计论证与预期答案不能进包。这样评审者看到的是作品，不是作者的意图。禁止项与 `excluded` 字段写入 manifest，评审前逐项做污染检查。

### 4. 候选必须匿名与随机

命名会泄露偏好：方案一、最终版、推荐版都会影响判断。候选标为 A/B/C 或组 1/组 2，顺序随机；映射 key 放在包外，评审完成后才可打开。

### 5. 先描述后判定

报告分两段：第一段只写看到什么（主体尺度、光源、密度、文字层级、事件），第二段才写结论。只有结论、没有观察的报告视为未完成；先判定后补观察视为无效。

### 6. 降级不阻断，但不等于通过

环境没有独立子代理时允许降级为角色分离自审，制作可以继续并交付；但该评审项只能记「未独立评审（降级）」，不计入已解决，必须写入覆盖限制。能力恢复后重新评审，旧记录保留。

### 7. 记录放在 `visual-notes.md`，不改 `qa.json`

`qa.json` 每次运行整体重写，且其 SHA-256 被写入成片溯源；把复核身份写进去会被覆盖并破坏摘要一致性。`observation.record` 已指向 `visual-notes.md`，因此新增统一的「独立评审记录」区块即可，不需要改代码或 schema。

### 8. 不新增自动审美门禁

评审结论仍是文字证据，不设分数、阈值或 CLI 通过字段。文档无法从技术上绝对证明子代理被调用，只能要求记录调用方式、投喂文件与隔离条件；无法证明时按降级处理。

## 风险与取舍

| 风险 | 取舍 |
| --- | --- |
| 有记录没派代理 | 要求记录执行方式、投喂文件清单、评审包摘要与报告摘要；缺项只能记自审 |
| 评审包被污染 | 允许清单 + manifest 禁止声明 + 污染检查；发现即重打包、旧评审作废 |
| 成本上升 | 只在 A/B 级节点派；B 级共享证据可合并；按 manifest 摘要复用 |
| 流程过度阻塞 | 降级可继续制作与交付，但不得声称通过；质量结论如实降低 |
| 子代理意见冲突 | 增加一次独立评审或按证据裁决，不搞多数投票 |
| 与历史规格冲突 | 新 delta 明确取代「不要求新增代理」；归档历史不改 |

## 未纳入

- 不新增 `m2v review` 的子代理调用参数。
- 不把评审包纳入清理白名单；仍由 `visual-notes.md` 的直接链接决定保留。
- 不为历史作品补做评审。
