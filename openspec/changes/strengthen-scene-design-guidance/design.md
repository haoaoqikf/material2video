## Context

动机见 proposal.md。入口与阶段指南有正文预算；场景指南没有必要压缩为栏目清单。当前结构检查只认证文件和链接，运行工程使用作品本地源码与依赖。

## Goals / Non-Goals

**Goals:** 用具体决策、关键状态和实际结果回写连接五维灵感与实现；归并指导且保留有效约束。

**Non-Goals:** 不修改作品或媒体，不改变技术/独立评审门禁，不引入模板字数、语义评分或新依赖。

## Decisions

1. 深度按机制触发，保留十二方面但不要求逐项填表。采用三组充分/不足教学演练，不使用统一篇幅或固定三行节拍，以支持不同类型和静态表达。
2. 场景记录把观察预期与实际结果分开，复用现有问题记录与报告，不新增状态字段。缺少核心关系时继续设计，静态通过不扩大为动态通过。
3. 讲解手法归场景指南，形象/取景诊断归视觉复核，实现排错归运行契约；外部项目的固定来源落到两部示例。令牌值和分类留在源码/测试，技术边界归运行和字幕契约，删除旧独立参考而非留跳转壳。
4. 阶段页只给关键动作和路由；重复的选案、返工、独立评审条件分别引用唯一权威，维持现有正文预算。
5. 修改技术示例为独立工程相对导入，核对递归依赖和资源恢复；只修说明，不改运行实现。

## Risks / Trade-offs

- 指南变长影响阅读 → 清晰分节，按当前机制定位，入口保持短。
- 删除参考遗漏技术约束或来源 → 删除前逐项迁移，检查 Git 活动引用和七部示例。
- 文字加深被误认为效果提高 → 教学与推演明确不是渲染证据，不声明作品或审美通过。
- 大范围测试拖慢文档任务 → 只运行导航与场景结构相关测试和只读一致性检查。

## Migration Plan

先补齐指南和有效内容归宿，再修活动引用并删除旧页。文档、导航和示例结构检查通过后提交实施，随后同步主规格并归档。需要回滚时通过 Git 恢复提交，不改历史媒体。
