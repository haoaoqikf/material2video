## Context

参见 `proposal.md`。当前 `storyboard.json` 是内容与时长真源，`data.figure.kind` 选择七个组件，`data.figure.motion` 使用具名节奏。组件由 `figures.js` 注册，Python 侧 `catalog.py` 保存校验镜像；页面通过 `data-a2v-figure` 挂载，并承担场景骨架与默认映射。现有 `render.py`、`preview.py` 以视频目录的 `index.html` 为入口，网页与脚本共享帧驱动契约。

## Goals / Non-Goals

**Goals:**

- 让新作品以文章和分镜作为源文件，通过共享页面完成预览与导出。
- 让 AI 只选择经过登记的组件、布局、主题和动效，浏览器内部实现仍由项目维护。
- 维持旧网页路径，避免为了采用新方式而批量迁移现有作品。

**Non-Goals:**

- 不把自由编写的 HTML/CSS/JS、Canvas 着色器或第三方包名称开放为分镜字段。
- 不在本变更中实现 20 个候选组件、图表全集或自动生成分镜的模型调用。

## Decisions

1. **渐进扩展版本 1 分镜。** 继续使用 `data.figure.kind`、`labels` 和 `motion`；顶层增加可选的 `visual.theme`，场景增加可选的 `visual.layout`。主题和布局只接受目录化预设，默认值复制当前深色画面与居中安全区的表现。避免另建一套完整 DSL，与现有字段竞争真源。另一方案是新建独立 visual JSON；它会重复存储场景 ID、文案引用和时长关系。
2. **共享页面与显式入口选择。** 在 Skill 资产中维护一个共享网页模板，从请求的分镜位置加载 JSON、创建场景节点并调用现有时间轴及组件挂载。预览/渲染 CLI 增加明确的分镜输入方式；已有网页输入方式保持原意。共享页面的资源解析基于仓库根和分镜的规范路径，不依赖当前工作目录。另一方案是为每个视频生成一份 `index.html`，但仍会产生重复且容易漂移的源文件。
3. **先校验再打开浏览器。** Python 校验器对声明式路径使用严格白名单，并由组件目录镜像提供组件名和可用参数；浏览器注册表与镜像由测试对照。已有 `figure.params` 仍需按组件能力逐项开放，不能默许任意键。另一方案是让浏览器忽略未知字段，会把错误延后成空画面。
4. **组件内封装实现。** 数字组件加入现有 `figures.js`、`figures.css` 和目录镜像，使用时间轴动效配方；共享页面只组装场景和预设布局，不保存视频文案。第三方效果将来可以在审查后封装进组件库，但分镜不引用来源包。

## Risks / Trade-offs

- [共享页面与现有 CLI 的本地资源路径可能错位] → 增加从不同工作目录预览/导出的集成验证，显式检查输出归属。
- [Python 目录镜像与浏览器注册表漂移] → 维持并扩充逐项对照测试，新增参数也纳入契约。
- [预设布局限制个别画面表达] → 保留旧网页路径；仅在经过实际作品验证后扩充布局集合。
- [双路径维护增加短期成本] → 复用同一时间轴、组件库与校验器，避免另起渲染引擎。

## Migration Plan

先增量引入字段、共享页面和 CLI 入口，保持现有作品及命令通过回归测试。新增一份仅用分镜的示例，验证预览、逐帧一致性和导出。若新入口出现问题，可继续使用现有专属网页路径；不自动改写旧分镜或旧视频文件。
