## Context

见 [proposal.md](proposal.md) 的 Why。当前 general 链路中，`validate` 只检查 v8 结构、ID 和帧窗；`prepare` 负责编译与字幕量测；`lookdev` 自动挑代表静帧；`qa` 的 claims 只检查旁白窗口覆盖；`layout_check` 只量子幕安全区；独立评审主要发生在粗片和最终成片。设计结论保存在 `DESIGN.md` 的散文里，没有进入分镜和场景的可验证约束；状态查询只有 `unprepared/prepared/candidate`；多次重置的基线保留没有数量上限。

实现受以下约束：不新增 v8 分镜字段、不改变运行时；不新增用户审批或 CLI 导出门禁；每个候选不增加额外完整草稿，真实返工允许新候选；独立评审的隔离规则不变；示例集合固定，只改现有三个；作品内容和生成媒体不入库；所有变更文档使用中文。

## Goals / Non-Goals

**Goals:**

- 把设计结论变成带检查点的可观察断言，使设计问题在写场景前暴露。
- 用场景单元检查点、量测和可选探针，把场景问题挡在全片渲染前。
- 用证据派生的状态层回答当前阶段、当前门、场景和下一步。
- 给多次重置设定有界的完整媒体保留和长期记录保留。
- 保持既有交付、评审和技术验收行为不变。

**Non-Goals:**

- 不引入自动审美评分、图像识别或 OCR 作为验收依据。
- 不新增第五个管理阶段、用户审批或 CLI 导出硬门禁。
- 不要求第二次全片渲染、草稿档位或 `productionProfile` 等价分支。
- 不新建平行设计文档、第二份问题表或独立状态数据库。
- 不追溯改造已交付作品的历史记录。

## Decisions

1. **检查点 ID 作为全流程共同键，合同嵌在 `DESIGN.md`。** 合同块是设计散文的机器可投影部分，声明场景/镜头 ID、tier、A 级时间结构、检查点、预期状态、文字计划和定量主张。备选方案是单独 `design.json`（形成平行来源）或写入 v8 分镜（改变运行时契约），均不采用。合同摘要进入制作证据依赖图，与渲染准备和缓存指纹分离，使纯合同修改仅使相关评审证据失效，不触发重新准备或编码。

2. **门放在现有四阶段内部，不新增阶段。** G0–G3 属于方案确定，G4–G5 属于粗片验证并在精制修订收敛，G6 属于最终验收。备选方案是只在粗片和终审评审（当前做法，问题发现太晚）或逐镜头派代理（成本过高），均不采用。A 级场景单独早审，B/C 批量并入粗片，控制评审成本。

3. **G4 采用“检查点静帧 + 关键帧对照 + DOM 量测 + 可选探针 + 场景窗口”。** 底层采集已支持任意 `selected_frames`，但现有 `lookdev` 只自动挑 hero/首尾/等距帧，无法对准设计检查点。备选方案是完整草稿渲染（违反单次生成）、纯 CV/OCR（脆弱且不可解释）、稀疏自动静帧（漏检查点），均不采用。SVG/HTML 场景优先用 `data-m2v-role` / `data-m2v-state`，不新增运行时 API；Canvas/WebGL 场景再选配状态导出。G4 复用 `outputs/code-cache/` 的场景片段，不额外触发全片渲染。

4. **状态层由追加式历史派生，不手工维护。** `history.jsonl` 是事件事实，`gates.json` 是可重建快照，`m2v status` 只读展示。备选方案是把进度写进 `project.json`（易漂移且污染版本库）、只在 `visual-notes.md` 写勾选（不可机读）或引入数据库（过度设计），均不采用。`pass` 必须同时满足证据摘要、上游摘要、独立评审和问题关闭；缺失证据只显示未开始/待评审/过期。

5. **基线默认保留目标为 3 个完整版本、记录长期保留。** 完整媒体包括当前版、直接前版和首个版本；由于当前版不在基线目录，无额外保护引用时完整基线目录最多 2 个。引用保护优先，通常增加一个保护版本后为 4 个，多个保护版本允许超额并报告引用与数量。备选方案是全部保留（磁盘失控）、只留 1 个（无法 A/B 和追溯）或对无引用版本无限保留（基线膨胀），均不采用。清理只删仅记录版本的媒体，必须读取引用和状态。

6. **评审分成两类：盲审美评审与设计→实现一致性审查。** 盲审美评审继续只读评审包，排除设计文档；一致性审查可以读合同和分镜，但只能判断 ID、帧窗、文字状态和结构是否自洽，不能产出“审美通过”。备选方案是所有评审都读设计（污染盲审）或所有评审都盲（无法检查合同一致性），均不采用。评审包统一记录门、检查点 ID、证据类型和摘要。

7. **门是制作完成条件，不是导出门禁。** 门状态和 `m2v status` 只读，既有 `validate`、`prepare`、`render` 的验收行为不变。备选方案是新增 CLI 硬门禁（与现有“人工评审可选、不阻断导出”冲突）或用户审批（项目明确禁止），均不采用。

8. **迟到缺陷回填最早可拦截门，并用摘要链传播失效。** 每个问题记录 `caughtAt` 和 `catchableAt`；终审发现可早期拦截的问题时，必须在较早门补检查或记录不可拦截原因。备选方案是只修当前问题（同类问题复发）或人工审计（不可靠），均不采用。

## 执行边界与证据依赖

### 门与阶段

证据矩阵以 [状态规格](specs/production-status-ledger/spec.md) 为准。G4 分为检查与评审两个维度；A 级两者完成、B/C 检查完成后即可开展 G5，G5 批量评审回绑 B/C 的 G4 后才允许标记粗片验证完成。粗片活动可以带问题迭代，不得把阶段未完成误读为禁止修复。镜头 A/B/C 与评审 A/B 是两个独立等级。

G5/G6 聚焦跨场及涌现问题，但可重新打开任何场景问题；漏检回填不限制终审权力。所有门通过意味着现有评审、问题关闭和交付检查证据已齐备，状态程序只聚合证据，不自行产生审美结论。既有 CLI 技术状态字段与含义保持不变，制作状态通过独立命名空间扩展。

### 摘要依赖矩阵

| 变化 | 失效范围 | 渲染影响 |
| --- | --- | --- |
| 单个合同检查点 | G1、对应 G2/G3/G4、依赖它的 G5/G6 | 纯合同修改不改变渲染缓存 |
| 全局合同约束 | G1 与所有依赖的 G2–G6 | 纯合同修改不改变渲染缓存 |
| 设计关键帧 | 对应 G2/G3/G4 及 G5/G6 | 不直接改变渲染缓存 |
| 单场源码或局部素材 | 对应 G4、G5/G6 | 沿用既有缓存规则；不使无关场景证据失效 |
| 分镜时间轴或共享素材/字体/场景依赖 | 受影响的 G1/G3/G4 及 G5/G6 | 沿用既有准备与缓存规则 |
| 成片字节 | G6 与最终交付绑定 | 旧评审不得授权新文件 |

准备指纹作为既有渲染依赖输入，不作为局部证据失效的唯一键；制作证据保存实际场景依赖摘要，避免全局指纹变化误伤无关场景。合同帧窗使用场景局部、起点包含终点不包含的区间，并显式存储映射到分镜场景与镜头的关系，不新增 storyboard 字段。G1 在源码存在前核验设计声明，G3 再核验实际分镜映射，避免要求实现先于设计存在。

### 登记与恢复

制作层提供 `m2v gates check/register/rebuild/repair`、`m2v review import`、`m2v issues update`、`m2v baseline create/prune` 入口；实现时先核对现有命令树再接入，不改变既有导出路径。check 产生合同/检查点报告并追加事件；register 验证已有证据后登记；import 验证独立评审来源与摘要；issues update 更新唯一问题表的机器块并登记摘要；rebuild 显式重建快照；repair 保留损坏原件后恢复可验证日志。事件使用唯一 ID 幂等导入，作品写锁保护登记与清理，快照原子写入，status 永远只读。

唯一问题表的机器块保存 ID、状态、必改标识、场景/检查点、caughtAt/catchableAt、复查证据与版本引用；可读正文与机器块必须由更新入口一致维护。外部编辑或解析失败不推断通过，清理对未知引用保守停止。日志尾部或中部损坏显式诊断，不静默丢弃并宣称通过。

### 采集、量测与来源

三档尺寸为原生画幅、852 宽与 393 宽等比例图，兼容竖屏。B/C 无设计图时只验合同，不伪造对照。来源标签仅是声明，G2 另需源记录及来源核验；自动摘要不能证明作者未截图。允许重叠关系、裁切、可见性、字号与文字预算按量测规格执行，Canvas/WebGL 无探针时提供人工逐项证据，否则未验证。时间采样记录步长并覆盖状态边界，不能判断连续运动时补片段或逐帧证据。

G5 采用引用场景缓存的可播放时间线，使用实际字幕、转场及音频合成规则，不额外编码全片粗稿；缺缓存仅补录缺区间。DOM 量测与任意帧采集允许运行浏览器，如实登记采集成本。每候选禁止额外全片草稿，不禁止缺陷修复后的新候选；记录完整生成尝试、成功次数与原因，QA 重试或复制不得重新编码。

### 清理与候选保护

保留级别仅 full/record-only，prunedAt 表示媒体删除完成，不能当第三个保留级别。清理先校验永久记录及引用，在作品锁内原子记录降级和待删清单，再幂等删除基线目录内列明媒体；中断保留可恢复清单。局部候选虽不新增重置基线，仍按既有覆盖保护规则保留比较证据，纳入媒体计数。数量目标不凌驾于引用保护。

## Risks / Trade-offs

- [风险] 合同和检查点增加设计与维护成本 → 只对 A 级和定量主张强制，B/C 使用默认检查点；检查点数量按作品需要，不设配额。
- [风险] 量测通过带来虚假信心 → 明确“结构通过 ≠ 审美通过”；G2、G4、G5、G6 的独立评审保留，量测不替代观感。
- [风险] 早期评审过多导致疲劳 → A 级场景单独早审，B/C 批量并入粗片；每道门只回答一个问题。
- [风险] 清理误删比较基线 → 清理读取保留记录、未关闭问题和进行中比较；被引用版本不得降级；只删仅记录版本的媒体。
- [风险] animatic 被误当最终画质 → 明确标注非交付物，只用于结构、时序和文字状态，不用于材质和光影结论。
- [风险] 状态层漂移 → 状态派生，不手工写；缺失证据不显示通过；历史只追加。
- [风险] 流程复杂度上升 → 按合同与依赖图 → 采集与分门评审 → 状态登记和清理 → 回归验收的依赖顺序实施；全部完成后才宣称启用新流程。

## Migration Plan

- 新启动的 general 作品及后续重制适用；已在制作品本轮沿用启动时契约，已交付作品不追溯，不补造旧证据。
- 先在 `examples/compound-interest` 后验回填检查点与 G4 回归报告（不冒充历史前置评审），验证 S5 计数、393 文字重叠和设计→实现漂移能被提前拦截；另外两个示例只做回归，不改内容。
- 不新增 v8 分镜迁移；设计合同、状态和基线记录均为制作层产物，不影响现有渲染路径。
- 更新 OpenSpec 规格、Skill 参考、README 与项目规划时，只描述实际落地能力；未实现部分保留在 OpenSpec 变更或规划中。
- 实施完成后按 AGENTS 的 OpenSpec 工作流提交、同步主规格并归档；回退时可移除状态与门产物，现有渲染和导出路径不受影响。
