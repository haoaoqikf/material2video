## Context

见 proposal.md - Why。金融组合目前用内容包围盒计算位移，计算机制可复用；画布为 1080×1920，旧纵向边界 y=180～1500 的中心是 840。

## Goals / Non-Goals

**Goals:**
- 股票与指数共用画布中线 y=960 作为几何居中目标。
- 纵向检查边界使用上下对称的 y=180～1740，并让评审指标、模板和文档保持一致。
- 保持 v7 计划数据、日期映射、时长和金融计算兼容。

**Non-Goals:**
- 不改变画布尺寸、背景、图表时间轴或视觉字号。
- 不宣称项目边界代表平台官方遮挡规范。
- 不把作品材料或渲染媒体加入 Git。

## Decisions

- 保留基于 SVG 实际包围盒的动态偏移，仅把目标中心定义为画布高度一半 960；不再使用旧安全区中点 840。
- 将上下各留 180px 的对称画布边距作为布局检查范围。单纯移动内容却保留 y=1500 底界会使居中目标与可用区域冲突；对称边界可保留边界门禁并反映新的画布对齐契约。
- 通过同一金融布局常量派生中心、范围和评审报告，避免 Python、前端模板及制作文档分别维护不同数字。
- 仅变更现有金融时间序列能力规格，不引入材料字段或计划版本迁移；特斯拉现有 v7 计划只需按新样式重新准备、预演和评审。

## Risks / Trade-offs

- 底部说明随整体下移后更接近屏幕底部控件区域 → 在 360×640 预演中抽查开场、中段、高波动阶段及终幕，并在报告中记录布局范围；若被遮挡则在提交前调整。
- 更宽的纵向布局范围不代表平台控件安全区 → 文档明确标为项目保守布局边界，不作平台官方规范声明。
