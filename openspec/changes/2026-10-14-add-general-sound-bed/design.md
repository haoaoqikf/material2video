## Context

通用类型已经有完整的配音链路（口播 → 字幕 → 全片帧时间轴 → `_mux_audio` 合入成片），但没有任何音乐层。文章类型两年来的 `soundtrack` + 闪避混音实现（`engine/sound.py`、`engine/audio.py` 的 `mix`/`duck_envelope`）已经稳定，缺的只是让通用类型接上它。

本变更的直接触发是制作 `videos/general/china-ancient-population` 时的听感问题：90 秒纯 TTS 干声，句读停顿全部落在 0.09–0.19 秒的窄区间，段间是精确的静音硬拼，听上去像播报机器人。

## Goals / Non-Goals

**Goals**

- 让通用片能声明一条受控音床，并复用文章类型已有的混音与素材摘要能力。
- 有音床时音轨退化为单条母版轨，闪避包络和采样边界整片统一。
- 修正通用成片音轨的交付规格，与项目既有契约一致。

**Non-Goals**

- 不新增音效（`soundtrack.effects`）支持：通用场景没有 beat 轴，音效起点没有可信锚点。
- 不做自动选曲、不做在线素材、不引入新依赖。
- 不改口播文本、音色或语速；不改字幕与画面契约。
- 不把配乐能力扩展到 financial-timeseries（该类型契约明确要求成片无音轨）。

## Decisions

### 复用共享声音契约，而不是给通用类型另写一套

`engine/sound.py` 的 `validate_sound` 原本硬编码遍历 `scenes[].narrationSegments[].speech` 并要求音效指向 `sceneId` + `beatId`。通用计划的场景用字符串 `narration`、也没有 `beats`，直接复用会校验不到任何东西或误报。

选择给 `validate_sound` 增加 `effects: bool = True` 开关：为假时只接受 `soundtrack.music`，遇到 `effects` 明确报「该场景结构没有 beat 轴，只支持 soundtrack.music」。这样两类型共用同一份增益、淡入淡出、路径与素材校验，差异只表达在「有没有 beat 轴」这一件事上。

替代方案是给通用类型复制一份校验。否决原因：增益范围、路径越界、淡入淡出上限这些规则会立刻分叉，以后修一处必然漏另一处。

### 有音床时改成整片单条母版轨

原实现把每个场景的旁白 WAV 各作为一条输入，用 `adelay` 摆到场景起点再 `amix`。这条路径在无音床时完全够用，也保持了「每场景一轨」的可追溯性。

一旦叠加音床，逐场景轨会带来两个问题：音乐必须做整片一次性的闪避包络，而包络要读字幕讲话区间；旁白的采样边界散在多条轨上，混音结果无法整片统一校验。因此选择：**有音床时**先按帧边界拼出整片旁白（复用 `audio.concatenate`），做二遍 loudnorm，再用 `audio.mix` 与音床闪避混合，最后作为一条母版轨落到第 0 帧。

无音床时保持原路径不变。这样现有通用作品（例如不含 `soundtrack` 的示例）准备记录与产物逐字节不变，回归风险集中在新增分支。

### 音轨编码规格统一到文章类型的交付规格

`_mux_audio` 原本输出 `-b:a 192k` 且不指定采样率与声道，结果跟着源走：源是 24kHz 单声道 WAV，成片就是 24kHz 单声道 AAC。渲染契约写明交付应为 AAC-LC / 44.1kHz / 立体声 / 128k，理由是 24kHz 单声道 AAC 会被 Windows Media Foundation 拒绝打开——这正是文章类型当初改规格的原因。

选择把通用类型改成同一组参数。代价是旧通用成片的音轨字节不再可复现，需要重新渲染才能对齐；收益是通用片交付不再依赖播放器宽容度。

### 音床素材：原创合成、无第三方采样

音床必须是本地相对路径素材，且要能循环。第三方曲库会引入许可与联网问题；`examples/buffer-smoothing/assets/generate.py` 已经确立了「自己合成、声明 CC0」的做法。

本作品的音床生成器按同一思路重写，并额外保证**循环接缝连续**：所有分量频率都取 1/8 秒的整数倍（8 秒循环恰好闭合），漂移用相位调制而非线性相位（深度同样取 1/8Hz 整数倍），因此末采样到首采样的步进与信号内部步进同量级，`-stream_loop -1` 循环时不会爆音。纯正弦听感像测试音，所以叠 7 层整数倍泛音并逐层衰减；不使用非整数倍失谐，因为那会与基频形成不整除循环长度的拍频，反而破坏接缝。

### 素材摘要进准备记录

有音床时把 `soundFingerprint`（声音配置）与音轨摘要写进 `inputs`，这样改音床素材或增益会让准备记录过期，符合「影响声音的变更使准备与评审过期」的既有规则。无音床时不写入这两个键，避免让现有作品的准备指纹无谓变化。

## Risks / Trade-offs

- [通用片音轨从逐场景轨变成单条母版轨] → 只在声明 `soundtrack` 时启用；无音床路径不变，并由既有测试覆盖。
- [成片音轨编码规格变化使旧成片字节变化] → 这是修正而非回归；受影响作品需重新渲染，已在 tasks 中显式记录。
- [音床盖住口播] → 复用文章类型的闪避包络（讲话时压低 10 dB，攻击/恢复 80/250 ms）与旁白二遍 loudnorm；实测定稿 −16 LUFS、真峰值 −1.58 dBTP，在交付上限内。
- [循环接缝爆音] → 以「跨接缝步进不超过内部最大步进」为判据实测，而不是看首尾采样值是否接近。
- [给通用类型加声音会让作者以为音效也可用] → `effects` 明确报错并给出原因，文档同步标注当前不渲染。
