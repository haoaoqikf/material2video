# 实施审查

- 关键结论：已检查 `engine/audio.py`、`engine/sound.py`、`types/general/adapter.py` 的差异与配套文档。计划校验复用共享声音契约，`soundtrack.effects` 明确失败；成片音轨改为 AAC-LC / 44.1kHz / 立体声 / 128k。
- 完整预演发现并修复的缺陷：母版旁白原先按**口播时长**首尾相接，而不是按全片帧边界推进。90 秒作品因此把整片人声压进前 70.5 秒——第 2 幕口播从 5.5 秒就开始（字幕在 8.0 秒），末段口播 70.3 秒结束（字幕到 87.4 秒），音床在 70.5 秒后是数字静音。闪避包络同样用的是场景内相对时间。修复后旁白按「到下一幕起点为止」的帧数推进、无口播幕补静音、嵌入片段用子作品整片音轨，闪避包络与字幕统一用全片时间；量测确认第 2 幕 8.08 秒、第 3 幕 23.06 秒起读，末段 87.38 秒结束，与场景起点和字幕一致，音床铺满到片尾淡出（88–89 秒 −45.9dB）。
- 交叉淡化：单条母版轨没有逐场景音轨可以 `afade`，淡化改为在 `audio.concatenate` 拼接时按槽位线性施加（新增可选 `fades` 参数，不传时逐字节保持既有行为），因此母版轨仍与画面共享淡化进度。
- 验证结果：通用类型 15 项、声音／素材剪辑／文章相关 102 项通过；全量离线回归 1041 项通过、4 项跳过（字体子集化需要 `uv sync --extra fonts`）、15 项 slow 未选；无失败项。新增两个回归：按帧边界拼接与闪避时间的单元断言，以及用真实 PCM 断言「口播留在自己那幕、音床铺到最后一段」的端到端用例；已用修复前的拼接方式反向确认该用例会失败（片尾电平 0）。
- 实机验证：`china-ancient-population` 重新 prepare、完整预演、评审并正式渲染。评审记录绑定准备指纹 `41afd676…` 与预演 SHA-256 `d5e438b7…`；成片 2700 帧、1080×1920、30fps、90.00 秒、AAC-LC 44.1kHz 立体声，音视频均可完整解码，整片 −16.4 LUFS、真峰值 −4.7 dBFS，与已评审预演逐字节一致（同 SHA-256）。作品与产物保持 Git 忽略。
- 逻辑影响：无音床路径不变（仍为逐场景轨与 `adelay`／`afade`）；有音床时计划校验拒绝 `effects` 并说明「没有 beat 轴」；嵌入场景只接受单条整片音轨，多条时明确失败而不是丢掉子作品声音。音床素材或参数变化使准备与评审过期。
- 性能影响：母版路径多一次整片拼接与二遍 loudnorm，均在 prepare 阶段，实测 90 秒作品准备未出现量级变化；渲染与验收路径不变。
- 剩余风险：主观听感评价仍留给人工试听（评审为可选工具，不阻断导出）。成片音轨编码规格变化使旧通用成片的音轨字节不再可复现，需要重新渲染才能对齐。
- 质量评分：92/100。扣分来自首版实现的帧边界拼接缺陷要到完整预演阶段才暴露，以及主观听感无法由自动检查覆盖。
