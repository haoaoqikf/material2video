## Context

现有 `general` 已有 v8 分镜、代码场景逐帧录制与制作检查；金融、建筑、汽车各有独立材料、无声适配器与 Remotion composition。六个风格包的组件经打包器特例导入，七个示例嵌套在包内。详情见 proposal.md。

## Goals / Non-Goals

**Goals:** 单一 v9 分镜、五类身份、单一成片 composition；保留已实现的金融计算、建筑步骤和汽车镜头；七例不依赖风格层而可运行。

**Non-Goals:** 不增加地图轨迹、剧情拍摄或新媒体生成能力；不迁移仓库外的旧用户作品；不改动现有素材许可结论。

## Decisions

1. **类型是作品级分类，来源是场景级能力。** `project.json` v2 只登记 `type` 和 `materials.storyboard` 等通用属性；`storyboard.json` v9 继承 v8 时间轴，每幕保持 `template: code` 与本地 `content.entry`。`storyboard.sources` 为可选的 ID 映射；每项形如 `{kind, files}`，`files` 是角色名到作品内相对路径的映射。来源种类 `financial-series`、`construction`、`vehicle-model` 分别沿用旧材料校验和计算。场景的 `content.sourceIds` 显式声明所用来源，SDK `useSceneSource(id)` 只能访问本幕获准的准备结果。金融只允许数据演化，建筑和汽车只允许三维空间。这样无需以旧类型名伪装内部子类型。
2. **只保留一条成片链路。** 将 general 的录制、音轨、字幕、转场、缓存和制作证据机制提为共享实现；三个专用 Web composition 的绘制核心变成代码场景可调用组件。Remotion Root 仅登记一个新版成片 composition；准备记录绑定新版本、来源文件摘要和结果、源码及依赖。旧 v1/v8、旧 composition ID、旧类型均拒绝。复用现有 Remotion、React、R3F 与代码场景组件，不引入同能力依赖。
3. **风格不再是可安装资源。** 通用计数、图表、轨道和字幕组件按功能进入 `m2v/code-scene`；只服务于单例的外观和常量放入该示例的 `scenes/`；未被示例或共享能力使用的旧风格文件删除。打包器仅允许作品本地、共享 SDK 与批准依赖，移除风格解析、配置文件和指纹分支。`web/src/styles/` 的基础 CSS 属于渲染实现，不作为风格包暴露。
4. **示例按目标类型搬迁。** 使用 `examples/<type>/<slug>/`，所有示例 `project.json` 改 v2，分镜改 v9，引用改为共享 SDK 或本地模块。字体登记目标从风格目录移到公共字体目录，示例媒体与声音配方保持既有摘要和许可；`.gitignore` 更新为新路径。
5. **命令只保留现行契约。** `m2v author` 承担原文、素材、声音等共用操作；`m2v data financial-plan` 生成金融来源计划。移除风格查询和旧迁移命令，通用命令按五类身份分发。类型目录仍是五类名称和初始化模板的唯一来源，但移除类别字段及路径逻辑。
6. **旧主规格随能力退役。** 六份风格包主规格和金融、建筑、汽车的独立类型主规格随原能力删除；当前材料能力由 `typed-scene-sources` 规格与三个专题参考指南描述。保留示例的作品级设计和历史验证记录，不把它们重新归入风格包。

## Risks / Trade-offs

- [金融或三维专用画面移入代码场景后与原成片不一致] → 复用原计算与几何算法，对关键帧做数值、静帧及同帧一致性检查。
- [示例依赖旧风格字体或组件] → 逐例迁移导入，按原素材配方恢复并执行准备及短预演；字体由公共登记恢复。
- [旧规格和文档仍称 general 或风格包] → 同步修订权威文档与规格，校验链接及类型目录生成区。

## Migration Plan

先落地 OpenSpec 规格；实现新版契约和来源桥接，再迁移七例并删除旧链路；定向验证后提交代码，随后同步主规格、归档并单独提交归档结果。旧用户作品须手工重新编排，旧准备与评审不能授权新渲染。
