## Context

现有问题范围包含职责、显示尺寸、来源、窗口、参考摘要与条件，关闭必须全部一致。参见proposal.md；用户换目标不是原目标修复，不能改写旧问题或重新开周期。

## Goals / Non-Goals

**Goals:** 在同一周期记录用户原话及新目标绑定，让旧失败在替代目标下重新独立复查。

**Non-Goals:** 不自动判断用户身份或审美，不把登记视为通过，不允许缩小窗口、变更职责/尺寸/来源，不新增周期或材料版本迁移。

## Decisions

- 输入version=1、source=user、instruction、reportIds、packPath、packSha256，目标来自已封存且当前有效的新盲包。记录以摘要收据挂接到现有周期历史，旧包和报告不变。
- 登记时选取同轮同职责的实际独立失败问题，检查新包覆盖原结构范围且目标确有变化。先验用户授权由助手依据对话核实，工具校验声明、记录和范围，不声称验证聊天身份。
- 问题关闭读取该问题最新有效目标变更；只替换参考和中性条件。仍须当前独立盲看及同轮目标对照通过，并且通过报告的导入位置晚于变更事件和原失败。登记不改问题状态。
- 多次用户换目标按问题ID逐次替换有效目标；每次验证范围，保留整个链。未登记问题继续严格采用原目标。
- 登记阶段即使是final也严格保留来源、场景、item身份和窗口覆盖；登记完成后的终审复查仍沿既有当前完整候选规则，允许全片剪短或重排，不把登记扩展为内容范围重写。
- 不采用重开周期或修改原scope，以免丢掉失败和观察历史。无新增第三方组件；复用现有锁、收据、包验证、范围匹配和问题投影。

## Risks / Trade-offs

- [工具无法独立认证自然语言授权] → source=user和原指令完整保存，操作规范只允许实际用户明确换目标时调用，不提供自动降标入口。
- [旧通过被借用] → 新目标登记不关闭问题，复查导入必须晚于变更。
- [记录损坏或复查范围缩小] → 摘要/周期/字段与结构范围每次校验，失败时维持开放投影并拒绝交付。

## Migration Plan

新增显式命令，不改既有v2记录或旧报告。正常路径无新记录时行为不变；回滚代码后带变更的关闭因原目标不匹配而重开，不会误授权。


## 实施验证与代码复核

直接验证：25个目标变更行为边界、6个既有评审闭环调用方、8个依赖登记边界及1个工作区版本一致性节点通过，共40项；此前本轮原生样品文件22项通过，未跑全仓回归。CLI帮助、真实作品的用户目标登记、受影响文档JSON/相对链接与OpenSpec严格校验通过。登记真实替代7个旧失败但不关闭问题，也未新开周期。

独立代码复核发现final登记错误继承旧终审的结构放宽，现已改为登记统一严格校验，独立复核4个边界节点通过（在上述25项内，不重复计数）。登记与后续当前全片复查的区别已写入本设计和规格。其余未发现阻断问题；不把代码审核当视觉通过。

逻辑影响只在有有效用户目标变更记录时生效；无记录仍使用原目标。没有新增媒体编码或浏览器工作，记录扫描约为问题数乘目标变更数，长周期重复读取/摘要尚无性能测量。工具无法认证自然语言用户身份，必须由操作者依据真实对话核实；这是明确披露的边界。

代码质量94/100，依据独立复核及直接集成验证；扣分主要为长周期性能边界与自然语言授权真实性不能由机器验证。
