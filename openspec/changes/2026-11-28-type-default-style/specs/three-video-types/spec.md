## MODIFIED Requirements

### Requirement: 三类视频身份

系统 MUST 仅登记 `text-motion`、`data-evolution`、`spatial-3d` 三类。三类决定制作指导、默认目录和按 `type-default-style` 定义的默认参考集。类型列表、初始化与作品校验 MUST 使用同一目录。类型与材料路由保持单层，MUST NOT 增加类别、风格子类型或风格包入口。每个工程 MUST 独立拥有执行能力。默认路径为 `videos/<type>/<slug>/`，有效工程移动后 MUST 能从任意目录执行。

#### Scenario: 初始化三类作品

- **WHEN** 分别使用三个有效类型初始化作品
- **THEN** 每个工程拥有 v3 作品描述、v9 分镜、本地场景入口、该类型的参考绑定和清单摘要。

#### Scenario: 旧身份被拒绝

- **WHEN** 初始化遇到旧类型、未登记类型、旧类别路径，或执行入口遇到旧契约工程
- **THEN** 在准备或渲染前明确失败。

### Requirement: 统一分镜与成片

三类 MUST 使用 `project.json` v3、`storyboard.json` v9、独立作品参考绑定以及同一场景时间轴、准备、预演、渲染、声音和制作证据机制。每幕由本地代码场景绘制，完整成片由单一 composition 合成。旧作品描述、旧分镜和旧准备记录 MUST 明确拒绝，不自动迁移。只有补齐参考绑定的 v3 工程才符合当前制作契约。

#### Scenario: 三类贯通

- **WHEN** 三类工程分别具有有效分镜、场景和已校验的本地参考绑定
- **THEN** 均可校验、准备、预演并按同一成片契约导出。

#### Scenario: 旧材料

- **WHEN** 工程使用旧格式材料、旧准备或缺少当前参考绑定
- **THEN** 明确指出不支持的契约或缺项，不将该输入用于当前导出。

### Requirement: 独立示例目录

仓库 MUST 在 `examples/<type>/<slug>/` 保留现有三个可运行示例。每例 MUST 随工程提供生效参考绑定、本地场景和执行入口。素材恢复与输出继续遵守来源摘要校验及 Git 忽略规则。

#### Scenario: 示例运行

- **WHEN** 逐一对三个示例执行校验、准备和短预演
- **THEN** 本地参考绑定与摘要可核验，作品材料与输出均留在自身工程内。
