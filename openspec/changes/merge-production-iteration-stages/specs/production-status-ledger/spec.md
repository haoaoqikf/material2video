## MODIFIED Requirements

### Requirement: 状态查询必须显示当前阶段、门、场景和下一步

查询 MUST 只读显示三阶段、G0–G6、自身结果、检查/评审状态、缺失风险覆盖、人数与触发原因、场景摘要和可执行下一步。前置未完成但自身有效 MUST 显示等待前置，缺证据显示缺项，真实依赖变化才过期；未知版本须明确诊断而不默认为通过。G4/G5 MUST 始终显示制作与迭代，不因粗片通过另切阶段；门、依赖、证据与问题关闭仍按当前有效状态计算。技术状态与制作状态 MUST 分命名空间，保留既有技术输出。

#### Scenario: 精简审核的适用判断

- **WHEN** G6 无split-final且一份有效综合终审已覆盖全部职责
- **THEN** 独立评审人数显示1/1，不要求structure和visual-copy两个不同身份

#### Scenario: 场景阻断

- **WHEN** 某个场景检查点失败
- **THEN** 查询显示该场景为阻断，列出未关闭问题 ID，并给出可执行的下一步

#### Scenario: 回到长期未处理的作品

- **WHEN** 制作助手在新会话中查询作品状态
- **THEN** 查询显示当前门、最后有效证据、过期项和下一步，无需重新阅读全部制作文档

#### Scenario: 机器读取

- **WHEN** 其他工具需要读取状态
- **THEN** 查询可输出结构化状态，包含门、场景、证据摘要和未关闭问题 ID
