## Context

动机见 [proposal.md](proposal.md)。现有 `article-media-assets` 只定义媒体导入、实测、许可与溯源；`video-production-workflow` 定义创作与复核流程。本轮在后者增加「载体来源决策」，不改媒体导入契约。

## Goals / Non-Goals

- 给 general 一个可执行的两层决策：整体定政策，逐场定实例。
- 让代码、外部素材与混合使用都在同一证据体制下被记录和复核。
- 不改运行时、素材导入、CLI 或渲染链路。

## Decisions

1. **两层，不是二选一**：整体设计决定证据体制与边界；逐场只决定具体实例。只在整体决定会在场景层才发现素材不可得、变化不可见或许可不行；只在逐场决定会导致全片证据体制不一致、母题漂移、许可失控。
2. **候选层也写载体组合**：三个叙事候选可以在「档案为主／代码为主／混合」上不同，但每案都要说明哪些内容必须真实、哪些只能解释；比较时把素材可得性与许可风险列为主要风险。
3. **判断标准是「证据 vs 解释」**：观众需要相信「这是真实的人／事／物／地点／数据原件」，或真实质感就是记忆点时，用外部素材；对象不可见、不存在、过大过小、危险或昂贵，或重点是机制、数量、关系、时间、反事实时，用代码；真实锚点＋代码揭示机制时用混合。
4. **逐场字段固定为「载体来源与理由」**：写来源类型、为什么、许可与溯源状态、真实／示意边界。字段是设计记录，不进入运行时；逐场设计表从 9 列扩为 10 列，不新增分镜 JSON 字段。
5. **硬边界不可用创作理由豁免**：图库不得冒充真实事件／人物／地点；代码不得伪造证据或实验结果；许可未知不得进入成片；档案不冒充 4K；原理动画标注示意；混合边界必须一眼可辨。
6. **代码-only 与 archive-only 都成立**：人生五选择与太阳系是解释型，全代码成立；美国科学里程碑是混合型。示例只作非重制记录，不重制视频。
7. **冲突回退整体**：逐场发现与整体政策冲突时，回退「表达载体」或选案层改策略，不就地改用图库或代码冒充。
8. **运行时保持不变**：外部素材仍只能经 `assets import` 后按 `useMediaAsset(id)` 取用；代码画面仍是 `scenes/` 下的 TSX；不新增来源字段或自动选择。

## Risks / Trade-offs

- 两层记录可能被误读为新增审批 → 明确它只是 `DESIGN.md` 与逐场表的设计记录，不新增评分、用户确认或 CLI 门禁。
- 「证据 vs 解释」可能被机械套用 → 允许混合，也允许全代码或全档案；关键是说明理由与边界。
- 逐场表增加一列会增加填写量 → 与「素材可得性、许可、真实／示意」风险相比，这点记录成本更低；共享规则仍写在全片一次。
- 示例补写可能被读成重制 → 每节明确「非重制记录」，不改写既有交付结论。

## Migration Plan

后续启动任务采用新指导；既有作品与评审历史不迁移、不倒填。实施完成后运行测试、`sync_docs.py --check` 与 OpenSpec 严格校验；同步主规格后归档并提交。
