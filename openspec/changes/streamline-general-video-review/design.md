## Context

动机见 [proposal.md](proposal.md)。本次检查了制作 Skill、检查点/独立评审/修订参考、四份主规格、production 的 contract/checks/ledger/reviews/acceptance/timeline 和相关测试及示例合同。当前工作树另有无声视频任务的改动，提案独立于该任务。

### 核查结论

| 当前机制 | 实际约束与问题 | 处理 |
|---|---|---|
| G0 输入、事实、许可 | 必要；不属于审美代理审核 | 保留，结果由现有材料复用 |
| G1 合同、G3 分镜映射 | 自动一致性检查，成本主要是人工合同填写 | 保留自动检查，删去普通镜头重复细表 |
| G2 独立关键帧 | 每个 A/core 要建立、结果、适用揭示图，三档尺寸及独立盲审 | 改为静态表达风险触发；缩略尺寸自动派生 |
| G3 animatic | 代码用 A 级或 structureRisk 触发，A 级本身就会追加一轮 | 仅独立的结构时序风险触发；能用同一核心样片覆盖则合并 |
| G4 场景检查 | 自动量测和完整窗口有价值，但每检查点均有独立评审计数 | 保留自动与人工替代核验；仅指定核心风险窗要求提前盲审 |
| G5 全片粗片 | 跨场观察有独立价值；现有 B/C 批量回绑造成 G4 等 G5 的状态绕行 | 一份全片报告；普通镜头 G4 不再等待批量回绑 |
| G6 终审 | ledger 固定两人且固定两类 focus；consistency 不计人数，仍另需五维三方凭据 | 默认一名新的综合终审；有目标图才同轮对照，不另派人 |
| acceptanceChecks | 每核心检查点在 G4/G6 重复登记窗口、摘要、五维、三方来源 | v2 删除开关与旧凭据形状，改用每轮覆盖表引用现有证据 |
| 返工/诊断 | 首次重要返工匿名比较、删30%与唯一画面双答等均可阻断完成 | 连续两轮同问题失败或实质争议才升级；其余成为诊断工具 |
| 版本绑定 | 摘要有必要，但 assets/fonts 全目录纳入每个 G4 范围，会误伤无关镜头 | 以实际依赖集绑定，共享依赖变化传播到使用者 |

以上是规则与代码核查，不是历史工时统计。尚不能声称节省具体分钟或提升成片质量。

## Goals / Non-Goals

目标：常规 general 的独立审查控制在 2–3 轮；有风险才增加工作；一个问题只登记一次；完成状态与实际覆盖一致。四个制作阶段与 G0–G6 ID 保留，使精简集中在职责而非重命名。

边界：不修改 storyboard v8、视频类型、渲染/配音/静音契约、素材来源政策、缓存复用或技术导出条件；不降低事实、许可、核心理解与可读性标准。候选比较和创作方法仍可主动使用，但不按固定数量验收。不把未知风险或缺失证据自动当作无风险。

## Decisions

### 1. 三轮主审，按用途选证

| 主审轮 | 时点与执行者 | 必须覆盖 | 交付记录 |
|---|---|---|---|
| 核心样片 | 扩展高投入实现前；一名独立代理 | 每项核心未验证风险；动态须完整事件窗；静态以目标图或实际原型验证 | 一份报告＋覆盖表，可覆盖多个核心窗 |
| 全片粗片 | 精修前；一名独立代理 | 全部场景、跨场衔接、结构、节奏、文案理解及视觉风险 | 一份全片报告；不为 B/C 复制逐点报告 |
| 最终成片 | 当前候选技术 QA 后；一名未参与该作品前期评审的新代理 | 当前文件全片、理解/结构/节奏/视觉/文案/手机可读性，实际问题闭环 | 一份综合报告，绑定当前视频摘要 |

核心样片只在存在未验证的核心表达、动态因果或关键视觉风险时必做；已验证的复用机制可引用来源和适用依据，不因 A 级标签本身强制一轮。不同风险可合并同次投喂，但报告须覆盖各窗口，不能用一个代表事件授权所有未验证风险。粗片和最终成片两轮不可互相替代；最终必须是新的观察者。每轮一人是默认人数，不表示所有轮共用同一人。

选择保留七个证据索引，而不把命令全部改成三个新门：自动检查不是主要负担，重命名会扩大 CLI、问题表和基线变更范围，不能改善审核质量。

### 2. 封闭的额外审核触发规则

v2 合同新增 `reviewPlan`，必需 `risks` 列表（允许空），每项含唯一 id、kind、scope（场景/镜头/检查点）、reason、requiredEvidence；不填写人工可随意降档的 reviewerCount。kind 仅接受下表；人数和所需环节由单一策略派生。已有 structureRisk 布尔改为列表中的结构风险；删除 acceptanceChecks。新增风险须更新计划且使相关要求重新计算，不能靠删风险掩盖失败或未解决问题。

| 触发 | 额外要求 | 不触发的情况 |
|---|---|---|
| static-expression：空间/隐喻/构图关系必须先由静态方案排除误读 | 独立目标关键帧与盲看；可作为核心样片轮的静态部分 | 只是 A 级标签、普通标题或已验证布局 |
| structure-timing：跨场顺序/延迟揭示在实现前存在具体未决风险 | animatic 评审，可与核心样片同轮 | 仅因片中有动画或 A 级镜头 |
| core-event：新的核心动态因果或可见变化尚未验证 | 完整动态窗口；静帧不能替代 | 无实质动态风险的静态作品 |
| split-final：用户明确要求双人，或已确认综合终审无法在同轮覆盖两类专业风险 | 两名新且互相隔离代理，全片分别负责结构与视觉文案 | 时长、镜头等级或主观追求更高级本身 |
| substantive-dispute：对核心实际缺陷或必改项有证据冲突 | 新代理先盲看，再核对中性原条件；单独保留争议结论 | 纯审美偏好差异 |
| repeated-failure：同一问题连续两轮修复仍未改善 | 至少两个实质不同的匿名候选，包含删短/重排或替换机制 | 第一次重要返工 |

split-final 的专业风险依据须具体指向当前观察能力或覆盖限制，不允许笼统写“高风险”；最终发现无法覆盖时先保持未完成，再登记升级，不能先通过再补理由。争议复核不是多数投票；复核未消除实际缺陷仍阻断。用户明确的硬性审核要求可增加要求，不可被默认策略覆盖。

### 3. 完成条件按门派生，不再固定计人数

| 门 | v2 完成条件 |
|---|---|
| G0 | 事实/许可/输入审查，无独立审美人数要求 |
| G1 | v2 合同与审核计划结构有效 |
| G2 | static-expression 风险适用时有有效来源目标图及核心轮静态观察；否则有计划依据的不适用 |
| G3 | 实际分镜/时长映射自动检查；structure-timing 才需要 animatic 观察 |
| G4 | 每场默认检查点及所有风险点检查通过；仅被计划选中的核心窗需要独立观察 |
| G5 | 全片粗片独立综合评审与完整覆盖 |
| G6 | 当前候选技术 QA、完整全片证据、一名新代理综合审查；split-final 则两名；全部必改关闭 |

G2/G3/G4 的观察可以由同一核心轮报告绑定多个检查事件，机器仍保留细粒度索引，不要求作者复制报告。G4 普通镜头检查通过即可关闭，不再等待 G5 回绑；G5 有权发现并重开任意场景问题。自身证据状态、等待前置、待评审和真实过期继续分列，next 只推荐缺失的实际工作。

### 4. 设计兑现并入同轮，保留先盲看

终审者先只读取当前成片中性包，写出不可覆写的 blind 观察及摘要；之后才能得到独立 consistency 包，查看适用目标图和中性目标条件。两阶段可由同一代理完成，两份来源引用合在一份轮次记录，consistency 结论不能替代 blind。无独立目标图的镜头只验用途与实际表现，不追补目标图，也不要求五维三方空表。

合同检查、数量和文字状态、动态过程采样继续存在；采样步长、关键状态边界、手机尺寸、观测限制仍按现有量测口径。字号、数量、许可等可自动证明的项目不要求独立代理再抄一遍。

### 5. 精简合同和记录，保留追溯

v2 保留场景/镜头/检查点 ID、等级、时间窗、文字和定量断言、必要禁止项。每场默认一个检查点；按真实状态变化和风险增加，不给每个普通内部镜头强制一套检查点。A 级六段时间结构改为依赖时机的风险窗才必填；无断言的列表允许为空，不能因此跳过实际内容核查。设计六项、七段式、十项自检、三机制、两问等作为设计方法库，统一回填现有设计区块，不以表单数量或固定候选数量判断完成。

保留 DESIGN.md、visual-notes.md 和原始报告三类记录。每轮只有一份覆盖表：范围/窗口、观察、结果、证据引用、问题 ID；详细量测只引用自动产物。自动登记稳定摘要和事件，一份报告多点绑定保持幂等与完整校验后写入，防止半成功。唯一问题表仍保留 caughtAt/catchableAt、关闭证据和基线引用。

### 6. 变更复查与证据有效性

局部布局/字幕改动：重查本窗和相邻衔接，其他场景细项证据在实际依赖未变时继续有效。核心关系、叙事顺序、总时长、全局样式变动：重审对应核心风险与全片结构。最终视频摘要变化：当前候选技术 QA 与全片综合终审重做，但不自动重开未改的选案、关键帧和场景量测。

场景依赖从实际导入源码、所用素材 ID、字体及全局配置解析；依赖无法精确确定时保守扩大并明确原因，不伪称精确。审核计划变更影响审核依赖，不进入渲染缓存指纹。删除风险或修改目标不能直接关闭关联未解决问题。

### 7. 实施边界与文件清单

- production/contract：v2、风险结构、稀疏检查点、条件时间结构；拒绝 v1 与旧字段。
- 新增 production 内聚策略模块：从合同与用户要求派生审核计划；checks、ledger、reviews、timeline 共用，不各自硬编码次数。
- checks/measure：条件关键帧/animatic、保留采样边界与自动量测；timeline 不再要求所有 A 镜头固定独立审查，仅要求计划中的前置风险完成。
- ledger/reviews/acceptance：综合 focus、覆盖表、同轮多门绑定、blind→consistency 顺序、独立身份约束、范围摘要；删除旧强制五维三方凭据实现和测试，不并存两套策略。
- CLI/status：沿用命令，显示实际所需审核、触发原因、缺失覆盖与下一步；不加用户审批。
- AGENTS.md、README、ARCHITECTURE（模块职责改变时）、Skill 及 production-workflow/checkpoint-gates/subagent-review/visual-review-rubric/director-review-and-edit/scene-design-and-acceptance/creative-production/visual-creative-direction/visual-impact-design/video-revision 等引用文档同步清理硬性重复条款。
- 三个既有示例更新当前合同、设计说明及演练，不新增示例、不提交生成媒体、不将历史演练伪装为真实评审。

### 8. 可验证的收益与验收矩阵

| 用例 | 预期 |
|---|---|
| 无核心未决风险的简单 general | G2 不适用、G3 仅映射、G4 自动检查；粗片1人＋最终1名新代理，共2轮2次独立调用 |
| 有 core-event 的常规 general | 核心1轮＋粗片1轮＋最终1轮，共3次独立调用；无额外 G2/G3 或 consistency 代理 |
| 同时有 static-expression/structure-timing/core-event | 可同轮分批选证；先解决所需前置风险，不因“合并”跳过时序；若风险需串行验证可增加调用并注明原因 |
| split-final | 最终两人互不读报告，默认路径不受影响 |
| 普通镜头局部改字 | 本窗与衔接复查；旧核心/无关场景证据有效；新候选仍全片终审 |
| 核心目标修改、删除失败风险、伪造来源 | 相应证据过期或阻断，不自动通过 |
| blind 未落盘就提交 consistency | 拒绝，不写部分成功事件 |
| 证据缺失、历史损坏、自审冒充独立 | 不通过，显示可执行修复步骤 |
| 金融、住宅 | 类型契约及技术导出不变 |

以程序测试与固定评审用例统计 required review 数量、实际独立调用次数、手填覆盖记录数和范围失效数量；对比旧策略的相同用例。常规核心样片例的硬性独立席位从 G2/G3/G4/G5 各1＋G6的2（合计6个席位，未计对照；席位不等于调用次数）降为3次调用。禁止直接把这解释成工时减半。性能要求：不得增加全片编码次数；每轮仅计算一次可复用依赖索引，同一文件摘要同次查询不重复读取；用依赖遍历/摘要计数验证。

## Risks / Trade-offs

- [单人终审可能漏检] → 使用前期未参与的新代理，结构和视觉分栏，证据不足不通过，明确 split-final 触发。
- [风险清单被当作免审开关] → 结构校验＋事实依据＋粗片/最终全覆盖兜底；删风险不消除未关闭问题。
- [合并投喂污染盲审] → blind 落盘先于 consistency，来源摘要及时间顺序可验证，污染则换新代理。
- [v2 中断在制工作] → 升级前明确列出旧合同，不能自动继承通过；安排在当前在制任务可接受的交接点实施。本次提案不切换在制作品。
- [精确依赖解析漏边] → 对动态引用保守扩大并披露；回归测试覆盖共享素材/字体/全局样式。
- [文档分散使旧强制要求复活] → 逐项强制条款清理清单，主规格与参考文档同时检查，不能只加一段精简总则。

## Migration Plan

1. 实施前复核工作树与在制无声视频变更的共享文件，保存基线，不混合提交。
2. 完成策略、v2 校验、台账及测试，再一次性更新示例与权威文档。当前合同只支持 v2；遇 v1 明确报错并提示重新编排当前合同，不自动迁移或运行旧分支。
3. 历史事件与报告按原字节保留；作为历史可展示，但不得混入 v2 的通过判定。v2 新制作周期标识用于隔离证据，不搬移或删改用户历史；沿用现有基线保护与清理。
4. 跑三例合同/分镜检查、风险矩阵和完整相关回归；用太阳系例作一次真实核心窗→粗片→终审闭环，不能只靠虚构报告证明审美流程可用。其他两例做受影响契约与技术回归，不默认重制三条视频。
5. 验证、审查、提交实现后同步主规格并自动归档；未完成真实闭环不得勾完任务或归档。
6. 必要时用独立 revert 提交回退本变更实现，保留生成证据与基线，不建立长期双版本策略。
