## Context

动机见 proposal.md。现有运动 skill 混合 UI 动效配方、审美偏好和帧驱动边界；入口、查表路由、来源指南和代码注释均有引用。共享原语已经要求显式 easing 且支持 linear，无须修改执行算法即可取消通用审美限制。

## Goals / Non-Goals

- 只保留一个必读创意参考和一个运动技术权威，不新建动效手册或风格注册表。
- 不改变渲染、曲线实现、默认值、作品材料与审核策略，不新增物理、流体或逐帧动画引擎。

## Decisions

1. 12 种动态风格并入既有灵感文档，使用名称／特点／适用场景三列表格，使用原则统一覆盖外观、表达、运动三维。必读要求沿用，采用自由；不加入示例、配方、评分或数量要求。
2. 删除整套 motion-design，取消人格、层次、固定步骤和预算。保留的帧数换算、显式缓动、数据与接触说明写入 code-scene-runtime 的运动实现约定；采集模式、纯时间与并行边界直接链接现有章节，不复制第二套规则。
3. 通用曲线方向由表达目标决定，linear 与其他缓动均可显式选择。共享曲线库、显式传参、有限值、端点及确定性仍然有效；不改算法或缺省。修正 primitives.ts 中声称缓动可省略的过时注释。
4. motion 路由改指运行契约，删除 UI 查表路由，ruleOwners 的“运动设计”改为“运动实现”，校验器同步。删除只保护退役 skill 存在性的测试，不新增固定文案测试。
5. 作品专属动作与历史名称保留，不追溯重制。活动链接与通用限制按来源逐项清理；源码注释修复不修改样例参数、测试期望或实际画面。

## Risks / Trade-offs

- 风格名被误写为已实现能力 → 说明清单只描述体验，不增加引擎或运行接口。
- 通用限制残留在共享契约 → 扫描活动文档、规格与注释，区分审美限制和显式 easing 等实现边界。
- 删除 skill 丢失技术约束 → 将数据准确、接触依赖与帧驱动说明迁至运行契约，保留现有源码与确定性测试。
- 参考清单无法证明创作质量提升 → 本轮仅验证文档、导航及现有实现不回归，不声称真实作品效果或效率改善。

## Migration Plan

实施与针对性验证完成后审查暂存并提交，再同步主规格、逐要求核对、归档及提交。无需作品迁移，回退使用本次 Git 提交；旧 skill 能力通过 retire_capabilities 显式退役，不保留空规格或兼容入口。
