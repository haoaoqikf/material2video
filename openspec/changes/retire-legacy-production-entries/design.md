## Context

三类独立工程由自己的 `setup` 生成或导入音效。主项目的文章审查与素材工作仍可读取当前分镜和声明的音效。主项目另有一套导入、合成及混音实现，其写入的生成器标识无法通过作品本地校验。

## Goals / Non-Goals

主项目承担作者工具和委托执行。作品承担音效落盘及混音。此次范围限于现行命令、主项目无调用的声音实现、模板的未接线入口、专题导航和三个旧单片规格。已发布作品使用各自独立源码和证据。

## Decisions

1. 去掉共享命令和写入实现，保留作者工具需要的只读复核。曾考虑增加主项目到音效库的专用委托动作。现有 `setup` 已覆盖正式制作入口，删除专用动作更符合精简目标。只接受 `film_runtime.sound-synthesis` 的当前登记，保留本地对参数、文件完整性和摘要的核验。只用于旁白的主项目音频共用工具继续服务现有调用。
2. 把合成、混音及导入的相关测试转到真正执行这些操作的作品运行时。旧命令的拒绝纳入现有 CLI 负例。模板里的未接线声音子命令一并删除。示例继续持有自己的运行快照。
3. 保留按需能力。默认内容根和随附示例共九个 project v3、分镜 v9 工程，分镜均未采用具名结构化来源。另有六个旧金融项目和一个旧车辆项目，证明相应题材有实际制作历史。建筑目前只有可验证的组件与专项契约，已按需复制，保留可复用的结构与资产校验。素材库近期有检索、采样和组织功能的维护记录，且作品有媒体来源台账。高级能力继续放在按需入口，直接导入与审计单列给常规制作。
4. 三部旧单片只把要求撤出活跃规格。归档保存撤下前的完整规格，与变更的逐条移除记录相互核对。《太阳系之旅》仍是随附示例，保留其正式验收规格。

## Risks / Trade-offs

- 既有脚本可能仍调用旧命令。当前作品用配方和本地 `setup` 重新生成，校验继续识别并拒绝旧生成器记录。
- 删除主项目混音副本后，原媒体边界由作品运行时测试覆盖。对本地来源读写做一次跨入口验证，以免主项目作者工具和作品 `validate` 得出不同结果。
- 按需功能可能由外部作品使用，本地盘点只能说明已检查范围。现有按需契约保持可用。
