## Context

`ArticleExplainer` 的六个模板把外观写死在组件里：圆角、内边距、间距、字号、图形尺寸全是字面量，
主题只能提供颜色、标题字重字距与动效时长。上一轮的 `velvet` 因此只读作换色。

本轮要把外观的决定权移到主题数据。约束有三条：

1. **dark / light 的画面必须逐像素不变**——既有作品、既有预演与既有验收都建立在当前取值上。
2. **`tokens.css` 不能被改成多主题**——`keynote-design-system` 规定令牌层只提供一套深色，
   并禁止按属性切换的作用域层（没人挂属性时整层令牌是空值，画面会静默落到初始值）。
3. **动效只能由帧号驱动**——源码闸门拒绝 `animation` / `transition` / `@keyframes` 与计时器。

## Goals / Non-Goals

**Goals**：主题同时决定取形、间距、构图与字阶；`velvet` 出现观感层级的变化而非换色；
dark / light 画面不变。

**Non-Goals**：不改分镜结构；不改时间轴与验收算法；不引入 CSS 作用域层；
不把字号塞回令牌层；不做逐模板的整版重绘（构图模式是参数化的对齐，不是新的版式系统）。

## Decisions

**取值放数据、不放"代码默认值 + 覆盖"。** 另一种做法是 dark/light 不声明新对象、
由组件保留现有字面量当兜底，只有 `velvet` 覆盖。更省 JSON，但那 37 个取值就继续住在组件里，
正是项目反对的"第二处事实"。因此三套主题都显式声明全部取值，逐像素不变由测试保证而不是由缺省保证。

**字段按语义角色，不按刻度。** 现有取值（160 / 420 / 54 / 44 / 28 / 24 / 20 / 16 / 12 / 10 …）
不构成任何干净的间距刻度，硬套 `sm/md/lg` 三档必然改变 dark / light。因此主题声明的是
**每个角色的取值**（`sceneTop`、`panelPadding`、`cardGap` …），而不是一个刻度表。

**缓动用控制点，不用曲线名。** 主题声明 `motion.entranceEasing` 为四个数的三次贝塞尔控制点，
`[0, 0, 1, 1]` 即线性（dark / light 用它，画面不变），`velvet` 用 `[0.37, 0, 0.63, 1]`（easeInOutSine，
对应原风格的 `sine.inOut`）。用控制点而不是 `"sine.inOut"` 这类名字，是因为名字需要一张
名字→曲线的映射表，而那张表本身又会变成第二处事实。实现是帧驱动的求值函数，
不产生 CSS 动画，不触碰源码闸门。

**构图模式是对齐参数，不是新版式。** 主题声明 `align`（`start` / `center`）与
`verticalAlign`（`start` / `center`）。`center` 时标题与正文水平居中，且幕外壳用
`justifyContent: center` 并把 `data-m2v-content` 从 `flex: 1` 改为自然高度，使标题与内容
作为一个整体垂直居中——这样"大量留白"来自参数，而不是把六个模板各重画一遍。

**垂直留白受量测边界约束。** 浏览器量测要求正文包围盒下沿 ≤ `--m2v-measure-content-bottom`（1502）。
幕外壳的 `sceneBottom` 就是这条约束的实现（`1920 - 420 = 1500`），因此任何主题的 `sceneBottom`
都不得小于 418。`velvet` 的"宽松"来自更大的 `sceneTop` 与更大的内部间距，以及垂直居中带来的对称留白，
而不是把内容推到字幕区。

**图形尺寸随字阶一起变。** `velvet` 的标题取 120px（与正文 40px 构成原风格的 3:1），
标题折行后需要更多纵向空间，因此因果图、媒体框与代码框的高度也必须是主题取值，
否则因果幕会越过内容下边界。

## Risks / Trade-offs

- **`velvet` 的标题 120px 会在较长标题上折成两行**，挤压内容区。取值按"最长幕仍不越 1502"
  标定，由浏览器量测作为门禁；实测不过就下调字阶或图形高度，不缩小安全边界。
- **37 个取值从组件搬到 JSON 是一次高风险搬运**：漏搬一处就静默回落到默认值或报错。
  缓解办法是把 dark / light 的取值逐字照抄，并用改动前后的采样帧截图哈希比对证明画面不变。
- **`velvet` 的间距与字号尚无视觉评审**，最终观感需要人看一眼；本轮只保证契约与量测通过。
- **构图模式只有水平与垂直对齐两个维度**，无法表达原风格的"对称、建筑感"的全部含义；
  这是参数化能到达的边界，文档中如实说明，不表述为已实现完整版式系统。
