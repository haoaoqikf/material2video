## Context

动机见 proposal.md。已有 policy、类型目录、跨语言画幅/帧率清单可复用；工作区的边界标注改动属于另一变更。

## Goals / Non-Goals

集中可执行规则及其文档投影，保留合同 v2、分镜 v8 与现有状态语义。不引入通用工作流引擎，不把审美判断编码为自动门禁，不改作品内容。

## Decisions

- production/workflow.py 定义不可变门描述（ID、阶段、范围、检查处理器、证据摘要），前置门由有序定义派生；ledger 保留证据状态计算，policy 保留风险决策。
- policy 风险目录同时提供门映射及文档文案，审核轮/人数通过现有 requirement/rounds 派生；同步脚本生成检查点文档的门表、风险表与轮次策略，其他入口链接该正文。
- 共享画幅读取移动到 core/frames.py，依赖 core.assets 的仓库根，不反向依赖浏览器模块；全部内部消费者同步更新。合同调用共享画幅/帧率校验。
- core/source_imports.py 提供引用提取和路径解析，构建与制作证据复用公共接口，但保留各自遍历、保守绑定与查询内缓存策略。
- 手工文档的权威归属：production-workflow 管阶段操作；checkpoint-gates 管合同字段与证据结构；subagent-review 管隔离和执行；visual-review-rubric 管视觉判断；visual-material-selection 管载体选择。Skill/README 提供导航。
- 合同字段仍由现有 contract.py 校验，不引入第二套 schema；此轮不生成字段说明，避免双重定义。示例继续作为被验证的消费者。

## Risks / Trade-offs

- 提取引用解析可能改变指纹 → 保留解析顺序与后缀，并运行可达性、缓存及证据失效回归。
- 文档删重可能丢失独有要求 → 仅删除重复策略，保留任务方法、证据格式和专题细节；核查相对链接及示例。
- 同文件已有未提交改动 → 保存基线，按本次增量暂存，不提交其他变更；如有交叠以三方方式保留工作区内容。
- 配置读取增加 I/O → 本次不新增跨查询缓存，保持外部编辑可见；引用解析维持原复杂度。

## Migration Plan

先完成定义与消费者切换，再生成文档并验证。无需材料迁移；失败时回退本次提交，不改写作品证据历史。
