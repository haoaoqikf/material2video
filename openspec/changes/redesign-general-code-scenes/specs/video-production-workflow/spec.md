## MODIFIED Requirements

### Requirement: 文章作为独立视频类型
系统 MUST 通过 general 制作 v8 全画布代码视频，支持默认横屏及显式竖屏，按 article-explainer 执行输入审查（topic 跳过）、素材导入、准备、完整预演自动验收及可选人工评审，保持可查询状态和版本绑定。MUST 保留配音、字幕、音床音效及 600 秒限制。

#### Scenario: 保留文章制作闭环
- **WHEN** 提交有效横屏或竖屏 v8 材料
- **THEN** 按相同画幅完成准备、预演与导出，不要求人工画面批准

## ADDED Requirements

### Requirement: 通用作品视觉设计与实际观看
制作助手 MUST 在编写场景前确定画幅并记录作品视觉设计，用户未指定时采用横屏。设计 MUST 包含参考依据、视觉隐喻、字体配色、开场/核心/结尾构图、运动与镜头承接以及声音意图。助手 MUST 检查代表关键帧，并实际观看含运动、转场和声音的代表片段；发现问题 MUST 记录时间位置、修改和复查。无法观看 MUST 明确说明，MUST NOT 虚构通过。设计与观看记录 MUST NOT 成为 CLI 导出门禁，不新增用户逐次确认。

#### Scenario: 未指定画幅
- **WHEN** 用户仅提供内容
- **THEN** 助手以横屏规划并记录视觉依据，再制作关键画面与代码

#### Scenario: 观看发现问题
- **WHEN** 代表片段存在节奏、构图或声音问题
- **THEN** 记录具体位置，修改相关材料后重新准备并检查

#### Scenario: 纯 CLI
- **WHEN** 有效材料通过技术验收与当前完整预演，但没有视觉设计或观看记录
- **THEN** CLI 不因缺失这些记录而阻断导出
