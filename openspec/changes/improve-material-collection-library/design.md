## Context

动机与范围见 proposal.md。当前 SQLite、不可变工作文档、Pillow、NumPy、E5、SigLIP 和本地预览可复用；作品运行时不依赖素材库。工作区存在其他文档改动，提交必须按实际差异隔离。

## Goals / Non-Goals

目标是有限预算下不偏向片头、批量收集能继续、候选更可信、素材能够积累与浏览。逐阶段完成并验证后再进入下一阶段。保持正式材料、渲染、评审和网络边界不变；本轮不引入账号、云服务、平台访问绕过或自动事实认证。

## Decisions

1. **跨时间分配预算**：共享确定性采样函数选择覆盖全轴的点；较小 OCR/视觉预算再次分布选择。策略名称进入缓存参数，结果报告实际覆盖。与单纯增大预算相比，保持当前资源上限并改善覆盖。
2. **流式与增量状态**：使用 `os.scandir` 逐目录遍历；成功文件路径、原字节摘要与媒体关系存于工作库独立表。每次扫描验证源内容摘要及已有对象，复用不消耗新获取预算；逐件事务保存，坏件隔离。内容未变化的失败项保留错误、默认不重复消耗获取预算，显式 `--retry-failed` 才重试，避免坏件阻塞后续；源内容变化自然重试。下一次从目录重新遍历但跳过已完成项，避免把不稳定目录枚举序号当可靠游标。代价是重复遍历及摘要读取，换取目录内容变化时不漏项；不承诺零 I/O。错误明细有固定容量并另报总数。
3. **原文文本与校准**：文本索引补来源标题/描述，无时间窗口并明确 origin；输入与配置摘要绑定来源文字。正负例先固定，实测后决定门槛及必要的相对背景证据，不凭感觉降低统一阈值。现有动作与身份 unknown 约束继续保留。
4. **组织信息分离**：SQLite 附加组织表以媒体 ID 关联，独立维护 tags/collections/favorite。统一浏览读取显式多库，复用现有静态预览的卡片与媒体派生方式；本地过滤脚本仅操作已转义的本页数据，CSP 固定哈希，无网络和任意脚本。旧 preview 的无脚本契约不变。
5. **相似分组复用视觉向量**：按完整向量空间身份分桶，用 NumPy 分块矩阵乘积比较，默认保守阈值、有限条目数，报告截断；组内各成员须满足与代表的相似标准，避免简单传递闭包把差异大的镜头串成同组。结果是建议，不执行物理去重。
6. **查询编码复用与实测**：第四阶段将编码移到一次请求的惰性缓存，模型校验仍保持有效。测试断言编码调用次数不随媒体数量增加；真实单次请求记录冷/热状态、范围与内存。逐站通过现有 discover/fetch 验证 Commons/NASA、Archive、B站/YouTube；缺 Key、会话或真实链接的来源如实记录，失败不冒充零命中或稳定支持。

### 外部方案调研与复用

- [E5 官方模型卡](https://huggingface.co/intfloat/multilingual-e5-small)：MIT，沿用已固定 revision 和许可，保留 query/passage 前缀；其相似度不能按通用概率理解，门槛需实际校准。
- [SigLIP 2 官方模型卡](https://huggingface.co/google/siglip2-base-patch16-224)：Apache-2.0，沿用已准备的 CPU 模型，研究多候选标签/背景对照的可行性；不额外安装更大模型。
- [ImageHash](https://github.com/JohannesBuchner/imagehash)：成熟的感知哈希，BSD-2-Clause；但新增哈希索引与依赖仍不能替代本项目已有的语义镜头向量，本轮优先复用现有有效向量。需要逐帧确定性且本地可恢复，不引入云图像服务。
- [NumPy matmul](https://numpy.org/doc/stable/reference/generated/numpy.matmul.html)：复用已锁定 2.5.4（BSD-3-Clause）进行有界分块计算，不引入向量数据库或大型聚类服务。
- [SQLite](https://docs.python.org/3/library/sqlite3.html)：复用标准库连接与事务保存组织/增量信息；现有预览已能提供本地卡片与接触表，继续扩展，无新增前端组件依赖。FTS5 有成熟方案，但当前万条词面性能已有通过记录，本轮不改造无直接瓶颈的词面存储。

## Risks / Trade-offs

- 稀疏采样仍会错过短动作 → 披露实际覆盖和未知，允许增加预算，不宣称全片理解。
- 阈值对题材敏感 → 分开校准与保留验证集，明确结果只覆盖实际语料。
- 本地目录可能在扫描时变化 → 摘要与状态检查，保留旧身份，变化项重试；不宣称 OS 级竞态隔离。
- 相似分组最坏为平方比较 → 分块内存、明确规模上限及截断，不分配全量平方矩阵。
- 外部平台随网络/风控漂移 → 保留逐站原始结果，受限项仍为 limited/not-tested，不削弱网络策略。

## Migration Plan

仅按需增加 SQLite 独立工作表，不升级既有文档版本或建立兼容分支；新采样和文本输入参数生成新索引身份，旧不可变记录保留。组织信息随工作库保存，不复制到正式媒体 schema。完成后同步主规格、归档并提交。
