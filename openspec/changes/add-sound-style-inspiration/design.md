## Context

动机见 proposal.md。素材声音文档承担声音字段、素材留证和混音技术要求；配音文档还混有声音角色与稀疏音效偏好。现有混音按 loop 配置决定是否重复素材，silence 只调制音乐与音效，旁白独立混入；无需修改算法即可落实本轮指导调整。

## Goals / Non-Goals

- 在现有必读文档内提供第四个创意维度，精简冲突的职责、角色、密度和报告要求。
- 不改变许可、定位、增益、交付响度与峰值、音轨长度、参数校验或听感证据边界；不新增声音引擎、字段或强制试听。

## Decisions

1. 音效清单使用名称／特点／适用场景三列表格，保持用户提供的 12 项；不引入复利案例、实现教程或独立音效 skill。四维共用必读且采用自选规则，不要求每维选择一种。
2. 音效、配乐与旁白按需独立使用，可以重复、密集、疏落、留静或完全无声。删除“音效只强调少数重要事件”、固定声音职责与重复 whoosh 的通用限制，以实际目标、旁白可懂度和可观察问题复核。
3. 音效角色与密度／强弱表改为可选思路，不要求固定 assetId、SOUND.md 或音乐段落表。必要意图引用 DESIGN.md 和既有时间线；来源许可仍由现有声音台账承担，不能因不写设计报告省略留证。
4. 需要同步时共用事件源；提前、延迟与独立氛围用现有偏移或显式时间定位，不要求每个音效对应画面动作。sceneId、时间范围和来源字段的既有校验不变。
5. 只有选择连续循环时才核对循环接缝。故意断续、重复和故障效果按目标判断，交付真峰值等技术要求仍保留。silence 只影响音乐与音效，完全无声窗口需同时安排无旁白；用户要求有声时不得擅自改为无声。
6. 声音技术文档保留，不把清单写成新增混响、音高或音乐生成能力。只改与本轮直接相关的文案、导航和规格，历史作品及归档保持原样。

## Risks / Trade-offs

- 删除角色表被误解为删除素材记录 → 明确保留现有来源、许可、参数和摘要台账。
- 静音被误读为全声静音 → 区分 silence 的音乐／音效范围与旁白安排。
- 密集或故障声音被一律判失败 → 用已声明目标和技术信号区分设计效果、真实缺陷与听感覆盖限制。
- 参考清单被写为现有音频引擎能力 → 仅描述听觉灵感，不新增字段或承诺实现效果。

## Migration Plan

完成文档调整与针对性验证、审查并提交实施，再同步主规格、逐要求核对和归档提交。无作品材料迁移或重制；回退使用本轮 Git 提交。
