## Context

动机见 [proposal.md](proposal.md)。运行时和技术检查不消费这些主观门禁；问题集中在 Skill 指导与主规格，须统一修订而非添加机器审美判断。

## Goals / Non-Goals

- 将核心体验、载体、揭示、强弱与主动精修放入现有四阶段及三类记录。
- 保留独立盲审和技术边界，使创意取舍有证据。
- 本轮不重做视频，不改 JSON、CLI、渲染实现，不宣称已验证主观感染力。

## Decisions

1. 修改现有立意六项而非叠加检查表：去掉强制母题、唯一赌注和三条决策数量，保留命题与事实验算。
2. 以完整表达段落为判断单位：先盲看落盘，后核对预先声明的中性目标；意图不豁免失败。
3. 将四个硬测试改为诊断：适用性和证据边界由视觉复核规范集中定义，其他入口引用。
4. 在原问题表和导演记录增加收益／损失及亮点强化，不新增报告种类。用成对情景演练检验误杀与漏放。
5. 现有三个示例只补后续设计／评审应用说明，不修改分镜、媒体或历史交付结论；校验器无对应审美逻辑时保持不变并记录检查结果。

## Risks / Trade-offs

- 放宽形式约束可能被当成随意放行 → 实际核心缺陷仍必改，创意风险须取证，不由作者自行解释关闭。
- 替代证据无法验证完整听感与连续体验 → 如实披露覆盖限制，不以规则演练宣称成片提升。
- 多文档旧句可能抵消新规则 → 搜索现行入口及主规格，逐项处理冲突；归档历史不追溯改写。

## Migration Plan

后续启动任务采用更新指导；既有作品不迁移、不倒填。完成文档检查、情景演练和既有校验后提交，随后同步主规格并归档。
