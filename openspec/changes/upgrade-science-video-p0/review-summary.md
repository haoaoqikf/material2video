# 实施审查与验收边界

## 主要发现

本轮补齐了上一轮因浏览器播放接口不可用而停下的验收，并在过程中发现并修复四处会让验收结论失真的缺陷：

1. **体检模板与解析器标签不一致**。`review.py` 首次生成的 `review.md` 模板写的是「图形承担论证」「动效服务理解」，而 `visual_narrative.review_v6` 与 `animation_review.review_a6` 只认「图形论证」「动效服务」。照模板逐格填写的人会一直看到「待评审」，命令却只报「未填写」，无法反推原因。现在模板改用解析器与文档一致的标签，解析器同时接受早期模板的旧标签（旧记录继续可读）。
2. **`production.py status` 的退出码永远不为 0**。全片评审行沿用记录里的 `pass`，关键幕与正式渲染行用 `passed`，而退出码只认 `passed`/`not-required`：所有评审都填好后命令仍返回失败。现在由 `production.all_stages_pass` 统一判定，两种成功写法都算通过。
3. **联系表被两条时间轴互相覆盖**。静态材料 `contact-sheet.png` 按分镜声明的时间轴生成、绑定（分镜 + 资产），但带 `--media` 的体检按配音派生的时长抽帧，仍写同一个文件名：先 `production.py keyframes` 再 `review.py --media` 就会把登记过的材料换成另一份 PNG，门禁报「材料已缺失或摘要已变化」，而画面一个字都没变。现在文件名跟着抽帧时间轴走（`contact-sheet.png` / `contact-sheet-media.png`），登记材料在任何执行顺序下都不再被覆盖。
4. **标杆示例自己没过交付门禁**。`examples/buffer-smoothing/storyboard.json` 六幕的 `visualIntent` 逐字相同（同 `focus`、同 `density`、同 `composition`），`validate.py --strict` 报 3 条 `adjacent-identical` 与 2 条 `intra-video-reuse`，退出码 2；其余 7 个示例都是 0。已按每幕真实信息关系改写为 contrast / cause / sequence / cause / contrast / collection，并把逐字复制的 `showWithoutText`、`primaryObject`、`motionMeaning` 改成各自幕的真实表达。这类改动不改变画面（`visualIntent` 除 `composition` 外不参与渲染，本次 `composition` 保持 `center`），重新生成的联系表摘要与改前完全一致，可验证。

四处都补了回归测试：`tests/test_review_template.py`（照模板填完就能通过）、`tests/test_production_workflow.py`（状态退出码）、`tests/test_review_material_paths.py`（联系表命名）、`tests/test_examples_strict.py`（仓库内每个示例都必须通过严格校验）。

此外，上一轮报出的 `motion.sweep` 在页面元素未就绪时抛 `Cannot read properties of undefined` 只在并发跑测试时复现过一次，随后 5 次运行（含两次关键帧材料生成、三次体检与两次渲染）均未再出现，暂按环境竞争记录，未改代码。

## 实际完成的评审

- 关键幕（opening / smooth / overload）静态与动态评审全部通过，依据分别是联系表逐帧与关键幕有声样片逐段抽帧。
- 全片静态、全片有声动态、全片口播内容（五项各 ≥ 4/5）评审全部通过。
- V6 图形论证 5/5；A6 动效服务 4/5（本片无未裁决装饰候选）；定制动画动态评审六幕五项均 ≥ 4。
- 机检提出的「相邻幕构图复用」已逐幕裁决：同一管路母题下状态与声明不同，不是模板化复制。
- 结论幕动作幅度为全片最小（部件展开较克制），评分 4/5，是当前最弱的一处，未触及下限。

## 验证结果

- Python 回归：全套 pytest 通过（本轮新增 10 条用例，含模板闭环、状态退出码、联系表命名与示例严格校验）。
- TypeScript/Vitest：14 文件、106 测试通过；前端类型检查与生产构建通过（构建仅有既有的大包与第三方注释警告）。
- 标杆严格分镜校验：`validate.py --strict` 退出码 0、零警告（改前为 2 与 5 条多样性提醒）；静态探针 18 帧抽检 0 错误，K 系列仅有既有提醒。
- 确定性：六幕收尾帧同帧重复截图 + 随机寻帧全部一致（PSNR ≥ 60 dB）。
- 材料一致性：改分镜声明后重新生成联系表，摘要与改前逐字节相同（`84938499…`），证明这次只改了声明、没有改画面；带 `--media` 的体检另写 `contact-sheet-media.png`，登记的 `contact-sheet.png` 不再被覆盖。
- 全片有声评审版：1557 帧 / 51.9 秒 / 540×960，解码验收通过，约 12.6 帧/秒。
- 正式成片：1080×1920/30fps、1557 帧、51.9 秒、5.1 MiB，解码 1557 帧通过；画面产出 310.9 秒（约 5.0 帧/秒，与前端构建并行时测得），总耗时 335.8 秒。音轨 AAC-LC 44.1kHz 立体声。
- 音轨量测：混音 −16.0 LUFS / 真峰值 −1.7 dBFS / LRA 3.1 LU；除片尾 0.34 秒外无 ≥ 0.3 秒静音；非旁白成分（音乐床 + 音效）平均 −25.9 dB，不压口播。
- 阶段状态：`production.py status` 退出码 0，正式渲染行「评审记录有效」。
- 文档：216 个 Markdown 文件的 171 个相对链接检查通过（仅存档变更里两处历史断链与一处历史 JSON 示例未动）；`git diff --check` 通过。

## 逻辑与兼容影响

分镜仍为 v3，可选 `speech`/`soundtrack`；无 `speech` 保留整幕 TTS。媒体清单 v1/v2/v3 均可读，新声音参数需要 v3。旧制作记录仍可读，但新增发布需补内容评审。字幕由媒体派生 `subtitleCues` 驱动，源分镜不能手写。混音不改变时长；错误不覆盖旧清单。模板标签变更只影响新生成的 `review.md`，解析器对旧标签保持兼容。带 `--media` 的体检改为输出 `contact-sheet-media.png`：依赖 `contact-sheet.png` 的既有流程（`production.py keyframes` 登记、评审量表引用）不受影响，只是那份联系表不再被配音时间轴覆盖。`production.py keyframes` 仍不读媒体，与「静态联系表按声明时间轴生成」的既有约定一致。

## 性能与资源

- 体检：18 帧抽检 + 逐帧动效扫描，一次约 40 秒（含契约页构建）。
- 关键幕样片：604 帧 / 20.1 秒，画面产出 46.2 秒（约 13.1 帧/秒）。
- 评审版渲染：1557 帧约 123.5 秒画面产出（约 12.6 帧/秒）。
- 正式成片：同帧数 310.9 秒画面产出（约 5.0 帧/秒，1080×1920，与前端构建并行时测得）；显著慢于评审分辨率，属预期。
- 逐帧活动量曲线（ffmpeg 降采样到 48×85 灰度后算相邻帧差）全程 51.9 秒视频只需数秒，可用于节奏复核。
- 未测 ffmpeg 子进程的峰值内存；先前记录的 tracemalloc 62,758 字节只覆盖包络生成，仍不能宣称全链路峰值。

## 剩余风险与质量评分

**声音听感未确认**：本轮口播内容评审依据的是口播文本（分镜为唯一真源，逐句与 `article.md` 核对）与音轨客观量测，没有做真实试听；TTS 音色、段间衔接和音乐听感的结论仍需人工过一遍 51.9 秒评审版才能作为发布记录。这是本轮唯一未闭环的验收维度，已写进作品目录的 `review.md` 与 `examples/buffer-smoothing/review.md`。

其他风险：结论幕动作偏轻（4/5）；六幕仍共用同一居中构图与同一水箱母题，靠状态区分而非构图差异（这也是本次只改声明、没改画面的原因——真要拉开构图差异需要重做代码场景，代价与收益不成比例，已作为已知局限记录）；SVG 曲线工具采用预采样点，精度由采样密度决定；M 系列扫描覆盖偏低（整片仅扫到 1 个入场元素）属既有量测口径，未在本轮扩大范围。

代码质量评分：**90/100**。闭环已完整（模板—填写—门禁—退出码—材料登记—正式渲染—归档），本轮修掉的四处缺陷都有回归测试，评审有材料摘要与帧级依据，标杆示例自身通过严格校验；扣分主要为声音听感未确认、结论幕动作偏弱与六幕构图单一，以及仍未测 ffmpeg 子进程峰值。
