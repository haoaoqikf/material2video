## Context

当前版本由共享 composition 递归解释 `sceneTree`，分镜不能包含可执行内容。该架构已经具备统一时间轴、契约页、K/M 闸门、源码溯源和内容根支持，但固定原语限制了作品级 SVG、复杂图表和关系布局。现有前端已经安装 ECharts 与 Dagre，Remotion 和 Tailwind 也已进入共享构建；Lucide 尚未安装。

本变更横跨分镜 schema、Python 校验与编排、前端模块解析、Tailwind 构建、Remotion composition、契约探针和溯源，因此需要在实施前固定代码边界和失败语义。动机见 `proposal.md`，行为合同见本变更的四组增量规格。

## Goals / Non-Goals

**Goals:**

- 让每幕可在现有场景树和作品级 TSX 组件之间显式选择，并可在一支作品中混用。
- 让作品代码拥有充分的 React、HTML/JSX、CSS、TypeScript 与 SVG 表达力，同时限制在固定依赖和本地资产范围内。
- 保持画面由帧号确定、预览与导出同源、离线可渲染、旧成片可判陈旧。
- 让自由场景继续被内容探针、安全区、溢出和动效闸门量测。
- 兼容仓库内作品与显式外部内容根，不把作品源码或产物加入 Git。

**Non-Goals:**

- 不提供浏览器内代码编辑器、热更新沙箱或在线包安装。
- 不支持任意 npm 包、CDN、远程素材、外部字体或作品自己的构建配置。
- 不把任意代码字符串嵌入 `storyboard.json`，也不通过 `eval` 解释表达式。
- 不取消场景树；简单场景仍优先走声明式路径。
- 不允许作品自建 Remotion composition、契约页、时间轴或渲染命令。
- 不声称静态检查能够把不可信代码变成强安全沙箱；该能力面向本地、受审查的 AI 生成作品源码。

## Decisions

### 1. 采用逐幕双轨渲染，而不是全作品二选一

分镜场景新增显式 `renderer` 判别联合：`tree` 使用现有 `sceneTree`，`code` 使用稳定模块标识。共享 `A2VComposition` 仍只负责一次时间轴定位，再将当前幕交给对应渲染器。代码模块不能声明 duration、fps 或相邻幕，因此不会形成第二套时间真源。

选择逐幕双轨是因为关键幕需要高表达力，而普通文字或列表幕使用场景树成本更低。备选方案“所有新作品都生成完整 TSX composition”会复制时间轴和契约逻辑；“继续扩充原语”会把一次性构图永久固化进共享注册表，均不采用。

### 2. 代码以文件模块存在，不在 JSON 中执行字符串

作品代码放在 `videos/<slug>/scenes/` 或对应外部内容根目录，分镜只保存不含扩展名和路径穿越的模块标识。模块导出符合共享 `A2VCodeScene` 类型的 React 组件；共享运行时注入 `scene`、`frame`、`fps`、画布、幕内帧与进度、主题及稳定随机工具。

文件模块能被 TypeScript、bundler、导入图和源码指纹正常理解。把 JavaScript 或表达式字符串放进 JSON 虽然生成方便，但会迫使系统使用动态求值、弱化类型与位置诊断，因此不采用。

### 3. 构建前生成当前作品的静态桥接模块

Python 解析作品归属与分镜后，把允许的场景入口传给一个 Node 生成步骤；生成步骤在 `web/.gen/` 写入临时 `active-scenes.ts`，对当前作品使用静态 import 并导出模块映射。Remotion 入口和契约页共同导入该映射。生成文件、作品代码与作品资产不纳入 Git。

静态桥接让 Vite/Remotion 能构建仓库外内容根，又不会让运行时接受任意路径。每次 preview/review/render 都从分镜重建并校验桥接，避免上一个作品的模块残留。失败或中断后，下次运行会覆盖而不是复用未知状态。

备选方案运行时动态 import 无法完整静态分析，也扩大路径和依赖边界；为每个作品创建独立前端项目则会产生依赖漂移，均不采用。

### 4. 白名单同时约束直接和传递可达导入

允许的裸模块根为 `react`、`react-dom`、`remotion`、项目实际需要的 `@remotion/*`、`echarts`、`@dagrejs/dagre`、`lucide-react`；Tailwind 通过共享 CSS 构建接入，不要求作品导入其运行时。相对导入必须留在当前作品 `scenes/` 与 `assets/`，项目别名只能指向单独公开的代码场景 API，不开放任意内部文件。

校验从场景入口遍历本地导入图，拒绝未知裸模块、Node built-in、`require` 和非字面量动态 import。构建器不读取作品 `package.json`，也不执行安装。Lucide 被视为本次唯一新增共享依赖，版本及许可证与其他依赖一起锁定。

只扫描入口文件不足以阻止辅助模块绕过规则；依赖浏览器 CSP 也无法在 Node 构建阶段约束导入，因此采用可达导入图。

### 5. 安全边界采用静态闸门加运行期断网

静态闸门扫描可达 TS/TSX/JS/JSX/CSS 与 SVG 文本，至少拒绝：动态代码求值、动态模块加载、Node 能力、进程/文件系统、网络 API、外部 URL、CSS `@import`、挂钟、系统随机、计时器、浏览器动画循环和 CSS 时间动画。诊断统一包含作品相对路径、行列和规则编号。

静态规则之外，契约页自动化与 Remotion Chromium 都阻断非本地请求；任何被阻断请求、页面异常、未处理 Promise 或控制台 error 都使评审/渲染失败。资产仅允许解析到工作区当前作品目录、共享 web 静态资产或媒体清单明确挂载的位置。

该模型保护构建与可复现性，但不把作品代码视为恶意多租户输入。若未来需要运行第三方不可信代码，必须另设进程/容器沙箱能力。

### 6. Tailwind 对作品源码显式建索引

生成步骤同时生成 Tailwind source 索引，使当前作品的 TSX/TS/CSS 被扫描。只保证源码中出现的完整类名；运行时拼接的类名必须改为完整字符串映射。构建结束后的 CSS 与场景 bundle 一起供契约页和 Remotion 使用。

直接让 Tailwind 扫描整个内容根会泄露其他作品、降低构建性能，并可能把历史内容意外带入成片，因此只索引当前作品可达文件。

### 7. 图表和图标有库级适配规则

- ECharts 使用 SVG renderer，默认和显式配置均强制 `animation: false`。需要动画时，组件根据 frame 计算当帧 option；实例在容器尺寸稳定后创建、更新，并在卸载时销毁。评审等待共享 ready 协议确认本帧 option 已落地。
- Dagre 在稳定排序的节点和边上、以固定配置计算一次布局。当前帧只改变 React/SVG 的可视属性，不改变布局输入。
- Lucide 作为静态 React SVG 使用，颜色走 `currentColor`；动画施加在组件属性或外层容器，并由 frame 计算。
- 原生 SVG 可以使用 path、mask、gradient、filter 与帧驱动属性，但外部 `<use>`、外部 URL、脚本和事件处理逃生口被拒绝。

相比直接允许库默认行为，专用规则会限制部分便利 API，但能保证随机寻帧与逐帧导出一致。

### 8. 自由场景必须实现最小可观察协议

代码场景根节点由共享包装器自动标记 `data-a2v-scene`；作品对需要体检的文本、图表和容器标记稳定的 `data-a2v-node`、`data-a2v-role`、`data-a2v-inside`，无来源数值继续标记 schematic。共享 TypeScript helper 提供类型化属性，减少拼写错误。

严格评审先验证最低标记覆盖，再运行现有 C/K/M 闸门。无法从自由 DOM 推断的场景树结构检查不冒充已通过，而是由代码场景专用检查替代；安全区、文字溢出、内容出现和同帧确定性仍为硬判定。

### 9. 溯源覆盖当前作品的完整可达输入

成片指纹从共享入口扩展为：共享可达源码与锁文件、生成清单的规范化内容、作品可达 TSX/TS/CSS/SVG、本地媒体与分镜。绝对内容根不写入指纹，统一记录相对于作品根的键，保证工作区迁移后仍可复核。

只记录入口文件会漏掉辅助组件和 CSS；记录整个内容根会让无关文章修改导致成片陈旧，因此沿用可达图边界。

### 10. 分镜 schema 采用显式判别联合并兼容现有作品

现有含 `sceneTree` 的 schema v2 分镜在缺少 `renderer` 时按 `tree` 解释，避免批量迁移。新代码场景必须显式写 `renderer.kind: "code"` 与模块标识，且不能同时声明 `sceneTree`；新的树场景生成规范应显式写 `renderer.kind: "tree"`，为未来收紧兼容入口留出空间。

不提升根 schemaVersion，因为时间轴、内容模型和契约页版本不变；若实现发现判别联合无法无歧义兼容，再单独评审版本升级，而不是在实施中静默改变。

## Risks / Trade-offs

- [自由 TSX 增加静态分析盲区] → 限定为本地受审查代码，遍历完整可达导入图，并以运行期断网、异常捕获和同帧复测补强；明确不宣称强恶意代码沙箱。
- [每篇作品都可写代码会造成质量漂移] → 保留场景树默认路径，只在视觉意图确有需要时选择代码场景；共享主题、字体、令牌和评审闸门继续生效。
- [ECharts 逐帧 setOption 可能拖慢渲染] → 优先复用实例，仅提交当帧必要变化，SVG 复杂度设置预算，并用代表性基准场景设性能回归线。
- [Tailwind 漏扫动态类导致预览样式缺失] → 只允许完整类名或完整字符串映射，并增加构建后代表类存在性测试。
- [仓库外内容根使 bundler 路径处理复杂] → 所有路径先由 Python 归属解析和边界校验，再生成规范化静态 import；Windows 与 POSIX 路径均加入测试。
- [Lucide 增加供应链和许可证面] → 只新增 `lucide-react`，固定版本、锁文件、许可证记录和升级检查，不开放作品依赖。
- [双轨增加校验矩阵] → 共享时间轴与契约不分叉，测试覆盖纯 tree、纯 code、混合、外部内容根和失败输入五类固定夹具。

## Migration Plan

1. 先增加 schema 的向后兼容判别联合与失败诊断，旧分镜默认保持 `tree`。
2. 建立代码场景 API、静态清单生成器、依赖/安全扫描与测试夹具，在 composition 尚未启用前验证边界。
3. 接入共享 composition、契约页和 Tailwind 当前作品扫描，完成纯 code 与混合作品预览。
4. 接入 ECharts、Dagre、Lucide、SVG 适配与探针协议，跑同帧确定性、随机寻帧及 K/M 评审。
5. 扩展 render/review/preview 与溯源，完成仓库内和外部内容根的限帧及完整渲染。
6. 更新示例和全部权威文档后，将代码场景标记为可用。

回滚时保留对 `renderer.kind: "tree"` 与旧版缺省 tree 的支持；撤下 code 分支、Lucide 依赖和生成桥接即可，代码场景分镜会明确报“不支持 code renderer”，不会退化成错误画面。
