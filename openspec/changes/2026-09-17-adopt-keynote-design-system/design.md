# 设计说明

本变更要解决的是一个判断问题：**「发布会级别的观感」怎么从形容词变成可执行、可复核的约束。**
下面记录关键技术决策、被否决的方案，以及实测依据。

## 决策 1：字体落盘，不走 CDN，也不继续吃系统字体

**选择**：把 Inter Variable（拉丁）与 Noto Sans SC Variable（中文）连同 OFL 许可证一起放进
`assets/fonts/`，由 `keynote.css` 用 `@font-face` 声明，页面只引用本地相对路径。

**理由与实测**：

- 渲染是「逐帧截图」，字体必须离线可用。CDN 会引入网络不确定性，
  与「同一帧永远渲染出同一画面」直接冲突；本机实测中还发现渲染链路走本地静态服务，
  挂外部域名的字体在断网时会静默回退，而回退**不报错**——只会让成片换一副字。
- 继续吃系统字体栈的问题已经被项目自己记录过（`visual-spec.md` 的「字体」一节：
  不同机器字宽有差异、Linux CI 可能没有中文字体），但一直停留在「可选增强」。
  本次把它变成默认路径。
- **中英混排的行盒不会跳变**：本机 Chromium 实测（100px 字号，`line-height: normal`），
  Noto Sans SC 与 Inter 的单行盒高度都是 132px（1.32 em），混排结果也是 132px。
  因此不需要给字体打补丁重写度量；但排版本层仍然**显式指定行高**，
  不依赖字体默认度量——这是唯一能保证跨字体跨平台一致的做法。
- Inter 声明了 `USE_TYPO_METRICS`，Noto Sans SC 没有；两者行高又是同一个值，
  说明当前 Chromium 的度量合成方式对这两支字体一致。该结论已实测，不靠推测。

**被否决**：把字体做成 npm 依赖在构建期拉取。项目没有前端构建步骤，
引入 package.json 只为拿两个文件，会让「克隆即可渲染」多一步且多一个包管理器依赖。
字体文件是**资产**而不是依赖，直接入库更简单、更可复现。

## 决策 2：引入成熟体系，但以令牌与 DSL 落地，而不是引入工具类框架

**选择**：引入外部成熟设计的**结论**（模块化字号阶、8pt 网格、亮度序表面、对比度下限、
留白预算），以一份自有 CSS 令牌文件 + 一个排版引擎模块落地；不引入 Tailwind 这类
需要构建步骤的工具类框架。

**理由**：

- 本项目的画面由**帧号推导**（禁止 CSS `animation`/`transition`），
  工具类框架的主要收益在「快速拼装交互界面」，与逐帧确定性渲染的收益面几乎不重叠；
- 引入构建步骤会打破「网页是纯静态文件、本地静态服务直接托管」这条链路，
  也让 Skill 的「AI 直接写网页」多一层编译心智负担；
- 真正决定观感的三件事——**字号阶、间距网格、对比度与留白**——本身就是数值，
  写成令牌比写成工具类更可检验、更容易被机检读取。

**被否决**：直接铺 Tailwind 或 Open Props 全集。前者需要构建，后者会引入大量
与视频无关的语义（主题、组件变体），而本项目真正稀缺的是**约束**，不是选项。

## 决策 3：排版从「试错」改为「测量后取档」

**选择**：新增 `assets/typography.js`，提供 `fit()`（在字号阶上取可容纳的最大档）、
`balance()`（均衡断行）、`optical()`（行首标点悬挂）、`emWidth()`（实测字宽）、
`measureAdvance()`（解释器实测参考宽度）。字宽来自**真实测量**：
解释器宽度用 `Range.getBoundingClientRect()` 量、每个字的字宽用 canvas `measureText`
按字符量并缓存。

**理由**：

- 项目已有一条实测结论：「衬线字体下单字宽约 1.02 × 字号，14 字一行必须降到 66px」
  ——这是**事后量出来的**，写进注释让人下次手工复用。它应该由引擎计算，
  否则每换一次字体、每换一次主题都要重新试错一遍；
- 「一行不超过 14 字」这类硬换行要求，本质上是在**没有排版引擎**的前提下，
  用人工断行回避「浏览器自动折行把重点词放到下一行」的问题。
  有引擎之后，断行可以按语义与字数均衡计算，人工断行仍被支持但不是唯一手段；
- 取档而非自由缩放：自由缩放会让每一幕的字号都略有不同，
  而「同帧字号种类受限」正是层级感的来源。取档把「可读」与「层级」分开解决。

**降级**：字体未加载或测量不可用时，`fit()` 返回按字数与经验系数估算的结果并标记为估算，
排版闸门据此报告「未实测」，而不是假装通过。

## 决策 4：观感闸门独立编号 K1–K6，与 C 系列分开

**选择**：设计宪法新增一节 K1–K6（留白预算 / 强调色占比 / 字号种类 / 对齐基线 /
正文对比度 / 卡片纪律），在 `review.py` 里与既有 C 系列**分开报告、分开计数**。

**理由**：

- C 系列回答「这是不是废片」，K 系列回答「这像不像发布会级别的画面」。
  两者混在一个总分里，会让「画面很空但结构齐全」的片子看起来及格；
- 每条 K 都给出**实测数值与阈值**（例如「留白率 32%，阈值 40%」），
  而不是「太满了」这种无法执行的结论——这是[视觉评审量表](../../../../.agents/skills/article2video/references/visual-review-rubric.md)
  对「必改」条目提出的同一要求；
- 不能实测时报告**跳过并说明原因**，绝不计为通过。假自动判定比没有判定更危险。

**阈值来源**：留白预算与字号种类上限取自可编码的设计研究结论
（信息幕 ≥40% 留白、hero 幕 ≥60%；单帧字号种类 ≤4）；
强调色占比参考 60-30-10 结构的 10% 分量，取 2%–15% 为健康区间；
正文对比度取 WCAG AAA 的 7:1（投影与压缩会吃掉一部分对比度）。

## 决策 5：预设显式启用，默认画面不变

**选择**：设计语言通过 `visual.preset`（值 `keynote`）启用；
分镜不声明时，共享页面加载的样式与脚本与本次变更前**逐帧一致**。

**理由**：

- 既有两支视频（`examples/why-effort-fails`、`videos/never-fear-interviews`）
  是项目的观感基线与回归样本，不能被一次「升级」顺带改掉；
- 设计语言的引入会改变字体、字号阶与间距，等于重排版面，
  这对新作品是收益，对已发布作品是无谓的返工；
- 显式启用让「这支片子用了哪套设计语言」写在分镜里，而不是藏在样式表里，
  符合项目「单一真源」的一贯做法。

## 决策 6：`typography.js` 不进渲染契约

**选择**：排版引擎是**可选增强**，与 `figures.js` 同级，页面不引用时 `timeline.js`
与渲染脚本的行为完全不变。渲染契约 `window.__A2V__` 不新增字段。

**理由**：渲染管线只关心「给定帧号画出什么」，排版引擎只是页面画得更好的手段。
把它写进契约会让契约承担与渲染无关的职责，也让未使用它的既有页面承担兼容成本。

## 风险与未决

- **字体体积**：中文可变字体约 17MB，拉丁约 0.9MB。仓库已经在 200MB 量级，
  可接受；若将来需要瘦身，应按**字体子集化 + 多份子集**处理，而不是回退到系统字体。
- **`optical`（标点悬挂）与均衡断行的交互**：首版只处理行首标点，
  不做行尾压缩（`text-spacing-trim` 在各平台支持度不一），
  因此极端窄列下仍可能出现略微松散的标点边界。
- **对比度是按令牌算的，不是按最终合成算的**。当文字压在渐变或图形上时，
  仍需要 `review.py` 的帧量测兜底；K5 只保证「令牌层面成立」。
