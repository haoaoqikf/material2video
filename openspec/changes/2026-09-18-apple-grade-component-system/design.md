# 设计：组件设计系统收口

## 背景

这一层要解决的是**页面级令牌已经建好、组件级没有跟上**的落差。下面的每条决定
都对应 `proposal.md` 里的一条实测证据；没有证据支撑的取舍不写进来。

## D1 令牌补四族：描边、字重、字距、图形几何

### 描边阶 `--a2v-stroke-1..5`

现状是 2 / 3 / 4 / 5 / 6 五种线宽散在 18 处声明里，没有语义。分档按**用途**而不是
按观感：

| 令牌 | 值 | 用途 | 现有哪些地方落进来 |
| --- | --- | --- | --- |
| `--a2v-stroke-1` | 1px | 发丝边界（卡片、面板的边框） | 现有 `--a2v-hairline` 的宽度侧 |
| `--a2v-stroke-2` | 2px | 次级结构（虚线辅助、坐标刻度） | `figures.css` 的 2px 两处 |
| `--a2v-stroke-3` | 3px | 数据描边（承载数据形状的轮廓） | 3px 两处 |
| `--a2v-stroke-4` | 4px | 图形主体（构件、轨道、节点边界） | 4px 十处（当前多数） |
| `--a2v-stroke-5` | 6px | 焦点与运动轨迹（强调弧、进度） | 6px（`.loop-arc`）与 5px（`.stair-jump`） |

两条取舍：

- **不是「一条 2px 走天下」。** 竖屏 1080 宽在手机上实际显示约 400–500 逻辑像素，
  1px 的线在缩放后接近消失；但把所有线抬到 4px 会让次级结构（虚线轨道、刻度）
  与数据描边一样重，层级反而塌掉。分档的理由与图形颜色的分类同源：
  问的是「这条线消失了，观众还看得懂吗」。
- **5px 归入 6px 那一档。** 现有的 5px 只出现在阶梯的跳跃弧上，语义与
  `.loop-arc` 的 6px 完全相同（都是「运动轨迹」）。保留两个只差 1px 的档位
  等于给了后人一个随手可选的理由，所以合并。

### 字重阶 `--a2v-weight-*`

规范给的分工是 700–800 / 500–600 / 400，代码里是裸数字。四档：
`regular` 400、`medium` 500、`semibold` 600、`bold` 700。

**上限收到 700，不是 800。** 现有 `.fig-number` 用了 800。Inter 与 Noto Sans SC
都是可变字体，800 在中文上会让笔画粘连（汉字比拉丁的笔画密度高得多），
而「更大的数字」这个诉求已经由字号阶的 `display` 档承担了。
主角数字改用 700 + 走 `display` 档，靠字号拉开层级——这正是
[视觉规范](../../../../../.agents/skills/article2video/references/visual-spec.md)
「层级靠字号拉开，不靠加粗」那句的落地。

### 字距阶 `--a2v-track-*`

16 处 `letter-spacing` 全是字面值（0.14em / 0.08em / 0.06em / 0.04em / 0.02em /
-0.03em …）。按**用法**收成四档：`tight` -0.03em（hero/display）、
`snug` -0.015em（headline/title）、`normal` 0（body）、`wide` 0.06em（caption），
另加 `label` 0.14em（标签与轴名）。

理由：字距是区分「标题感」与「正文感」最廉价的手段，但它的取值只有
「负一点 / 零 / 正一点 / 很正」这几种语义。现有的 0.02 / 0.04 / 0.08 / 0.12
是同一个语义的四个近似值，收成一档不会损失表达力，却让
「为什么这两个标签的字距不一样」不再有答案。

### 图形几何档

节点半径、表面内边距、连线宽度、箭镞尺寸各一档，落到令牌。
现有的 `.vs-head`（箭镞 11×16）与 `placeArrow`（M0 0 L-34 -16 L34 16 Z）
是同一件事的两套写法，收成一份。

## D2 基元与状态：一次实现，八处声明

### 为什么是基元类 + 状态属性，而不是再写一套组件样式

八个组件现在的做法是「各自把表面、标签、连线的长相写在自己的样式块里」。
要统一只有两种办法：**在每个组件里各改一遍**（下一个人加组件时又会漂移），
或者**把共同的部分提出来，组件只声明「我是什么、我现在是什么状态」**。
后者才是「设计系统一致」的落地方式，也是这次改动的核心。

### 状态只有四个

`rest` / `focus` / `muted` / `done`。**没有 `hover` / `active` / `disabled`**——
画面是逐帧渲染的，没有指针，也就没有交互态；硬塞进来只会得到四个永不被置上的属性。
四态对应的是叙事里的四种角色：基准、当前焦点、已被否定、已完成。

| `data-a2v-state` | 语义 | 表面 | 描边 | 文字 | 光晕 |
| --- | --- | --- | --- | --- | --- |
| `rest` | 基准 | `--fig-surface` | `--fig-line` | `--a2v-text-1` | 无 |
| `focus` | 当前焦点（一屏一个） | `--fig-surface` | `--a2v-accent` | `--a2v-text-1` | 内外发光 |
| `muted` | 已被否定的那一侧 | 画布色 | `--a2v-hairline` | `--a2v-text-3` | 无 |
| `done` | 已完成 / 已翻转 | `--a2v-accent-deep` | `--a2v-accent` | `--fig-on-ink` | 无 |

**状态只表达语义，不表达动效。** 不透明度、位移、缩放仍由组件按帧推导——
一旦把「进入 focus 时淡入 12 帧」写进状态定义，时序就有两个真源
（状态层与 `timeline.js` 的配方层），而配方层存在的全部理由就是
「手感只有一处」。同理，状态切换的位置（第几帧点亮）由分镜与组件决定，不由状态层决定。

### 三套旧机制怎么迁

| 旧写法 | 现在 | 迁移后 |
| --- | --- | --- |
| `is-accent` / `is-focus` | 语义即「当前焦点」 | `data-a2v-state="focus"` |
| `is-fact` / `is-after` / `is-flat` / `is-left` / `is-right` | 语义是「翻转/那一侧」 | 语义拆两层：结构位置保留类名，视觉状态用 `done` 或 `muted` |
| `--vs-heat` | 冷热连续量，不是离散状态 | 保留（它表达的是**连续**热度，四态表达不了），但它的端点色改用状态令牌 |
| `--a2v-emphasis-mix` | 强调词褪色进度，也不是离散状态 | 保留 |
| 内联 `height/top` 表达状态（落差尺） | 几何本身就是论证 | 保留几何动画，但表面与描边的**颜色/线宽**改由状态与令牌决定 |

**不追求「消灭所有修饰类」。** 结构性的类名（左/右/翻转前后）与连续量
（热度、褪色进度）不是状态，把它们硬塞进四态只会让四态失去语义。

## D3 容器内文字：几何由内容驱动

飞轮节点的缺陷不是「半径写小了」这一个 bug，而是**先定容器几何、再把文字塞进去**
这个顺序。八个组件里落在固定尺寸容器里的文字有五处（飞轮节点、双向选择节点、
冰山标注、天平载物、阶梯柱顶注）。

做法：

1. 容器先按内容测量后的尺寸定形：SVG 用同帧同步的 `getBBox()` 读文字实际宽度，
   容器半径/宽度 = `max(最小档, 文字半宽 + 内边距)`；
2. 文字超过容器允许的最大宽度时，按字号档降一档再测（复用排版引擎已有的
   `--a2v-ink-*` 档位顺序），降到正文下限仍放不下则由构建期检查报错；
3. **不引入 `textLength` 压缩。** 横向压缩字形会让中文看起来被挤扁，
   比溢出更难看；宁可减少字数或降档。

`getBBox()` 是同步的、只依赖已加载字体与已排版的文本，因此逐帧求值结果稳定，
不违反「画面只由帧号推导」。

### 为什么另外还要一条闸门

内容驱动的几何解决的是「现在这八个组件」，闸门解决的是「下一个人加的第九个组件」。
K8 把 SVG 文字纳入量程后，任何未来的容器与文字不匹配都会在验收里报出来。

## D4 K6 卡片采集：修「量不到」，不是修「判定」

K6 的判定逻辑（圆角 / 描边 / 投影 / 内描边四项中至少三项）本身没问题，
问题是**采集**：只看 `[data-a2v-figure] > *` 且圆角 > 8px 的节点，
于是 SVG 内的圆角矩形与包在包装元素里的卡片全被漏掉，`compare` 一幕
画面上两张卡片、闸门却报「这一幕没有可识别的卡片表面」。

改法：

- 遍历范围从「挂载点的直接子元素」扩到**整幕**；
- 对 HTML 元素照旧读计算样式；
- 对 SVG 元素改用图形自身的几何与描绘特征（`rx`/`ry`、`stroke-width`、
  `fill` 是否为面填充），把它归成同一组四项；
- **确实没有卡片时照旧跳过并写明原因**——「跳过不是通过」这条不变。

**不做的事**：不为了让 K6 好看而放宽阈值（四项 ≥ 3）。量不到就改量法，
量到了不达标就报——把阈值调松是这套闸门最容易走偏的方向。

## D5 兼容：非预设路径逐字节不变

沿用仓库既有手法，三个理由都成立才敢这么做：

1. **基元类不进作用域就没有规则。** `.a2v-surface` 等四条规则全部写在
   `[data-a2v-preset="keynote"]` 作用域内。未启用预设的页面里这些类名
   匹配不到任何声明，计算样式与布局不变。
2. **几何与字号一律写成 `var(--令牌, 原值)`。** 非预设路径取不到
   `--a2v-space-*` / `--a2v-stroke-*` / `--a2v-weight-*` / `--a2v-track-*`
   （它们都在预设作用域内定义），落回原值。
3. **`data-a2v-state` 是新增属性，非预设路径没有任何规则读它。**

回归证据沿用 `examples/declarative-number` 限帧 12 帧成片的 SHA256，
**并且把命令一起记录**：

```bash
uv run python .agents/skills/article2video/scripts/render.py \
  --storyboard examples/declarative-number/storyboard.json \
  --limit-frames 12 --capture-format png
# → A0A94CFC…（67185 字节）

uv run python .agents/skills/article2video/scripts/render.py \
  --storyboard examples/declarative-number/storyboard.json --limit-frames 12
# → CBEBD8BF…（58802 字节）
```

默认口径（JPEG q98）是流水线实际用的那条，两条都要对。
这两个值在本次变更开始时**实机复现过**（同一条命令连跑两次同值）。

**顺带修掉一处陈旧记录**：`keynote-design-system.md` 的「静默失效清单」一直写着
动效升级前的旧值 `DAFDD423…` / `DF1DB75D…`，照它复现不出来；
`docs/PROJECT_PLAN.md` 才有当前值。本次把参考文档改成与实测一致，
并补上一句「哈希是机器与工具链相关的」——它证明的是「本机同一条命令前后一致」，
不是「任何机器上都等于这个值」。**逐字节回归因此不能当作跨机器证据使用**，
跨机器的等价性由「剥掉档位声明后逐像素一致」这类比较来证明。

## D6 顺带修掉：`figures.css` 的字号兜底与字号阶不一致

`keynote.css` 的 `--a2v-ink-*` → 40 / 44 / 60 / 76 / 120px，
`figures.css` 的兜底 → 36 / 38 / 46 / 48 / 56 / 62px。未启用预设时组件跑在阶外，
K3 数不到。**兜底值不改成阶上取值**（那会破坏非预设逐字节不变），
而是加一条测试断言「兜底值集合在两处一致或已登记为例外」，
并把不一致的六处逐条对齐到**同一语义**：

- `--a2v-ink-body` 兜底 36 / 38 → 统一 38（组件内正文，阶外但一致）；
- `--a2v-ink-value` 兜底 46 / 48 → 统一 46；
- `--a2v-ink-lead` 兜底 56 / 62 → 统一 62；
- `--a2v-ink-display` 兜底 124 / 220 / 240 → 保留（装饰引号与主角数字本来就是
  两件东西，各自一档）。

**这是本变更里唯一会改动未启用预设画面的一处**，必须单独确认：
`examples/declarative-number` 只用到数字组件，其页面使用的 `--a2v-ink-*`
兜底若被改动就会改变成片哈希。因此这一步先量出「数字组件实际用到哪几个兜底」，
只对齐**数字组件不用到的**那些；用到的保持原值并登记为例外。

## D7 明确不做：布局坐标不做令牌化

`figures.js` 里有约 696 处数值字面量，其中 176 处在 markup 模板里。
这些绝大多数是**一张图的坐标**：天平立柱在 `M444 372 L444 96`、
圆上节点的角度、阶梯四根柱的高度数组 `[100, 210, 330, 460]`。

**坐标是内容，不是设计令牌。** 把 `444` 换成 `var(--a2v-scale-post-x)` 不会让
画面更一致，只会让读代码的人多跳一层，并且给「调一下这个令牌」制造出
一个本不该存在的旋钮——苹果自己的插画坐标也不会进设计系统。

本次收口的是**样式属性**（线宽、圆角、颜色、字号、字重、字距、间距）
与**状态表达**。判据很简单：这个数字换了之后，**八个组件是不是应该一起变**？
是 → 令牌；不是 → 图稿坐标。`figures.js` 里**内联写样式**（`style.strokeWidth`、
`style.fill`、`style.fontSize`）的部分属于前者，要收口；
`d`、`cx`、`cy`、`width` 这类几何属于后者，保留。

## D8 外部组件评估：不引入

用户允许引入外部组件。评估结论是**不引入运行时依赖**，理由三条：

1. **逐帧确定性**：画面必须只由帧号推导，渲染前有静态扫描禁止
   `Date.now` / `performance.now` / `Math.random` 与 CSS `animation`。
   主流组件库的入场动画都走 CSS 过渡或时钟驱动，接进来等于绕过这条约束。
2. **离线与不走 CDN**：资产自足性有测试守着（不允许外部 URL）。
   引入 CDN 依赖会在断网时静默回退，而这正是仓库反复记录的
   「成片照样出得来，只是变了样」那类缺陷。
3. **问题不同**：这里的组件是**图解**——天平、冰山、差量尺、飞轮，
   它们要回答的是「这幅图有没有完成论证」。通用控件库（按钮、表格、表单）
   解决不了这个问题，而它们能提供的令牌体系本仓库已经有了。

**已经按同一标准 vendored 的部分**：物理弹簧曲线（wobble 1.5.1 · MIT，含许可证）、
Inter 与 Noto Sans SC 可变字体（SIL OFL 1.1，含许可证）。以后评估外部资产
沿用这三条判据，不必重复讨论。

**不排除的方向**（本次不做，写在这里避免误读为已实现）：若将来需要
「图标级」的图形（勾、叉、箭头列表），优先用内联 SVG 的本地图标集，
仍要满足上述三条。
