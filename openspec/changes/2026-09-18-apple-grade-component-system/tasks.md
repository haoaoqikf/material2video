## 12. 下一轮的靶子：强调色"几乎不存在"（K2）

`examples/keynote-baseline` 八幕里**七幕**的 K2 报「几乎没有强调色」，
其中 `opening` 与 `attention` 是 **0.0**——一个强调色像素都没有。

先确认这不是使用量的问题：`figures.css` 里引用 `--a2v-accent` 的地方有 **35 处**，
所以问题不在"没写"，而在两处：

1. **形态太细**。强调色几乎只出现在描边、箭头、短横与圆点上，没有一处是块面。
   实测 `attention` 幕：96% 帧能数到 670px 的**纯**强调色（占比 0.00129），
   而 35% 与 68% 帧里**一个都没有**，最接近的像素是 (106,159,212)，
   与纯强调色 (50,214,255) 的通道最大差是 56——比容差 46 只多 10。
   即便按最宽的一帧算，0.00129 仍低于下限 0.002（≈4150px，约一块 64×64）。
2. **贴合时出现**。强调色元素多在入场末段才淡入，前三分之二帧里画面没有任何焦点色。

两件事要分开判断，不能合并成一个"放宽阈值"的动作：

- **该改组件**：每一幕都应当有一个用强调色**块面**表达的焦点，
  这正是第 5 组「状态迁移」要落地的东西——挂 `data-a2v-state="focus"` 的元素
  由基元层给强强调描边，而不是让每个组件临场决定用多细的线。
- **该改标定**：设计系统自己认可 `--a2v-accent-line`（alpha 0.55）与
  `--a2v-accent-soft`（alpha 0.14）是强调色的合法形态，但 K2 只承认
  与纯强调色通道差 ≤ 46 的像素——**半透明的强调色永远量不到**。
  这是 K2 的系统性盲区：按现在的算法，一个完全用 `--a2v-accent-line` 画的焦点
  会被判成"没有强调色"。
  要不要把 K2 改成量「强调色族」（`accent` / `accent-line` 合成后 / `accent-deep`）
  是一个设计判断，**必须先有第 5 组的落地结果再定**——
  否则就成了"把量不准的闸门调松"，而不是"把画面做对"。

顺序：先做第 5 组（让每幕真的有一个强调色焦点），再看 K2 剩多少缺口，
用那时的数据决定标定该怎么改。

## 13. 下一轮的第二个靶子：留白没有上限，画面成了"孤岛"（K1）

逐帧看图（`compare-96-f0380.png`）发现的问题比令牌层更显眼：

内容块（标题 + 两张卡片 + 一行注）只占画面高度的 **约 31%**（y ≈ 610–1200 / 1920），
上下各有 400–600px 的纯背景。标题在 1080 宽的画布上按手机观看显得偏小，
整屏读起来像"一个孤岛浮在海里"，而不是苹果官网那种**内容撑得起画布**的排布。

根因在闸门：K1 只有下限——「主体幕背景占比 ≥ 60%、其余幕 ≥ 40% 通过」。
实测 `compare` 的背景占比约 **0.85**，远超门槛，于是**死白再多也照样通过**，
连一条提醒都不会有。K1 的提醒逻辑只挂在另一个条件上
（「留白达标但亮到能读的墨迹 < 0.004」），管的是"墨迹太少"，
不是"内容太集中在中间一小块"。

要量的是**构图**而不是背景占比。候选判据（下一轮先用探针量出真实分布再定阈值）：

- 内容块的纵向跨度占画布高度的比例（`compare` 约 0.31，苹果官网的同类版面明显更高）；
- 最大字号占画布宽度的比例（当前标题偏小，"层级清晰"缺少尺度上的依据）；
- 或画面墨迹的纵向分布二阶矩——把"有效内容的高度"与"它落在哪"分开量。

需要注意的是**不能简单地"把内容放大"**：这件事与第 12 节（强调色形态）
是同一个问题的两面——每幕都缺一个**尺度上占主导**的焦点。
所以这一组应当与第 5 组的状态迁移一起做：先确定每幕的主焦点是谁、
它在尺度上占多大，再判断留白是否合理。

数据要落到探针里，不能靠某一帧的目测：先量出八幕各自的内容纵向跨度、
最大字号占比与背景占比，再定阈值，最后才改闸门。

## 15. 已做到的：强调色的形态与量法（第 4 轮）

第 12 节留了两个待判的读法：(a) 组件确实没把强调色用作焦点面，
(b) K2 的纯色色盒看不见设计系统认可的另外三个形态。**这一轮把两个都判了，答案是"都成立"。**

### 15.1 先否掉一个诱人的结论

逐色直方图看出 `attention` 有一片约 0.06 的蓝色面，一开始像是"大面积的半透明强调色"。
读出实际颜色是 **RGB(23,30,43)**——那是 `--fig-surface`（中性表面），不是强调色。
`--a2v-accent-soft`（alpha 0.14）合成出来是 (15,39,47)，暗到只会被读成"一块暗面板"。
四个幕最常见的颜色全是背景梯度。**所以画面上确实没有任何强调色块面**，
K2 说"缺一个焦点"是对的。

### 15.2 K2 对四种已登记的强调色成员里的三种失明

原判据是「与纯强调色逐通道相差 ≤ 46」的色盒。实测距离：

| 成员 | 合成 RGB | 通道最大差 | 色度 |
| --- | --- | --- | --- |
| 纯 `--a2v-accent` | (50,214,255) | 0 | 205 |
| `--a2v-accent-deep`（文档："图形着重色"） | (47,127,168) | 87 | 121 |
| `--a2v-accent-line`（alpha 0.55） | (32,122,146) | 102 | 114 |
| `--a2v-accent-soft-solid`（焦点面填充） | (22,70,95) | 160 | 73 |

`compare` 一幕的焦点**正是** `--a2v-accent-deep`。逐通道色盒也不是感知量——
它同时排斥变暗与变亮的同色。

- [x] 15.2 判据换成**色度（max−min）≥ 50 且色相在强调色 ±30° 内**。
      色度下限画在"中性面 32"与"最暗的族成员 73"之间，背景（4）、
      `--fig-surface`（20）与 `--a2v-accent-soft`（32）被干净排除，
      四位族成员（73–205）全部纳入。**阈值一个数字都没动**（下限仍是 0.002）：
      这不是把闸门调松，是把量错的量对。改完 24 帧里报警的从 17 帧降到 5 帧。
- [x] 15.3 反向测试：中性面、背景、白字、14% 染色必须**不算**；
      族成员四个必须**都算**（`tests/test_review.py`）。

### 15.3 焦点要有块面，不能只有描边

`focus` 态原先只把描边换成强调色。一帧 1080×1920 折算到判据图上只有约 540×960，
2px 描边缩完只剩 1px 左右，抗锯齿一糊就量不到。

- [x] 15.4 `.a2v-surface[data-a2v-state="focus"]` 的填充改为
      `--a2v-accent-soft-solid`（被压暗的强调色）。与 `done` 态一起构成
      rest（中性）→ focus（暗档）→ done（亮档）的三级强调色阶梯，
      而不是让两个状态都只靠描边区分。
- [x] 15.5 `attention` 的焦点标注迁到状态基元：`.berg-callout` 从写死
      `fill: --fig-surface` + `.is-accent` 的 2px 半透明描边，改成
      `a2v-surface` + `data-a2v-state`（焦点用 `focus`，其余 `rest`）。
      `rest` 态给出的填充与描边与原取值**完全一致**，所以只有焦点那一块变了。
      实测该帧的强调色族占比从 0.0013 涨到 **0.0296**；
      画面核对：第三个标注成为无可争议的焦点（青底 + 亮青描边 + 强调色文字），
      另两个保持白描边，颜色克制。

### 15.4 剩下 5 帧是真实缺陷，不用调阈值掩盖

| 帧 | 占比 | 真实原因 |
| --- | --- | --- |
| `opening` 96% | 0.0009 | 强调词按设计褪色（"恐惧退场，动作上场"），焦点转移到 `--a2v-accent-deep` 的角标文字，但只有字形笔画、没成面 |
| `compare` 35% | 0.0017 | 焦点面在入场末段才淡入，前三分之一帧没有焦点 |
| `loop` 35% | 0.0015 | 同上；飞轮四个节点全是 `rest`，没有 `focus` |
| `freedom` 35% | 0.0011 | 同上（阶梯的 `is-focus` 还没迁到状态基元） |
| `one` 全部三帧 | 0.0018 | 焦点是 140px 的强调色大数字——**面积是弱代理**：字形笔画只占整帧 0.18%，视觉上却无可争议是焦点 |

前四项要改的是**时序**（焦点应当早出现、且不要消失），
第五项要判断「面积」对排版型焦点是否是正确的代理量。**两者都不该用调阈值来掩盖。**

**下一轮的靶子**：入场时序（焦点早出现、强调不退场）+ 「面积」对排版型焦点的代理量。

## 16. 已做到的：焦点跟着行进走（第 5 轮）

- [x] 16.2 飞轮：`isFocus = index === arrived % nodeGroups.length`

- [x] 16.3 天平：`load-token`（"一个决定"的令牌面）取**静态** `focus`——

- [x] 16.4 三者都迁到 `a2v-surface` + `data-a2v-state`，删掉 `.stair-bar.is-focus`

## 18. 已做到的：字号阶抬高顶端，数字幕撑得起画布（第 7 轮）

第 17 节把留白的成因查纯了："内容跨度小"里混着的"块自己叠出来的假跨度"已经去掉，
剩下的是**尺度不足**。这一轮从字号阶顶端动手。

### 18.1 根因：预设把主角数字缩小了一半

`.fig-number` 的兜底一直是 `var(--a2v-ink-display, 240px)`。而 `--a2v-ink-display`
是**设计语言层专有的令牌**——未启用预设时它不存在，组件跑在自己的 240px 上；
启用预设后它变成 120px。也就是说：

> 本该是"给组件一个字号阶"，实际做的是**把主角数字从 240px 压到 120px**。

实测后果：数字幕的内容纵向只占安全区 **29%**（120px 的数字 + 91px 的标签
+ 59px 的注 = 394px），八幕里最空。

### 18.2 抬高时撞上的真实不变量

第一版直接把 `--a2v-size-numeral` 定成 400px，测试立刻拦下：

```
相邻档位比例 2.857 超出 1.1–1.6
```

这是**模块化字阶的不变量**（`TestTypeScale::test_scale_levels_are_ordered`），
也是 K3 存在的前提：档位比例忽大忽小，层级就散了。按项目惯例
**不为了让自己的改动过关而放松闸门**，改成补中间档：

| 档 | 字号 | 与上一档的比例 |
| --- | --- | --- |
| hero | 140px | 1.167 |

- [x] 18.4 顺手修掉一个会随加档漂移的隐患：`maxLevelIndex` 的两处兜底
      （没写档名 / 写了不认识的档名）原本写死为**下标 0**。字阶顶端还能继续加档，
