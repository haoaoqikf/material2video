# independent-subagent-review Specification

## Purpose

规定 A 级与 B 级评审的独立执行方式：默认由只读取评审包的独立子代理完成，候选匿名化并先描述后判定；环境不具备独立子代理时允许降级为角色分离自审并显著披露，但不得关闭评审项或声称通过。评审结果写入 `visual-notes.md` 并绑定版本，不新增 CLI 门禁或自动审美评分。

## Requirements

### Requirement: A/B 级评审必须由独立子代理执行

以下 A 级职责 MUST 由独立子代理覆盖，但不要求每项单独调用：冷观众/前 3 秒、文案复述关、三个叙事候选淘汰、两个美术方向比较、风格同族判定、逐场观察复述、第一次与第二次导演审查、扩展全片前核心表达复述、重要返工匿名比较和实质争议独立复核。

以下 B 级职责可分栏合并在阶段报告，MUST 由独立子代理量取或复核：传播潜力反面依据、画面可见文案清单核对、手机尺寸可读性、节奏与等待判断、风格八项指标量取。

独立子代理 MUST 使用新建上下文，MUST NOT 使用继承制作上下文的 fork；MUST 只读取评审包，MUST NOT 读取 `DESIGN.md`、风格契约、分镜、场景源码、旧评审结论与制作理由；盲看阶段 MUST NOT 接收验收条件，观察落盘后仅可提供中性可观察条件以核对原问题。制作助手 MUST NOT 代替子代理撰写观察或判定。

#### Scenario: A 级完成
- **WHEN** 冷观众评审使用新建上下文，只读取前 3 秒评审包，报告由子代理写出
- **THEN** 该评审可记为「已独立评审」，结论可作为阶段证据

#### Scenario: 同一助手切换角色
- **WHEN** 制作助手在同一会话里换一个角色提示后写「独立子代理已通过」
- **THEN** 只能记为「角色分离自审」，不得关闭评审项

#### Scenario: 子代理读取设计文档
- **WHEN** 评审包或任务书包含 `DESIGN.md`、风格契约或旧结论
- **THEN** 该评审无效，重新打包并分配新评审 ID

### Requirement: 评审包必须隔离设计信息并匿名化

评审包 MUST 固定放在 `outputs/review-pack/<review-id>/`，包含 `manifest`、证据文件、中性任务书与空白判定表。`manifest` MUST 记录评审 ID、级别、环节、时间码、显示尺寸、证据文件 SHA-256 与被排除文件。

评审包 MUST NOT 包含设计文档、分镜、场景源码、预期答案、旧评审结论、作者与轮次信息、匿名映射 key。验收条件 MUST 在盲看观察保存后单独提供，不含设计理由；共用证据 MUST 只读、绑定摘要，匿名任务仅暴露中性索引和净化后的证据，MUST NOT 暴露映射与主记录。候选比较 MUST 匿名并使用随机顺序；映射 key MUST 放在评审包外，评审完成后才可打开。

#### Scenario: 候选比较匿名
- **WHEN** 比较三个叙事候选
- **THEN** 候选标为 A/B/C 并随机排序，评审者看不到作者、轮次与采用偏好

#### Scenario: 缺少 manifest
- **WHEN** 评审包没有 manifest 或没有证据摘要
- **THEN** 评审不能作为阶段证据

#### Scenario: 污染检查失败
- **WHEN** 目录中出现作者、方向名、推荐标记或映射 key
- **THEN** 重新打包，旧评审作废，不得局部修补后继续使用

### Requirement: 评审者身份与证据必须可核验

评审记录 MUST 写明执行方式，只允许「独立子代理」「外部评审」「角色分离自审（降级）」三种。记录 MUST 包含评审者标识或调用记录、开始与结束时间、投喂文件清单、隔离方式、评审包 manifest SHA-256 与报告 SHA-256。

无法提供独立调用证据时 MUST 记为「未独立评审（证据不足）」，按降级处理。

#### Scenario: 只有角色标签
- **WHEN** 记录写「独立子代理」但没有投喂文件清单与隔离条件
- **THEN** 视为未完成，补做独立评审或改记降级自审

#### Scenario: 外部评审
- **WHEN** 用户或另一个独立会话按同一评审包完成评审
- **THEN** 可记为「外部评审」，但不得声称真实观众测试或外部导演评审

### Requirement: 评审输出必须先描述后判定

评审报告 MUST 分为两段：第一段只写实际看到的对象、尺度、光源、密度、文字与事件；第二段才写结论与差异项。观察 MUST 含时间码与显示尺寸。判定 MUST NOT 改写观察；先写判定后补观察的报告无效。只有结论、没有具体观察的报告视为未完成。

「像作品」「同族」「继续看」等判断 MUST 附具体帧、时间码与描述，不得单独作为结论。

#### Scenario: 只有结论
- **WHEN** 报告只写「不像作品」或「同族」，没有观察与差异项
- **THEN** 报告未完成，需重做或补充

#### Scenario: 先判定后描述
- **WHEN** 报告先写结论，再补观察内容
- **THEN** 该评审无效

### Requirement: 降级必须披露且不得关闭评审项

只有环境确实不具备独立子代理能力时才可降级；成本、时间与排期 MUST NOT 作为降级理由。降级时 MUST 先尝试独立方式并记录失败原因，再按角色分离自审执行：先只读评审包落盘观察，再对照设计。

降级项 MUST 记为「未独立评审（降级）」，MUST NOT 写成「通过」「冷审通过」「同族」或「像作品」；MUST NOT 计入已解决；MUST 写入交付的覆盖限制。能力恢复后 MUST 重新评审并保留旧记录。

#### Scenario: 无子代理工具
- **WHEN** 当前环境没有可用的独立子代理调用能力
- **THEN** 允许降级继续制作与交付，但评审项标「未独立评审（降级）」并披露

#### Scenario: 降级后写通过
- **WHEN** 记录把降级自审写成「冷审通过」
- **THEN** 视为违反门禁，改为未独立评审并写入覆盖限制

#### Scenario: 未执行
- **WHEN** 某 A 级项没有评审记录
- **THEN** 对应阶段未完成

### Requirement: 评审结果必须写入 visual-notes 并绑定版本

评审结论 MUST 写入作品 `outputs/visual-notes.md` 的「独立评审记录」区块，包含评审 ID、环节、级别、执行方式、评审者、投喂文件、隔离条件、结论、差异项与时间。发现问题 MUST 进入原有问题表。

记录 MUST 绑定准备指纹、成片或候选 SHA-256、评审包 manifest SHA-256 与报告 SHA-256；依赖变化后相关结论失效；未受影响观察仅可附依赖证明与旧版本来源后引用，不得伪装新版本实查。最终全片结论 MUST 重新绑定当前交付文件与完整检查。`visual-notes.md` MUST 直接链接评审报告与需要保留的证据文件。

#### Scenario: 报告未链接
- **WHEN** 记录只写结论，没有链接评审包与报告
- **THEN** 阶段未完成

#### Scenario: 版本变化
- **WHEN** 准备指纹或成片摘要变化
- **THEN** 复查受影响范围，未变观察可证明依赖后引用，最终全片检查仍须绑定当前文件

### Requirement: 评审不得替代确定性检查或用户决策

独立评审 MUST NOT 替代 `m2v qa`、`assets audit`、构建与测试、许可判断、用户意图确认、法律与平台政策判断或真实观众数据。评审者 MUST 只读，发现问题只报告，不修改作品、代码或文档。MUST NOT 用多个子代理投票代替证据。

#### Scenario: 用评审替代 QA
- **WHEN** 字幕对比度或音画时长检查未执行，只写子代理认为没问题
- **THEN** 技术验收仍未完成

#### Scenario: 子代理修改作品
- **WHEN** 评审者直接修改场景代码或分镜
- **THEN** 该评审不再独立，制作助手需重新打包并评审

#### Scenario: 自动审美评分
- **WHEN** 试图把评审结论转成分数或机器通过字段
- **THEN** 不允许；结论保持文字证据

### Requirement: 评审必须区分缺陷风险偏好并限定否决依据

独立评审 MUST 先保存盲看观察，再核对单独提供的中性目标及完整表达窗口；MUST NOT 接收预期答案或作者辩护。必须立即理解与允许延迟理解的目标 MUST 在设计阶段预先声明，MUST NOT 事后为失败改口。盲看证据 MUST 覆盖揭示前后；前三秒只能支持开场观察，不能判定后续核心回报失败。

评审 MUST 区分实际缺陷、创意风险、审美偏好与证据不足。实际缺陷必须包含时间位置、显示尺寸、实际现象、受影响目标及前后文证据；事实、许可、技术和关键可读性仍严格检查。创意风险通过完整段落或候选比较核实，未验证时保留未完成；偏好不直接产生必改项。

去文字、静音、缩略图及运动密度 MUST 作为适用性诊断，不直接否决文字主导、声画协作、静止、重复或抽象表达；形式标签不作为否决证据。有证据的核心缺陷 MUST 返工，制作助手 MUST NOT 用设计意图覆盖；实质分歧 MUST 按原有独立复核解决，允许得出证据不足或非缺陷取舍，不以投票或挑选宽松报告关闭。重要返工报告 MUST 同时记录收益与表达损失。

独立性、匿名化、版本绑定、两名最终评审与降级披露保持不变，不新增评分、审批或 CLI 门禁。

#### Scenario: 静止形成回报
- **WHEN** 镜头停留超过 1.5 秒但完整段落建立期待并兑现
- **THEN** 不因静止时长失败，记录实际作用

#### Scenario: 延迟揭示成功
- **WHEN** 开场局部难辨，完整表达窗口揭示主体与关系
- **THEN** 区分疑问和误读，不以开场截帧否决

#### Scenario: 作者解释替代作品
- **WHEN** 看完完整窗口仍形成核心误解，作者声称故意留白
- **THEN** 记为实际缺陷，设计意图不能豁免

#### Scenario: 偏好与证据不足
- **WHEN** 评审不喜欢文字风格或证据不足以判断听感
- **THEN** 分别记录偏好或覆盖限制，不自动变为已证实缺陷或通过

### Requirement: 分门评审包必须绑定门与检查点

评审包 manifest MUST 记录所属门、检查点 ID、证据类型（设计关键帧、animatic、场景窗口、粗片或最终成片）、显示尺寸、证据文件 SHA-256 与被排除文件。检查点 ID MUST 能被制作记录和唯一问题表引用。

盲审美评审包 MUST 继续排除 `DESIGN.md`、分镜、场景源码、旧结论和匿名映射 key。设计→实现一致性审查 MAY 读取检查点合同与分镜，但 MUST 作为独立评审类型记录，MUST NOT 产出“审美通过”“像作品”或“同族”结论。

#### Scenario: 场景评审包

- **WHEN** 生成 G4 场景单元评审包
- **THEN** manifest 记录门 `G4`、检查点 ID、场景窗口时间码、显示尺寸和证据摘要

#### Scenario: animatic 盲审包

- **WHEN** 生成 G3 animatic 盲审包
- **THEN** 包内只有 animatic 证据和中性问题，不含设计合同、分镜或制作理由

#### Scenario: 一致性审查读取合同

- **WHEN** 对合同与分镜做设计→实现一致性审查
- **THEN** 评审者可读取合同和分镜，但结论只能记录自洽性或结构问题，不能替代盲审美评审

### Requirement: 评审结论必须按门记录并可追溯

评审台账 MUST 记录门、检查点 ID、证据类型、来源文件 SHA-256、评审包 manifest SHA-256、报告 SHA-256、评审者类型与隔离方式。门状态 MUST 使用这些记录作为评审证据；缺少门或检查点绑定的报告 MUST NOT 作为阶段证据。降级评审 MUST NOT 关闭 A/B 级评审项。

#### Scenario: 报告缺少门绑定

- **WHEN** 评审报告没有记录所属门或检查点 ID
- **THEN** 该报告不能用于对应门的通过判定，需重新打包并分配新的评审 ID

#### Scenario: 独立评审可追溯

- **WHEN** 某次 G4 A 级评审使用新建上下文子代理完成
- **THEN** 台账记录门、检查点、manifest 摘要、报告摘要和隔离方式，状态层可据此显示通过

#### Scenario: 降级评审

- **WHEN** G4 评审因环境限制降级为角色分离自审
- **THEN** 状态显示降级旗标，不得把该评审计为独立通过或关闭 A 级评审项

### Requirement: 批量评审与全片评审必须声明覆盖范围

评审 manifest MUST 使用覆盖检查点 ID 列表和场景范围；全片或跨场评审 MUST 使用全片范围并列出适用检查点，MUST NOT 伪造单一检查点。B/C 批量报告 MUST 将每个场景结论回绑到 G4；未覆盖场景 MUST 保持待评审。镜头等级 MUST 与独立评审等级区分。盲审包中的检查点标识 MUST 为中性标识，MUST NOT 暴露预期结论；合同对照图 MUST 只进入一致性包，MUST NOT 混入盲审美包。

G5 包的可播放时间线 MUST 连同必要本地媒体、字幕和音频依赖隔离复制到包内，MUST NOT 通过外部作品目录引用泄露设计或旧结论；无法观看时间线的评审环境 MUST 提供包内分场片段与跨场窗口及完整顺序清单，不额外编码整片，证据不足保持待评审。

#### Scenario: 批量评审漏掉一个场景

- **WHEN** G5 批量报告没有覆盖某个 B 级场景
- **THEN** 该场景 G4 仍待评审，其他已有效覆盖的场景可关闭评审项
