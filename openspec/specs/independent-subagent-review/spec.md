# independent-subagent-review Specification

## Purpose

规定核心样片和最终综合终审等适用独立审核的执行方式：由只读取评审包的独立子代理完成，候选匿名化并先描述后判定；G5 全片粗片由制作助手内部检查，不属于独立评审轮次。环境不具备独立子代理时允许降级为角色分离自审并显著披露，但不得关闭适用评审项或声称通过。独立评审结果写入 `visual-notes.md` 并绑定版本，不新增 CLI 门禁或自动审美评分。

## Requirements

### Requirement: 适用审核轮必须由独立子代理执行

审核计划触发的核心样片和最终综合终审 MUST 由新建上下文、只接收评审包的独立子代理执行；轮次表示职责，不表示必须分派多个代理。G5 全片粗片为制作助手内部检查，不属于独立评审轮次。普通 general 新启动制作周期固定要求一次完整试制 core 盲审和一次 G6 独立终审；风险证据合入试制 core 轮。核心风险在相关高投入实现扩展前按计划评审，当前候选另做 G6 终审。最终代理 MUST 未参与该作品前期评审；split-final 触发时最终 MUST 两名新代理分别覆盖结构与视觉文案且互不读报告。候选数量、镜头等级、第一次重要返工 MUST NOT 自身触发额外代理；substantive-dispute 与 repeated-failure 按计划升级。代理 MUST NOT 接收制作理由、预期答案、源码或旧结论；作者不得代写独立观察。环境降级 MUST 显著披露且不得关闭适用的独立评审项。

#### Scenario: 低风险作品的独立评审

- **WHEN** 普通 general 没有未验证核心风险或风险升级条件
- **THEN** 先由独立代理盲看完整试制窗口，再于 G5 内部检查后由未参与前期评审的新代理执行当前候选综合终审

#### Scenario: 精简审核的适用判断

- **WHEN** 普通 general 的最终综合审查覆盖充分且无升级触发
- **THEN** 一名新的独立代理即可，系统不得要求固定第二人

#### Scenario: A 级完成

- **WHEN** 冷观众评审使用新建上下文，只读取前 3 秒评审包，报告由子代理写出
- **THEN** 该评审可记为开场范围的独立观察；前3秒结论不能替代完整试制窗口或全片终审

#### Scenario: 核心风险触发早期评审

- **WHEN** 审核计划登记了未验证核心风险
- **THEN** 由独立代理观察该风险的适用完整窗口，满足放行条件后再扩展对应实现，最终仍执行当前候选终审

#### Scenario: 同一助手切换角色

- **WHEN** 制作助手在同一会话里换一个角色提示后写“独立子代理已通过”
- **THEN** 只能记为“角色分离自审”，不得关闭适用独立评审项

#### Scenario: 子代理读取设计文档

- **WHEN** 评审包或任务书包含 `DESIGN.md`、风格契约或旧结论
- **THEN** 该评审无效，重新打包并分配新评审 ID

### Requirement: 评审包必须隔离设计信息并匿名化

评审包 MUST 固定放在 `outputs/review-pack/<review-id>/`，包含 `manifest`、证据文件、中性任务书与空白判定表。`manifest` MUST 记录评审 ID、级别、环节、时间码、显示尺寸、证据文件 SHA-256 与被排除文件。

评审包 MUST NOT 包含设计文档、分镜、场景源码、预期答案、旧评审结论、作者与轮次信息、匿名映射 key。验收条件 MUST 在盲看观察保存后单独提供，不含设计理由；共用证据 MUST 只读、绑定摘要，匿名任务仅暴露中性索引和净化后的证据，MUST NOT 暴露映射与主记录。候选比较 MUST 匿名并使用随机顺序；映射 key MUST 放在评审包外，评审完成后才可打开。

#### Scenario: 候选比较匿名
- **WHEN** 比较三个叙事候选
- **THEN** 候选标为 A/B/C 并随机排序，评审者看不到作者、轮次与采用偏好

#### Scenario: 缺少 manifest
- **WHEN** 评审包没有 manifest 或没有证据摘要
- **THEN** 评审不能作为阶段证据

#### Scenario: 污染检查失败
- **WHEN** 目录中出现作者、方向名、推荐标记或映射 key
- **THEN** 重新打包，旧评审作废，不得局部修补后继续使用

### Requirement: 评审者身份与证据必须可核验

评审记录 MUST 写明执行方式，只允许「独立子代理」「外部评审」「角色分离自审（降级）」三种。记录 MUST 包含评审者标识或调用记录、开始与结束时间、投喂文件清单、隔离方式、评审包 manifest SHA-256、报告 SHA-256 与 invocation 摘要。最终轮的 reviewerId MUST 未参与该作品前期评审；同一调用 MUST NOT 作为多个评审者；`split-final` 的两名评审者 MUST 互不读取对方报告。无法提供独立调用证据时 MUST 记为「未独立评审（证据不足）」，按降级处理。

external-review MUST 只作为补充意见，MUST NOT 作为独立完成途径或关闭适用独立项；独立完成继续要求可核验的independent-subagent。

#### Scenario: 同一调用冒充第二名终审

- **WHEN** 同一 invocation 被用于两个 reviewerId 的最终报告
- **THEN** 拒绝导入，不产生通过事件

#### Scenario: 只有角色标签

- **WHEN** 记录写「独立子代理」但没有投喂文件清单与隔离条件
- **THEN** 视为未完成，补做独立评审或改记降级自审

#### Scenario: 外部评审

- **WHEN** 用户或另一个独立会话按同一评审包完成评审
- **THEN** 可记为「外部评审」，但不得声称真实观众测试或外部导演评审

#### Scenario: 导入外部意见
- **WHEN** 外部评审报告合法且有具体观察
- **THEN** 保存补充意见，独立完成项仍等待合格子代理观察

### Requirement: 评审输出必须先描述后判定

评审报告 MUST 分为两段：第一段只写实际看到的对象、尺度、光源、密度、文字与事件；第二段才写结论与差异项。观察 MUST 含时间码与显示尺寸。判定 MUST NOT 改写观察；先写判定后补观察的报告无效。只有结论、没有具体观察的报告视为未完成。

「像作品」「同族」「继续看」等判断 MUST 附具体帧、时间码与描述，不得单独作为结论。

#### Scenario: 只有结论
- **WHEN** 报告只写「不像作品」或「同族」，没有观察与差异项
- **THEN** 报告未完成，需重做或补充

#### Scenario: 先判定后描述
- **WHEN** 报告先写结论，再补观察内容
- **THEN** 该评审无效

### Requirement: 降级必须披露且不得关闭评审项

只有环境确实不具备独立子代理能力时才可降级；成本、时间与排期 MUST NOT 作为降级理由。降级时 MUST 先尝试独立方式并记录失败原因，再按角色分离自审执行：先只读评审包落盘观察，再对照设计。

降级项 MUST 记为「未独立评审（降级）」，MUST NOT 写成「通过」「冷审通过」「同族」或「像作品」；MUST NOT 计入已解决；MUST 写入交付的覆盖限制。能力恢复后 MUST 重新评审并保留旧记录。

#### Scenario: 无子代理工具

- **WHEN** 当前环境没有可用的独立子代理调用能力
- **THEN** 允许降级继续制作与交付，但评审项标「未独立评审（降级）」并披露

#### Scenario: 降级后写通过

- **WHEN** 记录把降级自审写成「冷审通过」
- **THEN** 视为违反门禁，改为未独立评审并写入覆盖限制

#### Scenario: 未执行

- **WHEN** 计划要求的某一轮没有评审记录
- **THEN** 对应阶段未完成

### Requirement: 评审结果必须写入 visual-notes 并绑定版本

评审结论 MUST 写入作品 `outputs/visual-notes.md` 的「独立评审记录」区块，包含评审 ID、环节、级别、执行方式、评审者、投喂文件、隔离条件、结论、差异项与时间。发现问题 MUST 进入原有问题表。

记录 MUST 绑定准备指纹、成片或候选 SHA-256、评审包 manifest SHA-256 与报告 SHA-256；依赖变化后相关结论失效；未受影响观察仅可附依赖证明与旧版本来源后引用，不得伪装新版本实查。最终全片结论 MUST 重新绑定当前交付文件与完整检查。`visual-notes.md` MUST 直接链接评审报告与需要保留的证据文件。

#### Scenario: 报告未链接
- **WHEN** 记录只写结论，没有链接评审包与报告
- **THEN** 阶段未完成

#### Scenario: 版本变化
- **WHEN** 准备指纹或成片摘要变化
- **THEN** 复查受影响范围，未变观察可证明依赖后引用，最终全片检查仍须绑定当前文件

### Requirement: 评审不得替代确定性检查或用户决策

独立评审 MUST NOT 替代 `m2v qa`、`assets audit`、构建与测试、许可判断、用户意图确认、法律与平台政策判断或真实观众数据。评审者 MUST 只读，发现问题只报告，不修改作品、代码或文档。MUST NOT 用多个子代理投票代替证据。

#### Scenario: 用评审替代 QA
- **WHEN** 字幕对比度或音画时长检查未执行，只写子代理认为没问题
- **THEN** 技术验收仍未完成

#### Scenario: 子代理修改作品
- **WHEN** 评审者直接修改场景代码或分镜
- **THEN** 该评审不再独立，制作助手需重新打包并评审

#### Scenario: 自动审美评分
- **WHEN** 试图把评审结论转成分数或机器通过字段
- **THEN** 不允许；结论保持文字证据

### Requirement: 评审必须区分缺陷风险偏好并限定否决依据

独立报告 MUST 先盲看完整窗口落盘，再核对预先声明的中性条件，记录时间码、尺寸和观察。实际缺陷 MUST 指出现象、受影响目标和上下文；风险补证、偏好不自动否决、证据不足不等于通过。事实、许可、技术和关键可读性不得放宽。缩略图、去文字、静音、减法两问、传播判断 MUST 作为按风险选择的诊断工具，不因未逐项回答而阻断完成。实质争议 MUST 新代理复核，不用作者意图覆盖。终审人数 MUST 按审核计划而非固定两人。

#### Scenario: 精简审核的适用判断

- **WHEN** 作品依赖文字表达且没有去文字诊断需求
- **THEN** 不以未提交去文字测试否决，仍须完整检查文字理解与手机可读性

#### Scenario: 静止形成回报
- **WHEN** 镜头停留超过 1.5 秒但完整段落建立期待并兑现
- **THEN** 不因静止时长失败，记录实际作用

#### Scenario: 延迟揭示成功
- **WHEN** 开场局部难辨，完整表达窗口揭示主体与关系
- **THEN** 区分疑问和误读，不以开场截帧否决

#### Scenario: 作者解释替代作品
- **WHEN** 看完完整窗口仍形成核心误解，作者声称故意留白
- **THEN** 记为实际缺陷，设计意图不能豁免

#### Scenario: 偏好与证据不足
- **WHEN** 评审不喜欢文字风格或证据不足以判断听感
- **THEN** 分别记录偏好或覆盖限制，不自动变为已证实缺陷或通过

### Requirement: 分门评审包必须绑定门与检查点

评审包 MUST 记录轮次、门和覆盖场景/检查点/窗口、证据类型、尺寸、摘要与被排除文件。同轮报告 MUST 能引用多个门的检查事件，完整校验后幂等登记，不要求重复报告。blind 包 MUST 排除设计、分镜、源码、旧结论与预期答案；consistency 包 MUST 只在 blind 观察落盘后提供，且只能给目标图与中性条件。两阶段可同一代理执行，一致性不得替代盲审。

manifest文档示例 MUST 从实际打包器的字段构建逻辑生成，文档同步检查 MUST 检测漂移，不手写另一套level/stage/displaySize字段。

#### Scenario: 精简审核的适用判断

- **WHEN** 核心轮同时观察目标图与动态风险
- **THEN** 分步提供净化证据，同一轮覆盖多个适用门，不能将目标条件提前泄露给动态盲看

#### Scenario: 场景评审包

- **WHEN** 生成 G4 场景单元评审包
- **THEN** manifest 记录门 `G4`、检查点 ID、场景窗口时间码、显示尺寸和证据摘要

#### Scenario: animatic 盲审包

- **WHEN** 生成 G3 animatic 盲审包
- **THEN** 包内只有 animatic 证据和中性问题，不含设计合同、分镜或制作理由

#### Scenario: 一致性审查读取合同

- **WHEN** 对合同与分镜做设计→实现一致性审查
- **THEN** 评审者可读取合同和分镜，但结论只能记录自洽性或结构问题，不能替代盲审美评审

#### Scenario: 打包字段改变
- **WHEN** 打包器manifest字段发生变化
- **THEN** 文档同步重新投影同一字段形状，--check在投影未更新时失败

### Requirement: 评审结论必须按门记录并可追溯

独立报告 MUST 记录轮次、门及覆盖范围、来源/评审包/报告摘要、身份与隔离方式，引用检查事件及问题ID。同轮一份报告可绑定多门，不重复写观察；降级不得计为独立通过。新制作周期不得继承旧周期通过，来源不符或缺失不得支持完成。

#### Scenario: 按当前计划追溯

- **WHEN** 本轮证据来源与实际覆盖有效
- **THEN** 按该轮范围判定并保留问题重开权，不要求重复报告

#### Scenario: 报告缺少门绑定

- **WHEN** 评审报告没有记录所属门或检查点 ID
- **THEN** 该报告不能用于对应门的通过判定，需重新打包并分配新的评审 ID

#### Scenario: 独立评审可追溯

- **WHEN** 某次 G4 计划要求的评审使用新建上下文子代理完成
- **THEN** 台账记录门、检查点、manifest 摘要、报告摘要和隔离方式，状态层可据此显示通过

#### Scenario: 降级评审

- **WHEN** G4 评审因环境限制降级为角色分离自审
- **THEN** 状态显示降级旗标，不得把该评审计为独立通过或关闭计划要求的独立项

### Requirement: 批量评审与全片评审必须声明覆盖范围

每次独立评审 MUST 提供一份覆盖表，列明实际范围、时间窗、具体观察、结果、证据引用及问题 ID。G5 内部检查 MUST 记录实际检查范围、发现问题和未覆盖限制，但 MUST NOT 要求独立评审包或逐检查点通过报告。最终独立评审 MUST 覆盖当前候选全片；缺失覆盖 MUST 显示待评审。评审证据不足时不得通过。

#### Scenario: 内部粗片检查发现问题

- **WHEN** 制作助手在粗片检查中发现一场画面、承接或节奏问题
- **THEN** 将观察和问题 ID 记入制作记录，不要求建立独立代理报告

#### Scenario: 最终评审遗漏一个场景

- **WHEN** 最终综合报告遗漏一个场景或必要衔接
- **THEN** G6 保持覆盖不足，补评遗漏范围后才能完成终审

#### Scenario: 局部场景不要求单独独立报告

- **WHEN** 普通场景的 G4 检查已通过，最终综合评审覆盖全片
- **THEN** 不要求为该普通场景另建单独独立报告；若全片检查发现实际缺陷，仍重开对应 G4 问题

#### Scenario: 精简审核的适用判断

- **WHEN** 当前全片评审仅覆盖部分普通场景
- **THEN** 缺少的覆盖范围保持待评审，不要求逐 G4 另建独立报告

#### Scenario: 批量评审漏掉一个场景

- **WHEN** 全片评审漏掉一个普通场景
- **THEN** 全片报告保持覆盖不足，不把该场景已通过的自动 G4 改成缺单独评审

### Requirement: 核心实际片段必须完成适用的同轮目标对照

G4 核心风险窗涉及 static-expression 目标时 MUST 先保存独立盲审，再由同一评审者完成同轮目标对照；缺少有效配对不得授权扩展。对照 MUST 覆盖当前适用检查点并绑定同一检查事件、轮次与当前证据，不增加固定轮次或人数。G2 目标图本身通过不能替代实际片段对照；G6 保留终审对照。

#### Scenario: 只有核心盲审通过
- **WHEN** 有适用目标的 G4 核心窗仅有盲审通过
- **THEN** 状态显示待评审与缺少同轮设计对照，不能扩展该风险

#### Scenario: 对照不独立或对应其他观察者
- **WHEN** 对照为自审、对应其他轮次或未与该通过盲审绑定
- **THEN** 不计有效对照

### Requirement: 独立评审缺陷必须由当前独立复查闭环

自动登记的 REVIEW- 必改项 MUST 保留原范围与必改性质。关闭 MUST 引用同范围、绑定当前上游且证据有效的独立通过复查报告；制作解释、目标修改、降级自审或其他范围报告不得关闭。改变目标后仍 MUST 重新验证并保留失败历史。

#### Scenario: 修改目标后引用旧复查
- **WHEN** 合同或实际实现变化后尝试用旧独立报告关闭问题
- **THEN** 关闭被拒绝，问题保持未完成

#### Scenario: 用制作说明或量测替代独立复查
- **WHEN** REVIEW- 必改项仅附自写说明或自动量测报告
- **THEN** 不能关闭；普通确定性量测问题仍按原规则复查

### Requirement: 动态核心片段必须有实际视频容量

动态核心盲审覆盖 SHALL 至少包含一段可探测、有有效视频流与正时长的过程片段，其视频时长 SHALL 不短于检查窗时长，容差为作品一帧。短片段不得相加冒充完整过程；探测错误 SHALL 标明文件、检查点与原因。同一次操作每份媒体 SHALL 最多探测一次。时长合格不证明时间窗对应、连续性或讲解成立。

#### Scenario: 伪装或过短片段

- **WHEN** 动态核心报告引用伪装视频、无视频流或所有片段均短于检查窗
- **THEN** 导入拒绝该证据，输出具体原因，不用后缀或累计时长代替探测

#### Scenario: 帧容差与缓存

- **WHEN** 多个检查点引用同一合法视频，时长不足不超过一帧
- **THEN** 容量检查通过且同次操作只探测一次，实际表达继续由独立评审判断

### Requirement: 审查执行必须具有真实阶段与全片覆盖证据

阶段报告 MUST 对应真实执行和当前证据，不补造历史，不以空表、口头通过或任务勾选代替观察。独立评审每轮用一份覆盖表说明其实际范围、窗口、具体观察、结果、证据来源及问题 ID；内部粗片检查记录实际检查范围、发现的问题和未覆盖限制，不要求逐检查点重复提交通过说明。最终独立评审 MUST 覆盖当前候选全片；局部采样只能支持对应窗口。未完成必须如实报告。

#### Scenario: 内部粗片发现问题

- **WHEN** 制作助手在 G5 内部检查中发现问题
- **THEN** 记录时间范围、现象与问题 ID，并按原验收条件修复复查，不要求为该记录创建独立代理报告

#### Scenario: 最终评审遗漏全片范围

- **WHEN** 最终候选独立评审未覆盖全片理解、结构、节奏、视觉与文案
- **THEN** 最终评审保持未完成，补足缺失范围后再形成结论

#### Scenario: 最终候选之后补写早期检查

- **WHEN** 缺少实际 G5 内部粗片检查记录
- **THEN** 不得补造历史观察；按当前有效证据执行并记录本次检查及其时间

#### Scenario: 合并方法与审核职责

- **WHEN** 当前作品采用 v2 审核计划执行该职责
- **THEN** 按实际风险与全片覆盖验收，不因固定表单、候选数量或重复报告缺失另加审核

#### Scenario: 只查看部分接触表

- **WHEN** 独立报告只观察部分接触表或局部窗口
- **THEN** 结论只覆盖实际观察范围，不能声称完成当前候选全片终审

#### Scenario: 最终候选之后补写首次审查

- **WHEN** 最终候选之后才发现缺少 G5 内部检查记录
- **THEN** 不补造早期观察，执行并记录当前实际检查

### Requirement: 全片导演审查必须独立于逐场实现与技术验收

G5 MUST 由制作助手执行全片内部检查，覆盖结构、信息推进、节奏、开场承诺、重复、收束与已知视觉问题，并保留重开场景问题的权力。当前候选 G6 MUST 由新独立评审者覆盖全片导演及视觉文案职责；split-final 时按风险计划分派两名隔离代理。MUST 记录具体位置、观察、有效表达和缺陷，不用泛泛形容词或技术 QA 代替。G5 与 G6 不重复创建独立评审轮；减法与唯一画面问题作为按问题选择的诊断，不强制双答。

#### Scenario: G5 发现全片结构问题

- **WHEN** 制作助手在全片内部检查中发现开场承诺与结尾脱节
- **THEN** 登记问题并修订全片结构，不要求为该发现另派独立评审者

#### Scenario: G6 当前候选复核

- **WHEN** 当前候选进入最终验收
- **THEN** 按风险计划完成适用的独立全片终审，不能以 G5 内部检查代替

#### Scenario: 合并方法与审核职责

- **WHEN** 当前作品采用 v2 审核计划执行该职责
- **THEN** 按实际风险与全片覆盖验收，不因固定表单、候选数量或重复报告缺失另加审核

#### Scenario: 每场通过而全片不成立

- **WHEN** 所有场景检查通过但全片结构、节奏或承接仍不成立
- **THEN** 在 G5 内部检查中登记并修复全片问题，最终仍由 G6 独立评审当前候选

#### Scenario: 独立子代理执行审查

- **WHEN** 审核计划要求适用核心或最终独立评审
- **THEN** 由只读取评审包的新建上下文子代理执行，不将 G5 内部检查称作独立评审

#### Scenario: 自审没有外部观众参与

- **WHEN** 环境不支持独立子代理并采用角色分离自审
- **THEN** 明确披露降级，不能声称独立通过或关闭适用独立评审项

#### Scenario: 子代理读取设计文档

- **WHEN** 独立评审包包含设计理由、预期答案、源码或旧结论
- **THEN** 评审无效，重新制作中性评审包并分配新评审 ID

#### Scenario: 无独立子代理能力

- **WHEN** 执行环境无法启动独立子代理
- **THEN** 披露降级和未完成的独立项，不将 G5 内部检查作为替代

### Requirement: 自主视觉复核证据绑定
助手 MUST 在现有复核记录中登记准备指纹、检查对象摘要、时间范围、检查方式和结论。最终全片复核 MUST 同时绑定交付文件 SHA-256。准备指纹变化或交付文件被替换后，相关通过结论 MUST 失效；问题描述可以保留，但 MUST 在有效版本上复查。全局材质、运镜、字幕或混音变化后 MUST 重跑全片帧序列与自动音频替代验收。历史用户确认 MUST NOT 授权当前版本完成。

#### Scenario: 替换成片
- **WHEN** 最终 MP4 的摘要与复核记录不一致
- **THEN** 原全片通过结论无效，助手必须复核新文件后才能标记完成

#### Scenario: 旧记录无版本
- **WHEN** 旧复核记录缺少准备指纹或文件摘要
- **THEN** 记录只作为历史参考，不能支持当前版本完成
