# production-status-ledger Specification

## Purpose

定义制作状态层的门状态、历史记录、场景级状态和只读展示，使制作过程随时可回答当前阶段、当前门和下一步，且状态由证据派生而不是手工维护。

## Requirements

### Requirement: 门状态必须由证据派生

系统 MUST 使用追加式事件日志记录门事件，并 MAY 从中派生当前状态快照。状态 MUST 使用统一词汇：未开始、进行中、待评审、阻断、通过、过期、不适用、等待前置。

`通过` MUST 同时满足：证据文件存在且摘要匹配、上游摘要未变化、审核计划要求的独立评审证据存在、没有未关闭必改。缺少证据时 MUST 显示为未开始、进行中、待评审或过期，MUST NOT 显示为通过。降级评审 MUST 以旗标显示，MUST NOT 计为独立通过。普通场景 G4 检查通过 MUST 可独立关闭，不因缺少 G5 回绑而保持待评审。

#### Scenario: 缺少检查点报告

- **WHEN** 某个门没有对应的证据文件或证据文件已损坏
- **THEN** 该门显示为未开始或待评审，不能根据目录中存在其他文件推断通过

#### Scenario: 上游变化

- **WHEN** 分镜或场景源码摘要发生变化
- **THEN** 依赖的下游门自动显示为过期，旧结论只保留为历史

#### Scenario: 降级评审

- **WHEN** 计划要求的某一轮由角色分离自审完成
- **THEN** 状态显示降级旗标，不得显示为独立通过或计入已解决

自身证据与评审结果 MUST 由 evidenceStatus 保留；prerequisites MUST 列出未完成前置门，ready MUST 仅在自身通过／不适用且前置齐全时为真。本门自身通过但前置未完成 MUST 显示等待前置，MUST NOT 标成自身证据过期。

#### Scenario: 有效证据等待前置

- **WHEN** G1 自身有效而 G0 未完成
- **THEN** G1 显示等待前置且 evidenceStatus 为通过，补齐 G0 后可就绪，无需重做 G1

### Requirement: 状态查询必须显示当前阶段、门、场景和下一步

查询 MUST 只读显示四阶段、G0–G6、自身结果、检查/评审状态、缺失风险覆盖、人数与触发原因、场景摘要和可执行下一步。前置未完成但自身有效 MUST 显示等待前置，缺证据显示缺项，真实依赖变化才过期；未知版本须明确诊断而不默认为通过。精制修订 MUST 根据实际活动证据显示，不因任意 G5 历史事件就推断当前阶段。技术状态与制作状态 MUST 分命名空间，保留既有技术输出。

#### Scenario: 精简审核的适用判断

- **WHEN** G6 无split-final且一份有效综合终审已覆盖全部职责
- **THEN** 独立评审人数显示1/1，不要求structure和visual-copy两个不同身份

#### Scenario: 场景阻断

- **WHEN** 某个场景检查点失败
- **THEN** 查询显示该场景为阻断，列出未关闭问题 ID，并给出可执行的下一步

#### Scenario: 回到长期未处理的作品

- **WHEN** 制作助手在新会话中查询作品状态
- **THEN** 查询显示当前门、最后有效证据、过期项和下一步，无需重新阅读全部制作文档

#### Scenario: 机器读取

- **WHEN** 其他工具需要读取状态
- **THEN** 查询可输出结构化状态，包含门、场景、证据摘要和未关闭问题 ID

### Requirement: 状态必须支持场景级状态和失效传播

G4 状态 MUST 按场景和检查点细化，至少显示每个场景的通过检查点数、阻断检查点和未关闭问题。设计合同、关键帧、分镜、场景源码、准备指纹或成片摘要变化时，状态 MUST 沿摘要链把受影响的下游门标记为过期，并 MUST 保留旧事件为历史。

#### Scenario: 单个场景阻断

- **WHEN** 某个场景的检查点计数不符
- **THEN** 该场景显示阻断，其他已通过场景保持通过，作品整体当前门仍为 G4

#### Scenario: 全局设计变化

- **WHEN** 设计合同发生变化
- **THEN** 关键帧、分镜、场景、粗片和终审门按依赖关系标记过期

### Requirement: 状态层不得成为审批或导出门禁

状态层 MUST NOT 新增用户审批、MUST NOT 阻断正式导出，MUST NOT 改变既有 `validate`、`prepare`、`render` 的验收行为。状态通过仅表示相应门所需证据有效，MUST NOT 由状态程序自行产生审美结论；状态阻断 MUST NOT 单独构成 CLI 拒绝导出的理由。

#### Scenario: 状态阻断但技术门通过

- **WHEN** 状态显示某个场景阻断，但当前材料通过既有技术验收
- **THEN** 正式导出仍按既有规则执行；助手在制作报告中不得宣称制作复核完成

#### Scenario: 状态通过不等于作品通过

- **WHEN** 所有门显示通过
- **THEN** 所需独立评审、问题关闭和最终交付检查均已有当前版本有效证据，助手可据此报告制作复核完成；状态层仅聚合这些证据，不替代审美判断

### Requirement: 状态层必须与唯一问题表和任务清单分工

`outputs/visual-notes.md` MUST 继续作为唯一问题表，保存问题现象、处理历史和复查依据。状态层 MUST 只引用问题 ID，MUST NOT 复制问题详情。OpenSpec 任务清单 MUST 继续作为工作计划，MUST NOT 用勾选状态替代门证据。

#### Scenario: 状态引用问题

- **WHEN** 状态卡显示未关闭问题 `V07`
- **THEN** 问题现象、修改和复查记录只在唯一问题表中，状态层提供链接或 ID

#### Scenario: 任务已完成但门未通过

- **WHEN** 某个任务勾选完成，但对应门的证据或评审缺失
- **THEN** 该门仍显示未完成，任务勾选不构成通过依据

### Requirement: 每个门必须有确定的证据与适用条件

系统 MUST 从当前审核计划派生所需独立职责和人数：G0/G1无审美人数，G2按静态风险，G3映射及条件结构评审，G4自动检查及指定核心窗评审，G5一份全片粗片审查，G6当前QA及一名新代理综合终审（split-final时两名）。同轮报告允许多门绑定。G2 不适用须有依据；G3的自动映射不可跳过。普通场景 G4 MUST NOT 等待 G5 回绑。通过 MUST 同时满足摘要有效、范围覆盖、独立性及无未关闭必改；降级不得算独立通过。状态 MUST 分列自身证据、前置条件和就绪，不把等待前置当作过期。

#### Scenario: 精简审核的适用判断

- **WHEN** G4 普通场景检查通过且核心风险已验证
- **THEN** 下一步直达 G5，不产生普通场景待批量回绑的循环

#### Scenario: B/C 批量评审尚未完成

- **WHEN** 普通场景G4检查均通过，尚无G5批量报告
- **THEN** 普通G4关闭，直接开展G5全片粗片，不再等待回绑

#### Scenario: 没有 A 级或结构风险

- **WHEN** 作品无静态、结构或核心未决风险且有适用依据
- **THEN** G2不适用，G3只验证映射，粗片与最终各一轮

### Requirement: 状态事件必须可登记、重放并处理异常

证据登记与评审导入 MUST 在完整验证之后幂等写入，支持同轮多门覆盖；历史事件有唯一ID、作品/制作周期、时间、范围、上游与来源摘要。旧周期事件不得授权新周期。并发写入串行、快照原子、查询只读；损坏历史不能据以通过，显式修复先保留原件。唯一问题表 MUST 记录问题ID、状态、必改、范围、caughtAt/catchableAt、复查证据与基线引用；状态只引用问题，不复制详情；解析失败阻断判断并保护基线。

#### Scenario: 精简审核的适用判断

- **WHEN** 一份核心轮报告绑定三个检查但其中一项来源无效
- **THEN** 整份拒绝，不留下两个通过的部分成功事件

#### Scenario: 日志尾部写入中断

- **WHEN** 日志末尾存在未完成记录或中部记录损坏
- **THEN** 只读查询报告损坏位置，完整前缀可用于历史展示但不得据不完整历史宣称通过；显式修复入口保留原始损坏文件并重建可验证日志

#### Scenario: 快照落后于文件

- **WHEN** 快照显示通过但证据文件已被修改
- **THEN** 查询显示过期且不写文件，显式重建入口再生成快照

### Requirement: 状态扩展必须保留既有技术状态

既有 CLI 技术状态字段与含义 MUST 保持不变，制作阶段、门及场景表 MUST 使用独立命名空间扩展；机器可读输出 MUST 保留既有字段，MUST NOT 用 G0–G6 替换原技术状态。状态查询缺少制作记录时 MUST 显示制作记录缺失或旧流程适用说明，MUST NOT 改变既有技术状态或导出结果。

#### Scenario: 技术候选存在但制作检查未完成

- **WHEN** 当前作品已有有效技术候选而 G4 尚待评审
- **THEN** 原技术候选状态保持不变，新增制作状态显示 G4 待评审
