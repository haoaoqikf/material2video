# production-status-ledger Specification

## Purpose

定义制作状态层的门状态、历史记录、场景级状态和只读展示，使制作过程随时可回答当前阶段、当前门和下一步，且状态由证据派生而不是手工维护。

## Requirements

### Requirement: 门状态必须由证据派生

系统 MUST 使用追加式事件日志记录门事件，并 MAY 从中派生当前状态快照。状态 MUST 使用统一词汇：未开始、进行中、待评审、阻断、通过、过期、不适用。

`通过` MUST 同时满足：证据文件存在且摘要匹配、上游摘要未变化、所需独立评审证据存在、没有未关闭必改。缺少证据时 MUST 显示为未开始、进行中、待评审或过期，MUST NOT 显示为通过。降级评审 MUST 以旗标显示，MUST NOT 计为独立通过。

#### Scenario: 缺少检查点报告

- **WHEN** 某个门没有对应的证据文件或证据文件已损坏
- **THEN** 该门显示为未开始或待评审，不能根据目录中存在其他文件推断通过

#### Scenario: 上游变化

- **WHEN** 分镜或场景源码摘要发生变化
- **THEN** 依赖的下游门自动显示为过期，旧结论只保留为历史

#### Scenario: 降级评审

- **WHEN** 某个 A 级评审由角色分离自审完成
- **THEN** 状态显示降级旗标，不得显示为独立通过或计入已解决

### Requirement: 状态查询必须显示当前阶段、门、场景和下一步

制作查询 MUST 显示当前管理阶段、当前证据门、门状态表、场景级状态、下一步动作和最近历史。查询 MUST 支持查看完整历史和机器可读输出。查询 MUST 为只读操作，MUST NOT 修改材料或产物。

#### Scenario: 场景阻断

- **WHEN** 某个场景检查点失败
- **THEN** 查询显示该场景为阻断，列出未关闭问题 ID，并给出可执行的下一步

#### Scenario: 回到长期未处理的作品

- **WHEN** 制作助手在新会话中查询作品状态
- **THEN** 查询显示当前门、最后有效证据、过期项和下一步，无需重新阅读全部制作文档

#### Scenario: 机器读取

- **WHEN** 其他工具需要读取状态
- **THEN** 查询可输出结构化状态，包含门、场景、证据摘要和未关闭问题 ID

### Requirement: 状态必须支持场景级状态和失效传播

G4 状态 MUST 按场景和检查点细化，至少显示每个场景的通过检查点数、阻断检查点和未关闭问题。设计合同、关键帧、分镜、场景源码、准备指纹或成片摘要变化时，状态 MUST 沿摘要链把受影响的下游门标记为过期，并 MUST 保留旧事件为历史。

#### Scenario: 单个场景阻断

- **WHEN** 某个场景的检查点计数不符
- **THEN** 该场景显示阻断，其他已通过场景保持通过，作品整体当前门仍为 G4

#### Scenario: 全局设计变化

- **WHEN** 设计合同发生变化
- **THEN** 关键帧、分镜、场景、粗片和终审门按依赖关系标记过期

### Requirement: 状态层不得成为审批或导出门禁

状态层 MUST NOT 新增用户审批、MUST NOT 阻断正式导出，MUST NOT 改变既有 `validate`、`prepare`、`render` 的验收行为。状态通过仅表示相应门所需证据有效，MUST NOT 由状态程序自行产生审美结论；状态阻断 MUST NOT 单独构成 CLI 拒绝导出的理由。

#### Scenario: 状态阻断但技术门通过

- **WHEN** 状态显示某个场景阻断，但当前材料通过既有技术验收
- **THEN** 正式导出仍按既有规则执行；助手在制作报告中不得宣称制作复核完成

#### Scenario: 状态通过不等于作品通过

- **WHEN** 所有门显示通过
- **THEN** 所需独立评审、问题关闭和最终交付检查均已有当前版本有效证据，助手可据此报告制作复核完成；状态层仅聚合这些证据，不替代审美判断

### Requirement: 状态层必须与唯一问题表和任务清单分工

`outputs/visual-notes.md` MUST 继续作为唯一问题表，保存问题现象、处理历史和复查依据。状态层 MUST 只引用问题 ID，MUST NOT 复制问题详情。OpenSpec 任务清单 MUST 继续作为工作计划，MUST NOT 用勾选状态替代门证据。

#### Scenario: 状态引用问题

- **WHEN** 状态卡显示未关闭问题 `V07`
- **THEN** 问题现象、修改和复查记录只在唯一问题表中，状态层提供链接或 ID

#### Scenario: 任务已完成但门未通过

- **WHEN** 某个任务勾选完成，但对应门的证据或评审缺失
- **THEN** 该门仍显示未完成，任务勾选不构成通过依据

### Requirement: 每个门必须有确定的证据与适用条件

系统 MUST 按下表判定门完成，所有门都 MUST 无本范围未关闭必改、证据摘要匹配且上游有效；不适用 MUST 有可核验理由，MUST NOT 等同缺失证据。

| 门 | 必需证据与完成条件 |
| --- | --- |
| G0 | 当前输入、事实与许可审查；不适用项说明 |
| G1 | 合同解析、设计声明 ID/帧窗/文字状态/定量主张一致性报告，不依赖源码 |
| G2 | A 级或核心段落的独立关键帧、来源核验及所需独立盲审；无适用段落时可不适用 |
| G3 | 实际分镜映射、时间线一致性报告；存在 A 级或结构风险时另需 animatic 及独立结构时序评审，否则仅 animatic 子项不适用 |
| G4 | 逐场检查点断言、适用量测、人工替代核验及所需独立评审；B/C 评审可在 G5 批量执行并回绑 |
| G5 | 当前粗片的跨场结构与首次导演独立评审，以及回绑的 B/C 报告 |
| G6 | 当前成片技术 QA、全片完整证据、既有两名隔离代理终审、交付与来源检查 |

G4 MUST 分列检查与评审状态；B/C 检查通过但待批量评审时，G4 总状态为待评审且允许开展 G5。状态优先级 MUST 为：当前依赖变化导致过期优先，其次当前有效证据中的未关闭必改导致阻断，其次待评审、进行中、未开始；满足完整通过条件或不适用条件时分别显示通过或不适用。当前门 MUST 是最早未关闭适用门；下一步 MUST 考虑允许在 G5 完成的 B/C 评审，避免要求等待自身。阶段映射按工作流规格执行。

#### Scenario: B/C 批量评审尚未完成

- **WHEN** A 级 G4 已通过且全部 B/C 检查通过，B/C 仅缺独立评审
- **THEN** 当前门显示 G4 待评审，下一步是生成 G5 包进行批量评审，MUST NOT 阻止 G5 活动

#### Scenario: 没有 A 级或结构风险

- **WHEN** 作品没有 A 级、核心段落或结构风险，且记录已核验的适用性判断
- **THEN** G2 可不适用，G3 仍须完成分镜一致性，仅 animatic 子项不适用

### Requirement: 状态事件必须可登记、重放并处理异常

系统 MUST 提供明确的证据登记、评审导入、问题更新、基线创建/清理与快照重建入口；生产命令成功写出证据后 MUST 追加事件，失败 MUST NOT 留下成功事件。事件 MUST 具有唯一 ID、作品及版本 ID、事件类型、时间、范围、证据摘要和上游摘要；重复导入 MUST 幂等。并发追加 MUST 串行化，快照 MUST 原子替换。查询 MUST 只读检查当前证据，MUST NOT 为同步状态追加事件或更新快照。

唯一问题表 MUST 在 `outputs/visual-notes.md` 内提供可解析问题块，至少含 ID、状态、必改标识、门/场景/检查点、caughtAt、catchableAt、复查证据及受保护版本引用；现象与处理历史仍在同一文件，不另建问题数据库。问题更新入口 MUST 同时更新该块并登记其摘要；外部编辑后查询 MUST 以当前块重新判定，历史不能覆盖当前事实。解析失败 MUST 显示阻断诊断并保护所有可能引用的基线。

#### Scenario: 日志尾部写入中断

- **WHEN** 日志末尾存在未完成记录或中部记录损坏
- **THEN** 只读查询报告损坏位置，完整前缀可用于历史展示但不得据不完整历史宣称通过；显式修复入口保留原始损坏文件并重建可验证日志

#### Scenario: 快照落后于文件

- **WHEN** 快照显示通过但证据文件已被修改
- **THEN** 查询显示过期且不写文件，显式重建入口再生成快照

### Requirement: 状态扩展必须保留既有技术状态

既有 CLI 技术状态字段与含义 MUST 保持不变，制作阶段、门及场景表 MUST 使用独立命名空间扩展；机器可读输出 MUST 保留既有字段，MUST NOT 用 G0–G6 替换原技术状态。状态查询缺少制作记录时 MUST 显示制作记录缺失或旧流程适用说明，MUST NOT 改变既有技术状态或导出结果。

#### Scenario: 技术候选存在但制作检查未完成

- **WHEN** 当前作品已有有效技术候选而 G4 尚待评审
- **THEN** 原技术候选状态保持不变，新增制作状态显示 G4 待评审
