# material-library-organization Specification

## Purpose

让已经收集和索引的素材能够长期积累、按主题组织并跨显式工作库浏览，减少重复选材与寻找成本；所有组织信息与相似提示均保留实际媒体、来源和使用依据的独立身份，不替代事实核实或采用判断。

## Requirements

### Requirement: 标签收藏和主题集合

素材库 MUST 支持为已登记媒体设置标签、收藏与主题集合，支持读取、修改、移除及过滤；组织信息 MUST 在进程重启后保留，独立于不可变来源、媒体与索引。未知媒体、非法标签与无效输入 MUST 在写入前明确拒绝。

#### Scenario: 收藏素材并按集合找回
- **WHEN** 为一件媒体添加标签与主题集合并收藏，再重新打开库
- **THEN** 能按标签、收藏和集合筛选找回，媒体摘要及来源许可保持不变

### Requirement: 显式多库统一浏览

系统 MUST 为一个或多个显式工作库生成统一的本地浏览入口，支持文字、标签、收藏、集合筛选，并显示缩略图、尺寸、时长、来源及组织信息。跨库同名 ID MUST 保持库身份，不混淆路径；浏览 MUST 不隐式下载、索引或扫描其他目录，不自动修改正式作品。浏览页面 MUST 正确转义不可信文字并限制联网与可执行内容。

#### Scenario: 两个工作库同名媒体
- **WHEN** 显式选择的两个库包含相同 ID 但不同媒体
- **THEN** 页面分别显示它们及所属库，筛选和后续命令使用正确工作库

### Requirement: 相似镜头仅作为分组建议

系统 MUST 能对现有有效视觉索引中的图片或带时间窗口镜头给出相似分组，支持显式相似度与规模预算。不同模型空间 MUST 分开处理；结果 MUST 保留各成员的媒体、窗口、关键帧及相似依据，不把连锁相似自动当作相同内容，不合并来源或删除媒体。缺索引与预算截断 MUST 明确披露。

#### Scenario: 不同编码的相似画面
- **WHEN** 两个不同字节身份的素材具有足够相似的有效视觉索引
- **THEN** 可以作为同组建议查看，但原文件和两条来源关系均保留
