# driving-route-video Specification

## Purpose
提供与金融时间序列及通用讲解同级的自驾路线视频类型，用可追溯的真实高速优先驾车轨迹制作确定性二维小车动画。在线采集与离线成片分离，使起终点可替换、相同材料可复现，并以上海到郑州的首个作品验证路线、镜头与无声交付。

## Requirements

### Requirement: 独立自驾路线材料与生命周期

系统 MUST 提供 `driving-route` 类型，以独立的 `request.json` 和 `route.json` 执行初始化、校验、准备、片段预演、完整渲染、状态及可选评审，MUST NOT 要求 general storyboard。请求 MUST 声明起终点地址、所属城市、画面名称、高速优先策略及视频时长；初始化默认30秒。路线 MUST 记录请求摘要、定位结果、实际路线端点、明确坐标系、有序分段坐标、道路名称、总距离、提供方、采集时间及来源使用依据。画幅 MUST 固定1920×1080、60 fps；时长 MUST 为大于6秒的整数，首尾各保留3秒，剩余时间行驶。

#### Scenario: 初始化与更换端点
- **WHEN** 初始化 driving-route 作品并设置任意受支持的起终点
- **THEN** 创建独立类型材料模板；补齐有效真实路线后可制作，无需 general 分镜，且不把上海郑州写死为唯一端点

#### Scenario: 不完整与非法材料
- **WHEN** 材料仍含占位、缺少来源、坐标非有限或越界、无可行驶路线、时长非法，或显式输出画幅帧率与类型不一致
- **THEN** 校验指出字段及原因，拒绝准备和渲染，不以示意坐标填充真实路线

### Requirement: 高速优先在线采集与凭据隔离

`m2v driving-route fetch --project <目录>` MUST 先核验当前用途的数据留存、二维衍生画面及视频发布使用依据，再使用环境变量 `M2V_AMAP_KEY` 调用高德端点定位及高速优先驾车规划，并保存可被离线制作消费的材料。Key MUST NOT 写入材料、响应快照、日志、异常或 Git。定位 MUST 与请求城市和具体地点相符；歧义 MUST 报错，不擅自选择第一个地点。成功结果 MUST 绑定当前请求；取数失败 MUST 保留旧材料不变，MUST NOT 发布半份新材料。

#### Scenario: 取得真实路线
- **WHEN** 使用依据已核验、Key 有效、端点唯一匹配且服务返回有效驾车路线
- **THEN** 保存真实路线及来源，优先高速但保留真实进出城路段，不编造高速名、轨迹、距离或沿途城市

#### Scenario: 取数条件不满足
- **WHEN** Key 缺失、授权范围未落实、定位有歧义、请求超时、服务拒绝或路线响应无效
- **THEN** 命令明确失败，不暴露凭据，不损坏已有有效材料，也不切换虚构路线或其他提供方

### Requirement: 离线制作与材料绑定

`validate / prepare / preview / render` MUST 只读取已保存材料，MUST NOT 在线定位、算路、获取底图或因缺少Key而请求重新登录。请求变化后旧路线 MUST 不再授权准备或导出；路线材料、来源记录、画面实现或渲染参数变化 MUST 使相应准备记录或完整候选失效。相同有效输入与参数重复导出 MUST 复用既有摘要有效候选。

#### Scenario: 断网与无Key制作
- **WHEN** 已有有效材料、字体及构建资源，环境断网且未配置地图Key
- **THEN** 校验、准备、预演和正式渲染仍可执行，不发生外部网络访问

#### Scenario: 请求与路线不再匹配
- **WHEN** 更改起终点、城市、策略、画面名称或时长而未重新绑定有效路线
- **THEN** 拒绝复用旧路线并提示重新 fetch；不得仅使用旧准备记录继续交付

#### Scenario: 候选失效或复用
- **WHEN** 路线或渲染实现已变，或相同有效输入再次导出
- **THEN** 前者重新准备并生成绑定新输入的候选，后者复用摘要有效候选，不重复编码

### Requirement: 真实轨迹连续性与确定性行驶

系统 MUST 验证道路分段可按服务返回顺序连续连接，并在统一坐标系与投影中绘制，MUST NOT 把缺失路段直接跨接。小车 MUST 按累计距离推进，位置位于真实轨迹上，车头平滑跟随局部方向，MUST NOT 通过按坐标点序号匀速造成跳跃。路径简化 MUST 不改变路口连接或使车辆切出可见道路；同一帧的车、轨迹、路段强调与镜头状态 MUST 与执行顺序、机器速度和挂钟无关。

#### Scenario: 弯道与不均匀采样
- **WHEN** 轨迹点密度不均或经过连续弯道
- **THEN** 小车沿累计距离平稳前进，车头不在角度跨界时突然翻转，已走路线终点与小车位置一致

#### Scenario: 分段断裂
- **WHEN** 相邻道路段端点不能在已声明容差内连续连接
- **THEN** 校验失败并定位段号，不绘制跨缺口直线

#### Scenario: 帧重现
- **WHEN** 分别直接计算同一帧或按不同顺序读取帧
- **THEN** 所得位置、朝向、路线进度和相机状态一致

### Requirement: 二维地图镜头与信息呈现

画面 MUST 使用北向简洁二维路线图、起终点及主要高速名称，MUST NOT 依赖卫星图、三维地形或完整在线底图。默认30秒 MUST 按3秒全程建立、24秒行驶、3秒拉远收束组织；显式时长只调整中段行驶时间。镜头 MUST 平稳跟随并为前进方向留视野，开场完整呈现全程及起终点，结尾返回全程且到达状态可辨。必要来源署名 MUST 按来源要求显示并避免遮挡主体；其他文字只承担主题、地点、道路名称和结果，不添加制作说明。视频压缩行程 MUST NOT 冒充实时车速或实时导航。

#### Scenario: 上海到郑州首例
- **WHEN** 制作上海人民广场至郑州二七广场首例
- **THEN** 画面标上海与郑州，显示所获真实高速路线，小车从上海端驶至郑州端，片末展示完整已行驶路线

#### Scenario: 跟随与拉远
- **WHEN** 从全程镜头进入行驶并在到达后收束
- **THEN** 镜头连续过渡，地图保持北向、小车始终可见；当前视域内承担信息的道路和地名不被不合理裁切或重叠遮挡，全程及两端完整呈现要求适用于开场与收束

### Requirement: 无声交付与首例独立验收

完整交付 MUST 通过当前材料绑定、画幅、帧率、时长和无音轨自动验收，预演 MUST 不覆盖正式成片且不作为正式生成前置条件。首例制作完成 MUST 另外有独立子代理对当前候选的路线、贴路转向、镜头衔接、地名可读性及全程建立收束执行视觉评审并关闭必改项；自动技术通过 MUST NOT 代替该结论。作品材料、真实响应与媒体 MUST 留在忽略的内容目录，MUST NOT 加入 Git。

#### Scenario: 无声完整输出
- **WHEN** 有效作品执行正式渲染
- **THEN** 输出绑定当前输入的1920×1080、60 fps、约定时长MP4且不含音轨，并保留溯源和候选验收记录

#### Scenario: 首例仅技术通过
- **WHEN** 首例技术验收通过但缺少当前候选独立视觉评审或仍有必改项
- **THEN** 允许报告技术交付，不能报告首例制作完成，相关实施验收任务保持未完成
