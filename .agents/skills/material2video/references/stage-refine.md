# 精制修订与技术排查

首要问题：要修复哪个已确认问题，如何避免丢掉已经有效的表达？

## 必做

1. 修订先按[修订入口](video-revision.md)确定受影响范围、阶段和基线；读取原问题与当前证据，不重开无关选案。
2. 按依赖范围修正构图、尺度、时序、文字、资产和声音。保持事实、许可、模型与画面一致；材料变化后重新 prepare。修改必须落在可编辑材料上：生成产物是派生文件，不能代替可编辑材料，也不得只用改后的 MP4 冒充修订。
3. 记录修复收益及悬念、节奏、情绪或可读性损失。原问题沿唯一问题表闭环，不能仅写“已优化”。
4. 在同一完整窗口与显示条件下复查；有目标图时沿用先盲看后同轮对照。连续两轮同类修复无改善时按既有策略比较不同机制或剪辑。

## 排查只展开相关专项

- 场景、字体、ready、时钟、相机：读[运行时契约](code-scene-runtime.md)；出现细线、轨道或保持段问题再读[运行时排错](code-scene-troubleshooting.md)。
- 源文、分镜、时间轴：读[材料与分镜](article-to-storyboard.md)和[分镜契约](storyboard-schema.md)。
- 素材、声音与许可：读[素材声音](article-media-and-sound.md)；旁白变化另读[配音契约](voice-and-rhythm.md)。
- 评审、过期证据、状态或问题关闭：读[检查点契约](checkpoint-gates.md)与对应的[评审执行](subagent-review.md)。
- 需要运行命令：查 README 和实际 --help，不依赖复制的旧命令。

## 完成与回退

局部修复复查本窗及相邻衔接；机制、目标或主线改变按[回退路径](production-workflow.md#核心样片与全片粗片的回退决策)重做受影响独立验证，保留失败历史。技术限制不能靠作者说明豁免表达问题。必改项关闭后进入最终验收；排错成功不等于制作完成。
