# 配音与字幕

## 当前契约：分镜 v4 / 媒体 version 4

以下字段名和时间语义以 V4 为准；本文件后续音色、缓存、混音与编码说明继续适用。

- 每个有口播的 `stage` 声明 `narrationSegments` 与 `beats`；禁止字符串 `narration`。口播按 stages 顺序拼接。
- 输入文章必须先通过[输入审查](input-review.md)；正文与最终拼接口播均为130～170字（目标约150字）。声明总时长和配音派生的实际全片时长均须35～45秒。
- `m2v prepare --project <目录>` 在配音请求前验证输入审查有效，再生成媒体；配音后检查实际总时长并把结果写入 `standardCheck`。超限可保留诊断材料，但正式渲染被阻断。
- 媒体 `stages` 与分镜同序，保存每阶段实际 `durationInFrames` 和 WAV 路径；`resolvedBeats` 放在媒体根级，区间使用全片全局帧并含 `stageId`。
- 音效使用 `stageId`，不再使用旧 `sceneId`。字幕、对象轨道、镜头和音轨全部使用同一累计后的全局阶段边界。

入口：

```bash
uv run m2v prepare --project videos/article-narrative/<slug>
uv run m2v validate --project videos/article-narrative/<slug>
uv run m2v preview --project videos/article-narrative/<slug>
uv run m2v review-template --project videos/article-narrative/<slug>
uv run m2v render --project videos/article-narrative/<slug>
```

## 工作流

1. 含口播的每个阶段必须写分段口播 `narrationSegments` + `beats`；静音阶段省略两者。
   分镜契约 v4 不接受字符串 `narration`。
2. `m2v prepare --project <目录>` 校验当前分镜并生成配音、字幕及派生时间轴，写入作品 `outputs/`。
3. `m2v validate --project <目录>` 检查材料、媒体清单、字幕和 WAV 时长。
4. `m2v preview --project <目录>` 生成完整预演；再用 `m2v article keyframes --storyboard <分镜>` 生成技术体检和关键帧材料，并完成人工评审。
5. `m2v render --project <目录>` 在准备、完整预演和评审都仍绑定当前材料时输出正式视频。

省略 `--media` 时保留原无声模式，成片名为 `silent.mp4`；分镜里的 `narrationSegments` 不会自动触发联网或配音，
但会在日志中提示本次按无声导出。composition 读取的分镜在渲染前由媒体清单派生
（时长由实际口播派生），不由命令行替换其内容。路径推导规则见 [目录约定与输出路径](paths-and-outputs.md)。

带 `--media` 的预览、评审与渲染会把派生分镜落盘为媒体目录里的
`storyboard.effective.json`，契约页与 Remotion 的 props 都指向它——composition
的时长由 props 中的 `mediaTimeline.stages` 推导，原始阶段声明保持不变；
若遗漏媒体时间轴，画面会按声明时长走，与音轨派生时长不一致，导致总帧数校验失败或阶段抽帧错位。
渲染用的是输出目录旁的临时副本，随渲染销毁；预览与评审写媒体目录里的固定文件，
下次预览自动覆盖。代码场景清单与作品归属仍按原始分镜路径解析。

## 语音与字幕

使用 [edge-tts](https://github.com/rany2/edge-tts) 7.2.x，默认 `zh-CN-XiaoxiaoNeural`、`+0%`；`--voice` 指定音色，
`--rate=-10%` 调整语速，`--force` 强制重建。首次合成需要联网；服务可能变化，
缓存音频可离线复用，不承诺再次强制生成时波形完全相同。

每个口播阶段采用 WordBoundary 事件，将 100ns 时间单位转换为秒，从原文恢复标点后按句断开。
长句仅在真实词边界拆分，每条最多 28 字符。不支持逐字高亮、导入录音或段级语速与停顿。
音频损坏、时间戳缺失/倒退/越界、时间戳文字未覆盖原文时失败，不猜测字幕时长。
如果服务把数字或缩写改写成读音导致文字不匹配，请将 `narrationSegments[].text` 写成明确的口语文本。

v4 镜头、对象状态、口播和字幕共用 stages 派生出的单条全局时间轴。镜头推拉或焦点变化不会改变媒体阶段边界；媒体准备阶段不重置状态，也不执行图像匹配或节点复制。

分段口播按**原文顺序**消费词边界：每个词块按它在完整口播文本里的字符起点归到
所属段，段末恢复出来的标点允许落到下一段开头（它本来就没有独立时间），但词本身
跨过段边界即失败——那说明分段切在词中间。重复短语因此不会被映射到前一处。
任何一段拿不到词块、或词边界没有覆盖完整口播，同样失败而不猜测。

无口播阶段的实际帧数按该阶段声明时长保留；口播阶段按 TTS 的实际 WAV 边界推导帧数，并按累计帧数计算音频拼接位置，避免逐阶段取整误差累积。
音频统一解码为 24000Hz、单声道、16bit PCM WAV，按派生时间轴补静音并拼接。
按累计帧数计算采样位置，避免逐幕取整误差累积。字幕时间以视频开头为零点，
采用开始包含、结束不包含的区间；SRT 输出四舍五入到毫秒。

## 媒体清单 version 4

媒体清单独立于分镜版本，由程序生成，不建议手工编辑。

| 字段 | 含义 |
| --- | --- |
| `version` | 媒体清单版本，当前为 4 |
| `source` | 完整 v4 原分镜快照，用于网页一致性检查 |
| `sourceFingerprint` | 对原分镜排序键、紧凑 UTF-8 JSON 求 SHA-256 |
| `voice` / `rate` | 合成所用音色和语速 |
| `stages` | 与源分镜同序，每项含 `id`、实际 `durationInFrames`、阶段 WAV 相对路径 `audio`（静音为 null） |
| `resolvedBeats` | 根级全片时间轴，含 `stageId`、`beatId`、全局开始/结束帧、动作和目标 |
| `cues` | 全局字幕列表，每项含秒数 `start`、`end` 与字符串 `text` |
| `audio` | 统一 WAV 相对路径，必须在清单目录内 |
| `subtitles` | 完整 SRT 相对路径 |

`resolvedBeats` 是全局派生节拍时间轴，形状为
`{id, stageId, action, targets, meaning, startFrame, endFrame}`，区间按全片 fps **向外取整**
（起点向下、终点向上），并把起点钳到上一段的终点，使相邻区间首尾相接、不因取整
而重叠；起点包含、终点不包含。画面、字幕与配音共用这批边界——少了它，
composition 会退回无声等比例估算，字幕却按真实词边界走，两者在同一帧里各说各话。

读取时校验版本、原分镜指纹、stage ID/顺序/最短时长、字幕区间和统一 WAV 的实际长度，
并对全局 `resolvedBeats` 校验 stage/beat 顺序、重叠、越界与源声明一致性。旧媒体清单不能用于 V4，须重新 prepare；
只改网页样式不用重新合成。预览与导出均使用媒体 `stages` 中的派生时长，
不在网页重新估算配音时长。

## 缓存与失败处理

输出目录内 `cache/` 保存按文本、音色、语速、生成器版本、edge-tts 版本计算键的 WAV 和
字词时间戳 JSON。缓存校验包括音频长度、SHA-256 与时间戳；损坏时重新合成该幕。
未改变的场景复用缓存，改变原时长或画面文案不会重新请求相同口播。

连接超时 10 秒、接收超时 30 秒、单幕请求总超时 90 秒；网络失败最多重试两次，
间隔 1 秒、2 秒。无效参数不重试。日志包含场景、缓存命中与失败原因。

准备过程在输出目录内写临时文件；统一音轨和 SRT 使用新资源名，最后原子替换 `media.json`。
失败保留上次可用清单。旧资源为避免破坏已打开的预览不自动删除；不再使用后可清理整个输出目录。
清单与音轨属于哪篇文章，由它所在的 `videos/<type>/<slug>/outputs/media/` 目录决定：渲染时若 `--media`
不在当前文章的媒体目录内，直接报错而不是跨文章合成。
请将产物放在已忽略的 `outputs/`，生成媒体、清单和缓存均不提交 Git。

## 渲染与验收

字幕由共享网页层绘制，正文留出 180px；预览支持播放、暂停、重播和拖动，音轨为播放时钟。
渲染按帧 seek，不播放音频；先编码画面，再复制视频流合入 AAC 配音，无二次视频编码。
合成时配音统一转码为 **AAC-LC / 44.1kHz / 立体声 / 128k**：清单里的 WAV 是 24kHz 单声道，
但 24kHz 单声道 AAC 会被 Windows 的 Media Foundation 拒绝（`0xc00d36c4`），
44.1kHz 立体声是各平台兼容性最好的组合。画面像素格式固定为 `yuv420p(tv, bt709)`，
原因与对应校验见 [渲染契约](render-contract.md) 的「码流兼容性」。
清单、音轨与字幕都经临时目录原子落盘，之后会把访问权限交回目标目录的继承规则，
原因见 [渲染契约](render-contract.md) 的「交付文件的访问权限」。
最终 MP4 检查视频解码帧数、实际尺寸、帧率、时长及音轨解码长度，时长容差 100ms。
`--limit-frames` 同步裁切音轨和导出 SRT；省略 `--out` 时写入 `previews/`，不覆盖正式成片。
`--no-probe` 仅跳过最终成片验收，不跳过媒体校验。
支持本地音乐及节拍音效混音；自动选曲未实现。

## 配音音色与语速

音色与语速属于**作品属性**，在 `project.json` 的可选 `tts` 对象里声明：

```json
{
  "tts": {"voice": "zh-CN-YunxiNeural", "rate": "-6%"}
}
```

解析顺序固定为「命令行 > 作品配置 > 默认值」，只在 `engine/tts.py` 实现一次：

| 层 | 写法 | 说明 |
| --- | --- | --- |
| 命令行 | `m2v prepare --project <目录> --voice ... --rate=...` | 临时试听用，不改作品文件 |
| 作品 | `project.json` 的 `tts.voice` / `tts.rate` | 作品的正式选择 |
| 默认 | 晓晓 `zh-CN-XiaoxiaoNeural` + `+0%` | 未声明时使用 |

- `voice` 必须是合成服务的音色名（形如 `zh-CN-XiaoxiaoNeural`）；`rate` 为 −50% 至 +50% 的有符号百分比。
- 用 `m2v voices` 看当前可用音色（可用 `--locale all`、`--json`）。这条命令需要联网，只读，不写文件。
  音色**是否真实存在**只在合成时才能确定：准备前不联网是既有约束，所以配置校验只查格式。
- 未声明 `tts` 的作品，使用的音色、语速、准备记录与语音缓存键都保持不变。
- 改音色或语速会让已有语音缓存失效并重新合成，这正是"换声音"应有的代价。

**换音色比调语速更能改变节奏。** 同一篇长稿、同一标点，量测句间停顿：

| 音色（−6%） | 停顿中位 | 最短 / 最长 | 停顿个数 |
| --- | --- | --- | --- |
| 晓晓 | 0.218s | 0.051 / 0.729 | 44 |
| 云扬 | 0.247s | 0.052 / 0.840 | 54 |
| 云健 | 0.306s | 0.050 / 0.736 | 38 |
| 云希 | 0.404s | 0.053 / 0.764 | 47 |

调语速只是把同一套停顿等比拉长（实测比例恒为 1.08），语流密度不变；换音色才会改变
停顿的中位长度与个数。选中音色后再微调语速。

## 阶段语音与混音

v4 将每个阶段的 `narrationSegments[].text` 拼接后合成一次，统一使用上面解析出的音色与语速。
`narrationSegments[].speech`（段级语速及前后停顿）在 v4 中被拒绝，不参与当前配音。
实际语音时长向上取整到帧，再留出 12 帧稳定阅读时间；缓存按阶段文本、音色、语速和媒体契约版本区分，音乐不进入语音请求缓存键。

```json
{
  "soundtrack": {
    "music": {"sourceRef": "assets/bed.wav", "gainDb": -24, "loop": true, "fadeInMs": 500, "fadeOutMs": 500},
    "effects": [{"sourceRef": "assets/drop.wav", "stageId": "structure", "beatId": "b2", "offsetMs": 0, "gainDb": -12}]
  }
}
```

sourceRef 为分镜目录内本地相对路径，不支持 URL、绝对路径、.. 或反斜线，解析后不可越界。gainDb 为 −60 至 0；loop 默认 false；淡入淡出 0–60000ms，默认各 500ms；音效偏移为 ±60000ms 内整数，起点不得越出所属阶段，尾部可跨阶段，全片末尾裁切。最多 128 音效，缺失或损坏素材使 prepare 失败且旧清单保持有效。

旁白二遍 loudnorm 目标 −16 LUFS/−1 dBTP；静音保留。音乐默认 −24 dB，讲话时额外压低 10 dB，攻击/恢复 80/250ms（重叠包络合并）；音效默认 −12 dB。混音限制到 −2 dBFS 以留编码余量，AAC 编码后量测真峰值；超过 −1 dBTP 时降低增益重新合成，最多三次，否则失败。增益修正不改变时间轴。

清单 v4 保存 `narration`（原拼接旁白 WAV）、`soundFingerprint`、`soundAssets`（素材相对清单路径和 SHA-256）。`audio` 为最终混音 WAV，预览和导出共用。读取检查声音配置与素材摘要，变更后重新 prepare；V1–V3 媒体清单拒绝用于当前渲染。素材和媒体目录整体迁移时相对关系须保留。

媒体派生 props 携带 `subtitleCues`，共享 composition 按当前帧绘制字幕并预留字幕安全区；源分镜不能手写该字段。A4 核对字幕文本、顺序及真实词边界派生的 beat 区间，要求字幕与 beat 的边界相差不超过一帧。

## 通用片音床

通用类型（`general`）的计划可以声明同一份 `soundtrack.music`：作品目录内本地相对路径的音床素材、
增益、循环与淡入淡出，字段含义与上表一致。素材要求与文章类型相同，做法见
`examples/buffer-smoothing/assets/generate.py`（原创合成、无第三方采样、按 CC0 分发）。

```json
{
  "soundtrack": {
    "music": {"sourceRef": "assets/bed.wav", "gainDb": -26, "loop": true, "fadeInMs": 3000, "fadeOutMs": 4000}
  }
}
```

- **音床素材必须能无缝循环**。混音用 `-stream_loop -1` 铺满全片，接缝不连续就会在每个循环点响一下。
  判据不是「首尾采样值接近」，而是「末采样到首采样的步进不超过素材内部的最大相邻步进」：
  频率取循环长度的整数分之一、漂移用相位调制，才能让循环点与信号内部同样平滑。
- 声明音床后，音轨不再是逐场景轨，而是**整片一条母版轨**：先按全片帧边界拼出旁白，
  再按字幕讲话区间生成闪避包络与音床混合。口播保持清晰、音床在讲话时被压低。
- 改音床素材或任一参数都会让准备记录过期，必须重新 prepare。
- **`soundtrack.effects` 当前不渲染**：通用场景没有 beat 轴，给不出音效起点的可信锚点，
  声明它会让计划校验失败并说明原因，而不是猜一个位置。
- 本作品目录属于被忽略的内容目录，音床素材与生成器都不入库；只有做法（本文件）留在仓库里。
