# 独立子代理评审

制作助手知道自己的设计意图和后续内容，无法可靠冒充第一次观看者。本文规定适用审核的独立执行方式；审核适用性由[检查点契约的审核策略](checkpoint-gates.md#审核计划与风险触发)决定。环境不具备时降级为角色分离自审并显著披露，不得据此关闭评审项。

本文只规定评审方式与证据，不新增 CLI 命令、运行时字段或自动审美评分。

评审者可以读取[Frontend Design](../../frontend-design/SKILL.md)与[运动设计](../../motion-design/SKILL.md)作为观察词汇和方法，但两者不是评审包内容，不改变隔离、轮次、人数、问题分级或门禁。评审仍须先盲看落盘，再对照中性条件；不得把两个 skill 的上游默认判断直接当作否决依据。

## 与 CLI 可选评审的区别

- `m2v review-template` / `m2v review` 生成的 `outputs/review.json` 是**可选工具**，不阻断导出。
- 本文的适用审核轮是**制作完成条件**：缺少有效记录时，对应阶段保持未完成。
- 两者可以并存，但不能互相替代。

## 术语

| 术语 | 含义 |
| --- | --- |
| 独立子代理评审 | 新建上下文的子代理，只接收评审包，不接收设计文档或制作理由 |
| 外部评审 | 用户或另一个独立会话，接收同一评审包 |
| 角色分离自审 | 制作助手自己执行，但先落盘观察、后对照设计；**不是独立评审** |
| 降级自审 | 环境不具备独立评审能力时采用的角色分离自审，必须标注并披露 |

不再使用「独立上下文」作为执行方式的说法：它可以指子代理，也可以指同一助手的角色切换，无法核对。

## 审核轮：按计划派生

审核轮、人数与触发条件以[检查点契约](checkpoint-gates.md#审核计划与风险触发)为准。下表只说明各轮如何观察；A/B 表示职责，镜头等级不决定代理人数。代理使用新建上下文，先盲看保存观察，后单独接收中性可观察条件；不接收设计理由、预期答案或旧结论。

| 轮 | 时点 | 覆盖职责 |
|---|---|---|
| 核心样片 | 扩展高投入实现前（有计划风险时） | 每项未验证风险：静态目标图、时序 animatic、动态完整窗口；理解与表现分别判断 |
| 全片粗片 | 完整粗预演后、阶段问题收敛前 | 制作助手内部检查全片结构、信息推进、衔接、节奏与已知问题；不派独立代理 |
| 最终综合 | 当前最终候选技术 QA 后 | 全片检查理解、结构、节奏、视觉、文案与必要文字的手机可读性（示意／实拍边界标注除外）；有目标图时先盲看再同轮对照 |

风险触发统一见[审核策略](checkpoint-gates.md#审核计划与风险触发)；执行时补充以下观察方法：

| 任务 | 触发 | 覆盖职责 |
|---|---|---|
| 实质争议复核 | 核心条件或必改项结论冲突 | 新代理先盲看片段与前后文落盘，再核对中性原条件；不读旧结论，不投票、不挑宽松结论 |
| 连续两轮失败比较 | 同一问题两轮修复仍无改善 | 至少两个实质不同的匿名候选，包含删短、重排或替换机制 |
| 参考风格同族 | 明确要求借鉴具体参考 | 按风格契约匿名比较和量测 |

候选比较、美术方向比较、核心表达盲测和重要返工比较仍是可用方法，但不再由固定候选数量或“首次重要返工”自动触发。核心图形高潮的机制比较、适用诊断及定性观察按[视觉力量设计](visual-creative-direction.md#独立比较与选案)合入现有轮次，不逐镜头另派代理或新增评分。最终视觉审查重新核对当前候选，不能以更清楚或旧粗样通过抵消表现不足。作者预期与力量模板同样不进盲审包。

综合终审须覆盖视觉文案：必要文字与主体在手机尺寸下的可读性（示意／实拍边界标注是次要标记，不以手机可读为要求）、字幕文案一致性、内部引用和重复署名、参考光材质构图运动差距，以及按[诊断适用性](visual-review-rubric.md#诊断测试与适用性)执行手机、200px 缩略图、去文字、静音条件观察，不以字可读替代美术表现。评审者的隔离要求见本页[执行与降级](#执行与降级)，人数以[审核策略](checkpoint-gates.md#审核计划与风险触发)为准。传播反面依据并入轮次报告，不强凑缺陷数量；没有发现时写范围与依据。风格八项指标只按参考任务触发。事实、许可、技术 QA 仍按原检查执行。

## 评审判断与否决边界

性质与测试适用性以[视觉复核](visual-review-rubric.md#缺陷风险偏好与证据不足)为准：实际缺陷、创意风险、审美偏好、证据不足分开记录。事实、许可、技术与关键可读性不放宽；偏好、静止时长或形式标签不能单独否决。

先盲看包含揭示前后的完整表达窗口，保存实际疑问、错误认识、回报时刻及有效表达，再接收独立的中性目标材料。中性材料只能说明设计阶段预先声明的立即／延迟理解目标、检查范围及可观察条件，不包含预期答案或设计理由，不能事后改目标。前 3 秒只支持开场判断，不替代完整段落。

实际必改项须写时间位置、显示尺寸、现象、受影响目标及前后文证据；“像模板”“不够高级”“我没看懂”本身不够。创意风险先补证或比较，未验证的核心风险保持未完成；证据不足不等于缺陷或通过。重要返工同时记录收益与表达损失。

实质争议复核仍由新代理先盲看落盘再核对原条件，不读旧结论、不投票、不挑宽松报告。可以确认实际缺陷、给出有依据的非缺陷取舍或保持证据不足；作者意图不能覆盖有效核心否决。独立性、版本绑定及降级要求不变。

核心轮和终审的对照适用性、覆盖表 `assessment` 与推进条件统一见[审核策略](checkpoint-gates.md#审核计划与风险触发)及[覆盖表契约](checkpoint-gates.md#隔离包与每轮覆盖)。先盲看并落盘，再提供同轮对照包；目标图已通过不能替代实际实现。制作者不能把违反关键采用项的差距仅解释成“有意偏离”“内容需要”或“可读性取舍”后关闭。

独立失败自动登记为 `REVIEW-` 必改项，复查者必须查看修复后的当前证据，按原失败范围和观察类型重新判断。关闭直接引用已导入的有效独立通过报告；改变目标须保留失败历史并重做相关验证，涉及改变用户明确要求时才请求用户决定。两轮未改善按现有替代方案比较执行，不增加例行审批。

核心样片独立评审与 G5 全片内部检查都支持[推进与回退决策](production-workflow.md#核心样片与全片粗片的回退决策)：评审者只记录核心评审中实际观察到的问题现象、完整窗口、影响与证据；制作助手结合试制限制作出回退决定并记录 G5 实际检查。不能要求盲审者仅凭画面断言所有技术路线不可行，也不将技术解释混入盲包。设计／技术根本失败可首次即回退，无需等待两轮；粗片未精制和纯偏好不单独构成强制回退。四种推进决策写入制作记录正文，不作为独立报告新 JSON 字段；独立评审失败保持原报告与必改项，制作助手不能自行用重设计说明豁免。

## 讲解机制的隔离观察

适用镜头的实际观察问题与判断方式统一见[讲解关系的观察](visual-review-rubric.md#讲解关系的观察)。
沿用现有核心评审与终审轮及报告 observations、coverage；G5 是内部检查，不新增粗片独立评审轮或独立评分。

1. 盲包只提供当前媒体、完整事件窗口、有序时间码证据与必要前后文；问题中性询问对象、变化、
   结果、画面与字幕分别提供的信息、疑问与解答时刻，不提示应出现哪种机制或正确因果。
2. 评审者先落盘实际观察，明确播放、采样、声音和显示尺寸的覆盖限制。
3. 再提供单独的中性目标材料，说明预先声明的立即或延迟理解目标、检查范围与可观察条件，
   不给设计理由、标准答案、旧结论或完整 DESIGN.md；保留原盲看记录后写对照结论。
4. 有目标图时沿用现有同轮 consistency 包；没有目标图时沿用原条件核对，不补造图像对照，
   不把文字目标核对计为额外独立审美通过。失败或补证处理只引用
   [关闭规则](checkpoint-gates.md#讲解机制与关键采用项的关闭)。

## 返工候选比较

同一问题连续两轮修复仍无改善时，按[信息推进与返工升级](production-workflow.md#信息推进与返工升级)执行匿名独立比较。首次重要返工只记录收益与损失，不强制另派代理。比较时只投喂同一受影响段落的原版、删短或重排候选及理解衔接所需的前后文，必要时加入重设计事件候选。使用同等制作精度、同一显示尺寸和一致采样方式，保留各版本自己的时间轴与摘要，不强求重剪后相同时间码。

沿用本页匿名化规则，评审者先只接收证据与中性问题，观察落盘后才接收单独的中性原条件，不提供修改假设、设计理由或旧结论。询问看到了什么事件或新增认识、等待用途、理解断层、候选具体差异及采用或淘汰依据，同时比较修复收益及悬念、节奏、情绪、记忆或独特性损失。核心体验受损时继续寻找替代解法，不能以关闭问题数量选案。评审完成后制作助手才揭示映射，回填同一问题 ID 的独立复查结论；无法独立评审时按降级规则披露，不得据此关闭问题。

### 重制的理解、表现与相对改善

沿用重要返工匿名比较及唯一问题表，每次分别记录以下三项，不以可复述代替表现改善，不新增评分：

| 比较项 | 实际观察与依据 |
|---|---|
| 理解 | 看见什么事件，理解什么关系，何时得到新认识，是否有误读 |
| 表现 | 关键变化是否被构图、层次和时序突出；哪里仍不明显 |
| 相对改善 | 改善 / 无明显改善 / 退步 / 证据不足；对应位置、修复收益及悬念、节奏、情绪或可读性的损失 |

这四种相对改善结论是观察用语，不替换问题的四种状态。理解成立但表现未改善时分别记录，不能直接宣称整体改善或关闭原表现问题；证据不足先补证，不以投票或关闭问题数量选案，保留实质争议复核和两轮无改善升级。

比较使用同一显示条件、对应事件窗口和[一致的动态证据标准](visual-review-rubric.md#核心事件的最小动态证据)，各版本保留自己的时间轴。粗样用于选择机制，不能冒充精制效果；比较机制时保持相近制作精度。最终精制候选仍须与[保留基线](production-workflow.md#基线保留)核对原问题、理解、表现及收益／损失，不能把粗样胜出当作最终效果证明。匿名映射、先观察后核对及当前版本绑定规则不变，记录引用原问题 ID。

独立代理观察仅支持其证据覆盖的表达判断，不等同真实观众试映、留存或传播效果；不得将代理愿意继续观看或能复述写成普通观众实测。

## 评审包

共用同版本只读帧、手机图、时间轴与音频测量，以摘要绑定；各任务提供隔离证据视图。匿名任务仅暴露中性索引及净化文件，不泄露源路径、版本顺序、映射或主记录，不允许代理读包外资料。观察落盘后才可在单独材料提供中性原条件，不提供预期答案、设计理由或旧结论。

评审动态事件时，评审包须附完整事件窗口的有序、带时间码帧序列，覆盖建立、关键变化、停留与结果；同一窗口的视频可一并提供，但不能假定评审环境能够播放。采样按事件转折加密，不设统一频率。若评审者无法播放视频，应明确只依据帧序列作判断；帧间运动、接触或连续性无法从证据确认时须标为证据不足，不得用稀疏代表帧替代动态结论。静态表达可注明不适用及其实际检查方式。

动态核心的过程片段须实际探测，不以文件名后缀或端点静帧代替：至少一段可解码、有视频流与正时长的视频，其视频时长须不短于检查窗时长，容差为作品一帧；多个短片段不得相加冒充完整过程。探测失败须标明文件、检查点与原因。该检查只证明可探测与最低长度，不证明时间窗对应、连续性或讲解成立。评审帧包须从局部片段或正式成片抽取，不另行编排画面。


评审包是唯一投喂给评审者的材料，固定放在作品目录：

```
outputs/review-pack/<review-id>/
  manifest.json   评审 ID、级别、环节、时间码、显示尺寸、文件清单与 SHA-256
  frames/         帧序列或静帧
  compare/        参考帧与候选的并排图
  questions.md    只问「你看到什么」，不含设计意图
  verdict.md      空白判定表
```

`manifest.json` 至少包含：

```json
{
  "reviewId": "R01",
  "level": "A",
  "stage": "first-director-review",
  "timecodes": ["00:00.000-00:03.000"],
  "displaySize": "393x699",
  "files": [{"path": "frames/0001.png", "sha256": "..."}],
  "excluded": ["DESIGN.md", "outputs/style-reference.md", "outputs/visual-notes.md"]
}
```

核心视觉事件按[视觉事件设计](visual-creative-direction.md#视觉事件设计)复核；先保存实际变化与新增认识，再核对中性目标。五段式预期答案与设计理由不得进入盲审包。

评审包**不得包含**：`DESIGN.md`、`outputs/style-reference.md`、旧版 `visual-notes.md`、制作理由、候选名称与实现说明、既往评审结论、匿名映射 key。`excluded` 必须如实列出故意排除的文件。

评审包是证据，不是审批单或机器判定字段；不得据此新增导出门禁。

### 设计对照的同轮隔离

核心轮按[核心轮的视觉事件观察](production-workflow.md#核心轮的视觉事件观察)先盲看完整窗口、记录实际变化与新增认识，再核对中性原条件。终审按[设计对照](production-workflow.md#设计对照核心与终审同轮)先保存独立盲看观察，之后使用 `review_type=consistency` 包，对照目标关键帧与中性可观察条件；不修改已落盘的原始观察，不另增代理或审核轮。

完整导演方案由制作助手留在 DESIGN.md 中关联，两个包均不包含设计理由、预期答案或旧结论。对照包可以含目标图，但不得混入原盲包；包 ID、manifest 摘要及报告分别记录，对照包必须引用同一轮 blind 报告。对照只支持是否兑现目标，不计独立审美通过；核心目标改变须更新设计并重做受影响评审。无独立目标图的镜头只验用途与合同，明确图像对照不适用，不补造五维空表。在制作品不追溯补项。

### 匿名化

候选比较与风格同族必须匿名、随机顺序：

1. 制作助手生成映射 key，放在评审包**外**，例如 `outputs/review-packs/<review-id>.key.md`；评审者不得读取。
2. 候选标为 A/B/C 或「组 1/组 2」，随机顺序；随机种子哈希写入 manifest，种子原文写入 key。
3. 证据文件改为中性名称，去除作者、轮次、方向名、版本、日期、「最终版」「推荐版」等提示。
4. 只把评审包目录交给评审者，任务书要求只读取本目录。
5. 评审报告完成后，制作助手才可打开 key 解释结果；不得修改报告中的观察。
6. 风格同族若需要知道哪组是参考，先完成两组描述，再揭示映射；揭示后只写判定。

### 污染检查

评审前逐项确认：

- [ ] 目录中没有 `DESIGN.md`、分镜、场景源码、验收条件、旧结论。
- [ ] 没有作者、轮次、方向名、推荐标记。
- [ ] 映射 key 在包外。
- [ ] 文件名与元数据不泄露信息。
- [ ] 任务书没有引导性判断或预期答案。
- [ ] manifest 列出全部证据摘要。

发现污染时重新打包并分配新评审 ID；旧评审作废，不能局部修补后继续使用。

## 盲测规则

- 候选比较必须匿名、顺序随机；不得用「方案一/方案二」或描述性名称暗示偏好。
- 同一内容与显示宽度；重剪按事件对应，保留各自时间轴与必要前后文。
- 同阶段相关职责可合并调用，报告分栏回答；叙事与美术取舍分别匿名比较。
- 问题只问可观察项：「主体多大、光从哪来、画面密度如何、文字几层、哪里看不清」。
- 不要求评审者给出分数；结论可以是「不同族」「不可辨」「不成立」等定性判断。

## 执行与降级

按以下顺序选择执行方式，并在记录中如实写明：

1. **独立子代理评审**：新建上下文，禁止使用继承上下文的 fork；只投喂评审包。
2. **外部评审**：用户或另一个独立会话；同样只投喂评审包。
3. **角色分离自审（降级）**：环境不具备前两者时使用。先只看评审包并**落盘**观察，再读取设计对照；结论必须标注「未独立评审（降级）」。

独立性判定：

- 只有「另一次独立调用且上下文隔离」才算独立子代理；同一会话换角色提示、让另一个工具总结制作者文本、或制作者代写报告，都只能记为角色分离自审。
- 记录必须包含：评审者类型、标识或调用记录、开始与结束时间、评审包 manifest SHA-256、报告 SHA-256、隔离方式（如 `fresh_context_only_pack`）。
- 无法提供独立调用证据时，记为「未独立评审（证据不足）」，按降级处理，不得关闭冷审项。

降级规则：

- 降级不阻断制作与交付，但对应 A/B 项**不计入已解决**，只能记为「未独立评审（降级）」。
- 降级结论不得写成「冷审通过」「同族通过」「像作品」；只能写「符合设计」及具体观察。
- 降级项必须写入交付的覆盖限制。
- 有独立评审能力却未使用，不得记为降级；只能记为未完成。
- 能力恢复后重新做独立评审，使用新评审 ID 与新评审包摘要；旧降级记录保留，不覆盖、不改写。

## 记录

适用独立评审写入 `outputs/visual-notes.md` 的统一区块。G5 内部检查记录在同一文件的制作检查记录中，不伪装成独立评审：

```markdown
## 独立评审记录

| 评审 ID | 环节 | 级别 | 执行方式 | 评审者 | 投喂文件 | 隔离条件 | 结论 | 差异项 | 时间 |
|---|---|---|---|---|---|---|---|---|---|
| R01 | 冷观众 | A | 独立子代理 | <标识> | review-pack/R01/ | 未提供 DESIGN.md 与旧结论 | 继续看 | | |
| R02 | 第一次导演审查 | A | 角色分离自审（降级） | 制作助手 | | 未提供设计理由 | 结构成立 | | |
```

- 执行方式只允许：`独立子代理`、`外部评审`、`角色分离自审（降级）`。
- 隔离条件必须写「未读取哪些文件」，不能只写「独立」。
- 结论必须回应环节要求；不同族或不通过要写差异项。
- 记录绑定准备指纹与查看范围；依赖变化后相关观察失效；未变观察只附来源版本与依赖证明引用，不冒充新版本实查，每个最终文件仍须完整检查。
- 缺区块、缺执行方式或隔离条件时，对应阶段视为未完成。

## 门禁语义

**适用的独立评审没有执行，不等于通过。** 未执行、未记录、无法证明独立、因环境降级，都只能记为「未独立评审」，不得据此关闭适用评审项或声称「像作品」。G5 属于内部检查，不要求独立评审。

| 轮次 | 独立评审通过 | 降级自审 | 未执行 |
| --- | --- | --- | --- |
| 核心样片 | 可按覆盖表关闭计划风险 | 标「降级自审」，不计入已解决，写入覆盖限制 | 对应风险未完成 |
| 全片粗片（G5 内部检查） | 记录实际范围、发现问题及未覆盖限制 | 不适用 | 缺少内部检查记录时制作与迭代未完成 |
| 最终综合（含 split-final） | 可报告制作复核完成 | 标「降级自审」，不得声称独立验证完成 | 最终验收未完成 |

降级项可以让制作继续并交付，但不能让作品在报告中声称已完成独立验证。交付时须分别写清：哪些项由独立子代理完成、哪些项降级、哪些项未覆盖。

## 不适用

- 逐镜头派代理：成本高且碎片判断不如幕级或全片判断；只在 A/B 级节点派。
- 让代理决定采用哪个方案：代理提供观察与有证据的缺陷判断，最终取舍与责任保留在制作助手；已证实核心缺陷不能自行豁免。
- 纯规则检查：许可、时长、响度、文件摘要等由自动检查或人工核对完成。
- 用作者意图解释抽象表达是否成功：改为先盲看完整表达窗口，再核对预先声明的中性可观察目标；不能提供作者辩护或唯一预期答案，不能因“有意留白”自动放行，也不强求抽象感受只有一种复述。

## 评审输出模板


仅在相应创作、填写或排错任务触发时读取；本页不新增门禁或审核轮次。

评审者必须**先描述后判定**，按顺序填写，第一段写完才能看第二段：

```markdown
## 第一段：只看评审包
- 主体尺度：
- 光源方向与数量：
- 画面密度与留白：
- 文字层级与可读性：
- 事件与关系：
- 我的第一印象：
- 完整窗口中的疑问、误解、回报时刻与有效表达：
- 减法压力测试（问题触发时选填）：若只保留 70%，按顺序删哪些具体场景／镜头／时间范围
- 唯一画面／瞬间（问题触发时选填）：时间码、镜头 ID、画面内容与不可替代理由；过程型作品写完整窗口

## 第二段：对照
- 结论：通过 / 不通过 / 同族 / 不同族 / 证据不足 / 非缺陷取舍
- 具体差异项：
- 性质：实际缺陷 / 创意风险 / 审美偏好 / 证据不足
- 适用诊断、时间位置、显示尺寸、受影响目标及前后文证据：
- 重要返工收益与表达损失（非返工记不适用）：
- 执行方式：独立子代理 / 外部评审 / 角色分离自审（降级）
- 隔离条件：未读取 <文件列表>
```

「不通过」「不同族」必须写出具体差异与位置；不接受「感觉不对」「不够高级」这类无法复查的表述。
