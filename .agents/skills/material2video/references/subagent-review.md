# 独立子代理评审

制作助手知道自己的设计意图和后续内容，无法可靠冒充第一次观看者。本文把需要独立判断的评审环节固定下来：A 级与 B 级一律要求独立子代理；环境不具备时降级为角色分离自审并显著披露，不得据此关闭评审项。

本文只规定评审方式与证据，不新增 CLI 命令、运行时字段或自动审美评分。

## 与 CLI 可选评审的区别

- `m2v review-template` / `m2v review` 生成的 `outputs/review.json` 是**可选工具**，不阻断导出。
- 本文的 A/B 级评审是**制作完成条件**：缺少有效记录时，对应阶段保持未完成。
- 两者可以并存，但不能互相替代。

## 术语

| 术语 | 含义 |
| --- | --- |
| 独立子代理评审 | 新建上下文的子代理，只接收评审包，不接收设计文档或制作理由 |
| 外部评审 | 用户或另一个独立会话，接收同一评审包 |
| 角色分离自审 | 制作助手自己执行，但先落盘观察、后对照设计；**不是独立评审** |
| 降级自审 | 环境不具备独立评审能力时采用的角色分离自审，必须标注并披露 |

不再使用「独立上下文」作为执行方式的说法：它可以指子代理，也可以指同一助手的角色切换，无法核对。

## A 级：必须独立评审

| 环节 | 时点 | 评审包内容 | 必须产出 |
| --- | --- | --- | --- |
| 冷观众 | animatic 或粗预演后 | 前 3 秒帧、关键静帧、静音 | 会不会继续看、以为在讲什么、能复述什么 |
| 文案复述 | 文案定稿前 | 去标题的画面文字清单、对应幕帧 | 用自己的话复述「谁做了什么、新增什么」 |
| 叙事候选淘汰 | 每轮候选形成后 | 三个候选的同段样片，匿名 A/B/C，顺序随机 | 排序、淘汰理由、具体差异 |
| 美术方向比较 | 美术定稿前 | 两个方向的同内容片段，匿名，统一显示宽度 | 采用建议、构图/光/材质/字阶差异 |
| 风格同族 | 风格基准形成后 | 参考帧与本片帧并排 | 同族 / 不同族、具体差异项 |
| 逐场观察复述 | 每场验收开始 | 该场帧序列、文案时间窗、空白复述表 | 问题、事件、新增认识、继续看的理由 |
| 第一次导演审查 | 完整粗预演后、精制前 | 全片帧序列、空白导演观察表 | 主问题、观看动机、核心事件、答案、结尾回报 |
| 第二次导演审查 | 最终候选形成后、完成前 | 最终全片帧序列、空白观察表 | 结构必改项是否关闭、局部修改是否破坏全片 |

## B 级：必须独立评审

| 环节 | 时点 | 评审包内容 | 必须产出 |
| --- | --- | --- | --- |
| 传播反面依据 | 潜力报告前 | 成片、传播因素清单 | 至少 3 条具体反面证据 |
| 可见文案核对 | 全片复核 | 分页帧序列 | 内部路径、多余注释、重复署名、不可辨文字 |
| 手机可读性 | 各阶段定稿 | 393 宽帧（或声明尺寸） | 哪个字或主体不可辨，不写「够不够好」 |
| 节奏与等待 | 粗预演、最终候选 | 全片时间标注帧序列、节奏量测 | 哪段无新信息、等待承担什么用途 |
| 八项指标量取 | 风格契约回填 | 参考帧、本片帧、原尺寸 | 八项数值、与参考的差值 |

## 返工候选比较

同一问题连续两轮无改善时，按[创作流程](creative-production.md#信息推进与返工升级)执行 A 级匿名独立比较。只投喂同一受影响段落的原版、删短或重排候选及理解衔接所需的前后文，必要时加入重设计事件候选。使用同等制作精度、同一显示尺寸和一致采样方式，保留各版本自己的时间轴与摘要，不强求重剪后相同时间码。

沿用本页匿名化规则，评审者只接收评审包、原可观察验收条件与中性问题，不提供修改假设、设计理由或旧结论。询问看到了什么事件或新增认识、等待用途、理解断层、候选具体差异及采用或淘汰依据。评审完成后制作助手才揭示映射，回填同一问题 ID 的独立复查结论；无法独立评审时按降级规则披露，不得据此关闭问题。

## 评审包

评审包是唯一投喂给评审者的材料，固定放在作品目录：

```
outputs/review-pack/<review-id>/
  manifest.json   评审 ID、级别、环节、时间码、显示尺寸、文件清单与 SHA-256
  frames/         帧序列或静帧
  compare/        参考帧与候选的并排图
  questions.md    只问「你看到什么」，不含设计意图
  verdict.md      空白判定表
```

`manifest.json` 至少包含：

```json
{
  "reviewId": "R01",
  "level": "A",
  "stage": "first-director-review",
  "timecodes": ["00:00.000-00:03.000"],
  "displaySize": "393x699",
  "files": [{"path": "frames/0001.png", "sha256": "..."}],
  "excluded": ["DESIGN.md", "outputs/style-reference.md", "outputs/visual-notes.md"]
}
```

评审包**不得包含**：`DESIGN.md`、`outputs/style-reference.md`、旧版 `visual-notes.md`、制作理由、候选名称与实现说明、既往评审结论、匿名映射 key。`excluded` 必须如实列出故意排除的文件。

评审包是证据，不是审批单或机器判定字段；不得据此新增导出门禁。

### 匿名化

候选比较与风格同族必须匿名、随机顺序：

1. 制作助手生成映射 key，放在评审包**外**，例如 `outputs/review-packs/<review-id>.key.md`；评审者不得读取。
2. 候选标为 A/B/C 或「组 1/组 2」，随机顺序；随机种子哈希写入 manifest，种子原文写入 key。
3. 证据文件改为中性名称，去除作者、轮次、方向名、版本、日期、「最终版」「推荐版」等提示。
4. 只把评审包目录交给评审者，任务书要求只读取本目录。
5. 评审报告完成后，制作助手才可打开 key 解释结果；不得修改报告中的观察。
6. 风格同族若需要知道哪组是参考，先完成两组描述，再揭示映射；揭示后只写判定。

### 污染检查

评审前逐项确认：

- [ ] 目录中没有 `DESIGN.md`、分镜、场景源码、验收条件、旧结论。
- [ ] 没有作者、轮次、方向名、推荐标记。
- [ ] 映射 key 在包外。
- [ ] 文件名与元数据不泄露信息。
- [ ] 任务书没有引导性判断或预期答案。
- [ ] manifest 列出全部证据摘要。

发现污染时重新打包并分配新评审 ID；旧评审作废，不能局部修补后继续使用。

## 盲测规则

- 候选比较必须匿名、顺序随机；不得用「方案一/方案二」或描述性名称暗示偏好。
- 同一内容、同一时间码、同一显示宽度；长度不同时截取同一段。
- 一次评审只问一件事：评美术就不问叙事，评文案就不问节奏。
- 问题只问可观察项：「主体多大、光从哪来、画面密度如何、文字几层、哪里看不清」。
- 不要求评审者给出分数；结论可以是「不同族」「不可辨」「不成立」等定性判断。

## 执行与降级

按以下顺序选择执行方式，并在记录中如实写明：

1. **独立子代理评审**：新建上下文，禁止使用继承上下文的 fork；只投喂评审包。
2. **外部评审**：用户或另一个独立会话；同样只投喂评审包。
3. **角色分离自审（降级）**：环境不具备前两者时使用。先只看评审包并**落盘**观察，再读取设计对照；结论必须标注「未独立评审（降级）」。

独立性判定：

- 只有「另一次独立调用且上下文隔离」才算独立子代理；同一会话换角色提示、让另一个工具总结制作者文本、或制作者代写报告，都只能记为角色分离自审。
- 记录必须包含：评审者类型、标识或调用记录、开始与结束时间、评审包 manifest SHA-256、报告 SHA-256、隔离方式（如 `fresh_context_only_pack`）。
- 无法提供独立调用证据时，记为「未独立评审（证据不足）」，按降级处理，不得关闭冷审项。

降级规则：

- 降级不阻断制作与交付，但对应 A/B 项**不计入已解决**，只能记为「未独立评审（降级）」。
- 降级结论不得写成「冷审通过」「同族通过」「像作品」；只能写「符合设计」及具体观察。
- 降级项必须写入交付的覆盖限制。
- 有独立评审能力却未使用，不得记为降级；只能记为未完成。
- 能力恢复后重新做独立评审，使用新评审 ID 与新评审包摘要；旧降级记录保留，不覆盖、不改写。

## 输出模板

评审者必须**先描述后判定**，按顺序填写，第一段写完才能看第二段：

```markdown
## 第一段：只看评审包
- 主体尺度：
- 光源方向与数量：
- 画面密度与留白：
- 文字层级与可读性：
- 事件与关系：
- 我的第一印象：

## 第二段：对照
- 结论：通过 / 不通过 / 同族 / 不同族
- 具体差异项：
- 执行方式：独立子代理 / 外部评审 / 角色分离自审（降级）
- 隔离条件：未读取 <文件列表>
```

「不通过」「不同族」必须写出具体差异与位置；不接受「感觉不对」「不够高级」这类无法复查的表述。

## 记录

所有评审写入 `outputs/visual-notes.md` 的统一区块：

```markdown
## 独立评审记录

| 评审 ID | 环节 | 级别 | 执行方式 | 评审者 | 投喂文件 | 隔离条件 | 结论 | 差异项 | 时间 |
|---|---|---|---|---|---|---|---|---|---|
| R01 | 冷观众 | A | 独立子代理 | <标识> | review-pack/R01/ | 未提供 DESIGN.md 与旧结论 | 继续看 | | |
| R02 | 第一次导演审查 | A | 角色分离自审（降级） | 制作助手 | | 未提供设计理由 | 结构成立 | | |
```

- 执行方式只允许：`独立子代理`、`外部评审`、`角色分离自审（降级）`。
- 隔离条件必须写「未读取哪些文件」，不能只写「独立」。
- 结论必须回应环节要求；不同族或不通过要写差异项。
- 记录绑定准备指纹与查看范围；版本变化后旧记录失效。
- 缺区块、缺执行方式或隔离条件时，对应阶段视为未完成。

## 门禁语义

**没有冷审不等于冷审通过。** 未执行、未记录、无法证明独立、因环境降级，四种情况都只能记为「未独立评审」，不得写成「通过」，也不得据此关闭评审项或声称「像作品」。

| 级别 | 独立评审通过 | 降级自审 | 未执行 |
| --- | --- | --- | --- |
| A 级 | 可标「已关闭」 | 标「降级自审」，不计入已解决，写入覆盖限制 | 阶段未完成 |
| B 级 | 可标「已关闭」 | 标「降级自审」，影响潜力结论与精修判断 | 阶段未完成 |

降级项可以让制作继续并交付，但不能让作品在报告中声称已完成独立验证。交付时须分别写清：哪些项由独立子代理完成、哪些项降级、哪些项未覆盖。

## 不适用

- 逐镜头派代理：成本高且碎片判断不如幕级或全片判断；只在 A/B 级节点派。
- 让代理决定采用哪个方案：代理提供观察与否决，决策与责任保留在制作助手。
- 纯规则检查：许可、时长、响度、文件摘要等由自动检查或人工核对完成。
- 需要设计意图才能判断的抽象表达：独立评审看不到意图，容易把有意留白判成空洞；这类判断由逐场验收结合设计完成。
