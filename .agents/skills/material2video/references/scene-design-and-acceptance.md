# 逐场设计与独立验收

本页配合[循环创作流程](creative-production.md)与[自主视觉复核](visual-review-rubric.md)执行：
全片统一方向确定后，每个场景及其内部镜头都要有独立设计、试制、精制和验收。它不新增运行时
字段、CLI 门禁或用户审批；记录写在作品自己的 `DESIGN.md` 与 `outputs/visual-notes.md`。

场景单元按类型落地：`general` 以每一幕为一个场景、幕内镜头为内部镜头；金融与住宅以关键
段落、转折或图表阶段为一个场景，不强行套用讲解片结构，也不改变各自的声音与画幅契约。

## 操作入口

| 规格 | 操作入口 |
|---|---|
| 全片统一方向、受众、画幅与核心体验 | 作品 `DESIGN.md` 的创作目标与核心体验条目 |
| 每个场景的详细设计 | 本页「逐场设计表」，写入 `DESIGN.md` 或由 `DESIGN.md` 直接引用 |
| 多镜头单场的内部镜头与交界 | 本页「多镜头场景表」；镜头窗口仍由分镜与 `segmentWindows` 实现 |
| 场景试制与精制 | `m2v general keyframes`、`m2v lookdev`、`m2v preview` 的静帧、帧序列与样片 |
| 每场独立验收 | 本页「逐场验收表」，写入作品 `outputs/visual-notes.md` |
| 全片组合复核 | `m2v qa` 的全片帧序列、加密采样、自动音频与逐项人工判读 |
| 百万播放潜力 | [百万播放潜力](reach-potential.md)，最终写入 `outputs/reach-potential-report.md` |

这些入口都不阻断导出。缺少记录、证据不足或表现不成立时，助手不能把阶段或制作标为完成；
CLI 仍只执行既有的技术门禁。

## 制作前：手机关键事件目标

在动手写场景之前，先按作品画幅和声明的手机播放方向，把要看见的事件写成可观察目标：

| 项目 | 要写出的内容 |
|---|---|
| 显示尺寸 | 手机等比例缩放后的 CSS 像素尺寸；例如竖屏 1080×1920 按 393 宽（内容高约 699）复核，设备视口另有时须区分视口与画面内容；横屏按横屏比例缩放 |
| 关键可见事件 | 本片必须被看见的主体、动作或关系，按时间顺序列出，不用「清楚」「震撼」等形容词 |
| 主体辨认 | 观众能否辨认出谁/什么，例如「蓝框车」「红色慢区」；只检查对象是否可区分 |
| 动作理解 | 观众能否看出对象在做什么，例如「车驶出慢区」「后视镜里的红区后退」 |
| 关系理解 | 观众能否说出对象之间的关系或因果，例如「刹车沿车队向后传递」「换的是车不是路」 |

三类目标不能互相替代：主体可辨不等于动作可读，动作可读不等于关系成立。制作前写下的目标
就是后续问题记录的**原验收条件**；后续发现的问题必须回到这里逐条对照。

## 逐场设计表

每个场景一行，所有列都必须落实到本场选择；可以引用共享规则，但不得只写「沿用风格」。

| 列 | 要写出的内容 |
|---|---|
| 场景与位置 | 场景 ID、全片顺序、主线/补充/蓄势/高潮/回扣等作用 |
| 观众问题 | 观众进入本场时的疑问，以及本场结束时新增的认识 |
| 核心可见事件 | 具体对象、动作和结果；不能只有形容词或运镜描述 |
| 叙事任务 | 本场如何推进问题、兑现开场承诺、为下一场留下理由 |
| 美术 | 主体尺度、构图与留白、色彩光影材质、文字层级、代表基准帧 |
| 技术 | 画面与数据来源、同源约束、实现方式、性能风险与验证方法 |
| 动态 | 入场、事件、揭示、离场关键状态；运动路径、观察窗口与时间预算 |
| 文案声音 | 旁白段、画面可见文案、字幕、声音事件与留白 |
| 验收条件 | 本场关键可见事件的手机显示尺寸、可观察通过条件与对应失败现象；分别写主体辨认、动作理解、关系理解与无背景复述（看完能否说出发生了什么、新增什么权利），不得只写「看得清」 |
| 传播贡献 | 本场承担的解释、蓄势、视觉记忆点或分享动机，以及流失风险 |
| 版本证据 | 准备指纹、对象摘要、时间码、显示尺寸与证据链接；问题关闭必须指向修改后的有效版本 |

### 填写演练：普通单镜头场景

> 本段是模板填写演练，不是某支作品的真实制作记录。

| 列 | 填写示例 |
|---|---|
| 场景与位置 | `brake`；第 3 场；主线核心事件 |
| 观众问题 | 「没有事故，拥堵从哪来？」→ 知道一次轻刹车会沿车队向后放大 |
| 核心可见事件 | 1 号车轻点刹车，2～5 号车依次亮起制动灯，车距箭头随之缩短 |
| 叙事任务 | 把抽象的「低速区域」落到一次可跟踪的具体减速上 |
| 美术 | 俯视局部道路占画面 62%；车体不小于 96 px；单一橙红只用于制动灯；标题 76 px |
| 技术 | 车辆位置、灯态与车距全部来自同一轨迹采样，不手绘第二条曲线 |
| 动态 | 0～1.2 秒定位；首车刹车；约每 0.85 秒向后退一辆车；末段留出完整车队观察窗 |
| 文案声音 | 旁白 `b1`/`b2`；画面文案「一次轻刹车」；无额外音效 |
| 验收条件 | 撤去标题后仍能看出灯态向后传递；手机尺寸下能数出至少 4 辆受影响车辆 |
| 传播贡献 | 把生活困惑转成第一次可见因果；风险是车太小、灯态变化不够显眼 |
| 版本证据 | `preparedFingerprint`、`stills/brake.png`、`phone/brake.png`、时间码 00:19–00:29 |

### 填写演练：多镜头单场

> 本段是模板填写演练，不是某支作品的真实制作记录。内部镜头必须首尾相接或明确硬切，
> 并写出交界处观众看到什么、为什么需要换镜头。

| 镜头 | 幕内窗口 | 观众问题 | 画面主体与变化 | 交界与承接 |
|---|---|---|---|---|
| `wide` | 0–4.0 秒 | 这条路上到底发生了什么？ | 环路全景；红色慢区与青色车流同时可见 | 末帧把视线收到蓝框车辆，硬切进入跟拍 |
| `follow` | 4.0–9.5 秒 | 同一辆车会一直慢下去吗？ | 跟拍蓝框车辆；它驶出红区，红区换到后车 | 与上一镜共用红区位置；从车辆背后拉回全景 |
| `recap` | 9.5–13.0 秒 | 刚才看到的说明了什么？ | 环路回看；红区已经换了一批车 | 末帧停在结论句与唯一来源说明 |

## 逐场验收

验收分两步，顺序不能颠倒：

1. **先观察**：按[独立子代理评审](subagent-review.md)由新建上下文的子代理执行；不读取本场设计结论，
   只依据评审包中的帧序列、文案时间窗和量测，复述本场的问题、事件、新增认识与继续观看的理由。
   把复述原样记入 `visual-notes.md`。
2. **再对照**：读取设计，判断观察到的是否实现目标；独立评审结论不能被自审覆盖。环境不具备
   独立子代理时降级为角色分离自审，标注「未独立评审（降级）」，不声称是真实观众测试。

随后按维度分别记录结论，不能用一项通过覆盖另一项：

| 维度 | 判断依据 |
|---|---|
| 叙事 | 问题是否被本场推进，开场承诺是否兑现 |
| 审美 | 主体尺度、构图、色彩光影材质与文字层级是否达到本场目标 |
| 动态 | 关键状态是否可辨，运动是否帮助理解，观察窗口是否足够 |
| 文案声音 | 旁白主张与对应时间窗的画面对得上，画面文案字幕一致 |
| 技术 | 画面、数据、轨迹、灯态与图表是否同源，是否有性能或渲染异常 |
| 衔接 | 与前后场的空间、速度、色彩和叙事是否连续 |
| 传播 | 本场的解释、蓄势或记忆点是否成立，流失风险是否可接受 |

每场还要保留实际文案下的入场、事件、揭示、离场关键状态；动态场景保留全过程证据，静态
场景检查呈现顺序和阅读窗口。四张全片基准与技术 QA 都不能代替逐场验收。每场的执行方式、
投喂文件与隔离条件写入 `visual-notes.md` 的「独立评审记录」区块；缺记录时本场验收未完成。

### 逐场验收表

| 列 | 要写出的内容 |
|---|---|
| 场景/镜头 | 与分镜或镜头表完全对应的 ID |
| 观察复述 | 未读设计时写下的问题、事件、答案与继续观看理由 |
| 七类结论 | 叙事、审美、动态、文案声音、技术、衔接、传播分别写结论 |
| 必改项 | 影响理解、主体识别、文字阅读或明显视听异常的缺陷 |
| 原验收条件 | 制作前为本场写下的手机显示尺寸、主体辨认、动作理解与关系理解目标 |
| 失败现象与影响 | 实际看到什么、发生在哪个时间码、影响哪一类理解或观看动机 |
| 处理结果 | 改了什么、保留了什么；接受保留须写依据与剩余影响 |
| 复查证据 | 修改后有效版本的时间码、显示尺寸、帧序列或量测证据；关闭必须回应原验收条件 |
| 状态 | 未解决、待复查、已关闭、接受保留；只有「已关闭」计入解决 |
| 回退 | 精制 / 试制 / 预演 / 选案，按问题来源选择 |

### 四种问题状态

| 状态 | 含义 | 使用条件 |
|---|---|---|
| 未解决 | 问题已确认，尚未修改 | 有当前版本证据，能复现失败现象 |
| 待复查 | 已修改，尚未在当前有效版本验证 | 修改已进入可编辑材料并重新准备；旧版本证据不能关闭 |
| 已关闭 | 原验收条件已在当前有效版本得到满足 | 证据直接回应原问题的主体、动作或关系目标，并与当前准备指纹、成片摘要对应 |
| 接受保留 | 经实际比较后决定不修改 | 只适用于非核心表现差距；记录接受依据与未消失的影响，**不计入已解决**；影响核心理解或用户明确提出的核心缺陷不得使用该状态放行 |

「已关闭」必须同时满足：有原验收条件、有当前版本证据、证据回应的是原问题而不是替代指标。
重新渲染、文档意图、技术 QA 通过、标签更清楚、首尾呼应或「这属于设计停顿」都不能单独关闭问题。

同一问题连续两轮没有明显改善时，换表现方法或方案，保留前后对照；仍不成立就报告未完成，
不以重渲染、文档意图或技术通过放行。

### 反例演练（演练，非真实失败）

| 构造输入 | 必须得出的结论 |
|---|---|
| 手机尺寸下关键车辆动作仍不可辨，修改只是把标签放大加粗 | 主体可能更清楚，但动作理解未解决；保持待复查，直到证据证明动作与关系可理解 |
| 结尾偏长，修改只增加首尾呼应的构图或文案 | 呼应不回答时长问题；必须比较原版与精简版的时间线及帧序列，检查重复信息与等待用途，否则不得关闭 |
| 静音位置符合分镜声明且技术检查通过，于是判定节奏合适 | 设计停顿只解释“为什么静音”，不证明等待有用；仍须说明对应观察、理解或情绪用途，不能直接关闭节奏问题 |
| 非核心差距经实际比较后保留，却把状态写成已关闭 | 只能记接受保留，并写明剩余影响；不得计入已解决 |
| 用户明确提出的核心缺陷以「平台限制」「覆盖限制」解释 | 核心缺陷必须修复或保持未解决，不能改名放行 |

## 全片组合复核

逐场通过后再检查全片：问题与答案是否闭合、主次是否清楚、节奏是否有重复或长等待、
高潮位置是否成立、视觉体系是否统一、场景衔接是否连续。全局视觉修改或最终文件摘要变化后，
所有受影响场景及全片组合都要复查，不能复用失效结论。

## 完成边界

- 场景清单与实际分镜/镜头集合必须完全对应；缺项、缺场、漏镜头或只有「沿用风格」都算未完成。
- 制作前手机关键事件目标、设计表、观察复述、七类结论、问题闭环与证据缺一不可；缺少显示尺寸
  或三类理解区分时，本场验收未完成。
- 问题记录缺原验收条件、当前版本证据、影响或复查条件时不能标记已关闭；接受保留不等于解决。
- 记录不是导出条件，也不代替导出后的全片帧序列与自动音频复核。
- 发布数据未知时只影响[百万播放潜力](reach-potential.md)的判断，不阻塞作品完成。
