# 讲解设计与画面排错

本页提供可选的讲解手法与项目特有排错知识。按主题和实际问题选用，不规定创作顺序、逐镜问题、固定数量或不采用说明。视觉灵感的必读要求与自由采用原则见[视频视觉与表达参考](visual-expression-inspiration.md)。

设计记录见[方案指南](stage-plan.md#设计记录)；实际表达、证据与完成条件见[视觉复核](visual-review-rubric.md)和[检查点契约](checkpoint-gates.md)。

## 可选讲解手法

展示具体对象、演示最小过程、邀请观众尝试、并排比较、把数量变成可数对象、用图表总结或只用文字，都可以服务讲解。长片也可采用编年、论证链或围绕问题探索多个侧面；没有统一章节结构或必须出现的高潮。

文字、符号、平面图形和静态观察均可承担主体表达。体积、材质、具象对象与镜头运动按需要选择；不要求每个名词都配图，也不以去掉文字后是否完整作为通用标准。

## 四种讲解机制的执行方法

以下是可选方向，可以融合、改造或完全不用；采用时只核对实际承诺的关系。

| 方向 | 可能用途 | 已有能力与注意点 |
|---|---|---|
| 同一对象连续追踪 | 让观众认回变化前后的对象 | 复用对象状态、轮廓或其他身份线索；同一 ID 不等于画面可认回 |
| 相机与尺度变化 | 从局部到整体公开新关系 | 共用世界坐标与相机；区分对象运动和镜头运动，缩小画面不自动构成新认识 |
| 过程与结果联动 | 展示输入、过程与结果的联系 | 数字、图形由同一模型或进度计算；共用变量不自动证明因果可读 |
| 回场 | 在新语境下重新理解前面的画面 | 可复用对象或构图；不要求重复次数、状态变化数量或固定回场结构 |

实现入口见[运行时机制映射](code-scene-runtime.md#讲解机制与已有能力的映射)。需要跨幕连续行为时可采用[全局时间与连续行为](code-scene-runtime.md#全局时间与连续行为)；画面与声音共用时刻时可采用[幕内事件](storyboard-schema.md#幕内事件)。未决关键关系按现有风险计划验证，不将手法名称新增为风险类型。

## 无旁白字幕稿

无旁白作品的画面文字可承担主要讲解。文案的主次、尺度与停留按实际内容和观看尺寸确定，不设句数比例或每句必须有动作的创作配额。

共享字幕与语音字段以[准备与字幕契约](prepared-and-subtitles.md#语音与字幕)和[分镜时间轴](storyboard-schema.md#时间轴与字幕)为准。示例自绘的 `screenSubtitles` 是场景 props，其单行和长度约定见 [fold 设计](../../../../examples/text-motion/fold/DESIGN.md)与 [pigeon 设计](../../../../examples/principle-metaphor/pigeon/DESIGN.md)，不视为所有场景新增的共享字段。

事实、数字与比较口径沿用来源材料和[结构化来源契约](storyboard-schema.md#结构化来源v9)；必要注释按[项目约定](../../../../AGENTS.md#修改规则)。数据与图形保持真实对应，不用装饰数值或动画伪造证据。

## 看图诊断与形象判据

按实际问题定位**形象**（对象选择与呈现）、**取景**（布局、镜头与时间）或**实现**（绘制、参数与性能）。下表是可能成因与处理方向，不是逐镜检查表，也不自动判定成片失败。

## 一、症状 → 成因 → 改法

| 实际症状 | 可能成因 | 处理方向 | 层级 |
|---|---|---|---|
| 关键主体过小，细节或最小单元不可辨 | 按画得下定尺寸，忽略最终观看尺寸 | 调整屏幕占比、细节数量、排法或相机距离 | 取景 |
| 目标是认出具体对象，实际只能认出圆点或线条 | 所需识别线索不足 | 选择合适轮廓、参照、材质或必要名称；抽象符号已满足目标时无需具象化 | 形象 |
| 承诺展示的关键对象或变化缺失 | 分镜遗漏或文字与画面职责不清 | 补充相关表达或调整文案；不要求每句名词都画出 | 形象／取景 |
| 实心色块被辉光冲白、结构发糊 | 实心面进入辉光累加，范围或强度过大 | 将主体放到不受辉光影响的层，或降低该段辉光 | 实现 |
| 必要小字压主体、读不清 | 标注位置与阅读窗口冲突 | 调整位置、层级或出现时机，必要时精简 | 取景 |
| 线条、物体或文字侵入共享字幕区 | 镜头变化后未重新检查安全区 | 调整裁切、布局或可见范围，核对完整窗口 | 取景 |
| 字幕与亮背景对比不足 | 镜头进入亮区域 | 调整字幕背景、场景亮度或构图，使用共享字幕契约 | 取景 |
| 推拉先平移、后猛冲 | 缩放和焦点在不合适的空间插值 | 检查对数缩放与焦点求值，避免叠加突变 | 实现 |
| 同时变化太多导致阅读或因果混乱 | 信息与动作竞争 | 调整顺序、减少竞争信息或扩大必要窗口 | 取景 |
| 连续段落没有作用、等待冗长 | 重复信息或时长未随内容调整 | 删短、重组或改变表达；有效静止可保留 | 时序 |
| 转场中间失去对象身份 | 同时变形、缩放和切镜，认回线索不足 | 保留必要锚点，调整动作或直接切换，核对完整衔接 | 时序与衔接 |
| 与明确参考目标相比主体过暗或过空 | 关键尺度、明暗或层级未兑现 | 对照相应窗口定位差异，不强制增亮或填满所有画面 | 形象／取景 |
| 颜色变化造成数值或状态误读 | 颜色语义与数据不一致 | 调整编码并检查相关片段，不用颜色伪造成功、失败或数据关系 | 取景 |

修复后查看当前版本的同一窗口与必要前后文；涉及运动时不能只凭起终静帧关闭问题。实际缺陷、偏好及证据不足的区分见[问题分类](visual-review-rubric.md#缺陷风险偏好与证据不足)。

## 二、画得像它本身

当目标确实要求识别具体物体时，可从轮廓、参照、厚度、遮挡、接触或材质中寻找缺失线索。名称可以辅助识别，抽象符号也可以直接承担关系；不以“只有圆圈”“没有三维体积”单独认定失败。判断依据是目标受众在实际窗口里能否识别必要对象和理解相关关系。

## 三、主体尺度的起点

主体过小时，可先从最终显示尺寸与最小可辨单元反推屏幕占比，再调整排法、细节和相机。这个排错方向不要求每场预填占比或固定像素；需要精确比较时才按[参考分析](reference-video-analysis.md)量测，实际可读性仍由当前画面验证。
