# 讲解设计

本页用于 `general` 讲解片：把一个概念、机制或事实，变成观众在屏上看得见的变化。
它规定**怎么想、怎么写、怎么自查**，不新增制作阶段、分镜字段、门禁或审核轮次。
画面执行仍按[通用作品创作](article-to-storyboard.md)、[分镜 v8](storyboard-schema.md) 与
[自主视觉复核](visual-review-rubric.md)；无旁白屏幕字幕的实现约定见
[C 夜曲风格包](../../../../styles/vibe-night/GUIDE.md#7-无旁白屏幕字幕约定)与
[B 寓言风格包](../../../../styles/vibe-fable/GUIDE.md#7-无旁白屏幕字幕约定)。

## 什么时候用

- 用户要求讲清一个概念、机制、为什么或一段事实，而不是只展示素材。
- 无旁白、字幕即文案的知识短片，或旁白与画面共同讲解的通用作品。
- 需要判断「这句该画什么」「这个形象够不够清楚」「多少句可以不画」时。

只做外观转译、纯展示或纯数据录屏时，按对应专项文档执行，不强制套用本页。

## 六种画法

一句文案出来，屏上能做的事只有六种。v8 分镜里每一句都要选一种，写进作品 `DESIGN.md` 的
逐场设计表或分镜文案备注；不要求新增 JSON 字段。

| 画法 | 屏上做什么 | 适合的句子 | 在本项目里的常见实现 |
|---|---|---|---|
| **亲自试** | 摆出一个东西或一道小题，让观众先反应；文案晚半拍说出观众刚经历的事 | 开头、「你以为……」、直觉与反直觉 | 场景先给可读的题面或对象，数秒后再给结论；可用 `motion` 推进状态 |
| **照着句子画** | 句子里有什么就画什么，动词真的发生 | 讲故事、举例子、摆事实 | 可辨认的对象 + 连续动作；一次只改一处状态 |
| **当场做一遍** | 拿最小题目把方法一步步走完，状态和计数可见 | 讲方法、机制、「为什么一定这样」 | 本地计算 + 帧驱动计数；数字必须真算，不能手填装饰数 |
| **并排比** | 两样东西放进同一版式，只留一处不同 | 「A 比 B」、前后状态 | 同一比例尺、同一基线；差异必须能被指出 |
| **摆到一张图上** | 把已出场的对象放进坐标图，轴用人话写 | 总结「为什么会这样」、规律 | `Chart` 或自绘 SVG；一条片两三次，排在例子之后 |
| **只上字** | 规则卡、定义、结论、金句；或把上一幕停住 | 命名、结论、过渡、提问 | 大字或卡片；不硬配图 |

贯穿全片的两个动作不算新画法：**回场**（前面的对象、尺子或开场画面再次出现，含义改变）和
**合体**（把全片形象与观众生活里的东西放进同一画面）。回场至少改变一处含义，不做单纯重复。

## 什么时候画，什么时候不画

能画的尽量画，但不必每句都配新画面。大约**每五句留一句不画**：提问、结论、命名、过渡，
让上一幕停住，给观众把刚看到的东西想明白的时间。

| 这句话在做什么 | 怎么处理 |
|---|---|
| 讲一件事、举一个例子 | 照着句子画 |
| 讲方法、机制、「因为……所以……」 | 找一个最小题目，当场做一遍 |
| 说观众的直觉或感受 | 让他亲自试 |
| 比较两样东西 | 并排比 |
| 说一个数量 | 让它数得出来，或放到全片通用的尺子上 |
| 总结「为什么会这样」 | 摆到一张图上，用前面出现过的对象摆 |
| 把道理落到「你」身上 | 合体 |
| 提问 | 不画：停住上一幕，或只留一个对象／问号 |
| 起名字、下定义 | 只上字，前面的对象可以留在旁边 |
| 规则、结论、金句 | 只上字，或把上一幕停住 |
| 过渡句 | 不画，让下一幕进场 |

容易犯的错：刚演过的事，结论句又画一遍；没有东西可指的句子硬配光点、连线和抽象图形；
一个数能说清却画成图表；公式单独解释；每句话换一个新版式。

## 找一个形象

对概念清单里的每个概念，按顺序问；前面的问题有答案，就不再往后问。

1. **它本身是个东西吗？** 是，就画它本身：星、光、珠子、纸片、探测器、一只手。
   用可辨认的形状、厚度、遮挡与接触阴影；一个圆圈加标签不算画了它。
2. **它是一个过程或方法吗？** 找一个最小到能把每一步画出来的题目，走一遍：数到 10、
   猜 1–100、一天走多远、光走一年。
3. **它是一个量或程度吗？** 给它一把尺子，用同一把尺子量三样东西。
4. **它是观众脑中的事吗？** 设计一个五秒内能发生的小测试或小对比。
5. **它是一条规律吗？** 先各画两三个例子，再把例子摆到一张图上。
6. **都不是**（判断、态度、总结）：不画，只上字。

找到形象后再过三问，把形象做强：

- **观众在生活里哪儿见过它？** 找那个锚；找不到锚的概念，观众记不住。
- **换一个尺度看是什么样？** 拉近或拉远一级，原因和结果常常就连上了。
- **它坏了会怎样？** 让它错一次；正常时看不出它在干活，坏了才看得出。

六问决定画什么，「怎么才算画了」的判据与主体尺度起点见[看图诊断与形象判据](visual-diagnosis.md)：有体积材质、从认得的地方进场、记号只当小字用，以及先定屏幕占比再反推缩放。找不到形象就不写那句话——先把道理弄懂，含糊的句子都是没弄懂时写出来的。

### 先找形象，再写文案

形象必须先于文案成形，不是写完文案再配图。画不出来的句子，几乎都是句子里没有东西、没有动作；这类句子要改句，不是硬配一张图。检查依据：遮住字幕一列，只读「屏上是什么、在干什么」，仍能复述讲解；每句的关键名词在屏上找得到。形象与分镜未完成时不建工程、不写场景代码。

### 每一镜过三问

写不出来的镜头重做：

1. **屏上这是什么？** 用一个日常的词回答，遮住字幕和标签仍认得出。
   答案是「一些点」「几条线」「一个圈」「几根柱子」的不合格，除非它本身就是带刻度、
   带标签、叫得出名字的仪器。
2. **它在干什么？** 用一个动词回答，而且是字幕里的那个动词或它的直接后果。
3. **观众因此明白了什么？** 一句话，并且和上一镜明白的事不同。

## 数量要可数化

- 一个数能说清的，不画图表；要画，就画成**数得出来的东西**：一格一格、一颗一颗、
  一条逐步增长的线，而不是给数字配一根柱子。
- 同一个数量在片中只用一个单位、一把尺子；尺子一旦建立，后面都用它量。
- 屏上出现的数必须能复算：数值、单位、基准和来源写进作品事实表；示意与估算明确标注。
- 计数由帧号驱动，不手填「看起来差不多」的数字；动画结束时必须停在声明值上。
- 比较放在同一画面、同一比例尺；不能靠两个不同截图的记忆比较。

## 无旁白字幕稿

无旁白作品的屏幕文字就是文案本身。它在分镜 `content.props.screenSubtitles` 声明，
由场景在字幕安全区内自绘（字段、单行上限与互斥规则见
[C 夜曲 GUIDE](../../../../styles/vibe-night/GUIDE.md#7-无旁白屏幕字幕约定)与
[B 寓言 GUIDE](../../../../styles/vibe-fable/GUIDE.md#7-无旁白屏幕字幕约定)）。

- **量**：30–45 秒短片约 6–9 句可作参考；每个场景按内容和节奏安排一句、多句或无字幕。每句聚焦一项主要关系，必要时可用多个连续动作讲清它。
- **长度**：单行、中文不超过 28 字；超出拆句，不靠自动换行或缩小字号。
- **句式**：一句一个主语、一个动词、一个可指的对象；先具体后抽象，先例子后命名。
  能写成「这串珠子会自己折成一团」就不写「其结构具有折叠性质」。
- **名词可见**：每句里的关键名词都要在屏上找得到；找不到就先改文案或补形象。
- **数字可复算**：字幕里的数必须与画面计数、事实表一致；约数与精确值分开写。
- **不解释画面**：字幕说观众刚看见的事或即将看见的事，不写「如图所示」「接下来」。
- **不写制作话术**：不出现文件名、路径、内部流程、模型名或「示意」以外的制作说明。

写稿顺序：先给每个概念找到形象，再把形象里的东西和动作写进句子；不是先写完文案再配图。
把「画不出来的句子」逐条改写成「有东西、有动作」的句子，再建分镜。

## 分镜与画面一起写

分镜表每句至少能回答：这一句在做什么、选哪种画法、屏上什么在动、观众因此明白什么。
逐场设计表仍按[通用作品创作](article-to-storyboard.md)与
[逐场设计与独立验收](scene-design-and-acceptance.md)填写，不另建平行表单。

- 每段写清只讲明的关系及留给后段的解释；连续构图与阅读／动作／结果窗口回填现有逐场表和时间线。场景按讲解关系和节奏安排一句、多句或无字幕；每句控制信息密度，允许多个连续动作共同讲清同一关系，避免机械换字或换版式。
- 先将最难关系放进最小完整段落，按[完整段落试制](production-workflow.md#完整段落试制与逐段扩展)持续完善同一材料；讲不清先改画法或文案，不先做装饰。
- 关键揭示前留观察窗口；结论文字在揭示完成之后进入，不能压暗或退出正在被观察的全貌。
- 颜色、字号、位置与动效按作品 `DESIGN.md` 的语义表执行；同一颜色全片只表达一个含义。

### 贯穿对象、事件和完整动作

借鉴原项目 `pigeon_B` 与 `fold_C` 的原创样片：先在现有逐场表确定承载核心关系的对象、可认回的轮廓或颜色、随故事改变的状态及最后的新认识；纯文字或独立展示没有贯穿对象时说明不适用和替代组织方式。形状服务关系：要接合就设计可看懂的接触部位，要表达容量就设计可见边界；对象能否辨认和关系是否成立仍需实际画面验证。

分镜逐句记录对象、动作、景别、画面上的必要文字和适用声音，写明动作开始、关键接触或揭示、结果及观察停留。需要连续行为时先编排角色在整段中的位置、方向、动作和停顿，再决定哪些镜头展示；跨镜或跨幕保留同一时刻的状态及可认回线索，不用反复摆动代替完整行为。

关联画面、计数、字幕和事件音时，在既有时间线或逐场备注确定同一事件时刻及先后关系；例如一次接触可同时触发画面变化与声音，读数在相应结果出现时更新。修改事件时间后检查所有关联项。此处是制作协调方法，不表示系统自动生成事件表或自动同步。

依内容安排初态、动作和结果可被看清的时间；画面能够独立讲述时，主动考虑保留无字幕窗口，提问、结论或纯文字可静止。无字幕窗口不要求固定时长或比例，有旁白作品不强制静音。审看完整窗口和相邻衔接，分别记录画面、字幕与声音的观察覆盖；未覆盖的部分不能写成已验证。示例中的具体角色、画面和文案不复用。

## 长片叙事结构

长片先确定贯穿全片的问题或观察对象，再选择适合题材的组织方式。以下是三种可组合的结构，不规定章节数、单章时长或固定比例；章节目的和承接关系写进现有 `DESIGN.md` 逐场表，不新增材料字段。

| 结构 | 章节推进 | 适用情况 | 需要防止 |
|---|---|---|---|
| 编年 | 起点 → 触发变化 → 多阶段响应 → 后果 → 回到当下 | 历史、技术演进、事件经过 | 年份顺排但没有原因与后果；把背景堆成目录 |
| 论证链 | 提出判断 → 建立模型 → 用证据演示 → 检查反例与适用边界 → 推出结论 | 科学解释、机制、公共议题 | 只列支持材料；结论先于可观察证据 |
| 侧面探索 | 围绕同一问题，依次改变尺度、参与者、材料或场景 → 汇合共同规律 | 多因素系统、人物群像、空间与生态 | 章节可任意互换；每节都从头介绍主题 |

开场提出一个能在片中推进的问题，或先让一个具体对象进入麻烦处境。各章回答上一章留下的问题，并让下一章提出更具体的新问题；不适合悬念的论述片，可以用连续的推理任务代替悬念。反复出现的对象、动作、声音或构图须改变含义，结尾回到开场问题并给出回应、边界或明确的未决点。不要用重复镜头替代回扣。

### 完整设计示例：一滴雨水如何走到河里

这是一个约 8 分钟的论证链方案，题材是城市雨水去向。示例说明章节间如何递进，不是固定模板；实际水系、设施和数据须按作品所在城市核实。

| 段落 | 本段回答 | 可见对象与动作 | 留给下一段的问题／回扣 |
|---|---|---|---|
| 开场：雨落在屋顶 | 一滴雨水会经过哪些地方？ | 跟住一滴雨，落进屋檐边的排水口；雨势增强，入口开始积水 | 为什么入口接住了雨，街面还是会积水？ |
| 1. 汇水范围 | 屋顶、道路把雨水汇到哪里？ | 镜头从一滴拉远到屋面和街区，汇水边界逐块显出；水滴沿同一条路径前进 | 汇来的水为什么会在局部排不出去？ |
| 2. 管道容量 | 入口、支管和主干管如何传水？ | 同一股水进入逐渐汇合的管网；用同一把流量尺比较入口、管段与下游 | 管道设计容量够，为什么暴雨时仍会倒灌？ |
| 3. 瓶颈与边界 | 入流量、管网容量和下游水位如何共同作用？ | 让入流曲线越过管网容量，再升高下游水位；并排看畅通与受顶托两种状态 | 能否让峰值来得慢一些？ |
| 4. 暂存与渗透 | 哪些措施改变水到达管网的时间？ | 把屋顶、树池、透水地面和调蓄空间放回原汇水图；雨水暂存后再缓慢释放 | 这些设施会消除所有积水吗？ |
| 5. 适用范围 | 哪些雨型、地形和维护条件仍会造成积水？ | 用同一张系统图逐项改变雨强、出口水位与入口堵塞状态，显示能力边界 | 回到屋檐边那滴水，它现在走到哪一步？ |
| 结尾：回到开场 | 积水由整条路径的峰值与瓶颈共同决定，设施只能改变汇集、传输或暂存 | 回到同一屋檐和同一排水口；开场的积水状态与新的分流、暂存路径叠在一起 | 以一句结论收束，并指出本例仍需城市实测数据支持的部分 |

制作前把本例里的城市事实、尺寸、容量、降雨数值全部替换为有来源的材料；若不能核实，就保留定性机制，不在画面里填装饰数值。回扣保留同一滴水、入口与构图锚点，同时改变观众对“水去哪了”的认识。

## 四种讲解机制的执行方法

按内容选用，不要求每片或每镜凑齐四种机制。定义、命名、结论或纯文字作品可不适用，
在现有逐场表的用途或备注中说明即可。机制服务于关系表达，不以动画数量判断质量。

| 机制 | 设计时明确 | 执行方法 | 需要看见的证据 |
|---|---|---|---|
| 同一对象连续追踪 | 哪个对象必须认回；轮廓、位置关系、颜色或运动中哪些特征不变 | 用同一对象数据派生各阶段形态；转场保留可辨认的锚点；连续空间优先在同一场景内组织内部镜头 | 建立、变化、遮挡或转场、再次认回的完整窗口；同一对象 ID 不证明观众认回 |
| 相机与尺度变化 | 从局部到整体揭示什么关系；对象本身是否同时运动 | 二维保持统一世界坐标与整体变换，三维复用现有相机；明确相机和对象各自的运动 | 局部、尺度过渡、新信息进入与全貌停留；不能只比较两个大小不同的截图 |
| 过程与结果联动 | 输入变量、作用过程、结果，以及可见的先后关系 | 从同一模型状态计算图形、数字与结果；不分别手填互不相关的动画终值 | 过程改变如何带来结果，数值与图形一致；共用变量只证明实现一致，不证明因果可读 |
| 回场 | 回到哪个原画面，哪一处关系在结尾获得新含义 | 复用原对象、构图及状态计算，只改变讲解需要的状态；保留足够认回线索 | 认回原画面并获得新认识；重复镜头或字幕宣布结论不单独证明回场成立 |

在现有 [DESIGN.md 逐场表](scene-design-and-acceptance.md#逐场设计表)中，“可见事件”记录主体与结果，
“可见变化”记录变化与不变量，“新增认识或体验”记录目标关系，“导演卡与窗口”记录完整表达窗口，
“验收条件”记录可能误读与失败现象。无需新增 JSON 字段、表列、平行表单或每镜完整导演卡。
把“原对象变形后仍可认回”“局部属于哪个整体”“过程如何导致结果”等尚未验证的核心风险，
按[审核策略](checkpoint-gates.md#审核计划与风险触发)登记，不把四种机制名称变成新风险枚举。

先用最小完整窗口试制最难的关系，再扩展依赖它的场景与装饰。已有能力及其边界见
[运行时机制映射](code-scene-runtime.md#讲解机制与已有能力的映射)。发现缺口时先确认是表达设计、
取证还是运行时能力问题；只有证实后者才另行评估共享能力，不能以增加装饰组件代替。
实际观察方法见[讲解关系的观察](visual-review-rubric.md#讲解关系的观察)；失败处理只按
[检查点契约](checkpoint-gates.md#讲解机制与关键采用项的关闭)执行。

### 范例：把一个关系拆成四栏

以 `styles/examples/vibe-night/fold/` 的「第 6 颗珠子」为例。它同时用上了前表里的
「同一对象连续追踪」与「过程与结果联动」，拆法是四栏，不是四种机制各写一遍：

| 栏 | 内容 | 落到的具体决定 |
|---|---|---|
| 对象状态 | 一条 146 颗的珠链；第 6 颗（索引 5）是唯一会说「错」的那一颗 | 全场只维护一份珠位数据；折前折后按索引对应，颜色身份跟着索引走 |
| 动作 | 推近到前十二颗 → 第 6 颗翻面 → 颜色由冰蓝变玫红 → 一圈涟漪 | 翻面用横向压扁再摊开（`squash`），不是淡入淡出；涟漪只出现一次 |
| 结果 | 拉远后同一颗珠子露在密团表面，鼓成黏点，进而连成长杆、把细胞顶弯 | 细胞与镰刀由同一参数域的 `bend` 连续插值，不切换两套形状 |
| 声音 | 翻面一声 `flip` + 落地一声 `thud`；接杆时每接上一团一声 `thud`，越接越密 | 音效的 `offsetFrames` 直接取画面动作的帧号，不另写时间表 |

判据：遮住字幕，「翻面 → 露在表面 → 粘住下一个」仍然成立；把第 6 颗的颜色或索引
换掉，后面的黏点与长杆就不成立——这说明对象身份真的被追踪住了，而不是画面碰巧连上。

## 看图改图检查表

完成分镜与关键帧后，按顺序自查；发现即改，不把问题留到全片渲染。本表回答「查什么」；看到毛病之后「出在哪一层、怎么改」按[看图诊断](visual-diagnosis.md#一症状--成因--改法)定位，形象是否成立按[形象判据](visual-diagnosis.md#二画得像它本身)判断。

- [ ] 遮住字幕，只读「屏上是什么、在干什么」，仍能复述讲解。
- [ ] 每句的关键名词都能在屏上找到；找不到的已改文案或补形象。
- [ ] 「只上字／停住／提问：不画」约五分之一；一个都没有或超过一半都要重看。这是创作参考比例，不是验收阈值。
- [ ] 各场景的字幕数量服务内容与节奏；每句信息密度适当，连续动作与结果清楚，认识有所推进，没有机械换字。
- [ ] 每个抽象观点都有一种可见变化（空间、数量、速度、高度、距离、明暗或分叉之一，判定口径见[可见变化](visual-creative-direction.md#5-可见变化)）。
- [ ] 主体育屏上认得出、占得住画面；遮住字幕与标签仍知道这是什么（判据见[画得像它本身](visual-diagnosis.md#二画得像它本身)）。
- [ ] 屏上的数能复算，与事实表一致；单位、基准与示意标注齐全。
- [ ] 同一数量只用一把尺子；比较在同一画面、同一比例尺。
- [ ] 让人「哦——」的那一下有铺垫、有停顿、之后有结果；不是靠字幕宣布。
- [ ] 回场改变了含义；没有无用途的重复画面或等待。
- [ ] 393 宽手机横屏下，主体与必要文字可辨；屏幕字幕单行、≤28 字、在安全区内。
- [ ] 画面注释从紧：没有装饰英文、小字说明或片尾制作说明；必要注释用小字且不遮挡主体。
- [ ] 去掉声音仍成立；有旁白时，口播提到的特征在对应时间窗真的可见。

## 边界

- 本页只借讲解方法，不复制参考项目的画面、文案、角色、样片实现或字体。
- 不改变分镜 schema、共享字幕层、制作门、审核轮次与导出门禁；屏幕字幕不进入
  `subtitleCues`，但可通过组件默认的 `data-m2v-role="subtitle"` 进入 `textPlan` 与
  `measurement.subtitleRoles` 量测；有旁白的幕声明屏幕字幕会被 `validate` 拒绝。
- 作品内容按仓库规则不入库；本页属于制作方法，随仓库维护。
