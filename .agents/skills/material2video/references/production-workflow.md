# 通用作品制作流程

本页是阶段与记录的唯一入口；创作细节见[创作流程](creative-production.md)，评审职责见[独立子代理评审](subagent-review.md)。新流程仅用于后续启动任务，不迁移正在制作的作品；金融与住宅保留专用画幅、声音和材料契约。

## 正式流程摘要

在方案确定阶段逐场选定外部素材、代码或混合；外部素材优先检索合适视频，无合适视频再用图片，静态原件与代码适用场景按[素材选择规范](visual-material-selection.md#视频优先与代码适用场景)处理。选择依据与图片回退理由沿用 DESIGN.md 现有载体记录；粗片和最终评审结合实际画面检查，不增加阶段或 CLI 门禁。

三阶段管理项目状态，七步安排实际制作顺序：**方案确定**（准备内容与方向 → 确定叙事方案 → 设计视觉表达与分镜 → 适用时制作并盲审独立目标关键帧）→ **制作与迭代**（验证核心与开场，逐段完成画面、字幕与声音，检查全片并逐项修订关闭）→ **最终验收**（完整候选、技术检查、适用终审与交付）。用户方案足以实施时直接采用，不重开选案。

审核轮、风险触发与人数统一见[检查点契约的审核策略](checkpoint-gates.md#审核计划与风险触发)，执行与隔离方法见[独立评审流程](subagent-review.md)。

以下为制作原则，具体适用条件与证据要求见下文及[独立评审流程](subagent-review.md)：

- **关键帧先于动画**：`static-expression` 风险涉及的段落先用独立制作的目标关键帧验证画面；没有该风险时不因 A 级标签补图，静态表达不适用时记录原因与替代验证。
- **动态先验证风险最高的一段**：存在 `core-event` 风险时先验证最高风险核心事件的完整窗口，理解与表现分别成立后再扩展全片；无实质动态风险时记录不适用原因。
- **独立评审不接收设计理由、预期答案或旧结论**：先盲看并保存观察，再核对单独提供的中性原条件。
- **技术通过不代表作品通过**：导出成功与制作复核分别报告，最终理解、结构、节奏和视觉文案仍须独立验收。
- **同类问题连续两轮无改善，就更换机制或剪辑方案**：停止同类参数微调，按问题所在层级比较替代方案；连续两轮失败时保留匿名独立比较与收益、损失记录。

失败回到对应层：目标画面问题回到视觉事件或美术方向，动态理解问题回到事件因果或导演顺序，全片结构问题回到剪辑与叙事；修改目标画面后重新静态评审。

### 核心样片与全片粗片的回退决策

在**适用核心样片独立评审后、扩展相关正式实现前**，以及**G5 全片内部粗片检查后、阶段问题收敛前**，制作助手必须依据当前证据作出下表四种决策之一。核心轮是否适用、人数及覆盖仍按[审核策略](checkpoint-gates.md#审核计划与风险触发)派生，不新增例行审核轮或用户审批。核心片段只授权已验证机制和范围，不能替代全片结构检查。

| 决策 | 适用依据 | 推进边界 |
|---|---|---|
| 通过，允许扩展 | 该阶段的适用目标成立、证据充分，相关必改项已关闭 | 核心轮只扩展证据覆盖的相关实现；G5 检查后允许继续迭代并收敛问题；最终候选仍须终审 |
| 局部修复，复查后放行 | 可定位的实现或衔接缺陷，原设计仍可成立 | 修复本窗及相邻衔接，受影响范围复查通过前不扩展或精制 |
| 证据不足，补充试制 | 占位样片、关键资产缺失、采样或过程证据不足，尚不能判断 | 只补必要验证，不扩展相关高投入实现；不把未验证写成通过或技术不可行 |
| 退回重设计 | 证据确认方案或技术路线存在根本问题，局部修补不足以达到原目标 | 暂停依赖失败方案的扩展或精制，回到对应设计层，再按影响重新验证 |

**根本失败立即回退，不必先修两轮。** 两轮无改善是根因尚未确定或局部修复反复失效时的兜底升级要求，不是允许持续修补错误方案的配额。选择最小充分回退范围，不因局部失败推翻无关有效设计；同一问题存在多项原因时分别记录，不以一种通过覆盖另一种失败。

#### 核心样片的回退触发

| 场景 | 需要的当前证据 | 回退层级 |
|---|---|---|
| 表达机制不成立 | 完整窗口仍产生关键误读，原载体／因果无法让核心关系成立，不能靠作者解释补足 | 视觉载体、事件因果 |
| 导演或时序设计不合理 | 信息公开顺序、视点或注意力安排妨碍目标理解与体验，调整局部参数不足以解决 | 导演顺序、节奏设计 |
| 视觉方案无法承载核心体验 | 实际主体、构图、光线或尺度的代表性试制未能突出必要关系，原美术方向不足以解决 | 美术方向、目标关键帧 |
| 技术路线不可行或代价失控 | 试制结果指明工具、资产、性能或稳定性限制，以及必要效果与合理投入边界的冲突 | 技术路线，必要时更换表达机制 |
| 素材或事实基础不成立 | 关键素材不可得／许可不成立，或设计依赖错误事实，不能按原方案继续 | 素材策略、内容设计；同步重开相关材料审查 |
| 样片暴露全局矛盾 | 核心机制与全片硬约束、共享视觉方向或其他关键段落无法协调 | 整体设计及受影响场景 |

技术不可行必须有失败窗口、实际试制／量测及限制说明，记录已尝试路径、合理投入边界与替代验证；可以由当前证据确认不可行，无需穷尽所有工具。尚未尝试、单次可定位的实现错误或制作者认为另一方案更方便，不足以证明技术路线失败。优先寻找能保留核心目标的替代实现；改变目标时按下方重新放行规则执行，不能静默降标。

#### 全片粗片的回退触发

| 场景 | 需要的全片观察 | 回退层级 |
|---|---|---|
| 全片主线不成立 | 开场承诺、主体展开与结尾回报脱节，或重点错位 | 命题、叙事结构 |
| 信息或体验推进失效 | 重复、断层、提前泄底或无用途等待，局部时长调整不足以解决 | 内容取舍、分镜顺序、时长分配 |
| 各场成立但组合失效 | 跨场衔接、风格、尺度或声画组织相互抵消 | 全片组织、共享视听规则 |
| 核心样片无法推广 | 单段有效，但扩展后产生重复疲劳、强弱失衡或实现困难 | 核心机制使用范围、替代机制 |
| 整体制作条件不可承受 | 全片资产、性能、稳定性或工作量的证据显示当前方案无法在合理投入内兑现目标 | 技术方案、素材策略、设计复杂度 |
| 核心体验缺失 | 全片可以复述，却未兑现预先声明的关键体验或视觉重点 | 核心段落、整体强弱设计 |

G5 粗片按其内部检查目标判断，区分「尚未精制」与「设计失败」：缺少最终材质、灯光或细节本身不构成结构否决；粗片结构通过也不能授权尚未验证的正式视觉效果。结构与表达机制失败不得以「精修后会好」搁置。纯审美偏好、形式标签或无具体依据的「不够高级」不能单独触发强制回退。

#### 回退记录与重新放行

独立评审者先按隔离规则保存可观察现象、范围与证据；制作助手随后结合技术试制、用户约束和依赖定位回退层级。技术限制由制作助手补充，不冒充盲审者已查看源码或验证全部技术路线。实质争议仍按既有新代理复核处理，作者意图不能豁免已证实核心缺陷。

在 `outputs/visual-notes.md` 原问题 ID 下记录下列内容，新方案回填 `DESIGN.md`；不另设问题表或状态系统：

填写时读取[推进与回退记录模板](production-record-template.md)。

- **状态保持真实**：四种决策是制作记录正文，不是新的机器枚举；已证实失败沿用 `fail`，缺证沿用 `unverified`／覆盖项 `insufficient`，必改问题保持 `open`。重设计决定不能登记为通过；不把这些正文条目加入合同、分镜或独立报告 JSON。
- **先保护，再调整**：按[基线保留](#基线保留)保护受影响版本及比较证据，保留原失败历史；更新设计、审核计划和实现材料，按实际依赖使旧证据失效，不删除风险或改目标来关闭原问题。
- **按层重新验证**：核心机制或视觉方向改变，重做适用目标关键帧／核心样片独立观察及同轮对照；全片主线、顺序或时长结构改变，重做完整 G5 内部粗片检查；局部修复复查本窗和相邻衔接。材料／许可基础改变同步复核 G0。未受影响证据可按依赖证明保留。
- **关闭后恢复**：独立失败仍须当前、同范围同类观察的有效独立通过复查关闭，制作解释、改目标、量测或重新渲染均不能代替。对应评审和相关必改项关闭后才恢复受影响的扩展／精制；最终候选仍按既有规则重新终审。
- **自主推进边界**：无关内容核验、素材整理、独立模块及修复取证可以继续，不借取证之名扩展失败方案。只有替代方案需要改变用户明确要求时，提交具体冲突、依据和替代方案由用户决定；其余回退自主执行。

### 核心样片放行与失败处理

核心样片必须能代表其所验证的目标。G2 的独立目标图验证预期画面，G3 的 animatic 验证时序；二者不能代替 G4 实际实现。用于判断正式视觉表现的 G4 核心片段须采用实际主体资产、字体、灯光、文字合成及完整关键动作；占位资产和简化动作只能证明已覆盖的结构或技术范围，不授权扩展对应的正式实现。静态作品不强造动作，按其实际表达窗口复核。

核心盲审覆盖表按[检查点契约](checkpoint-gates.md#隔离包与每轮覆盖)分别记录理解、表现和证据代表性；理解成立不能覆盖表现不足。适用目标对照在核心轮同一代理盲审落盘后完成，不等到终审才首次检查实际实现是否兑现目标。审核人数、适用风险及对照范围仍只由[审核策略](checkpoint-gates.md#审核计划与风险触发)派生。

| 当前结果 | 继续的工作 | 暂不扩展的范围 |
|---|---|---|
| 理解成立、表现不足 | 回到主体造型、光、构图、动作或实现方案 | 依赖该视觉实现的镜头 |
| 表现成立、理解不足 | 回到事件因果、导演顺序与信息释放 | 依赖该表达的镜头 |
| 证据不足或样片不具代表性 | 补完整窗口、实际资产、必要显示尺寸与过程证据 | 尚未验证的正式实现 |
| 原定关键特征未兑现 | 按原目标修复，或保留失败记录后重设目标并复核 | 尚未关闭风险所影响的实现 |

本表给出表现／理解失败的定位线索，不表示所有失败都能局部修好；依照上方[回退决策](#核心样片与全片粗片的回退决策)判断局部修复、补证或退回重设计。无关的内容核验、素材整理和独立模块可以继续。扩展资格是制作行为约束，不是 render 硬门禁；允许为修复与取证生成片段，不得把技术导出当作风险关闭。根本失败立即回退；连续两轮无改善后必须比较不同机制、删短或重排，不能继续仅换色、加粒子、辉光或微调缓动来替代原目标。

### 讲解机制先于装饰扩展

讲解片按[四种机制](explainer-design.md#四种讲解机制的执行方法)在现有逐场表明确对象、变化、
目标关系、完整窗口与可能误读。按内容选用，不强制连续相机、全部动画化或凑齐四种机制。
核心样片先验证最难的解释关系；装饰、字体与亮度的局部优化不能代替机制成立。
盲审先记录实际看到的关系，再核对中性目标，执行见[独立评审](subagent-review.md#讲解机制的隔离观察)。
未成立时按[关闭规则](checkpoint-gates.md#讲解机制与关键采用项的关闭)暂停依赖范围并沿已有路径回退；
普通文字用途、合理延迟揭示和证据不足分别处理。存量作品不追溯补造合同或改写评审。

## 重制启动

已有作品的修改先按[视频修订入口](video-revision.md)定位影响、保护旧版并串联命令；本节继续作为重入阶段与基线记录的权威规则。

后续启动的修复或重制先核验旧片，不因指导更新追溯重做，也不补造旧评审或关闭旧问题。此入口进入现有三阶段，不新增阶段；新作仍从立意六项开始。

在作品 `DESIGN.md` 记录下表，先查用户会话与可追溯材料，再决定哪些能改。来源缺失如实记待核验，历史文档写「用户指定」只是核验线索，不能据此假定要求已失效；来源不清时保守保留，只有影响下一步决定且现有材料无法解决时才澄清。

| 项目 | 本轮记录 |
|---|---|
| 用户硬约束及来源 | 仍有效的内容、声音、画幅、时长等要求及会话或材料依据；待核验项与影响 |
| 历史实现选择 | 可调整的时长分配、顺序、文案、镜头或载体；说明为何不属于硬约束 |
| 问题与目标 | 唯一问题表 ID、旧版时间范围、原验收条件、已知缺陷及待验证假设 |
| 重入阶段与理由 | 局部修复或结构重制，受影响环节和必须保留的体验 |
| 基线与保留清单 | 旧版文件及 SHA-256、preparedFingerprint、证据索引与保留位置 |

局部修复（如标签裁切）按影响复查本场和衔接，不机械重跑全部选案；涉及核心事件、揭示顺序或全片结构的重制，重走相关设计、核心粗样与全片结构验证。既有时长、顺序、文案和测试断言不能自动升级为永久用户要求；实际重制方案确定后才同步受影响测试，不能为消除测试失败擅自放宽硬约束。

### 基线保留

新流程在整体重置前用 `m2v baseline create` 保存旧视频、摘要、准备记录及问题证据到 `outputs/baselines/<id>/`；局部修复用 `--candidate` 保护必要比较候选，不新增重置身份。引用保护、默认三个完整版本目标与仅记录媒体清理以[检查点基线契约](checkpoint-gates.md#基线保留与清理)为准。准备记录缺失如实标明，不伪造旧指纹；普通交付清理不删除制作门、评审包或基线树。

存量旧流程仍保留原 `outputs/remake-baseline/` 与 visual-notes.md 的直接文件链接保护，不自动迁移或补造历史。旧通过只作历史；缺少比较基线时明确相对改善证据不足。示例的产物根与正式作品一致，都是示例目录下的 `outputs/`。

## 用户详细方案直接采用

当用户给出的 general 设计已明确核心表达、关键事件或画面顺序及主要约束，足以开始设计或试制时，直接把它作为核心设计基线。此时不强制补齐三个叙事候选或两个美术方向，也不重复论证已明确的创意、不劝用户改选；在 `DESIGN.md` 记录用户方案、仍有效的决定及需要补充的假设。

明确的创意决定保持原样。未指定的非核心细节按最小且不冲突原则补全，并只记录会影响后续复核的必要假设。独立评审检查方案实际呈现的效果和执行质量，不承担重新选案职责。视觉事件与视觉力量、同一事件机制试制、粗样、最终候选、事实边界、技术可行性和交付验收仍按适用要求执行；这些验证用于确认表现兑现和发现真实问题，不是重开核心创意论证。

若事实、用户明确的硬约束或可验证技术条件存在客观冲突，记录冲突、依据及影响，并提出最小必要调整；个人审美偏好不构成硬冲突。方案尚不足以确定核心表达、关键事件／画面顺序或主要约束时，沿用原有候选流程；只对无法推断且会改变核心意图的信息请求澄清。

## 立意六项（方案确定前）

立意六项是组织设计的工具。开始设计时在作品 `DESIGN.md` 形成六项答案；已明确的用户方案直接映射，按最小且不冲突原则补充缺少的非核心信息，不得以补齐六项为由重开创意选案。不要求在候选前独立填完六份表单，未决的核心风险仍须进入审核计划。六项是设计问题，不是质量评分，也不转为用户确认、运行时字段或 CLI 门禁。

1. **一句话命题**：观众看完能用自己的话复述的主张。
2. **核心体验**：希望观众经历发现、震撼、好奇、紧张、共鸣或秩序美感中的什么，以及由哪个具体段落承载；“高级”“震撼”必须落实到可观察的表达。
3. **表达载体**：文字、图形、空间、档案素材、静态构图与声音如何分工，并写清**载体来源政策**：本片是档案证据型、解释型还是混合型；哪些内容必须由真实素材承担，哪些只能由代码解释；真实与示意的边界如何标注；素材许可与可得性风险如何回退。逐场只决定具体实例，不另立一套来源政策。采用重复母题时写各次出现的作用；不采用时写替代组织方式，不强制全片重复同一对象。
4. **揭示与记忆**：先看到什么、何时形成理解、最后记住什么；分别声明必须立即清楚与允许延迟理解的内容，以及揭示的完整时间窗口。
5. **可验算骨架**：片中定量主张及其验算方式；没有定量主张时明确写明。
6. **重点投入**：最值得投入的具体段落、预计秒数与工时，以及对理解、感受和记忆的贡献；数量按作品需要，不限定唯一一处，也不要求其理解贡献接近零。

母题可以通过状态、关系、情绪或后续语境改变含义，不要求单调增长或三次外形变化；实际作用须在完整段落中验证，不能只靠作者解释。允许不用母题，不强制反转、高潮、持续运动或额外装饰。金融住宅仅执行适用项并记录不适用原因，专用画幅、材料与声音契约不变。

立意六项是 `DESIGN.md` 的区块，不新增阶段名，不改变状态查询、CLI 或三阶段入口。

## 视觉创意方案（选定或直接采用方案后）

常规候选阶段，各案只提出核心表达与母题候选；选案后，或用户详细方案直接采用后、逐场设计与关键画面之前，按[视觉创意导演方法](visual-creative-direction.md)在 `DESIGN.md` 落实七段式：核心表达、核心视觉母题、整体视觉风格、分镜设计、视觉高潮、结尾视觉揭示、禁止项，并按未决问题使用十项自我检查。七段式用于落实与补全，不得借此改写已明确的用户创意；不因表单未逐项填写或候选未达固定数量判未完成。

- 七段是必答问题，不是质量评分、用户确认、运行时字段或 CLI 门禁。题材不适用时写明原因与替代做法（例如不采用统一母题、不设传统高潮或不设独立视觉揭示），不硬造。
- 七段不是平行表单，回填现有区块：核心表达→一句话命题；母题→表达载体；风格→视觉方向；分镜→逐场设计表；高潮/揭示→核心体验与揭示记忆；禁止项→反目标。
- 母题写成「把 ___ 设计成 ___」，载体必须可变化；**核心视觉母题**（整片组织载体，单数，不要求重复）与**母题重复**（同一载体多次出现并产生新作用）是两件事。
- 确定母题或替代载体后、逐场构图与关键画面前，按[视觉事件设计](visual-creative-direction.md#视觉事件设计)写核心事件；普通镜头简写，沿用可见事件栏，不另建表单。
- 核心图形高潮在事件确定后、详细实现前按[视觉力量设计](visual-creative-direction.md)比较同一事件的至少三个视觉机制，分开设计力量与动态释放；合入已有事件说明，沿用三阶段。
- 每个抽象观点至少对应一种可见变化（判定见[可见变化](visual-creative-direction.md#5-可见变化)）；镜头写行为（推进、跟随、升降、拉远、俯视、环绕、穿越、冲入、微观到宏观），不写页面切换。
- **镜头等级**：每个场景及内部镜头标 A/B/C；A 级记忆镜头优先投入关键帧、时间结构与动态验证，B 级推进、C 级功能镜头为 A 级服务。数量按作品需要，不设配额，也不降低可读性与正确性底线。
- **节奏设计**：A 级及依赖揭示时机的核心事件写建立、停顿、变化、延迟揭示、结果、消化的时间结构与关键时点容差；B/C 级只写时间预算。时间结构是视觉事件的时间投影，不新增 JSON 字段。
- 画面文字按镜头或信息单元计，原则上「一句主句 + 至多一句辅助」；标签、轴、数据、事实边界、口径、许可与示意标注不计。关声可读是设计诊断，不是有声作品的最终门禁。
- 必要注释沿用[项目约定](../../../../AGENTS.md#修改规则)的从紧范围，设计时采用明显小于主体文字的小字和次要位置，预留主体、关键数据、字幕及关键动作空间，避免争夺视觉焦点；示意／实拍边界标注以大屏原尺寸可辨、手机横屏不可辨为目标，不要求手机尺寸可读；承载必要信息的口径与其他注释仍须可读，素材署名默认可读、用户明确要求缩小时须把完整署名与许可留在作品材料与发布说明；空间不足先精简或调整位置。主题、对象名称、结论和正常字幕不归为注释；不设跨画幅统一像素字号。按[视觉复核](visual-review-rubric.md#反目标写进-designmd按题材检查)检查注释出现的完整时间窗口。
- 载体来源：整体政策在「表达载体」定稿；分镜按镜头/信息单元写「载体来源与理由」（档案／实拍／图库／代码／混合、为什么、许可与溯源、真实／示意边界）。逐场实例服从整体政策，冲突回退整体，不就地妥协。
- 运行时边界：幕间转场只有 `cut`/`fade`/`crossfade`；`shots[].camera` 由作品代码消费，不新增自动运镜。

### 运动载体优先级

- 默认顺序：**真实视频 → 代码动画/示意 → 静态图片**。静态图片不是运动段落的缺省载体，也不因检索方便而先于视频或代码。
- 不用静帧的推拉、缩放或轻微位移伪装视频；需要可见动作、过程或空间变化时，改用真实视频或代码动画。真实视频可以有自身的镜头运动，但不以人工推拉替代不存在的动作。
- 图片用于静态原件、识别或质感；公司、产品、生产或事件段落不得用无关图库照片冒充真实动作、公司自有产线或具体型号。
- 通用图库素材以持续可见的「示意」次要边界标注说明非实拍性质；真实与示意的判断、许可和来源沿用[视频优先与代码适用场景](visual-material-selection.md#视频优先与代码适用场景)。
- 逐场在「载体来源与理由」记录选择；图片回退须写明视频与代码为何都不适用，不能用作者解释代替画面证据。

### 导演设计：把设计意图落实为观众的信息顺序

关键表达镜头（A 级记忆镜头）在方案确定阶段还要形成导演设计，并与视觉隐喻、视觉事件、视觉力量分开记录：

| 层级 | 回答的问题 | 主要内容 |
|---|---|---|
| 视觉隐喻 | 用什么表示？ | 抽象概念对应的载体或视觉机制 |
| 视觉事件 | 发生什么？ | 主体、因果、状态变化及结果 |
| 导演设计 | 观众按什么顺序看到？ | 初始所见、隐藏信息、预期、公开时机、观察关系、注意力和最终认识 |
| 节奏设计 | 信息何时出现、停留多久？ | 建立、停顿、变化、延迟揭示、结果、消化的起止时间、观众认识、注意力、时机容差与失败现象；A 级必填，B/C 简写 |
| 视觉力量 | 变化如何获得尺度与注意力？ | 尺度、构图、空间、层级、对比及揭示前后的视觉中心；只对核心表达或高潮重点设计 |

导演卡写在作品 `DESIGN.md` 的现有逐场设计区，不新建 `DIRECTION.md` 或平行报告。卡首标镜头等级：A 级记忆镜头写完整导演卡与时间结构，B 级推进镜头只写 Scene Goal、Visual Event、Camera / Attention 与时间预算，C 级功能镜头只写用途、出现与离开时间及可读性；核心高潮再补视觉力量。预期、隐藏或揭示不适用时说明原因与替代表达，不机械制造反转。

导演卡以场景／镜头 ID 连接 storyboard：镜头 ID 对应 `shots[].id`，`shots[].target` 对应本镜主体或目标，已有 `startFrame` / `endFrame` 对应所设计的信息阶段；导演顺序与目的留在 `DESIGN.md`，执行镜头参数留在 storyboard 和代码。不得为了表达导演意图增加 v8 JSON 字段。任何相机动作都须说明它改变何种观察关系、何时执行、让观众看到或理解什么；只有“推近”“右摇”“环绕”等运镜词不构成导演设计。

七段式属于「方案确定」阶段，不新增阶段名，不改变状态查询、CLI 或三阶段入口。

## 三阶段主线

七步是实际制作顺序，不新增项目状态：**方案确定**包括内容方向、适用选案、视觉表达与必要的目标图/时序试验；**制作与迭代**合并核心风险试制、开场探索、逐段完善、G5 全片内部检查与修订；**最终验收**检查当前候选并交付。低成本原型可以在全片分镜完成前开始，只有其结论被明确限制在证据覆盖范围内；正式扩展前仍须完成足以执行的逐场设计与适用风险验证。

| 阶段 | 活动 | 完成条件 |
|---|---|---|
| 方案确定 | 立意、受众与资料、适用选案或采用用户方案、核心表达、足以执行的逐场设计，以及审核计划触发的静态/时序风险验证；未完成全片分镜时可制作低成本局部原型 | 事实边界明确，核心表达与手机验收条件可观察；风险依据明确；适用静态目标图或时序证据有效；原型结论不超出素材与实现精度；正式扩展前补齐足以执行的逐场设计 |
| 制作与迭代 | 存在核心风险时先验证最高风险完整窗口；逐段完成实际画面、适用声音和全片粗预演；制作助手执行 G5 内部检查并记录推进／回退决策 | 核心风险逐项通过适用独立观察；G5 覆盖全片结构、理解、衔接、节奏和已知问题，记录具体发现与未覆盖限制，不要求独立报告或逐点通过表；根本失败退回对应设计层；G4 检查与阶段必改项关闭；必要目标图对照有效；连续两轮失败才强制匿名候选比较 |
| 最终验收 | 一次完整候选、技术 QA、G6 适用终审、交付 | 技术检查完整；当前候选全片覆盖；理解、结构、节奏、视觉文案与必要文字手机可读性按[审核策略](checkpoint-gates.md#审核计划与风险触发)综合验收；必改项关闭并披露限制 |

核心试制、lookdev、hero、风险样片是阶段内活动，不另设阶段或审批。无实质问题不强制返工，不为凑满时长填充动效；不增加评分、用户确认或 CLI 门禁。

### 核心轮的视觉事件观察

审核计划存在 `core-event` 风险时，在扩展高投入实现前，由独立评审者只看中性证据并落盘回答：

> **这个镜头到底发生了什么值得看的变化？**

回答指出实际可见的状态变化、关系变化、尺度变化或认知揭示，以及对应时间位置和新增认识／体验。文字出现、物体移动、镜头推进只是手段，不能单独证明事件有效；文字对照、移动或运镜确实带来新关系、尺度发现或认知揭示时，应按实际效果判断，不按媒介形式否决。静态、功能、蓄势与消化镜头按用途和原合同检查，不为填表强造变化。

先保存观察，再核对预先声明的中性条件；设计理由和预期答案不进入盲审包。观察结果写入该轮覆盖表，逐项覆盖计划中的风险：

| 观察结果 | 下一步 |
|---|---|
| 核心变化清楚，理解与表现均成立且证据充分 | 可扩展该风险相关实现；G5 复核跨场后是否仍有效 |
| 变化存在但表现弱 | 调整构图、尺度、注意力、时序与结果停留，复查同一窗口 |
| 仅有形式动作，原定核心变化不成立 | 回到视觉事件或导演顺序，不以动画流畅放行 |
| 证据不足 | 补完整窗口或加密过程帧，保持未验证 |

记录沿用 `outputs/visual-notes.md` 的原始报告、镜头 ID、时间窗与唯一问题 ID，不复制逐检查点凭据。同一风险不能用一个代表事件授权其他未验证风险。同类问题连续两轮无改善，沿用替换机制或剪辑方案规则。

### 设计对照（核心与终审同轮）

有独立目标图的核心实际片段先完成核心轮对照，再扩展该风险相关实现。终审仍须核对当前全片，核心轮结果不替代最终轮。

有独立目标图的镜头，终审者先只看当前成片盲包并落盘观察，再在同一轮创建 `consistency` 包，对照目标图与中性可观察条件。对照检查构图与尺度、空间与层级、冲击力、注意力中心和时间兑现，但它们是观察维度，不是必须逐项填满的五维凭据。无独立目标图的镜头只验用途、合同与实际表现，不补造目标图或空表。

制作助手在既有逐场记录内保留「原目标、当前证据与时间窗、差异、收益／损失、结论或问题 ID」，不复制原始报告。无需像素一致；非实质媒介差异可说明依据后保留。核心目标未兑现则修实现或节奏；确需改变关键目标，先更新设计与目标图，再重做受影响评审，不能事后改目标豁免失败。缺图或过程证据不足时只报告已覆盖范围。

局部问题回绑 G4，跨场结构、节奏与全局风格问题回绑 G5；修复后更新受影响证据，G6 检查当前文件的必改项闭环并保留重开权。技术通过不能关闭未兑现问题。设计对照不新增代理、评审轮、storyboard／运行时字段、CLI 命令、自动审美判定、导出硬门禁或用户审批。

### 减法与唯一画面（按问题选用的诊断）

删 30% 与唯一画面是诊断工具，不是每片必答的完成条件。出现无用途重复、等待、收束或视觉核心问题时，可用它们帮助定位：

1. **删 30% 问**：若成片只能保留 70%，按什么顺序删除哪些具体场景、镜头或时间范围？
2. **唯一画面问**：若整片只能留下一个画面，留下哪个？以过程、对比或并置为记忆单位的作品可以回答一个完整瞬间或窗口，但仍须具体到时间码与镜头。

由执行该项诊断的人回答；G5 内部检查可由制作助手记录，G6 或适用核心评审可由独立评审者记录。制作助手可补充自己的答案与分歧。删除问题应给具体位置与保留理由，不能只写「压缩解释」「都很重要」；唯一画面应给不可替代理由。诊断缺失本身不否决；指不出任何画面或瞬间且实际构成视觉核心缺失时，登记问题并退回方案、关键帧或镜头设计。两问不表示必须实际删掉 30%，不改变减法复核「不设删除比例」的规则，也不新增 CLI 门禁或自动评分。方法模板见[全片导演审查](director-review-and-edit.md#不可替代性两问按问题选用的诊断)。

### 静态目标验证（按风险使用）

本验证只在审核计划声明 `static-expression` 风险时适用，属于相关风险的完成条件，不新建阶段。A 级标签本身不触发。正式扩展前，在作品 `DESIGN.md` 记录足以指导制作的美术方向与共享规则。核心对象和试验问题明确后，可先做低成本构图或实际场景草样帮助形成方向，并记录其证据精度和结论范围。用户已给出足以执行的方案时直接采用并只补齐未指定细节。

仅为风险范围内需要判断的状态制作独立目标关键帧。关键帧本身不能来自 TSX/代码场景、动画渲染或 lookdev 截帧；实际场景原型可作为原型证据使用，但不能冒充独立目标图。记录关键帧与检查点对应、目标尺寸和手机验收点。其他段落不补造目标图。

独立目标图用于说明设计目标，实际原型可以同时探索设计与技术可行性；原型能证明的范围由其主体资产、动作、时长和显示条件决定。改变已确认目标时，记录原因、收益和损失，并按影响重做对应静态评审或实际表达观察。

适用风险的核心盲看先提供去掉设计理由和说明文字的目标图并保存实际观察，再按需查看最终文案检查图文层级。记录核心关系是否成立、主体尺度与焦点的具体依据，不打分、不用票数。多张目标图需要检查构图、尺度、亮度层级与机制是否有重复；实际关系或表现失败时回到相应设计或实现层。偏好建议不自动成为否决。连续两轮参数微调无改善时改换视觉机制或美术方向。无静态表达风险时不制作目标图。

实际原型可以用于探索设计和技术可行性。适用目标图是后续实现的参考；没有目标图的场景按其声明用途、实际表现和适用风险验收。实质偏离须记录原因、收益与损失，并按影响复查。

### 核心事件短循环（扩展全片前，core-event 触发）

审核计划存在 `core-event` 风险时，先只推进一个最能代表核心表达、失败代价最高的事件窗口。选择依据、其他尚未验证的核心风险及为何此事件优先，记入 `DESIGN.md`；它并入核心样片轮，不增加阶段、CLI 门禁或评分。无该风险的作品说明不适用原因，不为形式制造动态样片。

试制前在 `DESIGN.md` 写清事件的初态、原因、变化、结果与完整观察窗口，并预先声明：观众应看见的关系、新认识出现的时刻、手机显示尺寸、理解与表现各自的通过条件、关键变化与揭示的时间结构与容差，以及会导致失败的误读或不可见现象。理解条件描述观众能复述什么；表现条件描述关键变化是否被构图、尺度、节奏与注意力突出。两者分开判断，不用其中一项替另一项通过。

首轮只制作覆盖初态、关键变化、揭示（适用时）和结果的低成本完整动态粗样，并按声明的时间结构核对关键时点、停顿与消化。保留判断因果所需的主体、画面比例、运动和观察时间；不扩展其他段落或投入全片精修。每项运动都应服务于信息揭示、关系或尺度变化、空间导航、情绪推进等至少一种表达作用；若运动没有增加理解或观看体验，应删减或改为静态，不为「像视频」制造动效。评审包绑定同一候选和完整事件窗口，提供连续候选文件（若评审环境可访问）及有序时间码帧序列，按风险加密关键转折；不得假设代理能播放视频。材料不足以判断时补证，不能当作通过。

由独立评审者先盲看并记录实际看到的变化、理解的关系、获得新信息的时刻、注意力与最有记忆的画面，再核对预先声明的中性条件。评审包不包含设计理由、预期答案或旧结论。若环境不能播放连续候选，报告必须区分帧序列支持的观察与无法确认的帧间运动；关键条件证据不足则不进入扩展。

短循环按[四种推进／回退决策](#核心样片与全片粗片的回退决策)记录：核心理解和表现都成立且证据充分，才以该事件作为后续设计基准；局部缺陷按原条件修复；证据不足补试制；设计或技术路线根本失败立即退回对应层。相同核心问题连续两轮无改善，停止同类微调，匿名比较不同表达机制，必要时换机制。评审分歧或证据不足时补证/复核，不以多数票或作者说明放行。其他段落仍须在后续全片粗片和最终候选中各自验收；一个事件通过不代表全片通过。

## 三类记录

1. `DESIGN.md`：立意六项、适用时的候选与比较，或直接采用的用户方案及必要假设；另含视觉创意七段式（含按问题使用的十项自检与例外留痕）、镜头等级清单、必要的风险窗时间结构、关键镜头导演卡及其 storyboard 映射、全片强弱与表达统一、受众、共享美术规则、逐场目标、必要的特殊技术与动态设计。模板见[视觉创意导演方法](visual-creative-direction.md)与[逐场设计](visual-creative-direction.md)。
2. `outputs/visual-notes.md`：阶段汇总、唯一问题表、证据索引、每轮评审引用、按问题选用的减法与唯一画面诊断结论、最终传播表现与交付结论。问题模板见[版本与问题闭环](visual-review-rubric.md#版本与问题闭环)。
3. 独立评审原始报告：保存原始观察，不复制全文到主记录；主记录直接链接报告及需要保留的证据文件。

每个问题只登记一次，场景与导演结论引用同一 ID；每个场景和内部镜头仍须覆盖，合并记录不免除验收。信息推进合入粗片逐段观察，传播假设写入设计，最终评估写入主记录，不另建潜力报告。

设计方法见[核心体验与表达设计](creative-production.md#核心体验与表达设计)；评审按[缺陷、风险、偏好与证据不足](visual-review-rubric.md#缺陷风险偏好与证据不足)分类。完整表达窗口是判断单位，开场诊断不自动否决后续揭示；创意风险不得仅凭设计意图放行。

## 技术链路

声音随画面事件设计：分镜记录需发声的动作与作用，代码合成或第三方音频先导入统一音效库，再用 `assetId` 和场景帧偏移定位。制作与迭代一并核对动作同步、质感、重复与旁白遮挡，最终检查波形、峰值、声道和循环接缝；自动信号通过不等于听感评审通过。命令、配方、来源与播放字段见[统一音效库](article-media-and-sound.md#统一音效库)。

当前实现基线采用 **v8 分镜 + React 全画布代码场景**，使用 project.json 与 storyboard.json，源码在 scenes/。这是现阶段的实现方式，不改变「先确定目标画面、再选择实现方案」的制作原则。若目标视觉需要其他资产或预渲染内容，可按现有素材契约导入，由 React/TSX 场景负责时间轴、组合与全画布呈现；视觉设计决定具体画面，代码绘制、3D、图片、视频、模型或预渲染素材可按当前素材与运行时契约组合使用。当前可通过素材 ID 解析已导入图片与视频；其他媒介须由场景实现或转换为当前支持的素材形式后使用，不因此反向限制关键帧设计。命令以[制作 Skill](../SKILL.md)为准：材料审查与选音 → prepare → 按需关键帧/短片检查 → render 保存一次完整候选 → 自动技术验收并交付同一文件。prepare 不录制全片；preview 只做局部片段检查，使用默认前十秒或显式短窗口，不得用接近全片的窗口代替正式生成；关键帧只采所需帧；正式生成复用区间缓存。重试验收或复制不重复编码，失败保留旧有效成片。

源文、素材、场景、旁白、字幕或实现依赖变化须重新 prepare。技术交付与制作复核分别报告；CLI 的状态、可选 review.json 与导出行为保持不变。

## 检查与证据

手机显示尺寸及主体辨认、动作理解、关系理解的适用目标分别声明；无动作表达不强制添加动作目标。检查采用时间标注帧序列、风险加密帧、量测与自动音频信号，不要求播放或试听；主观听感及采样间运动限制如实披露。无声作品保持无声，静音验收替代响度目标。声明了时间结构的风险窗按结构核对关键变化与揭示的时点、停顿和消化，时机偏差用时间标注帧序列记录，不用静帧代替。

每个最终交付文件均完整检查。局部变更复查本场及衔接，结构、时长与全局风格变化复查全片；证据复用与隔离见[评审包](subagent-review.md#评审包)。事实、许可、技术 QA 不由代理观感替代。

### 指定时刻的单帧检查

日常看图用 `lookdev` 的取点模式：`--sheet` 按秒指定时刻拼图、`--motion` 看区间转场、`--det` 核对同帧一致性、`--event` 围绕幕内事件取发生前/关键帧/发生后/结果停留。事件模式需要 `sceneId:eventId` 和显式 `--before`/`--after`，窗口越界或事件簇会在采集前报错或警告；它只解析当前准备记录，不自动绑定检查点。这些都是预览，不构成制作证据。

需要按 DESIGN.md 合同采集的指定时刻，仍执行 `m2v gates check --project <作品> --gate G4 --checkpoint <ID>`，直接按真实时钟采集；不再复制临时项目或注入 stillT 改写正式时间。

## 检查点制作门

制作合同、门与审核轮的绑定、问题闭环和基线保留统一见[检查点契约](checkpoint-gates.md)。本页维护阶段操作顺序，不另行定义审核人数与触发规则。

## 完整段落试制与逐段扩展

本节是阶段内执行顺序的权威，沿用三阶段、DESIGN.md、原时间线及唯一问题清单，不新增阶段、表单或审核轮。

### 设计时选定试制

在原逐场表或导演卡标记最难关系、最小完整试制段落、观众看后应能复述的认识和实际覆盖风险。优先让同一段兼顾开场与核心风险；不能覆盖时分别补足，不让一个段落的通过授权其他风险。时长由关系建立、变化、揭示和观察需要决定，不机械做满 30 秒，不把全片摘要塞进开场。

### 同一段材料持续完善

1. **连续构图**：在现有逐场表／导演卡附图或引用，先解决主体尺度、全中近景的选择、观众认识顺序与镜头承接。按实际需要取图，不要求固定张数，但四张叙事基准构图仍按原规则单独制作，不被本节草图替代；构图草图不替代 `static-expression` 风险所需的独立目标关键帧及盲审，也不替代适用 animatic。
2. **动态实现**：以实际主体、字体、字幕或适用文字、关键动作和必要声音完成这个段落，验证过程与结果；占位资产只证明已覆盖的技术范围。核心未通过前不扩展依赖它的高投入实现，不先堆装饰。计划声明 `core-event` 风险时，本节动态实现沿用[核心事件短循环](#核心事件短循环扩展全片前core-event-触发)的完整窗口、`DESIGN.md` 预声明条件与时间容差；其低成本动态粗样就是同一材料的前一版本，通过后继续完善而非另造样片。
3. **检查与修改**：按[检查与返工循环](#检查与返工循环)选择工具，沿原问题清单修订同一份可编辑材料；适用独立观察及设计对照仍按审核计划、隔离包与原窗口执行。
4. **保留并扩展**：试制通过后作为正式作品的一部分继续完善，不因从试制转正式制作而另造一套同用途场景或样片。复用材料不等于继承通过：版本、依赖、范围、合同绑定与隔离要求仍须满足；局部 lookdev 预览不直接成为 G4 合同证据。

### 每段完成一个关系

扩展时在原逐场记录写明本段只讲清什么、哪些解释留到后段。按分镜共同组织画面、字幕和声音：字幕讲述正在发生的动作时，让对应动作及时发生并留出看清结果的时间；也可让画面先演、字幕随后揭示，或让字幕与动作重叠。原项目以字幕出现后约 0.3 秒内启动对应动作为创作参考，具体时机由阅读与讲解需要决定，不设统一门槛或空白比例。无字幕、无声或纯文字段落按用途安排，不强加声音与动作。

按[贯穿对象、事件和完整动作](explainer-design.md#贯穿对象事件和完整动作)协调共享事件时刻、角色跨镜状态及必要声音，按内容留观察或纯画面窗口；复核覆盖关键变化及相邻衔接，分别说明声音与画面的证据覆盖。

普通段落自查并完成相关检查即可，不逐段新增独立评审；该段有计划风险时仍按覆盖要求验证。问题可定位就修复并同范围复查，无实质问题直接继续，不为凑次数强制改两轮，也不把重新渲染视为已关闭。静态问题重看相同时刻，运动问题复查完整动态窗口，均核对相邻衔接及有效表达是否损失。连续两轮失败的升级规则继续生效。

全部段落形成后，制作助手执行 G5 全片内部粗片检查，集中发现局部制作看不到的跨场问题；问题在制作与迭代内关闭，再进入 G6 独立终审。逐段通过不等于全片通过；适用核心风险评审与最终终审按[检查点契约](checkpoint-gates.md)执行，G5 不派独立代理。

## 检查与返工循环

制作与迭代不分粗片交接与精制交接。一份问题清单按「发现 → 修改 → 同范围复查 → 关闭」持续更新，记录时间范围、目标、收益与损失及证据引用；不另写两份阶段总结和计划。

| 问题 | 按需检查与复查 |
|---|---|
| 初次静态画面检查 | 代表性 lookdev 与指定 `--sheet` 二选一，不重复生成同用途拼图 |
| 已知时刻的文字、构图、颜色 | `lookdev --sheet` 重截相同时刻及必要对照；不为局部静态修改例行渲染全片 |
| 动作或转场 | `lookdev --motion` 定位中间状态，用完整动态窗口确认节奏、因果及相邻衔接；拼图不替代动态证据 |
| 对象状态、裁切、安全区 | 修改后重跑受影响检查点，不重跑无关检查 |
| 同帧输出不一致 | 按需 `lookdev --det`，普通构图或文案修改不例行执行 |
| 跨场结构与全局节奏 | 扩大到全片检查，不能靠局部帧放行 |

当前有效且满足版本、依赖、范围和隔离要求的材料可复用；过期项按实际绑定重新取证，不手改指纹或复制旧通过。问题收敛后进入最终验收，以当前完整候选完成原有技术 QA 和 G6 适用终审。G5 是内部制作检查，G6 是独立交付终审；各工具不是新增制作门、用户审批或完整渲染前置。
