# 已有视频的修订入口

本入口整理已有制作规则与命令，供助手处理“改一下这支视频”。影响分析由助手完成，缓存复用与证据有效性以现有工具结果为准；没有新增 `m2v revise` 命令、自动差异分析器或完成凭据。

## 接收修改意图

用户只需说明作品、修改位置或现象、期望结果，例如：“把结尾最后一句换掉，再多停留两秒，其他内容保持原样。”先从会话、作品目录和成片定位，不要求用户提供文件清单或命令。只有无法定位作品、要求相互冲突或歧义影响结果且材料无法消解时才询问；范围明确后直接执行常规修改与检查。

读取 `project.json`、总设计及受影响的[场景设计](scene-design.md)中的原承诺、当前结果和关键未知、可编辑材料、当前交付和已有记录，核对成片是否对应这些材料。只有 MP4 而缺少可编辑源时，说明缺失内容与可恢复范围，不能声称可以完整复用原制作链路。五类作品共用独立评审和制作验收；引用 financial-series 等结构化来源时，再展开对应来源契约。旧类型作品按当前 project v3、分镜 v9 重新编排到 `videos/<类型>/<作品名>/`，按当前交付与独立评审规则交接，不自动迁移或继承通过。

五类作品在现有 `DESIGN.md` 的重制启动记录中写本轮目标、保留约束、旧版时间范围、受影响场景/镜头/旁白/声音、重入阶段与理由、当前证据范围；问题仍使用 `outputs/visual-notes.md` 的唯一问题表。记录要求见[重制启动](production-workflow.md)，不另建平行问题表或合同。存量作品不因使用本入口追溯升级合同、补造历史证据。重制切换制作周期时，已关闭独立问题保持原周期闭环并继续核验历史证据摘要；不把旧源码与当前源码比较，也不把旧闭环算作新版通过。历史未关闭项保留未完成，不得借新周期的报告直接关闭。

## 按影响选择最短路径

| 修改 | 重入与检查范围 |
|---|---|
| 文字、布局、素材或声音质感调整 | 从精修切入，检查受影响画面、时点或信号、手机可读性及必要衔接。目标画面变化时补适用静态评审。 |
| 动作、揭示顺序、局部旁白、镜头时长或声音时点变化 | 回到关键过程或片段粗排。更新实际时间轴，检查动作、读数、字幕、配音预算、声画同步和后续偏移。 |
| 开场承诺、删段、章节或跨场结构变化 | 回全片预演，核对信息、指代、跨场节奏和首尾。核心目标或机制改变时，先回[研究与试制](stage-research.md)核对案例和已验证实现，再按缺口选案。 |
| 当前候选的验收或交付问题 | 走[验收交付](stage-production.md#验收交付)，复用当前有效证据。 |

按实际依赖扩大范围，不按字数或文件数判断：换图可能改变布局与许可，改一句话可能改变时长、事实和字幕，共享组件修改可能影响多个场景。不能因为用户说“小改”而跳过连带检查；也不因局部问题重做无关选案。

受影响的设计按[逐场循环](scene-design.md#渐进设计与开发循环)补查、实现和回写。

局部修订先核对当前制作周期及有效证据，不因新增请求例行重启周期、重做整套研究或追溯补造旧记录；实际过期或覆盖不足的项按绑定重取，新版完成条件仍适用。

风格未兑现的反馈先回到具体参考、深入拆解和本片转化，查清目标效果形成机制与当前差距，再做代表性实际画面并独立对照；不能直接换色、换字体后继续铺满全片。用户只要求方案和图片时，交付参考与本片画面的对应展示、关键拆解及未覆盖范围，不擅自制作完整新版。

增加或修改注释时，先核对[项目约定](../../../../AGENTS.md#修改规则)允许的注释范围，再按完整出现窗口检查字号层级与位置：从紧、小字、次要位置、不遮挡主体；主题、对象名称、结论和正常字幕不归为注释，不设跨画幅统一像素字号。

## 执行顺序与已有命令

1. **核对当前交付**。确认当前成片、可编辑材料及相关评审证据的对应关系。局部修复和整体重做直接更新当前作品，旧基线与修改前版本副本保留数量为 0。保留当前有效成片，直到新版通过原有交付验证并替换成功。存量旧基线及其专属文件按范围、引用和摘要核实后成组清理。独立评审原件保留在评审记录中，已清理且无同摘要原件的历史媒体注明不可复核，原结论和问题状态保持原样。
2. **修改可编辑材料**：回写分镜、场景、旁白与声音时间窗。未变的表达目标和用户约束继续沿用，旁白未变时沿用音色选择；旁白变化按[配音契约](voice-and-rhythm.md#配音音色与语速)重新判断并更新记录。不要只修改最终 MP4。
3. **准备与局部检查**。直接执行 prepare（包含校验，validate 用于独立排错），按[逐场循环](scene-design.md#渐进设计与开发循环)取得受影响窗口的证据，沿[返工记录](production-workflow.md#检查与返工循环)区分待复查与效果已确认。多个不连续风险分别检查，整片候选使用 render。
4. **处理证据**：查看当前状态，保留仍有效的证据，重做实际过期、受影响或覆盖不足的项。工具若因更广依赖将证据判过期，按实际绑定重新取证，不能手改指纹、复制旧通过或承诺所有未改场景均可复用。适用的独立审核轮按[隔离流程](subagent-review.md)执行，降级自审不得关闭独立项；实际依赖未变的场景证据继续有效。
5. **生成与收口**：按[收敛判断](production-workflow.md)先汇总本批修改、效果证据与仍需全片判断的事项，再 render 生成完整候选；不每修一处就生成全片。全局变化或局部无法验证的问题按影响扩大检查。导出后核对 `status` 中的技术 QA 与当前 MP4 摘要；若报告缺失或仍绑定旧版，对当前 `video.mp4` 执行 `m2v qa`，复用已经导出的文件。按[验收交付](stage-production.md#验收交付)复查受影响的独立证据，由总代理基于当前候选的抽帧、时间轴和适用信号复核整片并登记。失败时保留旧有效交付，报告原因。

以下是五类作品局部修订的命令示意，由助手替换作品路径、实际旧片名称和新版检查窗口；不是要求用户逐条操作。这里的 20–25 秒仅示意一个局部窗口。

```powershell
uv run m2v status --project videos/<类型>/<slug> --history
# 此处修改作品材料，并记录影响范围
uv run m2v prepare --project videos/<类型>/<slug>
uv run m2v preview --project videos/<类型>/<slug> --start-seconds 20 --end-seconds 25
uv run m2v status --project videos/<类型>/<slug> --history
# 按影响补做检查、评审与问题复查后生成完整候选
uv run m2v render --project videos/<类型>/<slug>
# 当前技术 QA 缺失或过期时，检查刚导出的文件
uv run m2v qa --project videos/<类型>/<slug>
# 对当前候选执行最终复核、登记证据后核对完成状态
uv run m2v status --project videos/<类型>/<slug> --history
```

录制区间、配音和其他缓存按实际依赖与命中结果复用，不保证仅重新渲染某个场景。命令与交付细则见[命令](../../../../README.md#命令)和[交付与溯源](delivery-and-provenance.md)。

## 修订交付

沿用[当前版本完成汇总](visual-review-rubric.md)，简要补充：修改前后差异、保留项、受影响及实际复查范围、当前交付与缺失的历史媒体。技术交付与制作复核分别报告，并共同绑定新版文件 SHA-256；列出未关闭问题与未覆盖范围。不能以局部检查通过替代最终全片复核，历史通过仅对应当时的媒体和观察条件。

## 操作判断演练

以下为文档演练，不代表实际制作或独立评审完成：

| 请求或状态 | 预期处理 |
|---|---|
| 修复第三场标签裁切，旁白和时长不变 | 核对当前成片，修复本场，复查完整窗口和衔接，沿用有效音色，不重开选案；最终仍复核全片 |
| 最后一句替换并延长两秒 | 核对音色记录、旁白预算、字幕和音轨末端；重新 prepare，以新版时间定位窗口，不沿用旧结束时间 |
| 重排中间两章 | 按结构修改检查因果、指代、时间轴及全片节奏，返回研究与创意试制或制作与验收的受影响活动 |
| 修改共享场景组件 | 检查所有实际引用者，不仅检查用户最先指出的场景 |
| 局部评审仍有效 | 按实际依赖保留，优先补足未覆盖的范围 |
| 工具判旧证据过期，助手认为画面没变 | 不改写旧摘要强行通过，按绑定与覆盖要求补取当前证据 |
| 存量作品只有旧片和不完整记录 | 如实保留缺失状态，不补造旧通过；先解决本轮所需来源与材料，未满足项明确报告 |
