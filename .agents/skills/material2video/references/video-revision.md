# 已有视频的修订入口

本入口整理已有制作规则与命令，供助手处理“改一下这支视频”。影响分析由助手完成，缓存复用与证据有效性以现有工具结果为准；没有新增 `m2v revise` 命令、自动差异分析器或完成凭据。

## 接收修改意图

用户只需说明作品、修改位置或现象、期望结果，例如：“把结尾最后一句换掉，再多停留两秒，其他内容保持原样。”先从会话、作品目录和成片定位，不要求用户提供文件清单或命令。只有无法定位作品、要求相互冲突或歧义影响结果且材料无法消解时才询问；范围明确后直接执行常规修改与检查。

读取 `project.json`、可编辑材料、当前交付和已有记录，核对成片是否对应这些材料。只有 MP4 而缺少可编辑源时，说明缺失内容与可恢复范围，不能声称可以完整复用原制作链路。金融与住宅沿用各自类型契约，不调用仅支持 general 的 gates/baseline 命令。

general 在现有 `DESIGN.md` 的重制启动记录中写本轮目标、保留约束、旧版时间范围、受影响场景/镜头/旁白/声音、重入阶段与理由、基线位置；问题仍使用 `outputs/visual-notes.md` 的唯一问题表。记录要求见[重制启动](production-workflow.md#重制启动)，不另建平行问题表或合同。存量作品不因使用本入口追溯升级合同、补造历史证据。

## 按影响选择最短路径

| 修改 | 重入与检查范围 |
|---|---|
| 局部文字、布局、素材替换 | 沿用有效方案；检查本场完整事件窗口、手机可读性及相邻衔接；目标画面变化时补相关静态评审 |
| 旁白、镜头时长、删段、声音调整 | 更新分镜和声音窗口，重新准备时间轴；检查配音预算、字幕、同步、后续时间偏移与跨场节奏 |
| 开场承诺、核心事件、揭示顺序、章节结构变化 | 回到相关设计与核心粗样，重验全片结构；按影响更新审核计划中的风险与对应轮次 |

按实际依赖扩大范围，不按字数或文件数判断：换图可能改变布局与许可，改一句话可能改变时长、事实和字幕，共享组件修改可能影响多个场景。不能因为用户说“小改”而跳过连带检查；也不因局部问题重做无关选案。

增加或修改注释时，先核对[项目约定](../../../../AGENTS.md#修改规则)允许的注释范围，再检查字号层级与位置：一律用明显小于主体文字的小字，置于次要位置；不得遮挡主体、关键数据、字幕或关键动作，不得争夺焦点。示意／实拍边界标注按次要标记设计，以大屏原尺寸可辨、手机横屏不可辨为目标，不要求手机尺寸可读；承载必要信息的口径与其他注释仍须可读，素材署名默认可读、用户明确要求缩小时须把完整署名与许可留在作品材料与发布说明。空间不足优先精简或调整位置。主题、对象名称、结论和正常字幕不归为注释，不设跨画幅统一像素字号；按[视觉复核](visual-review-rubric.md#反目标写进-designmd按题材检查)覆盖完整出现窗口。

局部实现、视觉、字幕与声音修订进入[制作与迭代](stage-iterate.md)，核心目标或主线改变先返回[方案确定](stage-plan.md)，当前候选的验收与交付问题进入[最终验收](stage-final.md)。

## 执行顺序与已有命令

1. **保护旧版**：在改材料与覆盖输出前核验旧片，记录 SHA-256 和来源。general 局部修复用候选基线，整体重置才创建重置基线。基线不包含完整可编辑源码；需要恢复编辑状态时，同时保留受影响材料的修改前副本到作品内容目录，记录位置，不把作品内容强行加入 Git。基线规则见[基线保留与清理](checkpoint-gates.md#基线保留与清理)。
2. **修改可编辑材料**：回写分镜、场景、旁白与声音时间窗。未变的表达目标和用户约束继续沿用，旁白未变时沿用音色选择；旁白变化按[配音契约](voice-and-rhythm.md#配音音色与语速)重新判断并更新记录。不要只修改最终 MP4。
3. **准备与局部检查**：执行 validate、prepare；按问题采集并实际查看修改后的帧或完整动作短窗口，覆盖事件起止和相邻衔接。按[检查与返工循环](production-workflow.md#检查与返工循环)在原问题正文区分待复查与效果已确认；多个不连续风险分别检查，不能用接近全片的 preview 替代 render。
4. **处理证据**：查看当前状态，保留仍有效的证据，重做实际过期、受影响或覆盖不足的项。工具若因更广依赖将证据判过期，按实际绑定重新取证，不能手改指纹、复制旧通过或承诺所有未改场景均可复用。等待前置不等于自身过期。适用的独立审核轮按[隔离流程](subagent-review.md)执行，降级自审不得关闭独立项；实际依赖未变的场景证据继续有效。
5. **生成与收口**：按[收敛判断](production-workflow.md#再次全片生成前的收敛判断)先汇总本批修改、效果证据与仍需全片判断的事项，再 render 生成完整候选；不每修一处就生成全片。全局变化或局部无法验证的问题按影响扩大检查。自动技术验收并交付同一文件；已有摘要有效候选的验收/交付重试复用该候选，不重复编码。最终完整复核和独立终审按[导演审查](visual-review-rubric.md)及当前合同执行，保留重开权。失败时保留旧有效交付，报告原因。

以下是 general 局部修订的命令示意，由助手替换作品路径、实际旧片名称和新版检查窗口；不是要求用户逐条操作。基线的 `--files` 相对输出根，先确认文件存在。这里的 20–25 秒仅示意一个局部窗口。

```powershell
uv run m2v status --project videos/general/<slug> --history --json
# 修改材料之前保护旧交付；整体重置时去掉 --candidate
uv run m2v baseline create --project videos/general/<slug> --candidate --reason "结尾局部修订" --files video.mp4
# 此处修改作品材料，并记录影响范围
uv run m2v validate --project videos/general/<slug>
uv run m2v prepare --project videos/general/<slug>
uv run m2v preview --project videos/general/<slug> --start-seconds 20 --end-seconds 25
uv run m2v status --project videos/general/<slug> --history --json
# 按影响补做检查、评审与问题复查后生成完整候选
uv run m2v render --project videos/general/<slug>
# 对当前候选执行最终复核、登记证据后核对完成状态
uv run m2v status --project videos/general/<slug> --history --json
```

录制区间、配音和其他缓存按实际依赖与命中结果复用，不保证仅重新渲染某个场景。命令与交付细则见[命令](../../../../README.md#命令)和[交付与溯源](delivery-and-provenance.md)。

## 修订交付

沿用[当前版本完成汇总](director-review-and-edit.md#完成边界)，简要补充：修改前后差异、保留项、受影响及实际复查范围、旧版基线与材料副本位置。技术交付与制作复核分别报告，并共同绑定新版文件 SHA-256；列出未关闭问题与未覆盖范围。不能以局部检查通过替代最终全片复核，也不能以基线中的旧通过证明新版完成。

## 操作判断演练

以下为文档演练，不代表实际制作或独立评审完成：

| 请求或状态 | 预期处理 |
|---|---|
| 修复第三场标签裁切，旁白和时长不变 | 候选基线，修复本场，复查完整窗口和衔接，沿用有效音色，不重开选案；最终仍复核全片 |
| 最后一句替换并延长两秒 | 核对音色记录、旁白预算、字幕和音轨末端；重新 prepare，以新版时间定位窗口，不沿用旧结束时间 |
| 重排中间两章 | 按结构修改检查因果、指代、时间轴及全片节奏，返回方案确定或制作与迭代的受影响活动 |
| 修改共享场景组件 | 检查所有实际引用者，不仅检查用户最先指出的场景 |
| 自身检查有效但等待上游门 | 保留自身有效结果，先处理缺少的前置，不重复采集该检查 |
| 工具判旧证据过期，助手认为画面没变 | 不改写旧摘要强行通过，按绑定与覆盖要求补取当前证据 |
| 存量作品只有旧片和不完整记录 | 如实保留缺失状态，不补造旧通过；先解决本轮所需来源与材料，未满足项明确报告 |
