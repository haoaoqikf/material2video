# 视觉创意导演方法

本页只服务 `general` 作品：在[立意六项](production-workflow.md#立意六项方案确定前)与三案选定方案之后、逐场设计与关键画面之前，把抽象主题转成一个可执行的视觉世界。金融与住宅只执行适用项，并记录不适用原因；它们的专用图表、画幅与声音契约不变。

## 1. 适用范围与边界

- 这一阶段以**视觉创意导演**身份工作：不是 UI 设计师，不是 PPT 设计师，不先排页面、卡片、标题或图标，而是先找视觉隐喻和正在发生的变化。
- 七段式是**必答问题**，不是质量评分、用户确认、运行时字段或 CLI 门禁。每项都要在作品 `DESIGN.md` 回答；题材不适用时写明原因与替代做法。
- 不强制重复母题、反转、传统高潮、持续运动或额外装饰。允许回答「本片不采用统一母题」「本片不设传统高潮」「本片不设独立视觉揭示」，但必须写替代组织方式与记忆点。
- 七段式属于设计记录，**不进入独立评审包**。评审包仍只收中性可观察目标与证据，不得投喂 `DESIGN.md` 或设计理由。
- 先问一句总原则：**这个概念能不能变成一个正在发生变化的东西？** 能，就优先用变化表达；不能，再考虑文字对照、档案并列或图表。

## 2. 与现有流程的衔接

常规制作顺序是：立意六项 → 三个叙事候选 → 选定方案 → 七段式中确定载体与核心视觉事件 → 美术方向 → 每个核心段落的独立目标关键帧及盲审 → 一个最高风险动态完整窗口原型 → 全片粗预演 → 精修 → 最终验收。用户提供足以执行的详细设计时，直接采用用户方案并进入七段式落实，不强制叙事或美术多方案选案；其余视觉事件、关键帧、视觉力量与呈现效果验证仍适用。

## 关键帧美术验证门

动画场景实现开始前，先在唯一设计文档 `DESIGN.md` 固定美术方向。按作品适用性说明人物造型、材质、光线、空间尺度、镜头、景深、色彩和构图规则；记录参考的来源、访问日期、用途和授权边界。参考图存入 `outputs/design/references/`。

为每个核心段落独立制作一张最终目标关键帧，存入 `outputs/design/keyframes/`。工具不限，但设计工作必须独立于动画场景：不得直接使用代码场景截图、动画渲染帧或 lookdev 静帧充当关键帧。关键帧是目标而不是实现快照，应有最终构图、主体尺度、焦点、层次、光线与情绪；在 DESIGN.md 登记文件路径、对应段落/镜头 ID、目标以及手机显示验收条件。它优先表达期望的最终观感，不要求先证明当前渲染技术可实现；不得因技术方案尚未验证而自行降低设计目标。

静态评审先盲看不含设计理由的画面；首轮评审图去掉说明性文字，独立记录观察后，再按需要查看含最终文案版本核验文字层级。每幅画需记录核心关系理解、吸引力、与其他段落的视觉差异、记忆画面潜力、尺度和视觉焦点的具体证据。不设审美分或通过人数比例。逐帧评审后，把全片所有关键帧按时间顺序并排查看，检查构图、主体尺度、亮暗层级与视觉机制的重复。若不同段落只是替换拓扑、文案或对象数量，而构图、尺度与机制没有实质变化，集合检查不通过。若重复母题有明确叙事作用，且画面关系、状态或观众认识确实推进，可在 DESIGN.md 记录依据后保留。核心理解不成立，或有关键视觉必改项未关闭，就回到事件设计或美术方向，不能动画。单纯偏好作为建议记录；若关键帧整体仍未形成有吸引力、可辨识且有记忆点的最终画面，不得以作者解释放行。连续两轮只微调参数仍无明显改善，必须换视觉机制或美术方向后重做关键帧。确无核心视觉段落或静态表达不适用时，在 DESIGN.md 记录理由和替代验证。

静帧门通过后再单独评估技术可行性。若当前方案难以实现，优先寻找保留关键视觉目标的实现机制；若目标画面需要改变，则修改稿必须重新经过静态评审。动态表达适用时再按[核心事件短循环](production-workflow.md#核心事件短循环扩展全片前)制作高风险完整窗口原型；原型通过才扩展全片。已通过关键帧是后续制作的视觉合同，不只是参考图。动画和精制须定性对照主体比例、镜头角度、亮暗关系、空间层级和关键视觉事件是否兑现；不要求像素级一致，但实质偏离须记录原因、收益与损失并复核。

七段式**不新增阶段名**，它属于「方案确定」阶段。三个候选阶段只为各案提出核心表达与母题候选，不要求先锁死一个母题；否则会压缩选案空间。至少两案必须在讲述机制上不同，不能只换母题名称或美术表层。

七段不是平行表单，逐项回填现有区块：

| 七段 | 回填位置 |
|---|---|
| 核心表达 | 立意六项「一句话命题」 |
| 核心视觉母题 | 立意六项「表达载体」 |
| 整体视觉风格 | 作品视觉方向与共享美术规则 |
| 分镜设计 | 逐场设计表 |
| 视觉高潮 | 全片强弱与核心体验 |
| 结尾视觉揭示 | 立意六项「揭示与记忆」 |
| 禁止项 | `DESIGN.md` 的反目标 |

## 3. 核心表达

用一句话回答：**这个主题真正想表达的变化、冲突或规律是什么？** 不要复述标题。

- 写观众看完能用自己的话复述的主张，以及「原来如此」的那一下。
- 反例：只写「美国科学高光」「人生五个选择」「太阳系介绍」——这些是题目，不是表达。
- 正例：「人生差距往往来自少数关键选择，被时间不断放大」「技术能力每扩展一次，能使用它的人就换一批」。

## 4. 核心视觉母题

优先回答：**如果整条视频只能使用一个视觉世界，它是什么？** 固定句式：

> 把 ______ 设计成 ______。

示例：「把人生设计成一条持续向前、不断分叉并可换道的时间轴。」

- 载体必须可随时间变化：对象、空间、系统、运动，或可随时间重组的文字/图形关系。不能只是静态页面、图标集合或装饰符号。
- 常见母题：时间轴、道路、轨道、电梯、河流、树、网络、地图、城市、工厂、游戏地图、棋盘、天平、漏斗、沙漏、齿轮、管道、星系、建筑、山峰、阶梯、迷宫、仪表盘、生长系统。
- **核心视觉母题 ≠ 母题重复。** 前者是整片的组织载体（单数，不要求重复出现）；后者是同一载体多次出现并产生新作用。核心载体可以只出现一次，也可以在状态、关系、情绪或语境中改变含义；不要求重复三次、外形持续变化或单调增长。
- 检验：删掉这个载体，影片是否失去组织？只换配色、字体或版式不算母题。
- 不采用统一母题时，按立意六项「表达载体」记录替代组织方式与各段作用，不写「统一风格」四个字了事。

## 视觉事件设计

视觉隐喻回答「用什么表示这个概念」；视觉事件回答「画面中发生什么变化」；导演设计回答「观众按什么顺序看到这些信息」；节奏设计回答「每个信息何时出现、停留多久」；视觉力量回答「哪个变化以多大的尺度和层级出现」。不要只设计这一幕长什么样，还要安排观众先看到什么、暂时不知道什么，以及新信息如何改变其认识。

### 接入位置与记录方式

选定方案、确定视觉母题或替代载体后，逐场构图与关键画面前，先设计核心视觉事件与 A 级镜头的时间结构，再为关键表达镜头写导演卡；都属于「方案确定」，不新增阶段。核心表达镜头填写下方五段式，普通镜头简写状态、变化、结果。沿用 `DESIGN.md` 逐场设计表的「可见事件」栏和导演卡区块，较长内容在同文档内链接，不新增平行文档。

### 五段式模板

**初始状态 → 变化 → 预期 → 揭示 → 结果**。画面状态与观众认识是两条相互对应的线；事件可以跨多个镜头，按完整表达窗口设计。

| 部分 | 画面状态：发生什么 | 观众认识：此时知道什么 |
|---|---|---|
| 初始状态 | 主体、起点、相同与不同的条件是什么？ | 已知什么，尚不知道什么？ |
| 变化 | 什么移动、增长、断裂、分叉、连接或改变？由什么引起？ | 已看见哪些线索，哪些关系仍未知？ |
| 预期 | 此时只公开了哪些局部或关系？ | 会形成怎样的初步判断或期待？不必故意误导。 |
| 揭示 | 何时公开此前未见的信息、因果或全貌？ | 哪个新信息补全或改变此前理解？ |
| 结果 | 主体最终怎样，哪些关系发生改变？ | 新理解是什么，有哪些画面证据支持，哪些仍需文字补充？ |

每个核心事件补一句**镜头的信息职责**：隐藏、公开或强调什么，在哪个时刻执行；不能只写「推进」「高速拉远」。明确表达窗口、结果观察时间及手机尺寸下的失败现象，供粗样验证。

无反转的直接因果、观察与收束表达，允许将预期或揭示写为「不适用」，同时说明原因与替代做法；不强制每幕高潮、反转、持续运动或高速拉远。静态文字、档案并置和图表关系也能推进认识。金融与住宅只执行适用项，保持专用图表、声音与材料契约。

### 时间结构：把事件落到时间

五段式回答「发生什么、观众知道什么」，时间结构回答「每个信息何时出现、停留多久、何时揭示」。同一个视觉创意，揭示早半秒或晚一秒可能改变理解，所以 A 级镜头和依赖揭示时机的核心事件必须写时间结构；B 级只写时间预算，C 级不写完整结构。下表是示意，不是固定时长；实际窗口按事件和作品节奏确定。

| 时间 | 段 | 画面状态 | 观众此刻知道／期待 | 必须看见 | 注意力落点 | 时机容差与失败现象 |
|---|---|---|---|---|---|---|
| 0.0–1.5s | 建立预期 | 正常状态与主体关系 | 已知什么，尚不知道什么 | 主体、起点、相同条件 | 先看哪里 | 建立不足时观众会误判什么 |
| 1.5–2.3s | 停顿 | 异常出现但不解释 | 形成疑问或初步判断 | 足以察觉异常的最小信息 | 异常处 | 停顿过长是否变成无用途等待 |
| 2.3–3.0s | 变化 | 差异扩大或关系改变 | 看见哪些线索，仍不知道什么 | 变化的方向与因果 | 变化发生处 | 变化不可见或过早暴露答案 |
| 3.0–4.5s | 延迟揭示 | 信息仍不完整 | 期待如何兑现 | 继续积累的证据 | 观众预期落点 | 延迟过久是否失去耐心或误读 |
| 4.5s | 揭示 | 公开此前未见的信息或全貌 | 哪条新信息补全或改变理解 | 新关系、新尺度 | 揭示后的视觉中心 | 容差范围；早于或晚于时点会怎样误读 |
| 4.5–6.0s | 结果与消化 | 主体进入最终状态 | 新理解是什么 | 结果、回扣或收束 | 结果与观众认识 | 停留不足是否来不及形成认识 |

- 六段按事件需要取舍。直接因果、静态对照、观察或安静收束可以省略停顿、延迟揭示或独立结果，但必须写明原因与替代节奏，不能为填满表格制造无用途停顿。
- 时间先按秒设计，再按作品帧率换算成帧，并与 storyboard 既有 `startFrame` / `endFrame` 对齐；它是五段式的时间投影，不新增 JSON 字段或运行时字段。
- 关键变化与揭示要写**时机容差**：最早、最晚的有效范围及越界后的误读。容差按事件设定，不是统一秒数。
- 动态粗样和逐场验收按声明的完整窗口核对：预期是否建立、揭示是否落在容差内、结果是否有消化时间。时机偏差按导演或节奏问题修订，不用增亮、换色或轻微调速关闭。

### 示例与反例

| 情形 | 事件设计或判断 |
|---|---|
| 完整揭示事件 | 行业：五个光点并排同速 → 跑道坡度分化 → 近景看起来差距不大 → 拉远公开整体高差 → 观众认识到同速不等于相近结果。镜头先隐藏整体差距，再公开全貌；行业高低只作有边界的情境示意，不冒充固定排名。 |
| 无反转直接因果 | 学习：主路受限 → 先前学习形成的连接亮起 → 光点换轨 → 到达可继续前进的路。预期与独立揭示不适用：直接观察因果，以换路前后对比获得认识，不刻意制造错误判断。 |
| 静态文字表达 | 同屏保留两份规则原文，观众依次比较可获得权利的差异。持续运动与独立反转不适用：依靠对照和观察窗口推进认识，不为填模板移动文档或伪造原文。 |
| 有运动但无认识推进 | 光点持续移动、节点不断增加，却未呈现设计声称的关系或结果；不能因为「有动画」就判事件成立。按完整窗口验证，先修因果、信息顺序或删去无用途重复。 |

### 试制、诊断与返工

动态事件按[核心事件的最小动态证据](visual-review-rubric.md#核心事件的最小动态证据)声明取证目标、过程与失败现象；证据不足先补证，不以参数设定或限制披露放行。扩展全片前，按[核心事件短循环](production-workflow.md#核心事件短循环扩展全片前)每次只推进一个最高风险、最能代表核心表达的完整窗口；先写可观察的理解与表现条件与时间结构，再用低成本动态粗样验证初态、变化、揭示（适用时）和结果，并按声明窗口核对关键变化与揭示的时点、停留和消化。独立评审按中性条件盲看；两类条件都成立且证据充分后，才扩展其他段落。静态表达或无实质核心风险时说明不适用，不为流程制造动态样片。证据按现有帧序列、风险加密采样与量测要求采集；采样不足以判断时补证，不凭作者说明通过。候选比较改变表达机制，不只换配色、路径数量或镜头速度；制作精度与显示尺寸保持可比。

先遮去结论句，保留必要标签（对象名称、坐标、图例、事实边界），问「仍发生了什么与观点有关的变化？」「这个变化支持了什么认识？」；再分析文字补足的部分。去文字仅作职责诊断，不是所有题材的通用否决条件。装饰运动不等于事件，文字主导也不等于失败。

独立评审先保存实际看到的变化、理解的关系及获得新认识的时刻，再核对中性目标。对导演设计，必须先盲看完整事件窗口，再记录实际建立的预期、新信息进入时点、注意力竞争与最终认识；不得先读导演卡。设计理由与五段式预期答案不得进入盲审包，仍按[独立评审](subagent-review.md)隔离执行。

返工先区分事件、导演顺序与实现缺陷：因果或认识推进未发生，回到事件结构；事件成立但观众先看到错误信息、预期未建立、揭示时机失效或注意力顺序错误，回到导演卡修订；只有结构与顺序成立、投影重叠、主体过暗、镜头取景或标签布局失效时，针对实现修复。不能用增亮、换色、Bloom 或轻微调速关闭导演问题。修复动作不等于问题关闭，按原条件复查当前有效版本；两轮无改善沿用现有返工升级。

本方法仅用于后续制作与明确启动的重制，不追溯要求已有成片重渲染。示例补写不代表实际试制或验收通过。不新增运行时字段、分镜 JSON 字段、CLI 门禁、审美评分或自动视觉校验器。

核心图形高潮在事件说明后接入[视觉力量设计](visual-impact-design.md)，补足尺度、注意力与动态释放；事件发生不能代替表现通过。完整方法只维护在该参考页。

## 导演设计：观众按什么顺序看到

视觉事件确定后，关键表达镜头还要设计观众的信息路径。它安排观看顺序和注意力，不重复描述载体或事件，也不等同于运镜清单。导演设计属于方案确定阶段，写入同一个 `DESIGN.md` 的逐场设计区；不新增 `DIRECTION.md`。

镜头等级决定投入与评审深度，不表示低等级可以粗糙。作品通常由少数 A 级镜头承担记忆点，其余镜头为它们服务；不要求所有镜头同等强度，也不要求每段都出现峰值。每个场景及内部镜头都要标注一个等级；作品应明确列出 A 级镜头，确实没有时说明原因与替代的视觉核心。

| 镜头等级 | 定义与投入 | 必填内容 |
|---|---|---|
| A｜记忆镜头 | 承载核心表达或视觉高潮，观众看完应能记住；优先投入目标关键帧、完整动态验证与精修 | 完整导演卡与时间结构；独立目标关键帧及盲审；核心事件短循环；核心高潮另补[视觉力量设计](visual-impact-design.md)：尺度参照、揭示前后构图、空间深度、视觉层级、画面占比与注意力变化 |
| B｜推进镜头 | 负责解释、连接、推进、观察或收束，为 A 级服务 | **Scene Goal**：观众最终理解什么；**Visual Event**：画面发生什么变化；**Camera / Attention**：观众先看哪里、镜头行为服务什么观察关系；时间预算。简单直接展示可注明不需隐藏或揭示 |
| C｜功能镜头 | 字幕、转场、必要信息与署名等 | 用途、出现与离开时间、可读性；不写完整导演卡 |

- A 级对应既有「关键表达镜头」，核心高潮再补视觉力量；B 级对应普通叙事镜头；C 级为功能镜头。
- A 级数量按作品需要，不设配额，不要求每段都成为 A 级；等级是投入分配与评审深度，不是评分，也不进入 v8 JSON、CLI 或运行时字段。
- 调整等级须记录原因：上调补齐 A 级验证，下调说明为何不影响核心表达。C 级仍须满足可读、事实与技术底线。

关键表达镜头的导演卡模板：

```markdown
### 导演卡：<场景 ID / 镜头 ID>
- 镜头等级：A（记忆镜头）/ B（推进镜头）/ C（功能镜头）
- Scene Goal：观众最终应理解什么？
- Visual Metaphor：用什么视觉机制表示？
- Initial State：最初看到什么，哪些关系可见？
- Visual Event：画面发生什么变化，因果是什么？
- Audience Expectation：揭示前会形成什么判断？不适用时说明原因。
- Hidden Information：暂时隐藏什么？若无，说明为何直接展示更合适。
- Reveal：何时、通过什么画面变化公开什么新信息？不适用时说明替代表达。
- Camera / Attention：观看关系如何变化；为什么此时移动/停留；注意力落在哪里？
- Final Recognition：揭示后应如何重新理解前面的画面？
- 完整时间窗口与节奏：建立 <起止> → 停顿 <起止> → 变化 <起止> → 延迟揭示 <起止> → 结果与消化 <起止>；每段写观众已知或期待、必须看见什么、注意力落点；另写关键变化与揭示的时机容差及失败现象。不适用段写原因。
```

时间结构用秒设计，按作品帧率换算为帧，并与 storyboard 既有 `startFrame` / `endFrame` 对齐；它落实事件时序，不新增 JSON 字段。B 级只写时间预算，C 级不写完整时间结构。

相机动作必须写出目的和认知作用。“镜头旋转 90 度”只描述动作；“前半段正面跟拍以隐藏道路高度，差距形成后转到侧面，让人物和完整坡度首次同框”才说明了它承担的导演信息。镜头可以不动；若认知顺序不需要变化，稳定直接展示就是有效设计。`Setup → Expectation → Change → Hidden Accumulation → Reveal → Recognition` 是需要延迟信息时可用的结构，不是每幕固定公式。

示例：行业隐喻可以是“道路代表行业发展环境”，事件是“同速前进时道路高度逐渐分化”。导演方案再规定：近距离正面跟拍先建立相近进展并遮住完整坡度；差距形成后镜头侧移并拉远，首次让全部道路与人物处于同一构图；停留让观众认识到“速度相近，所处环境不同，长期位置会分开”。若近景已暴露高度，或拉远只缩小画面而没有新增关系信息，导演揭示尚未成立。

### 从 DESIGN 映射到 storyboard

导演卡是设计依据，不是 storyboard JSON 字段。用 `scene.id`、`shots[].id` 和 `shots[].target` 建立可查对应，在导演卡中记录关键窗口及其对应的镜头 ID；再用既有 `startFrame` / `endFrame` 落实建立、公开新信息、停留等阶段。`shots[].camera` 只提供由场景代码消费的路径等实现数据，不承载完整导演意图；storyboard 或代码不得重新发明核心表达、隐藏信息或揭示顺序。细节见[分镜映射约定](storyboard-schema.md#导演设计映射)。

## 5. 可见变化

抽象观点必须变成「看得见的变化」，每个核心观点至少一种：

| 变化类型 | 画面问题 |
|---|---|
| 空间 | 位置、距离、方向、遮挡关系变了吗？ |
| 数量 | 数量、密度、堆积或消失变了吗？ |
| 速度 | 加速、减速、节奏或停顿变了吗？ |
| 高度 | 上升、下坠、坡度或层级变了吗？ |
| 距离 | 靠近、远离、拉远或穿越变了吗？ |
| 明暗 | 点亮、熄灭、显影或对比变了吗？ |
| 分叉 | 分裂、汇聚、连接、断裂或换道变了吗？ |

把「出现一个 X」改写成「X 如何变化」：

- 弱：屏幕出现五个行业名称和五个图标。
- 强：五条起点相同的轨道因产业周期不同，逐渐形成完全不同的坡度和高度。
- 弱：金币、股票、K 线。
- 强：两条一开始几乎重合的资产曲线，经过几十年被复利拉开巨大差距。

映射表写进 `DESIGN.md`：

| 抽象观点 | 可见变化类型 | 画面事件 | 镜头证据 | 不适用原因 |
|---|---|---|---|---|
|  |  |  |  |  |

文字对照、重组或图表关系如果能产生新意义，也可以作为可见变化的一种；但只显示名称、图标或说明文字不算。是否成立按完整段落判断，不按形式标签判断。

确定可见变化后，按下一节决定由代码、外部素材还是混合承担。

## 载体来源决策：代码、外部素材与混合

先定政策，再逐场选实例；两层不能互相替代。

### 整体政策（写进 `DESIGN.md`「表达载体」）

- **证据体制**：本片是档案证据型、解释型还是混合型。
- **必须真实**：哪些人、事、物、地点或数据原件必须由真实素材承担，不用图库替代。
- **只能解释**：哪些机制、尺度、关系、时间或反事实只能由代码解释。
- **边界标注**：真实与示意如何区分；片尾署名与必要示意标注只做一次，不逐幕堆注释。
- **许可与可得性**：素材来源、许可风险，以及拿不到素材时回退到改方案还是改表达。
- **母题与风格**：代码与素材服从同一视觉语言，不因来源不同变成两套片子。

### 候选层

三个叙事候选各自说明载体组合（档案／实拍／图库／代码／混合）与理由；可以在证据体制上不同，但都要说明哪些内容必须真实、哪些只能解释。比较时把素材可得性与许可风险列为主要风险。

### 逐场实例（写进逐场设计表「载体来源与理由」）

- 本段任务：证据、识别、机制、关系、情绪还是过渡。
- 具体来源：档案／实拍／图库／代码／混合；为什么选它。
- 所需变化在素材里是否看得见；看不见就换素材或改代码。
- 许可、来源、原生尺寸与时长是否满足。
- 与整体政策冲突时回退设计，不就地妥协。

### 判定顺序

1. 整体政策允许这种来源吗？
2. 本段任务需要观众相信「这是真的」吗？
3. 素材可得、可用、可许可吗？所需变化看得见吗？
4. 用代码会不会退化成通用信息图？
5. 记录理由与真实／示意边界。

### 硬边界

- 不得用图库素材冒充真实事件、人物或地点。
- 不得用代码动画伪造证据或实验结果。
- 许可未知不得进入成片；外部素材必须经 `assets import` 导入并留证。
- 档案不冒充 4K；原理动画明确标注示意。
- 混合时真实与示意的边界必须一眼可辨；不能用真实素材给虚构结论背书。

### 失败模式

- 只在整体决定：到场景才发现素材不可得、变化不可见或许可不行，反复回退。
- 只在逐场决定：全片证据体制不一致，观众不知道该信什么；母题与风格漂移；许可与署名失控。

运行时边界：外部素材只能通过 `useMediaAsset(id)` 取用，且必须已导入并留证；代码画面是 `scenes/` 下的 TSX。两者都不新增字段。来源、许可与混音规则见[文章媒体与音效](article-media-and-sound.md)。

## 6. 统一视觉语言与转场

全片共享字体、配色、材质/光影、尺度、留白、运动与静止规则；各场引用规则名，不逐场重复填表。

- 上一段的视觉元素如何自然变成下一段？优先形态变换：轨道分叉、曲线展开、网络生长、空间拉远、结构翻转。
- 黑屏、翻页、淡入淡出**不是绝对禁用**；作为默认过渡时须记录叙事理由，作为章节分隔、时间跳转或收束使用时允许。
- 运行时边界：幕间转场契约只有 `cut`、`fade`、`crossfade`（当前 `fade` 与 `crossfade` 的合成行为相同）。形态变换发生在代码场景内部的元素/镜头之间，**不新增转场类型或运行时字段**。

## 7. 镜头行为

设计镜头，不设计页面。每一幕或内部镜头至少写明一种镜头行为：

| 行为 | 适合表达 | 失败信号 |
|---|---|---|
| 向前推进 | 进入、逼近、投入 | 只是把页面放大 |
| 横向跟随 | 时间、队列、旅程 | 主体不动，背景平移 |
| 向上升高 | 尺度、层级、俯瞰 | 升上去没有新信息 |
| 向后拉远 | 揭示全貌、对比、收束 | 拉远后仍是同一张图 |
| 俯视 | 地图、结构、关系 | 俯视只是换机位 |
| 环绕 | 立体关系、对象观察 | 环绕却没有新侧面 |
| 穿越 | 进入内部、跨越边界 | 穿越后没有新空间 |
| 快速冲入 | 强调、冲击、转折 | 冲入后没有落点 |
| 微观到宏观 | 尺度揭示、认知反转 | 只是连续缩放 |

横屏空间分工见第 9 节。镜头行为写入逐场设计表的「镜头行为与母题状态」，不新增列。

运行时边界：`shots[].camera` 是分镜声明，最终由作品代码用 `CameraRig`、`useShot` 或自写相机消费；Python 渲染器不会自动运镜。字段定义见[分镜结构](storyboard-schema.md#可选字段)，实现见[代码场景契约](code-scene-runtime.md)。

## 8. 开场、中段与结尾

- **开场**：尽早给出可辨认的主体、有效动作或疑问，不用标题卡和空镜铺垫。前两秒要能回答「我在看什么、为什么继续看」。
- **中段**：默认参考分布是「1 个开场吸引点 + 2 个中段强度峰值 + 1 个结尾回报」，按内容可增减；可以多个峰值，也可以克制。
- **结尾**：可以是高潮、视觉揭示或安静收束，不强制传统高潮。优先设计一次**视觉揭示**：前面一直跟随局部，最后拉远、翻转或升维，显出原本看不懂的全貌。
- 强度来源：尺度突变、前后对比、多路径同时展开、数量骤增、镜头突然拉远、结构突然显露。
- 不设独立高潮或视觉揭示时，记录实际强度曲线、替代记忆点及原因，不硬加。

## 9. 横屏空间分工

16:9 横屏不要把元素都堆在中央：

- 左 → 右：时间、顺序、累积、推进。
- 上 → 下：路径、升降、层级、纵深。
- 远 → 近：尺度、优先级、接近、揭示。

横屏特别适合时间轴、多条轨道、数据曲线、平行世界、决策树、地图、网络和左右对比。竖屏、单主体、对称、地图/图表题材写转译方式；不要求每镜同时使用三套语法，也不用横向构图硬套竖屏。

## 10. 文字预算与关声可读

文字预算按**镜头或信息单元**计，不按 `scene` 机械限制（一个 `scene` 可以包含多个镜头和多段信息）：

- 每个镜头/信息单元围绕一个核心信息，原则上「一句主句 + 至多一句辅助」。
- 不计入：对象标签、轴/图例、数据标签、事实边界、方法口径、许可、示意标注。
- 旁白不按句数限制，仍按既有[信息单元预算](creative-production.md#信息单元预算)；旁白不得复述画面文字。
- 文字主导、信息图、档案与静止构图**不因形式被否决**；完整段落缺少信息、关系或体验推进时，才按版式重复规则处理。
- 「关掉声音后仍能大致看懂」是设计目标与诊断，用于发现只能靠旁白/文字支撑的空洞画面；**不是**有声作品拆声后完整成立的验收门禁，也不替代声音复核。声音承担必要线索时记录原因。

## 11. 反平庸默认清单

以下形式默认不采用；**这是模板提醒，不是形式否决清单**，不按形式标签否决。只有完整段落缺少信息、关系或体验推进时才登记必改；采用例外须记录理由与替代做法。

- 无信息推进的 PPT 卡片、仅作装饰的圆角矩形信息块。
- 图标 + 标题 + 说明的固定三件套。
- 缺少关系变化的五宫格、六宫格。
- 只复述文字步骤的流程图、无信息增量的普通柱状图。
- 大量 emoji、无关系变化的静止人物。
- 普通网页 dashboard 模板、逐页切换、每幕淡入淡出。
- 廉价霓虹、满屏粒子、无意义 HUD、大量装饰性科技线条。

自检：如果方案可以轻松做成 PPT，重新设计。但档案人物、真实数据图、真实流程、文字对照与信息图本身仍是合法载体。

|---|---|---|

| 2 | 母题可变化 | 第 3 项表达载体；[母题重复与版式重复](visual-review-rubric.md#母题重复与版式重复)；母题可信度风险样片 |
| 3 | 可见变化 | [逐场设计表](scene-design-and-acceptance.md#逐场设计表)；构图与空间关系检查 |
| 4 | 视觉语言/转场 | [表达统一](creative-production.md#核心体验与表达设计)；四张基准 |
| 5 | 镜头行为 | 镜头叙事与整片强度；动态与节奏复核 |
| 6 | 开场/中段/结尾 | 前两秒检查；全片强弱；第一次导演审查 |
| 7 | 视觉揭示 | 第 4 项揭示与记忆；导演审查结尾回报 |
| 8 | 横屏空间 | 画幅/构图/空间关系；手机尺寸复核 |
| 9 | 文字预算/关声 | 信息单元预算；观众可见文案；静音诊断 |
| 10 | 反平庸 | 反目标/冷审；幻灯片式检查；唯一问题表 |

任何一项为否，回到对应步骤优化；不适用时写明原因，不新增评分、用户确认或 CLI 门禁。

## 14. 例外留痕与常见误用

- 不适用时写原因与替代做法，不写「本片风格化」了事。
- 不把「高级」「震撼」「电影感」当设计；必须落到可观察的画面事件与镜头行为。
- 不靠装饰动效补救信息推进问题；推近、扫光、粒子不能代替新认识。
- 不把设计文档当成片证据；成片没有对应可见事件时，按设计未兑现处理。
- 不把禁止项当形式否决；形式标签本身不产生必改项。
- 不把七段式塞进独立评审包；评审者仍先盲看，后对照中性条件。
- 不要求每部作品都有母题、反转、高潮或视觉揭示；例外必须留痕。

## 15. 判断演练

| 情形 | 应得出的结论 |
|---|---|
| 漂亮卡片逐页替换，但没有信息、关系或体验推进 | 失败；按版式重复必改 |
| 文字对照、重组或图表关系产生新意义 | 通过；不因文字主导或信息图形式否决 |
| 单次连续旅程，没有重复母题 | 通过；记录替代组织方式 |
| 没有传统高潮，但强度曲线有理由 | 通过；记录替代记忆点，不强制添加高潮 |
| 竖屏没有使用左→右时间语法 | 记录转译方式，不判失败 |
| 声音承担关键线索，关声后信息不完整 | 记录原因，按完整声画验收；不因静音诊断自动判必改 |
| 数据图、档案、静止人物有真实信息变化 | 通过；形式本身不构成失败 |
| 设计文档写了母题，成片每幕仍是同构卡片 | 设计未兑现；按实际缺陷或证据不足处理 |

这些是规则推导，不是实际样片或观众验证；作品仍须提供真实版本与证据。

## 16. 紧凑示例：人生五选择

以 `examples/five-life-choices` 说明七段式的写法：

- **核心表达**：人生差距由少数选择在时间里放大，但路仍可调整。
- **核心视觉母题**：把人生设计成一条持续向前、不断分叉并可换道的时间轴。
- **整体视觉风格**：深黑底、米白/灰文字、蓝白线描、持续移动的 2.5D 镜头。
- **分镜设计**：城市=轨道第一次分叉；行业=五条跑道形成不同坡度；伴侣=两条轨迹合流或分屏；投资=轨道变增长曲线；学习=轨道旁生长知识网络；结尾=拉远成决策树。
- **视觉高潮**：行业段拉远后的高度差；结尾决策树。
- **结尾视觉揭示**：几十条可能路径中只有一条最亮，观众这时才看见整棵树。
- **禁止项**：五张同构卡片、PPT、霓虹紫、emoji、网页 dashboard、收益承诺。

示例只作写法示范，不替代作品自身方案；具体取值以该作品当前 `DESIGN.md` 与成片为准。
