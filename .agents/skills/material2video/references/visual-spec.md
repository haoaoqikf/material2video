# 竖屏视觉规范

面向抖音类竖屏信息可视化短视频的排版、层级与动效约定。目标是「中文排版清晰、无溢出、
跨机器可复现」，并让画面具备稳定的高级感；配色与气质的具体取舍仍由每支视频自己决定。

> **版本范围：** 本文的画布、安全区、排版与风格建议可继续参考；下文部分动效机制、
> 转场、`visual.kicker`、`scene.motions` 与旧版运行时目录表描述的是 v3 历史契约，
> 不适用于当前 v4。当前以一个持续视觉世界承载多个叙事阶段；v4 字段以
> [分镜契约](storyboard-schema.md)为准，创作流程以[文章到分镜](article-to-storyboard.md)为准。
> 不要将本文的旧字段或旧场景切换规则用于 v4 分镜。

规范分两层：

- **硬约束**：画布、安全区、字号下限、帧驱动，违反会直接导致裁切、模糊或闪烁；
- **配方**：层级、动效、风格方向，是可以直接照抄的数值，也是「高级感」的来源。

启用导演契约的作品还可声明景别、构图重心、景深和镜头运动；运动必须由帧号推导，
不得使用 CSS `animation` / `transition`。兼容的 `dissolve` 只表达场景进入；`inherit`、
`transform`、`decompose`、`recompose`、`break` 建立显式节点连续性，并在风格包规定的窗口内
同时渲染上一幕源节点和当前幕目标节点。映射必须引用稳定 id，异类变形必须登记在原语注册表，
不能根据相似外观自动猜测。

## 画布

| 项目 | 值 | 说明 |
| --- | --- | --- |
| 逻辑尺寸 | 1080 × 1920 | 9:16 竖屏，与分镜的 `width`/`height` 保持一致 |
| 帧率 | 30fps | 与分镜的 `fps` 保持一致 |
| 色彩 | sRGB | 不做 HDR |

画面按逻辑尺寸写死布局，**不要**用 `vw`/`vh`/百分比做响应式适配。
composition 以分镜声明的尺寸原样挂载，不存在预览缩放这一层。

## 安全区

平台 UI 会遮挡画面上下缘，正文必须留在安全区内。令牌在 `web/src/styles/tokens.css`
里定义，并提供 `.m2v-safe` 容器：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `--m2v-safe-top` | `220px` | 顶部留白（状态栏、账号信息） |
| `--m2v-safe-bottom` | `320px` | 底部留白（文案、进度条、按钮） |
| `--m2v-safe-x` | `96px` | 左右留白 |

可用区高度为 `1920 - 220 - 320 = 1380px`。排版超长时优先精简文案，
而不是压缩安全区。

## 字号下限

以 1080px 宽为基准，保证在手机小屏上仍可读：

| 用途 | 建议区间 |
| --- | --- |
| 开场主标题 | 110–150px |
| 金句正文 | 76–96px |
| 结论全文 | 88–110px |
| 节点 / 卡片标签 | 56–72px |
| 辅助说明、注释 | 30–38px |

低于 30px 的文字在竖屏上基本不可读，应改为口播或删除。

**下限由代码兜住，不靠自觉。** 启用设计语言预设时，声明了
`data-m2v-fit="<档位>"` 的文本元素由排版引擎按**实测可用宽度**在字号阶上取档，
到 36px 正文下限即停，不会再往下缩；缩到下限仍放不下时，引擎把
`data-m2v-fit-fits="false"` 写到元素上，观感闸门 K7 据此报「需要拆场景」。
也就是说「文案太长」不会再以「字变小了」的形式悄悄发生。
详见[发布会级设计语言](keynote-design-system.md)。

当前字号阶最低档为 caption 28px；它是所有显式声明 `role` 的树文字所允许的下限。
36px 是正文建议下限，不代表 caption/label 等辅助角色也须大于 36px。全片实测不能容纳时由 K7 阻断。
文字取档最多允许四行；测量使用已加载字体下的 DOM 实际行盒。四行与最低字号仍无法容纳时写入 `data-m2v-fit-fits="false"`，由 K7 阻断。

## 排版层级

字号只解决「看得清」，层级才决定「看起来贵」。同一画面里按下表分工，
不要靠加粗和变色堆重点：

| 角色 | 字号 | 字重 | 颜色令牌 | 说明 |
| --- | --- | --- | --- | --- |
| 主命题 | 110–150px | 700–800 | `--m2v-text-1` | 一幕只出现一句 |
| 正文 / 金句 | 76–98px | 500–600 | `--m2v-text-1` | 长句拆场景，不缩小字号 |
| 小节标题 | 44–56px | 500 | `--m2v-text-2` | 只做引导，不抢焦 |
| 标签 / 序号 | 28–34px | 400 | `--m2v-text-3` 或强调色 | 配 `letter-spacing: 0.22em` |
| 行动提示 | 34–40px | 500 | `--m2v-text-2` | 配左侧强调竖线 |

规则：

- **一个画面一个视觉焦点**：强调色只在焦点元素上出现；
- 标题用负字距（`-0.02em` 左右），标签用正字距（`0.2em` 以上），
  正文保持 0，字距是区分「标题感」和「正文感」最廉价的手段；
- 每个场景最多 3 行正文，每行不超过 14 个汉字，用分镜里的换行符手动断行，
  不要让浏览器自动折行决定重点词的位置；
- 关键短语用强调色 + 光晕标出，**不要**整句加粗或变色；
- 字号取自**模块化字号阶**：启用预设后，不在阶上的字号会绕过
  [K3 闸门](keynote-design-system.md)（同帧字号种类），层级也就无法被机检。
  十档取值与配对的行高、字距见[发布会级设计语言](keynote-design-system.md)。
  组件内部的文字同样受这条约束——样式表（`web/src/styles/primitives.css`、
  `web/src/styles/keynote.css`）里的字号一律写成
  `var(--m2v-*, 原值)`：令牌生效时落到阶上，令牌缺失时落回原值，
  两种情况都不会出现「页面上是阶上字号、组件里却是 30px」的漏网。

## 图形标注

「以形表意」的画面（天平、冰山、落差尺这类比喻）需要几个短标签才能读懂，
但它们不该写死在网页里，也不该塞进正文。分镜用 `annotations` 提供这些标签，
每个场景类型有一套约定键；网页按 `data.annotations["键"]` 取用，
取不到时留空而不是回退到默认文案：

| `type` | 约定键 | 用途 |
| --- | --- | --- |
| `title` | `leftPan`, `rightPan` | 天平两侧托盘上的名字 |
| `quote` | `assumption`, `fact`, `dropLabel`, `noDropLabel` | 落差尺：两栏标题与两把尺的标签 |
| `list` | `tip`, `mass`, `surface` | 冰山：水面之上、水面之下、水面线 |
| `diagram` | `gauge` | 反馈循环的进度表标签 |
| `timeline` | `axis`, `before`, `after` | 阶梯：纵轴名、翻转前后两种读法 |
| `conclusion` | `leftNode`, `rightNode` | 双向选择的两个端点 |
| `chart` | `unit`, `note` | 数值单位（拼在数值后面）与来源/补充说明 |

键的取值是**每篇文章自己的选择**，上表只是当前网页实现的键名。
新增画面时先在网页里定键名，再把同一组键写进分镜与本节表格。

## 视觉层级与景深

深色画面最容易显得「扁平、廉价」，按下面三层叠起来即可获得景深：

1. **背景层**（常驻，放在 `[data-m2v-stage]` 内、场景容器之外）：
   光晕 + 网格 + 细点阵，直接用 `theme.css` 的
   `.m2v-bg-glow` / `.m2v-bg-grid` / `.m2v-bg-grain`；
2. **表面层**（卡片、节点）：`--m2v-bg-1` 打底 + `--m2v-surface` 顶亮底暗渐变
   + 1px `--m2v-hairline` 边框 + `--m2v-inset-highlight` 内高光
   + `--m2v-shadow-2` 双层投影（近处小阴影定形，远处大阴影造景深）；
3. **焦点层**：只让一个元素同时拿到强调色边框、内发光与外发光
   （`rgba(var(--m2v-accent-rgb), a)` 拼接光晕，按帧改变 `a`）。

不要用 `filter: blur()` 做大面积模糊：它既拖慢逐帧截图，也无法被
「同帧一致」的验收覆盖。需要光晕就用 `radial-gradient` 或 `box-shadow`。

## 动效

新版默认动画按 `establish → change → result → settle` 编排，最后至少保留 12 帧稳定阅读（`STABLE_READING_FRAMES = 12`，见 `web/src/runtime/motionPlan.ts`）。节点组可按顺序、反向、中心扩散或显式路径传播错峰；基础布局、beat 状态、节点动效、跨幕连续性与镜头轨迹使用独立通道并按该顺序组合。

- 只使用**由帧号推导**的 `transform`、`opacity`、颜色变化；
- 禁止 CSS `animation` / `transition`，原因见 [渲染契约](render-contract.md)；
  渲染入口会在开渲前静态扫描并提示这类写法；
- 单次入场动效建议 12–30 帧（30fps 下 0.4–1.0 秒）；
- 逐项呈现的间隔建议 4–12 帧，过快会看不清，过慢会拖节奏
  （注册表 `motionRuntime.stagger`：默认 4 帧，下限 2、上限 12）；
- 画面不要长时间完全静止：把后续动效绑到更晚的 beat 上，让节奏铺满幕内时间。
  配音会把场景拉长，后段静止在成片里像卡住。

**分镜只声明受控配方，不写曲线。** 幕的 `motions[]` 每条恰好给 `target`（单节点）或
`targets`（节点组）之一，恰好给 `phase`（`establish` / `change` / `result`）或 `beatId`
之一，外加具名 `recipe`，可选 `durationFrames`；`targets` 必须声明 `stagger`，
`stagger` 只能用于 `targets`。

配方只有五个：`reveal`、`fade`、`rise`、`count`、`draw`。错峰只有四种：`forward`、
`reverse`、`center`、`path`——`path` 必须给出覆盖全部目标的有效路径，否则校验失败。
每个原语支持哪些配方由注册表 `primitive.motions` 决定，声明不支持的组合会在校验阶段报错。

时间来自节拍，不来自秒。运行时的纯函数在 `web/src/runtime/`：

| 模块 | 提供什么 |
| --- | --- |
| `motionPlan.ts` | `defaultPhases()` 把幕切成四个阶段；`sceneMotionPlan()` 把声明落到帧区间；`staggerOrder()` 算错峰次序；`motionProgress()` 给 0..1 进度；`visualMix()` / `channelStyle()` 把通道合成 `style` |
| `beats.ts` | 分段口播与语义 beat 的时间轴（`BeatTimeline`） |
| `camera.ts` / `continuity.ts` / `transition.ts` / `geometry.ts` | 镜头轨迹、跨幕连续性、转场与几何求解 |
| `timeline.ts` | 幕边界与总帧数（`totalFrames()`） |

`sceneMotionPlan()` 会把每条动效的结束帧夹在 `settle` 起点之前，因此「最后一帧还在动」
在计划层就不可能发生。所有配方共用同一条三次缓出曲线（`1 - (1 - p)^3`），
不存在按配方各写一条曲线的入口。

**曲线不由分镜选。** 分镜里没有「缓动名」，也没有弹簧参数：曲线由运行时统一给出，
换曲线就是改 `motionPlan.ts`，而不是散落在各幕的声明里。这样「整支片子的手感」
只有一处可调，新写的幕也不会慢慢长成另一种手感。

### 配方与节奏只有一处真源

上面那些是运行时的**机制**，「移动多远、错峰多密、镜头推多快」是**做法**。
它存在的唯一理由是——

> 这些数字决定整支片子的手感。散在各幕声明里就没人能整体调，
> 新写的幕也会慢慢长成另一种手感。

所以做法只写在 `web/src/runtime/motionPlan.ts` 与注册表
`web/src/registry/registry.json` 的 `motionRuntime` 段（阶段顺序、稳定阅读帧数 12、
错峰间隔上下限 2–12、镜头强度上下限 0–1），分镜只按名字引用：`recipe`（五个）、
`phase`（三个阶段）、`stagger.kind`（四种）。

**节奏不是分镜字段。** 没有 `figure.motion` 这类「节奏档」，
快慢由 `durationFrames`、错峰间隔与镜头强度表达；组件不持有任何节奏状态。

**改配方可以（那正是它存在的意义），但改完不能变成弹跳**：实测第一帧位移不得超过
全程的 25%、走到 90% 至少要 6 帧、过冲不超过 10%、末尾必须正好停在终点——
这四条由动效量测（M0–M4）在任意作品上判。

### 动效时长参考

下面的帧数是 30fps 下的实测推荐值，可直接照抄，再按成片观感微调：

| 场景 | 做法 |
| --- | --- |
| 卡片 / 节点入场 | `rise`，位移 56–64px，20–24 帧，绑在所在 beat 上 |
| 文字聚焦入场 | `reveal` 或 `fade`，位移 24px + 透明度 0→1，22 帧 |
| 标签横线 / 强调竖线 | `draw` 或 `reveal`，20 帧 |
| 关键短语点亮 | 颜色 + 光晕 0→峰值，26–30 帧，在句子读完后触发 |
| 关系图连线 | `draw`，正向 14 帧、回环 60 帧 |
| 对比双栏 | 两个目标各 24–26 帧，用 `stagger` 让起点相差 45–60 帧 |
| 结论逐字 | `reveal`，每字间隔 2 帧，起点在第 8 帧 |
| 数值滚动 | `count`，只在步数足够时执行（见 [发布会级设计语言](keynote-design-system.md) 的瞬跳约束） |

`stagger.intervalFrames` 的范围是 2–12，因此「起点相差 45–60 帧」要靠多个目标编组
累积出来，而不是把单个间隔值放大超过上限。

**改完配方要跑轨迹机检。** 量测实现是 `src/m2v/motion.py`，两处共用一份：
`tests/test_motion_review.py`（参考实现上的严格判定）与 `文章类型视觉体检`
（验收命令，对任意作品都跑，结论进 `report.json` 的 `motion` 段、终端 M0–M4 一栏）。
它按帧走完每一幕，逐个量到每一个「从不透明走向不透明」的元素（基准示例上共 90 个），
判据：

| 判据 | 阈值 | 适用 |
| --- | --- | --- |
| 首帧不透明度 | ≤ 25% | 有位移的入场（实测 9 个；旧实现第一帧就到 0.438） |
| 到 0.9 的帧数 | ≥ 6 帧 | 有位移的入场（实测最少 7 帧） |
| 落地距幕尾 | ≥ 12 帧 | 全部入场（实测最小 25 帧） |
| 落地前不透明度回退 | 不许 | 全部入场 |

速度判据**只适用于有位移的入场**：90 个里另外 81 个是纯淡入（逐字揭示的单字符
2 帧、小标注与箭头 2–5 帧），那是刻意的做法，一刀切会把它们误判成弹跳。
刻意停在部分不透明度的装饰（光晕、火花、引号、注脚）不进扫描——这里判的是
内容入场的快慢与落地，不是光晕什么时候亮。
位移的形状判据（含过冲与「末尾必须正好为 0」）由测试里的单元素用例精确钉住。
验收里的动效结论**只提示、不拦人**（不改退出码）；测试里还有一个反例：
把入场整体加速 8 倍后重扫，闸门必须报错——否则说明它量不到。

### 语义动作与中层原语

上面这一整套回答的是「元素怎么出现」。声明了分段口播的幕还要回答第二个问题：
**「这一步口播在解释什么」**。后者由受控语义动作表达（唯一真源是
`web/src/registry/registry.json` 的 `actions`）：

| 动作 | 画面变化 | 改变状态或关系 |
| --- | --- | --- |
| `establish` | 建立对象，让它出现 | 否（中性） |
| `connect` | 建立两个对象之间的关系 | 是 |
| `transfer` | 把量或注意力从一个对象移到另一个 | 是 |
| `accumulate` | 让量级累积上升 | 是 |
| `deplete` | 让量级消耗下降 | 是 |
| `transform` | 把对象变成另一种形态 | 是 |
| `compare` | 并置两个对象凸显差异 | 是 |
| `highlight` | 强调已有对象 | 否（中性） |
| `loop` | 回到起点形成闭环 | 是 |
| `break` | 打断已有关系 | 是 |
| `restore` | 把被打破的关系复位 | 是 |

`establish` 与 `highlight` 是**中性**动作：它们只让对象出现或更醒目，不改变状态与关系。
一幕全是中性动作时，观众看到的是依次出现的卡片而不是一次推理——动画论证的 A3
闸门判的就是这件事。

五个中层原语消费同一份 beat 状态（当前 beat、局部进度、已完成集合），
各自只改**已登记**的视觉状态：

| 原语 | 方向 / 状态 | 随 beat 变化的部分 | 帧间冻结的部分 |
| --- | --- | --- | --- |
| `flow` | `ltr`/`rtl`/`ttb`/`btt` | 哪个阶段是当前阶段（`data-m2v-stage-state` 由 `pending` → `active` → `done`） | 阶段数量、内容、基础几何 |
| `cycle` | `cw`/`ccw` | 轨道高亮弧的长度与当前阶段 | 同上；箭头方向固定 |
| `timeline` | `ltr`/`rtl`/`ttb`/`btt` | 进度轴填充（`scaleX`/`scaleY`，不改宽高） | 同上 |
| `gauge` | — | 指针角度与读数（`data-m2v-shown`） | 满值刻度（`data-m2v-value`）、刻度数量 |
| `pictogram` | — | 已填充单位数（`data-m2v-filled`） | 单位总数（`data-m2v-units`）与图标 |

**冻结布局是硬要求**：节点数量、内容与基础几何在帧间不变，变化只发生在视觉状态上。
用 `transform` 表达进度而不是改宽高，正是为了不让每帧的重排抖动进成片。
量级原语按当前 beat 的局部进度求值——进行中的 `accumulate`/`transfer`/`restore`
用进度本身，`deplete`/`break` 用 `1 - progress`，其余动作与无 beat 的情况按
「已完成/未开始」取端点值。判据与量测锚点见
[渲染契约](render-contract.md)的「语义节拍运行时」，动作支持清单见
[视觉原语目录](primitive-catalog.md)。

## 可复用风格方向

三套风格都建立在同一套令牌上，只改令牌与构图，不必换运行时：

| 方向 | 背景与表面 | 强调色 | 排版 | 动效节奏 |
| --- | --- | --- | --- | --- |
| 深色科技（示例采用） | 近黑底 + 光晕 + 网格 + 细点阵，卡片带内高光 | 单一青色 `#35e0c8` | 大字重标题 + 负字距，标签正字距 | 20–30 帧入场，微过冲 |
| 编辑杂志 | 浅底 `#f6f7f9`，白色卡片，投影收敛 | 一点朱红或墨蓝 | 标题更大、正文更松，允许两栏 | 16–22 帧，曲线更克制 |
| 极简高级 | 单一深色或米色底，几乎无网格 | 用文字色而非彩色强调 | 大面积留白，一次只放一句话 | 24–36 帧，长缓动 |

## 场景节奏

- 场景时长由**口播文案**所需时间决定，不要先定时长再塞文案；
- 30fps 下常用参考：开场命题 4–6 秒，金句 6–9 秒，对比 8–10 秒，
  关系图 10–14 秒，结论 8–11 秒；
- 单场景不要短于 24 帧（0.8 秒），否则入场动效会被压缩到看不清；
  `统一入口校验` 会对过短的场景给出警告；
- 总时长按当前标准为 **35–45 秒**（见分镜契约）；超过 90 秒建议拆成多条。

## 画面的组成

画面不再是一张作品自己的 HTML：composition（`web/src/compositions/M2VComposition.tsx`）
按分镜把每一幕挂进舞台，样式与令牌集中在 `web/src/styles/`，动效原语在
`web/src/runtime/`。分层如下：

| 层 | 位置 | 负责 |
| --- | --- | --- |
| 设计令牌与主题 | `web/src/styles/tokens.css`、`theme.css` | 颜色 / 表面 / 字号 / 间距 / 安全区变量 |
| 设计语言预设 | `web/src/styles/keynote.css` | `visual.preset: "keynote"` 的字体栈、字号阶、主题块、工具类 |
| 场景树原语样式 | `web/src/styles/scene-tree.css` | 布局 / 内容 / 图形原语的样式（形状变体、图表、状态） |
| 版面与字幕 | `web/src/styles/declarative.css`、`primitives.css` | 场景版面、字幕条、四族动效基元 |
| 原语实现 | `web/src/primitives/SceneTree.tsx` | 布局求解、内容引用、动效可视状态、字号取档 |

场景树承担「一幕画面怎么画」，composition 只负责舞台、背景与逐幕挂载；
可用原语与组合方式见 [视觉原语目录](primitive-catalog.md)。

背景层是常驻元素，挂在舞台内、场景元素之外，场景容器抬到背景之上：

```tsx
<div data-m2v-stage>
  <div className="m2v-bg-glow stage-bg" aria-hidden="true" />
  <div className="m2v-bg-grid stage-bg" aria-hidden="true" />
  <div className="m2v-bg-grain stage-bg" aria-hidden="true" />
  {/* 场景由组件按帧渲染，z-index 高于背景层 */}
</div>
```

本篇素材放在 `videos/<type>/<slug>/assets/`，由 `image` 原语的 `sourceRef` 引用；
不允许再写作品专属的画面代码，需要新表达时按原语注册表流程新增通用原语。

## 设计语言预设（可选）

分镜根级的 `visual.preset` 决定是否启用一层「发布会级」设计语言。v4 中该字段必填，
目前唯一取值是 `"keynote"`；未声明或声明了未登记的取值都由校验器报错并指出
`visual.preset` 字段路径。

**缺省时行为逐帧不变。** composition 始终引入 `web/src/styles/keynote.css`，
但只有分镜声明了预设才会在根元素写 `data-m2v-preset="keynote"`（`M2VComposition`
的 `useLayoutEffect`）：预设的全部规则（字体栈、主题块、字号阶、工具类）
都带 `[data-m2v-preset="keynote"]` 作用域，一条也不会生效；字号取档
（SceneTree 对声明了字号档的文字原语按实测宽度向下取档）只在预设存在时执行。
画面、字体与版式因此与未启用预设的取值完全一致——这不是口头承诺，
`tests/test_react_design_tokens.py` 在浏览器里量计算值守住作用域。

启用后多出来的约束：模块化字号阶（正文下限 36px，组件内部字号通过
`--m2v-ink-*` 别名一并收进阶上）、8pt 间距阶、两套主题
（`keynote-dark` / `keynote-light`）、对比度预算（正文 7:1、大字与图形 4.5:1）、
随仓库分发的 webfont，以及观感闸门 K1–K10；预设另外把 `--m2v-safe-top` 从
220px 提到 240px，并提供 `--m2v-safe-bottom-with-subtitles: 520px`。
v4 分镜的 `visual` 只接受 `theme` 与 `preset`，**不存在 `visual.layout`**：版面由
`world.sceneTree` 的原语承担。下面这套 `data-layout` 兜底只服务旧版 composition
（`M2VComposition.tsx`），预设不推翻它，只补齐原本缺的 `left` 一档。
完整的启用方式、令牌表与闸门阈值见[发布会级设计语言](keynote-design-system.md)。

### 幕角标 `visual.kicker`

每幕的 `visual` 可以写一个可选字段 `kicker`：画面左上角的**定位词**，与右上角的
`04 / 08` 幕号合成一条角标。

```json
{ "id": "attention", "type": "list", "visual": { "layout": "center", "kicker": "注意力" } }
```

规则（由校验器守住，错误路径为 `scenes[i].visual.kicker`）：

- 一个词，**最多 8 个字**；要说得更多请放进 `title` 或 `subtitle`
- 非空、单行
- 只允许写在**幕**的 `visual` 上，顶层 `visual`（主题、预设）不接受

**没写 `kicker` 时角标留空**，不回落到 `type`。这一条是有来历的：角标原先直接渲染
`scene.type`，于是画面上出现的是分镜的内部类型标识符——`TITLE`、`LIST`、
`TIMELINE`、`NUMBER`、`CONCLUSION`。那是 schema 字段名，不是给读者看的字：
既没有信息量（读者不需要知道"这是一条时间线"），也和整屏中文格格不入。
一个内部标识符永远不该出现在画面上，所以兜底是"不显示"（`M2VComposition`
里留一个空 span），而不是"显示类型名"。

角标只在启用预设时挂载，因此它**不影响未声明预设的既有作品**。

## 字体

画面用**随仓库分发**的两套可变字体，不依赖渲染机器的系统字体，也不走 CDN：

| 字体 | 家族名 | 文件 | 用途 |
| --- | --- | --- | --- |
| Inter Variable | `"M2V Inter"` | `web/src/assets/fonts/Inter-Variable.ttf` | 拉丁与数字（图表数值列的对齐依赖它） |
| Noto Sans SC Variable | `"M2V Sans"` | `web/src/assets/fonts/NotoSansSC-Variable.ttf` | 中文 |

两者均为 SIL OFL 1.1，许可证原文（`OFL-Inter.txt` / `OFL-NotoSansSC.txt`）随字体
一同分发。**不走 CDN**：渲染是逐帧确定性导出，CDN 断网或限流时会静默回退到
系统字体，成片照样出得来，只是换了一副字。

- 唯一真源是 `web/src/assets/fonts.json` + `web/src/assets/fonts/`；
- `web/src/fonts.ts` 在首帧前用 CSS Font Loading API 注册（`font-display: block`，
  避免回退字体先渲染的那一帧被拍进成片），并声明 `font-weight: 100 900`
  （可变字体必须写完整区间，否则粗细档会被合成）；
- 字体栈只写在 `:root[data-m2v-preset="keynote"]` 作用域内：预设一启用即生效，
  未启用预设的画面继续用系统栈；`@font-face` 的 URL 注册是全局的，作用域由
  `tests/test_react_design_tokens.py` 在浏览器里量出来；
- 构建前 `web/scripts/sync-fonts.mjs` 把字体同步进 `public/fonts/`（gitignore 的
  生成物），源文件缺失时**构建直接失败**。

体积与许可见 `web/src/assets/fonts/README.md`；字体层的取舍理由见
[发布会级设计语言](keynote-design-system.md)。

## 排版自查

导出前至少检查一次：

- [ ] 所有正文在 `.m2v-safe` 内，没有被上下缘裁切；
- [ ] 图形内的文字没有穿出它所属的容器（节点圆、托盘、卡片）——
      这一条是 **K8 硬判定**，失败会让体检错误数非零、退出码非零；
- [ ] 组件的间距、内边距、线宽、字重、字距、圆角都引用令牌（设计宪法 C17），
      没有裸数字——新写的样式最容易漏；
- [ ] 同一帧最多一个元素处于焦点态（`data-m2v-state="focus"`），
      强调色只出现在它身上；
- [ ] 最长的一行没有贴边或与其它元素重叠；
- [ ] 正文没有超过 3 行，长句已拆场景或手动换行；
- [ ] 同一画面只有一个视觉焦点，强调色只出现在它身上；
- [ ] 背景、表面、焦点三层都在，画面没有「贴在纯色底上」的扁平感；
- [ ] 卡片 / 节点有 1px 边框、内高光与双层投影，而不是纯色块；
- [ ] 入场动效都绑定在声明过的 `phase` 或 `beatId` 上，没有凭空多出的曲线；
- [ ] 末帧的画面已经落定（动效结束帧被夹在 `settle` 起点之前），
      而不是靠常驻微动掩盖「还在动」；
- [ ] 每帧重复渲染结果一致（可对同一帧截图两次比对）；
- [ ] 声明了分段口播的幕：每条 beat 的 `meaning` 说明了它解释什么，动作里至少一个
      真正改变状态或关系（全是 `establish`/`highlight` 会被 A3 拦下）；
- [ ] 最后一条 beat 完成后至少还有 12 帧稳定阅读时间（A5），所有动效的结束帧在幕尾前
      12 帧结束（A8）——`sceneMotionPlan()` 已把结束帧夹在 `settle` 起点之前。

## 逐句字幕

有声模式共享运行时自动添加 `.m2v-with-subtitles` 与字幕层；1080 × 1920 下默认 48px、
行高 1.3、白字深色描边，左右沿用 96px 安全边距，底部沿用 320px 安全边距。
每条字幕最多 28 个字符，用真实字词边界拆分；最多两行，采用均衡换行。
正文 `.m2v-safe` 的底部额外留出 180px，禁止覆盖字幕区域。其他画布尺寸需相应调整样式。
空白或停顿时间不显示字幕；不缩小字号塞入超长字幕，不按字数猜测发音时间。
字幕随逐帧截图烧录，预览与导出排版相同，SRT 不携带字体样式。
