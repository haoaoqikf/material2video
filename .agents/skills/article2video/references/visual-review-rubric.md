# 视觉评审量表

`review.py` 把「该看的」摆出来，这份量表负责「怎么打分」。
量表存在的意义是让评审可复现：同一支片子，不同的人（或不同的视觉模型）
看完应当得到接近的结论，而不是各自凭感觉。

前面的机检（见[设计宪法](design-constitution.md)）只保证**这不是一段废片**；
真正决定有没有人看完的是下面这六项。

## 怎么用

```bash
uv run python .agents/skills/article2video/scripts/review.py \
    --page videos/<slug>/index.html \
    --storyboard videos/<slug>/storyboard.json \
    --media videos/<slug>/outputs/media/media.json
```

产出三样东西：

| 文件 | 用途 |
| --- | --- |
| `contact-sheet.png` | 全片联系表：先独立看一遍，不要先读报告 |
| `frames/*.png` | 每幕三帧原图，用于逐幕细看 |
| `report.json` | 机检结果：契约探针、帧量测、静态宪法，以及视觉叙事 V 系列与动画论证 A 系列 |

**评审顺序很重要**：先看联系表形成整体印象，再读 `report.json`。
反过来会让人只看机检过得去的地方，忽略机检根本管不到的问题。

`report.json` 的 `visualNarrative` 给出 V 系列：V1–V4 是机检硬判定（与
`validate.py --strict` 同口径，失败会并入错误数与退出码），V5 是**文字主导候选清单**
（列出候选幕与判定证据，只呈现不改退出码），V6 是你现在要写的结论。
逐幕细看时把 V4/V5 的证据当作提示，而不是当作结论——脚本只报告结构，
「图形有没有真的承担论证」由你判断。

`report.json` 的 `animationReview` 给出 A 系列：A1–A5、A7、A8 是机检硬判定
（节拍覆盖、含义声明、状态或关系变化、字幕同步、结尾停留、单一焦点、稳定结束，
失败同样并入错误数与退出码），A6 是你现在要写的**装饰动画**结论。
A 系列只约束声明了 `narrationSegments` 的幕；字符串口播由 v3 校验拒绝，
无声预览下 A4（字幕同步）也记为「跳过」——跳过不等于通过。
A 系列与 V 系列分开计数、不合成总分：V 问「有没有论证型图形」，
A 问「这些图形动起来有没有在解释论点」。

## 六项评分

每项 0–5 分。60 分制总分 **≥ 40 才值得发布**，任何一项为 0 则重做。

### 1. 三秒内是否看懂（权重最高）

只看第一帧和前三秒。它有没有在观众滑走之前把命题说清楚？

- 5：第一帧就能读出「这条片子要讲什么」，且好奇下一句；
- 3：需要看到第 2–3 幕才明白主题；
- 0：前三秒是标题卡或空镜，不知道要讲什么。

### 2. 图形是否承担了论证

画面是「配图」还是「论据」？

- 5：图形本身完成了推理（例如天平从倾斜到归零，直接说出了「代价不对等」）；
- 3：图形好看但只是装饰，换成别的图也不影响理解；
- 0：画面与文案各说各的。

这一项的分数就是 `review.md` 里的 **V6 图形论证**评分，**≥ 4 才允许发布**。
打分时逐幕问一句：「把标题和正文都遮住，这一帧还剩什么？」剩下的是关系或变化
（柱高差、箭头方向、圆周顺序、天平倾角），这一幕就是图形论证；剩下的是
整齐的卡片、图标和留白，它就是排版。V4 会报出「声明为 comparison 却只有文字与
包装节点」这类结构矛盾，V5 会列出文字主导候选——这两处证据要逐条裁决，
不能整体打包成「已确认」。

### 3. 一目了然

单帧静看 2 秒，能不能说出这一帧在讲什么？

- 5：焦点唯一，视线自然落在该落的地方；
- 3：需要找一下才知道看哪；
- 0：元素互相打架，读不出主次。

### 4. 动效是否服务于理解

逐个动效问「它在解释什么」。

- 5：每个动作都在推进理解，删掉任何一个都会损失信息；
- 3：有一两处纯装饰，但整体不碍事；
- 0：大量无来由的旋转、缩放、抖动。

这一项里「有没有解释论点」的部分已经机检过了：A1–A5、A7、A8 会报出节拍没覆盖口播、
含义只是复述、全是中性动作、字幕与画面边界不一致、结尾没有阅读时间、同帧多个焦点、
最后一帧还在动这些具体问题。**剩下的是机检给不出结论的那一半**：不服务于任何 beat
的装饰配方（`report.json` 的 `animationReview.a6.candidates`）是否恰当。逐条问
「删掉它会不会损失信息」，然后按下面的格式裁决。**这一项的分数就是 A6 的分数**
（`review.md` 里写 `| 动效服务 | N |`，或在 `## A6` 小节里写 `评分：N/5`），
**≥ 4 才允许发布**。

### 5. 文字是否可读

按手机屏幕的真实尺寸判断，不要放大看。

- 5：所有文字一眼可读，断行位置符合语义；
- 3：个别行偏小或断行别扭；
- 0：需要暂停才能读。

### 6. 节奏

整支片子的快慢是否有变化，还是从头到尾一个速度？

- 5：有铺垫、有转折、有收尾，关键那一幕明显慢下来或重下来；
- 3：整体平稳，没有明显的高点；
- 0：机械均速，像幻灯片。

## 必须重做的红线

以下任何一条命中，不看总分，直接重做：

- 前三秒读不出主题；
- 某一幕整帧空白或几乎空白（把 `report.json` 的 `ink` 当作证据）；
- 出现成片的控制条、调试信息或其他不该入镜的元素；
- 观众看完说不出这一幕的论点。

## 评审结论怎么写

结论要写进 `report.json` 同级的 `review.md`，格式固定：

```markdown
# 评审：<slug>（<日期>）

总分：xx/60

| 项 | 分 | 依据 |
| --- | --- | --- |
| 三秒看懂 | 4 | 第一帧标题+天平已经把「代价不对等」说清楚 |
| 图形论证 | 5 | 天平从倾斜到归零，图形本身就是论据 |
| 一目了然 | 4 | 焦点稳定；第 4 幕节点略小 |
| 动效服务 | 4 | 入场动效都在引导视线；第 2 幕的卡片错峰入场服务于节奏，保留 |
| 文字可读 | 5 | — |
| 节奏 | 3 | 03–04 两幕节奏接近，缺少起伏 |

## 候选裁决

- scene-04：通过——圆周顺序表达循环，遮住文字后仍能读出「回到原点」
- scene-07：不通过——三张卡片加图标，遮住文字后只剩排版，改声明为 typography

## A6 候选裁决

- scene-02:card-1：通过——错峰入场把视线引到量级上，删掉后节奏塌成一段
- scene-05:badge：不通过——徽标缩放不解释任何东西，已删除该配方

## 必改
1. 第 4 幕的循环节点缩小后仍显拥挤，减少到 3 个节点。

## 可选
- 第 5 幕翻转牌可以再早 6 帧出现。
```

`## 候选裁决` 逐条对应 `report.json` 里 V5 列出的文字主导候选，结论取
「通过」「不通过」「候选未裁决」之一。**V5 有候选而未裁决，或 V6 评分低于 4，
发布清单里的 `publishable` 就是否**——「图形论证」这一项不能靠总分补。
没写 `## 候选裁决` 小节时，只要 V5 列出了候选，状态就是「候选未裁决」。
用 `评分：4/5` 单独写在 V6 小节里也可以，`review.py` 会识别这种写法；
但评分与裁决是两件事：分数够高而候选未裁决，仍然不能发布。

`## A6 候选裁决` 同理逐条对应 `animationReview.a6.candidates`（形如
`scene-02:card-1`，即「哪一幕的哪个节点的配方」），结论格式相同。
A6 的分数取自第 4 项「动效服务」那一行，也可以单独写在 A6 小节里
（`评分：N/5`）。**A6 有候选而未裁决，或 A6 评分低于 4，`publishable` 同样是否**；
A6 缺失时状态是「待评审」而不是通过——人工结论缺失既不会伪造成脚本错误，
也不会被当成默认合格。没有候选配方时，只要分数够高，A6 直接通过。

「必改」必须具体到**哪一幕、改什么、改成什么**，不能写「整体再高级一点」——
那种意见无法执行，也无法验证有没有改到位。
