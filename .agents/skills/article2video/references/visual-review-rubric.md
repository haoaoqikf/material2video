# 视觉评审量表

`文章类型视觉体检` 把「该看的」摆出来，这份量表负责「怎么打分」。
量表存在的意义是让评审可复现：同一支片子，不同的人（或不同的视觉模型）
看完应当得到接近的结论，而不是各自凭感觉。

本量表面向 v4 单场景动态叙事。`stages[]` 是同一视觉世界中的推理阶段；文中“场景/幕”若出现在旧版示例或报告字段中，应按当前制作对象映射到阶段，不能据此推断画面发生了场景切换。

前面的机检（见[设计宪法](design-constitution.md)）只保证**这不是一段废片**；
真正决定有没有人看完的是下面这六项。

## 怎么用

```bash
uv run a2v review \
    --storyboard videos/<slug>/storyboard.json \
    --media videos/<slug>/outputs/media/media.json
```

产出三样东西：

| 文件 | 用途 |
| --- | --- |
| `contact-sheet.png` | 全片联系表（按分镜声明的时间轴抽帧）：先独立看一遍，不要先读报告 |
| `frames/*.png` | 每幕三帧原图，用于逐幕细看 |
| `report.json` | 机检结果：契约探针、帧量测、静态宪法，以及视觉叙事 V 系列与动画论证 A 系列 |

体检带 `--media` 时画面按配音派生的时长解释帧号，抽到的其实是另一批帧，
因此那份联系表写成同级的 `contact-sheet-media.png`；`contact-sheet.png` 始终只按
分镜声明的时间轴生成，它是 `production.json` 登记的静态材料，带不带配音都不变。

**评审顺序很重要**：先看联系表形成整体印象，再读 `report.json`。
反过来会让人只看机检过得去的地方，忽略机检根本管不到的问题。

`report.json` 的 `visualNarrative` 给出 V 系列：V1–V4 是机检硬判定（与
`a2v validate --project <目录>` 同口径，失败会并入错误数与退出码），V5 是**文字主导候选清单**
（列出候选幕与判定证据，只呈现不改退出码），V6 是你现在要写的结论。
逐阶段细看时把 V4/V5 的证据当作提示，而不是当作结论——脚本只报告结构，
「图形有没有真的承担论证」由你判断。

`report.json` 的 `animationReview` 给出 A 系列：A1–A5、A7、A8 是机检硬判定
（节拍覆盖、含义声明、状态或关系变化、字幕同步、结尾停留、单一焦点、稳定结束，
失败同样并入错误数与退出码），A6 是你现在要写的**装饰动画**结论。
A 系列只约束声明了 `narrationSegments` 的阶段；字符串口播由 v4 校验拒绝，
无声预览下 A4（字幕同步）也记为「跳过」——跳过不等于通过。

article2video Skill 的 AI 助手负责自动填写导演计划和 `production.json` 评审。先读文章、分镜、`motion-design.md` 与 `report.json`，再亲自打开联系表、关键幕样片和全片有声评审版；必须查看实际画面，不能从分镜、脚本报告或文件存在推断画面通过。静态维度为主体尺度、连续构图重复、信息密度、视觉母题和高潮分量；动态维度为动作解释力、口播同步、节奏变化和结果停留。每维选 `pass`、`fail` 或 `pending`，已判定项的依据须定位到场景与帧号/时间。缺材料、打不开或证据不足时留为 `pending`。每条已完成评审均写 `assessment`：`reviewer: "ai"`、`model`、`session` 和材料类别摘要；静态引用 `keyframes`，关键幕动态引用 `samples`，全片动态引用 `rehearsal`。材料摘要由 `production.py` 登记，必须逐字引用对应 `materials.*.sha256`。脚本验证来源结构、材料摘要和输入指纹，但不替 AI 判断审美。

来源字段形状示例；占位摘要须从当前记录的对应 `materials.*.sha256` 复制：

```json
{
  "assessment": {
    "reviewer": "ai",
    "model": "Codex current-session model",
    "session": "Codex session 2026-09-29",
    "materials": {
      "keyframes": "<materials.keyframes.sha256>"
    }
  }
}
```

AI 同时在 `review.md` 填写 V6 图形论证与 A6 装饰动画评分及候选裁决；这些字段仍是 `文章类型视觉体检` 的审美门禁输入，须按实际联系表与视频证据逐条作结论。AI 评审可满足发布门禁，但结论和来源会保存在作品本地记录中供复核。旧记录仍可读，无来源的历史通过不能用于新渲染。

任一失败项都要在作品根的 `production.json` 增加返工项，填写 `id`、`sceneIds`（全片问题使用空数组）、`dimension`、`problem`、`direction`、`returnStage`、`severity` 与 `status`。必改项只能在修改版本复查通过并填写 `recheck.evidence` 和与记录当前值一致的 `recheck.fingerprints` 后设为 `resolved`。修改分镜或共享渲染资产会使所有评审过期；静态联系表按分镜声明时间轴生成，不读媒体（`production.py keyframes` 与不带 `--media` 的体检写同一份 `contact-sheet.png`，带 `--media` 的体检另写 `contact-sheet-media.png`），配音变化只使动态评审过期。重新生成材料不会自动通过。

关键幕样片供导演验证局部表达，全片评审版供验证整体节奏。两者与正式 composition 同源；评审版可降低分辨率和编码质量，不改变帧序、动作、口播或字幕同步。正式渲染要求关键幕、全片静态和有声动态评审均通过，且无未解决必改项。
A 系列与 V 系列分开计数、不合成总分：V 问「有没有论证型图形」，
A 问「这些图形动起来有没有在解释论点」。

## 六项评分

每项 0–5 分。60 分制总分 **≥ 40 才值得发布**，任何一项为 0 则重做。另有不可由总分抵消的单项门槛：**节奏必须至少 4/5**；缺少节奏评分、低于 4 分，或没有能定位到有声预演时间/阶段的依据，正式渲染均不通过。

### 1. 三秒内是否看懂（权重最高）

只看第一帧和前三秒。它有没有在观众滑走之前把命题说清楚？

- 5：第一帧就能读出「这条片子要讲什么」，且好奇下一句；
- 3：需要看到第 2–3 幕才明白主题；
- 0：前三秒是标题卡或空镜，不知道要讲什么。

### 2. 图形是否承担了论证

画面是「配图」还是「论据」？

- 5：图形本身完成了推理（例如天平从倾斜到归零，直接说出了「代价不对等」）；
- 3：图形好看但只是装饰，换成别的图也不影响理解；
- 0：画面与文案各说各的。

这一项的分数就是 `review.md` 里的 **V6 图形论证**评分，**≥ 4 才允许发布**。
打分时逐幕问一句：「把标题和正文都遮住，这一帧还剩什么？」剩下的是关系或变化
（柱高差、箭头方向、圆周顺序、天平倾角），这一幕就是图形论证；剩下的是
整齐的卡片、图标和留白，它就是排版。V4 会报出「声明为 comparison 却只有文字与
包装节点」这类结构矛盾，V5 会列出文字主导候选——这两处证据要逐条裁决，
不能整体打包成「已确认」。

### 3. 一目了然

单帧静看 2 秒，能不能说出这一帧在讲什么？

- 5：焦点唯一，视线自然落在该落的地方；
- 3：需要找一下才知道看哪；
- 0：元素互相打架，读不出主次。

### 4. 动效是否服务于理解

逐个动效问「它在解释什么」。

- 5：每个动作都在推进理解，删掉任何一个都会损失信息；
- 3：有一两处纯装饰，但整体不碍事；
- 0：大量无来由的旋转、缩放、抖动。

这一项里「有没有解释论点」的部分已经机检过了：A1–A5、A7、A8 会报出节拍没覆盖口播、
含义只是复述、全是中性动作、字幕与画面边界不一致、结尾没有阅读时间、同帧多个焦点、
最后一帧还在动这些具体问题。**剩下的是机检给不出结论的那一半**：不服务于任何 beat
的装饰配方（`report.json` 的 `animationReview.a6.candidates`）是否恰当。逐条问
「删掉它会不会损失信息」，然后按下面的格式裁决。**这一项的分数就是 A6 的分数**
（`review.md` 里写 `| 动效服务 | N |`，或在 `## A6` 小节里写 `评分：N/5`），
**≥ 4 才允许发布**。

### 5. 文字是否可读

按手机屏幕的真实尺寸判断，不要放大看。

- 5：所有文字一眼可读，断行位置符合语义；
- 3：个别行偏小或断行别扭；
- 0：需要暂停才能读。

### 6. 节奏

整支片子的快慢是否有变化，还是从头到尾一个速度？在全片有声预演中检查段落速度、力度与停留是否贴合口播推进；用时间码或明确阶段记录证据。相同视觉世界或相同构图不自动构成节奏问题，但每阶段应有与推理对应的可见状态推进。

- 5：有铺垫、有转折、有收尾，关键那一幕明显慢下来或重下来，状态变化和口播力度互相支撑；
- 4：有可辨认的快慢/力度变化和收束，证据显示关键段落与普通段落存在有意差异；
- 3：整体平稳，没有明显的高点；未达到发布门槛，必须返工；
- 0：机械均速，像幻灯片。

评分至少 4/5 是正式渲染硬门槛，不能被高总分补足。`review.md` 的“节奏”行必须写 1–5 分及具体证据，例如 `00:12 核心动作加速；00:34 高潮停留后收束`。若只写“整体流畅”或分镜计划，没有实际有声预演中的时间/阶段依据，按待评审处理。

评审关键幕动态粗剪时先静音播放，确认对象状态、关系、焦点或镜头变化确实推进了论证，并在动作后留下稳定结果。之后再带声音看全片，检查这些变化与语义 beat、口播力度和段落节奏是否同步。若静音播放只看到字幕或标签更新，应记录具体阶段和必改方向。布局相同但对象状态有意义地推进时可以保留；不得仅因布局一致要求更换场景或构图。

## 必须重做的红线

以下任何一条命中，不看总分，直接重做：

- 前三秒读不出主题；
- 某一幕整帧空白或几乎空白（把 `report.json` 的 `ink` 当作证据）；
- 出现成片的控制条、调试信息或其他不该入镜的元素；
- 观众看完说不出这一幕的论点；
- 全片节奏低于 4/5、缺少可定位的有声预演证据，或评审未完成。

## 评审结论怎么写

结论要写进 `report.json` 同级的 `review.md`，格式固定：

```markdown
# 评审：<slug>（<日期>）

总分：xx/60

| 项 | 分 | 依据 |
| --- | --- | --- |
| 三秒看懂 | 4 | 第一帧标题+天平已经把「代价不对等」说清楚 |
| 图形论证 | 5 | 天平从倾斜到归零，图形本身就是论据 |
| 一目了然 | 4 | 焦点稳定；第 4 幕节点略小 |
| 动效服务 | 4 | 入场动效都在引导视线；第 2 幕的卡片错峰入场服务于节奏，保留 |
| 文字可读 | 5 | — |
| 节奏 | 4 | 00:12 核心动作加速；00:34 高潮停留后收束 |

## 候选裁决

- scene-04：通过——圆周顺序表达循环，遮住文字后仍能读出「回到原点」
- scene-07：不通过——三张卡片加图标，遮住文字后只剩排版，改声明为 typography

## A6 候选裁决

- scene-02:card-1：通过——错峰入场把视线引到量级上，删掉后节奏塌成一段
- scene-05:badge：不通过——徽标缩放不解释任何东西，已删除该配方

## 必改
1. 第 4 幕的循环节点缩小后仍显拥挤，减少到 3 个节点。

## 可选
- 第 5 幕翻转牌可以再早 6 帧出现。
```

`## 候选裁决` 逐条对应 `report.json` 里 V5 列出的文字主导候选，结论取
「通过」「不通过」「候选未裁决」之一。**V5 有候选而未裁决，或 V6 评分低于 4，
发布清单里的 `publishable` 就是否**——「图形论证」这一项不能靠总分补。
没写 `## 候选裁决` 小节时，只要 V5 列出了候选，状态就是「候选未裁决」。
用 `评分：4/5` 单独写在 V6 小节里也可以，`文章类型视觉体检` 会识别这种写法；
但评分与裁决是两件事：分数够高而候选未裁决，仍然不能发布。

`## A6 候选裁决` 同理逐条对应 `animationReview.a6.candidates`（形如
`scene-02:card-1`，即「哪一幕的哪个节点的配方」），结论格式相同。
A6 的分数取自第 4 项「动效服务」那一行，也可以单独写在 A6 小节里
（`评分：N/5`）。**A6 有候选而未裁决，或 A6 评分低于 4，`publishable` 同样是否**；
A6 缺失时状态是「待评审」而不是通过——人工结论缺失既不会伪造成脚本错误，
也不会被当成默认合格。没有候选配方时，只要分数够高，A6 直接通过。

## 定制动画动态评审

分镜中只要有一幕声明 `renderer.kind: "code"`，`report.json` 就会新增
`bespokeAnimationReview`。这套评审独立于 V/A 自动量测：必须播放输出目录里的真实样片，
按全片阶段推进，为每个阶段在同一模块中的五个维度评分并写出可核对的时间或帧依据。五项**各自都至少 4/5**，不取平均，
才通过。静帧或联系表不能证明动作含义和节奏。

体检首次生成 `review.md` 时，会按分镜阶段列表生成表格。把状态从「待评审」改成「启用」，
填写每幕各项 1–5 分及播放证据：

```markdown
## 定制动画动态评审

状态：启用

| 场景 | 焦点清晰度 | 动作解释力 | 节奏变化 | 转场连贯性 | 结果可读性 | 依据 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| profit | 4 | 5 | 4 | 4 | 4 | 00:12 利润沿线回到本金；00:18 下一轮由扩大后的本金开始 |
```

缺少该章节、启用标记、场景行、任一评分或依据时，状态为「待评审」；任一分低于 4，
状态为「不通过」。这两种状态都会让代码场景作品的渲染入口拒绝正式渲染。所有必需行达标后，
状态为「通过」。没有代码场景的作品为「不适用」，保持原评审规则。

五项的判断口径：

- **焦点清晰度**：播放中视线是否能迅速找到唯一主对象，有无被次动作抢走；
- **动作解释力**：对象是否通过位置、状态或关系变化展示了推理步骤；
- **节奏变化**：动作是否有铺垫、执行、反馈和停顿，不同段落是否机械重复；
- **转场连贯性**：焦点变化是否可读，跨幕连续或有意切换是否成立；
- **结果可读性**：主动作结束后是否保留稳定时间让人读清结果。

静音播放核心图形幕，确认动作与论点的对应关系；再带声音播放，检查动作时点是否贴合实际 beat。
写具体观察时间，例如「00:12 利润回流前路径已建立」，不要只写「动画很顺」。

「必改」必须具体到**哪一幕、改什么、改成什么**，不能写「整体再高级一点」——
那种意见无法执行，也无法验证有没有改到位。

## 口播内容门禁

在实际全片有声观看后填写 `reviews.full.content` 五项：opening_question、explanation_chain、spoken_naturalness、closing_response、boundary_accuracy。每项记录 score（整数 1–5）、status 与阶段/时间依据；至少 4 为 pass，否则 fail，未观看为 pending。整体状态由各项决定；assessment 引用当前 rehearsal 摘要。与静态/动态评审共享指纹、材料更新和返工规则。旧记录缺内容评审仍可读，但正式渲染阻断。
