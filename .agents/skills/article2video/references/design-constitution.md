# 设计宪法

这份文件是「什么算做对了」的判据。它服务于一个具体目标：让 AI 产出的画面
稳定在**可发布**的水准，而不是每次重新争论审美。

当前生产契约为 v4：全片只有一个 world，`stages[]` 是其中的叙事阶段。下文旧示例中的“幕/场景”在适用时指 stage；历史量测说明不代表 v4 已迁移该项，当前是否可机检以 [视觉评审量表](visual-review-rubric.md) 和 `review.py` 实际报告为准。

每条规则有编号（C1…）、理由、以及**能不能机检**。能机检的部分由
`scripts/review.py`（帧量测、契约探针、K/V/A 系列）与 `tests/` 下的守卫执行；
不能机检的部分由 [视觉评审量表](visual-review-rubric.md)
交给人和视觉模型判断。**不要把不能机检的东西写成机检**——假自动判定比没有判定更危险。

## 一、结构与层级

**C1 三层结构**（结构保证：由共享 composition 输出）
画面由「背景 / 表面 / 焦点」三层构成：共享 composition 输出一个 `[data-a2v-stage]`、
一层常驻背景（`stage-bg`）与持续的 `[data-a2v-world]`。v4 的同一 world 跨阶段保持身份，
阶段改变的是叙事上下文和可观察状态。缺背景层时画面会平，
缺舞台时层级无处安放。
*理由*：高级感的第一来源是层级，不是装饰。
*为什么不再单独机检*：这三层现在由 `web/src/compositions/A2VComposition.tsx`
统一输出，作品没有「写漏」的入口；再按契约页的 HTML 查一遍只会得到恒真的结论。

**C2 每个阶段推进一个推理点**（人工）
每个 `stage` 只推进一件事，整片 world 服务于同一核心观点。两个论点挤在同一阶段，观众都记不住。
*判定*：看该阶段能不能用一句话说清新增了什么理解。

**C3 全片有唯一视觉根**（结构保证：由共享 composition 输出）
全片 world 的 `[data-a2v-figure]` 由共享 composition 持续挂载；作品既不需要、
也无法自行切换画面根。world 未声明有效 `sceneTree` 或代码模块会在校验阶段直接失败。
*理由*：缺画面的场景在成片里就是一块空白，而预览时未必看得出来。
*为什么不再单独机检*：这条失败已经前移到 v4 校验期，不再靠事后查 DOM 才发现。

## 二、动效

**C4 曲线纪律**（机检：结构）
曲线只有一条：三次缓出 `1 - (1 - p)^3`，写在 `web/src/runtime/motionPlan.ts`。
分镜里没有缓动名，也没有弹簧参数——受控配方（`reveal` / `fade` / `rise` /
`count` / `draw`）由运行时映射到这条曲线。
*理由*：曲线混用会让整支片子的手感不一致，而这种不一致很难指认、只能感觉到。

**C5 帧驱动**（机检：静态 + 运行时）
画面只由帧号推导。禁止 CSS `animation`/`transition`、`Date.now`、
`performance.now`、`Math.random`。
*理由*：逐帧求值与浏览器时钟无法对齐，成片会出现随机闪烁。

**C6 节奏统一**（机检：分镜字段）
全片快慢只通过全局 `beatId` 或阶段 `phase` 绑定表达；媒体派生 beat 边界驱动画面与字幕，
代码模块也只能消费共享时间上下文。分镜与组件均不维护第二套时间轴。
*理由*：节奏是整幕的属性，散落在组件里就无法整体调整。

**C7 动画服务于理解**（人工）
每个动效都要能回答「它在解释什么」。装饰性位移、无来由的旋转、
为了动而动的缩放一律删掉。
*判定*：能不能用一句话说出这个动作在讲什么；说不出就删。
*A 系列的关系*：C7 是审美裁决，A1–A5、A7、A8 是它的可机检部分——
节拍是否覆盖口播、含义是否声明、动作是否真的改变了状态或关系、
字幕与画面是否共用边界、结尾是否留够阅读时间、焦点是否唯一、画面是否稳定收束。
剩下的「这条装饰动效是否恰当」交给 A6 由人裁决。

**C19 语义节拍驱动画面**（机检：分镜 + 解析时间轴）
声明分段口播的幕必须让画面变化跟着 beat 走：字幕、配音与画面共用同一批边界，
动作取自受控词汇表，`meaning` 说明这条节拍解释了什么。
*理由*：入场配方只管「怎么出现」，说不清「正在解释哪一步推理」；没有共享时间轴时，
字幕说到第三句而画面还在演第一步，评审也拿不出判断依据。

## 三、视觉

**C8 不用大面积模糊**（机检：静态）
禁止 `filter: blur()` 与 `backdrop-filter`。柔光用 `radial-gradient`
或分层阴影实现。
*理由*：大面积模糊既拖慢逐帧截图（每帧几百毫秒），又容易糊成一片。

**C9 文字可读**（机检：帧量测 + 人工）
正文与背景的对比要够；正文字号不小于规范下限；一行不超过约定字数。
*理由*：竖屏在手机上只有几秒的注意力，读不清就等于没有。

**C10 安全区**（机检：帧量测）
顶部 220px、底部 320px（有字幕时再加 180px）不放重要内容。
*理由*：平台的界面会盖住这两块。

**C11 画面不空**（机检：帧量测）
每一幕都要有实质内容，整帧墨迹覆盖率不得低到接近空白。
*理由*：组件没挂上、文案为空、画面全黑，都不会报错，只会安静地出一段废片。

**C16 图形看得见**（机检：静态）
图形颜色按**用途**分五类（数据描边 / 图形内文本 / 边界描边 / 装饰描边 / 面填充），
各有判据与判定基座：前两类对画布 ≥ 4.5:1，**边界描边**（一个物体唯一可见的边界）
对抬升面 ≥ 3:1，装饰描边 ≥ 1.5:1，面填充不设数值下限（形状由描边界定）。
活样式层（`web/src/styles/` 下的 `keynote.css`、`primitives.css`、`scene-tree.css`）
的 `fill` / `stroke` / `background` 里不得出现字面色值，一律走令牌。
纯分隔线（`--a2v-hairline`）**刻意**保持耳语并豁免于 WCAG 1.4.11——
它管的是「理解内容所必需的图形对象」，把每条分隔线都提到 3:1 会让画面变重、层次变平。
*理由*：图形没人量的时候可以安静地消失——留白闸门甚至**奖励**它，
因为图形越淡、背景像素越多。而写死的颜色不跟主题走，换到深色预设就与底色同色。
实测踩过：深色 `--fig-line-soft` 1.63:1、浅色主描边 3.31:1、
`.load-hollow` 与 `.drop-track` 的浅色页取值压在近黑底上，空壳只剩虚线、差量条只剩虚线框；
天平吊绳被按取值归成装饰后，横梁像浮在空中。
C9「文字可读」管不到这里：它量的是文字，管不了 SVG 的线。

**C17 组件走令牌，不走裸数字**（机检：静态）
组件样式表里的**间距、内边距、线宽、字重、字距、圆角、字号**必须引用令牌，
并以 `var(--令牌, 原值)` 形式书写——令牌缺失时落回原值，画面逐字节不变。
判据是「这个数值改变时，用到它的所有组件是不是应该一起变」：
是则必须是令牌；否则视为图稿坐标（`d`、`cx`、`cy`、`width` 这类），
可以保留为组件自身的常量，不强行令牌化。
*理由*：规范写着「组件的间距取自 8pt 阶」，实测 13 处 `gap` 与 4 处 `padding`
一个都没走阶，30 / 46 / 18 / 22 / 26 / 34 全不在阶上；`stroke-width` 散着
2 / 3 / 4 / 5 / 6 五种线宽。只查令牌**有定义**的检查不查组件**有没有用**，
「看起来成体系」和「真的成体系」之间就没有检查。
*当前边界*：描边、字重、字距、圆角、间距、内边距与 `margin-top` 已经走令牌
（活样式层里字面值已清零）；颜色一侧由
`tests/test_figure_contrast.py` 的分类表守住（新增令牌必须先进表），
间距与几何一侧靠组件单测与代码评审。

**C18 状态语汇唯一，一个概念一个名字**（机检：静态 + 运行时探针）
表达「当前焦点」的元素必须挂基元类 + `data-a2v-state="focus"`，
SHALL NOT 再用临场类名（`is-accent` / `is-focus`）另写一套；
同一帧最多一个元素处于 `focus`。连续量（`--a2v-focus-mix`、`--vs-heat`）
与结构性类名（`is-left` / `is-right` / `is-fact` 这类）**不进**四态——
四态表达不了连续量，硬塞会让状态失去语义。
*理由*：焦点原先有三套并行写法（`is-accent`、逐帧切换的 `is-focus`、组件自算的
色值），「主次分明」因此只能靠每个画面临场发挥；三个组件同一帧都亮着时，
观感闸门量得到强调色，却量不出「谁是主」。
*守卫*：`web/src` 的组件单测断言状态写法与基元类的对应关系，
`review.py` 的运行时量测在同一帧的多处强调里量「谁是主」；
同一帧最多一个 `focus` 由动效量测与组件测试共同守住。

## 四、内容

**C12 文案单一真源**（机检：静态）
文案只写在 `storyboard.json`。网页源码里不得再出现分镜里的长句。
*理由*：抄一份就会在改文案时两边不一致，而错误只会在成片里被发现。

**C13 原语从目录里选**（机检：分镜校验）
先查 [视觉原语目录](primitive-catalog.md)，用受控原语组合表达意图。
原语表达不了的基础能力按注册表契约新增通用原语，并沉淀回目录。
*理由*：每次从零画一遍既慢又难保持一致；目录是这张体系里真正会增值的资产。

**C14 标注必须真的画出来**（机检：契约探针）
分镜声明的每个标注，都要能在整幕的 DOM 里找到。
*理由*：这是最隐蔽的一类缺陷——组件挂上了、画面也出来了，
只是图上没有一个字。它不报错，只能靠读 DOM 或逐帧看图发现。

## 五、设计语言层

**C15 设计语言层必须有作用域**（机检：静态）
`@font-face` 是全局注册的（浏览器没有作用域化的字体定义），`:root` 也是全局的。
因此设计语言层里任何一条漏掉 `[data-a2v-preset="keynote"]` 的令牌规则都会**静默**
改变预设作用域之外的画面：字体栈泄漏会让整支片子换一副字，主题块写成
`:root, :root[data-a2v-preset="keynote"]…` 会让浅色页面被整片刷黑——而
`validate.py`、`render.py` 与成片验收全部照常通过。
*守卫*：`tests/test_react_design_tokens.py` 在浏览器里量计算值——预设与主题
的属性挂在根元素上，作用域之外的画面若吃到预设令牌会直接失败；
裸 `:root` 只放默认主题的兜底令牌、主题块不得与裸 `:root` 并列，
由 `keynote.css` 的结构约定与组件测试守住。
*理由*：不报错的破坏最贵——它不拦渲染，只改成品。

## 六、观感闸门（K1–K10）

这一组只在作品声明了 `visual.preset` 时运行（v4 起 `visual.preset` 必填，
因此实际总是运行）。判定方法、
阈值与设计取舍见[发布会级设计语言](keynote-design-system.md)；这里只记
「能不能机检」以及什么算**实测**、什么只是**跳过**。K 系列与 C 系列**分开计数、
不合成总分**：C 系列答「这是不是废片」，K 系列答「这像不像发布会级别的画面」。

| 闸门 | 判定方法 | 强度 |
| --- | --- | --- |
| K1 留白预算 | 背景像素占比（与角落像素灰度差 ≤ 16 的像素算背景）；主体幕 `title` / `quote` / `conclusion` ≥ 60%、其余幕 ≥ 40% 通过，低于门槛但在 0.18 以内判提醒、再低判失败；留白达标但「亮到能读的墨迹」< 0.004 时降为提醒 | 机检：帧量测 |
| K2 强调色占比 | 强调色**族**的像素占比：色度（max−min）≥ 50 且色相在强调色 ±30° 内（不是与某一个色值的逐通道色盒——色盒看不见设计系统登记的另外三个成员）；区间 [0.002, 0.15]，> 0.25 判失败、0.15–0.25 提醒、偏低只提醒（不对称判定） | 机检：帧量测 |
| K3 同帧字号种类 | ≥ 44px 的字号去重计数；≤ 4 通过、5 提醒、≥ 6 失败 | 机检：帧量测 |
| K4 对齐基线 | 字号 ≥ 44px 的文本块归到几条对齐线：与安全区中心相差 ≤ 6px 算「居中」一条，其余按左边缘 12px 容差聚类，**两条线上的块中心之和与画面中心的两倍相差 ≤ 12px 时并成一条（镜像对称栏）**；≤ 2 通过、3 提醒、≥ 4 失败 | 机检：帧量测；正文级文本块不足两个时**跳过并写明原因** |
| K5 正文对比度 | 文本样张前景对背景的 WCAG 比值取最差一条；半透明前景先合成到背景，背景透明时回退 `--a2v-bg-0`；字号 < 44px 用 7:1、≥ 44px 用 4.5:1，低于下限但在 85% 以内判提醒、再低判失败 | 机检：帧量测；渐变裁切文字（`background-clip: text`）与完全透明文字跳过，一条都算不出时整条跳过 |

正文可读性约束同样适用于图表类别/轴标签与「示意」标记：柱图类别排在柱体外并使用正文墨色，浅色主题下的小字号强调标签使用 `--a2v-accent-ink`，不能直接用只有 4.55:1 的浅底强调色。
| K6 卡片与描边纪律 | 卡片在圆角 / 描边 / 投影 / 内描边中具备几项；≥ 3 项通过、1 张不达标提醒、≥ 2 张失败 | 机检：元素几何；采集范围是**整幕里所有被画出来的 HTML 表面**（不是图形挂载点的直接子元素，最外层优先避免嵌套徽标重复计）；**SVG 圆角图形与 HTML 图表的数据标记都不是卡片**；整幕没有可识别的 HTML 卡片表面时跳过并写明原因 |
| K7 文字溢出（**硬判定**） | 文本块墨迹四边对 `.a2v-safe` 的越界量（容差 8px，容纳入场位移与亚像素舍入），或排版引擎报 `fits: false`（缩到 36px 正文下限仍放不下）；同一个文本块的多个文本节点按块归并，取各方向最大越界量 | 机检：帧量测 + 元素几何；越界即 `fail`，**并入体检错误数与退出码**，并报出文本块、方向与像素值 |
| K8 容器内溢出（**硬判定**） | 组件用 `data-a2v-inside` 声明文字装在哪个形状里，探针按 `getBBox()` 在 SVG 用户坐标下取文字盒与容器盒：圆形按「矩形内接于圆」判四周，矩形按四边判（容差 2px——入场变换对文字与容器一致，相对位置不变）；未声明容器的幕跳过并写明原因 | 机检：元素几何；越界即 `fail`，**并入体检错误数与退出码**。K7 的参照只有安全区，而图形内按几何位置绘制的文字既不受安全区判定、也不受容器判定——这条补的正是那一整格 |
| K9 图形描边一致性（提醒） | 同帧所有带描边的 SVG 元素的计算线宽去重；取值须落在描边阶（1 / 2 / 3 / 4 / 6）上且档数 ≤ 3 | 机检：元素几何；只提示、不改退出码——线宽不一致是观感问题，不是画面损坏 |
| K10 主次分明（提醒） | 同幕同帧里可见文本按「面积 × 字号」排序，第一名 / 第二名 ≥ 2.0 通过、≥ 1.5 提醒、再低失败；可见文本块不足两个时跳过并写明原因 | 机检：元素几何；只提示、不改退出码。阈值由基线实测得出（能测的六幕最小 3.12），不是拍的 |

**K7 与 K8 是 K 系列里的硬判定。** 其余 K 闸门只提示：留白少了、强调色淡了都是主观判断，
最终该由人定。文字被裁掉、压出安全区或穿出所属形状不是主观判断——它意味着观众会看到
半行字，与 C 系列「不是废片」同类。因此它们的失败会调用 `cli._apply_hard_gates`
并入错误列表，「体检完成」的错误数变为非零、退出码变为非零。
只打印一行失败而不影响结论，等于把硬判定降级成建议。

**跳过不等于通过。** 每条跳过都会写明原因（「正文级文本块不足两个」「这一幕没有
卡片表面」「取不到主题的强调色令牌」「取不到安全区几何」等）并单独计入「跳过」数量，
终端汇总也只列非通过项。把跳过混进通过，是这套闸门最容易犯的错。

## 七、视觉叙事闸门（V1–V6）

C 系列答「这是不是废片」，K 系列答「这像不像发布会级别的画面」，V 系列答
**「各阶段的图形变化有没有共同论证这个观点，还是整支片子靠文字撑着」**。三组分开计数、不合成总分。
判定口径与 `validate.py --strict` 完全一致（同一份 `a2v/visual_narrative.py` 分析，
`RULE_VERSION` 版本化），所以「严格校验通过」与「V1–V4 通过」不会互相矛盾。

| 闸门 | 判定方法 | 强度 |
| --- | --- | --- |
| V1 文字幕预算 | 文字幕阶段数量对 `ceil(阶段数 × 30%)`；报告分子、分母、上限与 stage id | 机检：分镜结构；失败**并入错误数与退出码** |
| V2 连续文字幕 | 相邻两个阶段是否均为文字幕；报告每一对 | 同上 |
| V3 非文字模式覆盖 | 报告声明的非文字视觉模式去重计数；v4 不设最低数量，单一隐喻可以贯穿全片 | 同上；只报告，不阻断 |
| V4 声明与结构一致性 | 声明非 `typography` 模式的阶段是否拿得出结构证据 | 同上，逐阶段列出声明模式与证据 |
| V5 文字主导候选 | 列出文字主导阶段及其判定证据，供逐条裁决 | 机检：证据清单；**只呈现，不改退出码** |
| V6 图形承担论证 | 从 `review.md` 读人工结论：评分 ≥ 4/5 且无未裁决候选才算通过 | **人（或视觉模型）**；缺失即「待评审」 |

**什么算结构证据。** 确定性脚本只承认九类：图表承担数据关系、受控图片承担画面信息、
连接关系承担推进或因果、圆周关系布局（≥ 2 个内容子节点）承担循环或关系，
以及五个中层原语——`flow`（推进顺序）、`cycle`（闭环阶段）、`timeline`（阶段进度）、
`gauge`（单一量级）与 `pictogram`（单位化量级）。三个关系容器同样要求**至少两个
语义对象**：一根箭头加一个阶段不构成关系。布局原语（`stack`/`row`/`column`/`split`/
`grid`/`overlay`/`group`）、`surface`、`shape`、`icon` 与单个 `number` 都是包装或文字——
把文字卡片换个布局包装、加两个图标、套一层 `group`，都不会让它变成论证型图形。
代码场景（`renderer.kind == "code"`）结构上不可验证，只按声明分类，V4 对它们跳过并写明原因。

**V5 的候选不是失败。** 它是「文字主导」的证据清单：列出判据（例如「只有文字、
数值、符号图标、装饰形状或包裹它们的表面」），由人决定是改声明为 `typography`、
重构场景树，还是保留并在 V6 说明理由。把候选直接判成失败会把「刻意排版型作品」
一并误杀；把候选当成通过，则是这套闸门最容易犯的错。

**V6 只接受人工结论。** `review.md` 里没有 V6 结论时状态是「待评审」，**不能显示通过**。
支持三种写法：量表表格里的 `| 图形论证 | N |` 行、V6 小节里的 `评分：N/5`，
以及 `## 候选裁决` 小节里的 `- <场景 id>：结论` 列表。发布清单要求
V6 ≥ 4/5 且**没有未裁决候选**；只要还有候选停在「待评审」「候选未裁决」或「不通过」，
`publishable` 就是否。V 系列与 K 系列一样：跳过不等于通过，待评审不等于通过。

## 八、动画论证闸门（A1–A8）

V 系列问「这一幕有没有论证型图形」，A 系列问**「这些图形动起来的时候，有没有在解释
论点」**。两者是两件事：一幕可以既有图表又有满屏入场动效——结构证据齐全，
而观众看到的只是元素依次出现。A 系列的判定口径由
`a2v/animation_review.py` 唯一实现（`RULE_VERSION` 版本化），机检部分与
`review.py` 的 A 系列章节、`report.json` 的 `animationReview` 同源。

| 闸门 | 判定方法 | 强度 |
| --- | --- | --- |
| A1 节拍覆盖 | 每个口播段绑定到存在的 beat，每个 beat 至少被一段引用，同一 beat 的引用连续，且解析出的帧区间数量与声明一致 | 机检：分镜 + 解析时间轴；失败**并入错误数与退出码** |
| A2 含义声明 | 每条 beat 的 `meaning` 非空，且不是该 beat 口播原文的复述、也不只是动作名 | 同上 |
| A3 状态或关系变化 | 非文字幕阶段至少两条 beat，且至少一条动作真正改变对象状态或关系；全是 `establish`/`highlight` 判失败 | 同上 |
| A4 字幕同步 | 有声时字幕 cue 边界与画面 beat 边界共用同一份时间轴（逐帧允许 ±1 帧取整差）；cue 跨过口播段边界说明两者没有共用边界 | 机检：分镜 + 媒体清单；**无声时如实跳过** |
| A5 结尾停留 | 全片最后一条 beat 完成后至少留 12 帧稳定阅读时间 | 机检：解析全局时间轴；失败并入错误数与退出码 |
| A6 装饰动画人工裁决 | 从 `review.md` 读人工结论：评分 ≥ 4/5 且所有装饰配方都已裁决才算通过 | **人（或视觉模型）**；缺失即「待评审」 |
| A7 单一焦点 | 任一帧最多一个焦点对象（显式 `state: "focus"`，或关系容器里被当前 beat 点亮的阶段） | 机检：分镜 + 解析时间轴；失败并入错误数与退出码 |
| A8 稳定结束 | 所有入场配方在绑定阶段结束前留 12 帧，画面不会在末帧还在动 | 同上 |

**适用范围。** A1–A5、A7、A8 只约束**声明了 `narrationSegments` 的阶段**。含口播的 v4 分镜必须声明分段口播；无声阶段可不声明。跳过不等于通过，待评审也不等于通过——这两条在 A 系列与 V 系列上是同一个原则。

**A3 的关键在中性动作。** `establish`（建立/出现）与 `highlight`（强调）只让对象出现或
更醒目，**不**改变对象状态与关系。一幕全是它们时，观众看到的是依次出现的卡片，
不是一次推理——这正是 A3 存在的理由，也是「多个元素入场」与「动画解释了论点」的分界。

**A4 为什么要求 cue 与段边界对齐。** 字幕按句子标点断开，口播段是作者为绑定 beat 而
切的边界。两者若不一致（例如某段口播切在一句话中间），某个 cue 就会跨过段边界，
那一刻字幕说不出画面正在解释的那一步——共用边界是这条契约的全部意义。

**A6 只接受人工结论。** 不服务于任何 beat 的配方是**装饰**，不是错误：节奏感和画面
稳定常常需要它们。但「这条动效是否恰当」是审美判断，机检给不出结论，因此只列出
候选清单交给 A6。`review.md` 里没有 A6 结论时状态是「待评审」，不能显示通过；
支持量表表格里的 `| 装饰动画 | N |` 行、A6 小节里的 `评分：N/5`，以及
`## 候选裁决` 小节里的 `- <场景>:<目标>：结论` 列表。发布清单要求 A6 ≥ 4/5 且
**没有未裁决候选**。人工结论缺失绝不伪造成脚本错误——它拦的是「可发布」标记，
不是退出码。

## 机检与人工的分工

| 规则 | 谁来查 | 查不出来时的后果 |
| --- | --- | --- |
| C 系列：C1 / C3 | 结构保证：由共享 composition 输出，无需机检 | 画面缺层或整幕空白 |
| C 系列：C4 / C6 / C19 | 分镜校验 + 运行时动效计划（`motionPlan.ts`） | 手感漂移，或节奏与口播脱节 |
| C 系列：C5 / C13 | 校验器与源码闸门（`source_policy.py`、`code_gate.py`） | 成片闪烁，或画面用了目录外的写法 |
| C 系列：C8 / C12 | **暂无实现**（原 `constitution.py` 的静态检查已随旧组件路径删除） | 大面积模糊拖慢逐帧渲染；网页另抄一份分镜文案，改文案时两边不一致 |
| C 系列：C10 / C11 / C14 | `review.py` 帧量测与契约探针 | 出废片或标签全空 |
| C 系列：C2 / C7 / C9 | **人（或视觉模型）** | 片子能播，但没人看完 |
| C15（设计语言层作用域） | `tests/test_react_design_tokens.py`（浏览器量计算值） | 预设作用域泄漏，作用域外的画面静默改样 |
| K 系列：K1–K6 / K9 / K10 | `review.py` 的观感闸门（只给数值，跳过项写明原因） | 画面能用但不像发布会级，最终判断仍归人工 |
| K7 文字溢出 | `review.py` 的观感闸门，失败并入错误数与退出码 | 文字被裁掉或压出安全区，且流水线能拦住 |
| K8 容器内溢出 | 同上；文字用 `data-a2v-inside="<容器选择器>"` 声明自己所属的容器，探针按 `getBBox()` 判圆周与容器边界，未声明的不判定、如实记「跳过」 | 图形内的文字穿出容器（例如标签比圆还宽），而 K7 的参照只有安全区、量不到它 |
| 图形颜色预算 | `tests/test_figure_contrast.py`（分类表 + 对比度 + 禁字面色值 + 边界令牌必须被引用） | 图形与底色同色：空壳只剩虚线、差量条只剩虚线框，看着像没画完 |
| 组件走令牌（C17，见上） | `tests/test_figure_contrast.py` 颜色侧 + 组件单测与代码评审 | 间距、线宽、字重、字距、圆角在组件里各写各的，规范写了但没人执行 |
| 状态语汇唯一（C18，见上） | `web/src` 组件单测的状态断言 + `review.py` 运行时量测 | 焦点又有第二套写法，同一帧几处都在强调，「谁是主」量不出来 |
| V 系列：V1–V4（文字幕预算 / 连续文字幕 / 模式覆盖 / 声明与结构一致） | `review.py` 的视觉叙事章节 + `validate.py --strict`（同口径） | 整支片子由文字卡片撑起来，而机检、观感闸门与渲染全部照常通过 |
| V 系列：V5（文字主导候选清单） | `review.py` 输出证据，**由人裁决** | 把文字卡片当图形论证交付，观众看到的是会动的幻灯片 |
| V 系列：V6（图形承担论证） | **人（或视觉模型）** 写进 `review.md`；缺失即「待评审」 | 结构上过了 V1–V4，但图形仍然只是配图 |
| A 系列：A1–A5 / A7 / A8（节拍覆盖 / 含义声明 / 状态变化 / 字幕同步 / 结尾停留 / 单一焦点 / 稳定结束） | `review.py` 的动画论证章节（读分镜与媒体清单，不需要浏览器） | 画面由多个元素依次入场，字幕与动画各走各的，最后一帧还在动——观感闸门与渲染全部照常通过 |
| A 系列：A6（装饰动画裁决） | **人（或视觉模型）** 写进 `review.md`；缺失即「待评审」 | 装饰动效喧宾夺主，而机检只认得出「它不服务于任何 beat」 |

**C8 与 C12 目前没有实现，这是已知边界。** 旧整页组件路径上曾有一份按网页源码
做静态体检的实现（C1 / C3 / C4 / C5 / C6 / C8 / C12），它随那条路径一并删除：
画面已不由作品自己的 HTML 决定，按契约页的 HTML 查结构只会得到恒真的结论。
C1 / C3 因此改为「由共享 composition 结构保证」，C4 / C6 由分镜校验与运行时
动效计划承担，C5 / C13 由源码闸门承担；**C8（不用大面积模糊）与 C12（文案单一
真源）暂时没有替代判据**——需要时按现行结构补进 `source_policy.py` 或分镜校验，
不要按旧口径去查契约页的 DOM。

C 系列里的 C2 / C7 / C9 才是真正决定播放量的部分。机检负责保证「不是废片」，
人工评审负责保证「值得看完」——把后者也交给脚本，等于放弃质量。
