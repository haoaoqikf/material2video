# 配音与字幕

## 工作流

1. 每幕可写字符串 `narration`，或写分段口播 `narrationSegments` + `beats`
   （二者互斥）；省略或空字符串表示静音。
2. `prepare.py --storyboard <json>` 生成媒体；省略 `--out-dir` 时写入该文章的
   `outputs/<slug>/media/`（示例为 `outputs/examples/<slug>/media/`）。
3. `validate.py <json> --media <media.json>` 检查清单与源分镜、字幕和 WAV 时长。
4. `preview.py --storyboard <json> --media <media.json>` 预览。
5. `render.py --storyboard <json> --media <media.json>` 输出
   `outputs/<slug>/voiced.mp4` 和同名 SRT；省略 `--out` 时由文章归属推导，显式 `--out` 仍然优先。

省略 `--media` 时保留原无声模式，成片名为 `silent.mp4`；已有 narration 不会自动触发联网或配音，
但会在日志中提示本次按无声导出。composition 读取的分镜在渲染前由媒体清单派生
（时长按口播延长），不由命令行替换其内容。路径推导规则见 [目录约定与输出路径](paths-and-outputs.md)。

带 `--media` 的预览、评审与渲染会把派生分镜落盘为媒体目录里的
`storyboard.effective.json`，契约页与 Remotion 的 props 都指向它——composition
的时长由 props 推导，props 仍是原始分镜时画面按声明时长走，音轨却按派生时长合成：
渲染的总帧数交叉校验直接失败，体检抽帧会落进下一幕入场前的空窗、被误判成空白帧。
渲染用的是输出目录旁的临时副本，随渲染销毁；预览与评审写媒体目录里的固定文件，
下次预览自动覆盖。代码场景清单与作品归属仍按原始分镜路径解析。

## 语音与字幕

使用 [edge-tts](https://github.com/rany2/edge-tts) 7.2.x，默认 `zh-CN-XiaoxiaoNeural`、`+0%`；`--voice` 指定音色，
`--rate=-10%` 调整语速，`--force` 强制重建。首次合成需要联网；服务可能变化，
缓存音频可离线复用，不承诺再次强制生成时波形完全相同。

每幕采用 WordBoundary 事件，将 100ns 时间单位转换为秒，从原文恢复标点后按句断开。
长句仅在真实词边界拆分，每条最多 28 字符。不支持逐字高亮或导入录音。
音频损坏、时间戳缺失/倒退/越界、时间戳文字未覆盖原文时失败，不猜测字幕时长。
如果服务把数字或缩写改写成读音导致文字不匹配，请将 narration 写成明确的口语文本。

当前导演契约中的 `camera` 与 `transition` 是分镜声明字段，不改变媒体清单的帧边界；跨幕连续变形和镜头运动的媒体级时间轴尚未实现，不能把声明字段误认为已渲染能力。

分段口播按**原文顺序**消费词边界：每个词块按它在完整口播文本里的字符起点归到
所属段，段末恢复出来的标点允许落到下一段开头（它本来就没有独立时间），但词本身
跨过段边界即失败——那说明分段切在词中间。重复短语因此不会被映射到前一处。
任何一段拿不到词块、或词边界没有覆盖完整口播，同样失败而不猜测。

每幕实际帧数为 `max(原帧数, ceil((WAV时长 + 0.3) * fps))`；空口播保持原帧数。
音频统一解码为 24000Hz、单声道、16bit PCM WAV，按派生时间轴补静音并拼接。
按累计帧数计算采样位置，避免逐幕取整误差累积。字幕时间以视频开头为零点，
采用开始包含、结束不包含的区间；SRT 输出四舍五入到毫秒。

## 媒体清单 version 2

媒体清单独立于分镜版本，由程序生成，不建议手工编辑。

| 字段 | 含义 |
| --- | --- |
| `version` | 媒体清单版本，当前为 2 |
| `source` | 完整原分镜快照，用于网页一致性检查 |
| `sourceFingerprint` | 对原分镜排序键、紧凑 UTF-8 JSON 求 SHA-256 |
| `voice` / `rate` | 合成所用音色和语速 |
| `scenes` | 与源分镜同序，每项含 `id`、实际 `durationInFrames`、场景 WAV 相对路径 `audio`（静音为 null）；声明了分段口播的幕还含 `resolvedBeats` |
| `cues` | 全局字幕列表，每项含秒数 `start`、`end` 与字符串 `text` |
| `audio` | 统一 WAV 相对路径，必须在清单目录内 |
| `subtitles` | 完整 SRT 相对路径 |

`resolvedBeats` 是逐幕的派生节拍时间轴，形状为
`{id, action, targets, meaning, startFrame, endFrame}`，区间按场景 fps **向外取整**
（起点向下、终点向上），并把起点钳到上一段的终点，使相邻区间首尾相接、不因取整
而重叠；起点包含、终点不包含。画面、字幕与配音共用这批边界——少了它，
composition 会退回无声等比例估算，字幕却按真实词边界走，两者在同一帧里各说各话。

读取时校验版本、原分镜指纹、场景 ID/顺序/最短时长、字幕区间和统一 WAV 的实际长度，
并对每幕 `resolvedBeats` 校验顺序、重叠、越界与源声明一致性。**version 1 的旧清单
继续可读**：只要不含分段口播就照常可用；含分段口播的旧清单会明确要求重新 prepare，
而不是拿旧缓存凑一个时间轴。修改原分镜后清单立即过期，须重新 prepare；
只改网页样式不用重新合成。预览与导出均使用 `scenes` 中的派生时长，
不在网页重新估算配音时长。

## 缓存与失败处理

输出目录内 `cache/` 保存按文本、音色、语速、生成器版本、edge-tts 版本计算键的 WAV 和
字词时间戳 JSON。缓存校验包括音频长度、SHA-256 与时间戳；损坏时重新合成该幕。
未改变的场景复用缓存，改变原时长或画面文案不会重新请求相同口播。

连接超时 10 秒、接收超时 30 秒、单幕请求总超时 90 秒；网络失败最多重试两次，
间隔 1 秒、2 秒。无效参数不重试。日志包含场景、缓存命中与失败原因。

准备过程在输出目录内写临时文件；统一音轨和 SRT 使用新资源名，最后原子替换 `media.json`。
失败保留上次可用清单。旧资源为避免破坏已打开的预览不自动删除；不再使用后可清理整个输出目录。
清单与音轨属于哪篇文章，由它所在的 `outputs/<slug>/media/` 目录决定：渲染时若 `--media`
不在当前文章的媒体目录内，直接报错而不是跨文章合成。
请将产物放在已忽略的 `outputs/`，生成媒体、清单和缓存均不提交 Git。

## 渲染与验收

字幕由共享网页层绘制，正文留出 180px；预览支持播放、暂停、重播和拖动，音轨为播放时钟。
渲染按帧 seek，不播放音频；先编码画面，再复制视频流合入 AAC 配音，无二次视频编码。
合成时配音统一转码为 **AAC-LC / 44.1kHz / 立体声 / 128k**：清单里的 WAV 是 24kHz 单声道，
但 24kHz 单声道 AAC 会被 Windows 的 Media Foundation 拒绝（`0xc00d36c4`），
44.1kHz 立体声是各平台兼容性最好的组合。画面像素格式固定为 `yuv420p(tv, bt709)`，
原因与对应校验见 [渲染契约](render-contract.md) 的「码流兼容性」。
清单、音轨与字幕都经临时目录原子落盘，之后会把访问权限交回目标目录的继承规则，
原因见 [渲染契约](render-contract.md) 的「交付文件的访问权限」。
最终 MP4 检查视频解码帧数、实际尺寸、帧率、时长及音轨解码长度，时长容差 100ms。
`--limit-frames` 同步裁切音轨和导出 SRT；省略 `--out` 时写入 `previews/`，不覆盖正式成片。
`--no-probe` 仅跳过最终成片验收，不跳过媒体校验。
背景音乐、自动选曲及音乐混音当前未实现。
