# 发布会级设计语言

这份文件回答一个问题：**「像发布会一样」到底能不能被判定？**

在本层出现之前，项目的「高级感」由三样东西拼起来：规范里的若干数值、
组件里写死的裸数字、以及每次渲染完靠人眼看一眼。结果是同一套组件在不同视频里
观感差异明显，换个人重做一遍就会漂移。本层把它拆成两半——

- **设计语言层**（`assets/keynote.css`）：把「高级感」固化成令牌与用法类；
- **排版引擎**（`assets/typography.js`）：把「一行放得下几个字」从试错变成计算；
- **观感闸门 K1–K9**（`scripts/a2v/keynote.py`）：把上面两层的效果变成**数值结论**。

它与 [视觉规范](visual-spec.md) 的分工是：视觉规范是**通用**规范，任何视频都适用；
本文件只描述**启用预设之后**多出来的那层约束，以及它凭什么自称「发布会级」。

## 一、怎么启用

在分镜根级声明预设即可，不需要改网页、不需要新依赖：

```json
{
  "version": 1,
  "visual": { "theme": "dark", "preset": "keynote" }
}
```

- `preset` 是**可选**字段；目前唯一取值是 `"keynote"`，未知值由校验器报错并指出
  `visual.preset` 字段路径（不写就是未启用）。
- 未声明 `preset` 时：设计语言层的全部规则因带 `[data-a2v-preset="keynote"]`
  作用域而不生效，`declarative.js` 也不会调用排版引擎
  （页面仍然 `link` 了 `keynote.css`、`script` 了 `typography.js`，
  这一点是刻意的——按需注入会让「有没有生效」变得难以验证）。
  画面**逐帧不变**，这不是口头承诺，有逐字节回归证据，见「五、静默失效清单」。
- 两套主题都支持预设：`"theme": "dark"` 与 `"theme": "light"`。
- 参考实现见 `examples/keynote-baseline/`（8 幕 / 2040 帧 / 68s）。

## 二、为什么是这几个数值

### 字体：落盘，不走 CDN

`assets/fonts/` 里是 Inter Variable（拉丁与数字）与 Noto Sans SC Variable（中文），
SIL OFL 1.1，随仓库分发。理由不是「开源免费」，而是**可复现**：
字体是观感的第一个变量，也是「配色一样但看起来不一样」最常见的原因。
CDN 会在断网、限流、版本漂移时静默回退到系统字体，而成片照样出得来。

字体栈只在预设作用域里覆盖 `--a2v-font`。这一点是硬要求，原因写在第五节。

### 字号阶：每档都配行高与字距

| 档位 | 令牌 | 字号 | 行高 | 字距 | 用途 |
| --- | --- | --- | --- | --- | --- |
| numeral | `--a2v-size-numeral` | 350px | 1 | -0.04em | 数字幕的主角数值，一屏只用一次 |
| mega | `--a2v-size-mega` | 220px | 1 | -0.035em | 只为字阶连续而存在（见下） |
| hero | `--a2v-size-hero` | 140px | 1.06 | -0.03em | 开场与收束，一屏只用一次 |
| display | `--a2v-size-display` | 120px | 1.1 | -0.025em | 主角数字、极短命题 |
| headline | `--a2v-size-headline` | 96px | 1.14 | -0.02em | 金句、主命题 |
| title | `--a2v-size-title` | 76px | 1.2 | -0.015em | 小节标题、大号说明 |
| lead | `--a2v-size-lead` | 60px | 1.32 | -0.005em | 引文、结论正文 |
| body | `--a2v-size-body` | 40px | 1.47 | 0em | 正文、条目标题 |
| label | `--a2v-size-label` | 34px | 1.4 | 0.14em | 组件标签、轴名 |
| caption | `--a2v-size-caption` | 28px | 1.45 | 0.06em | 角标、来源、页码 |

相邻档位比例在 1.1–1.6 之间，顶部刻意拉大：发布会画面上「大标题 vs 说明文字」
的对比本身就是层级，不靠加粗。**正文下限 36px**——低于这个值在竖屏上不可读，
正确做法是拆场景，不是缩字号（`A2V.type.minBodyPx` 会在取档时守住它）。

行高与字距必须**显式**写在令牌里，不依赖字体自带度量：跨字体、跨机器保持版式
一致的前提就是把这两项钉死。

`tests/test_keynote_assets.py` 会把 CSS 令牌与 `typography.js` 的 `SCALE` 逐档对齐，
两边改岔了会直接测试失败——否则表现是「引擎算出 96px，样式表预置 124px」。

**顶端的 `mega` 档为什么存在。** 第七轮把主角数值从 120px 抬到 350px，
因为组件的兜底一直是 `var(--a2v-ink-display, 240px)`，而 `--a2v-ink-display`
是设计语言层专有的令牌——**预设把大数字从组件自己的 240px 压到了 120px**，
本意是"给它一个阶"，实际是把它缩小了一半（数字幕的内容纵向只占安全区 29%，
八幕里最空）。抬高时不能从 140 直接跳到 350：相邻档位比例有 1.1–1.6 的模块化约束
（测试守着这条），2.5 倍会破坏字阶的连续性，也会让拟合引擎对大数值
从 350 一档掉到 140。所以补一档 `mega`（220px）当桥。
它本身不被任何元素声明，作用是让字阶与取档都保持连续。

### 组件墨色字号：`--a2v-ink-*` 把这层也收进字阶

页面的字号阶管不到**组件内部**的文字。`figures.css` 原本散着一批裸字号
（30 / 32 / 36 / 38 / 44 / 46 / 48 / 56 / 62 / 124 / 220 / 240px），
其中 30–38px 那几处还低于正文下限：在竖屏上读不出来，而且不在阶上，
`K3`（同帧字号种类）就数不到它们——层级统计变成一张漏网的表。

预设给同一个字阶再起一套**别名**，组件引用语义名而不是裸数字：

| 别名 | 指向 | 落在组件里的位置 |
| --- | --- | --- |
| `--a2v-ink-caption` | `--a2v-size-caption`（28px） | 图形角标、来源、坐标注 |
| `--a2v-ink-label` | `--a2v-size-label`（34px） | 轴名、次要标注 |
| `--a2v-ink-body` | `--a2v-size-body`（40px） | 组件内正文、小标题 |
| `--a2v-ink-value` | 44px（与 K3 的统计下限同值） | 条目数值、标签 |
| `--a2v-ink-lead` | `--a2v-size-lead`（60px） | 引文、数字说明 |
| `--a2v-ink-title` | `--a2v-size-title`（76px） | 图形小标题 |
| `--a2v-ink-display` | `--a2v-size-display`（120px） | 图形主数值、装饰引号 |
| `--a2v-ink-numeral` | `--a2v-size-numeral`（350px） | 数字幕的主角数值（`.fig-number`） |

`--a2v-ink-value` 刻意与 K3 的 44px 同值，不再另立一档；`--a2v-ink-display`
让 240px 的主角数字落到顶档，仍然是画面里最大的东西，但成为**可枚举**的一档。

写法一律是 `font-size: var(--a2v-ink-body, 36px)`——第二参数是原值兜底。
未启用预设的页面取不到这些令牌，落回原值，因此**渲染结果逐字节不变**；
只有预设页面才吃到新数值。用 `var()` 而不是直接把裸值改成令牌，
就是为了守住这条兼容性。

### 版面：三种 `visual.layout` 有确定的落点

分镜用 `visual.layout` 选版面，共享页面在**没声明时兜底为 `center`**
（`declarative.js`：`(scene.visual || {}).layout || 'center'`）。
这意味着 `data-layout` 属性总是存在，预设无法从它区分「显式要居中」与
「没声明所以居中」，因此预设**不推翻**这个兜底——那要改共享页面，
会波及所有未启用预设的视频。预设只做两件事：

1. 补齐页面原本没有定义的一档 `left`（`align-items: flex-start; text-align: left`）；
2. 居中版面上隐藏引文装饰（`.quote-rule` / `.quote-mark`）：
   竖线与引号是「给左边缘一个视觉锚点」用的，居中构图没有左边缘，
   留着它们只会把正文推离画面中心（实测偏差 31px）。

三种版面的几何由 `tests/test_keynote_layout.py` 用浏览器实测复核：安全区不越界、
字号全部落在阶上、居中版面文字中心误差 ≤2px、下置版面内容底边低于画面中线。

### 间距：8pt 网格，允许一个半档

`--a2v-space-1..10` = 4 / 8 / 16 / 24 / 32 / 48 / 64 / 96 / 128 / 192（px）。
4px 是唯一允许的半档，留给发丝级间隙；其余全部是 8 的倍数。
硬要「全部 8 的倍数」会逼着组件用 8px 去凑视觉上的 4px，反而破坏对齐。

### 组件令牌：描边、字重、字距、图形几何

页面级的四族令牌管不到**组件内部**。实测 `figures.css` 发现，
规范写的约束在组件里基本没落地，而机检一条也看不到：

| 属性 | 声明总数 | 走令牌 | 字面值 | 字面值样例 |
| --- | --- | --- | --- | --- |
| `gap` | 13 | 0 | 13 | 30 / 46 / 18 / 22 / 44px |
| `padding` | 4 | 0 | 4 | `26px 20px 24px` |
| `letter-spacing` | 16 | 0 | 16 | 0.14 / 0.08 / 0.02em |
| `font-weight` | 10 | 0 | 10 | 500 / 600 / 700 / 800 |
| `stroke-width` | 18 | 0 | 18 | 2 / 3 / 4 / 5 / 6 |
| `border-radius` | 11 | 3 | 8 | 19px / `0 0 19px 19px` |

四族新令牌按**用途**分档，组件一律写成 `var(--令牌, 原值)`——
未启用预设时取不到令牌就落回原值，画面逐字节不变（这条有成片哈希守着）。

| 族 | 令牌 | 取值 | 为什么是这几档 |
| --- | --- | --- | --- |
| **描边阶** | `--a2v-stroke-1..5` | 1 / 2 / 3 / 4 / 6px | 发丝边界 / 次级结构 / 数据描边 / 图形主体 / 焦点与运动轨迹。不是「一条 2px 走天下」：竖屏 1080 宽在手机上只剩 400–500 逻辑像素，1px 缩完接近消失；但全抬到 4px 会让次级结构与数据描边一样重，层级反而塌掉。原先的 5px 只出现在阶梯的跳跃弧上，语义与 `.loop-arc` 的 6px 完全相同，留两个差 1px 的档位等于给后人一个随手可选的理由，因此合并 |
| **字重阶** | `--a2v-weight-*` | 400 / 500 / 600 / 700 | 上限收到 700：Inter 与 Noto Sans SC 都是可变字体，800 在中文上笔画会粘连（汉字笔画密度远高于拉丁）；而「更大」这个诉求已经由字号阶的 display / hero 档承担了 |
| **字距槽** | `--a2v-track-*` | -0.07 / -0.03 / 0 / 0.06 / 0.14em | 组件层原有 16 处字距取值从 -0.07 一路铺到 0.14（0.01/0.02/0.04/0.06/0.08/0.10/0.12/0.14）。那不是一个刻度而是一串近似值——同一个语义「小标签要松开」有五个取值，「为什么这两个标签的字距不一样」就永远没有答案。按语义收成五槽，逐值映射到最近一槽。值本身复用既有的 `--a2v-tracking-*`，不新造同义族 |
| **图形几何** | `--fig-node-r-min` / `--fig-surface-pad` / `--fig-connector-w` / `--fig-arrow-*` | 76px / 16px / 4px / 34×16px | 只收「八个组件应当一起变」的那几个量。一张图的**坐标**（立柱位置、圆上节点角度、柱高数组）是内容而不是令牌，刻意留在组件里 |

**令牌闭包已经完成**：描边、字重、字距、圆角、1px 边框、间距（`gap`）、
内边距与 `margin-top` 全部走令牌——`figures.css` 新增 **86 处**令牌引用
（描边阶 22 / 间距阶 25 / 字距槽 16 / 圆角档 13 / 字重阶 10），
这六组属性的字面值降到 0（只余 `0` / `auto` 这类复位值）。
不在 8pt 阶上的取值一并改到阶上：30 → 32、46 → 48、44 → 48、18 → 16、22 → 24、
26 → 24、34 → 32、14 → 16、62 → 64、10 → 8、84 → 96、6 → 4。

两处不能靠"就近取整"决定，要问那块留白在画面里承担什么：

- `.drop-board` 的栏间距 40 距 32 与 48 **等远**。取 48：48 = 2×栅格沟槽，
  两栏因此落在 12 列栅格上，作为对照的两栏分隔也更明确。
- `.vs-board` 的 84 落在阶的空档里（64 与 96 之间）。取 96：
  下取 64 会把标题与图形之间的分隔缩掉 20px，与原本的手感差得太远。
  规则是**取阶上最近的档；等距时向上（留白更多的一侧）**。
- `.drop-panel` 原来的 `26px 20px 24px` 上下不等（26 vs 24），是手调出来的偶然差，
  收成上下 24 + 左右 16——同一个面板的上下内边距没有理由不相等。

这套判据由 `tests/test_figure_token_closure.py::TestTokenClosure` 逐条守住：
以后往组件里写一个裸数值（`stroke-width: 3px`、`gap: 18px`、`padding: 12px`）
会直接测试失败，而不是靠人眼在成片里发现"哪里不太对"。
写这个测试时它立刻抓出一处漏网——`.drop-fill` 的
`border-radius: var(--a2v-radius-sm, 19px) 19px 0 0`，第二个角还是字面值。

### 图形基元与状态

组件原先各自发明表面、标签与连线的长相。同一个语义「强调/焦点」有三种写法：
冰山与双向选择用静态的 `is-accent`，阶梯用逐帧改的 `is-focus`，
双栏对照用一条 `--vs-heat` 连续量。三种写法并存，「主次分明」就只能靠每个画面临场发挥。

令牌层因此定义四个**基元类**（挂在组件已有的元素上，不新增 DOM 层级）：

| 基元 | 用途 |
| --- | --- |
| `.a2v-surface` | 任何表面：卡片、节点圆盘、托盘 |
| `.a2v-label` | 图形内的文字 |
| `.a2v-connector` | 连线、箭头、轨道、轴线 |
| `.a2v-frame` | 边界框：一个物体唯一可见的边界 |

状态只有四个，语义固定，**只表达颜色，不表达动效**：

| `data-a2v-state` | 语义 | 表面 | 描边 | 文字 |
| --- | --- | --- | --- | --- |
| `rest` | 基准 | `--fig-surface` | `--fig-line` | `--a2v-text-1` |
| `focus` | 当前焦点（一屏一个） | `--fig-surface` | `--a2v-accent` | `--a2v-text-1` |
| `muted` | 已被否定的那一侧 | `--a2v-bg-0` | `--a2v-hairline` | `--a2v-text-3` |
| `done` | 已完成 / 已翻转 | `--a2v-accent-deep` | `--a2v-accent` | `--fig-on-ink` |

几条取舍：

- **没有 hover / active / disabled。** 画面是逐帧渲染的，没有指针，也就没有交互态；
  硬塞进来只会得到几个永不被置上的属性。四态对应的是叙事里的四种角色。
- **不写 `opacity` 与 `transform`。** 不透明度与位移属于动效配方层；
  一旦写进状态定义，时序就有两个真源——而配方层存在的全部理由就是「手感只有一处」。
- **SVG 的焦点光晕由组件自绘**（例如 `.loop-token-halo` 那种径向渐变圆），
  不用 `filter`：仓库禁用大面积模糊类的写法，逐帧截图的性能与可复现性靠这条守住。
- **基元类的作用域是硬约束**：这些规则只在预设生效时存在，未启用预设的页面里
  基元类匹配不到任何声明，画面因此逐字节不变。
- **当前只有飞轮一个组件挂了基元与状态**，其余七个仍各写各的——这是进行中的迁移，
  不是已完成的能力。

### 容器内文字：几何由内容测量决定

飞轮节点原先半径 76px（直径 152px），而节点标签在预设下取 `--a2v-ink-value` = 44px，
四个汉字带字距约 183px——**比直径还宽 31px**，文字必然穿出圆。
逐帧看图直接可见（`outputs/examples/keynote-baseline/inspect/frames/loop-68-f1124.png`），
而当时的 K7 报的是「量了 2 个文本块，都在安全区内」。

根因不是「半径写小了」，而是**先写死容器几何、再把文字塞进去**这个顺序。
现在改成按实测宽度定形：宽 w、高 h 的文字块居中放进半径 r 的圆，
需要 `r ≥ sqrt((w/2)² + (h/2)²)`；逐行数试算，取所需半径最小的一种装法，
再用 `tspan` 写成单行或多行。宽度用 `getComputedTextLength()` 实测——
运行时在首次 seek 之前 await 过 `document.fonts.ready`，量到的一定是最终字体，
结果逐帧可复现。

**不使用 `textLength` 横向压缩字形**：压缩会让中文看起来被挤扁，比溢出更难看。
放不下就降字号档，降到正文下限仍放不下就报错，而不是让它变形。

顺带修掉一处同类缺陷：节点文字原先以 `y = 圆心` 作基线，也就是基线压在圆心上，
视觉上比圆心低约 0.35em；现在按行盒中心对齐，单行与多行都以圆心为中心。

### 表面：按亮度序排列

同一主题内的表面只有一条序列，组件不发明自己的颜色：

| 用途 | 深色 | 浅色 |
| --- | --- | --- |
| 画布 `--a2v-bg-0` | `#08090c` | `#eff1f4` |
| 抬升 `--a2v-bg-1` | `#0f131a` | `#f8f9fb` |
| 最高 `--a2v-bg-2` | `#161c26` | `#ffffff` |
| 强调色 `--a2v-accent` | `#32d6ff` | `#0a6ad9` |
| 图形着重 `--a2v-accent-deep` | `#2f7fa8` | `#0b4f9e` |
| 图形渐变末端 `--a2v-accent-soft-solid` | `#16465f` | `#0d3f7d` |
| 强调褪色落点 `--a2v-emphasis-fade` | `#d5dce8` | `#565c6e` |

对比度预算：正文级墨色对画布 **≥ 7:1**，大字（≥44px）与图形着重色 **≥ 4.5:1**。
括号里的实测值由 `tests/test_keynote_assets.py::TestContrastBudget` 复核，
不是靠写注释时的印象。

**一个主题只有一个强调色。** 60-30-10 里的那个 10 只允许一处：
一屏里出现两种强调色，观众就不知道先看哪里（K2 会给出实测占比）。

### 图形颜色：分类 + 对比度预算

`--fig-*` 不是一堆可以随手调的灰，每一类有自己的判据。**分类按用途，不按取值**：
「因为它是细的，所以它是装饰」是自证，正确的问题是「这条线消失了，观众还看得懂这张图吗」。
**分类表是契约**：`tests/test_figure_contrast.py` 按表断言，出现未归类的图形颜色令牌直接报错，
所以新增一个 `--fig-*` 的第一件事是把它归到下面五类里的一类。

| 类 | 判据与基座 | 令牌 |
| --- | --- | --- |
| **数据描边** | 对 `--a2v-bg-0` ≥ **4.5:1** | `--fig-line`（5.69 / 5.22）、`--fig-line-data`（7.75 / 7.42）、`--fig-water-line`（4.82 / 5.23） |
| **图形内文本** | 对 `--a2v-bg-0` ≥ **4.5:1**；画在 `--fig-ink` 上的文字对 `--fig-ink` ≥ 4.5:1 | `--fig-water-text`（8.06 / 7.22）、`--fig-on-ink`（15.97 / 16.30，对 `--fig-ink`）、`--fig-title-grad-from/to`（17.09 / 13.38、9.70 / 8.79） |
| **边界描边** | 对 `--a2v-bg-2` ≥ **3:1**，且必须真的被引用 | `--a2v-hairline-strong`（3.32 / 3.09） |
| **装饰描边** | 对 `--a2v-bg-0` ≥ **1.5:1** | `--fig-line-soft`（1.63 / 1.63） |
| **面填充** | **不设数值下限** | `--fig-surface`、`--fig-water`、`--fig-hollow`、`--fig-node-shadow`、`--fig-drop-track`、`--fig-drop-fill-from/to`、`--fig-drop-fact-from/to`、`--fig-gauge-track` |

括号里是（深色 / 浅色）实测值。几条不显然的取舍：

- **判据基座写进表里，规则才没有解释空间。** 数据描边与图形内文本对画布判定；
  **边界描边对抬升面 `--a2v-bg-2` 判定**——它压在面板上，同一个颜色在两层上的比值不同
  （深色分隔线对画布 1.52:1、对抬升面 1.64:1），拿画布去量一个压在面板上的边框，
  只会得到一个乐观的数字。
- **边界描边是「一个物体唯一可见的边界」。** `.drop-track` 的填充只有 0.03 白，
  边框是这根竖尺唯一能被看见的边界，所以用 `--a2v-hairline-strong`；
  这一类还要求**令牌必须真的被引用**——`--a2v-hairline-strong` 曾经定义了却一处都没用，
  注释里写着 2.99:1 而按新基座实测只有 2.49:1，两件事都没人发现。
  「定义了却没人用」和「排版引擎全绿但空转」是同一类静默失效，只是发生在 CSS 层。
- **纯分隔线是刻意耳语的，并且这件事也被守住。** `--a2v-hairline`（对抬升面
  1.65 / 1.24:1）用于卡片与面板的边框、场景序号的分隔规则。WCAG 1.4.11 管的是
  「理解内容所必需的图形对象」，纯分隔线本来就在豁免范围内；卡片的身份由
  **填充 + 圆角 + 投影**共同界定，边框只是辅助。把每条分隔线都提到 3:1
  会让画面整体变重、层次变平——这正是 K2 早期「强调色占比低就判失败」那类误判。
  测试里有一条显式断言「分隔线必须低于 3:1」，让「不抬高它」成为被守住的决定。
- **面填充不设下限，是因为设了会把正确做法判成缺陷。** 浅色主题自己的面阶
  （`--a2v-bg-0` `#eff1f4` → `--a2v-surface-1` `#ffffff`）只有 1.13:1，
  而 `--fig-surface` 取白色正是跟着这套面阶走。形状读不读得出来由描边负责：
  `.berg-tip` 有 4px 的 `--fig-line` 描边，`.load-hollow` 有 `--fig-line` 描边。
- **面填充的量级已经查清：三档按性质分家，不给实心物体单独加重。**
  看过全分辨率实测帧之后确认，实心物体（台阶柱、圆盘、块体）读作
  「细描边 + 耳语填充」，形状毫无歧义；而冰山图里**水上尖端是耳语填充、
  水下主体是冷色实心**——这个差就是那张图的语义（看得见的一角与看不见的
  主体不是一回事）。给实心物体加重填充不是「变得更实」，而是把刻意做出来的
  层级抹平。三档的区分是**性质**而不是幅度：实心面取该主题的亮度阶（中性）、
  次级面（水体）是唯一的冷色透明面、空壳是耳语级。
  机检因此只判关系不判幅度：实心面不等于画布、三档不塌成同一个取值、
  次级面带冷色色相。**已知边界**：实心面等于抬升面（浅色主题都是 `#ffffff`，
  深色主题两者只差 1.01:1），所以画在面板**上**的实心物体没有面阶，
  识别由描边承担——这是接受的取舍，面板本身已经与画布分开。
- **`--fig-line-data` 与 `--fig-line-soft` 分家，是因为用途不同。** `.loop-track`、
  `.stair-axis` 与 `.scale-rope` 承载结构，靠一条 1.63:1 的线说不清楚；
  `.scale-rope` 吊着两个秤盘，是横梁与秤盘之间唯一的联系，它一淡横梁就像浮在空中。
  把 `--fig-line-soft` 整体提到 4.5:1 会让「软线」这个语义消失。
- **槽是刻度参照，不是装满的柱。** `--fig-drop-track` 在浅色页面只有 1.05:1，
  深色这边同样只给耳语级的一层白（`rgba(255,255,255,0.03)`）。给重了，
  「从未拥有」那一栏会看着是满的——而它按设计就该是空的
  （`figures.js` 的 `updateGap` 里 `applyDrop(pick('fillB'), 0)`）。
- **两套主题各自取值，不取公共下限。** 浅色背景下同样的视觉重量需要更深的颜色，
  这是对比度计算本身的性质，不是实现偏差。
- **图形颜色一律走令牌，一个字面值都不许写。** 写死的颜色不跟主题走：
  `.load-hollow` 的 `rgba(22,24,29,0.035)` 和 `.drop-track`/`.drop-fill` 的
  `rgba(22,24,29,0.025)`、`#3a3f4a→#23262d` 都是浅色页面上的取值，
  压到深色预设的近黑底上就与底色同色——「空壳」只剩虚线，「差量」只剩虚线框。
  `test_svg_paint_never_hardcodes_a_color` 让这条不再靠自觉。
- **描边的视觉重量不是问题，对比度才是。** 曾经怀疑 `viewBox` 缩放会把 4px 的线
  等比压成头发丝，实测下来所有 SVG 描边的 `getScreenCTM` 缩放比**都是 1**，
  声明的宽度就是渲染宽度。这类猜想先用运行时量测否掉再动手，不要照猜测定阈值。

### 安全区

预设把 `--a2v-safe-top` 从 220px 提到 240px：发布会版的顶部留白本来就更大，
而且更保险。K1 的留白预算按**更宽**的 220px 判定，所以预设只会更保守，不会擦线。

## 三、排版引擎（`A2V.type`）

它解决的是「先写字、看效果、再回来改字号」这个来回。所有接口只依赖帧号与
实际测量，因此逐帧可复现。

**引擎不会自己去猜哪些元素该取档。** 组件必须显式声明
`data-a2v-fit="<档位>"`（档位取该元素在预设下的现有字号档），
共享页面在预设生效时对声明过的元素取档；**没有声明的元素一个字都不会被动**。

| 接口 | 做什么 |
| --- | --- |
| `fit({el, text, availableWidth, …})` | 按可用宽度在字号阶上**从大到小**取第一个放得下的档，再按宽度把长段落均衡断开；触及正文下限即停，返回 `fits: false` 与 `reason: 'overflows-at-min-size'` |
| `applyFit(el, options)` | 把结果写回元素：**默认只写字号**，并记 `data-a2v-fit-level / -measured / -balanced / -fits` |
| `autofit(root, options)` | 对一幕里所有声明了 `data-a2v-fit` 的节点取档，按「有效字符 + 档位」缓存；`availableWidth` 传的是容器（`.a2v-safe`），不是元素自己 |
| `balance(text, maxChars)` | 按语义断点均衡断行：显式 `\n` 是硬换行永不重排、各行均衡、**末行不得只剩一个字或一个标点**、中文避头尾 |
| `reflow(el, lines)` | 把断行结果写回元素而**不破坏子元素**：按代码点映射回原文本节点，换行追加在「前一个字符所属节点」末尾 |
| `canReflow(el)` | 重排安全判定：出现 `<br>` 或逐字揭示的单字节点就返回 false，只取字号不改文案 |
| `optical(node)` | 行首标点与开引号悬挂（负外边距，不占行首位置） |
| `measureAdvance(el)` / `emWidth(ch, font)` / `emWidths(text, font)` | 实测字宽（em 单位），按字体签名缓存 |
| `charsPerLine(el, px, width, sample)` | 由实测宽度反推「一行放得下几个字」，按**待排文本自身**的平均字宽标定 |

### 声明档位的组件元素

| 元素 | 档位 | 该元素在预设下的字号 |
| --- | --- | --- |
| `.title-text` | `display` | 120px |
| `.section-title` | `title` | 76px |
| `.fig-number-label` | `title` | 76px |
| `.quote-text` | `lead` | 60px |
| `.stair-caption` / `.fig-number-caption` / `.closing-action` | `body` | 40px |
| `.vs-note` | `caption` | 28px |

**幕标题曾经是 `body`（40px），这是排版层级失效的单一根因。** 四个分节式幕
（`compare` / `attention` / `loop` / `freedom`）的标题原先都按**眉标**排版：
40px、字重 500、字距 `+0.14em`、颜色取最暗的 `--a2v-text-3`。逐幕实测的结果是
标题成了整屏**最弱**的元素：

| 幕 | 标题 | 同幕里比它强的内容 |
| --- | --- | --- |
| `compare` | 40px / w500 / 最暗 | 卡片标签 44px |
| `attention` | 40px / w500 / 最暗 | 标注 44px **w700** |
| `loop` | 40px / w500 / 最暗 | 节点标签 44px **w600** |
| `freedom` | 40px / w500 / 最暗 | 阶梯标签 40px w600，且**更亮** |

错位在于**文案与排版不一致**：分镜的 `title` 写的是一句完整的话
（「多出来的那部分是什么」），页面上方的英文眉标（`COMPARISON`）才是角标。
文案是标题、排版却是角标，于是「层级清晰 / 主次分明 / 对比明确」在同一处同时失效。

修法是把它当标题：档位换到阶上已有的 `title`（76px），
字重 / 字距 / 颜色由 `--a2v-heading-weight`、`--a2v-heading-track`、
`--a2v-heading-color` 三个角色令牌一起换掉（字重 700、字距 `-0.03em` 收紧、取最亮的
`--a2v-text-1`）。四幕的标题是 7–10 个汉字，76px 下最宽约 760px，
仍在 888px 的安全区内；更长的标题由引擎按实测宽度自动往下取档，不需要另设规则。

改完之后同一帧里是三级：**标题 76px / 内容 44px / 注 28px**。

#### 第 3 轮留下的另一半：角标本身也不是文案

上面把 `title` 当标题排好了，但那一节里已经写明——"页面上方的英文眉标
（`COMPARISON`）才是角标"。第 3 轮只修了标题的那一半，**角标这一半留到了第 8 轮**。

角标原先在 `declarative.js` 里是一行：

```js
kind.textContent = scene.type || '';
```

于是画面左上角显示的是分镜的**内部类型标识符**：`TITLE`、`LIST`、`TIMELINE`、
`NUMBER`、`CONCLUSION`。这不是"文案不够好"，是**根本没有文案**——
那是 schema 字段名，读者不需要知道"这是一条时间线"；而且它是英文，
整屏其余部分都是中文。

现在角标只能来自作者写的 `visual.kicker`（一个词、最多 8 个字、单行），
**没写就留空，不回落到 `type`**。示例分镜的八幕因此各写了一个定位词：

| 幕 | 类型 | 角标 | 该幕的标题 / 正文 |
| --- | --- | --- | --- |
| `opening` | title | 问题 | 选项越多 决定越慢 |
| `compare` | comparison | 比较 | 多出来的那部分是什么 |
| `cost` | quote | 代价 | 选择消耗的 是做决定的力气 |
| `attention` | list | 注意力 | 注意力去了哪里 |
| `loop` | diagram | 循环 | 推迟的决定没有消失 |
| `freedom` | timeline | 自由 | 自由不是拥有全部 |
| `one` | number | 取舍 | 需要保留的选项（示意） |
| `closing` | conclusion | 答案 | 缺的不是更好的选项 而是一把砍掉选项的刀 |

角标是**话题名词**，不是格式名词，也不是标题的前几个字：`TITLE` 说的是
"这一屏是标题卡"，`问题` 说的是"这一段谈的是问题"。前者是制作者关心的事，
后者才是读者用得上的定位。

留空而不是删掉整个 `span`，是因为角标这一行是 `justify-content: space-between`——
少一个子元素会把幕号从右边甩到左边，那是版式变化，不是"少了一个角标"。

角标只在启用预设时挂载（`declarative.js` 的 `if (preset)`），
所以这一处修复**动不到未声明预设的既有作品**。

两类元素**故意不声明**：

- `44px` 的 `.title-sub-line` / `.vs-text` 用的是 `--a2v-ink-value`，
  它不是字阶里的一档；
- `.closing-text` 是逐字揭示结构（每个字一个 `<span class="reveal-char">`），
  重排会让字与节点错位，因此不取档。

**行高、字距、字重归组件，字号归字阶。** 档位声明只落成 `font-size`：
`.quote-text` 的 1.55 行高是引文的呼吸，`.vs-note` 另有 0.06em 的字距。
把这些一并换成字阶默认值，等于在声明档位的同时把组件的排版设计
静默换掉——那只是把「一个属性两处真源」从字号搬到行距上。
幕标题是这条规则**刻意的例外**：它的字距与颜色确实换了，
因为原来那套（眉标字距 + 最暗色）本身就是错的角色，不是"组件的设计值"。

**它是可选增强，不属于渲染契约。** `window.__A2V__`（见
[渲染契约](render-contract.md)）不包含它；未启用预设的页面根本不调用
`autofit`。降级路径是明确的：字体未加载或测量不可用时，
`fit()` 返回按字数与经验系数估算的结果并置 `measured: false`，
画面仍然成立，只是不再「实测后再取档」。

## 四、观感闸门 K1–K9

K 系列与 C 系列（「不是废片」，见[设计宪法](design-constitution.md)）**分开计分**。
理由：C 系列答的是「这段片子能不能看」，K 系列答的是「它好不好看」，
把两种结论混成一个分数，就再也看不出问题出在哪一层。

K 系列内部还有一层区分：**K7 是硬判定，其余是提醒。** 文字被裁掉或压出安全区
属于画面坏了，与 C 系列同类；留白少了、强调色淡了都是主观判断，只提示、不拦人。

| 闸门 | 判定 | 阈值 | 语义 |
| --- | --- | --- | --- |
| K1 留白预算 | 背景色像素占比 | 默认 ≥ 40%；主体幕（`title` / `quote` / `conclusion`）≥ 60% | 留白是高级感的第一来源；同时要求可读墨迹 ≥ 0.4%，防止「把标题调暗到看不见」也算通过 |
| K2 强调色占比 | 强调色**族**的像素占比：色度 ≥ 50 且色相在强调色 ±30° 内 | 区间 [0.002, 0.15] | **不对称**：>0.25 判失败（滥用），偏低只判提醒（稀缺） |
| K3 同帧字号种类 | ≥44px 的层级字号去重计数 | ≤ 4 种 | 层级靠字号拉开，不靠加粗；角标与装饰字形不计入 |
| K4 对齐基线 | 对齐线条数：居中块算一条，左对齐按左边缘 12px 容差聚类，**互为镜像的两条线并成一条** | ≤ 2 条通过 / 3 条提醒 / ≥4 条失败 | 正文级文本块不足两个时**跳过**并写明原因 |
| K5 正文对比度 | 文本样张前景对背景的 WCAG 比值 | **<44px 用 7:1，≥44px 用 4.5:1** | 渐变裁切文字与透明文字跳过；背景透明时回退到 `--a2v-bg-0` |
| K6 卡片与描边纪律 | 卡片在圆角/描边/投影/内描边中具备几项 | ≥ 3 项 | 一幕里 ≥2 张「平卡」（只有 1 项）判失败；采集范围是**整幕里所有被画出来的 HTML 表面**（不是挂载点的直接子元素），最外层优先避免嵌套徽标重复计；**SVG 里的圆角图形是图解对象，不算卡片**；整幕没有可识别的 HTML 卡片表面时**跳过**并写明原因 |
| K7 文字溢出（**硬判定**） | 文本块墨迹边界对 `.a2v-safe` 的越界量，或引擎的 `fits: false` | 四边越界 ≤ 8px | 越界即 `fail`，并报出**是哪个文本块、往哪个方向、越了多少像素**；同时并入体检的错误数与退出码 |
| K8 容器内溢出（**硬判定**） | 组件用 `data-a2v-inside="<容器选择器>"` 声明文字装在哪个形状里；探针按 `getBBox()` 取 SVG 用户坐标下的文字盒与容器盒，圆形按「矩形内接于圆」判四周（`max(角点到圆心的距离) - r`），矩形按四边判 | 越界 ≤ 2px | 越界即 `fail`，报出文字内容、容器、越界方向与像素值；未声明容器的幕**跳过并写明原因** |
| K9 图形描边一致性（提醒） | 同帧所有带描边的 SVG 元素的计算线宽去重 | 取值在描边阶上且档数 ≤ 3 | 提示实测线宽列表；不在阶上或档数过多都算「图形语言不成体系」，只提示、不改退出码 |

几条设计取舍值得写下来，它们都是被真实误报逼出来的：

- **K2 为什么不对称。** 一屏只用一个强调色时，它在像素上天然只占千分之几。
  早期版本把「占比低」也判失败，结果每一幕都失败——闸门在惩罚正确的做法。
  滥用却是真问题，所以只对超量设失败线。
- **K2 为什么改成量「强调色族」。** 原判据是「与纯强调色逐通道相差 ≤ 46」的色盒。
  设计系统自己登记了四个强调色成员，色盒只看得见最亮的那一个，实测距离：

  | 成员 | 合成的 RGB | 与纯色的通道最大差 | 色度 |
  | --- | --- | --- | --- |
  | 纯 `--a2v-accent` | (50,214,255) | 0 | 205 |
  | `--a2v-accent-deep`（文档写的是「图形着重色」） | (47,127,168) | 87 | 121 |
  | `--a2v-accent-line`（alpha 0.55） | (32,122,146) | 102 | 114 |
  | `--a2v-accent-soft-solid`（焦点面填充） | (22,70,95) | 160 | 73 |

  于是「用强调色着重色画的焦点」在闸门里等于不存在——`compare` 一幕的焦点
  正是 `--a2v-accent-deep`。逐通道色盒本来也不是感知量：它同时排斥变暗与变亮的同色。
  换成**色度 + 色相**之后，四位成员全部纳入（色度 73–205），
  而背景与中性面被排除（色度 4–32）：

  | 需要排除的 | RGB | 色度 |
  | --- | --- | --- |
  | 背景梯度 | (11,12,15) | 4 |
  | 中性表面 `--fig-surface` | (23,30,43) | 20 |
  | `--a2v-accent-soft`（alpha 0.14） | (15,39,47) | 32 |

  色度下限取 **50**，把这条线画在 32 与 73 之间。
  之所以也排除 `--a2v-accent-soft`：14% 透明度的染色只是**暗示**，
  在近黑底上合成出 (15,39,47)，读者不会把它读成"这里有一个焦点"；
  焦点要有可辨识的色块。
  **阈值一个数字都没动**（下限仍是 0.002）：这不是把闸门调松，是把量错的量对。
  改完 24 帧里报警的从 17 帧降到 5 帧，而剩下 5 帧是真实的
  「焦点出现太晚 / 焦点太小」（见 K2 之后的说明）。
- **K2 余下的 5 帧为什么是真实缺陷。** 24 帧抽检里只剩 5 帧报警，
  它们各自对应一个仍然存在、且**不是闸门问题**的缺陷：

  | 帧 | 占比 | 真实原因 |
  | --- | --- | --- |
  | `opening` 96% | 0.0009 | 强调词按设计褪色（「恐惧退场，动作上场」），焦点转移到 `--a2v-accent-deep` 的角标文字上，但那里只有字形笔画，没成面 |
  | `compare` 35% | 0.0017 | 焦点面在入场末段才淡入，前三分之一帧没有焦点 |
  | `loop` 35% | 0.0015 | 同上；飞轮四个节点全是 `rest`，没有 `focus` |
  | `freedom` 35% | 0.0011 | 同上（阶梯的 `is-focus` 还没迁到状态基元） |
  | `one` 全部三帧 | 0.0018 | 焦点是 140px 的强调色大数字——**面积是弱代理**：字形笔画只占整帧的 0.18%，视觉上却无可争议是焦点 |

  前四项要改的是**时序**（焦点应当早出现、且不要消失），第五项要判断
  「面积」对排版型焦点是否是正确的代理量。两者都不该用调阈值来掩盖。
- **焦点要跟着行进走，而不是在结尾才成立。** 第五轮把上表的四个"太晚"缺陷
  一路查到同一个根因：「哪一块是焦点」的判断散在每个组件自己的写法里，
  而且判据普遍**末尾才成立**——阶梯是 `index === 最后一根 && p > 0.95`
  （时间轴 `[0.07, 0.24, 0.48, 0.73]`，所以前 73% 的帧整屏没有焦点），
  飞轮干脆没有（四个节点永远 `rest`），天平是一个 66% 才起步的 `glow`。
  三处都**已经算出"当前是哪一个"**，只是没接到视觉状态上：
  阶梯把口播进度只用在了说明文字，飞轮把"到达了哪个节点"只用在了脉冲。
  接上去之后 `freedom` 从 0.0011 涨到 0.0167、`loop` 从 0.0004 涨到 0.0205，
  而一个画面仍然只有一个焦点。
- **K4 为什么数「对齐线」而不是量散的幅度。** 居中和「居中 + 左对齐混排」
  都是合法构图，用左边缘离散度衡量会把合法构图判成失败。数线条数才对应
  「观众眼里有几条参考线」。
- **K5 为什么两档阈值。** 正文（<44px）要 7:1，大字（≥44px）4.5:1——
  这是 WCAG 对「大字」的定义，也是为什么字号阶本身就在替对比度省力：
  同样一句话放大到 lead 档，可接受的下限就降了一档。
- **K5 为什么跳过渐变文字。** 用 `background-clip: text` 画的标题，计算样式里的
  `color` 是透明的，直接量会得到一个毫无意义的比值。跳过它并让 K1 的可读墨迹
  条件兜住「渐变太暗」这种情况。
- **跳过不是通过。** 每条 skip 都会写明原因并计入「跳过」计数，
  在终端汇总里单独一行列出。把 skip 混进 pass 是这套闸门最容易犯的错。
- **纵向节奏只有一个真源：安全区的 `gap`。** 第六轮量了块与块之间的**实际间距**，
  发现阶上只有 `--a2v-space-6`（48px）一档被用到，画面上却有
  **29 / 32 / 48 / 80 / 88 / 147px 六个值**。多出来的全是块自己叠的：
  `.vs-board` 的 `margin-top: 96px`、`.vs-note` 的 32px、
  `.fig-number-caption` 吃到的 `<p>` 浏览器默认外边距（40px）、`.closing-action` 的 8px。
  同一份设计里出现六个节奏值，读者读到的不是"这里有分组"，是"没对齐"——
  所以改成语义层一条规则收口（`… .a2v-safe > * { margin: 0 }`），
  **分组交给字号与颜色表达**（28px 的暗注 vs 76px 的标题已经说清从属关系），不交给间距。
  顺带查清六条幕级 `gap` 覆写里有四条是死规则：它们按 `data-scene-id` 寻址，
  而那些 id 不在当前分镜里——按场景 id 寻址的间距**不可移植**。
- **K4 为什么要合并镜像的两条线。** 这一条是被自己的改动逼出来的：  幕标题从 40px 升到 76px 后跨过了 K4 的采样门槛（≥ 44px），
  `compare` 一幕从「通过」变成「提醒」——多出来的那条线是幕标题，
  而另外两条是两张卡片各自把标签对齐到**本栏**左边界（左 267 / 左 637）。
  实测两块的中心是 355 与 725，相加 1080 = 2 × 540（画面中心），
  也就是说这是标准的两栏镜像构图，并非排布散乱。
  判据因此补了一条：**两条左对齐线上的块中心之和与画面中心的两倍相差 ≤ 12px，
  就视为一对镜像对称栏，并成一条线**，并在明细里写成
  「镜像对称（左 267 / 左 637）」——不写清楚的话，人只会看到两个不同的左边界，
  以为那是一处要修的错。
  这条规则**不会把闸门调松**：真的散乱排布（如左 100 / 350 / 700）不成镜像对，
  照样判提醒；容差 12px 也有反向测试守住（差 25px 的两条线必须不并）。
- **K4 的采样门槛会随排版改动而变。** 门槛是「字号 ≥ 44px」，
  所以把某个元素放大到 44px 以上会让它**新进入**这条闸门的采样，
  闸门结论随之变化——这不是回归，是采样范围变了。
  看到 K4 突然多一条线时，先确认新进来的块是不是本来就该参与判定。
- **K7 为什么是硬判定、而且必须影响退出码。** 它一开始只打印一行「失败」，
  而顶层结论照旧写着「0 个错误：体检通过」——流水线只看退出码，看不到那行字，
  硬判定就被降级成了建议。现在 K7 的失败会并入错误数（`cli._apply_hard_gates`），
  退出码随之非零。终端摘要里的 `[error]` 行与 `report.json` 的 `errors` 都能看到
  越界方向与像素值。
- **K7 为什么按「文本块」归并。** 一段话会被拆成多个文本节点（强调词、逐字揭示），
  逐节点判定会把同一个问题报成三条，其中一条还叫「key」。现在向上找到第一个
  非行内容器（`.key` / `.key-underline` / `.plain` 视作行内），按块取各方向最大越界量。
- **K7 为什么留 8px 容差。** 入场动画会把文字整体位移，字幕级元素还有亚像素舍入，
  一有越界就报错会天天误报；而 8px 在 1080 宽的画面里已经能看出来了，再多就不是舍入。

### 结果结构

`scripts/a2v/keynote.py` 提供 `Gate` 与 `KeynoteResult`：

- 状态取值 `pass / warn / fail / skipped`，严重度 `0 / 1 / 2 / 3`；
- `KeynoteResult.render(scene_id, frame, gates)` 按**闸门 × 场景聚合**，
  同一闸门同一场景只保留最差状态并记录采样帧号；
- 没有聚合之前，24 个采样帧会输出 72 条结论，一半是同一件事的重复，
  终端里根本看不出该改哪里；
- CLI 只打印**非 pass** 的聚合行。全 pass 时不占用版面。

## 五、静默失效清单

这一节记录的都是「不报错、校验通过、渲染通过、成片变了」的缺陷。
它们的共同点是只能在画面上看出来，因此必须靠测试或闸门兜住。

1. **设计语言层泄漏到未启用预设的页面。**
   `@font-face` 是全局注册的（浏览器没有作用域化的字体定义），`:root` 也是全局的。
   曾经有两处漏掉作用域：字体栈写在裸 `:root` 上，使未启用预设的既有视频整体换字体；
   深色主题块写成 `:root, :root[data-a2v-preset="keynote"]…`，把浅色主题的页面整片刷黑。
   修复后 `examples/declarative-number` 限帧 12 帧的成片与改动前**逐字节一致**。
   这个回归要连**命令一起记**，否则照着记下来的哈希复现不出来：

   ```bash
   uv run python .agents/skills/article2video/scripts/render.py \
     --storyboard examples/declarative-number/storyboard.json \
     --limit-frames 12 --capture-format png
   # → SHA256 A0A94CFC…（67185 字节）

   uv run python .agents/skills/article2video/scripts/render.py \
     --storyboard examples/declarative-number/storyboard.json --limit-frames 12
   # → SHA256 CBEBD8BF…（58802 字节）
   ```

   两者都对但互不相等，因为截图格式会进入编码结果；默认口径（JPEG q98）才是
   流水线实际走的那条。**取值以本节为准**：动效升级那一轮把画面里每个入场元素的
   位置都改了，哈希被刻意重新记录过一次（原值 `DAFDD423…` / `DF1DB75D…` 已作废，
   记录见 [项目规划](../../../../docs/PROJECT_PLAN.md)）；
   哈希是**机器与工具链相关**的，换 ffmpeg 或浏览器版本就会变，
   因此它证明的是「本机同一条命令前后一致」，不是「任何机器上都等于这个值」。
   现在由
   `tests/test_keynote_assets.py::TestPresetScoping` 守住：
   裸 `:root` 只允许放默认主题的三个兜底令牌，主题块不得与裸 `:root` 并列。
2. **组件里写死颜色。** 不跟主题走，换预设后会原地留一抹旧主题的颜色。
   组件只在必须写 SVG 表现属性（子元素写 `style` 会连入场变换一起盖掉）的位置
   使用 `color-mix()` 引用令牌，其余一律由样式表决定。
3. **组件写行内 `color`。** 行内样式优先级高于任何样式表规则，等于让设计语言层
   永远覆盖不了那一个元素。现在组件改成写自定义属性
   （`--a2v-emphasis-mix` 报告「强调词褪到哪一档」），由样式表翻译成颜色。
4. **缺一个 `--fig-*` 令牌。** 浏览器会安静地画出透明图形。
   由 `TestFigureTokenCoverage` 检查 `figures.css` 引用的每一个令牌
   在两套主题里都有定义。
5. **字号不在阶上。** 组件自带的 240px 会绕过 K3。预设生效时把它收到 hero 档。
6. **强调词褪色后读不出来。** 开场幕的强调词会从强调色褪到 `--a2v-emphasis-fade`；
   这个落点必须自己就满足 4.5:1，否则「褪色」等于「消失」。由测试守住。
7. **排版引擎全绿但空转。** `autofit()` 每帧扫描 `[data-a2v-fit]`，而组件里
   一次都没出现过这个属性：单测全过、校验通过、成片里的字号却仍然全是写死的。
   「引擎存在」与「引擎被用上」是两件事，所以由
   `tests/test_typesetting_wiring.py` 在真实页面上断言「声明过的元素真的取到了档」。
8. **取档抹掉强调标记。** `applyFit()` 为了让均衡断行生效而直接写
   `el.textContent`，把 `<span class="key">` 连同强调色一起删掉——实测 `.key`
   数量从 1 变成 0。强调色是「单一焦点」的载体，静默消失等于画面失去焦点。
   现在按代码点映射回原文本节点，且**改动字符即拒绝**；结构不安全时只取字号。
9. **引擎与 CSS 双真源。** 同一个元素，组件 CSS 给 60px、引擎给 40px，
   接上就会让整支片的字号系统性地变小。现在
   `tests/test_typesetting_wiring.py` 断言「取到的档位 == 声明的档位」
   且「实测字号 == `--a2v-size-*`」。
10. **可用宽度量的是自己。** 收缩适应的元素（居中弹性列里的 `.quote-text`），
    它的 `clientWidth` 就等于自己那行文字——拿它当上限再除自己的宽度，
    永远除得尽，结论恒为「放得下」，而且不报错。现在显式传容器 `.a2v-safe`。
11. **溢出没有人管。** C1–C6 是源码静态检查，K1–K6 覆盖留白/强调色/字号/对齐/
    对比度/卡片，没有任何一项检测「文字是否越出安全区」。现在由 K7 兜住，
    且它是硬判定。
12. **图形没人量，写死的颜色也没人管。** 三件事叠起来让图形可以安静地消失：
    `TestFigureTokenCoverage` 只查令牌**有定义**；K5 的对比度只量 DOM 里的
    **文本样张**，SVG 的 `fill`/`stroke` 不在量程内；K1 奖励留白——
    图形越淡，背景占比越高，**越容易通过**。实测下来深色 `--fig-line-soft`
    只有 1.63:1、浅色主描边只有 3.31:1、浅色水体描边 1.89:1，而所有检查全绿。
    更隐蔽的是 `.load-hollow` 与 `.drop-track`/`.drop-fill` 里那几个
    **写死的浅色页取值**：深色预设下它们与底色同色，「看着很大其实没有重量」
    的空壳只剩虚线，一幕「差量」只剩虚线框，看着像没画完。
    现在由 `tests/test_figure_contrast.py` 按分类表断言对比度预算，
    并禁止 `fill`/`stroke`/`background` 里出现字面色值。

13. **图形里的文字谁也不管。** `inspect.py` 采集文本时显式排除 SVG 宿主文本
    （`ownerSVGElement` 或 `tagName === 'svg'`），理由是 `getComputedStyle` 对 SVG 文本
    会返回祖先字号，量出来没有意义。这个理由对 K3 / K4 / K5 成立，
    但连带把容器判定也一并关掉了：K7 唯一的参照是 `.a2v-safe`，
    而图形内部的文字（飞轮节点、双向选择节点、冰山标注、天平载物、阶梯柱顶注）
    画在各自的几何位置上——**既不受安全区判定，也不受容器判定**。

    于是「文字比圆还宽 31px」这种一眼可见的缺陷能在全绿的体检里活着：
    飞轮节点半径 76px、标签 44px、四个汉字约 183px，K7 却报「都在安全区内」。
    现在由 K8 补上：只检查**组件显式声明过容器**的文字
    （`data-a2v-inside` 指向容器选择器），因为「这段文字是不是装在某个形状里」
    无法由几何自动判断——阶梯的注写在柱子**上方**，同样是近邻，却一点不装在里面。
    反例证据：把内容驱动几何关掉（复现「先写死半径再塞字」），K8 立刻报出
    「「打开选项」穿出 .loop-node-disc（圆周）16.0px」等四条、错误数 1、退出码 1。

14. **规范写了、组件没执行、机检没覆盖。** 这是第 12、13 两条的共同形状，
    在组件层尤其严重：规范写着「组件的间距取自 8pt 阶」，实际 13 处 `gap`
    与 4 处 `padding` 一个都没走阶；`stroke-width` 18 处全是字面值。
    `TestFigureTokenCoverage` 只查令牌**有定义**、不查组件**有没有用**，
    于是「看起来成体系」和「真的成体系」之间没有任何检查。

    这一条已经补上：`figures.css` 的描边、字重、字距、圆角、间距、内边距
    全部走令牌（86 处引用，字面值清零），并由
    `tests/test_figure_token_closure.py::TestTokenClosure` 逐条守住——
    以后写一个裸数值会直接测试失败。但这个**形状**本身要一直警惕：
    它不报错、不影响出片，只是让画面在细节上不像一套东西。

15. **「跳过」被当成了严重程度。** 同一幕要抽三帧，结论按「最严重的一条」聚合，
    而 `_SEVERITY` 原先把 `skipped` 排在 `pass` **之上**。于是
    「入场帧还没出现、中后段量到了」的幕会被整幕降级成「无法判定」：
    `compare` 的两张卡片在入场帧量不到，整幕就报「没有可识别的卡片表面」，
    而画面上明明有卡片——**这个漏判同时来自采集范围太窄与聚合顺序不对**，
    两个原因叠在一起，让 K6 在参考作品上一条都没量到。

    现在 `skipped` 排在 `pass` 之下：它不是严重程度，是「这一帧没有可测的东西」。
    只有**所有**采样帧都跳过时才如实报跳过。判据由
    `tests/test_figure_token_closure.py::TestGateAggregation` 守住。

    要警惕的推论：任何「多帧聚合」的判定都有这个问题——
    聚合函数的语义必须是「这一组观测说明了什么」，
    而不是「把每一帧的结论按枚举顺序取最大值」。

### 静默失效：令牌合规，画面不合规

令牌级的对比度测试（`test_dark_ink_meets_wcag` 一类）只管**令牌本身**。
组件自己拼出来的颜色可以完全合规地违反它——第二十轮抓到一例：

天平图右侧那行文字是 `color-mix(in srgb, var(--a2v-accent-deep) N%, #4a4a4a)`，
那个 `#4a4a4a` 是**冻结端点**，不跟主题走。深色主题的墨色是浅的
（`rgba(255,255,255,0.72)`），混向一个深灰于是把未点亮的文字压到
**2.26:1**（40px 大字号门槛 3:1）。浅色主题反而碰巧没问题（它的墨色本来就深）。

修法不是新造令牌：`.load-text.is-ink` 本来就声明了 `fill: var(--a2v-text-2)`，
正确的主题墨色一直就在那里，**是行内样式把它盖掉了**。组件改成报告
`--a2v-token-glow`，落点写在预设作用域的 CSS 里，端点用该元素本来的
`--a2v-text-2`。改后深色未点亮 2.26 → **7.23:1**。

判据落在**组件填充色**上（`TestComponentContrast`，两套主题各量一次，
未点亮与点亮两态都要 ≥3:1），并配一条反向保险：两态的填充必须真的是两个颜色
——否则通道卡住时，"两个状态都合规"会让上一条静默通过。

未启用预设的那条路径实测也是 2.09:1，但**不修**：它的契约是"逐帧不变"。

### 静默失效之五：定义了、却没人用的图形几何令牌

`--fig-arrow-len: 34px` 与 `--fig-arrow-half: 16px` 定义在设计层里，
而 `placeArrow` 写的是 `'M0 0 L-34 -16 L-34 16 Z'`——**令牌正是从这段代码里
提出来、却没接回去**。这类"设计层给了档位、组件没接"的缺口，到第二十四轮已经
是第五次（阴影、帧驱动光晕、重点面墨色、动效时长、箭镞几何），所以这次除了接线，
还补了一条**窄口径判据**：`--fig-*` 图形几何令牌定义了就得有人用。

判据的第一版把刚接好的线又报成"没人用"——因为它只认 `var(--fig-x)` 这种 CSS
写法，而脚本里是用 `tokenPx(el, '--fig-x', 兜底)` 读的。**两种消费方式都要认**，
这一点写进了判据注释：判据自己有 bug 时，最先被它误伤的正是你刚做对的那一步。

接线本身是**取值等价**的：兜底值就是令牌原本的取值（34 / 16），所以未启用预设
时成片逐字节不变；设计层改档位时，画面不必改代码就跟着走。

### 从"逐令牌"升级到"可达性"：一条死链是怎么藏住的

第二十五轮把口径放大到**全部令牌**，并且换掉了判定方式。原先看的是"这个令牌
有没有被 `var()` 引用过"，而网格那一串能骗过它：

（这段公式现在只是**历史样例**：第 42 轮已经把整条链连同 `--a2v-grid-column`、
`--a2v-columns`、`--a2v-gutter` 一起删掉了，账本从 26 条降到 19 条。留住它是因为
它说明的是判定方式，不是当前令牌表。）

```
--a2v-grid-column  =  calc((var(--a2v-content-width) - (var(--a2v-grid-columns) - 1)
                            * var(--a2v-grid-gutter)) / var(--a2v-grid-columns))
```

链上每一环都被下一环"消费"了，可**整条链没有任何组件在用**——逐令牌看单跳，
等于看不见这条死链。改成从**真实属性值里的 `var()`** 出发，顺着定义图走一遍
（别名之间的引用不算根），一次就列出 26 个够不到的令牌，网格那一串在其中。

账本 `IDLE_TOKENS` 给每个令牌一个分类和一条理由：

| 分类 | 含义 | 例 |
| --- | --- | --- |
| `ladder` | 整套刻度的一档——刻度就该完整，外侧档暂时没画面用是正常的 | `--a2v-space-10`、`--a2v-radius-xl` |
| `legacy` | 旧名字的别名，留着不破坏手写页面 | `--a2v-line-body`、`--a2v-tracking-label-legacy` |
| `unwired` | 设计层先给了、组件还没接；要写清是"等着接"还是"时代遗留" | `--a2v-dur-*`、`--fig-connector-w` |

四条判据守着它：没有令牌能在账本外闲置；账本里每一条都必须是**真的**没人用
（接了线就得删条目，否则账本会退化成"曾经闲置"的历史清单）；名单不许增长；
每条都要有分类和写得清楚的理由——这一条当场就抓到五处偷懒写的"同上"。



## 六、动效：步数不够就不滚

动效曲线本身只有三条（`outQuint` 出场 / `inOutCubic` 双向 / `outCubic` 逐项门控），
弹性由 `A2V.motion` 的四个弹簧配方提供（响应与阻尼都按曲线实测核对）。
这一节记的是**另一类**问题：曲线再自然，只要被驱动的量本身是阶跃的，
画面上就是一次瞬跳。

### 数字滚动的最少步数

数字幕原先无条件做滚动：

```js
value.textContent = String(Math.round(raw * progress));
```

`value: 1` 于是也"滚"——而 1 只有一级，滚动退化成一次瞬跳。逐帧实测
（`one` 幕，180 帧，绝对起点 1500）：

| local 帧 | 数字 | 不透明度 |
| --- | --- | --- |
| 15 | `"0"` | 0.023 |
| 18 | `"0"` | 0.524 |
| 21 | `"0"` | **0.861** |
| 24 | `"1"` | 0.974 |

第 15–23 帧，350px 的强调色数字以最高 **0.86** 的不透明度显示 **"0"**，
第 24 帧跳成 "1"。这有两层问题：

1. **动效不自然**：最大的、最亮的元素上出现一次硬阶跃
2. **画面在断言错误的信息**：那一幕讲的正是一「只保留 1 个」，
   而它在近一秒里清楚地写着 0

修法是给滚动一条**门槛**：`ROLL_MIN = 10` 步。滚动时长约为幕长的 26%
（1.5–2s），10 步约合 5–7 步/秒，是"读得出在数数"的下限；不足 10 步就不滚，
直接显示最终值，位移与淡入交给弹簧入场——它本来就在做这件事，
不需要数字再"帮忙"。

`examples/declarative-number` 的 `value: 73`（74 步）仍然滚动，因此这条门槛
**在构造上就不会改变未声明预设的既有作品**（该示例正是那条兼容契约的载体，
哈希复验亦通过）。

守住它的是 `tests/test_motion_trajectory.py::TestNumberRoll`：
一条断言"不透明度 ≥ 0.5 时数字必须等于最终值"（在真浏览器里逐帧读
`.fig-number` 的 `textContent`），另一条用非预设示例断言"步数够时必须仍旧滚动"——
没有第二条，第一条就退化成了"禁止数字动效"。

### 还没做到的：焦点是二值的

同一类问题在另一处还没修。图形状态是**离散**的（`rest` / `focus` / `muted` / `done`），
而确定性契约禁止 CSS `transition`，所以状态切换必然是**一次瞬跳**。
实测 `loop` 幕：节点圆盘在相邻采样帧之间

```
填充 rgb(23,30,43) → rgb(22,70,95)
描边 rgba(255,255,255,0.52) → rgb(50,214,255)
```

——没有中间态。圆盘不小，所以每约 2.7 秒就有一次可见的"啪"。

这和 `compare` 曾经剩下的那条 K2 提醒是**同一个根**：设计系统里没有"连续焦点量"。
第十二轮把 `compare` 也解决了（见下面"基元原先只在 SVG 上落地"一节）——
那一幕缺的不是连续量，是**基元压根没有 HTML 形态**，所以只能用 1px 边框表达焦点。

### 焦点也可以是连续量：`--a2v-focus-mix`

修法**不是**加第五个状态——规格明确说连续量不该并进四态——而是给 `focus` 态
加一个**在状态之内**的连续通道：

| `--a2v-focus-mix` | 外观 |
| --- | --- |
| `1`（默认） | 完整焦点外观，与从前逐像素一致 |
| `0` | **等于 rest** |

于是"从 rest 换成 focus"不再是一次跳变：`focus` 的外观由
`color-mix(in srgb, <焦点色> calc(mix * 100%), <rest 色>)` 得到，
`mix = 0` 时就是 rest 色。默认 1 保证了别的组件（冰山标注、阶梯条、天平托盘）
逐像素不变。

**交接因此可以同时满足两条**：任何一帧 `data-a2v-state="focus"` 的元素只有一个，
而视觉上没有缝——

```
frac ∈ [0, 0.5)   旧节点是 focus，mix 从 1 降到 0（淡出）
frac ∈ [0.5, 1)   新节点是 focus，mix 从 0 升到 1（淡入）
```

换手正好发生在 `mix = 0` 的那一帧，两侧外观都等于 rest。实测换手帧上新焦点
元素的填充是 `color(srgb 0.0902 0.1176 0.1686)` = `rgb(23,30,43)`，
与 rest **逐位相同**；随后 mix 0.18 → 0.45 → 0.91 连续升上去。
`pulse`（到达时鼓一下）跟着同一权重，鼓包因此在到达时最大。

守住它的是 `tests/test_motion_trajectory.py::TestFocusHandover` 三项：
同帧焦点数 ≤ 1、焦点量逐帧变化不超过阈值（翻牌会一次跳掉整格）、
以及**拿到 `focus` 的那一帧 mix 必须接近 0**。

### 已修的缺陷：飞轮的两个节点画在同一处

做连续焦点时量几何，发现 `loopPoint` 被"小球走的环"和"节点摆在哪"**共用**，
而它每格固定转 120°——那是按一圈 3 个停位写死的（`SEGMENTS: 6` × 120° = 720°
= `LAPS: 2`）。但分镜给了 **4 个节点**，于是：

| 节点 | 圆盘矩形（1080×1920 页面坐标） |
| --- | --- |
| `打开选项`（index 0） | x=424 y=644 w=233 |
| `推到明天`（index 3） | x=432 y=653 w=215 |

两者中心都是 ≈(540, 760)——**中心距实测 0.0px**，屏幕上只看得到三个圆盘，
"打开选项"这一步在画面上被完全遮住；焦点走到 index 0 时，
被点亮的是那个位置最上面可见的标签，读者读到的是"推到明天"。
弧线也一样：每个节点一段弧（`index → index+1`），4 个节点配 120° 步长
会多画一段重叠弧。

**这不是动效问题，是构图与信息问题**——少了论证的一步。

修法：`loopPoint(travel, stops)` 的步长改成 `360 / stops`，而 `stops` 取**节点数**。
现在四个圆盘各占一角（上/右/下/左），环是四段 90° 弧闭合成的整圆。

配套地把格数从写死的 6 格改成 `停位数 × LAPS`。依据就在组件自己的注释里——
「两次完整循环之后条满」——而 `LAPS: 2` 在此之前是个**从未被用过的常量**，
所以 4 个节点配 6 格时小球转不满整圈、也回不到起点，
与"推迟的决定没有消失"这句论点正好相反。3 个节点时 `3 × 2 = 6`，
与原来的值一致，所以这条推导对既有场景是恒等的。

**预设门控**：`loopPoint` 是共享几何，而非预设的 `why-effort-fails` 也有 `loop` 幕，
所以未启用预设时仍用冻结的 3 个停位 / 6 格。实测两个版本的 `figures.js`
（1736 行 vs 1775 行）渲染 `why-effort-fails` 限帧成片**逐字节一致**。

守住它的是一条渲染期测试 `TestLoopGeometry`：读四个圆盘的中心，
任意两个中心距不得小于半个直径。把步长改回写死的 120° 时，
它报出 `('打开选项', '推到明天', 0.0)`。

### 已修的缺口：基元原先只在 SVG 上落地

`versus` 幕（两种反应并排）是 **HTML 盒子**：`.vs-side` 是 div，靠
`border` / `background` / `box-shadow` 成形。而表面基元当时只声明
`fill` / `stroke`——**HTML 根本没有对应的属性**，所以那个组件用不了状态语汇，
只能自己算一遍：

```css
.vs-side.is-right {
  border-color: rgba(var(--a2v-accent-rgb), calc(0.24 + 0.5 * var(--vs-heat, 0)));
  background: var(--a2v-surface-strong);   /* ← 永远不变 */
  box-shadow: …, 0 0 calc(46px * var(--vs-heat, 0)) rgba(…, calc(0.3 * var(--vs-heat, 0)));
}
```

于是"这一侧才是答案"这个焦点，只有一条 **1px、alpha 0.24** 的暖边框加一层光晕。
实测整幕的强调色占比 **0.0016**——门槛是 0.002。这和第四轮 `focus` 态查出的
问题同源：细描边缩到判据图上只剩 1px，抗锯齿一糊就量不到。

修法是给每个状态**同时声明两种媒介**：

| 媒介 | 属性 | 谁读 |
| --- | --- | --- |
| SVG | `fill` / `stroke` | `<rect>`、`<circle>`、`<path>` |
| HTML | `background-color` | `<div>` 一类盒子 |

各属性对另一种媒介无副作用（`background-color` 不影响 SVG 几何，
`fill` 不影响 div）。

两个细节：

- HTML 侧写 `background-color` 而**不是 `background` 简写**——简写会把
  `background-image` 一起重置，把组件自己的材质抹掉。`versus` 的材质是
  `--a2v-surface` / `--a2v-surface-strong` 那层白色光泽（`theme.css` 里
  它们是 gradient 而不是颜色），它与状态无关，应当留在组件里。
- 描边属于**边界框**基元，不在这里声明：`versus` 自己那套随 `--vs-heat`
  升温的边框因此保留下来，作为"箭头到达"的强调，与状态不冲突。
  基元选择器是三层（属性 + 类 + 属性），所以它盖得住组件写的
  `.vs-side { background: … }`，组件不必让步。

迁移后右侧是 `a2v-surface` + `data-a2v-state="focus"`（左侧是 `rest`），
底色由 `--a2v-focus-mix` 给出，材质仍然保留。实测：

```
左侧 rgb(23,30,43)                            ← --fig-surface
右侧 rgb(22,70,95)                            ← --a2v-accent-soft-solid，色度 73
compare K2  0.0016 / 0.0027 / 0.0027  →  0.0289 / 0.0292 / 0.0292
```

闸门因此首次达到 **53 条通过 / 0 条提醒 / 0 条失败**。

守住它的是两条测试：`test_every_state_declares_both_media`（每个状态都要有
两种媒介的写法，且不许用 `background` 简写）、以及那一批浏览器的渲染测试。

### 已修的层级倒置：`compare` 的载荷比问题还小

`versus` 的板面按内容收缩（flex 项的 `min-width: auto`），文字又固定在
`--a2v-ink-value` 的 46px 兜底值上，于是实测：

| | 修前 | 修后 |
| --- | --- | --- |
| 板面宽 | 596px（安全区 888px 的 67%） | **888px（100%）** |
| 每栏 | 226×268 | **372×300，等宽** |
| 选项文字 | 44px | **60px** |
| 幕标题 | 76px | 76px |
| K3 字号层级 | `[44, 76]` | `[60, 76]` |
| K1 留白 | 0.807 | **0.758** |

要害是**层级倒置**：这一幕的载荷（两种反应）比问题（幕标题）还小。
而且 44px 恰好压在 K4 的采样下限上，所以它连"独立字号层级"都算不上，
是正文那一档。

修法与第七轮同源——**提高字号上限本身不会溢出**，因为 autofit 会自己往下走；
配合让两栏均分安全区宽度（`min-width: 0` 才允许 flex 压过内容宽度）。
字号上限取 `lead`（60px）而不是 `title`（76px）：后者会让标题与载荷同尺寸，
K3 反而从 `[44, 76]` 变成 `[76]`——**层级变平**，实测过才发现。

这一条挂在预设上：`figures.css` 是全局的，而非预设的 `why-effort-fails`
也有一幕 `comparison`。

守住它的是 `TestVersusGeometry` 三项（真浏览器量板面与文字）：
板面占安全区宽度 ≥ 90%、两栏等宽（差 ≤ 2px）、选项文字 ≥ 60px 且声明了排版档位。
撤掉"板面占满宽度"那条规则时，它报
`板面只占安全区宽度的 82%（724/888）`。

### 已修的漂移：字号阶是唯一的字号真源

第十四轮逐个量了八幕里每一个文字节点的字号，抓到两处不在阶上的值。
字号阶是 350 / 220 / 140 / 120 / 96 / 76 / 60 / 40 / 34 / 28。

**(1) 结论句自己算字号。** exchange 组件的私有 `fitFontSize()` 是
`clamp(floor(888 / 最长行字数), 54, 96)`。这是**有意的**取舍——注释写着
"测量既拖慢逐帧渲染，也会把布局抖动带进画面"，所以它不走 `typography.js`
那套实测自适应。但代价是返回任意整数：实测结论句 **88px**。

**(2) 闸门阈值倒灌进设计系统。** 设计语言层曾写着

```css
--a2v-ink-value: 44px; /* 与 K3 的统计下限对齐，不再另立一档 */
```

44px 是 **K3 的采样下限**——一个测量阈值，而阶上根本没有这一档。
`figures.css` 里还有两处直接写死 `font-size: 44px`。两处缺陷合起来，
八幕里有 **5 幕**踩着阶外字号。

后果不只是"不在阶上"：`closing` 一幕里节点标签 44px 与行动句 40px
**相差 4px 却不是一个值**——观感上看不出区别，只像失手。

修法：

| 位置 | 原值 | 现取值 |
| --- | --- | --- |
| 结论句（exchange） | `floor(888/字数)` → 实测 88 | 阶上由大到小取放得下的档位 → **76** |
| `--a2v-ink-value` | `44px` | `var(--a2v-size-body)` → **40** |
| `.title-sub-line` | `44px` | `var(--a2v-ink-value, 44px)` → 预设下 **40** |
| `.berg-callout-label` | `44px` | `var(--a2v-ink-value, 44px)` → 预设下 **40** |

结论句那一处**仍然不测量**（保持原取舍），只是把"任意整数"换成"阶上的档位"，
数字也不复制（读 `A2V.type.levels`）。两处写死的 44px 改用令牌兜底：
未启用预设时回落到 44px（那条路径逐帧不变），预设下取阶上的 40px。

八幕实测全部落在阶上：

```
opening [120,40,28]   compare [76,60,28]   cost [34,28]
attention [76,40,28]  loop [76,40,34,28]   freedom [76,40,34,28]
one [350,76,40,28]    closing [76,40,28]
```

### 为什么之前没抓到：测试自己抄了一份阶梯

`tests/test_keynote_layout.py` 里硬写着

```python
SCALE = {28.0, 34.0, 40.0, 44.0, 60.0, 76.0, 96.0, 120.0, 140.0}
```

**44 就在里面**，而真阶的 220 / 350 反而没写。于是"字号必须在阶上"这条
不变量恰好放过了 44px。**抄一份真源的代价，就是抄错的那一档刚好放过
对应的缺陷。** 现在改成从设计语言层正则读出 `--a2v-size-*`，阶变了测试跟着变。

另一半原因是覆盖面：合成样张只有四种版面、没有 `title` / `exchange`
这类组件，**量不到组件自己写死的字号**。新增的 `TestBaselineTypeScale`
打开真分镜逐幕采样，并加了一条"相邻两档至少差 10%"——差几个像素的两个字号
不构成层级。

反向验证：把 `--a2v-ink-value` 放回 44px，它报出 5 幕 9 个元素阶外
（opening 的 `title-sub-line`、attention 的 `berg-callout-label` ×2、
loop 的四个节点标签、closing 的 `ex-node-text` ×2）。

### 已修的缺陷：`a2v-label` 的焦点态是个空操作

状态语汇建好之后，`--a2v-label` 基元的焦点态写的是

```css
[data-a2v-preset="keynote"] .a2v-label                       { fill: var(--a2v-text-1); … }
[data-a2v-preset="keynote"] .a2v-label[data-a2v-state="focus"] { fill: var(--a2v-text-1); }
```

两处取值一模一样，所以组件把 `data-a2v-state="focus"` 挂上去，**画面毫无变化**。
这比"组件没迁过来"更隐蔽：检查项上它是绿的，规则也在，只是不做任何事。

线索来自组件那边：`.berg-callout-label.is-accent { fill: var(--a2v-accent) }`
——标签本就该在焦点时变成强调色。**修基元与迁组件是同一件事。**

焦点态改为 `fill: var(--a2v-accent)` 并补上 HTML 媒介的 `color`，然后
`.berg-callout-label` 迁到 `a2v-label` + `data-a2v-state`，删掉那条临场规则。
棘轮 `PENDING` 从 5 项缩到 4 项。

实测（同一幕、同一帧）：

```
未启用预设  rest rgba(244,247,251,0.96)   focus rgb(53,224,200)   ← 该主题的强调色
预设        rest rgba(255,255,255,0.96)   focus rgb(50,214,255)
```

一个需要留意的细节：删掉的那条规则是**全局**的，而基元只在预设作用域内定义，
所以组件里补了一条按**状态属性**（不是临场类名）写的规则，把未启用预设时的
表现原样接住。若不做这一步，非预设的 iceberg 作品会静默丢掉焦点标签的强调色——
仓库里两个非预设例子都没有 iceberg，逐字节回归**照样会通过**，那是运气不是保障。

### 三条阴性审计，与一条不成立的判据

同一轮按"先量再改"的办法审了另外三处，结论都是**干净**：

- **间距**：`figures.css` 走 `--a2v-space-*` 47 处、写死 15 处，而写死的全是
  光学微调（`-1px` 幽灵描边、`2px` 下划线、`-104px` 引号装饰），
  本来就不属于间距节奏；
- **文案**：全片全角标点 3 处、半角 0 处；无句末句号；中文数字 11 处、
  阿拉伯数字 0 处；行长都在组件预算内；
- **图标**：三套箭头确实不同族（实心三角 16×22 / 实心三角 34×32 / 开口 V 形），
  但 `arrow` 与 `chevron` 在图标体系里本就**语义不同**（流向 vs 状态转换），
  现有用法自洽，不凭猜改。

**K1 的留白上限：这个判据表达不了它想表达的东西。** 把 quote 幕的文案从
11 字缩到 **2 字**，留白值只从 0.748 动到 0.758。因为 `empty` 量的是
「与左上角像素颜色接近的占比」，而背景带网格与渐变，非角落像素天然超出容差，
**该指标被背景纹理卡在 ~0.85**（基线 24 帧全落在 0.710–0.850）。
给它加上限等于量一个够不到的数字，所以**不加**。
「留白合理」的上界若要做，得换一个能表达"空"的量（例如内容包围盒占安全区的比例）。

### 顺带补的护栏：脚本必须能解析

往 `figures.js` 的组件模板字符串里写注释时带了反引号，模板字符串被提前终结，
整个 `figures.js` 语法错误——**首页加载失败、所有图形消失**，体检直接报
`Cannot read properties of undefined (reading 'renderScene')`，
而纯静态的那批检查全都没拦住。

现在 `TestAssetSyntax` 用 `node --check` 逐个检查页面脚本。这类破坏不需要
浏览器，报错还精确到行列。把那个反引号放回去时它报
`SyntaxError: Unexpected identifier`。

**帧驱动的光晕也有令牌。** 投影是 `--a2v-shadow-1/2/3`，焦点光环是
`--a2v-focus-halo`；强调词的"重点光"与对侧卡片的热光晕现在分别是
`--a2v-glow-emphasis-blur/alpha` 与 `--a2v-glow-heat-blur/alpha`
（两套主题各一份，先取同值）。组件**不写行内 `text-shadow`**：
行内优先级最高，会把设计层那一层整个盖掉——它只报告"亮到哪一档"
（`--a2v-emphasis-glow`，0 到 1），模糊与浓度由设计层给。
未启用预设时组件仍走原来的行内写法，因此既有视频逐帧不变。

### 重点面上的墨色：`--a2v-on-focus`

状态语汇把 `focus` 态的填充定为 `--a2v-accent-soft-solid`——一个被压暗的强调色。
这个面在**两套主题里都是深色**，而状态定义里原先**没说过压在这个面上该用什么
墨色**，于是每个组件各自发明，而且都选了强调色：深蓝面上写蓝字。

第二十一轮实测（把文字真正坐着的那块面量出来）：

| 位置 | 深色 | 浅色 |
| --- | --- | --- |
| 天平·右盘文字（未点亮，面是重点面） | 4.73:1 ✓ | **1.07:1** ✗ |
| 天平·右盘文字（点亮） | **2.28:1** ✗ | **1.30:1** ✗ |
| 取舍·答案卡上的选项 | 5.88:1 ✓ | **2.01:1** ✗ |

截图确认：浅色主题下右盘是深蓝字压深蓝面；答案卡是实心宝蓝卡片上写蓝字，
而同一张画面里左边白卡上的深色字很清楚。

现在这个角色有名字了：`--a2v-on-focus`（深色 `rgba(255,255,255,0.96)`，
对 `#16465f` 是 9.2:1；浅色 `#ffffff`，对 `#0d3f7d` 是 10.6:1）。
压在重点面上的字一律用它。天平右盘的"亮起来"改成同一支浅色墨的**亮度渐变**
（alpha 0.69 → 0.96）——原来的"文字变强调色"在重点面上必然撞色，
而亮度渐变既保住动作又始终可读。修后 16 行全部达标，最低 5.77:1。

判据：`TestComponentContrast` 以**表驱动**的方式量「文字落在组件自有的面上」
的每一处（天平左右盘、答案卡、冰山标注名与说明、阶梯刻度，8 行 ×2 套主题），
`ink` 按媒介取（SVG 读 `fill`、HTML 读 `color`），面由选择器显式给出——
不靠推断。任何一行选不中会自己报出来。

### 动效语汇的实测：两个单位、20 个取值、阶梯还没接上

第二十二轮把 `figures.js` 里 49 处 `api.progress` 调用的实参逐个解析出来
（括号配平，正则会被 `beat(state, x)` 的内层括号截断），得到：

- **时长参数有 20 个不同取值**，而且**混用两种单位**：一半是帧数
  （12 / 14 / 18 / 20 / 22 / 24 / 26 / 28 / 40），一半是场景占比
  （0.05 / 0.08 / 0.09 / 0.1 / 0.12 / 0.14 / 0.16 / 0.2 / 0.28 / 0.36）。
  同一个位置的数字，在有的调用里是"20 帧"、在另一些里是"整幕的 20%"——
  读代码的人看不出是哪种，而两者在长短幕里的实际差别很大。
- 缓动是三条常量（`EASE_OUT` 23 处、`EASE_SYMMETRIC` 19 处、`EASE_SOFT` 6 处）
  外加**1 处裸字符串 `'linear'`**。裸字符串已经改成同名的 `EASE_LINEAR` 常量
  （行为等价，冻结路径逐字节一致可证）。
- 时长阶梯 `--a2v-dur-fast/base/slow`（7 / 11 / 17 帧，也就是 240 / 360 / 560ms）
  **零运行时消费者**——动效时长是各组件手挑的。它与第 19 轮的阴影、第 21 轮的重点面
  墨色属于同一类"设计层给了档位、组件没接"，但**病因不同**，别照那两次的经验修：
  - 这里是**单位与语义都对不上**：阶梯用毫秒，引擎按帧；而且引擎的帧参数是按语义
    命名的（呼吸周期 120~150、归位 36、错落 2），7/11/17 在其中没有对应物
    （第 45 轮实测：帧值 7 全库 1 次、11 与 17 零次）
  - 更硬的一条：确定性契约禁止 CSS `animation`/`transition`，所以 CSS 时长令牌
    在帧驱动下**没有合法消费者**——不是"还没人接"，是这个机制被禁止
  - 它因此不是欠账而是**一份意图记录**：`tests/test_motion_vocabulary.py` 以
    `LADDER_TOKENS` 记着它，并期待"各组件手挑的时长"逐步减少

现在有两条判据守在这里（`tests/test_motion_vocabulary.py`）：缓动不许写裸字符串；
手挑时长的去重数量不得再涨（上限 20，是个上限不是目标）。把时长接回阶梯会
让这个数字降下来——那一步要改的是共享的动效路径，会同时动到未启用预设的
逐帧输出，所以必须与"冻结路径逐字节一致"的约束一起设计，不是顺手能做的。

## 七、状态语汇：四族基元

画面上承载状态的元素，各按角色归到四族基元之一，靠 `data-a2v-state` 取状态：

| 族 | 类名 | 供给什么 | 用在哪些元素 |
| --- | --- | --- | --- |
| 面 | `a2v-surface` | `fill` + `stroke` + HTML 的 `background-color` | 圆盘、柱子、令牌、卡片、标注框 |
| 文字层 | `a2v-label` | `fill`（SVG）/ `color`（HTML） | 组件标签、节点标签 |
| 连接件 | `a2v-connector` | 墨色通道 `--a2v-connector-ink` + 端点形状 | 连线、弧、箭头头 |
| 边界框 | `a2v-frame` | `stroke` + 线宽 | （暂无消费者） |

四态：`rest` / `focus` / `muted` / `done`。

**连接件只给墨色与端点形状，几何归组件。** 同族元素的形态差得很远：
虚线连线（3px + `dasharray`）、6px 的弧、圆盘的边界、纯填充的箭头头。
基础规则里原本写死 `stroke-width: var(--fig-connector-w, 4)`——没有消费者时
看不出问题，一旦有消费者就会把 3px / 5px 一起改成 4px。

**墨色为什么走通道变量。** 同族里既有 `fill: none` 的描边路径，也有只有 `fill`
的填充标记，而基元的选择器是三层（属性 + 类 + 属性）——只要它直接写 `fill`，
就会盖掉组件的 `fill: none`，一条弧线会变成一块实心。所以基元把颜色写进
`--a2v-connector-ink`，组件决定它落到 `stroke` 还是 `fill` 上：

```css
.berg-link  { fill: none; stroke: var(--a2v-connector-ink, var(--fig-line)); }
.ex-arrow   {            fill:   var(--a2v-connector-ink, var(--fig-line)); }
```

反过来，**填充标记要显式盖回基元的 `fill: none` 并关掉 `stroke`**：

```css
.fig-exchange .ex-arrow[data-a2v-state] { fill: var(--a2v-connector-ink, …); stroke: none; }
```

三层选择器（父级 + 元素 + 状态属性）才盖得住三层的基元；`stroke: none`
是因为基元的 `stroke` 会在三角外面描一圈 1px 的发丝边。

**未启用预设时的表现显式限定作用域**，不靠优先级碰运气：

```css
:root:not([data-a2v-preset="keynote"]) .ex-node-disc[data-a2v-state="focus"] { … }
```

两套规则并列时谁赢取决于文件顺序，这是最容易在重构里悄悄翻车的一类。

**一个概念只能有一个名字。** 第 16 轮曾给这一族新起名 `a2v-stroke`，
而 `a2v-connector` 早就存在（注释写着"连线、箭头、轨道、轴线"），
只是它当时**只有形状、没有状态规则**。重名的成因是**手抄的基元清单**：
`test_figure_token_closure.py` 里一份、新写的断言里又一份，两份还不一致
（后者漏了 `a2v-frame`），谁也没报错。现在基元清单从 `keynote.css` 推导。

**迁完之后：** 八幕用到的组件里，承载状态的角色全部走基元 + `data-a2v-state`，
"未迁移清单"归零并加了"不得再增长"的终点断言。

**基元没覆盖的：** 只有四态，而画面里还有"连续量"（`--a2v-focus-mix`、`--vs-heat`）
与"结构性类名"（`is-left` / `is-right`）。它们按设计**不该**塞进这四态——
四态表达不了连续量，硬塞会让状态失去语义。这条边界是刻意的。

### 文案：机器守机械规则，措辞归作者

第 26 轮量过一遍：3 份分镜、178 条字符串、8 条规则**零命中**——现有文案是干净的。
所以 `tests/test_storyboard_copy.py` 的价值在"防"不在"修"：重复标点、首尾空白、
连续空格、TODO 占位、中英标点混用、半角标点紧跟汉字、三点省略。
规则有意收窄——**只有含汉字**的字符串才查中文标点类问题，纯英文的配置值
（`"layout": "center"`）不判，判据不该对它看不懂的语种下判断。

措辞本身（这句话清不清楚、友不友好）机器判不了，也不该假装能判。
设计层能做的是保证**排版**不让文案吃亏：不截断、不溢出、行高字距成套、
强调不超过一个焦点。

### 状态的完整性：一张合成的 4×4 矩阵

第二十三轮先做了一次**状态普查**（基线八幕 × 8 帧采样），结果是：

| 基元 | rest | focus | muted | done |
| --- | --- | --- | --- | --- |
| `a2v-surface` | ×64 | ×40 | 未出现 | 未出现 |
| `a2v-label` | ×56 | ×24 | 未出现 | 未出现 |
| `a2v-connector` | ×40 | ×32 | 未出现 | 未出现 |
| `a2v-frame` | 未出现 | 未出现 | 未出现 | 未出现 |

也就是说：语汇**承诺**了 16 格，基线只走到 6 格，边界框那一族连元素都没出现过。
这本身不是缺陷——为了"用上状态"而给画面加状态是装饰，与"色彩克制"相抵。
缺陷在另一处：**承诺了却做不到**。所以判据不能只看基线用到没用到，
而是**合成 16 个元素**（四族 × 四态，SVG 与 HTML 各一份）插进真实页面，
量它们的计算样式。它一次就查出两件事：

1. **边界框四态全缺**——四族里唯独它一条状态规则都没有，`data-a2v-state`
   写在边界框上是个静默空操作。现已补齐，规则是**边界跟着面走**：
   rest 中性 / focus 强调（并抬一档线宽）/ muted 弱化 / done 收束。
2. **`a2v-label` 的 muted 在 HTML 侧是空操作**——它的两个媒介**静止墨色不在一档**
   （HTML 侧是 `--a2v-ink-3` 眉标，SVG 侧是 `--a2v-text-1` 图形内的字），
   而 muted 原先两个媒介都写 `--a2v-text-3`，于是 HTML 侧纹丝不动。
   现在 muted 是"在各自媒介的静止墨色上**再褪一档**"：SVG 到 ink-3，HTML 到 ink-4
   （那一档的注释写着"不进正文"，正合 muted）。

`done` 那一态取 `--fig-on-ink`，是给**压在 done 面**（填充 `--a2v-accent-deep`）
上的文字用的——这是配对契约，单独压在画布上会读不出来。第 21 轮的
`--a2v-on-focus` 是同一个道理的另一个落点。

两条判据（`TestPrimitiveStateMatrix`）：每一格都得画出东西（不许 `none` 或空）；
每一格的**两种媒介**都必须与各自的 rest 不同（只变一种，另一种媒介上的组件
就完全收不到这个状态）。

## 八、已知偏差：浅色底上光晕不承担焦点

这一条不是待办，是**测得到的性质**，写在这里以免下次重新追一遍。

### 9.1 现象

同一份分镜按两套主题渲染，`attention` 幕的强调色像素占比（K2 口径）：

| 幕内位置 | 深色 | 浅色 |
| --- | --- | --- |
| 早期帧 | 0.0096 | 0.0017（低于 0.002 提醒线） |
| 中段帧 | 0.0366 | 0.0296 |
| 后期帧 | 0.0034 | 0.0035 |

- 强调色像素的**包围盒两套主题完全一致**（x 5%~95% / y 14%~68%），差异**只集中在中央
  那格**（冰山图形）：早期帧浅色 749 vs 深色 4823
- 其余七幕两套主题差在 1% 上下——**只有 attention 幕掉出来**，因为它最依赖光晕，
  别的幕有实色兜底
- 浅色主题的 K1–K9 结果：**52 通过 / 1 提醒 / 0 失败**；深色 53 通过 / 0 失败。
  也就是说这是一条**提醒**，不是失败

### 9.2 机制

预设下一共有三支强调色光晕，**两套主题的模糊半径与透明度完全相同**，差的只是合成后的色：

| 机制 | 归属 | 参数 |
| --- | --- | --- |
| 重点词光晕 | `[data-a2v-preset="keynote"] .key` 的 `text-shadow` | 26px / 0.22 × `--a2v-emphasis-glow` |
| 升温光晕 | `figures.css:876` 一带 | 46px / 0.3 × `--vs-heat` |
| 焦点令牌混色 | `figures.css:199` | `--a2v-on-focus` × `--a2v-token-glow` |

同样的半透明强调色压在近白画布上，合成后的色度会掉到「强调色像素」的色度线（50）以下；
压在深色画布上则仍然是彩色。**光晕在浅底上天然不显色**，与参数无关——把 alpha 调高到
能在浅底上数出来（≥0.30）反而会在浅底上显得廉价。

（另有一支背景径向渐变在 `theme.css:128~129`，属**非预设层**的整片洗色，与本节无关。）

### 9.3 想关掉它的话

## 十、当前边界（收尾）

### 浅色底不能靠光晕凑强调色

`--a2v-glow-*` 的结构参数（模糊半径、alpha）两套主题完全一样，差在实际光晕色：
深色 `rgba(50,214,255,0.13)`，浅色 `rgba(10,106,217,0.07)`——**alpha 只有一半，
色相还更暗**。压在近白画布上合成完，色度只剩十几，够不到「强调色像素」的
色度线（50）；即便提到与深色同 alpha 也只有约 27，要到 0.3 才过线，
而那个浓度在浅底上会显得廉价。

所以浅底上的强调色质量要靠**实色标记**，不是辉光。深底用辉光、浅底用实色，
这也是通行做法。

### 采到的东西读不出来，等于没采到

`parse_color` 原来只认 `rgb()`/`rgba()`/`#hex`，而浏览器会把 `color-mix()` 的结果
序列化成 `color(srgb r g b)`。采集器把答案卡的底色**采回来了**，闸门却读不懂，
于是**静默退回画布**，量出 1.13 的假失败——假失败之所以能骗过三轮，就因为它和
"真的没有背景"长得一模一样。现在这条形式会被折成 `rgb()`。

教训：**采集范围修好了，不等于数据被读懂了**；解析失败必须留痕，不能静默降级。

### 浅色 ink-3 现在是正文档（第 33 轮改的）

浅色块原来写着 `--a2v-ink-3: #565c6e; /* 6.05:1 */`，低于正文线 7.0
（深色同档 7.79:1）。实测对纯白 6.66、压浅面板 5.89——**逐条样本**显示
`compare` 的 vs-note 与 `cost` 的 drop-cap 用的正是这一档（`rgb(86,92,110)`）。

第 33 轮把它提到 `#454b5b`：对纯白 **8.71:1**、对浅面板 **7.70:1**。

**第 29 轮曾判定"压暗这一档不是选项"**，理由是它得暗到对白 8.71，而 ink-2 是
8.94，"两档差 2%，层级就没了"。那把尺子用错了：人眼分辨的是**亮度**，
`#454b5b` 比 ink-2 高 32%，档差清楚可见——差的是比值看起来只差 1.43。
结论：**比值差不是档差的尺子**；判断层级要看亮度。

顺带一提：`.gauge-label` / `.drop-label` 那两条浅色补丁（改读 ink-2）现在成了
冗余，留着无害，属于可清理项。
