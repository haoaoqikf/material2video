# 金融时间序列视频专题

> **规范阶段，尚未实现。** 本文是待实现专题的制作参考，不是当前可执行入口。现有文章 Skill、v4 schema、校验器和正式渲染门禁保持不变；以下材料当前不渲染，不能直接交给现有脚本制作。

待实现行为以 [OpenSpec 专题规格](../../../../openspec/changes/add-financial-timeseries-video/specs/financial-timeseries-video/spec.md) 为准，架构选择见 [设计](../../../../openspec/changes/add-financial-timeseries-video/design.md)，未来路线见 [项目规划](../../../../docs/PROJECT_PLAN.md#金融时间序列视频专题规范阶段尚未实现)。

## 1. 目标与请求

用户给出“公司或指数 + 起止年份”，由 Codex 等 AI 编程工具自行搜索资料，制作横屏单标的折线图：日期推进、价格或点位逐步展开、重大事件到达时标注，全片无音轨。首期覆盖 A 股、港股、美股及对应指数。

请求示意：“展示某家公司 2010 年到 2024 年的股价变化，带重大事件，先不要声音。”这不是对真实公司的行情查询。

必填标的名称与起止年份；可补充证券代码、市场、视频时长。年份默认展开为完整自然年；标的必须唯一识别，记录名称、代码、市场、币种或点位单位、上市或指数起始日期。公司多地上市、指数名称歧义或年份倒置时先澄清，不自行猜测。

## 2. 数据搜索与核验

AI 在制作准备阶段搜索公开免费来源，不依赖账号或付费密钥；本专题不预设固定网站、行情 API 或内置模型服务。每次制作需核验来源实际可用性和数据定义，不能把搜索摘要或来源不明的图表截图当成完整日线序列。

1. 找到交易日日线收盘数据，核对标的代码、市场、单位、时间范围和日期所属市场。
2. 股票默认仅调整拆股、合股，不计分红再投资。以区间末端的股份单位为基准；来源符合该基准时可直接使用，否则需留存可核实的转换依据。指数使用来源明确的官方点位，标注价格指数或其他类型。
3. 区分原始收盘价、前复权、后复权、含分红调整收盘价和仅拆合股调整价。“Adjusted close”名称本身不足以证明口径。若自行推导，保存原始价格、拆合股比例、生效日期、基准日期和计算说明；不能把包含分红的因子混入。
4. 免费数据不能满足口径时，说明问题并请求选择替代口径；不可静默降级。更换数据源也要重查口径，不能拼接定义不同的序列。
5. 校验日期排序、重复冲突、有效数值与交易日覆盖。周末、节假日和已核实停牌不产生虚构报价；应有交易数据异常缺失时阻断数据验收，不补零、插值或用折线跨越掩盖。
6. 上市前、指数起始前、未来日期或来源覆盖不足，披露请求范围与实际范围；需要缩短时先获得用户确认。来源全部不可用时说明无法获取，不替换标的。

保存原始下载或响应、标准化价格序列和来源清单。来源至少记录链接、获取时间、覆盖范围、调整定义；推导数据还需记录依据。图内显示币种或点位单位、口径与来源摘要，详细链接留在作品材料中。渲染只读已固定的本地文件，不联网。

## 3. 事件自动筛选

AI 搜索并自动筛选，无需逐条请用户确认。优先公司公告、交易所披露、指数发布机构和政府资料，必要时采用可信媒体。每个事件包含实际日期、简短事实标题和来源链接；区分发生日、公告日、报道日，统一采用标的市场当地日历日期。

公司事件优先，指数相关事件与重大市场事件可补充。默认最多八个，按标的关联、重要性、来源可信度及时间覆盖筛选，合并同类重复事件；保留候选、入选和排除理由。没有可靠事件时允许零标注，并说明资料不足。

日期冲突无法解决的候选排除。不得根据曲线涨跌编造事实，不直接写“某事件导致股价上涨/下跌”；事实标记表示时间上的发生，不自动表示因果。事件必须落在确认后的展示范围内。

休市日事件使用真实日期，锚定横轴时间位置，不伪造对应价格，不挪到下一交易日。详细说明按时间依次展示，已经发生的时间轴标记保留。

## 4. 视觉与时间编排

- 1920×1080，30 fps，单标的、单持续场景。标题、折线、日期、当前价格或点位、事件标注和来源摘要构成画面。
- 横轴覆盖确认后的完整日历范围；纵轴基于完整有效价格序列预先确定并固定，避免播放中自动缩放造成误读。
- 揭示交易日有效点并连接相邻有效点，连线仅是视觉表达；不得显示插值形成的“历史报价”，也不得提前揭示未来点。
- 当前价格显示最近已揭示有效交易点的收盘价并标明其交易日期；休市时日历继续走，价格不伪装成当日报价。第一个有效点之前显示“尚无区间内报价”，不借用未来价格。
- AI 在分镜前决定总时长，不设置固定默认秒数。根据跨度、事件数量和可读性决定速度、停留与理由；用户给出时长但无法满足阅读要求时先说明冲突。
- 保存日期到视频帧的确定性映射。演变段日期单调向前，段与段之间连续，暂停段日期不变；不能把不同年份均分成视频片段却隐瞒变速。
- 开头交代标的、范围、口径；事件到达时出现标记和说明，说明在独立区域顺序展开，避免覆盖曲线或彼此重叠。结尾完整总览至少停留三秒，即九十帧。
- 不包含配音、音乐、音效或静音音轨；最终 MP4 必须完全没有音频流。

## 5. 作品材料建议

下面定义文档层最小材料，不是稳定程序接口；具体 schema、命令及 v4 接入方式由后续实现设计确定。这些文件**当前不渲染**，也不替代 `storyboard.json`。

| 材料 | 建议文件 | 最小信息 |
| --- | --- | --- |
| 需求记录 | `request.json` | 原始请求、唯一标的、请求/实际日期范围、口径及确认记录 |
| 价格序列 | `prices.json` | 日期、收盘数值；附带单位、调整基准、交易日覆盖核验与来源 |
| 事件清单 | `events.json` | 实际日期、事实标题、来源；附带候选及筛选理由 |
| 动画编排 | `animation-plan.json` | 总时长、fps、固定坐标范围、日期到帧映射、事件停留及编排理由 |

原始下载和完整来源记录作为附属材料；静音预演与验收记录放在作品产物目录。实际作品使用已有忽略目录 `videos/<slug>/`，或外部内容根中的作品目录；四类材料、真实行情、事件资料及媒体均不入库。方法与规范入库，不使用 `git add -f` 绕过忽略，不增删替换现有三个示例。

## 6. 制作与验收

目标流程：解析需求 → 确认标的 → 搜索与核验数据 → 搜索与筛选事件 → 保存数据和来源 → 编排时间轴 → 静音预演 → 数据与视觉验收 → 导出 MP4。

数据验收检查唯一标的、价格/指数口径、单位、日期排序、重复冲突、交易日覆盖、原始来源与推导依据；范围或替代口径有变动时核对用户确认记录。

事件验收逐条核实日期、标题和来源，检查重复、数量、筛选理由、休市日位置及因果措辞；事件稀少或为零时记录原因，不硬凑数量。

动态验收播放完整静音预演，并抽查开头、各变速边界、事件前/中/后及结尾。核对日期单调性、价格与交易日期、曲线揭示范围、固定坐标、说明可读性与重叠、事件持续标记及九十帧结尾。随机寻帧与重复渲染核对同帧一致；不得只看静态截图就认定节奏通过。

媒体验收检查 MP4 的分辨率、fps、时长和完整终帧，确认音频流数量为零。各项结论留在作品验收记录中；数据或视觉未通过时先修复，不正式导出。

专题将使用独立数据和无声验收，不套用文章字数、口播及有声评审。**此流程尚未实现，当前文章入口没有获得豁免，也没有可供执行的专题 CLI 命令。** 后续实施须补齐接口、校验器、无声门禁及渲染接入，再验证当前文章能力无回归。
