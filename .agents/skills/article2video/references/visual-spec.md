# 竖屏视觉规范

面向抖音类竖屏信息可视化短视频的排版、层级与动效约定。目标是「中文排版清晰、无溢出、
跨机器可复现」，并让画面具备稳定的高级感；配色与气质的具体取舍仍由每支视频自己决定。

规范分两层：

- **硬约束**：画布、安全区、字号下限、帧驱动，违反会直接导致裁切、模糊或闪烁；
- **配方**：层级、动效、风格方向，是可以直接照抄的数值，也是「高级感」的来源。

## 画布

| 项目 | 值 | 说明 |
| --- | --- | --- |
| 逻辑尺寸 | 1080 × 1920 | 9:16 竖屏，与分镜的 `width`/`height` 保持一致 |
| 帧率 | 30fps | 与分镜的 `fps` 保持一致 |
| 色彩 | sRGB | 不做 HDR |

画面按逻辑尺寸写死布局，**不要**用 `vw`/`vh`/百分比做响应式适配。
composition 以分镜声明的尺寸原样挂载，不存在预览缩放这一层。

## 安全区

平台 UI 会遮挡画面上下缘，正文必须留在安全区内。令牌在 `web/src/styles/tokens.css`
里定义，并提供 `.a2v-safe` 容器：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `--a2v-safe-top` | `220px` | 顶部留白（状态栏、账号信息） |
| `--a2v-safe-bottom` | `320px` | 底部留白（文案、进度条、按钮） |
| `--a2v-safe-x` | `96px` | 左右留白 |

可用区高度为 `1920 - 220 - 320 = 1380px`。排版超长时优先精简文案，
而不是压缩安全区。

## 字号下限

以 1080px 宽为基准，保证在手机小屏上仍可读：

| 用途 | 建议区间 |
| --- | --- |
| 开场主标题 | 110–150px |
| 金句正文 | 76–96px |
| 结论全文 | 88–110px |
| 节点 / 卡片标签 | 56–72px |
| 辅助说明、注释 | 30–38px |

低于 30px 的文字在竖屏上基本不可读，应改为口播或删除。

**下限由代码兜住，不靠自觉。** 启用设计语言预设时，声明了
`data-a2v-fit="<档位>"` 的文本元素由排版引擎按**实测可用宽度**在字号阶上取档，
到 36px 正文下限即停，不会再往下缩；缩到下限仍放不下时，引擎把
`data-a2v-fit-fits="false"` 写到元素上，观感闸门 K7 据此报「需要拆场景」。
也就是说「文案太长」不会再以「字变小了」的形式悄悄发生。
详见[发布会级设计语言](keynote-design-system.md)。

## 排版层级

字号只解决「看得清」，层级才决定「看起来贵」。同一画面里按下表分工，
不要靠加粗和变色堆重点：

| 角色 | 字号 | 字重 | 颜色令牌 | 说明 |
| --- | --- | --- | --- | --- |
| 主命题 | 110–150px | 700–800 | `--a2v-text-1` | 一幕只出现一句 |
| 正文 / 金句 | 76–98px | 500–600 | `--a2v-text-1` | 长句拆场景，不缩小字号 |
| 小节标题 | 44–56px | 500 | `--a2v-text-2` | 只做引导，不抢焦 |
| 标签 / 序号 | 28–34px | 400 | `--a2v-text-3` 或强调色 | 配 `letter-spacing: 0.22em` |
| 行动提示 | 34–40px | 500 | `--a2v-text-2` | 配左侧强调竖线 |

规则：

- **一个画面一个视觉焦点**：强调色只在焦点元素上出现；
- 标题用负字距（`-0.02em` 左右），标签用正字距（`0.2em` 以上），
  正文保持 0，字距是区分「标题感」和「正文感」最廉价的手段；
- 每个场景最多 3 行正文，每行不超过 14 个汉字，用分镜里的换行符手动断行，
  不要让浏览器自动折行决定重点词的位置；
- 关键短语用强调色 + 光晕标出，**不要**整句加粗或变色；
- 字号取自**模块化字号阶**：启用预设后，不在阶上的字号会绕过
  [K3 闸门](keynote-design-system.md)（同帧字号种类），层级也就无法被机检。
  八档取值与配对的行高、字距见[发布会级设计语言](keynote-design-system.md)。
  组件内部的文字同样受这条约束——`figures.css` 里的字号一律写成
  `var(--a2v-ink-*, 原值)`：预设生效时落到阶上，未启用预设时落回原值，
  两种情况都不会出现「页面上是阶上字号、组件里却是 30px」的漏网。

## 图形标注

「以形表意」的画面（天平、冰山、落差尺这类比喻）需要几个短标签才能读懂，
但它们不该写死在网页里，也不该塞进正文。分镜用 `annotations` 提供这些标签，
每个场景类型有一套约定键；网页按 `data.annotations["键"]` 取用，
取不到时留空而不是回退到默认文案：

| `type` | 约定键 | 用途 |
| --- | --- | --- |
| `title` | `leftPan`, `rightPan` | 天平两侧托盘上的名字 |
| `quote` | `assumption`, `fact`, `dropLabel`, `noDropLabel` | 落差尺：两栏标题与两把尺的标签 |
| `list` | `tip`, `mass`, `surface` | 冰山：水面之上、水面之下、水面线 |
| `diagram` | `gauge` | 反馈循环的进度表标签 |
| `timeline` | `axis`, `before`, `after` | 阶梯：纵轴名、翻转前后两种读法 |
| `conclusion` | `leftNode`, `rightNode` | 双向选择的两个端点 |
| `chart` | `unit`, `note` | 数值单位（拼在数值后面）与来源/补充说明 |

键的取值是**每篇文章自己的选择**，上表只是当前网页实现的键名。
新增画面时先在网页里定键名，再把同一组键写进分镜与本节表格。

## 视觉层级与景深

深色画面最容易显得「扁平、廉价」，按下面三层叠起来即可获得景深：

1. **背景层**（常驻，放在 `[data-a2v-stage]` 内、场景容器之外）：
   光晕 + 网格 + 细点阵，直接用 `theme.css` 的
   `.a2v-bg-glow` / `.a2v-bg-grid` / `.a2v-bg-grain`；
2. **表面层**（卡片、节点）：`--a2v-bg-1` 打底 + `--a2v-surface` 顶亮底暗渐变
   + 1px `--a2v-hairline` 边框 + `--a2v-inset-highlight` 内高光
   + `--a2v-shadow-2` 双层投影（近处小阴影定形，远处大阴影造景深）；
3. **焦点层**：只让一个元素同时拿到强调色边框、内发光与外发光
   （`rgba(var(--a2v-accent-rgb), a)` 拼接光晕，按帧改变 `a`）。

不要用 `filter: blur()` 做大面积模糊：它既拖慢逐帧截图，也无法被
「同帧一致」的验收覆盖。需要光晕就用 `radial-gradient` 或 `box-shadow`。

## 动效

- 只使用**由帧号推导**的 `transform`、`opacity`、颜色变化；
- 禁止 CSS `animation` / `transition`，原因见 [渲染契约](render-contract.md)；
  渲染入口会在开渲前静态扫描并提示这类写法；
- 单次入场动效建议 12–30 帧（30fps 下 0.4–1.0 秒）；
- 逐项呈现的间隔建议 4–10 帧，过快会看不清，过慢会拖节奏；
- 画面不要长时间完全静止：入场结束后用常驻微动（`breath`，振幅 3–5px、
  周期 120–150 帧）保持活性；配音会把场景拉长，后段静止在成片里像卡住。

共享运行时 `web/src/runtime/motion.ts` 提供的原语（全部是纯函数）：

```ts
progress(localFrame, startFrame, durationFrames, 'outCubic'); // 0..1
stagger(index, stepFrames, baseFrame);                        // 第 i 项的起始帧
since(localFrame, startFrame);                                // 距起点几秒（弹簧的输入）
spring(seconds, SPRINGS['firm']);                             // 物理弹簧（具名预设）
range(p, from, to, { clamp: true });                          // 进度映射为任意数值
breath(localFrame, { periodFrames: 120, amplitude: 4 });      // 常驻呼吸位移
drawPathStyle(p, length);                                     // SVG 描边动画的样式
revealCharOpacities(units, p, { frame, staggerFrames });      // 逐字揭示的不透明度
```

组件侧再包一层 DOM 绑定（`web/src/runtime/figures.tsx`）：`enterStyle` /
`enterSvgAttrs` 把入场配方换算成 React 的 `style` 与 SVG 属性串，
`svgTransform` / `svgOpacity` 输出 SVG 安全的字符串，`beat(fig, fraction)`
把幕内比例点换算成帧号。

**`spring` 收的是秒数（`since`），不是 0..1 的进度。**
弹簧本身就是曲线，喂给它一条已经缓动过的进度等于把两条曲线串起来，
它的自然周期（`response`）就失去了意义——这条错犯过：位移在 3 帧内走完，
而注释还写着「0.6 秒收敛」，观众看到的是一次带残影的硬切。
`spring` 的两个参数都是物理量：`response` 是自然周期（秒，只决定快慢），
`dampingFraction` 是阻尼比 ζ（只决定过冲，峰值 ≈ `e^(-πζ/√(1-ζ²))`）。
曲线由 wobble 1.5.1（MIT）的解析解给出，移植在 `web/src/runtime/spring.ts`。

缓动名可选：`linear`、`outCubic`、`inOutCubic`、`outQuint`、`outBack`。
时间只走三条曲线：出场用 `outQuint`、双向变化用 `inOutCubic`、
逐项门控用 `outCubic`；混用更多曲线会让画面显得杂。

### 动效配方层

上面那些是**原语**，配方层是**做法**：入场怎么组合、弹性多大、什么时候收敛、
常驻微动多快。它存在的唯一理由是——

> 这些数字决定整支片子的手感。写在六个组件里就没人能整体调，
> 新写的组件也会慢慢长成另一种手感。

所以数字只写在 `web/src/runtime/motion.ts`，组件用名字调用：

```ts
enterStyle(fig, sinceBeat(fig, 0.1), { distance: 24, amplitude: 3 }); // HTML 元素入场（返回 style）
enterSvgAttrs(fig, sinceBeat(fig, 0.1), { distance: 34, axis: 'x' }); // SVG 分组入场（返回属性串）
spring(seconds, SPRINGS['lively']);                                   // 具名弹性
idle(f, { amplitude: 2.4, phase: 50 });                               // 幕内常驻微动
beat(fig, 0.42);                                                      // 幕内比例点（自动按节奏缩放）
tempo('impact');                                                      // 节奏名 → 速度倍率
```

`seconds` 一律由 `since(localFrame, startFrame)` 得到。

两档入场配方，区别只在「移动多远、呼吸多快」，曲线完全相同：

| 配方 | 用于 | 默认位移 | 呼吸周期 | 呼吸振幅 |
| --- | --- | --- | --- | --- |
| `surface` | 卡片、文字块等画面表面 | 44px | 130 帧 | 3px |
| `figure` | SVG 图形本体 | 40px | 140 帧 | 2.5px |

两者共用同一条弹性（`response` 0.44 秒 / ζ 0.9）与同一个收敛点（幕内 24% 处起 36 帧
`inOutCubic` 把缩放钉回 1，同时让常驻微动渐入）。

具名弹性，避免在组件里写裸数字：

| 预设 | response | ζ | 过冲 | 收敛 | 感觉 |
| --- | --- | --- | --- | --- | --- |
| `enter` | 0.5s | 1 | 0 | ≈0.46s | 温和入场，一点不过冲 |
| `firm` | 0.44s | 0.9 | ≈0.2% | ≈0.31s | 图形主体到位（默认） |
| `lively` | 0.4s | 0.62 | ≈8.4% | ≈0.40s | 有分量的落点，回弹看得出来 |
| `snap` | 0.28s | 0.8 | ≈1.5% | ≈0.22s | 小元素快速归位 |

`response` 只决定快慢、`dampingFraction` 只决定过冲，两个参数互不干扰——
这正是换掉「阻尼 + 频率」那套凑出来的系数换来的好处：想更快只调 `response`，
想更弹只调 `dampingFraction`。

`motionRecipes()` 与 `motionSprings()` 返回当前取值的快照，
供文档与调试对照；`web/src/runtime/motionDoc.test.ts` 把本文档这两张表
逐值钉在 TS 常量上（改了常量或改了表都会失败）。
**改配方是可以的（那正是它存在的意义），但改完不能变成弹跳**：实测第一帧
位移不得超过全程的 25%、走到 90% 至少要 6 帧、过冲不超过 10%、末尾必须正好停在终点。

**节奏**由分镜的 `figure.motion` 决定（`calm` 0.82 / `normal` 1 / `impact` 1.24），
运行时从场景声明里读，组件不持有任何节奏状态。

### 动效时长参考

下面的帧数是 30fps 下的实测推荐值，可直接照抄，再按成片观感微调：

| 场景 | 配方 |
| --- | --- |
| 卡片 / 节点入场 | 位移 56–64px + 缩放 0.96→1，`spring(seconds, SPRINGS['firm'])`，20–24 帧窗口 |
| 文字聚焦入场 | 位移 24px + 透明度 0→1，22 帧 `outQuint` |
| 标签横线 / 强调竖线 | `scaleX` / `scaleY` 0→1，20 帧 `outQuint` |
| 关键短语点亮 | 颜色 + 光晕 0→峰值，26–30 帧 `inOutCubic`，在句子读完后触发 |
| 关系图连线 | `drawPathStyle` 描出，正向 14 帧、回环 60 帧 `inOutCubic` |
| 对比双栏 | 左右各 24–26 帧，起点相差 45–60 帧；落选一栏降到 0.42 不透明度 |
| 结论逐字 | `revealCharOpacities` 每字间隔 2 帧，起点在第 8 帧 |
| 场景末段 | `breath` 振幅 3–5px，`settle` 从第 70 帧起 40 帧渐入 |

**改完配方要跑轨迹机检。** 量测实现是 `scripts/a2v/motion.py`，两处共用一份：
`tests/test_motion_review.py`（参考实现上的严格判定）与 `review.py`
（验收命令，对任意作品都跑，结论进 `report.json` 的 `motion` 段、终端 M0–M4 一栏）。
它按帧走完每一幕，逐个量到每一个「从不透明走向不透明」的元素（基准示例上共 90 个），
判据：

| 判据 | 阈值 | 适用 |
| --- | --- | --- |
| 首帧不透明度 | ≤ 25% | 有位移的入场（实测 9 个；旧实现第一帧就到 0.438） |
| 到 0.9 的帧数 | ≥ 6 帧 | 有位移的入场（实测最少 7 帧） |
| 落地距幕尾 | ≥ 12 帧 | 全部入场（实测最小 25 帧） |
| 落地前不透明度回退 | 不许 | 全部入场 |

速度判据**只适用于有位移的入场**：90 个里另外 81 个是纯淡入（逐字揭示的单字符
2 帧、小标注与箭头 2–5 帧），那是刻意的做法，一刀切会把它们误判成弹跳。
刻意停在部分不透明度的装饰（光晕、火花、引号、注脚）不进扫描——这里判的是
内容入场的快慢与落地，不是光晕什么时候亮。
位移的形状判据（含过冲与「末尾必须正好为 0」）由测试里的单元素用例精确钉住。
验收里的动效结论**只提示、不拦人**（不改退出码）；测试里还有一个反例：
把入场整体加速 8 倍后重扫，闸门必须报错——否则说明它量不到。

## 可复用风格方向

三套风格都建立在同一套令牌上，只改令牌与构图，不必换运行时：

| 方向 | 背景与表面 | 强调色 | 排版 | 动效节奏 |
| --- | --- | --- | --- | --- |
| 深色科技（示例采用） | 近黑底 + 光晕 + 网格 + 细点阵，卡片带内高光 | 单一青色 `#35e0c8` | 大字重标题 + 负字距，标签正字距 | 20–30 帧入场，微过冲 |
| 编辑杂志 | 浅底 `#f6f7f9`，白色卡片，投影收敛 | 一点朱红或墨蓝 | 标题更大、正文更松，允许两栏 | 16–22 帧，曲线更克制 |
| 极简高级 | 单一深色或米色底，几乎无网格 | 用文字色而非彩色强调 | 大面积留白，一次只放一句话 | 24–36 帧，长缓动 |

## 场景节奏

- 场景时长由**口播文案**所需时间决定，不要先定时长再塞文案；
- 30fps 下常用参考：开场命题 4–6 秒，金句 6–9 秒，对比 8–10 秒，
  关系图 10–14 秒，结论 8–11 秒；
- 单场景不要短于 24 帧（0.8 秒），否则入场动效会被压缩到看不清；
  `validate.py` 会对过短的场景给出警告；
- 总时长 30–60 秒较适合单条内容；超过 90 秒建议拆成多条。

## 画面的组成

画面不再是一张作品自己的 HTML：composition（`web/src/compositions/A2VComposition.tsx`）
按分镜把每一幕挂进舞台，样式与令牌集中在 `web/src/styles/`，动效原语在
`web/src/runtime/`。分层如下：

| 层 | 位置 | 负责 |
| --- | --- | --- |
| 设计令牌与主题 | `web/src/styles/tokens.css`、`theme.css` | 颜色 / 表面 / 字号 / 间距 / 安全区变量 |
| 设计语言预设 | `web/src/styles/keynote.css` | `visual.preset: "keynote"` 的字体栈、字号阶、主题块、工具类 |
| 场景树原语样式 | `web/src/styles/scene-tree.css` | 布局 / 内容 / 图形原语的样式（形状变体、图表、状态） |
| 版面与字幕 | `web/src/styles/declarative.css`、`primitives.css` | 场景版面、字幕条、四族动效基元 |
| 原语实现 | `web/src/primitives/SceneTree.tsx` | 布局求解、内容引用、动效可视状态、字号取档 |

场景树承担「一幕画面怎么画」，composition 只负责舞台、背景与逐幕挂载；
可用原语与组合方式见 [视觉原语目录](primitive-catalog.md)。

背景层是常驻元素，挂在舞台内、场景元素之外，场景容器抬到背景之上：

```tsx
<div data-a2v-stage>
  <div className="a2v-bg-glow stage-bg" aria-hidden="true" />
  <div className="a2v-bg-grid stage-bg" aria-hidden="true" />
  <div className="a2v-bg-grain stage-bg" aria-hidden="true" />
  {/* 场景由组件按帧渲染，z-index 高于背景层 */}
</div>
```

本篇素材放在 `videos/<slug>/assets/`，由 `image` 原语的 `sourceRef` 引用；
不允许再写作品专属的画面代码，需要新表达时按原语注册表流程新增通用原语。

## 设计语言预设（可选）

分镜根级的 `visual.preset` 决定是否启用一层「发布会级」设计语言。字段可选，
目前唯一取值是 `"keynote"`；未知值由校验器报错并指出 `visual.preset` 字段路径。

**缺省时行为逐帧不变。** composition 始终引入 `web/src/styles/keynote.css`，
但只有分镜声明了预设才会在根元素写 `data-a2v-preset="keynote"`（`A2VComposition`
的 `useLayoutEffect`）：预设的全部规则（字体栈、主题块、字号阶、工具类）
都带 `[data-a2v-preset="keynote"]` 作用域，一条也不会生效；字号取档
（SceneTree 对声明了字号档的文字原语按实测宽度向下取档）只在预设存在时执行。
画面、字体与版式因此与未启用预设的取值完全一致——这不是口头承诺，
`tests/test_react_design_tokens.py` 在浏览器里量计算值守住作用域。

启用后多出来的约束：模块化字号阶（正文下限 36px，组件内部字号通过
`--a2v-ink-*` 别名一并收进阶上）、8pt 间距阶、两套主题
（`keynote-dark` / `keynote-light`）、对比度预算（正文 7:1、大字与图形 4.5:1）、
随仓库分发的 webfont，以及观感闸门 K1–K10；预设另外把 `--a2v-safe-top` 从
220px 提到 240px，并提供 `--a2v-safe-bottom-with-subtitles: 520px`。
版面仍由分镜的 `visual.layout` 选择，**未声明时 composition 兜底为居中**——
预设不推翻这个兜底，只补齐原本缺的 `left` 一档。
完整的启用方式、令牌表与闸门阈值见[发布会级设计语言](keynote-design-system.md)。

### 幕角标 `visual.kicker`

每幕的 `visual` 可以写一个可选字段 `kicker`：画面左上角的**定位词**，与右上角的
`04 / 08` 幕号合成一条角标。

```json
{ "id": "attention", "type": "list", "visual": { "layout": "center", "kicker": "注意力" } }
```

规则（由校验器守住，错误路径为 `scenes[i].visual.kicker`）：

- 一个词，**最多 8 个字**；要说得更多请放进 `title` 或 `subtitle`
- 非空、单行
- 只允许写在**幕**的 `visual` 上，顶层 `visual`（主题、预设）不接受

**没写 `kicker` 时角标留空**，不回落到 `type`。这一条是有来历的：角标原先直接渲染
`scene.type`，于是画面上出现的是分镜的内部类型标识符——`TITLE`、`LIST`、
`TIMELINE`、`NUMBER`、`CONCLUSION`。那是 schema 字段名，不是给读者看的字：
既没有信息量（读者不需要知道"这是一条时间线"），也和整屏中文格格不入。
一个内部标识符永远不该出现在画面上，所以兜底是"不显示"（`A2VComposition`
里留一个空 span），而不是"显示类型名"。

角标只在启用预设时挂载，因此它**不影响未声明预设的既有作品**。

## 字体

画面用**随仓库分发**的两套可变字体，不依赖渲染机器的系统字体，也不走 CDN：

| 字体 | 家族名 | 文件 | 用途 |
| --- | --- | --- | --- |
| Inter Variable | `"A2V Inter"` | `web/src/assets/fonts/Inter-Variable.ttf` | 拉丁与数字（图表数值列的对齐依赖它） |
| Noto Sans SC Variable | `"A2V Sans"` | `web/src/assets/fonts/NotoSansSC-Variable.ttf` | 中文 |

两者均为 SIL OFL 1.1，许可证原文（`OFL-Inter.txt` / `OFL-NotoSansSC.txt`）随字体
一同分发。**不走 CDN**：渲染是逐帧确定性导出，CDN 断网或限流时会静默回退到
系统字体，成片照样出得来，只是换了一副字。

- 唯一真源是 `web/src/assets/fonts.json` + `web/src/assets/fonts/`；
- `web/src/fonts.ts` 在首帧前用 CSS Font Loading API 注册（`font-display: block`，
  避免回退字体先渲染的那一帧被拍进成片），并声明 `font-weight: 100 900`
  （可变字体必须写完整区间，否则粗细档会被合成）；
- 字体栈只写在 `:root[data-a2v-preset="keynote"]` 作用域内：预设一启用即生效，
  未启用预设的画面继续用系统栈；`@font-face` 的 URL 注册是全局的，作用域由
  `tests/test_react_design_tokens.py` 在浏览器里量出来；
- 构建前 `web/scripts/sync-fonts.mjs` 把字体同步进 `public/fonts/`（gitignore 的
  生成物），源文件缺失时**构建直接失败**。

体积与许可见 `web/src/assets/fonts/README.md`；字体层的取舍理由见
[发布会级设计语言](keynote-design-system.md)。

## 排版自查

导出前至少检查一次：

- [ ] 所有正文在 `.a2v-safe` 内，没有被上下缘裁切；
- [ ] 图形内的文字没有穿出它所属的容器（节点圆、托盘、卡片）——
      这一条是 **K8 硬判定**，失败会让体检错误数非零、退出码非零；
- [ ] 组件的间距、内边距、线宽、字重、字距、圆角都引用令牌（设计宪法 C17），
      没有裸数字——新写的样式最容易漏；
- [ ] 同一帧最多一个元素处于焦点态（`data-a2v-state="focus"`），
      强调色只出现在它身上；
- [ ] 最长的一行没有贴边或与其它元素重叠；
- [ ] 正文没有超过 3 行，长句已拆场景或手动换行；
- [ ] 同一画面只有一个视觉焦点，强调色只出现在它身上；
- [ ] 背景、表面、焦点三层都在，画面没有「贴在纯色底上」的扁平感；
- [ ] 卡片 / 节点有 1px 边框、内高光与双层投影，而不是纯色块；
- [ ] 入场动效都走 `outQuint` / `inOutCubic`，没有凭空多出的曲线；
- [ ] 末帧不是完全静止（有 `api.breath` 级别的微动）；
- [ ] 每帧重复渲染结果一致（可对同一帧截图两次比对）。

## 逐句字幕

有声模式共享运行时自动添加 `.a2v-with-subtitles` 与字幕层；1080 × 1920 下默认 48px、
行高 1.3、白字深色描边，左右沿用 96px 安全边距，底部沿用 320px 安全边距。
每条字幕最多 28 个字符，用真实字词边界拆分；最多两行，采用均衡换行。
正文 `.a2v-safe` 的底部额外留出 180px，禁止覆盖字幕区域。其他画布尺寸需相应调整样式。
空白或停顿时间不显示字幕；不缩小字号塞入超长字幕，不按字数猜测发音时间。
字幕随逐帧截图烧录，预览与导出排版相同，SRT 不携带字体样式。
